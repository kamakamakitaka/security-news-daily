# ゼロデイを超えて：攻撃者の目線でネットワークを見直そう

**元記事**: [Beyond the Zero-Day: See Your Network Like an Attacker | Webinar with HD Moore](https://inl03.netline.com/ltr6/?_m=3n.009a.3994.sp0ao46r89.31ok)
**解説日**: 2025年6月10日

---

## 背景知識

まず、この記事を理解するために必要な基本的な概念を整理しておきましょう。

### 🏠 ネットワークの「区画」って何？
会社や工場のコンピューターネットワークは、普通いくつかの「区画（セグメント）」に分けて管理されています。たとえば：

- 一般社員が使うPC群
- 重要な顧客情報が入ったサーバー群
- 工場の機械を動かすシステム群

これらを「壁（ファイアウォール）」で区切ることで、万が一ハッカーが1つの区画に侵入しても、他の区画には影響が出ないようにするのが基本的な考え方です。**「セグメンテーション（区画分け）」** と呼びます。

### 🦠 ゼロデイ脆弱性とは？
ソフトウェアには「バグ（欠陥）」が潜んでいることがあります。**ゼロデイ脆弱性**とは、「まだ誰にも知られていない・まだ修正パッチが存在しない」欠陥のことです。
名前の由来は「開発者が対応できた日数がゼロ日（= 完全に無防備）」から来ています。

### 🗺️ 資産管理リストとネットワークマップの違い
- **資産管理リスト**：「うちの会社はPC100台、サーバー20台を持っています」という一覧表
- **ネットワークマップ**：「このPCはあのサーバーと繋がっていて、そこからあの機器にもアクセスできる」という繋がりの地図

この違いが、今回の記事の核心です。

## 技術的な詳細

### 🔍 「セグメンテーション幻想」とは何か？

多くの会社はこう考えています：
「重要なサーバーは別の区画に置いてあるから安全だ」

ところが実際にネットワークを詳しく調べてみると、こんな「穴」が見つかることがあります：

| よくある落とし穴 | 具体例 |
|---|---|
| **二重接続機器** | 気づかぬうちに2つの区画に繋がっているPCや機器（橋渡しになってしまっている） |
| **野良デバイス** | 誰も管理リストに載せていないのに、ネットワークに繋がっている機器 |
| **見えない機器群** | 工場の機械（OT機器）などが産業用のゲートウェイの裏に隠れていて、スキャンに引っかからない |

これをたとえるなら、

> 🏰 「城の周りに堀を作った。でも実は一部に橋がこっそり架かっていて、敵はそこから簡単に渡れた」

という状況です。

### 🗺️ 攻撃者が見ている「地図」の話

防御側が持っているもの → **「リスト」**（うちにはPC100台ある）
攻撃者が見ているもの → **「経路の地図」**（このPCから侵入すれば、3ステップで重要サーバーに辿り着ける）

攻撃者は「どんな機器があるか」ではなく、**「どう動けば目的地に辿り着けるか」** を考えています。まるでゲームの「ルート最適化」のような発想です。

### 🏭 IT・IoT・OTが混在する環境の危険性

現代の企業では、3種類のネットワークが混在していることが多いです：

- **IT（Information Technology）**：一般的なオフィスのPC・サーバー
- **IoT（Internet of Things）**：センサー・監視カメラ・スマートデバイスなど
- **OT（Operational Technology）**：工場の製造機械・制御システムなど

これら3つが同じ環境にあると、**「つなぎ目（seam）」** が生まれ、そこが攻撃者の狙いどころになります。

## なぜ重要なのか

### ⚠️ 「全部パッチを当てる」戦略の限界

記事冒頭に書かれているように、現代では：

- ゼロデイ脆弱性は次々と発見される
- **AIを使って攻撃コードを書く速度が、パッチを当てる速度を超えつつある**
- 全ての機器に漏れなく・素早くパッチを当てることは、現実的にほぼ不可能

だから「侵入されないこと」だけを目標にするのではなく、**「侵入されても被害を最小限にする」** 発想が必要になっています。

### 🏢 影響を受ける組織

- 工場や製造業（IT+OT混在環境）
- 医療機関（医療機器+ITシステム）
- 大規模なオフィス環境（IoTデバイスが多い）
- 上記が混在しているあらゆる企業

つまり、**現代のほぼ全ての企業・組織に関係する話**です。

## 対策・今後の展望

記事が提案する対策をわかりやすく整理すると：

### ✅ 4つの重要アクション

```
1. 知らない資産を見つける
   → 管理リストにない「野良デバイス」「シャドーIT」を発見する

2. セグメントをつなぐ「橋」を見つける
   → 複数のゾーンに繋がってしまっている機器を特定する

3. 静的なリストから「経路マップ」に切り替える
   → 攻撃者がどのルートで侵入できるかを可視化する

4. 本当に重要な箇所に絞って修正する
   → 全部直すのではなく、攻撃者の「近道」になっている部分を優先的に直す
```

### 🔭 今後の展望

AIによる攻撃の高速化が進む中、今後は：
- **「攻撃者視点での継続的なネットワーク監視」** が標準的なセキュリティ対策になっていく
- 一度だけ確認して終わりではなく、**リアルタイムで変化を検知する仕組み**が重要になる

と考えられます。

以前、**「IAM攻撃対象の縮小：アイデンティティの見える化プラットフォーム（IVIP）」** について解説しました。

あの記事では「**誰がどのシステムにアクセスできるか（アイデンティティ）を可視化する**」ことの重要性をお伝えしました。

今回の記事はその視点をさらに広げて、「**誰がアクセスできるか**」だけでなく「**ネットワーク全体のどこからどこへ移動できるか（経路）**」を可視化することの重要性を伝えています。

つまり：
- IVIP → **「人（アイデンティティ）」の見える化**
- 今回の内容 → **「ネットワーク経路」の見える化**

この2つは、**「攻撃者に見えていて防御側に見えていない部分をなくす」** という同じ方向性を持つ取り組みと言えます。セキュリティの世界では、この「見える化」がますます重要なテーマになっています。

## 用語解説

| 用語 | 意味 |
|---|---|
| **ゼロデイ（Zero-Day）** | まだパッチ（修正プログラム）が存在しない、発見されたばかりの脆弱性 |
| **セグメンテーション** | ネットワークを複数の区画に分けて、影響範囲を限定する手法 |
| **Metasploit（メタスプロイト）** | セキュリティの専門家がネットワークの脆弱性をテストするために使うツール。ハッカーも悪用する |
| **ファイアウォール** | 不正な通信をブロックするネットワークの「門番」 |
| **マルチホーム機器** | 複数のネットワークに同時に接続されている機器。意図せず「橋渡し」になることがある |
| **OT（Operational Technology）** | 工場の機械や電力・水道などのインフラを制御するシステム |
| **IoT（Internet of Things）** | インターネットに繋がる家電・センサー・機器全般 |
| **シャドーIT** | 会社の管理部門に申請せず、社員が勝手に使っているデバイスやサービス |
| **アタックパス（Attack Path）** | 攻撃者が侵入後、目的の機器に辿り着くまでに使う経路 |
| **runZero（ランゼロ）** | HD Moore氏が設立した、ネットワーク資産発見ツールを提供するセキュリティ企業 |
| **ウェビナー** | Web + Seminarの造語。インターネット上で行うオンラインセミナー |
