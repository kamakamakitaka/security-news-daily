## 背景知識

このニュースを理解するために、まずいくつかの基本的な考え方を押さえておきましょう。

### 🏠 ネットワークを「建物」で例えてみると…

会社のコンピューターネットワークは、大きな建物に例えられます。

- **部屋（セグメント）**：重要なデータがある部屋、一般業務の部屋、工場の機械を操作する部屋など、用途ごとに区切られています
- **壁（ファイアウォール）**：部屋と部屋の間にある壁。許可された人（データ）しか通れません
- **扉（ネットワーク経路）**：部屋をつなぐ通路。本来は管理されているはずですが…

## 技術的な詳細

### 😰 「パッチを全部当てればOK」が通用しなくなった理由

昔のセキュリティ対策の王道は「脆弱性が見つかったらすぐにパッチ（修正プログラム）を当てる」でした。でも今は…

```
脆弱性が発見される
    ↓（ほぼ同時に）
AIが攻撃コードを自動生成
    ↓（数時間〜数日）
攻撃者が悪用し始める
    ↓（数日〜数週間後）
パッチが配布される
```

**AIの登場で、攻撃コードが作られるスピードが、修正するスピードを上回ってしまった**のです。だから「パッチで完全に防ぐ」という戦略だけでは限界があります。

---

### 🗺️ 「リスト」と「地図」の決定的な違い

ここが今回の記事の核心です。

#### 防御側（会社のIT部門）の見方
```
資産台帳（インベントリ）
━━━━━━━━━━━━━━━
・サーバーA（経理部）
・サーバーB（人事部）
・PC 100台
・プリンター20台
━━━━━━━━━━━━━━━
「よし、全部把握してる！」
```

#### 攻撃者の見方
```
ネットワーク地図（攻撃経路マップ）
━━━━━━━━━━━━━━━━━━━
PC（感染）→ 古いIoTカメラ→ 工場制御システム
         ↗
誰も知らないブリッジ機器（2つのネットワークに足をかけている）
━━━━━━━━━━━━━━━━━━━━
「重要なシステムへの道が見えた！」
```

**防御側はモノのリストを持っているが、攻撃者は経路の地図を持っている**。この視点の差が、被害につながります。

---

### 🕳️ 「セグメンテーションの幻想」とは？

会社のネットワークは通常、以下のように区切られています：

```
[ 一般業務ネットワーク ] ─── 壁（ファイアウォール）─── [ 重要システム ]
                                                          [ 工場制御システム ]
```

「壁があるから安全！」と思っていても、現実には…

- **マルチホームデバイス**（2つのネットワークに同時につながっている機器）が「壁に穴を開けて」いる
- **誰も登録していない古い機器**が、本来アクセスできないはずのセグメントで動いている
- **工場の機械（OT機器）** がゲートウェイの裏に隠れていて、通常のスキャンツールでは見えない

これを記事では「**セグメンテーションの幻想**」と呼んでいます。壁があると思っていたら、実は穴だらけだった、という状況です。

## なぜ重要なのか

### 攻撃者が「一点突破」から「経路移動」に変わった

現代の攻撃は、最初の侵入（フットホールド）から始まり、ネットワーク内を横移動して最終目標にたどり着きます。

```
メール添付ファイル    社員PCに感染    社内ネットワーク探索
（フィッシング）  →  （足がかり）  →  見えていない経路を発見
                                         ↓
                                    重要データ盗難 or
                                    工場システム停止
```

### 特に危ない「IT・IoT・OTが混在する環境」

```
オフィスのPC（IT）
    ↕ ← ここのつながりが危険
工場の機械（OT）
    ↕
温度センサーや監視カメラ（IoT）
```

工場の製造ラインを制御するシステムが、オフィスのPCと間接的につながっていると、オフィスへの攻撃が工場停止につながる可能性があります。実際に過去には病院や電力会社でこうした攻撃が起きています。

## 対策・今後の展望

### ✅ 記事が提案する4つのアクション

#### 1️⃣ 知らない資産を見つける
> 「認識していないIoT機器や、OTゲートウェイの裏に隠れた機器を発見する」

自分の家にある全ての鍵穴を把握していないと、泥棒対策はできません。まず「何がつながっているか」を完全に把握することが第一歩です。

#### 2️⃣ セグメンテーションを壊しているブリッジを見つける
> 「複数のネットワークにまたがっている機器や、孤立しているはずのゾーンをつないでいる忘れられた資産を見つける」

「壁の穴」を探して塞ぎましょう。

#### 3️⃣ 静的なリストではなく「攻撃経路マップ」を使う
> 「足がかりが実際にどう移動するかを示すライブの攻撃経路マッピングに切り替える」

資産リストを作って満足するのではなく、「攻撃者がどう動けるか」という視点でネットワークを見直すことが必要です。

#### 4️⃣ 本当に重要な箇所だけを優先的に修正する
> 「攻撃者の目標までの経路を短くしている資産とリンクに修正を集中する」

全部を完璧に直すのは現実的ではありません。「攻撃者にとって最も美味しい経路」を優先的に塞ぐことが大切です。

### 🔭 今後の展望

AIが攻撃を加速させている時代において、**「侵入を100%防ぐ」発想から「侵入されても被害を最小化する」発想への転換**が、セキュリティの世界では主流になっています。これを「**ゼロトラスト（誰も信用しない）**」という考え方とも呼びます。

## 用語解説

| 用語 | 解説 |
|------|------|
| **ゼロデイ（Zero-Day）** | まだ誰にも知られていない（パッチが存在しない）脆弱性。発見された当日から攻撃に使える |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやシステムのバグや設計ミスで、攻撃者に悪用される可能性があるもの |
| **パッチ** | ソフトウェアの欠陥を修正するための更新プログラム |
| **Metasploit（メタスプロイト）** | セキュリティ専門家が「攻撃手法を学び・テストする」ために使うオープンソースのフレームワーク。悪用もされる |
| **セグメンテーション** | ネットワークをいくつかのグループに分けて、グループ間の通信を制限するセキュリティ手法 |
| **フットホールド（Foothold）** | 攻撃者がネットワークに最初に侵入した「足がかり」となる地点 |
| **マルチホームデバイス** | 複数の異なるネットワークに同時に接続されている機器。意図せず「橋渡し」になることがある |
| **IoT（アイオーティー）** | カメラ・センサー・家電などインターネットにつながった「モノ」全般 |
| **OT（オーティー）** | 工場の製造ラインや電力・水道などのインフラを制御するシステム（Operational Technology） |
| **IT（アイティー）** | 一般的なオフィス業務に使われるPC・サーバーなどの情報技術（Information Technology） |
| **ゼロトラスト** | 「社内ネットワークだからといって信用しない」という考え方。全ての通信を疑ってかかるセキュリティ設計 |
| **インベントリ（資産台帳）** | 会社が管理している機器やソフトウェアのリスト |
| **runZero** | HD Moore氏が設立した会社。ネットワーク上の全資産を発見・可視化するツールを提供している |
| **ウェビナー** | オンラインで開催されるセミナー（Web + Seminar） |
