# ゼロデイを超えて：攻撃者の目でネットワークを見る

**元記事**: [Beyond the Zero-Day: See Your Network Like an Attacker | Webinar with HD Moore](https://inl03.netline.com/ltr6/?_m=3n.009a.3994.sp0ao46r89.31ok)
**解説日**: 2025年6月13日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な考え方を押さえておきましょう。

### 🏠 ネットワークの「部屋分け」＝セグメンテーション

会社のネットワークは、たとえると**大きなビル**のようなものです。
重要な部屋（役員室や金庫室）と、一般の部屋（会議室や休憩室）を**壁や鍵で分けている**ように、ネットワークも「重要なシステム」と「一般の端末」を分離して管理します。この仕組みを**ネットワークセグメンテーション**といいます。

### 🔓 ゼロデイとは？

**ゼロデイ（Zero-Day）**とは、ソフトウェアの欠陥（バグ）が見つかったとき、まだ誰も修正プログラム（パッチ）を作っていない状態の脆弱性のことです。
「0日間の猶予しかない」という意味で、発見された瞬間から攻撃に使われる危険があります。

### 📋 IT資産台帳（インベントリ）とは？

会社が持っているパソコン・サーバー・ネットワーク機器などを一覧にした**「持ち物リスト」**のことです。

### 🛠️ Metasploitとは？

**Metasploit（メタスプロイト）**は、セキュリティの専門家がネットワークの弱点を調べるために使う有名なツール（フレームワーク）です。本来は防御のために使われますが、攻撃者も同様の技術を悪用します。

## 技術的な詳細

### 😰 「セグメンテーションできてる」は思い込みかもしれない

「うちは重要なシステムをちゃんと分離してるから大丈夫」と思っている企業は多いです。
でも実際にネットワークを**地図として**描き直してみると、思わぬ「抜け穴」が見つかります。

記事では以下のような例が挙げられています：

| 問題 | たとえで言うと |
|------|--------------|
| 2つのネットワークに同時につながっている機器（マルチホーム端末） | ビルの壁に穴をあけて両側の部屋に顔を出しているスパイ |
| 誰も把握していない機器が重要なセグメントにいる | 受付に登録されていない人が金庫室の近くにいる |
| OT（工場設備）のゲートウェイの裏に隠れた機器 | 裏口から入れる倉庫があるのに誰も知らない |

### 📍 「リスト」と「地図」の決定的な違い

セキュリティ担当者は**「持ち物リスト（インベントリ）」**を管理しています。
でも攻撃者が見ているのは**「経路の地図（マップ）」**です。

```
【守る側の視点】
  ✅ 機器Aを持っている
  ✅ 機器Bを持っている
  ✅ 機器Cを持っている

【攻撃者の視点】
  → 機器Aに侵入
  → 機器Aから機器Bに移動できる（セグメントをまたいで！）
  → 機器Bから機器C（重要システム）に到達！
```

リストには「機器が存在する」ことしか書いていませんが、攻撃者は**機器と機器のつながり方（パス）**を読んでいます。この「見え方の差」こそが、今回の記事が指摘する最大の問題です。

### 🏭 IT・IoT・OTが混在する環境の危険性

現代の企業では：
- **IT**（パソコンやサーバーなど一般的な情報システム）
- **IoT**（監視カメラ・スマートデバイスなど）
- **OT**（工場の機械・制御システムなど）

この3つが同じネットワーク環境に**ごちゃまぜに**なっていることが多く、その「境界のつなぎ目」こそが攻撃者に狙われやすいポイントです。

## なぜ重要なのか

### ⚡ AIによって攻撃のスピードが上がっている

記事の冒頭に「AIがパッチが当たるよりも早くエクスプロイト（攻撃コード）を書いている」とあります。
つまり——

> 穴を塞ぐより速く、攻撃ツールが作られる時代になった

ということです。「全部のパッチを間に合わせる」戦略はもはや現実的ではありません。

### 🎯 だから「侵入されてからどこまで行けるか」が重要

「侵入を100%防ぐ」ことが難しい以上、
**「侵入された後に、どこまでの被害で食い止められるか」**
が本当の勝負になります。

これが記事の冒頭の「**Assume the breach（侵入されることを前提とせよ）**」という考え方です。

## 対策・今後の展望

記事では以下の4つのアクションが提案されています：

### ✅ 1. 知らない資産を見つける
- 「シャドーIT」（会社が把握していない個人持ち込み機器）
- 「シャドーIoT」（知らないうちにネットワークにつながったデバイス）
- OTゲートウェイの裏に隠れた機器

### ✅ 2. セグメント分離を破っている「橋」を見つける
- 複数のネットワークに同時につながっているマルチホーム端末
- 「分離しているはず」の区域をつないでしまっている忘れられた機器

### ✅ 3. 静的なリストから「ライブ攻撃経路マップ」へ切り替える
- 「何が存在するか」だけでなく「どう移動できるか」を可視化する

### ✅ 4. 「本当に重要な修正」に集中する
- 全部を直そうとするのではなく、攻撃者が**最短ルートで重要システムに到達できる経路**を優先的に塞ぐ

## 過去記事との関連

以前、**「IAM（アイデンティティ管理）の攻撃リスクを減らす方法」**について解説しました。あの記事では「**誰が何にアクセスできるか**という"人の動き"が見えていないことが危険」という話でした。

今回の記事はそれと似ていて、**「機器やネットワークがどうつながっているか"形"が見えていないことが危険」**という話です。

まとめると——

| 過去の記事 | 今回の記事 |
|-----------|-----------|
| 人（アカウント・権限）の可視化が大事 | ネットワーク（機器・経路）の可視化が大事 |
| 「誰が動けるか」の地図 | 「どこへ行けるか」の地図 |

どちらも**「見えていないものが攻撃者に利用される」**という共通のテーマを持っています。セキュリティの本質は「可視化」にあるといえるでしょう。

## 用語解説

| 用語 | 意味 |
|------|------|
| **ゼロデイ（Zero-Day）** | まだ修正されていない脆弱性。発見即攻撃可能な危険な状態 |
| **パッチ** | ソフトウェアの欠陥を修正するための更新プログラム |
| **エクスプロイト** | 脆弱性を突いて攻撃するためのプログラムやコード |
| **セグメンテーション** | ネットワークを区画に分けて管理・隔離すること |
| **マルチホーム端末** | 複数のネットワークに同時に接続している機器 |
| **IT** | 一般的な情報システム（PC・サーバーなど） |
| **IoT** | インターネットにつながるデバイス（カメラ・センサーなど） |
| **OT** | 工場や設備の制御システム（PLCなど） |
| **シャドーIT** | 会社が把握・承認していない機器やサービスの利用 |
| **Metasploit** | セキュリティ専門家が使う脆弱性診断フレームワーク |
| **インベントリ** | 会社が管理するIT資産の一覧リスト |
| **Assume the Breach** | 「侵入されることを前提に防御を設計する」という考え方 |
| **攻撃経路（アタックパス）** | 攻撃者が侵入後に重要システムへ到達するまでの経路 |

---

> 💡 **一言まとめ**
