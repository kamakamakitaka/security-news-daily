# エンドポイント検知・対応（EDR）はもはや"当たり前"——その次に来るものとは？

## 背景知識

まず、この記事を理解するために必要な基本的な概念を整理しましょう。

### 🏠 エンドポイントって何？

「エンドポイント（Endpoint）」とは、ネットワークに接続されているパソコン・スマートフォン・サーバーなど、**個々の端末**のことです。会社の中で社員が使うパソコン1台1台がすべて「エンドポイント」にあたります。

> 💡 **例え話**: 会社というお城があるとしたら、エンドポイントは「お城の窓や扉」のようなものです。攻撃者はこれらの入り口から侵入しようとします。

### 🛡️ セキュリティ対策の3段階

| レベル | 名前 | 役割 | 例え |
|--------|------|------|------|
| 第1段階 | **EPP**（エンドポイント保護） | 既知のウイルスをブロックする | 玄関のカギ・警報機 |
| 第2段階 | **EDR**（検知・対応） | 不審な動きを監視・調査する | 館内の監視カメラ＋警備員 |
| 第3段階 | **MDR**（マネージド検知・対応） | 専門家チームが24時間代わりに監視 | 外部の警備会社に委託 |

### 🤖 AI時代の攻撃者

最近のハッカーはAIを使って、より巧妙で素早い攻撃ができるようになっています。従来の「ウイルス対策ソフトで検知できる攻撃」だけでなく、**正規のシステムツールを悪用する手口**（後述）も増えており、単純な防御では対処しきれなくなっています。

## 何が起きたのか

セキュリティ企業「**Bitdefender（ビットディフェンダー）**」が行った調査で、以下のことが明らかになりました。

### 📊 調査結果のポイント

> **回答者の97.7%がすでにEDRを導入済み**

これは非常に高い数字であり、「EDRはもはや特別なものではなく、基本中の基本になった」ということを示しています。

しかし同時に、こんな問題も浮かび上がりました：

- **EDRを導入しても、使いこなせていない組織が多い**
- **45%のIT・セキュリティ担当者が「アラート（警告）を調査しきれない」と回答**
- 特に**中小〜中堅企業（mid-market）** は、専門チームがおらず対応に苦労している

> 💡 **例え話**: 監視カメラを取り付けたのに、映像を見る警備員がいない状態——これでは防犯の意味が半減してしまいます。

## 技術的な詳細

### 🎭 なぜEPPだけでは不十分なのか？

昔のウイルス対策ソフト（EPP）は、**既知のウイルスのパターン**を照合して検知するものでした。しかし現代の攻撃者は、そのパターンに引っかからない手口を使います。

#### 代表的な手口①：**LOTL（Living-off-the-Land）攻撃**

「土地の資源で生き延びる（現地調達）」という意味で、**Windowsなどに最初から入っている正規の管理ツールを悪用する攻撃**です。

```
【通常の使い方】
  管理者 → PowerShell（Windowsの管理ツール）→ システム設定の変更

【LOTL攻撃】
  攻撃者 → PowerShell（同じツール）→ 裏でデータを盗む・マルウェアを仕込む
```

> 💡 **例え話**: 工場に忍び込んだ泥棒が、持参した道具を使わず、**工場にもともとある工具を使って**機械を壊す——セキュリティソフトには「工場の正規の工具が使われている」ようにしか見えません。

#### 代表的な手口②：**資格情報の悪用（Credential Abuse）**

パスワードやID（「資格情報」）を盗み、**正規ユーザーになりすまして**ログインする攻撃です。

- ウイルスを使わないので、ウイルス対策ソフトに検知されにくい
- 「正規のログイン」に見えてしまう

### 🚨 「アラート疲れ」の問題

EDRは不審な動きをすべて記録・通知しますが、1日に**数百〜数千件のアラート**が出ることも珍しくありません。

```
1日のアラート数の例（中規模企業）：
  ├─ 重大（本物の攻撃）    ：約3件
  ├─ 中程度（要確認）      ：約50件
  └─ 低リスク（誤検知など）：約500件以上
```

すべてを手作業で確認するのは現実的に不可能で、担当者は疲弊してしまいます。これを**「アラート疲れ（Alert Fatigue）」**と呼びます。

## なぜ重要なのか

### 💼 企業にとってのリスク

EDRを導入せず、古いEPPだけで運用している組織には、以下のリスクがあります：

| リスクの種類 | 具体的な内容 |
|-------------|-------------|
| **ランサムウェア被害** | 検知が遅れてデータが暗号化される |
| **復旧時間の増大** | 攻撃の痕跡を追えず、復旧に数週間かかる |
| **法的リスク** | 万が一漏洩した場合、「適切な対策をしていたか」を裁判で証明できない |
| **取引・保険への影響** | 取引先・保険会社・規制当局が「サイバーレジリエンス（回復力）」を要求 |

### 🌍 社会全体への影響

現代のビジネスでは、**顧客・取引先・保険会社・規制当局**のすべてが「あなたの会社はサイバー攻撃に対して適切な備えをしていますか？」と問うようになっています。

EDRを持たない会社は、ビジネスの信頼性そのものが問われる時代になっています。

## 対策・今後の展望

### ✅ 今すぐできる考え方の転換

この記事が訴える最重要メッセージは：

> **「攻撃は防げる」という前提から「攻撃はいつか来る」という前提へ**
> → 「Assume Breach（侵害されること前提）」の思考

```
古い考え方：
  攻撃 → ブロック → 安全 ✓

新しい考え方：
  攻撃 → 一部が侵入 → 素早く検知 → 即座に封じ込め → 被害最小化 ✓
```

### 🏢 中小〜中堅企業向けの現実的な解決策

自前でSOC（セキュリティ監視センター）を持てない企業には、**MDR（Managed Detection & Response）** という選択肢があります。

> 外部の専門家チームが24時間365日、あなたの会社のシステムを代わりに監視・対応してくれるサービスです。

**メリット**：
- 専門人材を雇わなくて済む
- 24時間監視が実現できる
- コストを抑えられる

### 🔮 今後のトレンド

- AIを使った**自動アラート分類・優先付け**で人間の負担を減らす
- EDRから**XDR（拡張型検知・対応）** へ——エンドポイントだけでなく、ネットワーク・クラウド・メールも一元監視
- **AIvs AI**の構図——攻撃者もAIを使うため、防御側もAIで対抗する時代へ

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **EPP** | イーピーピー | Endpoint Protection Platform。ウイルス対策ソフトなど、攻撃を事前にブロックするもの |
| **EDR** | イーディーアール | Endpoint Detection & Response。端末の不審な動きを検知・調査・対応するもの |
| **MDR** | エムディーアール | Managed Detection & Response。外部の専門家チームに検知・対応を委託するサービス |
| **SOC** | ソック | Security Operations Center。セキュリティを24時間監視する専門チーム・組織 |
| **LOTL** | ロトル | Living-off-the-Land。OSに標準搭載のツールを悪用する攻撃手法 |
| **資格情報（クレデンシャル）** | — | パスワードやIDなど、ログインに使う情報 |
| **ランサムウェア** | — | データを暗号化して「身代金」を要求するマルウェア（悪意のあるプログラム） |
| **アラート疲れ** | — | 大量の警告通知に疲弊し、重要なものを見逃してしまう状態 |
| **XDR** | エックスディーアール | Extended Detection & Response。EDRをネットワーク・クラウド等にも拡張したもの |
| **Assume Breach** | アシューム・ブリーチ | 「侵害されることを前提に備える」という現代のセキュリティ思想 |
| **サイバーレジリエンス** | — | サイバー攻撃を受けても、素早く回復できる組織の能力・強靭さ |

---

> 🎯 **まとめ**: セキュリティは「壁を高くする」だけの時代から、「侵入されたときにいかに素早く気づき、被害を最小限に抑えるか」の時代に変わっています。EDRはその第一歩ですが、導入するだけでなく「使いこなす体制」を整えることが、これからの企業には不可欠です。
