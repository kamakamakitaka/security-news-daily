# AIツールが2年間見つからなかったRedisの重大な脆弱性を発見（CVE-2026-23479）

**元記事**: [Autonomous AI Tool Finds 2-Year-Old RCE Flaw in Redis (CVE-2026-23479)](https://inl03.netline.com/ltr6/?_m=3n.009a.3995.sp0ao46r89.31qy)
**解説日**: 2026年6月4日

---

## 背景知識

まず、このニュースを理解するためにいくつかの基本知識を押さえましょう。

### Redisってなに？
**Redis（レディス）** とは、データを超高速で読み書きできる「データベースソフトウェア」です。LINEやTwitterのようなサービスが「誰がオンライン中か」「最新の投稿は何か」といった情報を素早く処理するために広く使われています。実は **クラウド環境（AWSやGoogleクラウドなど）の大多数** で使われているほど、世界中に普及しているソフトウェアです。

### RCEってなに？
**RCE（Remote Code Execution＝遠隔コード実行）** とは、攻撃者がインターネット越しに、他人のサーバーで「好きな命令を実行できてしまう」攻撃のことです。鍵をかけていない他人の家に入って、家電を自由に操作できるようなイメージです。セキュリティ上、最も危険な脆弱性のひとつです。

### 脆弱性ってなに？
**脆弱性（ぜいじゃくせい）** とは、ソフトウェアの「セキュリティ上の欠陥・バグ」のことです。泥棒が入れる窓のひび割れのようなものです。今回の脆弱性は **CVE-2026-23479** という識別番号が付けられています。

### CVSS（危険度スコア）ってなに？
**CVSS** とは脆弱性の「危険度を0〜10点で評価するスコア」です。今回は **8.8点（10点満点）** という非常に高い危険度が付けられています。

## 何が起きたのか

### 事件の概要

2023年初頭にRedisのプログラムに「バグの種」が仕込まれ、**2年以上にわたって誰にも気づかれなかった重大な脆弱性**が発見されました。

発見したのは人間のセキュリティ研究者ではなく、**「Xint Code」という自律型AI（自動でバグを探すAIツール）** です。このAIは2025年12月にロンドンで開催されたセキュリティハッキングコンテスト「ZeroDay.Cloud 2025」でこの脆弱性を実際に攻撃できることを実演しました。

修正パッチは2026年5月5日にリリースされ、現在はアップデートで対処できます。

## 技術的な詳細

少し難しい話になりますが、できるだけわかりやすく説明します！

### バグの種類：「Use-After-Free（解放済みメモリの使用）」

このバグは **「Use-After-Free（ユーズ・アフター・フリー）」** と呼ばれる種類のバグです。

📦 **わかりやすいたとえ話：**
> 荷物を一時的に預けた「コインロッカー」を想像してください。
> あなたが荷物を取り出してロッカーを「返却（解放）」した後、
> 別の人がそのロッカーを使い始めます。
> でもあなたのプログラムは「まだ自分のロッカーだ」と思って中を覗こうとする…
> そこには他人の荷物（偽データ）が入っています。
> これが「Use-After-Free」です。

Redisの内部では、`unblockClientOnKey()` という関数が「待機中の命令を処理する」際に、**処理が終わったクライアント（利用者）のデータを削除した後、削除したはずのデータを読み続けてしまう** バグが存在しました。

### 3段階の攻撃手順

攻撃者はこのバグを使って、以下の3ステップでサーバーを乗っ取ります。

**ステップ①：住所を盗み見る（メモリアドレスのリーク）**
```
攻撃者がRedisに特殊な1行スクリプトを送る
→ サーバーのメモリ（記憶領域）の「住所」が漏れる
```
サーバーのメモリがどこにあるかを知ることで、次の攻撃の狙いを定められます。

**ステップ②：偽の「住人」を送り込む（偽データの注入）**
```
わざとメモリを解放させる
→ 空いた場所に「偽のクライアント情報」を注入する
→ Redisが偽情報を本物だと信じる
```

**ステップ③：プログラムを乗っ取る（関数ポインタの書き換え）**
```
Redisの「メモリ管理機能」を悪用
→ 「strcasecmp（文字比較関数）」の呼び出し先を「system（コマンド実行関数）」に書き換える
→ 次にRedisが文字を比較しようとすると、代わりにシェルコマンドが実行される
```

🏠 **たとえ話：**
> 郵便局員（Redis）が「田中さん宅へ届けて」という指示書（関数ポインタ）を持っています。
> 攻撃者がその指示書の住所を「攻撃者の家」に書き換えると、
> 郵便局員は知らないうちに攻撃者の指示通りに動いてしまいます。

### なぜ2年間見つからなかったのか？

このバグは **2つの別々のコード変更が組み合わさって** 初めて危険になりました。

- **変更①だけ**では問題なし
- **変更②だけ**でも問題なし
- **①＋②が組み合わさると** 致命的なバグに

人間のコードレビューでは「それぞれの変更は安全そうだ」と判断されてしまったため、見逃されたのです。これを **「2コミット問題」** と呼ぶことができます。

## なぜ重要なのか

### 影響範囲が非常に広い

セキュリティ会社「Wiz」の調査によると：
- **クラウド環境の大多数** でRedisが動いている
- しかもその多くが **パスワードなし** で動いている

これは「玄関ドアのない家が街中にたくさんある」状態です。

### 攻撃の条件がゆるい

この攻撃には「認証済みセッション（ログイン済みの状態）」が必要ですが、デフォルト設定では **パスワードなしでログインできる** ため、実質的に誰でも攻撃できる状態です。

### Dockerイメージにも問題あり

公式のRedis Dockerイメージ（よく使われるインストールパッケージ）では **RELRO（メモリ保護機能）が不完全** なため、攻撃がさらに簡単になります。

### AIが人間より先に発見した意義

これまでセキュリティの脆弱性発見は人間の専門家の仕事でした。今回、**AIが自律的に複雑な脆弱性を発見し、実際に攻撃まで成功させた**ことは、セキュリティの世界に大きな変化をもたらす可能性があります。良い面（防御側もAIを使える）と悪い面（攻撃者もAIを使える）の両方があります。

## 対策・今後の展望

### 今すぐできる対策

#### ✅ 最優先：アップデートする
使っているRedisのバージョンに合わせて以下にアップデートしてください：

| 現在のシリーズ | 安全なバージョン |
|---------------|----------------|
| Redis 7.2.x | **7.2.14** |
| Redis 7.4.x | **7.4.9** |
| Redis 8.2.x | **8.2.6** |
| Redis 8.4.x | **8.4.3** |
| Redis 8.6.x | **8.6.3** |

> 💡 **Redis Cloud（マネージドサービス）** を使っている場合は、すでに自動で修正済みです。

#### ✅ アップデートできない場合の応急処置

1. **Redisをインターネットに直接つながないようにする**（ファイアウォールで保護）
2. **パスワードを設定する**（デフォルトはパスワードなしのため）
3. **権限を分ける**（管理者権限・スクリプト実行権限・設定変更権限を1つのアカウントに持たせない）
4. **Lua（スクリプト）機能を無効にする**（使っていない場合）→ 攻撃のステップ①を防げる

### 今後の展望

現時点では「実際に悪用された」という報告はありませんが、攻撃の詳細な手順が公開されてしまったため、今後悪用される可能性が高まっています。**できるだけ早くアップデートすることが重要です。**

また、今回の発見が **AIによるもの** である点も重要です。AIが攻撃・防御の両方で使われる時代が来ており、セキュリティの世界が急速に変化していることを示しています。

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **Redis** | レディス | 高速データ処理ソフトウェア。多くのWebサービスで使用 |
| **CVE** | シーブイイー | 脆弱性に付けられる世界共通の識別番号 |
| **RCE** | アールシーイー | 遠隔コード実行。攻撃者が外部からサーバーで命令を実行できる攻撃 |
| **CVSS** | シーブイエスエス | 脆弱性の危険度を0〜10で表すスコア |
| **Use-After-Free** | ユーズアフターフリー | 解放済みのメモリ領域を誤って使い続けるバグの種類 |
| **ヒープメモリ** | - | プログラムが動的に使うメモリ領域。データの一時保管場所 |
| **GOT（Global Offset Table）** | ジーオーティー | 関数の場所を記録したプログラム内の「住所録」。書き換えると攻撃に悪用できる |
| **RELRO** | レルロ | メモリ保護機能のひとつ。GOTの書き換えを防ぐ |
| **ASLR** | エーエスエルアール | メモリの配置をランダムにしてアドレスを推測されにくくするセキュリティ機能 |

| **Lua** | ルア | プログラミング言語の一種。Redisでスクリプト実行に使われる |
| **Docker** | ドッカー | アプリをまとめて配布・実行するためのコンテナ技術 |
| **自律型AI** | じりつがたエーアイ | 人間が指示しなくても、自動で判断・行動できるAI |
| **パッチ** | - | バグや脆弱性を修正するためのソフトウェア更新プログラム |
