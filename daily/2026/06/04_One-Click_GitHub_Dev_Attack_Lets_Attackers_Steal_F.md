# ワンクリックでGitHubの認証トークンが盗まれる！開発ツールの脆弱性が発覚

**元記事**: [One-Click GitHub Dev Attack Lets Attackers Steal Full GitHub OAuth Tokens](https://inl03.netline.com/ltr6/?_m=3n.009a.3995.sp0ao46r89.31qs)
**解説日**: 2026年6月5日

---

## 背景知識

今回のニュースを理解するために、まずいくつかのキーワードを押さえておきましょう。

### 🔧 Visual Studio Code（VS Code）とは？
マイクロソフトが開発した、プログラマーが使う「コードエディタ（プログラムを書くためのメモ帳の超高機能版）」です。世界中の開発者に使われており、無料で使えることから非常に人気があります。

### 🐙 GitHubとは？
プログラムのソースコード（設計図）を保存・管理・共有できるサービスです。個人の学習用から、大企業の重要なシステムまで、膨大な量のコードが保管されています。「リポジトリ（リポ）」と呼ばれる単位でコードを管理します。

### 🔑 OAuth（オーオース）トークンとは？
「あなたが本物の利用者ですよ」と証明するための**デジタルな合鍵**です。パスワードを都度入力する代わりに、このトークン（長い文字列）を使ってサービスにアクセスします。これが盗まれると、まるで本物の鍵を複製されたようなもので、攻撃者があなたになりすまして操作できてしまいます。

### 🌐 GitHub.devとは？
GitHubが提供する、**ブラウザ上で動くVS Code環境**です。アプリをインストールしなくても、ブラウザを開くだけでコードを編集できる便利な機能です。

### 🔌 拡張機能（エクステンション）とは？
VS Codeに後からインストールできる追加機能のことです。「プラグイン」とも呼ばれ、便利な機能を後から追加できますが、悪意のあるものをインストールすると危険です。

## 何が起きたのか

セキュリティ研究者のAmmar Askar氏が、**VS Codeのブラウザ版（GitHub.dev）に深刻な脆弱性（セキュリティの欠陥）**を発見しました。

> 💀 **たった1回リンクをクリックするだけで、あなたのGitHub OAuthトークンが盗まれる可能性がある**

このトークンが盗まれると、攻撃者はあなたの**すべてのリポジトリ（非公開のものも含む）**を自由に読んだり書き換えたりできてしまいます。

### 発見から公開までの経緯

| 日時 | 出来事 |
|------|--------|
| 2026年6月2日 | 研究者がGitHub（Microsoft）に脆弱性を報告 |
| 報告の約1時間後 | 研究者が脆弱性の詳細を**一般公開** |
| 記事執筆時点 | Microsoftが脆弱性を認め、修正作業中と発表 |
| その後 | Microsoftが「修正完了、ユーザー対応不要」と発表 ✅ |

⚠️ 報告からわずか1時間で公開されたのは異例で、研究者が「Microsoftの過去の対応を信頼できなかった」と説明しています。

## 技術的な詳細

少し難しいですが、できるだけわかりやすく説明します！

### 攻撃の全体像を「合鍵泥棒」に例えると…

```
🏠 あなたの家（GitHubアカウント）
  └── 合鍵（OAuthトークン）を持って
      └── コンビニ（GitHub.dev）に入ろうとした瞬間
          └── 扉の隙間から悪人が合鍵をコピーした！
```

### 攻撃のステップ（技術的な仕組み）

**① 悪意のあるリンクをクリックさせる**

攻撃者が用意した特別なリンクをクリックすると、GitHub.dev（ブラウザ版VS Code）が開きます。

**② Webview（ウェブビュー）の悪用**

VS Codeには「Webview」と呼ばれる、ブラウザの画面内にさらに小さなブラウザを表示する仕組みがあります（マークダウン（文書形式）のプレビューなどに使われます）。

本来は安全なサンドボックス（隔離された箱）の中で動くはずですが、**この箱とメインの画面の間で情報をやり取りする仕組みに抜け穴がありました**。

**③ 攻撃者の悪質なコードが動く**

```
悪意のあるWebview内のJavaScript（プログラム）が...
  └── キーボード操作を「偽造」する
      └── Ctrl+Shift+P（コマンドパレットを開くショートカット）を自動実行
          └── 攻撃者が用意した悪意のある拡張機能をインストール
              └── OAuthトークンを盗み出す！
```

**④ 信頼チェックを巧みにすり抜ける**

通常、知らない開発者の拡張機能をインストールしようとすると「本当に信頼しますか？」という確認画面が出ます。しかし、**「.vscode/extensions」という特定のフォルダに拡張機能を置いておくと、この確認画面をスキップできる**という別の仕組みが悪用されました。

**⑤ 全リポジトリへのアクセス**

盗んだトークンは特定のリポジトリ専用ではなく、**あなたがアクセスできる全リポジトリに使える**ものでした。そのため被害が非常に大きくなります。

## なぜ重要なのか

### 👤 一般ユーザーへの影響

- 自分のプログラムを勉強用に保存している人でも、**プライベートリポジトリが丸見えに**なる可能性
- コードの中にパスワードやAPIキー（他サービスへのアクセス権）が含まれていた場合、**連鎖的に被害が拡大**する

### 🏢 企業・プロ開発者への影響

- **企業の機密ソースコード**（製品の設計図）が盗まれる
- **社内システムのセキュリティ情報**が漏洩する
- サプライチェーン攻撃（ソフトウェアの部品を汚染して広範囲に被害を出す攻撃）に悪用される可能性

### 📊 影響の深刻さ

| 項目 | 内容 |
|------|------|
| 攻撃の難しさ | **非常に簡単**（リンクを1回クリックするだけ） |
| 被害の範囲 | **全プライベートリポジトリ** |
| 被害者が気づきにくい | **バックグラウンドで静かに動作** |

## 対策・今後の展望

### ✅ 現状：Microsoftが修正完了

記事の最後にあるように、Microsoftはすでにこの脆弱性を修正しました。

> 「この問題はサービス側で対処しました。ユーザー側での対応は不要です」
> — Microsoft広報

つまり、**今すぐ特別な対応は必要ありません**。

### 🛡️ ただし、今後のために覚えておきたい対策

1. **知らないリンクは不用意にクリックしない**
   - 「ちょっとこのリポジトリ見てみて！」系のリンクは特に注意

2. **VS Code拡張機能は信頼できるものだけインストール**
   - ダウンロード数や評価を確認する習慣を

3. **GitHubのセキュリティ設定を定期的に確認**
   - [Settings → Developer settings → OAuth Apps] で不審なアプリがないか確認

4. **デスクトップ版のVS Codeを使う**
   - 今回の脆弱性はブラウザ版（GitHub.dev）のみの問題。デスクトップ版は影響なし

5. **2段階認証（2FA）を必ず設定**
   - トークンが盗まれた場合でも、追加の防御層になる

## 過去記事との関連

以前、「**偽サイトがGoogleで上位表示されてマルウェアを配布する詐欺**」や「**悪意のあるGoogle・YouTube広告でMacにバックドアを仕込む攻撃**」について解説しました。

今回の攻撃と共通しているのは、**「普段使っているサービスや画面を信用させて攻撃する」という手口**です。

```
過去の事例：  「本物そっくりのサイト」や「広告」を信用させる
今回の事例：  「普段使っているVS Code/GitHub.dev」の画面を信用させる
```

攻撃者はますます**「日常的に信頼しているもの」を踏み台にする**ようになっています。どんなに使い慣れたツールやサービスでも、「おかしいな」と感じたら立ち止まる習慣が大切です。

## 用語解説

| 用語 | 説明 |
|------|------|
| **VS Code** | Microsoftが作った無料のコードエディタ。世界中の開発者が使用 |
| **GitHub** | プログラムのコードを保存・管理するサービス |
| **OAuth トークン** | サービスへのアクセスを証明するデジタルな合鍵 |
| **リポジトリ（リポ）** | GitHubでコードを管理する単位（フォルダのようなもの） |
| **GitHub.dev** | ブラウザ上で動くVS Codeの軽量版 |
| **拡張機能（エクステンション）** | VS Codeに追加インストールできる機能パーツ |
| **Webview** | アプリの画面内に表示される小さなブラウザ領域 |
| **JavaScript** | ウェブページを動かすためのプログラミング言語 |
| **コマンドパレット** | VS Codeで各種コマンドを検索・実行できるツール（Ctrl+Shift+Pで開く） |
| **サンドボックス** | 他の領域に影響を与えないよう隔離されたプログラム実行環境 |
| **脆弱性** | システムやソフトウェアにあるセキュリティ上の欠陥・弱点 |
| **サプライチェーン攻撃** | ソフトウェアの部品や配布経路を汚染して広範囲に被害を出す攻撃 |
