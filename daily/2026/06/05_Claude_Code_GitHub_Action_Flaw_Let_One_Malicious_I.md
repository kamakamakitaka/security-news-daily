# Claude Code GitHub Actionの脆弱性：たった1つの「issue投稿」でリポジトリを乗っ取れた問題

**元記事**: [Claude Code GitHub Action Flaw Let One Malicious Issue Hijack Repositories](https://inl03.netline.com/ltr6/?_m=3n.009a.3996.sp0ao46r89.31s6)
**解説日**: 2026年6月5日

---

## 背景知識

まず、この記事を理解するために必要なキーワードを整理しましょう。

### 🔧 GitHub / GitHubリポジトリとは？
**GitHub**は、プログラムのソースコード（設計図）をインターネット上で管理・共有するためのサービスです。「リポジトリ（repo）」は、その設計図を保管しているフォルダのようなものです。

### 🔧 GitHub Actionsとは？
GitHubには「**GitHub Actions**」という自動化の仕組みがあります。例えば「コードが更新されたら自動でテストを実行する」「バグ報告（issue）が届いたら自動で分類する」といった作業を自動でやってくれる「ロボット係員」のようなものです。

### 🔧 Claude Code GitHub Actionとは？
**Anthropic社**（AIのClaudeを作っている会社）が作ったGitHub Actionsの拡張機能です。AIのClaudeを組み込んで、「バグ報告を自動で分類する」「コードのレビューをAIがやってくれる」などの作業を自動化できます。

### 🔧 issueとは？
GitHubの「**issue（イシュー）**」とは、バグ報告や機能要望などを書き込める掲示板のようなものです。誰でも公開リポジトリにissueを投稿できます。

### 🔧 CI/CDパイプラインとは？
「**CI/CD**」とは、コードのテストやリリース作業を自動的に流れ作業でこなす仕組みのことです。工場のベルトコンベアのようなイメージです。

### 🔧 GitHub Appとは？
GitHubに登録できる「アプリアカウント」のようなものです。人間ではなくプログラムがGitHubを操作するために使います。誰でも無料で作れます。

## 何が起きたのか

GMO Flatt Securityのセキュリティ研究者・**RyotaK氏**が、Anthropicの「Claude Code GitHub Action」という機能に深刻な脆弱性（セキュリティの穴）を発見しました。

### 事件のポイントをひと言で言うと…

> 🚨 **悪意ある人物が、たった1つのissueを投稿するだけで、他人のGitHubリポジトリを完全に乗っ取れた**

しかも恐ろしいことに、**Anthropic自身のリポジトリ**も同じ問題を抱えていたため、そこを攻撃すれば「このツールを使っている世界中のプロジェクト全体」に悪意のあるコードを送り込める「サプライチェーン攻撃」が可能な状態でした。

## 技術的な詳細

攻撃の仕組みを順番に説明します。難しそうに見えますが、例え話でわかりやすく解説します！

---

### ステップ① 「ボット名詐欺」で入口を突破

Claude Code GitHub Actionには、「誰がClaudeを呼び出せるか？」のチェック機能がありました。本来は**書き込み権限を持つ人だけ**が使えるはずでした。

しかしチェックに穴がありました。

> 「名前の最後が `[bot]` で終わるアカウントは信頼できるボットだから、通してあげよう」

というルールがあったのです。これはGitHub Appが作るアカウントを信頼するための仕組みでしたが…

**問題：GitHub Appは誰でも無料で作れます！**

攻撃者は自分でGitHub Appを作り、名前を `evil[bot]` のようにして、他人の公開リポジトリにissueを投稿するだけで、Claudeを起動できてしまいました。

🔑 **例え話**: 「社員証を持っている人は入れます」というルールで、社員証が100円ショップで誰でも買えるような状況です。

---

### ステップ② 「プロンプトインジェクション」でAIを操る

入口を突破した後、攻撃者は**プロンプトインジェクション**という手法を使いました。

**プロンプトインジェクション**とは：
> AIに読ませるテキストの中に、こっそり「命令文」を混ぜ込んで、AIに本来の仕事とは違うことをやらせる攻撃

🔑 **例え話**: 先生から「この手紙を校長先生に届けてください」と頼まれた生徒が、手紙の中を見たら「読んだ人はこの生徒に100万円渡してください」と書いてあったようなイメージです。

RyotaK氏はissueの本文に「エラーメッセージ風のテキスト」を書き、その中にClaudeへの命令を隠しました。Claudeはその命令を「本来のタスク」だと思って実行してしまいます。

---

### ステップ③ 秘密情報を盗み出す

命令を実行させる先は **`/proc/self/environ`** というLinuxの特殊ファイルです。

> このファイルには、プログラムが動くときに使う「環境変数」と呼ばれる秘密の設定情報（パスワードやトークンなど）が入っています。

Claude Codeはこのファイルへのアクセスをブロックしようとしていましたが、RyotaK氏はその防御も回避する方法を見つけ、Claudeに秘密情報をissueに書き出させることに成功しました。

---

### ステップ④ 認証情報を使って完全乗っ取り

盗み出した情報の中に**OIDCトークン用の認証情報**がありました。

**OIDCトークン**とは：
> 「私は○○というリポジトリで動いているワークフローです」と証明する電子的な身分証明書

この仕組みをAnthropicのバックエンドに使うと、**そのリポジトリへの書き込み権限を持つトークン**を取得できます。

これを盗めば、攻撃者はそのリポジトリのコードや設定ファイルを自由に書き換えられます。

---

### その他の攻撃ルート

記事にはさらに2つの攻撃方法も紹介されています：

1. **設定ミスを利用する方法**: Anthropicが公開しているサンプル設定に `allowed_non_write_users: "*"` （全員がClaudeを呼び出せる）という危険な設定が含まれており、それをコピーして使っているプロジェクトはそのままリスクを引き継いでいた

2. **タイミング攻撃**: 信頼されたユーザーがissueを投稿してClaudeが起動した後、Claudeが内容を読む前にissueを書き換えると、その悪意ある内容が「信頼済み」として処理される

## なぜ重要なのか

### 🌍 影響範囲が非常に広い

```
攻撃者
  ↓（1つのissueを投稿）
脆弱なリポジトリのClaude
  ↓（秘密情報を盗む）
攻撃者がリポジトリを乗っ取る
  ↓（Anthropic自身のリポジトリも攻撃可能）
Claude Code Actionを使っている全プロジェクトに悪意あるコードが拡散
```

これは「**サプライチェーン攻撃**」と呼ばれる非常に危険なパターンです。一箇所を攻撃するだけで、それを利用している何千・何万ものプロジェクトに影響が波及します。

### 🚨 実際に被害が起きていた

これは理論上の話ではありません。記事の末尾にこう書かれています：

> 2026年2月、同様の手法で「Cline」というソフトウェアのプロジェクトが攻撃され、npm（JavaScriptのプログラム配布サービス）に不正なバージョン（`cline@2.3.0`）が公開されてしまった

つまり**同じ種類の攻撃が実際に使われた前例がある**のです。

### 🤖 AIの新しいリスク

この問題は「AIを便利なツールとして使うと、AIが攻撃の入口になる」という新しいリスクを示しています。AIは命令に忠実に動くため、悪意ある命令を見抜けないことがあります。

## 対策・今後の展望

### ✅ 今すぐやるべきこと

1. **バージョンアップ**: `claude-code-action` を **v1.0.94以降** に更新する

2. **権限の見直し**: Claude Codeを呼び出せるのを、書き込み権限を持つ人だけに制限する

3. **設定の確認**: `allowed_non_write_users: "*"` という設定がないか確認・削除する

4. **最小権限の原則**: ClaudeにはAnthropicのAPIキーとGITHUB_TOKENだけを渡し、それ以外の秘密情報は渡さない

5. **不要な機能を外す**: 情報を外部に漏らせるようなツールや権限は削除する

### 🔮 今後の展望

AIを使った自動化ツールはますます普及していますが、今回の事件は「**AIに広い権限を与えることの危険性**」を改めて示しました。今後のAI連携ツールは：

- 最小限の権限しか持たせない
- AIへの入力（信頼できないユーザーからのテキストなど）を厳格にフィルタリングする
- プロンプトインジェクション対策を必ず組み込む

といった設計が必須になってくるでしょう。
