# PCPJackが230台のクラウドサーバーを乗っ取り、こっそりメール送信ネットワークを構築

**元記事**: [PCPJack Hijacks 230 AWS, Google Cloud, and Azure Servers for Covert SMTP Relay Network](https://inl03.netline.com/ltr6/?_m=3n.009a.3996.sp0ao46r89.31ru)
**解説日**: 2026年6月6日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### ☁️ クラウドサーバーとは？
AWS（Amazon）・Google Cloud・Microsoft Azureは、世界中の企業が「インターネット上の仮想コンピューター」を借りられるサービスです。Netflixやスタートアップ企業など、大小問わず多くのビジネスがここでシステムを動かしています。

### 📧 SMTPとは？
**SMTP（Simple Mail Transfer Protocol）**は、メールを送信するための「郵便システムのルール」のようなものです。メールを送るとき、裏側では必ずこの仕組みが動いています。

### 🔁 SMTPリレーとは？
メールを「代わりに転送してあげる中継地点」のことです。正規の企業サーバーを中継点にすると、スパムフィルターに引っかかりにくくなります。これが今回悪用されたポイントです。

### 🎮 C2（コマンド＆コントロール）サーバーとは？
ハッカーが「乗っ取ったコンピューター群」に命令を送るための「司令塔」です。乗っ取られたコンピューターは定期的にここに「お伺い」を立て、命令を受け取ります。

---

## 何が起きたのか

**「PCPJack」というハッカー（グループ）が、世界中のクラウドサーバー230台をこっそり乗っ取り、大量メール送信の隠れネットワークを作り上げた**という事件です。

整理するとこうなります：

| 項目 | 内容 |
|------|------|
| 被害規模 | 230台のクラウドサーバー |
| 対象 | AWS・Google Cloud・Microsoft Azure上の企業サーバー |
| 被害地域 | アメリカ・ヨーロッパ・アジア |
| 発見者 | セキュリティ企業「Hunt.io」 |
| 発見のきっかけ | ハッカーが司令塔サーバーの2つのフォルダを「鍵なし（認証なし）」で公開していた |

> 🚨 つまり、ハッカー自身がうっかりドアを開けっぱなしにしていたため、発見されてしまいました！

## 技術的な詳細

少し詳しく、でもわかりやすく仕組みを説明します。

### ステップ①：サーバーへの侵入
PCPJackは**クラウドサービスの認証情報（ID・パスワード）を盗む専用ツール**を使い、企業のサーバーに不正ログインしました。このツールはセキュリティ企業のSentinelOneが2026年4月に最初に発見しています。

### ステップ②：隠れプログラムの設置
侵入後、サーバーに**隠しファイル（名前がドットで始まる `.xs` というファイル）**を仕込みました。ドット始まりのファイルはLinuxでは「隠しファイル」として扱われ、普通は見えません。まるで「見えないエージェントを送り込む」イメージです。

### ステップ③：定期的なお伺い（Beacon）
仕込んだプログラムは**Beacon（ビーコン）**と呼ばれ、定期的に司令塔サーバーに「チェックイン（報告）」します。GPSの発信機のようなものです。

```
乗っ取られたサーバー ──（5〜10分ごとに報告）──▶ 司令塔サーバー
                    ◀──（命令を受信）──────────
```

### ステップ④：メール送信能力のテスト
すべての乗っ取りサーバーが使えるわけではありません。プログラムは自動で「このサーバーはGmailのメールサーバーに接続できるか？」をテストし、**できないサーバーは使い物にならないとして除外**します。

> 🎯 まるでハッカーが「使えるバイトだけ採用する」ような選り好みをしているわけです。

### ステップ⑤：プロキシリストの更新・共有
使えると判断されたサーバーは**5分ごとに別のサーバーへ自動転送**されていました。誰かが常にこのリストを受け取って活用していたことになります。

## なぜ重要なのか

### 🔴 信頼できる企業サーバーが「踏み台」にされる
スパムメールや詐欺メールは通常フィルターで弾かれます。しかし、**正規の企業サーバーから送信されたように見せかけると、フィルターをすり抜けやすくなります**。これが最大の危険性です。

### 🔴 被害者が気づきにくい
乗っ取られた企業側は、サーバーがメール送信の踏み台にされていても気づきにくい状態でした。隠しファイルを使い、静かに動作するよう設計されていたためです。

### 🔴 目的はまだ不明
調査時点では、このメール送信ネットワークが**フィッシング詐欺・スパム広告・マルウェア配布のどれに使われるのか**は特定できていません。これが特に不気味な点です。

### 🔴 規模感
230台という数は、毎日何百万通ものメールを送れる規模です。

## 対策・今後の展望

### 企業・サーバー管理者ができること

- ✅ **クラウドの認証情報（ID・パスワード）を定期的に変更・強化する**
- ✅ **多要素認証（MFA）を必ず設定する**（パスワードだけでなく、スマホ認証などを追加）
- ✅ **サーバーのログ（操作記録）を定期的にチェックする**
- ✅ **不審な隠しファイル（ドット始まりの見慣れないファイル）がないか確認する**
- ✅ **`/var/tmp/` などの一時フォルダに不審なプログラムがないか監視する**

### 一般ユーザーができること

- ✅ **差出人アドレスが正規でも、不審なリンクはクリックしない**
- ✅ **急かすような内容のメール（「今すぐ確認！」など）は特に疑う**
- ✅ **メールのリンクは直接タイプするか、公式アプリ経由でアクセスする**

### 今後の展望
Hunt.ioはすでにこの情報を公開しており、関係するIPアドレスもセキュリティコミュニティで共有されています。ただし、**「誰がこのリストを受け取っていたのか」「何のために使われたのか」はまだ調査中**です。

## 用語解説

| 用語 | 意味 |
|------|------|
| **SMTP** | メールを送信するための通信ルール |
| **SMTPリレー** | メールを代わりに中継・転送する仕組み |
| **クラウドサーバー** | インターネット上に存在する仮想コンピューター |
| **C2サーバー** | ハッカーが乗っ取ったPCに命令を出す「司令塔」 |
| **Beacon（ビーコン）** | 定期的に司令塔に報告する仕込みプログラム |
| **Sliver** | オープンソースのハッキングフレームワーク（本来は研究用） |
| **Chisel** | ネットワークのトンネルを作るツール（正規ツールが悪用された） |
| **SOCKS5プロキシ** | インターネット通信を別のサーバー経由で行う仕組み |
| **SCP** | サーバー間でファイルを安全にコピーするプロトコル |
| **認証情報** | ログインに必要なIDやパスワードのこと |
| **多要素認証（MFA）** | パスワード＋別の認証手段を組み合わせるセキュリティ対策 |
| **ASN** | インターネット上のネットワーク識別番号 |
| **フィッシング詐欺** | 偽サイト・偽メールで個人情報を騙し取る詐欺 |
