# PCPJackが230台のAWS・Google Cloud・Azureサーバーを乗っ取り、隠密メール中継ネットワークを構築

**元記事**: [PCPJack Hijacks 230 AWS, Google Cloud, and Azure Servers for Covert SMTP Relay Network](https://inl03.netline.com/ltr6/?_m=3n.009a.3996.sp0ao46r89.31ru)
**解説日**: 2026年6月6日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### ☁️ クラウドサーバーとは？
AWS（Amazon）・Google Cloud・Microsoft Azureは、インターネット上に仮想的なコンピューターを貸し出すサービスです。世界中の企業がウェブサイトやアプリの運営にこれらを使っています。「クラウドサーバー」とは、この仮想コンピューターのことです。

### 📧 SMTPとメール中継とは？
**SMTP（Simple Mail Transfer Protocol）** はメールを送るための通信ルール（プロトコル）です。メールを送るとき、あなたのメールアプリは「SMTPサーバー」という中継地点を経由してメールを届けます。  
**メール中継（SMTP Relay）** とは、メールを別のサーバーを経由させて送る仕組みです。これを悪用すると、**送信元を偽ったスパムや詐欺メールを大量に送れてしまいます**。

### 🎭 C2サーバーとは？
**C2（Command and Control）サーバー** とは、ハッカーが乗っ取ったコンピューター群を遠隔操作するための「司令塔」です。軍隊の司令部のようなイメージです。

### 🔦 ビーコンとは？
乗っ取られたコンピューターにこっそり仕込まれた小さなプログラムで、定期的に「ただいま、指令ください」とC2サーバーに連絡を入れます。犬に付けるGPS首輪のようなものです。

## 何が起きたのか

**「PCPJack」と呼ばれるハッカー（グループ）が、米国・ヨーロッパ・アジアの企業が使うクラウドサーバー230台以上を密かに乗っ取り、大規模な「隠密メール送信ネットワーク」を作り上げていた**ことが発覚しました。

発見のきっかけは**ハッカー自身のミス**でした。C2サーバー上に2つのフォルダーを**パスワードなしで公開状態**にしてしまい、セキュリティ企業「Hunt.io」がその中身を丸ごと確認できてしまったのです。フォルダーの中には、攻撃に使ったプログラムのソースコード、ツール、ログファイルなどが残っていました。

> 💡 **例えるなら…**  
> 銀行強盗の犯人が、自分の計画書・使った道具・犯行記録を全部入れた段ボール箱を、銀行の前に鍵もかけずに放置してしまったようなものです。

## 技術的な詳細

### 🛠️ どうやって攻撃した？

**① サーバーへの侵入**  
PCPJackはクラウドサービスを狙った**資格情報（ID・パスワード）窃取フレームワーク**を使い、企業のサーバーに不正侵入しました。2026年4月にセキュリティ企業「SentinelOne」が最初に発見しています。

**② ビーコンの埋め込み**  
侵入したサーバーに、**「.xs」という隠しファイル名**のビーコンプログラムをこっそり仕込みます。ファイル名の先頭に「.（ドット）」を付けることで、Linuxでは通常の操作では見えない隠しファイルになります。保存場所は `/var/tmp/.xs` です。

**③ メール送信能力のチェック**  
全ての乗っ取ったサーバーが使えるわけではありません。プログラムは自動的に「このサーバーはGmailのSMTPサーバー（smtp.gmail.com:587）に接続できるか？」をテストし、できないサーバーは**自動的に除外**します。  
つまり、**メールを送れるサーバーだけを厳選している**のです。

**④ プロキシネットワークの構築**  
選ばれたサーバーは「SOCKS5プロキシ」として設定され、**5分ごと**に別のサーバーへリストが同期されます。誰かがこのリストを受け取り、利用していたようです。

**⑤ 自動管理システム**  
C2サーバーでは「chisel_verifier.py」というPythonスクリプトが常時動いており、**60秒ごとに**各サーバーの状態を確認し、使えなくなったサーバーを自動的にリストから除外していました。まるで自動管理システムのようです。

### 🔢 ポート番号の割り当てが巧妙
各サーバーには **MD5ハッシュ（一種の計算式）** を使って固定のポート番号（10000〜14999の範囲）が割り当てられます。同じサーバーは常に同じポート番号を使うため、管理が簡単になっています。

### 📌 被害の深刻さ
| 項目 | 内容 |
|------|------|
| 乗っ取られたサーバー数 | **230台以上** |
| 対象クラウド | AWS・Google Cloud・Microsoft Azure |
| 被害地域 | **米国・ヨーロッパ・アジア** |
| 発見時の状況 | **まだ稼働中** |

### 😨 なにが怖いのか？

1. **企業が気づかないうちに「スパムの踏み台」にされる**  
   自分の会社のサーバーが、スパムメールや詐欺メールの送信に使われている可能性があります。送信元が正規企業のサーバーなので、スパムフィルターに引っかかりにくくなります。

2. **目的がまだ不明**  
   Hunt.ioは「最終的な目的は現時点では不明」と述べています。スパム送信なのか、フィッシング詐欺なのか、それとも別の攻撃なのか…用途がわからない分、余計に不気味です。

3. **230台はあくまで「確認できた分」**  
   実際にはもっと多くのサーバーが影響を受けている可能性があります。

## 対策・今後の展望

### 🏢 企業・クラウド管理者向け

- **📋 ログの定期確認**：サーバーに不審なファイル（特に `/var/tmp/` などの一時フォルダーにドットで始まる隠しファイル）がないか確認しましょう
- **🔑 認証情報の管理強化**：クラウドのID・パスワードが漏洩していないか確認し、多要素認証（MFA）を導入しましょう
- **📡 外部への通信監視**：サーバーがSMTPポート（587番など）に不審な接続をしていないか監視しましょう
- **🔍 EDRツールの導入**：不正なプロセスやファイルを自動検出するセキュリティツールを使いましょう

### 🧑‍💻 一般ユーザーへの影響

直接的な被害はありませんが、**このネットワークが詐欺メールやフィッシングメールの送信に使われた場合、あなたのメールボックスにも届く可能性があります**。

## 用語解説

| 用語 | 解説 |
|------|------|
| **SMTP** | メールを送るための通信ルール。郵便でいう「配送システム」のようなもの |
| **SMTP Relay（メール中継）** | メールを別のサーバーを経由して送る仕組み。悪用されるとスパム送信に使われる |
| **C2サーバー** | 乗っ取ったコンピューターを遠隔操作するための「司令塔」サーバー |
| **ビーコン（Beacon）** | 乗っ取られたPCに仕込まれ、定期的にC2サーバーに連絡するプログラム |
| **Sliver** | オープンソースのC2フレームワーク。本来はセキュリティテスト用だが攻撃にも悪用される |
| **SOCKS5プロキシ** | 通信を中継する仕組み。送信元IPアドレスを隠せるため悪用されやすい |
| **Chisel** | ネットワークトンネリングツール。ファイアウォールを迂回するのに使われる |
| **MD5ハッシュ** | データから固定長の「指紋」のような数値を生成する計算方法 |
| **SCP（Secure Copy Protocol）** | 暗号化されたファイル転送プロトコル |
| **ASN** | インターネット上のネットワークを識別する番号 |
| **資格情報（クレデンシャル）** | ログインに使うIDとパスワードのセット |
| **PCPJack** | 今回の攻撃を行ったとされるハッカー（グループ）の名称 |

> 今回の事件は「クラウドサーバーのセキュリティ管理の甘さ」が狙われた典型例です。企業がクラウドを便利に使う一方で、適切な管理をしないと「知らないうちに犯罪の踏み台にされる」リスクがあることを示しています。ハッカーのミスで発覚しましたが、このような攻撃の多くは長期間気づかれないまま継続します。
