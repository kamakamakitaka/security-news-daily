# AIエージェントがFFmpegで21件のゼロデイ脆弱性を発見！Chromeも過去最多429件のバグを修正

**元記事**: [AI Agent Uncovers 21 Zero-Days in FFmpeg; Chrome Patches Record 429 Bugs](https://inl03.netline.com/ltr6/?_m=3n.009a.3997.sp0ao46r89.31t2)
**解説日**: 2025年7月11日

---

## 背景知識

まず、この記事を理解するために必要なキーワードをおさえましょう。

### 🎬 FFmpegって何？

**FFmpeg（エフエフエムペグ）** は、動画や音声を処理するための「縁の下の力持ち的なソフトウェア」です。YouTubeの動画変換、VLCメディアプレーヤー、Zoom、Discord、さらにはスマートテレビや監視カメラのソフトウェアなど、**世界中のほぼすべての動画・音声を扱うシステムに組み込まれています**。

> 🏠 例え話：FFmpegは「見えない厨房」のようなもの。レストランで料理が出てくる裏では厨房が動いていますが、客席から見えない。同様に、動画を再生するたびに裏でFFmpegが働いているのに、ほとんどのユーザーはその存在を知りません。

### 🌐 Google Chromeって何をするソフト？

言わずと知れたWebブラウザ。世界シェア約65%を占める、最も使われているブラウザです。

### 🤖 AIエージェントって何？

普通のAI（ChatGPTのように質問に答えるもの）と違い、**自分で考えて、自分で行動して、タスクを達成する自律型AI**のことです。プログラムのコードを自動で読み込み、危険な箇所を探し出す、いわば「AIの自動セキュリティ検査員」です。

### 🔒 ゼロデイ脆弱性って何？

**ゼロデイ（Zero-Day）** とは、ソフトウェアの開発者がまだ気づいていない（修正プログラムが「0日分」しかない）セキュリティの穴のことです。

> 🏚️ 例え話：家の鍵が古くて実は外から簡単に開けられる欠陥があったとします。でも家主はそれを知らない。この「知られていない欠陥」がゼロデイです。泥棒（ハッカー）に先に見つかったら大変なことになります。

## 何が起きたのか

今週、セキュリティ界隈で2つの大きなニュースがほぼ同時に飛び込んできました。

### 📌 ニュース1：AIが約1,000ドル（約15万円）でFFmpegの「21個の知られていない穴」を発見

セキュリティスタートアップ企業 **depthfirst（デプスファースト）** が開発した自律型AIエージェントが、FFmpegの約150万行（！）に及ぶプログラムコードを自動でスキャン。その結果、**誰も気づいていなかった21個のゼロデイ脆弱性**を発見しました。

驚くべき点はそのコストです。この作業にかかった費用は **約1,000ドル（約15万円）** 。セキュリティの専門家チームを雇って同じ調査をしたら、数百万〜数千万円かかることを考えると、桁違いの安さです。

さらに驚くのは「発見された穴の古さ」。

| 脆弱性 | 存在していた期間 |
|--------|-----------------|
| 最も古いもの | **2003年から22〜23年間！** |
| 一般的なもの | 15〜20年間 |

20年以上、誰にも気づかれずに潜んでいた穴が、AIによって数日で発見されたわけです。

---

### 📌 ニュース2：Chrome 149が過去最多429個のバグを一度に修正

Googleが公開した **Chrome バージョン149** には、**429個のセキュリティバグの修正**が含まれています。これは一度のリリースで修正した件数として**過去最多記録**です。

そのうち100件以上が「緊急（Critical）」または「重大（High）」レベル。

最も深刻な脆弱性（CVE-2026-10881）は**CVSS（危険度スコア）が9.6/10.0**という超高評価で、Googleはこれを発見した研究者に **97,000ドル（約1,400万円！）** の報奨金を支払っています。

## 技術的な詳細

### 🔍 FFmpegで見つかった脆弱性の種類

今回発見されたバグのほとんどは **「ヒープ/スタックオーバーフロー」** と呼ばれる種類のものです。

> 📦 例え話：コップ（メモリの決められた領域）に水（データ）を注ぐとき、コップからあふれた水が隣のコップ（関係ない領域）に流れ込む現象です。攻撃者はこの「あふれた水」を悪意のある命令に置き換えることで、パソコンを乗っ取ることができます。

影響を受けるのは以下のような部分：
- **TSデマルチプレクサ**（テレビの放送信号の解析部分）
- **VP9デコーダ**（YouTubeなどでよく使われる動画形式の処理部分）
- **H.264パーサー**（最もポピュラーな動画圧縮形式の処理部分）

特に危険なのは、**信頼できない送信元からのRTSP（ネットカメラのライブ映像ストリーミング）やAV1形式の動画**を処理する場合。悪意のある動画ファイルを再生させるだけで、攻撃が成立する可能性があります。

---

### 🌐 Chromeの最悪の脆弱性

最も危険なChromeのバグ（CVE-2026-10881）は **「ANGLE グラフィックスエンジン」** という部分にある **「範囲外読み書き（Out-of-Bounds Read/Write）」** という脆弱性です。

> 🏰 例え話：Chromeにはウェブサイトを「お城の牢屋（サンドボックス）」の中に閉じ込めて、ホストのパソコンに悪さをさせない仕組みがあります。しかしこのバグを使うと、悪意あるウェブサイトが「牢屋を脱走」して、あなたのパソコン上で好き勝手なプログラムを実行できてしまいます。

### 🤖 なぜ今AIがセキュリティに使われているのか

| 人間の専門家 | AIエージェント |
|-------------|---------------|
| 150万行のコード解析に数ヶ月〜数年 | 数日〜数週間 |

別の研究では、AIエージェントが**Linuxカーネル（OSの核心部分）の100個の既知バグのうち半数以上の再現コードを自動生成**することに成功しており、従来の「ファジング（無数のランダム入力でテストする手法）」を上回る結果も出ています。

## なぜ重要なのか

### 📢 FFmpegはあなたの身近なデバイス「ほぼ全部」に入っている

- スマートフォン（動画再生アプリの多くが使用）
- スマートテレビ
- Webサービス（YouTube、Twitterなど）
- 監視カメラシステム
- Pythonのライブラリ（プログラマーがよく使う）
- Dockerコンテナ（サーバー上のアプリ）

つまり、**世界中の数十億台のデバイスやサービス**が影響を受け得ます。しかも20年以上前から存在するバグですから、すでに誰かに悪用されていた可能性もゼロではありません。

### ⚡ 「バグを見つけるコスト」が急激に下がっている

これが最も重要なポイントです。

- **以前**：ゼロデイ1件の発見 → セキュリティ専門家が数ヶ月かけて数百万円分の作業
- **現在**：AIで21件を一度に発見 → 約15万円・数日間

バグを見つけることが「安く・早く」なりました。しかしそれは悪意のあるハッカーにとっても同じです。**善意の研究者だけでなく、犯罪者もAIを使ってバグ探しをしている**可能性が高まっています。

## 対策・今後の展望

### ✅ あなたにできる対策

**Chromeユーザー（最優先！）**
```
Windows/macOS: Chrome 149.0.7827.53/54 に更新
Linux:         Chrome 149.0.7827.53 に更新
```
Chromeは設定 → ヘルプ → Google Chromeについて から確認・更新できます。**自動更新をオンにしておくのが最善策です。**

---

**FFmpegを使っているシステム管理者・開発者の方へ**

1. **OSのセキュリティアップデートを即座に適用する**（Ubuntu, Debian, CentOSなどのパッケージ更新）
2. **「隠れたFFmpeg」に注意！** システムパッケージだけでなく、以下にも古いFFmpegが埋め込まれていることがある：
   - Pythonのライブラリ（pipでインストールしたもの）
   - Dockerのコンテナイメージ
   - 家電製品（スマートテレビ、NAS、監視カメラ）

3. **特に危険な状況**：信頼できない送信元からの動画（RTSPストリーム、AV1動画）を処理しているサービスは優先的に対処する。

---

### 🔮 今後の展望：「AIとセキュリティ」の新時代

この記事が示している未来は明確です：

```
AIがバグを大量・高速・低コストで発見
        ↓
バグ報告の「洪水」が発生（Googleのバグ報奨金プログラムにも影響）
        ↓
人間のトリアージャー（報告の選別担当者）が追いつけない
        ↓
修正プログラムの配布・インストールも遅れがち
        ↓
その間にハッカーが悪用するリスク
```

Googleはすでに、AIが生成した大量の報告書に対応するため、**「長い解説文ではなく、簡潔な再現手順（PoC）を提出せよ」** という形にバグ報奨金プログラムを4月に改定しています。

セキュリティ業界全体が「AIのペースに追いつく体制」への移行を急いでいますが、**修正を実際に作って届けて・インストールさせる作業は、まだ主に人間の手に委ねられている**というジレンマが残っています。

## 過去記事との関連

今回の記事では、過去の関連事例として以下が紹介されています：

- **Google Big Sleep エージェント**：昨年（2024年）にもFFmpegのバグをAIで発見しており、FFmpegの公式セキュリティページに「BIGSLEEP」タグ付きで掲載されています。
- **Anthropic の Mythos モデル**：AIが約10,000ドル（約150万円）でFFmpegの16年前のH.264バグなどを発見し、FFmpeg 8.1に修正が取り込まれています。
- **Redisのゼロデイ**：ほんの数日前にも別の自律型AIツールが、オープンソースのデータベースソフト「Redis（レディス）」にバージョン7.2.0から2年以上潜んでいた深刻な脆弱性を発見したと報告されました。

これらはいずれも同じトレンドを示しています：**「AIによるバグ発見の民主化」が急速に進んでいる**ということです。

## 用語解説

| 用語 | 解説 |
|------|------|
| **FFmpeg** | 動画・音声処理の定番オープンソースライブラリ。世界中のほぼすべての動画関連ソフトに使われている |
| **ゼロデイ脆弱性** | 開発者がまだ知らない（修正が0日分しかない）セキュリティの穴 |
| **AIエージェント** | 指示を与えると自律的に考え・行動してタスクを完了する自律型AI |
| **ヒープオーバーフロー** | プログラムのメモリ領域「ヒープ」からデータがあふれ、別の領域を上書きしてしまうバグ |
| **スタックオーバーフロー** | メモリ領域「スタック」からデータがあふれるバグ。同様に悪用可能 |
| **CVE（シーブイイー）** | Common Vulnerabilities and Exposures の略。世界共通の脆弱性識別番号 |
| **CVSS（シーブイエスエス）** | 脆弱性の危険度を0〜10で表すスコア。9.6は「非常に危険」レベル |
| **PoC（ピーオーシー）** | Proof of Concept（概念実証）の略。「この脆弱性は本当に悪用できる」と示す実証コード |
| **サンドボックス** | 悪意あるプログラムを「箱の中」に閉じ込めてホストシステムを守る仕組み |
| **RTSP** | カメラのライブ映像などをネットワーク越しに送るプロトコル（通信規格）|
| **デマルチプレクサ（demuxer）** | 動画ファイルから映像・音声・字幕などを分離して取り出す処理部分 |
| **ファジング（Fuzzing）** | 大量のランダムなデータを入力してバグを探す従来型のテスト手法 |
| **トリアージ（Triage）** | 大量のバグ報告を優先度に従って選別・分類する作業 |
| **オープンソース** | ソースコード（設計図）が公開されていて誰でも使えるソフトウェア |

---

> 💡 **まとめ**：AIがセキュリティバグを「安く・速く・大量に」見つける時代が来ました。これは善意の研究者にも、悪意のあるハッカーにも同じことが言えます。私たちユーザーにできる最善策は、**Chromeや各種ソフトウェアを常に最新版に保つこと**。そして社会全体では、AIが見つけたバグを「人間が素早く修正・配布できる体制」を整えることが急務になっています。
