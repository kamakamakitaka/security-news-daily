# Wazuhを使ったフィッシングと内部脅威の検知

**元記事**: [Detecting Phishing and Insider Threats Using Wazuh](https://inl03.netline.com/ltr6/?_m=3n.009a.3997.sp0ao46r89.31te)
**解説日**: 2025年1月

---

## 背景知識

この記事を理解するために、まず3つの重要なポイントを押さえておきましょう。

### 🏢 現代の企業ネットワークのイメージ

企業のネットワークは、学校に例えるとわかりやすいです。

```
【学校(企業ネットワーク)のイメージ】

  外の世界
    ↓
 正門(ファイアウォール) ← ここで外部の不審者をブロック
    ↓
 校舎内(社内ネットワーク)
  ├── 職員室(機密データ)
  ├── 教室(一般業務システム)
  └── 生徒・先生(社員・契約社員)
```

**重要なポイント**: 正門を突破されなくても、**すでに中にいる人が悪いことをすることがある**のです。これが今回の記事の核心です。

### 🛡️ SIEMとは何か？

**SIEM（シーム）**とは「Security Information and Event Management（セキュリティ情報・イベント管理）」の略です。

> 📌 **超かんたん説明**: 学校中に設置された「監視カメラ+記録システム」のようなものです。誰がいつどこに入ったか、何を持ち出したか、不審な行動をしていないかを一か所で監視・記録します。

### 🔍 Wazuhとは？

**Wazuh（ワズー）**は、無料で使えるオープンソースのSIEMツールです。パソコンやサーバーの「ログ（行動記録）」を集めて、怪しい動きを自動的に見つけてくれます。

## 何が起きたのか

今回の記事は「事件が起きた」というニュースではなく、**現在進行形で企業が直面している2大脅威**と、その検知方法についての解説記事です。

### 2大脅威とは？

| 脅威 | 出どころ | 特徴 |
|------|---------|------|
| **フィッシング攻撃** | 外部の攻撃者 | メールなどで人をだます |
| **内部脅威** | 組織の内部の人 | すでに正規のアクセス権を持っている |

### 🚨 特に問題なのは「2つが重なるケース」

```
フィッシング攻撃
    ↓ パスワードを盗む
攻撃者が「正規ユーザー」として侵入
    ↓
内部脅威と区別がつかなくなる！
```

**つまり**: 外部の攻撃者が、内部の人に「なりすます」ことで、通常の監視をすり抜けてしまうのです。

## 技術的な詳細

### 📧 フィッシング攻撃の仕組み

フィッシング攻撃は「**人間の心理**」を利用します。ソフトウェアの弱点ではなく、**人間の弱点**を狙うのが特徴です。

```
【フィッシング攻撃の流れ】

Step 1: 偽メールの送信
  "Amazonカスタマーサービス"を装ったメールが届く
  （実際は攻撃者が送っている）
        ↓
Step 2: ユーザーが罠にはまる
  「緊急！アカウントが不正利用されています。
   今すぐこちらをクリック→[偽サイト]」
        ↓
Step 3: 情報の窃取
  偽サイトでIDとパスワードを入力してしまう
        ↓
Step 4: 侵入・拡大
  盗んだ情報で本物のシステムに侵入
  社内の他のシステムへ侵入を拡大（横展開）
  より強い権限を手に入れようとする（権限昇格）
```

#### フィッシングの特徴的なサイン
- 🔴 本物そっくりな偽ドメイン（例：`amazon.co.jp` → `amaz0n.co.jp`）
- 🔴 「今すぐ！」「緊急！」などの焦らせるメッセージ
- 🔴 クリックすると偽ログインページに飛ぶリンク
- 🔴 開くと自動的に悪意あるプログラムが動く添付ファイル

> 💡 **例え話**: フィッシングは、「銀行員のふりをした詐欺師が電話してきて、暗証番号を聞き出す」オレオレ詐欺に似ています。技術ではなく「人をだます」のがポイントです。

### 👤 内部脅威の仕組み

内部脅威は「**すでに中にいる人**」から発生するリスクです。

#### 内部脅威の2種類

```
【悪意のある内部脅威】
 元従業員や不満を持つ社員が意図的に情報を盗む・システムを壊す

【悪意のない内部脅威】
 うっかりフィッシングに引っかかった善意の社員
 セキュリティ知識が不足して機密データを誤って共有
```

#### 内部脅威の検知が難しい理由

```
通常の社員の行動:
  ├── ファイルにアクセスする → 普通の業務
  ├── データを変更する → 普通の業務
  └── 管理コマンドを実行する → 普通の業務（管理者なら）

問題のある社員の行動:
  ├── ファイルにアクセスする → 一見、普通の業務に見える
  ├── データを変更する → 一見、普通の業務に見える
  └── 管理コマンドを実行する → 一見、普通の業務に見える
```

**つまり**、個々の行動だけを見ていては判断できない。**「いつもと違うパターン」**を発見することが重要なのです。

#### 内部脅威の典型的なサイン
- 🔴 本来の業務と関係ない機密ファイルへのアクセス
- 🔴 深夜や休日など変な時間帯のログイン
- 🔴 見慣れない場所（国など）からのアクセス
- 🔴 急に管理者権限を使い始めた
- 🔴 ログ（記録）を消そうとした

---

### 🔍 Wazuhによる検知の考え方

Wazuhがやっていることを図で表すと：

```
【Wazuhの動き】

各パソコン・サーバーのログ ┐
ネットワークの通信記録     ├→ Wazuhが全部集める → パターン分析 → アラート発出
ユーザーのアクセス記録    ┘

例：
「Aさんが深夜2時に(←いつもと違う)
 海外からログインして(←いつもと違う)
 人事データベースにアクセスした(←Aさんの業務に無関係)」

→ 3つの「いつもと違う」を組み合わせて危険と判断！
```

## なぜ重要なのか

### 📊 フィッシングと内部脅威が危険な理由

1. **フィッシングは「人間」を狙う**
   - いくら高性能なセキュリティシステムを入れても、**人が騙されたら意味がない**
   - 技術が進化しても、人間の心理（信頼・焦り・恐怖）は変わらない

2. **内部脅威は「正規ユーザー」として動く**
   - 正規のIDとパスワードを使っているため、**普通のセキュリティをすり抜けてしまう**
   - 被害に気づくまでに時間がかかることが多い

3. **2つが組み合わさると特に危険**
   - フィッシング → パスワード盗取 → 内部脅威と化す
   - この経路が**現在最も多い攻撃パターンの一つ**

### 💼 実際の被害例（一般的なケース）

```
フィッシング攻撃でパスワードが盗まれる
        ↓
攻撃者が社内システムに「正規ユーザー」として侵入
        ↓
顧客情報・機密情報を盗む（情報漏洩）
        ↓
企業の信用失墜・巨額の損害賠償・法的責任
```

## 対策・今後の展望

### 🛡️ 個人レベルの対策

```
✅ メールのリンクをむやみにクリックしない
✅ 送信者アドレスをよく確認する
   （例: amazon@○○.co.jp の○○部分が怪しくないか）
✅ 急かすメッセージには要注意
✅ 二段階認証（2FA）を設定する
   （パスワードが盗まれても、もう一段階の確認が必要）
✅ 不審に思ったらIT部門に相談する
```

### 🏢 組織レベルの対策

| 対策 | 内容 |
|------|------|
| **SIEMの導入** | Wazuhなどで全ログを一元管理・監視 |
| **異常検知** | 「いつもと違う」パターンを自動検出 |
| **最小権限の原則** | 業務に必要な最低限のアクセス権だけ付与 |
| **定期的な訓練** | フィッシングメール訓練で社員の意識向上 |
| **ゼロトラスト** | 「社内だから安全」と思わず、常に確認する考え方 |

### 🔮 今後の展望

- **AI・機械学習**を使った異常検知がさらに進化
- 「**行動分析（UEBA）**」：ユーザーの行動パターンをAIが学習して異常を即検出
- フィッシングメール自体もAIで生成され、より巧妙になる「いたちごっこ」が続く

## 用語解説

| 用語 | 読み方 | 説明 |
|------|--------|------|
| **フィッシング** | - | 偽メール・偽サイトで情報を騙し取る攻撃 |
| **内部脅威** | ないぶきょうい | 組織の内部の人によるセキュリティリスク |
| **SIEM** | シーム | セキュリティログを一元収集・分析するシステム |
| **Wazuh** | ワズー | 無料で使えるオープンソースのSIEMツール |
| **クレデンシャル** | - | IDとパスワードなどの認証情報 |
| **ラテラルムーブメント（横展開）** | - | 侵入後に社内の他システムへ侵入を広げること |
| **権限昇格** | けんげんしょうかく | より強い管理者権限を不正に手に入れること |
| **マルウェア** | - | ウイルスなど悪意あるソフトウェアの総称 |
| **ゼロトラスト** | - | 「誰も信頼しない」を前提とするセキュリティの考え方 |
| **ログ** | - | システムの操作・アクセスの記録 |
| **二段階認証（2FA）** | - | パスワード以外にもう一つの確認（SMSコードなど）を要求する仕組み |
| **ソーシャルエンジニアリング** | - | 技術ではなく「人間」を騙して情報を得る攻撃手法 |

---

> 💬 **まとめ**: セキュリティの敵は「外からくるハッカー」だけではありません。**メールに騙された社員**も、**悪意を持った内部の人**も脅威です。Wazuhのような監視ツールで「いつもと違う行動」を早期に発見することが、現代のセキュリティ対策の鍵となっています。
