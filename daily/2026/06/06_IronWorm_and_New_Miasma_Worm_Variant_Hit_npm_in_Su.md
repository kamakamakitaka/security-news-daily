# IronWormとMiasmaワームの新変種がnpmを標的にしたサプライチェーン攻撃

**元記事**: [IronWorm and New Miasma Worm Variant Hit npm in Supply Chain Attacks](https://inl03.netline.com/ltr6/?_m=3n.009a.3997.sp0ao46r89.31tq)
**解説日**: 2025年6月9日

---

## 背景知識

まず、この記事を読むために必要な「基礎知識」を整理しましょう。

### 📦 npmとは？
**npm（Node Package Manager）** とは、プログラマーが使う「部品の通販サイト」のようなものです。アプリを作るとき、すべてを1から作るのは大変なので、誰かが作った便利なプログラム部品（パッケージ）をダウンロードして使います。世界中の開発者がこのnpmを使っており、数百万個ものパッケージが登録されています。

### 🔗 サプライチェーン攻撃とは？
「サプライチェーン」とは「供給の連鎖」という意味です。たとえば、スーパーの食品が「農家 → 工場 → 物流 → 店舗 → 消費者」と流れるように、ソフトウェアも「部品の作者 → npmレジストリ → 開発者 → ユーザー」と流れます。この**流通経路のどこかに毒を混ぜる攻撃**がサプライチェーン攻撃です。

> 🥪 **例え話**: コンビニのおにぎりの材料を作る工場に毒を混ぜれば、全国のコンビニのおにぎりが一度に危険になります。それと同じ発想です。

### 🐛 ワームとは？
**コンピューターワーム**とは、自分自身でコピーを作りながら次々と他のシステムへ広がるマルウェア（悪意のあるプログラム）です。人間が操作しなくても、自動的に感染を広げます。

### 🦀 Rustとは？
プログラミング言語の一種です。高速かつ検出が難しいプログラムを書けるため、攻撃者に悪用されることがあります。

## 何が起きたのか

今回、npmのエコシステム（npmを使った開発の世界）に**2種類の深刻な攻撃**が同時に発覚しました。

### 攻撃①：IronWorm（アイアンワーム）
- **「asteroiddao」というnpmアカウントが乗っ取られ**、50以上の正規パッケージに悪意のあるコードが仕込まれました
- このコードは開発者のパソコン上にある**あらゆる秘密情報を盗み出す**マルウェアです
- 盗んだ情報を使ってさらに次の被害者へと広がる**自己増殖型**の攻撃です

### 攻撃②：Miasma（ミアズマ）ワームの新変種
- **57個のnpmパッケージ**、286以上のバージョンにわたって感染が確認されました
- 以前から存在していたMiasmaワームの**新しい亜種（バージョンアップした悪いプログラム）**です
- 盗まれたデータは「liuende501」というGitHubアカウントに送られていました（現在は閉鎖）

## 技術的な詳細

### IronWormの仕組みを深掘り

```
[攻撃の流れ]
1. 攻撃者がnpmアカウント「asteroiddao」を乗っ取る
      ↓
2. 正規のパッケージに悪意のあるコードを混ぜて公開
      ↓
3. 開発者が「普通のパッケージ」だと思ってインストール
      ↓
4. インストール時に自動でマルウェアが起動
      ↓
5. 開発者のPCから秘密情報を根こそぎ盗む
      ↓
6. 盗んだ情報でGitHubにアクセスし、他のプロジェクトにも感染を広げる
```

#### 🎯 何を盗むのか？
IronWormは以下の情報を標的にしています（**86種類もの環境変数**を探します）：

| 対象 | 内容 |
|---|---|
| AIサービス | OpenAI、Claude（Anthropic）、Google Gemini のAPIキー |
| クラウドサービス | Amazon Web Services（AWS）の認証情報 |
| 開発ツール | Docker、Kubernetes、npmのトークン |
| 暗号資産 | Exodusウォレットのファイル |

> 🔑 **例え話**: 家の鍵束（各種サービスのパスワードやAPIキー）を全部まとめて盗まれるようなものです。

#### 🫥 見つかりにくくする技術
- **eBPF rootkit（カーネルルートキット）**: OSの最深部（核心部分）に隠れ、自分自身の存在を消します。セキュリティソフトからも見えなくなる非常に高度な技術です。
- **Tor（トーア）経由の通信**: 犯罪者への情報送信経路を匿名化し、追跡を困難にします。
- **「claude」になりすます**: GitHubへのコード変更（コミット）を、AIアシスタント「Claude」の作者名で登録することで、正規の作業に見せかけます。

#### 🔄 自己増殖の仕組み
1. 盗んだGitHubの認証情報を使い、開発者が管理するプロジェクトのコードを書き換える
2. GitHub Actionsのワークフロー（自動作業手順）を改ざんして、秘密情報をこっそり外部に送る
3. npmの「Trusted Publishing」という仕組みを悪用して、感染したパッケージをnpmに自動公開する
4. 次の開発者がそのパッケージを使い、また感染が広がる…

> 🔁 **例え話**: 感染した人が無意識のうちに他の人の飲み物にウイルスを入れ、次々と感染を広げるようなイメージです。

## なぜ重要なのか

### 💥 影響範囲が非常に広い
- npmは**世界中の開発者が毎日使う**インフラです。1つのパッケージが感染すると、それを使った何千・何万ものアプリケーションが影響を受けます
- 今回の攻撃は**57〜50以上のパッケージ**、**286以上のバージョン**に及んでいます

### 🤖 AIツールの認証情報も狙われている
- OpenAI、Claude、Gemini などのAPIキー（AIを使うための鍵）が標的になっています
- これらが盗まれると、**被害者のAI利用枠を悪用されたり、高額請求されたりする**可能性があります

### 😰 「信頼しているもの」が武器になる
- 開発者は「有名なパッケージだから安全」と信じてインストールします
- しかし今回は**その信頼が悪用**されました。正規のパッケージに毒が混入されているため、注意しても防ぎにくいのです

### 🔍 発見が極めて困難
- eBPF rootkitによってプロセスが隠蔽されるため、感染に気づきにくい
- GitHubへの変更も「Claudeが書いたコード」に見せかけられている

## 対策・今後の展望

### 開発者ができる対策

#### ✅ パッケージの確認
- npmパッケージをインストールする前に、**公開日時や作者の信頼性**を確認する
- 突然バージョンが増えたパッケージには注意する
- `npm audit`コマンドで既知の脆弱性を定期的にチェックする

#### ✅ 認証情報の管理
- APIキーやパスワードは**ソースコードに直接書かない**
- 定期的にAPIキーをローテーション（更新・無効化）する
- 不審なアクセスがないか、各サービスのログを定期確認する

#### ✅ 開発環境の保護
- カーネルロックダウン（OSのセキュリティ機能）を有効にすることで、eBPF rootkitの一部機能を無効化できる
- 最小権限の原則（必要最低限の権限しか与えない）を守る

#### ✅ GitHub/CIの設定
- GitHub Actionsのワークフローを定期的に見直す
- 見覚えのないコミットがないか確認する
- Trusted Publishingの設定を適切に管理する

### 今後の展望
- JFrog、Endor Labs、StepSecurityなどのセキュリティ企業が**supply chain攻撃の監視を強化**しています
- npmやGitHubのプラットフォーム側でも不審なパッケージの検出・削除が進んでいます
- ただし攻撃者も手法を進化させており、**いたちごっこ**の状態が続いています

## 用語解説

| 用語 | 解説 |
|---|---|
| **npm** | JavaScriptのプログラム部品を管理・配布するシステム。世界最大のパッケージレジストリ |
| **サプライチェーン攻撃** | ソフトウェアの流通経路に悪意のあるコードを混入させる攻撃 |
| **マルウェア** | 悪意を持って作られたプログラムの総称（ウイルス・ワーム等） |
| **ワーム** | 自己増殖しながら広がるマルウェアの一種 |
| **情報窃取ツール（Infostealer）** | パスワードやAPIキーなどの秘密情報を盗むマルウェア |
| **Rust** | 高速・高安全性のプログラミング言語。マルウェアにも悪用される |
| **APIキー** | クラウドサービスやAIを使うための「合言葉（認証キー）」 |
| **eBPF rootkit** | OSの核心部（カーネル）に隠れるマルウェア。発見が非常に困難 |
| **Tor** | 通信を匿名化するネットワーク。犯罪者の隠れ蓑に使われることがある |
| **GitHub Actions** | コードの変更に応じて自動でビルド・テストなどを行う仕組み |
| **Trusted Publishing** | npmが提供するCI環境からの安全なパッケージ公開の仕組み（悪用された） |
| **環境変数** | プログラムが動く環境の設定情報。パスワードやキーが保存されることが多い |
| **CI環境** | Continuous Integration（継続的統合）。コードの自動テスト・ビルド環境 |
| **Trojanized（トロイの木馬化）** | 正規のソフトウェアに見せかけて悪意のあるコードを埋め込むこと |
| **exfiltration（データ流出）** | 盗んだデータを攻撃者のサーバーへ送信すること |

---

> 💡 **まとめ**: 今回の攻撃は「信頼されているソフトウェアの部品に毒を混ぜる」という非常に巧妙な手口です。開発者だけでなく、そのソフトを使う一般ユーザーにも影響が及ぶ可能性があります。「有名なパッケージだから安全」という思い込みが最大の危険であることを覚えておきましょう。
