# VS CodeがExtension自動更新を2時間遅らせてサプライチェーン攻撃を防ぐ機能を追加

**元記事**: [VS Code Adds 2-Hour Extension Auto-Update Delay to Limit Supply Chain Attacks](https://inl03.netline.com/ltr6/?_m=3n.009a.3998.sp0ao46r89.31um)
**解説日**: 2025年7月11日

---

## 背景知識

まず、このニュースを理解するために必要な基礎知識をおさえましょう！

### VS Code（Visual Studio Code）って何？
Microsoftが作った**無料のコードエディター（プログラムを書くためのアプリ）**です。世界中のプログラマーが愛用しており、「拡張機能（Extension）」と呼ばれる追加パーツをインストールすることで、自分好みにカスタマイズできます。

例えるなら、スマートフォンに**アプリを追加**するようなイメージです。

### 拡張機能（Extension）って何？
VS Codeに機能を追加するための**プラグイン（追加パーツ）**です。「日本語化する機能」「Pythonのコードをきれいに整える機能」など、何千種類ものExtensionがあります。

### ソフトウェアサプライチェーン攻撃って何？
これが今回のニュースの**キーワード**です！

「サプライチェーン」とは、もともと製品を作る→運ぶ→届けるまでの流れのこと。それがソフトウェアの世界では、**「ソフトが開発されてユーザーの手元に届くまでの流れ」**を指します。

攻撃者はこの流れのどこかに**こっそりマルウェア（悪意あるプログラム）を混入**します。

> 🍱 **たとえ話で理解しよう！**
> お弁当工場(開発者)が作ったお弁当(ソフト)が、コンビニ(配布サービス)を経由してあなた(ユーザー)に届く途中で、悪者が**こっそり毒を入れる**ようなイメージです。あなたは「正規のお弁当だ！」と思って食べてしまう…。

---

## 何が起きたのか

Microsoftは、**VS Code バージョン1.123**から、拡張機能（Extension）の**自動更新に2時間の「待ち時間」を設ける**新機能を追加しました！

具体的には：

- 🕐 新しいバージョンのExtensionが公開されてから、**2時間後**に自動更新が適用される
- ⚡ 手動で「今すぐ更新」ボタンを押せば、即時更新も可能
- 🔵 Microsoft・GitHub・OpenAIなどの**信頼できる大手パブリッシャー（公開者）**のExtensionは、これまで通り即時更新される
- 📋 更新待ちのExtensionは、「なぜまだ更新されていないか」と「いつ自動更新されるか」が画面上で確認できる

---

## 技術的な詳細

### なぜ「2時間の待ち時間」が有効なのか？

攻撃の流れを追ってみましょう👇

```
①悪意ある攻撃者がExtensionに
　マルウェアを仕込んで公開
        ↓
②すぐに自動更新が走ると…
　→ 何百万人ものユーザーに
　　悪意あるコードが届いてしまう！
        ↓
③セキュリティ研究者や
　レジストリ管理者が気づいて
　削除・修正するまでに時間がかかる
```

ここで**2時間の待ち時間**を挟むと…

```
①悪意あるExtensionが公開される
        ↓
②2時間の待ち時間（バッファー）
        ↓
③その間にセキュリティチームが
　問題を発見・報告・削除できる！
        ↓
④ユーザーには悪意あるバージョンが
　届かずに済む 🎉
```

> 🛡️ **ポイント**: 2時間という時間は「問題を発見して対応するための猶予（ゆうよ）時間」として機能します。完全な防御ではありませんが、被害を大幅に減らせます。

### 同様の動きが他のツールでも！

実は同じような「インストール待ち時間」機能が、他のパッケージ管理ツール（プログラムの部品を管理するツール）にも続々と追加されています：

| ツール名 | 設定名 | 対応バージョン |
|---------|--------|--------------|
| **npm** | min-release-age | v11.10.0以上 |
| **pnpm** | minimumReleaseAge | 10.16以上 |
| **Bun** | minimumReleaseAge | 1.3以上 |
| **Yarn** | npmMinimalAgeGate | Berry 4.10.0以上 |
| **RubyGems** | クールダウン機能 | Bundler 4.0.13以上 |

業界全体で「リリース直後のインストールを少し待つ」という防衛戦略が広まっています！

## なぜ重要なのか

### 影響範囲が非常に大きい

VS Codeは世界中で**数千万人のプログラマー**が使っています。もしExtensionにマルウェアが混入されると：

- 😱 開発者のPCが乗っ取られる
- 💻 作成中のアプリに悪意あるコードが埋め込まれる
- 🌊 さらにそのアプリを使うユーザーにも被害が広がる（これがまさにサプライチェーン攻撃！）

### 実際に過去に起きた事件

ソフトウェアサプライチェーン攻撃は**現実の脅威**です。近年、悪意あるパッケージが公開されてから削除されるまでの**短時間に大きな被害**が出るケースが増加しています。

---

## 対策・今後の展望

### VS Codeユーザーができること

1. ✅ **VS Codeを最新バージョン（1.123以上）に更新する**
   → 自動的に2時間ディレイ機能が有効になります

2. 👀 **Extensionを追加する際は信頼性を確認する**
   → インストール数が多い・レビューが豊富・大手が作ったものを選ぼう

3. 🚫 **使っていないExtensionは削除する**
   → 攻撃面を減らすことができます

4. 📢 **怪しいExtensionを見つけたら報告する**
   → セキュリティチームの早期発見につながります

### 今後の展望

業界全体として、**「公開直後のソフトウェアは少し待つ」**という文化が根付きつつあります。これは：

- 攻撃者にとっては「悪意あるコードが広まる時間が短くなる」
- セキュリティチームにとっては「問題を発見・対応する時間が増える」

という、とても合理的な防衛策です。今後も同様の機能を持つツールが増えていくでしょう。

## 過去記事との関連

今回取り上げた記事の中でも触れられていますが、RubyGems（Rubyというプログラミング言語のパッケージ管理システム）も最近同様の「クールダウン（待ち時間）機能」をBundler 4.0.13で追加しました。npmやYarnなどのJavaScript系ツールも同様の対策を追加しており、**業界全体でサプライチェーン攻撃への対策が急速に進んでいる**ことがわかります。これらは同じ問題意識（攻撃者が公開直後の短時間を狙う）に対する同じアプローチ（少し待つ）と言えます。

## 用語解説

| 用語 | 意味 |
|------|------|
| **VS Code（Visual Studio Code）** | Microsoftが作った無料のコードエディター（プログラムを書くアプリ） |
| **拡張機能（Extension）** | VS Codeに機能を追加するプラグイン（追加パーツ） |
| **サプライチェーン攻撃** | ソフトウェアが開発・配布される流れのどこかに悪意あるコードを混入させる攻撃 |
| **マルウェア** | 悪意を持って作られたプログラムの総称（ウイルスなども含む） |
| **自動更新（Auto-Update）** | ソフトウェアが新しいバージョンに自動的に切り替わる機能 |
| **パッケージ管理ツール** | プログラムの部品（パッケージ）を管理・インストールするツール |
| **npm / pnpm / Yarn / Bun** | JavaScriptのパッケージ管理ツールの名前 |
| **RubyGems / Bundler** | Rubyというプログラミング言語のパッケージ管理システム |
| **レジストリ** | パッケージ（ソフトの部品）が登録・管理されているデータベースのこと |
| **パブリッシャー** | Extensionやパッケージを公開・提供している人や組織 |
| **クールダウン / ディレイ** | 意図的に設けた「待ち時間」のこと |

> 💡 **まとめ**：VS Codeが「Extensionの自動更新を2時間遅らせる」機能を追加しました。これは「悪意あるコードが公開直後に世界中に広まる前に対処する時間を作る」という、シンプルながら効果的なセキュリティ対策です。業界全体でこの「少し待つ」アプローチが広まっており、開発者を狙ったサプライチェーン攻撃への防衛が強化されています。
