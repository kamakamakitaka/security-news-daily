# LLMエージェントを使ってSalesforceサイトを自動ハッキングしてみた

**元記事**: [Hacking Salesforce Sites With an LLM Agent](https://inl03.netline.com/ltr6/?_m=3n.009a.3999.sp0ao46r89.31w6)
**解説日**: 2025年6月10日

---

## 背景知識

このニュースを理解するために、まず3つのキーワードを押さえておきましょう。

### 🏢 Salesforceとは？
Salesforceは、企業が「顧客情報の管理」に使う世界最大級のクラウドサービスです。たとえば、ある会社が「お客さんの名前・電話番号・購入履歴」などを管理するのに使います。銀行、病院、大手ITメーカーなど、世界中の大企業が使っているため、**そこに保存されているデータは非常に機密性が高い**のです。

> 📌 「Salesforce Experience Cloud」は、Salesforceの機能を使って作った「外部向けWebサイト」のことです。ログインしていない一般の人もアクセスできる部分があります。

### 🤖 LLM（大規模言語モデル）とは？
ChatGPTやClaudeのような「AIと会話できるシステム」の中身です。テキストを理解して、推論し、文章や**プログラムコードも生成できます**。

### 🕵️ 「エージェント型AI」とは？
「1回の質問に答える」だけでなく、**自分でタスクを分解して、複数の行動を自律的に実行できるAI**のことです。たとえば「このサイトの弱点を探して」と指示すると、自分でサイトを調べ、弱点を分析し、攻撃コードまで書いて実行する、という一連の作業を人間なしでやってのけます。

---

## 何が起きたのか

セキュリティ企業「Reco」の研究チームが、**AIエージェントを使ってSalesforceのサイトを自動的にハッキングする実験**を行いました。

流れをざっくり言うと：

1. 「このURL（サイトのアドレス）を調べて」とAIに渡すだけ
2. AIが**完全自律で**サイトの弱点を探し、攻撃コードを書き、実際に実行
3. **実在する大企業のSalesforceサイトから、実際のデータを取得することに成功**

しかも、これは「やってはいけないこと」を示すための研究（ペネトレーションテスト＝侵入テスト）として行われており、結果は**「セキュリティにお金をかけている大企業のサイトでも、深刻な脆弱性が見つかった」**というものでした。

また、「ShinyHunters（シャイニーハンターズ）」というハッカー集団がすでに数千ものSalesforceサイトをスキャンしていたことも触れられており、**この手法は研究者だけでなく、実際の攻撃者にも使われつつある**ことが示されています。

## 技術的な詳細

AIエージェントは「5つのフェーズ」に分かれて動作します。人間のセキュリティ専門家が行う作業を、そのままAIが自動化したイメージです。

```
[URLを渡す] → Phase1 → Phase2 → Phase3 → Phase4 → Phase5
                ↑___________（必要に応じてやり直し）___________↑
```

### Phase 1: 偵察（サイトの地図を作る）

> 🗺️ 例え話：泥棒が家に入る前に「窓はどこ？鍵のかかっていないドアは？」と下調べするイメージ

AIは**URLだけを手がかりに**、Salesforceの「Auraフレームワーク」（Salesforceのサイトを動かす仕組み）に問い合わせて、以下を自動で調べます：

- **アクセスできるデータの種類**（顧客情報テーブル、取引記録テーブルなど）
- **サーバー側の処理メソッド**（どんな操作をサーバーに頼めるか）
- **公開されているページや書類**

これによって「攻撃できそうな場所の全体マップ」が完成します。

### Phase 2: データ分析（どこに価値あるデータがあるか）

次に、見つかったデータの種類を「機密度」で分類します。

| 優先度高（狙うべき） | 優先度低 |
|---|---|
| `Contact`（顧客連絡先） | `BlogPostEntry`（ブログ記事） |
| `Lead`（見込み客情報） | `HelpArticle`（ヘルプ記事） |
| `CreditCardTransaction`（クレジットカード取引） | など |

AIは「これは機密性が高いデータだ」と**自分で判断**して、優先的に調べる対象を絞り込みます。さらに、ログインしていないゲストユーザーとして実際にデータを取得できるか試みます。

### Phase 3〜5（記事の続き部分）

記事の全文は切れていますが、一般的にはこのあと：
- **脆弱性の特定**（どの穴が使えるか）
- **攻撃コードの自動生成**（ゼロから書いて実行）
- **検証**（本当にデータが取れたか確認）

というフェーズに続きます。

### 🔑 ポイント：なぜAIが強力なのか

```
従来のハッキングツール：決まったパターンしか試せない
　　　　　　　　　↓
AIエージェント：状況を見て「考え方を変えて」再チャレンジできる
```

たとえば「このやり方では取れなかった。じゃあ別のアプローチで」と**人間のように推論して戦略を変える**ことができます。これが従来の自動化ツールとの最大の違いです。

## なぜ重要なのか

### 📈 攻撃の敷居が劇的に下がった

これまで「高度なサイバー攻撃」には、豊富な専門知識が必要でした。しかし今や、**AIに「このサイトを調べて」と言うだけで、自動的に高度な攻撃が実行できる**時代になりつつあります。

> 🎮 例え話：格闘ゲームで「複雑なコンボ技」を覚えなくても、ワンボタンで最強技が出せるようになった、みたいなイメージです。

### 🏭 影響を受けるのは私たちにも身近な企業

Salesforceは世界中の大企業が使っています。もし脆弱性を悪用されると：

- 📋 顧客の個人情報（名前・住所・電話番号）の流出
- 💳 クレジットカード情報の漏洩
- 🤝 取引先の機密ビジネス情報の流出

などが起こり得ます。あなたが普段使っているサービスの運営企業も、被害者になる可能性があります。

### 🚨 すでに実際の攻撃者も動いている

記事の冒頭にある「ShinyHunters」は、実在するハッカー集団で、過去にも大規模な情報漏洩を起こしています。彼らがすでに数千サイトをスキャン済みというのは、「研究の話」ではなく「現実の脅威」です。

## 対策・今後の展望

### 企業側がやるべきこと

| 対策 | 説明 |
|---|---|
| **Salesforce設定の見直し** | ゲストユーザーが見えるデータを最小限に制限する |
| **定期的な侵入テスト** | 自分たちのサイトを自らハッキングして弱点を先に見つける |
| **AIによる防御側の強化** | 攻撃AIに対抗するために、防御側もAIを活用する |
| **アクセス権限の最小化** | 「必要な人だけが必要なデータにアクセスできる」設定を徹底 |

### 私たちができること

- 個人情報を入力するサービスが「信頼できる企業か」を確認する習慣
- 同じパスワードを使い回さない（情報漏洩時の被害を最小化）
- 不審なメール・連絡には応答しない（漏洩した情報を使ったフィッシング詐欺に注意）

### 今後の展望

「AIが攻撃する」「AIが防御する」という**AIどうしの戦い**の時代が本格的に始まっています。セキュリティ業界では今後、「AIエージェントを使った自動防御システム」の開発競争がさらに激化するとみられています。

## 用語解説

| 用語 | 意味 |
|---|---|
| **LLM（大規模言語モデル）** | ChatGPTやClaudeのような、テキストを理解・生成できるAIの一種 |
| **AIエージェント** | 目標を与えると、複数の行動を自律的に組み合わせて実行できるAI |
| **Salesforce** | 企業の顧客情報管理に使われる世界最大級のクラウドサービス |
| **Salesforce Experience Cloud** | Salesforceの機能を使って作った外部向けWebサイト |
| **Auraフレームワーク** | SalesforceのWebサイトを動かす仕組み（技術基盤） |
| **偵察（Reconnaissance）** | 攻撃前に対象の情報を収集する行為 |
| **脆弱性（ぜいじゃくせい）** | システムの弱点・穴のこと |
| **エクスプロイト** | 脆弱性を実際に攻撃するためのプログラム・手法 |
| **ペネトレーションテスト** | 許可を得た上で、自分のシステムをわざとハッキングして弱点を探すテスト |
| **ゲストユーザー** | ログインしていない状態でサイトにアクセスする一般利用者 |
| **ShinyHunters** | 大規模な情報漏洩を繰り返している実在のハッカー集団 |
| **Apex** | Salesforceのサーバー側処理を書くためのプログラミング言語 |
