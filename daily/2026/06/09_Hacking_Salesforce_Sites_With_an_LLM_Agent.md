# LLMエージェントを使ってSalesforceサイトをハッキングする

**元記事**: [Hacking Salesforce Sites With an LLM Agent](https://inl03.netline.com/ltr6/?_m=3n.009a.3999.sp0ao46r89.31w6)
**解説日**: 2025年6月9日

---

## 背景知識

まず、この記事を理解するためにいくつかの基本的な言葉を押さえておきましょう。

### Salesforce（セールスフォース）とは？
世界中の企業が使っている「顧客管理システム（CRM）」のクラウドサービスです。「どのお客さんに何を売ったか」「問い合わせの履歴」「個人情報」などを管理するデータベースとして、特に大企業でよく使われています。銀行・病院・ECサイトなど、あなたの個人情報を持っているかもしれない企業が多数利用しています。

### LLM（大規模言語モデル）とは？
ChatGPTやClaudeのような「AIチャット」の中核技術です。大量のテキストを学習して、人間のように文章を理解したり生成したりできます。最近は「ただ会話するだけ」でなく、コードを書いたりツールを操作したりできるようになっています。

### エージェント（AI Agent）とは？
「自律的に行動するAI」のことです。人間が一つひとつ指示しなくても、「目標」を与えるだけで自分で考えて行動し続けます。例えば「このサイトの弱点を全部見つけて攻撃して」と言うだけで、全部自動でやってくれるイメージです。

### Salesforce Experience Cloud（体験クラウド）とは？
Salesforceの機能の一つで、企業がお客さんや取引先向けに「外部公開サイト」を作れる仕組みです。ログインしなくても一部のデータにアクセスできる部分があるため、設定を間違えると情報漏えいの危険があります。

---

## 何が起きたのか

セキュリティ企業「Reco（リコ）」の研究チームが、**AIを使って完全自動でSalesforceサイトの脆弱性を発見・攻撃できるエージェントを開発しました**。

🔑 ポイントをざっくり言うと：

- URLを一つ渡すだけで、そのSalesforceサイトの弱点を**自動で全部見つけて、攻撃スクリプトまで書いて実行する**
- 人間のセキュリティ専門家がやるような調査・分析・攻撃を、**AIが全部ひとりでやる**
- 実際に**大手テクノロジー企業のサイト**に試したところ、セキュリティ投資をしている企業でも**深刻な脆弱性が見つかった**

また記事では、「ShinyHunters（シャイニーハンターズ）」という実際のハッカー集団がすでに数千ものSalesforceサイトをスキャンしていたことも明かされています。AIによる攻撃は「研究の世界の話」ではなく、**リアルな脅威として始まっている**ということです。

## 技術的な詳細

このAIエージェントがどうやって攻撃するのか、5段階に分けて解説します。

---

### 🔍 フェーズ1：偵察（Reconnaissance）― まず「どこが入り口か」を調べる

> 例え話：泥棒が家に入る前に「窓はどこか」「鍵がかかっていない扉はどこか」と外から観察するイメージ

AIはURLだけを手がかりに、Salesforceの「Auraフレームワーク」という仕組みを使って、サイトが外部に公開している情報をすべて調べます。

- 📋 どんなデータベースのテーブルが存在するか（例：「顧客」「注文」「クレジットカード」など）
- ⚙️ サーバー側でどんな処理が動いているか（Apexコントローラーメソッド）
- 🗺️ どんなページやファイルが公開されているか

これらをまとめた「攻撃マップ」を自動で作成します。

---

### 📊 フェーズ2：オブジェクト分析 ― どのデータが危険か優先順位をつける

> 例え話：見つけた部屋のうち「金庫室」「書類室」「物置」を区別して、価値があるものから調べるイメージ

AIは見つけたデータベースのテーブルを「どれだけ機密性が高いか」で自動分類します。

| 優先度 高 | 優先度 低 |
|-----------|-----------|
| `Contact`（個人情報） | `BlogPostEntry`（ブログ投稿） |
| `Lead`（見込み客情報） | `HelpArticle`（ヘルプ記事） |
| `CreditCardTransaction`（クレカ取引） | `PublicAnnouncement`（お知らせ） |

機密性の高いテーブルに対して、**ゲストユーザー（ログインしていない状態）でもデータが取得できるか**を試します。

---

### 💣 フェーズ3〜5：脆弱性の発見・攻撃スクリプトの作成・実行

AIは以下を自動でこなします：

1. **脆弱なエンドポイントを特定**（「ここは認証なしでアクセスできる！」）
2. **攻撃コード（エクスプロイト）をゼロから自動生成**
3. **実際に実行してデータを盗み出す**
4. **必要なら公開情報（ネット上のデータ）も使って攻撃の精度を上げる**

さらに驚くべきは、**AIが自分で判断して「もう一度やり直す」「別のアプローチを試す」** という柔軟な思考をすることです。固定のプログラムではなく、まるで本物のハッカーのように状況に応じて戦略を変えます。

## なぜ重要なのか

### 😰 「難しすぎる攻撃は実行できない」という常識が崩れた

これまでのセキュリティの考え方では、「脆弱性があっても、攻撃が複雑すぎれば普通のハッカーにはできない」という部分が安全の盾になっていました。しかし**AIエージェントはその複雑さを一瞬でクリア**します。

### 👥 影響を受ける人の規模が巨大

Salesforceは世界15万社以上が利用しており、日本でも銀行・保険・医療・ECなどの大企業が多数使っています。もし設定ミスがあれば、**あなたの名前・住所・購入履歴・クレジットカード情報が漏れる可能性**があります。

### ⚡ 攻撃の「民主化」が進む

以前はサイバー攻撃には高度な専門知識が必要でした。しかしAIエージェントを使えば、**プログラミングの知識がほとんどなくても高度な攻撃が実行できる**時代になりつつあります。これは非常に危険な変化です。

### 🧪 「研究として作った」が「武器にもなる」

Recoは「防御側が危機を理解するために作った」と言っています。しかし同じ技術は攻撃者も使えます。実際、ShinyHuntersのようなハッカー集団はすでに似た手法を使い始めています。

## 対策・今後の展望

### 企業・サービス管理者向けの対策

| 対策 | 内容 |
|------|------|
| ✅ アクセス権限の見直し | ゲストユーザーに必要以上のデータへのアクセスを許可しない |
| ✅ 定期的なペネトレーションテスト | AIツールを使った疑似攻撃で自社の弱点を事前に発見する |
| ✅ Salesforceの設定監査 | Experience Cloudのパブリック設定を定期的にチェックする |
| ✅ データの最小公開原則 | 外部に公開するデータは「必要最低限」に絞る |

### 一般ユーザーにできること

- 🔐 使っているサービスが情報漏えいしていないか、「Have I Been Pwned（https://haveibeenpwned.com）」などで確認する
- 📧 不審なメール・SMS（フィッシング）に注意する（漏れた情報を使った攻撃が来る可能性）
- 🔑 重要なサービスには**多要素認証（MFA）**を設定する

### 今後の展望

AIによる攻撃と防御の「いたちごっこ」は今後さらに加速します。セキュリティの世界では**「AIで守る」か「AIで攻められる」かの二択**になりつつあり、AI活用のスピードが企業の安全を左右する時代が来ています。

## 用語解説

| 用語 | 意味 |
|------|------|
| **LLM（大規模言語モデル）** | ChatGPTやClaudeのような、大量のテキストを学習したAI。文章理解・生成・コード作成などが得意 |
| **AIエージェント** | 目標を与えると自律的に行動し続けるAI。一つひとつ指示しなくてもよい |
| **Salesforce** | 世界最大級の顧客管理（CRM）クラウドサービス。大企業の顧客・取引データを管理する |
| **Experience Cloud** | Salesforceの外部公開サイト作成機能。設定ミスが情報漏えいにつながることがある |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやシステムのセキュリティ上の欠陥・弱点 |
| **エクスプロイト** | 脆弱性を実際に攻撃するためのコードやプログラム |
| **偵察（Reconnaissance）** | 攻撃前にターゲットの情報を集める行為 |
| **Auraフレームワーク** | SalesforceのWebアプリ構築技術。外部からメタ情報を取得できる仕組みがある |
| **Apexコントローラー** | Salesforceのサーバー側で動く処理ロジック（プログラム） |
| **ゲストユーザー** | ログインしていない状態でサイトにアクセスしている人 |
| **ShinyHunters** | 実在するハッカー集団。多数の企業データの盗難・販売で知られる |
| **ペネトレーションテスト** | 専門家が意図的に攻撃を試みて、セキュリティの弱点を事前に見つける検査 |
| **多要素認証（MFA）** | パスワード以外にも「スマホへの通知」などで本人確認を追加する仕組み |
