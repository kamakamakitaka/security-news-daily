# PyPIへの「ハデス」攻撃：19パッケージに毒が仕込まれ、資格情報を自動で盗み出す

**元記事**: [Hades PyPI Attack: 19 Packages Poisoned to Auto-Run Bun Credential Stealer](https://inl03.netline.com/ltr6/?_m=3n.009a.3999.sp0ao46r89.31wc)
**解説日**: 2025年6月10日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な仕組みを押さえておきましょう。

### 🐍 PyPI（パイパイ）とは？
**PyPI（Python Package Index）** は、Pythonというプログラミング言語で使える「便利な道具の倉庫」です。プログラマーは `pip install パッケージ名` というコマンド1つで、世界中の人が作ったプログラム部品（パッケージ）を自分のパソコンに追加できます。スマホのアプリストアと同じようなイメージです。

### 📦 サプライチェーン攻撃とは？
普通のサイバー攻撃は「直接ターゲットを狙う」ですが、**サプライチェーン攻撃**は「みんなが使う部品や道具に毒を仕込む」方法です。  
> 💡 **例え話**: スーパーの野菜に農薬を混ぜることはできなくても、野菜の種に毒を混ぜれば、買った農家全員に被害が広がる…それがサプライチェーン攻撃のイメージです。

### 🔑 クレデンシャル（資格情報）とは？
**クレデンシャル**とは、IDやパスワード、APIキー（サービスにアクセスするための鍵）など、「あなたが本人であることを証明するデータ」の総称です。これが盗まれると、他人があなたのサービスに勝手にログインできてしまいます。

### ⚙️ CI/CDとは？
**CI/CD（継続的インテグレーション／継続的デリバリー）** は、プログラムを自動でテスト・公開する仕組みです。開発現場では必須ツールで、AWSやGitHubなどの重要なサービスへのアクセス権を持っていることが多く、攻撃者にとって「大きな鍵束」を盗めるチャンスになります。

## 何が起きたのか

セキュリティ企業の **Socket社** と **StepSecurity社** が発見した内容によると、**「Hades（ハデス）」** と名付けられた悪意ある攻撃キャンペーンが、PyPIの **19種類のパッケージ、合計37個のファイル** に悪意あるコードを仕込んでいたことが明らかになりました。

### 被害を受けたパッケージの一部

| パッケージ名 | 感染バージョン |
|---|---|
| bramin | 0.0.2〜0.0.4 |
| coolbox | 0.4.1〜0.4.2 |
| executor-engine | 0.3.4〜0.3.5 |
| magique | 0.6.8〜0.6.9 |
| napari-ufish | 0.0.2〜0.0.3 |
| spateo-release | 1.1.2 |
（他多数）

さらに、**生物情報学（バイオインフォマティクス）** 分野のパッケージ群も標的になっていました。

## 技術的な詳細

攻撃の仕組みを、ステップごとに分かりやすく説明します。

### 🪤 Step 1：罠入りパッケージを配布する
攻撃者は正規のパッケージに見せかけた（あるいは本物のパッケージを改ざんした）ものをPyPIに登録しました。

### 🚀 Step 2：インストールしただけで自動実行
通常は「インストールしたパッケージを呼び出して（import）初めて動く」ものですが、今回は **`*-setup.pth`** という特殊なファイルが使われました。

> 💡 **例え話**: 普通の爆弾は「スイッチを押すと爆発」ですが、今回は「部屋に置いた瞬間に爆発する」タイプ。つまり、**インストールするだけで悪意あるコードが走り始めます**。

このファイルはPythonが起動するたびに自動で読み込まれる仕組み（`site`モジュール）を悪用しています。

### 📥 Step 3：「Bun」ランタイムをダウンロード
コードは **Bun（バン）** というJavaScript実行ツールをGitHubからこっそりダウンロードします。

> 💡 **なぜBunを使うの？**: Node.jsというJavaScript実行環境がなくても動くからです。検出されにくい「抜け道」として使われています。

### 🔍 Step 4：ロシア語環境かどうかを確認
興味深いことに、マルウェアはまず**システムがロシア語ロケール（言語設定）かどうかを確認**します。ロシア語環境ならば動作を止めます。これは攻撃者がどこの国の人間かを示す手がかりとも言われています。

### 💸 Step 5：資格情報をごっそり盗む
難読化（わざと読みにくくした）されたJavaScriptが動き出し、以下の情報をすべて盗み出します：

| 盗まれる情報 | 具体的な内容 |
|---|---|
| 開発サービスのキー | GitHub, npm, PyPI, RubyGems, JFrog |
| クラウドサービスのキー | AWS, GCP（Google）, Azure（Microsoft） |
| DevOps関連 | CircleCI, Kubernetes, Docker設定 |
| AIサービス | Anthropic（Claude）の設定 |
| その他 | SSHキー、.envファイル、シェル履歴 |

### 📤 Step 6：GitHubの公開リポジトリに送信
盗んだデータは、**GitHubの公開リポジトリ**（説明文に「Hades - The End for the Damned」と書かれたもの）に送られます。

## なぜ重要なのか

### 👨‍💻 開発者が特に危険
このマルウェアは**一般ユーザーではなく、プログラマーや開発者を狙っています**。開発者のパソコンにはクラウドサービスのAPIキーや、会社のシステムへのアクセス権が保存されていることが多く、1人が感染するだけで会社全体のシステムが危険にさらされます。

### 🏥 研究分野も標的に
バイオインフォマティクス（生物情報学）など、セキュリティに不慣れな研究者も使うパッケージが狙われており、**研究データの漏えいリスク**もあります。

### 🔄 進化し続ける攻撃
今回の「Hades」は、以前の「Miasma」「Shai-Hulud」という攻撃キャンペーンの進化版です。攻撃者は検出を回避しながら手法を磨き続けており、**いたちごっこが続いています**。

### 🤖 AIセキュリティスキャナーを欺こうとする
Hadesクラスターの一部は、AIを使ったセキュリティスキャンツールを騙すための工夫も施されており、**自動検出が難しくなっています**。

## 対策・今後の展望

### ✅ 今すぐできる対策

1. **パッケージのバージョンを確認する**  
   上記の感染バージョン一覧を確認し、該当するものを使っていたら即座に削除・更新しましょう。

2. **インストール前に評判を調べる**  
   - ダウンロード数が極端に少ない
   - 作者が不明・最近登録された  
   といったパッケージは慎重に。

3. **仮想環境（venv）を使う**  
   Pythonプロジェクトごとに独立した環境を使うと、感染の広がりを抑えられます。

4. **APIキーや資格情報を定期的に更新・無効化する**  
   もし感染した可能性があれば、すぐにすべてのAPIキーを無効化して再発行しましょう。

5. **セキュリティスキャンツールを活用する**  
   `pip-audit` などのツールで依存パッケージの脆弱性をチェックしましょう。

### 🔮 今後の展望
攻撃者は「Miasma → Hades」と名前を変えながら進化しています。今後も同様の手口が**npm（JavaScript）やRubyGems（Ruby）** など他のパッケージ管理システムでも使われる可能性が高く、継続的な監視が必要です。

## 過去記事との関連

以前、**FROST攻撃**（SSDのアクセス速度の違いを利用して、ユーザーが開いているサイトやアプリを特定する攻撃）についてご紹介しましたが、今回の「Hades攻撃」はまったく異なるアプローチです。

| | FROST攻撃 | Hades攻撃 |
|---|---|---|
| 手法 | SSDのタイミング差を観測 | 偽パッケージを配布 |
| ターゲット | 一般ユーザー | 開発者・研究者 |
| 目的 | 閲覧履歴の特定 | 資格情報の窃取 |

共通点は「**普段使いしている仕組みを悪用する**」という点です。FROSTはブラウザとSSDの連携を、HadesはPyPIというパッケージ管理の信頼性を悪用しています。**「信頼している仕組みが攻撃の入口になる」**という現代のサイバー攻撃の本質が、どちらにも共通しています。

## 用語解説

| 用語 | 読み方 | 意味 |
|---|---|---|
| **PyPI** | パイパイ | Pythonのパッケージ配布サイト（倉庫） |
| **サプライチェーン攻撃** | — | 製品や部品の流通経路に悪意を仕込む攻撃 |
| **クレデンシャル** | — | ID・パスワード・APIキーなどの認証情報 |
| **API キー** | エーピーアイキー | サービスにアクセスするための「鍵」となる文字列 |
| **Bun** | バン | 高速なJavaScript実行環境（Node.jsの代替） |
| **難読化** | なんどくか | コードをわざと読みにくく変形して解析を妨げること |
| **CI/CD** | シーアイシーディー | プログラムを自動でテスト・公開する仕組み |
| **ロケール** | — | OSの言語・地域設定 |
| **リポジトリ** | — | コードやファイルを保管・管理する場所（GitHubなど） |
| **バイオインフォマティクス** | — | コンピューターで生物学データを解析する学問分野 |
| **`.env`ファイル** | ドットエンブ | アプリの設定情報（APIキーなど）を書いた隠しファイル |
| **SSHキー** | エスエスエイチキー | サーバーに安全にアクセスするための電子的な鍵 |

> ⚠️ **まとめ**: 「有名なパッケージ管理システムだから安全」という思い込みは危険です。**インストール前に必ずパッケージ名・バージョン・作者を確認する習慣**を持ちましょう。特に開発者の方は、自分の資格情報が企業全体のセキュリティに直結することを意識してください。
