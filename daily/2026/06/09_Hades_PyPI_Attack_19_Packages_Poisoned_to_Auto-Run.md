# PyPI「Hades」攻撃：19個のパッケージに毒が仕込まれ、起動するだけで認証情報が盗まれる

**元記事**: [Hades PyPI Attack: 19 Packages Poisoned to Auto-Run Bun Credential Stealer](https://inl03.netline.com/ltr6/?_m=3n.009a.3999.sp0ao46r89.31wc)
**解説日**: 2025年6月10日

---

## 背景知識

まず、この記事を理解するための基礎知識を整理しましょう。

### 🐍 PyPI（パイパイ）って何？
**PyPI（Python Package Index）** は、Pythonというプログラミング言語用の「アプリストア」のようなものです。プログラマーが便利な機能を「パッケージ」としてここに登録し、世界中の開発者が `pip install パッケージ名` というコマンド一発で使えるようにしています。

> 例え：スマホのApp Storeに誰でもアプリを公開できるように、PyPIにも誰でもパッケージを公開できます。

### 📦 サプライチェーン攻撃って何？
**サプライチェーン攻撃**とは、製品の「流通経路」を狙う攻撃です。食品で例えると、スーパーに並ぶ前の「製造・流通段階」で毒を混ぜてしまうようなイメージです。PyPIの場合、開発者が日常的に使うパッケージ自体に悪意のあるコードを仕込むことで、多くの被害者を一度に狙えます。

### 🔑 認証情報（クレデンシャル）って何？
パスワード、APIキー（サービスへのアクセス用の特別な鍵）、SSH鍵（サーバーへのログイン用の鍵）など、「本人確認に使われる情報」の総称です。これが盗まれると、アカウントを乗っ取られたり、企業のシステムに不正アクセスされたりします。

### 🤖 CI/CDって何？
**CI/CD（継続的インテグレーション/継続的デリバリー）** は、プログラムを自動的にテスト・公開するシステムです。現代の開発現場では当たり前のように使われており、ここの認証情報が盗まれると企業の製品そのものが改ざんされる危険があります。

## 何が起きたのか

セキュリティ企業Socketが、PyPI上で **「Hades（ハデス）」** と名付けられた新たな悪意のある攻撃キャンペーンを発見しました。

### 被害の規模
- **19個のパッケージ**に悪意のあるコードが仕込まれた
- 影響を受けるバージョンは合計 **37種類**
- 「Miasma（ミアズマ）」「Shai-Hulud（シャイ＝フルード）」という過去の攻撃シリーズの最新版

### 被害を受けたパッケージの一部
```
bramin, cmd2func, coolbox, dynamo-release, executor-engine,
executor-http, funcdesc, magique, mrbios, napari-ufish,
nucbox, okite, pantheon-agents, pantheon-toolsets, など
```

また、生命科学・バイオインフォマティクス（遺伝子解析など）分野のパッケージも別グループとして狙われています：
```
embiggen, ensmallen, gpsea, mflux-streamlit, nhmpy, など
```

> 💡 注目点：生命科学の研究者まで標的にしているのは非常に珍しく、攻撃の対象が広がっている証拠です。

## 技術的な詳細

### 🎯 攻撃の流れ（ステップ・バイ・ステップ）

```
①  開発者が pip install [感染パッケージ] を実行
        ↓
②  インストールと同時に「*-setup.pth」ファイルが仕込まれる
        ↓
③  次回以降、Pythonを起動するだけで自動的に悪意のあるコードが実行される
        ↓
④  GitHubから「Bun（バン）」というJavaScriptの実行環境をダウンロード
        ↓
⑤  難読化（読めないように変換）されたJavaScriptのスティーラー（情報窃取ツール）が起動
        ↓
⑥  PC内の認証情報を大量に収集して攻撃者のGitHubリポジトリに送信
```

### 🔥 特に怖いポイント：インストールするだけで発動する

通常、パッケージに仕込まれた悪意のあるコードは「プログラムの中でそのパッケージを使う（`import`する）」ときに動きます。しかし今回の攻撃では、**`*-setup.pth` というファイルを使う**ことで、Pythonを起動するだけで自動実行されます。

> 例え：普通のウイルスは「アプリを開いたとき」に動くのに対し、今回は「パソコンを起動するだけ」でウイルスが動くようなイメージです。

### 🌐 Bun（バン）を使う理由

攻撃者はなぜわざわざ「Bun」というJavaScript実行環境を使うのでしょうか？

- 多くのシステムにはNode.jsがインストールされていないため、代わりにBunを使うことでほぼどんな環境でも動作する
- 単独で動くZIPファイルとしてダウンロードできるため、環境に依存しない
- セキュリティツールの検知をすり抜けやすい

### 🗂️ 盗まれる情報の種類

| カテゴリ | 具体的な情報 |
|---------|------------|
| 開発プラットフォーム | GitHub, npm, PyPI, RubyGems のトークン |
| クラウドサービス | AWS, GCP（Google Cloud）, Azure のキー |
| CI/CDツール | CircleCI, JFrog, Kubernetes の認証情報 |
| AIサービス | Anthropic（Claude）の APIキー |
| システム情報 | SSH鍵、シェル履歴、.envファイル、Dockerの設定 |

### 🤖 AIスキャナーを欺く新手法

今回の攻撃で特に注目されるのが、バイオインフォマティクス系パッケージのグループです。このグループでは悪意のあるコードが `__init__.py` という必ず読み込まれるファイルの中に**難読化された1行**として隠されており、AIによるセキュリティスキャンを騙すよう工夫されています。

### 🇷🇺 ロシア語環境では動作しない

興味深いことに、このマルウェアはシステムのロケール（地域・言語設定）がロシア語である場合、動作をしない設定になっています。これはロシア語圏のユーザーを意図的に除外していることを示しており、攻撃者がどの地域の人物かを示すヒントと見られます。

## なぜ重要なのか

### 👨‍💻 開発者・研究者が特に危険
このニュースは一般ユーザーよりも、**ソフトウェア開発者や研究者**にとって非常に深刻な問題です。

- エンジニアは日常的に多くのパッケージをインストールする
- 1人のエンジニアの認証情報が盗まれると、会社全体のシステムが危険にさらされる
- CI/CDの認証情報が盗まれると、公開製品のプログラムそのものが改ざんされる可能性がある

### 🔗 サプライチェーン攻撃の連鎖リスク

```
個人開発者のPCが感染
      ↓
会社のGitHubアカウントが乗っ取られる
      ↓
会社のソフトウェアに悪意のあるコードが混入
      ↓
そのソフトウェアを使う何万人ものユーザーが被害を受ける
```

### 📈 攻撃が継続的に進化している
「Shai-Hulud → Miasma → Hades」と名前を変えながら、同じ攻撃者グループが手法を改良し続けています。今回の「Hades」は特に以下の点で進化しています：

1. **より広い分野を標的**（バイオインフォマティクスまで）
2. **より検知されにくい**（AIスキャナー対策）
3. **より確実に実行される**（インストールだけで発動）

## 対策・今後の展望

### ✅ 開発者が今すぐできること

**1. 怪しいパッケージを確認・削除する**
```bash
# 感染パッケージのリストに自分のプロジェクトが含まれていないか確認
pip list | grep -E "bramin|cmd2func|coolbox|magique|..."
```

**2. パッケージをインストールする前に確認する習慣をつける**
- PyPIのパッケージページでダウンロード数や更新履歴を見る
- 公式サイトや信頼できるソースを確認する

**3. 仮想環境（venv）を使う**
- プロジェクトごとに独立した環境を作ることで、感染の拡大を防ぐ

**4. 認証情報を定期的に更新・無効化する**
- 感染が疑われる場合は、GitHubやAWSなどのAPIキーをすぐに無効化する
- 特にCI/CDのシークレット情報は最優先で確認する

### 🛡️ セキュリティツールの活用
- **Socket**（今回発見したセキュリティ企業）のツールは、パッケージインストール前に悪意のある動作を検知できます
- **StepSecurity** なども同様の対策ツールを提供しています

### 🔮 今後の展望
- 攻撃者は「Hades」の後も新しい名前で攻撃を続ける可能性が高い
- PyPI側での審査強化が求められているが、膨大な量のパッケージすべてを事前チェックするのは現実的に難しい
- AIによる悪意のあるコード検出技術との「イタチごっこ」が続く見込み

## 過去記事との関連

以前、**FROST攻撃（SSDのタイミングでアクセスサイトを特定する手法）** についてご紹介しましたが、今回の記事はアプローチが全く異なります。

- **FROST攻撃**：ハードウェアの特性を使ったパッシブ（受動的）な情報収集
- **Hades攻撃**：信頼されたソフトウェア流通経路を使ったアクティブ（能動的）な認証情報窃取

ただし両方に共通しているのは、**「普通に使っているだけで攻撃される」** という点です。セキュリティは「怪しいサイトを避ける」だけでは不十分で、日常的に使うツールやサービス自体が攻撃経路になり得るという、現代のサイバーセキュリティの難しさを示しています。

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **PyPI** | パイパイ | Pythonのパッケージ配布サイト（App Storeのようなもの） |
| **サプライチェーン攻撃** | - | 製品の流通・配布経路を狙った攻撃 |
| **認証情報（クレデンシャル）** | - | パスワードやAPIキーなど、本人確認に使われる情報 |
| **APIキー** | エーピーアイキー | Webサービスへアクセスするための特別な鍵 |
| **難読化** | なんどくか | コードを読みにくく変換して、人間やAIに内容を隠す技術 |
| **Bun** | バン | JavaScriptを動かすための新しい実行環境 |
| **CI/CD** | シーアイシーディー | プログラムを自動でテスト・公開するシステム |
| **スティーラー** | - | 情報を盗み出す悪意のあるプログラム |
| **setup.pth** | セットアップ・ピーティーエイチ | Pythonが起動時に自動読み込みする設定ファイル |
| **SSH鍵** | エスエスエイチかぎ | サーバーに安全にアクセスするための暗号化された鍵 |
| **.envファイル** | ドットエンブ | パスワードなどの設定情報をまとめたファイル |
| **ロケール** | - | OSの地域・言語設定 |
| **exfiltration** | エクスフィルトレーション | 盗んだデータを外部に送り出すこと |

> ⚠️ **まとめ**: 今回の「Hades」攻撃は、開発者が毎日使うPyPIというパッケージ管理サービスを狙ったもので、インストールするだけで認証情報が盗まれる非常に危険な手口です。「有名なサービスだから安全」という思い込みは禁物。どんなパッケージをインストールするかは慎重に確認しましょう。
