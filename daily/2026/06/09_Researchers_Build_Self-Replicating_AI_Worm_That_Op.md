# 自分で考えて広がるAIワーム、ついに登場！ローカルAIだけで動くサイバー脅威の新時代

**元記事**: [Researchers Build Self-Replicating AI Worm That Operates Entirely on Local, Open-Weight Models](https://inl03.netline.com/ltr6/?_m=3n.009a.3999.sp0ao46r89.31vc)
**解説日**: 2025年6月

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### 💡 コンピューターウイルスとワームの違い

- **コンピューターウイルス**: 人間がファイルを開いたり操作したりしないと広がらない悪意のあるプログラム
- **ワーム（Worm）**: 人間の操作なしに、**自分でネットワークを移動して勝手に広がる**悪意のあるプログラム。まるで地面を掘り進む「ミミズ（ワーム）」のように、勝手にネットワーク内を進んでいくイメージです。

### 💡 LLM（大規模言語モデル）って何？

ChatGPTやGeminiのような「AIチャット」の中核となる技術です。大量のテキストを学習して、文章を理解したり、質問に答えたり、**新しい文章やコードを生成**したりできます。

### 💡 オープンウェイトモデルって？

ChatGPTはOpenAIの会社のサーバーでしか動きません。一方「オープンウェイトモデル」は、設計図（重みデータ）が公開されているので、**自分のパソコンやサーバーに直接インストールして動かせるAI**のことです。代表例は「Llama」や「Mistral」など。

### 💡 CVE（シーブイイー）って何？

**Common Vulnerabilities and Exposures**の略で、「公式に登録されたセキュリティの弱点リスト」のことです。「CVE-2024-XXXX」のように番号で管理されています。ソフトウェアに穴（脆弱性）が見つかると、ここに登録されて世界中に知らされます。

### 💡 「パッチを当てる」とは？

脆弱性（弱点）を修正するためのプログラムの更新（アップデート）を適用することです。OSやアプリのアップデートをイメージしてください。

## 何が起きたのか

カナダのトロント大学の研究チームが、**「自分で考えて、自分で広がる」AIを使ったコンピューターワーム**を開発・実験に成功しました。

> 🧪 これは研究目的の実証実験であり、実際に外部のネットワークに放たれたわけではありません。完全に隔離された実験環境で行われています。

### 実験の概要

研究チームは「FakeCorp（フェイクコープ）」と名付けた、**意図的に脆弱な33台のパソコン・サーバーからなるテスト用ネットワーク**を作りました。このネットワークで、AIワームを15回の独立した実験で動かしました。

**結果はこうなりました：**

| 項目 | 結果 |
|------|------|
| 発見した脆弱性の平均数 | **31.3個** |
| 管理者権限を奪えたホスト数 | **平均23.1台**（目標の約75%） |
| 自己複製できたホスト数 | **平均20.4台**（全体の62%） |
| 実験期間 | **7日間** |
| 自己複製の世代数（最大） | **7世代** |

ミミズが土の中で増殖するように、このワームはネットワーク内でどんどん「子ども」を作りながら広がっていったのです。

## 技術的な詳細

### 🔧 従来のワームとの決定的な違い

**従来のワームのイメージ：**
```
「Aという鍵穴にしか使えない合鍵」を持って家に侵入する
→ Aの鍵穴がない家には入れない
→ 鍵穴Aを交換（パッチ）されたら終わり
```

**今回のAIワームのイメージ：**
```
「どんな鍵穴でも、見た瞬間に合鍵を作れる職人」が侵入する
→ 家ごとに違う鍵穴でも、その場で対応策を考えて鍵を作る
→ 1つの鍵穴を直しても、別の穴を使って入ってくる
```

### 🤖 AIワームの動き方（ステップ解説）

```
①【偵察】
  ターゲットのサーバーに近づき、
  どんなソフトウェアが動いているか調べる

       ↓

②【AI思考】
  「このサーバーはApache 2.4が動いてるな。
   最近CVEで報告された脆弱性を使えるかも…」
  ↓ リアルタイムで攻撃方法を考える（LLMが担当）

       ↓

③【攻撃実行】
  AIが生成した攻撃コードを実行
  （成功率は約44%）

       ↓

④【自己複製】
  侵入成功 → 自分のコピーを相手サーバーに設置
  侵入失敗 → 次のターゲットへ移動

       ↓

⑤【繰り返し】
  感染したサーバーもAIノードとして活動開始
  → ネットワーク全体に広がる
```

### 🌐 分散型AIの工夫

このワームの特に巧妙なところは、**感染したGPU（画像処理チップ）を持つサーバーを「AIの計算拠点」として使う**という発想です。

たとえるなら：
- 最初の1台が「司令部」として機能
- 感染させた強いサーバーを「分隊の思考装置」として活用
- 計算能力が弱いデバイスも、強いサーバーから指示をもらって動ける

### 📅 学習済みデータより新しい脆弱性も攻撃できた

最も驚くべき点の1つは、**AIが学習した時点より後に発見された脆弱性（CVE）も、リアルタイムで公開情報を読み込むことで攻撃できた**ことです。

> これは「教科書に載っていない問題でも、インターネットで調べながら解ける」ようなイメージです。

実際に使われた攻撃手法の例（専門用語ですが、多様な攻撃をこなしたことがわかります）：
- **SambaCry** → Linuxのファイル共有機能の欠陥
- **Dirty Pipe** → Linuxカーネルの特権昇格バグ
- **PrintNightmare** → Windowsの印刷機能の欠陥
- **SQLインジェクション** → データベースへの不正命令
- など、計10種類以上の異なる攻撃手法を**その場で自動生成**

## なぜ重要なのか

### 🚨 「パッチを当てれば安全」という常識が崩れる

これまでのセキュリティ対策の基本は「脆弱性が見つかったらすぐパッチを当てる」でした。

- **従来の考え方**: 「CVE-XXXX のパッチを当てた → このワームは防げる ✅」
- **今回の研究が示すこと**: 「1つのCVEを直しても、AIが別の攻撃方法をその場で考えて侵入してくる 😱」

### 🔓 外部AIサービスに依存しない点が危険

ChatGPTなどのクラウドAIを使った攻撃ツールは、運営会社が「不正利用を検知したらアクセス禁止」にできます。でもこのワームは：

- 完全にローカル（自前のサーバー）で動くAIを使用
- インターネット上の外部サービスに接続しない
- **誰かに止めてもらうことができない**

### 📊 現実の脅威レベルは？

研究チームも強調していますが、今回の実験は**意図的に脆弱な環境**で行われています：

- 実際の企業ネットワークは、もっと防御が固い
- エンドポイント検知（ウイルス対策ソフトなど）も実験では無効化されていた
- つまり「現時点ですぐ世界中の会社が危ない」わけではない

ただし、AIの能力は急速に向上しており、**今後2〜3年でこの技術が本物の攻撃に使われる可能性は十分ある**と専門家は警告しています。

## 対策・今後の展望

### 🛡️ 個人・組織が今できること

1. **OSやソフトウェアのアップデートを怠らない**
   - パッチ1つでは防げないかもしれないが、それでも対策の基本中の基本

2. **ネットワークのセグメント分割**
   - 全てのサーバーを同じネットワークに繋げず、区画を分ける（感染が広がりにくくなる）
   - ちょうど「船の防水区画」のように

3. **最小権限の原則を守る**
   - サーバーやソフトウェアに「必要最低限の権限しか与えない」
   - AIが権限を昇格させにくくなる

4. **異常な動作の監視（EDR/SIEM）**
   - ネットワーク内で「おかしな動き」を検知するシステムを導入
   - 今回の研究でも、防御システムを無効化した環境での実験だった

### 🔬 研究コミュニティへの影響

この研究はArXiv（学術論文の公開サイト）に掲載されており、現在査読（専門家によるチェック）中です。この種の「攻撃的な研究（Offensive Research）」は、**守る側が先に問題を知って対策を立てるため**に重要です。

### 🤔 AIセキュリティの今後

- **AI vs AI の時代へ**: 攻撃がAI化するなら、防御もAI化が必要
- **オープンウェイトモデルの規制議論**: 誰でも使えるAIモデルをどう管理するか、各国で議論が始まっている
- **自動パッチ適用の重要性**: 人間がパッチを当てる速度では間に合わなくなる可能性

## 用語解説

| 用語 | 解説 |
|------|------|
| **ワーム（Worm）** | 人間の操作なしにネットワーク内を自動的に広がるマルウェア（悪意のあるプログラム） |
| **LLM（大規模言語モデル）** | ChatGPTなどのAIチャットを支える技術。大量のテキストから学習して文章や코드を生成できる |
| **オープンウェイトモデル** | 設計データが公開されていて、自分のコンピューターで動かせるAIモデル |
| **CVE** | 世界共通のセキュリティ脆弱性番号。「CVE-年-番号」の形式 |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやシステムのセキュリティ上の弱点・穴 |
| **パッチ** | 脆弱性を修正するためのソフトウェアアップデート |
| **GPU** | 画像処理専用チップ。AI計算にも使われる高性能プロセッサ |
| **権限昇格** | 一般ユーザーの権限から管理者権限を不正に奪うこと |
| **自己複製** | ワームが自分のコピーを別のコンピューターに作ること |
| **ArXiv（アーカイブ）** | 査読前の学術論文を公開するウェブサイト |
| **Proof-of-Concept（PoC）** | 「概念実証」。「理論上可能なだけでなく、実際に動くことを示した」という意味 |
| **SQLインジェクション** | データベースに不正な命令を送り込む攻撃手法 |
| **エンドポイント** | ネットワークに接続されたパソコンやサーバーなどの端末 |
