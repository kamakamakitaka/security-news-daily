# 自分でコピーして広がるAIワーム、ローカルAIだけで動作することが実証される

**元記事**: [Researchers Build Self-Replicating AI Worm That Operates Entirely on Local, Open-Weight Models](https://inl03.netline.com/ltr6/?_m=3n.009a.3999.sp0ao46r89.31vc)
**解説日**: 2025年6月

---

## 背景知識

このニュースを理解するために、いくつかの基本的な概念を先に説明します。

### 🐛 コンピューターウイルスと「ワーム」って何が違うの？
コンピューターウイルスは、人間が何かファイルを開いたり操作したりすることで広がります。一方、**ワーム（Worm）** は「ミミズ」という意味の通り、**人間の操作なしに自分でネットワークを這い回って自己増殖するマルウェア（悪意のあるプログラム）** です。  
有名な例として、2000年代に世界中のPCを感染させた「MSBlast」や「Conficker」などがあります。

### 🤖 LLM（大規模言語モデル）って何？
ChatGPTやGeminiのような**AI会話システムの中核となる技術**です。大量のテキストデータを学習して、質問に答えたり文章を生成したりできます。今回の記事に出てくる「オープンウェイトモデル」とは、**プログラムの設計図（重みパラメータ）が一般公開されているAIモデル**のことで、自分のパソコンやサーバーにインストールして使えるものです（例：Llamaシリーズなど）。

### 🔒 脆弱性（ぜいじゃくせい）とCVEって何？
**脆弱性**とは、ソフトウェアやシステムに存在する「セキュリティ上の穴（バグ）」のことです。  
**CVE（Common Vulnerabilities and Exposures）** は、発見された脆弱性に付けられる「通し番号」のようなものです（例：CVE-2021-XXXXX）。セキュリティの世界では「穴を見つけたら番号を付けて管理し、対策パッチ（修正プログラム）を配布する」という仕組みがあります。

### 🏠 「ローカル」で動くとなぜ危険なの？
ChatGPTなどのクラウドAIは、OpenAIなどの会社のサーバーを通じて動きます。そのため、**「不正利用だと判断したらアクセスを遮断する」** という安全装置があります。  
しかし、自分のマシン上で動く「ローカルAI」には、そのような外部からの監視や制限がありません。インターネットから切り離された環境でも動き続けます。

## 何が起きたのか

カナダの**トロント大学**の研究チーム（CleverHans Lab）が、**AIを頭脳に持つ自己増殖型ワーム**を実際に作って実験し、その結果を論文として発表しました（2025年6月2日、arXivという論文共有サイトに掲載）。

### 実験の概要
- **実験環境**：33台のコンピューターで構成された意図的に脆弱な仮想ネットワーク（「FakeCorp」と命名）
- **使用OS**：Ubuntu・Debian・Rocky Linux（Linuxの仲間たち）、Windows Server、IoT機器など多種多様
- **結果**：7日間で62%にあたる**約20台に自律的に感染・拡散**、人間の操作はゼロ

### 具体的な数字で見ると…

| 項目 | 結果 |
|------|------|
| 平均発見した脆弱性の数 | 31.3個 |
| 管理者権限を奪取できたホスト数 | 23.1台（対象の約75%） |
| 自己複製に成功したホスト数 | 20.4台（全体の約62%） |
| 自己増殖の世代数（最大） | 7世代 |
| 個別の攻撃成功率 | 約44% |

## 技術的な詳細

### 🧠 従来のワームとどう違うのか

**従来のワーム（例：昔ながたの悪意あるプログラム）**
```
出発点 → 「この脆弱性を攻撃するぞ」という命令が最初から書き込まれている
       → その脆弱性にパッチが当たったら？ → 終わり。止まる。
```

**今回のAIワーム**
```
出発点 → 「まず相手のシステムを調べろ」という指示だけ持っている
       → 調査結果をAIに送る
       → AIが「この相手にはこの攻撃が有効そうだ」と考えて攻撃コードを生成
       → 攻撃実行 → 成功したら自分自身をコピーして次のターゲットへ
```

つまり、**攻撃の「レシピ」を自分でその場で考える**のです。料理で例えると、従来のウイルスは「カレーのレシピ」しか持っていませんが、このAIワームは「冷蔵庫の中身を見てからベストな料理を考える料理人」みたいなものです。

### 📚 さらに怖い機能：「知識のアップデート」

このワームは、インターネット上に公開されている脆弱性情報（セキュリティアドバイザリ）を**リアルタイムで読み込む**ことができます。

> **実験では、AIが学習した時点より後に発見された脆弱性（新しいCVE）を持つホストにも、アドバイザリを読み込むことで攻撃に成功しました。**

これは非常に重大な意味を持ちます。「AIモデルの学習データが古いから大丈夫」という理屈が通用しないということです。

### ⚡ 実際に使われた攻撃手法の例

このワームが自律的に実行した攻撃には以下のようなものが含まれます（すべて実在の脆弱性です）：

- **Dirty Pipe**：Linuxカーネルのファイル書き込み脆弱性
- **PrintNightmare**：Windowsの印刷機能の脆弱性
- **Drupalgeddon 2**：有名なCMSツール「Drupal」のWebアプリ脆弱性
- **SQLインジェクション**：データベースに不正命令を送り込む攻撃
- **SambaCry**：Linuxのファイル共有機能の脆弱性

これらは事前にプログラムされたのではなく、**AIが調査してその場で「これが使えそうだ」と判断して実行した**ものです。

### 🖥️ GPU（グラフィックカード）を乗っ取って「頭脳」にする仕組み

AIモデルを動かすには高性能な計算機（GPU）が必要です。このワームは、**感染先のGPU搭載マシンを計算リソースとして利用**し、そこでAIを動かして次の攻撃を考えるという「分散型AI推論」を実現しました。GPU搭載ホストへの完全な自己複製の成功率は**68.8%**でした。

## なぜ重要なのか

### ① 「パッチを当てれば安全」という常識が崩れる

これまでのセキュリティの基本は「脆弱性が見つかったらパッチ（修正プログラム）を当てる」でした。しかし、このワームは**1つの脆弱性に依存しない**ため、特定のパッチを当てても別の穴から入ってきます。

### ② 外部AIサービスへの依存がない = 遮断できない

OpenAIやGoogleのAIサービスは「不正利用を検知したらアクセスを遮断できる」という安全網があります。しかし、このワームは**完全にローカルで動く**ため、そのような外部からの遮断が効きません。

### ③ 人間が一切介在しない完全自律型

攻撃から拡散まですべて自律的に行われ、**攻撃者は最初にワームを放つだけ**でよくなります。攻撃のコストが大幅に下がり、高度な知識がなくても大規模攻撃が可能になるリスクがあります。

### ④ オープンソースのAIモデルで実現できる

特別な企業の高性能AIは不要で、**一般公開されているオープンウェイトモデルで実現可能**という点も重要です。

> ⚠️ **注意**：この研究は完全に隔離された実験環境で行われており、現実の防御が施されたネットワークではより難しくなります。研究者たちも「これは現実の堅牢なネットワーク全体への感染を示したものではない」と明記しています。

## 対策・今後の展望

### 🛡️ 現時点でできる対策

**個人・企業レベル**
1. **パッチの迅速な適用**：従来通り、パッチ管理は引き続き最重要（1つの脆弱性をつぶすことに意味はある）
2. **ネットワークの分離（セグメンテーション）**：社内ネットワークを細かく分け、ワームが横断しにくくする
3. **最小権限の原則**：各ユーザーやシステムに必要最小限の権限だけを与え、管理者権限の奪取を難しくする
4. **EDR（エンドポイント検知・対応）ツールの導入**：不審な動作をリアルタイムで検知するセキュリティソフト

**セキュリティ業界全体**
1. **AIによる行動検知**：特定の攻撃パターンではなく、「不審な行動パターン」を検知するAI防御システムの整備
2. **ゼロトラストアーキテクチャ**：「社内にいるから安全」ではなく、すべての接続を常に検証する考え方の普及

### 🔭 今後の展望

この研究は**「こんな危険なものが作れる」という警告**として公開されています。研究者たちの目的は、防御側がこの脅威を知って対策を先回りして考えられるようにすることです。  
実際の攻撃への悪用を防ぐため、論文では攻撃の詳細な実装コードは公開されていません。

## 用語解説

| 用語 | 説明 |
|------|------|
| **ワーム（Worm）** | 人間の操作なしにネットワーク上を自動的に広がるマルウェア |
| **LLM（大規模言語モデル）** | ChatGPTなどのAIチャットの基盤技術。大量のテキストを学習してテキストを生成する |
| **オープンウェイトモデル** | 設計データが一般公開されており、誰でも自分のマシンで動かせるAIモデル |
| **CVE** | 発見されたセキュリティ脆弱性に付けられる世界共通の識別番号 |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやシステムに存在するセキュリティ上の穴・バグ |
| **パッチ** | 脆弱性を修正するための更新プログラム |
| **権限昇格** | 一般ユーザーが管理者（root/Administrator）権限を不正に取得すること |
| **GPU** | 元々は画像処理用の演算装置だが、AI処理にも使われる高性能計算チップ |
| **自律型エージェント** | 目標を与えられると人間の指示なしに自分で判断・行動するAIシステム |
| **ゼロトラスト** | 「社内ネットワークだから安全」という前提を捨て、常にすべてを検証するセキュリティ考え方 |
| **CVSS** | 脆弱性の深刻度を0〜10のスコアで表す国際標準（10が最も深刻） |
| **arXiv（アーカイブ）** | 正式な査読前の学術論文を公開するウェブサイト |
| **Dirty Pipe / PrintNightmare** | 実在するLinux/Windowsの脆弱性の名称（ニックネーム） |
| **SQLインジェクション** | データベースへの不正な命令を入力欄から送り込む攻撃手法 |
