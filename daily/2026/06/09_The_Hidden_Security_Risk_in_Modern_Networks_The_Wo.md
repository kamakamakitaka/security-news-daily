# 現代ネットワークに潜む隠れたセキュリティリスク：ツールとツールの「すき間」の作業

**元記事**: [The Hidden Security Risk in Modern Networks: The Work Between Tools](https://inl03.netline.com/ltr6/?_m=3n.009a.3999.sp0ao46r89.31vu)
**解説日**: 2025年7月10日

---

## 背景知識

このニュースを理解するために、まず「企業のセキュリティチームってどんな仕事をしているの？」というところから説明しましょう。

### 企業のセキュリティ担当者の日常

大きな会社では、サイバー攻撃や不審な動きを24時間監視している専門チームがいます。彼らは毎日、たくさんの「セキュリティツール（道具）」を使って働いています。たとえば：

| ツール名 | 役割 | わかりやすい例え |
|---|---|---|
| **SIEM**（シーム） | 全システムのログを集めて異常を検知する | 「学校の監視カメラの映像を一括管理するシステム」 |
| **ファイアウォール** | 不正な通信をブロックする | 「不審者を門で止める守衛さん」 |
| **IAM**（アイアム） | 誰がどのデータにアクセスできるかを管理する | 「部屋ごとに鍵の権限を管理する仕組み」 |
| **ITSM**（アイティーエスエム） | ITの問題を管理するチケットシステム | 「学校の修繕依頼を管理する書類システム」 |

これらのツールはそれぞれ**別々のシステム**として動いており、担当者が手動で情報をやり取りしている場面が多いのが現状です。

### 「MTTR」って何？

記事に出てくる **MTTR（Mean Time To Remediate）** とは「問題を発見してから修復が完了するまでの平均時間」のことです。この時間が長いほど、攻撃者に悪さをされ続ける時間も長くなります。

## 何が起きたのか

> 「検知（見つける力）は問題ではない。ツールも問題ではない。今日の本当の問題は**実行**、つまりツールとツールの**すき間で起きている作業**だ」

これはある特定の事件ではなく、セキュリティ業界全体が抱える**構造的な問題**を指摘した記事です。

### 一言でまとめると

> 🔍 **「監視ツールは揃っている。でも、そのツールたちをつなぐ"人の作業"がボトルネックになっていて、セキュリティ対応が遅くなっている」** という問題が明らかになっています。

たとえば、不審なアクセスを検知したとき、担当者がやらなければならない作業はこんな感じです：

```
⚠️ アラート発生！
    ↓
① 複数のシステムから情報を手動で集める
    ↓
② 「本物の脅威か？誤検知か？」を確認する
    ↓
③ 誰が担当するかを決めてチケットを作る
    ↓
④ 上司に承認をもらう
    ↓
⑤ 実際に設定変更などの対処をする
    ↓
⑥ 作業ログを記録する
```

この全てが**手動・バラバラのシステム間**で行われているのです。

## 技術的な詳細

### 問題が起きやすい3つのポイント

#### 🚨 ① アラートの調査と対応（インシデントレスポンス）

学校に例えると、「不審者がいるかも？」という情報が入ったとき：

- 監視カメラの映像を確認
- 生徒の出席簿を確認
- 先生に連絡
- 校長に報告
- 対処の指示をもらう

…という作業を**全部バラバラのシステムで手動でやっている**状態です。

これが原因で起きる問題：
- ✅ 対応が遅れて被害が拡大する
- ✅ 毎日大量のアラートが来て担当者が**燃え尽き症候群**になる
- ✅ 本当に危険なアラートを見逃してしまう

#### 🔐 ② アクセス管理と設定変更

誰かに「このシステムへのアクセス権を与えてほしい」と申請があった場合：

```
申請 → セキュリティ担当が確認 → IT担当が別システムで処理 → 上長承認 → 設定反映
```

この間、**チームがバラバラのシステムを使っている**ため：
- 同じ作業を二度やる（二度手間）
- 「最小権限の原則（本当に必要な権限だけ与える）」が守られない
- 監査のときに証拠が残っていない

#### 🌐 ③ クラウドとオンプレミスの混在環境

**クラウド**（インターネット上のサーバー）と**オンプレミス**（社内の物理サーバー）が混在している環境では：

- 担当チームが分かれている
- ツールも違う
- セキュリティ基準も統一されていない

まるで「日本語と英語が混在する書類を手動で翻訳しながら仕事している」ような状態です。

## なぜ重要なのか

### 数字で見る影響

```
⏱️ システム障害が何時間も続く
    → 企業の金銭的損失・信用の失墜

🐌 MTTR（修復時間）が遅い
    → 攻撃者が長時間システム内に留まれる

😰 担当者の燃え尽き・ミス
    → 人手不足がさらに深刻になる悪循環
```

### AI導入でも解決しない理由

「AIを使えばいいんじゃないの？」と思うかもしれません。実は、AIは**検知（発見）** の精度は上げてくれますが、ツールとツールの**すき間の人間作業**は自動化できていないのです。

むしろAIによって「早く、大量に」アラートが届くようになったため、処理しきれない担当者のプレッシャーが増しているという皮肉な状況が生まれています。

> 🏃‍♂️ **例え話**：
> 「宅配便の仕分けロボットが超高速になったのに、玄関から各部屋への配達は相変わらず人が走って運んでいる」ような状態です。

## 対策・今後の展望

この記事が示唆する解決策は大きく3つです：

### ✅ 1. ワークフローの自動化（オーケストレーション）

ツールとツールの間の作業を自動的につなぐ仕組みを導入する。
例：アラートが発生したら自動的にチケット作成・担当者通知・証拠記録まで行う。

### ✅ 2. システム間の統合（インテグレーション）

SIEM、ファイアウォール、IAM、ITSMなどを**APIで自動連携**させ、人間が手動でデータを移し替えなくてもいい環境を作る。

> 💡 **API（エーピーアイ）とは**: アプリ同士が自動で会話できる仕組み。LINEとカレンダーを連携させるようなイメージ。

### ✅ 3. 標準化されたプロセスの構築

チームや環境が異なっても、同じ手順・基準で作業できるようにルールを統一する。

### 今後の動向

セキュリティ業界では **SOAR（Security Orchestration, Automation and Response）** と呼ばれる「セキュリティ作業の自動化・連携ツール」への注目が高まっています。今後はAIとの組み合わせで、「すき間の作業」をどこまで自動化できるかが競争の焦点になるでしょう。

## 用語解説

| 用語 | 読み方 | 意味 |
|---|---|---|
| **SIEM** | シーム | Security Information and Event Management。複数のシステムからログを集めて異常を検知するツール |
| **MTTR** | エムティーティーアール | Mean Time To Remediate。問題発見から修復完了までの平均時間 |
| **IAM** | アイアム | Identity and Access Management。誰がどのシステムにアクセスできるかを管理する仕組み |
| **ITSM** | アイティーエスエム | IT Service Management。ITの問題・依頼を管理するシステム（チケット管理など） |
| **API** | エーピーアイ | Application Programming Interface。アプリ同士が自動で連携するための仕組み |
| **SOAR** | ソアー | Security Orchestration, Automation and Response。セキュリティ作業を自動化・連携させるツール群 |
| **オンプレミス** | - | 会社内に物理的に設置されたサーバーやシステム（クラウドの対義語） |
| **ゼロトラスト** | - | 「社内だから安全」という考えを捨て、全アクセスを常に検証するセキュリティの考え方 |
| **最小権限の原則** | - | ユーザーに必要最低限のアクセス権だけを与えるセキュリティの基本ルール |
| **アラート疲れ（Alert Fatigue）** | - | 大量のアラートに慣れすぎて、本当に重要な警告を見逃すようになる状態 |
| **ボトルネック** | - | 全体の流れを遅くしている一番詰まっている箇所。瓶の首の細い部分が由来 |

---

> 💬 **まとめ**
> 
> セキュリティの問題は「監視ツールが足りない」だけでなく、**ツールとツールの間にある"人間の作業"がいかに非効率か**という点にも潜んでいます。どんなに高性能なAIや監視システムを入れても、それをつなぐ「橋」がなければ、対応は遅いままです。今後のセキュリティ強化は「何を検知するか」だけでなく「いかに素早く連携して対処するか」がカギになってきています。
