# マイクロソフト製ウイルス対策ソフトに新たなゼロデイ脆弱性「RoguePlanet」発見！最新Windows環境でも管理者権限を乗っ取られる恐れ

**元記事**: [Microsoft Defender RoguePlanet Zero-Day Grants SYSTEM Access on Updated Windows](https://inl03.netline.com/ltr6/?_m=3n.009a.4000.sp0ao46r89.31xk)
**解説日**: 2026年6月11日

---

## 背景知識

まず、このニュースを理解するために必要な基礎知識を整理しましょう。

### Microsoft Defenderって何？
**Microsoft Defender（マイクロソフト・ディフェンダー）** は、Windowsに最初から組み込まれているウイルス対策ソフトです。追加費用なしで使えるため、多くのWindowsユーザーが頼っているセキュリティの「盾」のような存在です。

### ゼロデイ脆弱性って何？
**ゼロデイ脆弱性（Zero-Day）** とは、ソフトウェアのメーカーがまだ知らない、または修正パッチ（修正プログラム）をリリースしていない段階で発見・公開されたセキュリティの穴のことです。  
「ゼロデイ（0日）」という名前は、「メーカーが対応できた日数がゼロ」という意味から来ています。家のドアの鍵穴に欠陥があるのに、鍵屋さんにまだ知らせていない、あるいは修理されていない状態でその情報が広まってしまったようなイメージです。

### SYSTEM権限って何？
Windowsには「誰がパソコンを操作しているか」によって、できることの範囲（権限）が異なります。

| 権限レベル | 説明 | 例え |
|---|---|---|
| 一般ユーザー | 自分のファイルだけ操作できる | アパートの住人 |
| 管理者（Administrator） | ほとんどの設定を変更できる | 管理人 |
| **SYSTEM** | OSの最深部まで何でもできる | ビルのオーナー |

**SYSTEM権限** はWindowsで最も強い権限です。これを乗っ取られると、パソコン上で何でも自由にできてしまいます。

### PoC（概念実証コード）って何？
**PoC（Proof of Concept）** とは、「この脆弱性は実際に悪用できますよ」と証明するために作られたサンプルの攻撃プログラムです。研究者が脆弱性の深刻さを示すために使いますが、悪意ある人に使われると本物の攻撃になってしまう危険性もあります。

## 何が起きたのか

「Chaotic Eclipse（混沌の日食）」または「Nightmare-Eclipse（悪夢の日食）」というニックネームを持つ匿名のセキュリティ研究者が、Microsoft Defenderに存在する新たなゼロデイ脆弱性「**RoguePlanet（ローグプラネット＝はぐれ惑星）**」の攻撃実証コード（PoC）をGitHub上で公開しました。

### 特に怖いポイント
- ✅ **最新のWindows 10・11でも動作する**（2026年6月のパッチ適用済み環境でも！）
- ✅ 攻撃が成功すると、**SYSTEM権限のシェル（コマンド操作画面）** が取得できてしまう
- ✅ 別のセキュリティ研究者が実際に試したところ、**1回目で成功した**と報告

> 💡 **「シェル」とは？**  
> コンピュータに直接命令を入力できる画面（コマンドプロンプトのようなもの）のことです。SYSTEM権限のシェルを得るということは、パソコンを完全に支配できる状態になるということです。

## 技術的な詳細

### 攻撃の仕組み：「レースコンディション」

この攻撃は**レースコンディション（Race Condition）** という手法を使っています。

**例え話で説明すると：**  
2人の人が同時に銀行ATMから引き出しをしようとしているとき、ATMの処理がほんの一瞬「残高確認」と「引き出し実行」の間にタイムラグがある場合、そのすきをついて「残高がある」と誤認させつつ、実際には二重に引き出せてしまうことがあります。

コンピュータでも同様に、**2つの処理が同時に走る一瞬のタイミング**をついて、本来できないはずのことをやってしまうのがレースコンディション攻撃です。

```
通常の処理の流れ：
[Defenderがファイルを確認] → [安全と判断] → [処理完了]

攻撃の流れ：
[Defenderがファイルを確認] → ⚡この瞬間にすり替え！⚡ → [悪意あるファイルが実行される]
```

### ISO画像のマウントを悪用
記事によると、この脆弱性は**ISOファイルのマウント**に関係しています。

> 💡 **ISOファイルとは？**  
> CD・DVDディスクのデータをまるごと1つのファイルにまとめたものです。「マウント」とは、そのISOファイルをあたかも本物のディスクを入れたかのようにパソコンに認識させることです。

Windows 10・11では一般ユーザーでもISOをマウントできますが、Windows Serverではできないため、現状このPoCはサーバー環境では動作しません（ただし研究者は「サーバーも理論的には脆弱」と述べています）。

### 成功率にムラがある
研究者自身が「ある機種では100%成功するが、別の機種では動かないこともある」と述べています。レースコンディション攻撃はタイミング依存のため、マシンの性能や状態によって成否が変わります。

## なぜ重要なのか

### 🚨 深刻な理由3つ

**① 最新環境でも有効**  
通常、セキュリティパッチを最新にしておけばある程度安全ですが、今回はそれが通用しません。2026年6月のパッチ適用済みWindowsでも脆弱性が存在します。

**② 守るはずのソフト自体が攻撃の入り口に**  
ウイルスから守るためのDefenderが、逆に攻撃の踏み台になるというのは非常に皮肉で深刻な状況です。鍵をかけるために使う錠前屋が不正侵入の手口を持っているようなものです。

**③ 連続する脆弱性公開**  
今回の「RoguePlanet」は、同じ研究者が最近公開したDefenderの脆弱性シリーズの最新版です：

| 脆弱性名 | CVE番号 |
|---|---|
| BlueHammer（ブルーハンマー） | CVE-2026-33825 |
| UnDefend（アンディフェンド） | CVE-2026-45498 |
| RedSun（レッドサン） | CVE-2026-41091 |
| **RoguePlanet（今回）** | 未割り当て |

そして、**過去3つの脆弱性はすでに実際の攻撃に悪用されている**ことが確認されています。

### 公開の背景：研究者とMicrosoftの対立
この連続した脆弱性公開の背景には、研究者とMicrosoftの深刻な対立があります。

研究者は以下のような主張をしています：
- Microsoftが自分の脆弱性報告を無視・却下した
- 報奨金（バグバウンティ）を支払ってもらえなかった
- MSRCアカウント（脆弱性報告用の公式窓口）へのアクセスを一方的に停止された
- 自分の名誉を傷つけられた

これに対しMicrosoftは：
- 「脆弱性の無許可公開は決して正当化されない」
- 「顧客を不必要なリスクにさらす行為だ」
- 「セキュリティ研究を犯罪扱いする意図はない」
- 「協調的な脆弱性開示（CVD）を強く支持する」

と述べています。

> 💡 **協調的脆弱性開示（CVD）とは？**  
> 脆弱性を発見した研究者が、まずメーカーに非公開で連絡し、修正パッチが出来上がってから公開する、という業界の慣習・ルールです。いきなり公開すると悪用されるリスクが高まるため、「協力して対処しよう」という考え方です。

また、GitHubとGitLab上の研究者アカウントも削除されており、別のセキュリティ研究者 Kevin Beaumont氏は「MicrosoftがGitHubの所有者権限を乱用して自社製品の脆弱性情報を隠蔽しようとしている」と批判しています。

## 対策・今後の展望

### 今すぐできること

| 対策 | 説明 |
|---|---|
| **Windowsアップデートを常に最新に** | 今は有効ではないが、パッチがリリースされたら即適用が必須 |
| **怪しいソフトを実行しない** | この脆弱性は「すでに攻撃者がログインしている状態」での権限昇格に使われる可能性があるため、最初の侵入口を作らないことが重要 |
| **多層防御を心がける** | Defender単体に頼らず、不審なメールを開かない・怪しいサイトにアクセスしないなどの基本を徹底する |

### ⚠️ 現状の厳しい現実
残念ながら、**現時点でこの脆弱性に対する公式パッチは存在しません**。Microsoftは修正に取り組んでいると思われますが、公式な対応はまだ発表されていない状況です。

### 今後の展望
- Microsoftが緊急パッチをリリースすることが期待されます
- 研究者とMicrosoftの対立が続く限り、さらなる脆弱性公開のリスクがあります
- GitHubアカウントが削除されても、情報はすでに広まっており、悪意ある第三者が攻撃に転用する可能性が高まっています

## 過去記事との関連

以前「**マイクロソフトが過去最多206件の脆弱性を修正（2026年6月）**」という記事を解説しました。あの記事では、Microsoftが月例パッチで大量の脆弱性を修正したというポジティブな内容でしたが、今回はその**最新パッチを適用しても防げない新たな脆弱性**が発見されたというニュースです。

「パッチを当てても安全とは限らない」という現実を改めて突きつけられる内容であり、セキュリティ対策は一度やれば終わりではなく、**継続的な監視と対応が必要**だということがよくわかります。

## 用語解説

| 用語 | 説明 |
|---|---|
| **ゼロデイ脆弱性** | メーカーが修正パッチを出せていない未知・未修正のセキュリティの穴 |
| **Microsoft Defender** | Windowsに標準搭載のウイルス対策ソフト |
| **SYSTEM権限** | Windowsで最も強い操作権限。何でも実行可能 |
| **PoC（概念実証コード）** | 脆弱性が実際に悪用できることを証明するサンプルの攻撃コード |
| **レースコンディション** | 2つの処理が同時進行する一瞬のタイミングのすきをついた攻撃手法 |
| **ISOファイル・マウント** | ディスクのデータを1ファイルにまとめたもの（ISO）を仮想ドライブとして読み込む操作 |
| **シェル** | コンピュータに直接命令を入力できる操作画面 |
| **CVE番号** | 脆弱性に割り当てられる世界共通の識別番号 |
| **MSRC** | Microsoft Security Response Center。脆弱性を報告する公式窓口 |
| **協調的脆弱性開示（CVD）** | 脆弱性をまずメーカーに非公開で報告し、修正後に公開するというルール |
| **バグバウンティ** | 脆弱性を発見・報告した研究者に企業が支払う報奨金制度 |
| **権限昇格** | 低い権限のユーザーが、不正な手段で高い権限を得ること |

---

> 🔑 **今回のまとめ**  
> Windows標準のセキュリティソフト「Defender」に、最新パッチ適用済みでも悪用できる深刻な脆弱性が公開されました。研究者とMicrosoftの対立が背景にあり、今後も同様の公開が続く可能性があります。公式パッチが出るまでは、基本的なセキュリティ習慣（怪しいファイルを開かない、不審なサイトにアクセスしない）を徹底することが最善の対策です。
