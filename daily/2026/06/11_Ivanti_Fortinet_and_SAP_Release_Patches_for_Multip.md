# Ivanti・Fortinet・SAPが複数の深刻な脆弱性にパッチを公開

**元記事**: [Ivanti, Fortinet, and SAP Release Patches for Multiple Critical Vulnerabilities](https://inl03.netline.com/ltr6/?_m=3n.009a.4001.sp0ao46r89.31z4)
**解説日**: 2026年6月12日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な知識を押さえておきましょう。

### 今回登場する会社とソフトウェアって何？

| 会社名 | 製品名 | 一言で言うと |
|--------|--------|------------|
| **Fortinet** | FortiSandbox | 怪しいファイルやプログラムを「隔離された箱（サンドボックス）」の中で安全に動かして検査するセキュリティソフト |
| **Ivanti** | Ivanti Sentry | 会社のスマートフォンやタブレットを安全に管理するためのシステム（以前は「MobileIron」という名前でした） |
| **SAP** | NetWeaver / Commerce Cloud / Data Hub | 大企業が使う業務管理システム（在庫・会計・人事などをまとめて管理できる超大型ソフト） |

これらはどれも「企業向けの大切なシステム」です。学校に例えると、**学校全体の成績・出席・お金の管理をまとめてやっているシステム**のようなもの。もしここに穴があると、学校中の情報が盗まれてしまうイメージです。

### 「脆弱性（ぜいじゃくせい）」って何？

ソフトウェアの「セキュリティ上の穴」のことです。家の鍵に例えると、**「特定の方法でドアを叩くと鍵なしで開いてしまうバグ」**のようなものです。

### 「CVSSスコア」って何？

脆弱性の深刻さを **0〜10点** で表した数字です。

- 🟡 **7.0〜8.9** = 「重大」
- 🔴 **9.0〜10.0** = 「緊急（最も危険）」

今回の脆弱性はほぼすべて **9点以上** という、超危険なレベルです。

## 何が起きたのか

**Fortinet・Ivanti・SAPの3社が、同時期に複数の深刻な脆弱性を修正するパッチ（修正プログラム）を公開しました。**

簡単にまとめると：

- 🔴 **Fortinet（FortiSandbox）**: 攻撃者がログインなしで、サーバーに好き勝手なコマンド（命令）を送り込める穴（CVSSスコア: 9.1）
- 🔴 **Ivanti（Sentry）**: 2つの穴があり、1つは **完全リモートコントロール可能**（CVSSスコア: **10.0 = 満点！**）、もう1つは**管理者アカウントを勝手に作れる**（CVSSスコア: 9.9）
- 🔴 **SAP**: 4つの穴があり、なりすまし・メモリ破壊・不正アクセスなどが可能（CVSSスコア: 9.0〜9.9）

現時点では「実際に攻撃に使われた」という証拠はありませんが、非常に危険な状態です。

## 技術的な詳細

それぞれの脆弱性の「仕組み」をわかりやすく解説します。

### 🔵 Fortinet: コマンドインジェクション（CVE-2026-25089）

**コマンドインジェクション**とは、「入力欄に悪意ある命令を混ぜ込む攻撃」です。

> **例え話**: レストランの注文票に「ハンバーガー。あと金庫も開けておいて」と書いたら、店員さんが本当に金庫を開けてしまった…というイメージです。

FortiSandboxのWeb画面（WEB UI）に特殊なHTTPリクエスト（ウェブへの命令）を送ると、システムがそれを「正当な命令」と勘違いして実行してしまいます。しかも**ログイン不要**で攻撃できます。

### 🔴 Ivanti: OSコマンドインジェクション（CVE-2026-10520、CVSSスコア: 10.0）

これが今回最も危険な脆弱性です。

攻撃の流れを図にすると：

```
攻撃者
 │
 │  特殊なHTTPリクエストを送信
 ▼
/mics/api/v2/sentry/mics-config/handleMessage（というアドレス）
 │
 │  「設定の変更命令だ！」と誤解される
 ▼
handleExecute()（というプログラム部品）
 │
 │  命令を実行してしまう
 ▼
攻撃者がサーバーの最高権限（root）を取得 💀
```

「root（ルート）権限」とは、コンピューターの**すべての操作ができる神様のような権限**のことです。これを取られると、ファイルの盗み見・削除・改ざんなど何でもできてしまいます。

**修正方法**: Ivantiは問題のあるアドレスへのアクセスを遮断し、ログインしていない人はログインページに飛ばすように変更しました。セキュリティ研究者のSonny Macdonald氏は「単に穴をふさぐだけでなく、前に認証（ログイン確認）という壁を追加した。二重の対策だ」と評価しています。

### 🟠 Ivanti: 認証バイパス（CVE-2026-10523、CVSSスコア: 9.9）

**認証バイパス**とは、「ログインの仕組みをすり抜ける攻撃」です。

> **例え話**: 学校の入口に「生徒証を見せてください」というガードがいるのに、「裏口から入ればノーチェックで入れる」という抜け道があるイメージです。

この脆弱性を使うと、ログインなしで**管理者アカウントを自分で作り、完全な管理権限を取得**できてしまいます。

### 🟡 SAP: 4つの脆弱性

| 脆弱性ID | 種類 | 危険な内容 |
|---------|------|-----------|
| CVE-2026-44748 | XMLシグネチャラッピング | なりすましで他人の権限を乗っ取れる |
| CVE-2026-27671 | メモリ破壊 | ログインなしでサーバーを壊せる |
| CVE-2026-22732 | Springセキュリティの欠陥 | 不正アクセスが可能になる |
| CVE-2026-40128 | ディレクトリトラバーサル | 見てはいけないファイルを盗み見られる |

特にCVE-2026-44748（XMLシグネチャラッピング）は面白い仕組みで：

> **例え話**: 銀行の「本人確認済み」のスタンプが押された書類を手に入れて、中身の名前だけ書き換えて提出したら、銀行が「本人確認済みだ！」と信じてしまった…というイメージです。

正規の署名済みメッセージを改ざんしても、サーバーが「正しい署名だ」と誤って認識してしまうのです。

## なぜ重要なのか

### 影響を受ける人の規模が大きい

これらの製品は**世界中の大企業・官公庁・金融機関**が使っています。

- **FortiSandbox** → 大企業のセキュリティ部門
- **Ivanti Sentry** → 従業員のスマホ・タブレットを管理している企業
- **SAP** → 世界中の大企業（フォーチュン500企業の**9割以上**がSAP製品を使用していると言われています）

### CVSSスコア10.0という「満点の危険度」

Ivantiの脆弱性（CVE-2026-10520）はCVSSスコアが**10.0（満点）**です。これは：

- ✅ ネット経由で攻撃できる
- ✅ ログイン不要
- ✅ 特別な技術がなくても攻撃できる可能性がある
- ✅ 攻撃が成功すると完全なシステム支配ができる

…という、最悪の条件が揃っているためです。

### 「まだ悪用されていない」は油断できない

記事には「現時点では悪用の証拠はない」とありますが、脆弱性が公表されると**ハッカーたちが一斉に試し始める**のがセキュリティ業界の現実です。パッチを当てるまでの時間が勝負です。

## 対策・今後の展望

### 今すぐできる対策（利用企業向け）

各製品のアップデートを**今すぐ適用**することが最優先です：

**Fortinet FortiSandbox**
| 現在のバージョン | アップデート先 |
|----------------|--------------|
| 5.0.0〜5.0.5 | **5.0.6以上**にアップグレード |
| 4.4.0〜4.4.8 | **4.4.9以上**にアップグレード |
| Cloud/PaaS 5.0.4〜5.0.5 | **5.0.6以上**にアップグレード |

**Ivanti Sentry**
- **R10.5.2・R10.6.2・R10.7.1以上**にアップグレード

**SAP**
- 各製品の最新パッチを適用（SAP公式のセキュリティノートを確認）

### 一般的なセキュリティの教訓

1. **ソフトウェアは常に最新版を使う** → パッチが出たらすぐ当てる
2. **不要な外部アクセスを制限する** → 攻撃に使われたAPIエンドポイントへの外部からのアクセスを制限する
3. **ログを監視する** → 不審なアクセスがないか定期的に確認する

## 用語解説

| 用語 | 説明 |
|------|------|
| **脆弱性（ぜいじゃくせい）** | ソフトウェアのセキュリティ上の穴。攻撃者に悪用される可能性がある |
| **パッチ** | 脆弱性を修正するための更新プログラム。「穴をふさぐ当て布」のイメージ |
| **CVE** | 脆弱性に付けられる世界共通の識別番号（例: CVE-2026-10520） |
| **CVSSスコア** | 脆弱性の深刻さを0〜10で表した数値。10が最も危険 |
| **コマンドインジェクション** | 悪意ある命令をシステムに混ぜ込む攻撃手法 |
| **認証バイパス** | ログインの仕組みをすり抜けて不正アクセスする攻撃 |
| **HTTPリクエスト** | ウェブサーバーへの「お願い・命令」のこと |
| **root権限** | コンピューターの最高管理者権限。何でもできる神様レベルの権限 |
| **XMLシグネチャラッピング** | 正規の署名済み文書を改ざんして、サーバーに誤って受け入れさせる攻撃 |
| **ディレクトリトラバーサル** | 「../../../」などを使って、本来アクセスできないフォルダのファイルを盗み見る攻撃 |
| **メモリ破壊** | プログラムが使うメモリ（作業領域）を壊して、異常な動作を引き起こす攻撃 |
| **サンドボックス** | 怪しいプログラムを安全な隔離環境で動かして検査する仕組み |
| **エンドポイント（API）** | ソフトウェア同士が通信するための「窓口」となるURLのこと |
