# AIの進化で「セキュリティ監視サービス」が限界に？MDRの課題を解説

**元記事**: [Rethinking MDR as Attackers and Defenders Embrace AI](https://inl03.netline.com/ltr6/?_m=3n.009a.4002.sp0ao46r89.31zi)
**解説日**: 2025年1月

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえましょう。

### 🏢 企業のセキュリティ現場とは？

大きな会社には毎日**何十万件もの「セキュリティアラート（警告）」**が届きます。アラートとは、「怪しいログインがあった」「変なファイルが実行された」といった通知のことです。しかし、これを全部人間がチェックするのは不可能に近いです。

### 🔍 MDR（Managed Detection and Response）とは？

**MDR（マネージド・ディテクション・アンド・レスポンス）**とは、日本語に訳すと「**外部委託型の脅威検知・対応サービス**」のことです。

> 🏥 **例え話**：自分の会社に24時間365日の警備員を雇う余裕がないとき、「警備会社」に監視をお願いするイメージです。セキュリティ版の「警備委託サービス」がMDRです。

2010年代から多くの企業が採用してきた、セキュリティの「定番サービス」でした。

### 🤖 AIを使った攻撃とは？

近年、ハッカー（攻撃者）たちはAIを使って攻撃を自動化・強化しています。
- **フィッシングメール**（偽メールで情報を騙し取る攻撃）をAIで大量生成
- **マルウェア**（悪意あるソフトウェア）をAIで変形させ、検知を回避
- **偵察作業**（ターゲットの弱点調査）をAIで自動化

### 📊 MITRE ATT&CKフレームワークとは？

**MITRE ATT&CK（マイター・アタック）**は、攻撃者がどのような手順・技術で侵入するかをまとめた「攻撃手法の辞典」のようなものです。セキュリティの専門家が防御策を評価するときの「物差し」として使われます。

---

## 何が起きたのか

この記事は、**長年使われてきたMDRというセキュリティサービスが、AI時代の脅威に追いつけなくなっている**という問題を指摘したものです。

具体的には、以下の3つの深刻な問題が明らかになっています。

### ❶ アラートの60%が誰にも見られていない

MDRは「24時間365日監視します！」と約束しますが、実際には**全アラートの約60%は誰にも確認されていない**のが現実です。

> 📬 **例え話**：学校のポストに毎日100通の手紙が届くけど、先生たちは「緊急」と書かれた手紙しか開封できない。残りの60通は机の上に積まれたまま...という状態です。

なぜかというと、現代の企業環境では**人間が処理できる量をはるかに超えるアラート**が発生するからです。担当者は重要度の高いものから順番に処理するため、低優先度のアラートは後回しになります。

### ❷ 低優先度アラートに本物の脅威が潜んでいる

2025年の調査（世界中の企業から集めた**2500万件のアラートを分析**）によると、

- 本物の脅威の約**1%は「低優先度・情報提供レベル」のアラートから発生**していた
- 年間45万件のアラートが届く企業の場合、**週1件ペースで「本物の事件」が見落とされている計算**になる

> 🕵️ **例え話**：泥棒は正面玄関から堂々と入らず、誰も気にしない裏口の小さな鍵穴を狙います。ハッカーも同じで、わざと「低優先度」に見せかけた手口で侵入します。

### ❸ 対応品質が「その日の担当者」によって変わる

高優先度アラートが確認されても、**調査の質が一定ではない**という問題もあります。
- 夜中の3時のアラートと、昼間のアラートでは調査の深さが違う
- 担当者の経験・スキルによって判断にばらつきが出る
- 人手が足りない時間帯は対応が浅くなりがち

## 技術的な詳細

### 🔄 検知エンジニアリングの「悪循環」

MDRには「**検知エンジニアリング**」という、「どんな怪しい動きをアラートとして通知するか？」というルールを作る作業があります。

しかし現状では：

```
【問題のある現状サイクル】

アナリストがアラートを調査
    ↓
「誤検知（偽物）」として処理して終わり
    ↓
でもその判断結果はルールの改善に活かされない
    ↓
同じ間違ったルールが何度も誤検知を出し続ける
    ↓
本当の脅威を見逃すルールも放置される
```

> 🏫 **例え話**：学校のテストで「この問題の答え方が間違っていた」とわかっても、次のテストの問題が修正されないまま使い回されるようなイメージです。

### 🤖 AIが攻撃をどう変えたか

| 昔の攻撃 | AI時代の攻撃 |
|---------|-------------|
| 手作業でフィッシングメール作成 | AIで数千通を自動生成・個別最適化 |
| 固定パターンのマルウェア | 毎回形を変えて検知を回避 |
| 手動での偵察活動 | AIで自動的に脆弱点を探索 |
| エンドポイント（PC端末）中心 | クラウド・ID・ネットワーク全方位に拡大 |

### 🔒 MDRの「ブラックボックス問題」

多くのMDRサービスは**顧客に調査プロセスを見せない**設計になっています。

- 顧客が受け取るのは「要約レポート」だけ
- どんな証拠を見て、どんな判断をしたか確認できない
- 問題があっても気づけない

## なぜ重要なのか

### 📈 影響の大きさ

この問題は「一部の大企業だけの話」ではありません。

- **MDRを導入している企業は「守られている」と信じている**が、実際には週1件レベルで脅威が見落とされている可能性がある
- 「見落とされた脅威」は企業内でひそかに広がり続ける（**ラテラルムーブメント**＝横移動と呼ばれる）
- データ漏洩や業務停止などの深刻な被害につながる

### 🌐 社会的な影響

もし大企業や医療機関・インフラ企業のMDRが機能不全に陥っていたとすると：

- 個人情報の大規模漏洩
- 病院・電力・交通などの重要インフラへの攻撃の見落とし
- 社会的に大きな混乱を招く可能性

### 💡 構造的な問題

これは「MDRの担当者がサボっている」という話ではありません。**人間の処理能力の限界と、AI時代の攻撃量・速度のミスマッチ**という、構造的な問題です。

## 対策・今後の展望

### ✅ 企業が今できること

#### 1. 「AIファースト」なセキュリティへの移行を検討する
人間がアラートを1件ずつ確認する体制から、**AIが全アラートを自動分析・自動対応**する仕組みへの移行が求められています。

#### 2. MDRサービスの「中身」を確認する
- 実際に何%のアラートが調査されているか数字で聞く
- 低優先度アラートへの対応方針を確認する
- 調査プロセスを透明化してもらう（ブラックボックスにさせない）

#### 3. 検知ルールを定期的に見直す
- 誤検知の多いルールを改善する仕組みを作る
- MITRE ATT&CKフレームワークを使って「どの攻撃パターンに対応できているか」を定期評価する

### 🔮 業界の今後の方向性

```
現在のMDR（人間中心）
    ↓ 変革が求められている
次世代のセキュリティ運用（AI + 人間の協働）

・AIが全アラートをリアルタイムで自動分類・調査
・人間はAIが判断できない複雑な判断だけに集中
・調査結果が自動でルール改善にフィードバックされる
・24時間均質な対応品質を保てる
```

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **MDR** | エムディーアール | Managed Detection and Response。外部委託型のセキュリティ監視・対応サービス |
| **アラート** | あらーと | セキュリティシステムが発する「怪しい動きがあった」という通知・警告 |
| **フィッシング** | ふぃっしんぐ | 偽メールや偽サイトで個人情報やパスワードを騙し取る攻撃 |
| **マルウェア** | まるうぇあ | 「悪意のあるソフトウェア」の総称。ウイルス・ランサムウェアなど |
| **偵察（リコネサンス）** | ていさつ | 攻撃前にターゲットの弱点や情報を調査する活動 |
| **ラテラルムーブメント** | らてらるむーぶめんと | 侵入後、攻撃者が社内ネットワークを横移動して権限を拡大すること |
| **誤検知（False Positive）** | ごけんち | 本当は問題ないのに「危険」と誤ってアラートが出ること |
| **検知エンジニアリング** | けんちえんじにありんぐ | 何をアラートとして通知するかのルールを設計・改善する作業 |
| **MITRE ATT&CK** | まいたーあたっく | 攻撃者の手口・技術をまとめた「攻撃手法の辞典」。防御評価の物差しとして使われる |
| **CVE** | しーぶいいー | 公開されたソフトウェアの脆弱性（セキュリティの弱点）の識別番号 |
| **P1/P2/P3/P4** | ぷりおりてぃ | アラートの優先度分類。P1が最高優先度、P4が最低優先度 |
| **エンドポイント** | えんどぽいんと | ネットワークに接続されたPC・スマホなどの端末機器 |

> 💬 **まとめると...**
> 
> 「うちの会社はセキュリティ会社に監視を頼んでいるから安心」と思っていても、AIを駆使する攻撃者の前では**従来のMDRモデルには構造的な穴がある**という話です。全アラートの60%が未確認、見落とされた脅威が週1件ペースで潜伏...これは「完璧なサービスはない」という現実を改めて教えてくれます。セキュリティは「任せっきり」ではなく、**定期的に「本当に機能しているか？」を検証することが大切**です。
