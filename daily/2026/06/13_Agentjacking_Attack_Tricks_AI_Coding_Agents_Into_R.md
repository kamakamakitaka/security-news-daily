# AIコーディングエージェントを乗っ取る「Agentjacking」攻撃が発見される

**元記事**: [Agentjacking Attack Tricks AI Coding Agents Into Running Malicious Code](https://inl03.netline.com/ltr6/?_m=3n.009a.4003.sp0ao46r89.321k)
**解説日**: 2025年6月17日

---

## 背景知識

このニュースを理解するために、まずいくつかのキーワードを押さえておきましょう。

### 🤖 AIコーディングエージェントとは？
「Claude Code」や「Cursor」といったAIツールのことです。プログラマーが「このバグを直して」と指示すると、AIが自動でコードを読んで修正してくれる、いわば**AIプログラマーのアシスタント**です。最近、多くの開発現場で使われるようになっています。

### 🐛 Sentry（セントリー）とは？
ソフトウェアが動いているときに起きたエラーを自動的に記録・通知してくれるツールです。例えば「このアプリ、昨日午後3時にこういうエラーが100件起きました」という報告書を作ってくれます。多くの企業が無料で使える**オープンソースのバグ監視サービス**です。

### 🔑 DSN（Data Source Name）とは？
Sentryにエラーを送るための「投稿用パスワード」のようなものです。重要な点は、**誰でも書き込めるが、読み取りには制限がある**という仕組みになっています。そして、このDSNはウェブサイトのソースコードに公開された形で埋め込まれていることが多いです。

### 🔌 MCP（Model Context Protocol）とは？
AIエージェントが外部のサービス（SentryやGitHubなど）と連携するための「橋渡しの仕組み」です。AIが「Sentryのエラー情報を見せて」とお願いすると、MCPがその情報を取ってきてAIに渡してくれます。

---

## 何が起きたのか

セキュリティ企業「Tenet Security」の研究者たちが、**「Agentjacking（エージェントジャッキング）」** と名付けた新しい攻撃手法を発見しました。

この攻撃を一言で言うと：

> **「AIアシスタントに偽の指示書を読ませて、悪意あるプログラムをこっそり実行させる」** 攻撃です。

攻撃者はターゲットの会社のサーバーに侵入することなく、**Sentryという信頼されたツールを経由して**、AIに悪質なコードを実行させることができます。

研究チームは実際に100社以上でテストを行い、なんと**85%の成功率**を達成しました。また、少なくとも**2,388もの組織**が攻撃可能な状態にあることも確認されています。

## 技術的な詳細

攻撃の流れを、**宅配便の例え話**で説明します。

---

### 📦 例え話：偽の配達指示書

あなたが「倉庫管理AI」を雇っているとします。このAIは倉庫に届いた荷物の伝票を読んで、自動で指示通りに作業してくれます。

1. 悪い人が、**本物そっくりの偽の伝票**を倉庫に送りつけます
2. AIは「これは正式な指示書だ」と信じてしまいます
3. AIが伝票に書かれた「金庫を開けて中身を外に出せ」という指示を実行してしまいます

---

### 🔍 実際の攻撃ステップ

```
①  攻撃者が、ターゲット企業のウェブサイトから
    Sentry DSN（公開されている書き込みキー）を見つける

         ↓

②  そのDSNを使って、Sentryに「偽のエラー報告」を送り込む
    ※ エラーの内容に「悪意あるコマンド」をこっそり仕込む

         ↓

③  開発者がAIエージェントに
    「Sentryのエラーを直して」と頼む

         ↓

④  AIエージェントがMCP経由でSentryに接続し、
    偽のエラー報告（=攻撃者の命令）を受け取る

         ↓

⑤  AIは「これはSentryからの正当な修正手順だ」と信じ込み、
    開発者のパソコン上で悪意あるコードを実行してしまう！
```

### 🎭 騙しのポイント：マークダウン偽装

攻撃者は偽のエラーメッセージの中に、本物のSentryのメッセージと**見た目がそっくりな書式（マークダウン形式）** を使って指示を埋め込みます。AIには本物と偽物の区別がつかないため、攻撃者の命令を「正規の修正手順」だと思って実行してしまいます。

### 😱 漏れる可能性がある情報
攻撃が成功すると、以下のような機密情報が盗まれる可能性があります：
- 🔐 環境変数（APIキーやパスワードなど）
- 🗂️ Gitの認証情報（ソースコード管理システムのログイン情報）
- 🔒 非公開リポジトリのURL（社内の秘密のコードの場所）
- 👤 開発者の個人情報

## なぜ重要なのか

### 🛡️ 従来のセキュリティ対策をすり抜ける

この攻撃の最も恐ろしい点は、**既存のセキュリティツールでは検知できない**ことです。

| セキュリティ対策 | 通常の攻撃 | Agentjacking |
|---|---|---|
| ファイアウォール | ✅ ブロック可能 | ❌ すり抜ける |
| WAF（Webアプリ防御） | ✅ ブロック可能 | ❌ すり抜ける |
| EDR（端末監視） | ✅ 検知可能 | ❌ すり抜ける |
| VPN | ✅ 保護できる | ❌ 関係ない |

なぜなら、**AIエージェントが「自分の意思で」正当な権限を使って実行している**ように見えるからです。セキュリティシステムからすれば、「開発者本人が許可した操作」と区別がつきません。

### 📈 AI活用が増えるほどリスクが拡大

現在、多くの企業がAIコーディングエージェントを業務に取り入れています。AIを信頼して使えば使うほど、この攻撃の被害を受けやすくなるというジレンマがあります。

### 🏢 Sentryの対応が不十分

Sentryは問題を認識していますが、「技術的に完全な修正は難しい」として**根本的な修正を行わない**という判断をしました。一部の特定の攻撃パターンをブロックするフィルターを追加しただけで、本質的な問題は解決されていません。

---

## 対策・今後の展望

### 👨‍💻 開発者ができる対策

1. **AIエージェントに外部サービスの「自動実行」を許可しない**
   - 「修正案を提示するだけ」にして、実際の実行は人間が確認してから行う設定にする

2. **AIエージェントが実行しようとしているコードを必ず確認する**
   - 「何でもやって」ではなく、「提案だけして、実行前に見せて」というモードで使う

3. **Sentryの権限を最小限にする**
   - AIエージェントからSentryへのアクセス権限を制限する

4. **DSNの管理を厳重に行う**
   - 使っていないDSNは無効化する

### 🏗️ 業界全体での課題

- AIエージェントが外部サービスのデータを**盲目的に信頼しない**仕組みが必要
- MCPのようなプロトコルに**データの信頼性を検証する機能**を追加する必要がある
- AIを使った開発環境向けの**新しいセキュリティ基準**の整備が急務

## 過去記事との関連

以前、**「GoogleがGemini AIを悪用した中国のフィッシング詐欺ネットワークを訴えた」** というニュースを解説しました。あの事件では「AIを道具として悪用して人間を騙す」攻撃でした。

今回のAgentjackingはさらに一歩進んでいます。**「AIそのものを騙して、AIに悪事を実行させる」** という新しいステージの攻撃です。

```
【AIの悪用の進化】

フェーズ1：AIを使って人間を騙す（フィッシング詐欺など）
    ↓
フェーズ2：AIを騙して、AIが人間の代わりに悪事を働く（今回）
```

この流れは、**AIが社会に深く組み込まれるほど、AIへの攻撃が増える**という重要なトレンドを示しています。AIを守るセキュリティの重要性が、今後ますます高まっていくことがわかります。

## 用語解説

| 用語 | 読み方 | 意味 |
|---|---|---|
| **AIコーディングエージェント** | - | コードを自動で書いたり修正したりするAIツール（例：Claude Code、Cursor） |
| **Sentry** | セントリー | ソフトウェアのエラーを自動で記録・通知するオープンソースツール |
| **DSN** | ディーエスエヌ | Sentryにエラーを送るための公開されたキー（書き込み専用） |
| **MCP** | エムシーピー | AIが外部サービスと連携するための標準的な仕組み |
| **マークダウン（Markdown）** | - | 文章の見た目を整えるための記法（#で見出し、**で太字など） |
| **プロンプトインジェクション** | - | AIへの入力に悪意ある命令を混ぜ込んで誤動作させる攻撃 |
| **EDR** | イーディーアール | パソコンやサーバーの不審な動作を監視するセキュリティソフト |
| **WAF** | ワフ | Webサービスへの不正なアクセスを防ぐ防御システム |
| **IAM** | アイエーエム | 誰がどのシステムにアクセスできるかを管理する仕組み |
| **環境変数** | かんきょうへんすう | プログラムが使うパスワードやAPIキーなどを保存する設定値 |
| **Gitリポジトリ** | ギット- | ソースコードを管理・保存するためのシステム |
| **オープンソース** | - | プログラムのコードが公開されていて誰でも使えるソフトウェア |

---

> 💡 **まとめ**：AIアシスタントは非常に便利ですが、「AIが信頼しているデータ」を改ざんすることで、AIを悪用できることが証明されました。「便利なものには落とし穴がある」という視点で、AIツールを使う際は常に「本当にこの操作を実行していいか」を人間が確認する習慣が大切です。
