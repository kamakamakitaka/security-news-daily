# 400以上のArch Linuxパッケージが乗っ取られ、情報窃取ツールとルートキットが仕込まれた事件

**元記事**: [Over 400 Arch Linux AUR Packages Hijacked to Deploy Infostealer and eBPF Rootkit](https://inl03.netline.com/ltr6/?_m=3n.009a.4003.sp0ao46r89.3212)
**解説日**: 2025年6月

---

## 背景知識

この事件を理解するために、まずいくつかのポイントを押さえましょう。

### 🐧 Arch Linuxとは？
**Arch Linux（アーチ・リナックス）** は、エンジニアや開発者に人気のある「Linux（リナックス）」というOS（基本ソフト）のひとつです。Linuxとは、WindowsやmacOSのように、パソコンを動かすための基盤となるソフトウェアのことです。Arch Linuxは「自分で細かく設定できる」ことが売りで、主にIT技術者や開発者が使います。

### 📦 パッケージ・リポジトリとは？
スマートフォンに「App Store」や「Google Play」があるように、Linuxにも**ソフトウェアをまとめてダウンロードできる場所**があります。これを**リポジトリ（パッケージ置き場）** と呼びます。

今回の舞台となった **AUR（Arch User Repository）** は、**ユーザーが自由にソフトウェアのレシピを投稿・管理できる非公式の場所**です。公式リポジトリよりも審査が緩い分、便利なソフトが多く揃っていますが、その分リスクもあります。

### 🔨 ビルドスクリプト（PKGBUILD）とは？
AURのソフトウェアは「レシピ（PKGBUILDというテキストファイル）」として公開されています。ユーザーがそのレシピを使うと、パソコンが自動でソフトをダウンロード・組み立て（ビルド）してインストールします。**料理レシピのようなもの**で、「何をどこから持ってきて、どう調理するか」が書いてあります。

### 🦠 今回登場する主な脅威の種類
| 用語 | 簡単な説明 |
|------|-----------|
| **インフォスティーラー** | パソコンの中の情報（パスワードなど）を盗み出すマルウェア |
| **ルートキット** | 自分の存在をOSから隠すための悪意あるソフト |
| **eBPF** | Linuxの深い部分で動く仕組み。本来は監視ツール用だが、悪用されると非常に危険 |
| **マルウェア** | 悪意のあるソフトウェア全般の総称 |

## 何が起きたのか

### 事件の概要

2025年6月11日以降、**AURに登録されている400以上のパッケージが攻撃者に乗っ取られました。**

具体的には：

1. 攻撃者が**メンテナー（管理者）が放棄したパッケージ**を探し出す
2. そのパッケージを自分のものとして**正式に引き継ぐ**（AURのルール上、これは合法的にできる）
3. パッケージのレシピ（PKGBUILD）に**こっそり悪意あるコードを追加**する
4. 何も知らないユーザーがそのパッケージをインストールすると、**マルウェアが自動的に実行される**

> 🍳 **料理で例えると…**
> あなたが信頼していた料理本（パッケージ）の著者が引退したあと、知らない人がこっそりレシピを書き換えて「材料の一つとして毒を入れる」ように変更した、というイメージです。本のタイトルも見た目も変わっていないので、読む人は気づきません。

### この攻撃の巧妙な点

攻撃者はさらに**Gitのコミット履歴（変更記録）を偽造**しました。「この変更は昔からの信頼できるメンテナーがやった」ように見せかけたのです。実際にはそのアカウントは一切関与していなかったことが後から判明しています。

## 技術的な詳細

### 🎣 攻撃の仕掛けはどこに？

悪意あるコードはレシピ（PKGBUILDまたは.installスクリプト）の中に追加されました。具体的には：

```
npm install atomic-lockfile
```

というコマンドが追加され、これを実行すると **`atomic-lockfile`** という悪意あるnpmパッケージ（JavaScriptのライブラリ）が一緒にダウンロードされます。

> **npm（エヌピーエム）** とは、JavaScriptのソフトウェアを共有するための別のパッケージ置き場です。

このnpmパッケージには**「インストール前に自動実行されるフック（仕掛け）」** があり、その中に `deps` という悪意あるプログラムが入っています。パッケージをビルドする（組み立てる）だけで、このプログラムが走ってしまいます。

### 🕵️ マルウェアが盗む情報

Rust（プログラミング言語）で作られたこのマルウェアは、主に**開発者のパソコン**を狙っています。盗み出す情報は非常に広範囲です：

| カテゴリ | 具体的な内容 |
|----------|-------------|
| **ブラウザ情報** | Chrome、Edge、Braveなどのクッキー・ログイントークン・保存データ |
| **コミュニケーションツール** | Slack、Discord、Microsoft Teamsのセッションデータ |
| **開発者向けサービス** | GitHubのトークン、npmの認証情報、HashiCorp Vaultのキー |
| **AIサービス** | OpenAI/ChatGPTのAPIキーとアカウント情報 |
| **SSH情報** | SSHキー、接続履歴（known_hosts）、コマンド履歴 |
| **インフラ情報** | DockerやPodmanの認証情報、VPNの設定 |

> **SSHキー**とはサーバーに安全にアクセスするための「鍵」のようなものです。これが盗まれると、攻撃者がそのサーバーに自由に入れてしまいます。

### 📡 盗んだ情報の送り先

盗まれたファイルは **temp.sh** というサービスを使ってインターネット経由で外部に送信されます。攻撃者との通信は **Torネットワーク**（追跡が非常に困難な匿名通信網）経由で行われます。

### 🔁 しつこく居座る仕組み（持続性）

マルウェアは**「電源を切っても再起動後にまた動き出す」** ように自分をシステムに登録します。これを**パーシステンス（持続性）** といいます：

- **管理者権限がある場合**：`/etc/systemd/system/` にサービスを登録
- **一般ユーザーの場合**：`~/.config/systemd/user/` に登録

どちらの場合も `Restart=always`（常に再起動）という設定になっており、消そうとしてもすぐに復活します。

### 👻 eBPFルートキットによる隠蔽

管理者権限がある場合、マルウェアはさらに**eBPFルートキット**を起動します：

- **`hidden_pids`**：マルウェアのプロセス（動いているプログラム）を隠す
- **`hidden_names`**：プロセス名を隠す
- **`hidden_inodes`**：通信ポートを隠す
- **デバッガーをブロック**：調査ツールを起動しようとすると強制終了させる

> 🔦 **例え話**：部屋の電気を点けても（ツールで調査しても）、泥棒が「透明マント」を着ているせいで見えない、というイメージです。

## なぜ重要なのか

### 🎯 ターゲットが「開発者」という点が深刻

今回の攻撃は、一般のユーザーではなく**IT開発者やエンジニアを狙っています**。これは非常に重要な意味を持ちます：

- 開発者のパソコンには**会社のサーバーにアクセスできるSSHキーやGitHubトークン**が入っている
- それが盗まれると、**その開発者が関わる全てのプロジェクトや会社のシステム**が危険にさらされる
- 一人の開発者への攻撃が、**数百〜数千人のユーザーに影響するサービス**への侵入口になり得る

### 🔓 「ソフトウェアのサプライチェーン攻撃」という手口

この攻撃は**「ソフトウェア・サプライチェーン攻撃」** と呼ばれる種類に属します。ソフトそのものにバグがあったわけではなく、**ソフトが配布される流通経路を汚染した**攻撃です。

> 🏭 **工場で例えると…**：食品工場のラインに侵入して、出荷前の商品に異物を混入させるようなイメージです。商品自体は正規品ですが、出荷時点で汚染されている。

### ⚠️ パッケージを削除しても完全には消えない

記事の中で特に強調されていた重要な点：

> 「パッケージを削除するだけでは不十分。ルートキット機能を持つマルウェアが一度でも実行されたなら、パッケージマネージャーでは機械が完全にきれいかどうかを保証できない」

つまり、**もし感染した可能性があるなら、OSの再インストールを考える必要がある**ということです。

## 対策・今後の展望

### ✅ もしAURユーザーであれば今すぐやること

1. **6月11日以降にインストール・更新したAURパッケージを確認する**
   - Arch Linuxのメーリングリストやコミュニティで公開されている「影響を受けたパッケージリスト」と照合する
   
2. **感染の疑いがあれば、パスワードを全て変更する**
   - 特にGitHub、npm、各種クラウドサービスのパスワードとAPIキー
   - SSHキーを全て無効化して再生成する

3. **ブラウザのセッションを全て無効化する**
   - Chrome、Edge、Brave等のブラウザからログアウトし、保存済みのセッションを消去する

4. **重篤な場合はOSの再インストールを検討する**
   - ルートキットが入った可能性があるなら、パッケージを消すだけでは不十分

### 🛡️ AURを使う際の一般的な注意点

- AURは**公式リポジトリよりリスクが高い**ことを常に意識する
- PKGBUILDの中身を**インストール前に読む習慣**をつける
- **長期間メンテナーがいないパッケージ（孤児パッケージ）**の使用は特に注意する
- `makepkg`で作業する際は**仮想環境やサンドボックス（隔離された環境）**を使う

### 🔮 今後の展望

この事件を受けて、Arch LinuxのコミュニティはAURの**孤児パッケージの引き継ぎ審査を強化する**方向で議論が進むと予想されます。また、npmパッケージ側でも `atomic-lockfile` の削除対応が行われています。

## 過去記事との関連

今回の事件は、過去に起きた **XZ Utils事件（2024年）** と非常に似た構造を持っています。XZ Utilsでも、攻撃者が長期間かけて開発者コミュニティに信頼を築き、オープンソースソフトウェアにバックドア（裏口）を仕込みました。

共通点：
- **オープンソースの信頼モデルを悪用**している
- **技術的な脆弱性（バグ）ではなく、「人やプロセスへの信頼」を狙っている**
- 一般ユーザーではなく**インフラを支える開発者・エンジニアをターゲット**にしている

このような「**サプライチェーン攻撃**」は増加傾向にあり、オープンソースコミュニティにとって深刻な課題となっています。

## 用語解説

| 用語 | 解説 |
|------|------|
| **AUR（Arch User Repository）** | Arch Linuxユーザーがソフトウェアのレシピを自由に投稿・管理できる非公式パッケージ置き場 |
| **PKGBUILD** | AURでのパッケージのレシピファイル。「何を、どこから、どう組み立てるか」が書かれている |
| **インフォスティーラー** | パソコン内の認証情報や個人データを盗み出すマルウェアの一種 |
| **eBPF（Extended Berkeley Packet Filter）** | Linuxカーネル（OSの心臓部）で動く仕組み。本来は監視・パフォーマンス分析用だが、悪用可能 |
| **ルートキット** | 自分の存在をOSや管理ツールから隠すマルウェア。発見・除去が非常に難しい |
| **サプライチェーン攻撃** | ソフトウェアの配布経路（流通ルート）を汚染する攻撃。ソフト本体ではなく「届けるルート」を狙う |
| **npm** | JavaScriptのパッケージを共有するシステム。Node.js開発者が使う |
| **Tor（トーア）** | 通信を複数のサーバーに経由させ、発信元を追跡困難にする匿名通信ネットワーク |
| **SSH（Secure Shell）** | サーバーに安全にリモート接続するための技術。SSHキーは「鍵と鍵穴」のように使う |
| **systemd** | Linuxでサービス（バックグラウンドプログラム）を管理するシステム |
| **ビルド** | ソースコードやレシピを元に、実際に動くソフトウェアを「組み立てる」プロセス |
| **プリインストールフック** | パッケージをインストールする「前に」自動的に実行されるスクリプト |
| **クリプトマイナー** | 暗号通貨を無断で採掘（マイニング）するマルウェア。パソコンのCPU・GPUを勝手に使う |
| **HashiCorp Vault** | パスワードやAPIキーなどの機密情報を安全に管理するためのツール |
| **APIキー** | サービスにアクセスするための「合言葉」のようなもの。盗まれると不正利用される |

---

> 💡 **まとめると…**
> 今回の事件は「ソフトウェアを信頼する仕組みそのものを武器にした攻撃」です。バグや欠陥があったわけではなく、**コミュニティの善意と信頼の仕組みが悪用されました**。技術的なセキュリティだけでなく、「誰が、何を、どのように管理しているか」を確認することの大切さを改めて示す事件です。
