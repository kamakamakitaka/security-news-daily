# Splunk Enterpriseの重大な脆弱性：ログイン不要でコードを実行できる危険な欠陥が発見された

**元記事**: [Critical Splunk Enterprise Flaw Lets Attackers Run Code Without Authentication](https://inl03.netline.com/ltr6/?_m=3n.009a.4004.sp0ao46r89.323g)
**解説日**: 2026年6月16日

---

## 背景知識

このニュースを理解するために、まずいくつかのキーワードを押さえておきましょう。

### Splunk（スプランク）とは？
Splunkは、企業や組織が「ログ（システムの動作記録）」を収集・分析するためのソフトウェアです。銀行や病院、大企業など、コンピューターを大規模に使っている組織が「何かおかしいことが起きていないか？」を監視するために使います。いわば、**会社のコンピューター全体を見張る監視カメラシステムのようなもの**です。Splunkは現在、ネットワーク機器で有名なCiscoという大企業の傘下にあります。

### PostgreSQL（ポストグレスキューエル）とは？
PostgreSQLは、データベース管理システムの一種です。**データベース**とは、大量のデータを整理して保存・検索できる「巨大な電子棚」のようなものです。Splunkは内部でこのPostgreSQLを使ってデータを管理しています。

### 認証（Authentication）とは？
認証とは、「あなたは誰ですか？」を確認する仕組みです。スマホのパスコードや、ウェブサービスのID・パスワード入力がこれにあたります。**「認証なし（Unauthenticated）」**とは、この確認をすり抜けて、つまり**誰でも・どこからでも**アクセスできてしまう状態を意味します。

### リモートコード実行（Remote Code Execution / RCE）とは？
攻撃者が、**インターネット越しに遠く離れた場所から**、対象のコンピューターに好き勝手なプログラムを動かせてしまうことです。これはセキュリティの世界で最も危険な攻撃の一つとされています。「家の鍵を壊して侵入し、家の電気・ガス・水道をすべて自由に操作できる」ようなイメージです。

---

## 何が起きたのか

Splunkは2026年6月、自社のソフトウェア「**Splunk Enterprise**」に非常に深刻なセキュリティ上の欠陥（脆弱性）が見つかったとして、修正アップデートを公開しました。

この脆弱性は**CVE-2026-20253**という識別番号がつけられており、深刻度のスコアは**9.8点（満点10点）**という、ほぼ最高レベルの危険度です。

具体的に何が問題かというと、Splunk Enterpriseの特定のバージョンでは、**パスワードなしで誰でもサーバー内のファイルを操作したり、任意のプログラムを実行したりできてしまう**抜け穴が存在していたのです。

影響を受けるバージョンは以下の通りです：

| バージョン | 状況 |
|---|---|
| 10.0.0 〜 10.0.6 | 影響あり → 10.0.7で修正済み |
| 10.2.0 〜 10.2.3 | 影響あり → 10.2.4で修正済み |
| 10.4以降 | 影響なし |

なお、クラウド版の「Splunk Cloud」はこの問題の影響を受けません。

## 技術的な詳細

セキュリティ研究機関「watchTowr Labs」が、この脆弱性がどのように悪用できるかを詳しく発表しました。少し難しいですが、できるだけわかりやすく説明します。

### 問題の根本原因

Splunk Enterpriseには、PostgreSQLデータベースのバックアップ（データの保存）やリストア（データの復元）を行うための「窓口（エンドポイント）」が存在します。

- `/v1/postgres/recovery/backup`（バックアップ用）
- `/v1/postgres/recovery/restore`（リストア用）

本来、これらの窓口には**「あなたは誰ですか？」という認証チェックが必要なはず**ですが、なんとこれが**まったく存在していませんでした**。これはつまり、誰でもこの窓口を叩けば中に入れてしまう、鍵のかかっていない非常口のようなものです。

### 攻撃の流れ（ステップごとに解説）

攻撃者がこの脆弱性を悪用する手順を、例え話を交えて説明します。

```
【例え話】
図書館（Splunkサーバー）に、
スタッフ用の通用口（認証なしエンドポイント）が
鍵もかかっていない状態で放置されていた、という状況です。
```

**ステップ①：罠のデータベースを作る**
攻撃者はまず、自分のコンピューター上に**罠を仕込んだデータベース**を用意します。このデータベースには、悪意のある命令（SQLクエリ）が含まれています。

**ステップ②：バックアップ機能を悪用してファイルを書き込む**
認証チェックのない「バックアップ用の窓口」を使って、その罠のデータベースの内容をSplunkサーバー内の任意の場所にファイルとして書き込みます。

```
【例え話】
通用口から図書館に侵入し、
「偽の本（罠のファイル）」を本棚に差し込む感じです。
```

**ステップ③：リストア機能で悪意のあるコードを実行させる**
今度は「リストア用の窓口」を使って、さきほど書き込んだ罠のデータベースをSplunkのPostgreSQLに読み込ませます。すると、データベースに仕込んでおいた悪意のある命令が自動的に実行されます。

ここで使われるのが**`lo_export`**という機能です。これはデータベース内のデータをファイルとして書き出せる正規の機能ですが、攻撃者はこれを使って**悪意のあるPythonスクリプト（プログラム）**をSplunkのシステムフォルダに書き込みます。

**ステップ④：Splunkが自動的にウイルスを実行してしまう**
Splunkは定期的に特定のPythonスクリプトを自動実行する仕組みを持っています。攻撃者はそのスクリプトファイルを上書きしてしまうため、**Splunk自身が攻撃者のプログラムを実行してしまう**のです。

```
【例え話】
図書館員（Splunk）が毎朝決まった本棚の本を読む習慣があったとします。
攻撃者がその本をこっそり差し替えておけば、
図書館員自身が「罠の本（悪意のあるプログラム）」を読んでしまう、という状態です。
```

## なぜ重要なのか

### 危険度が非常に高い理由

1. **認証が不要** → パスワードやアカウントがなくても攻撃できる
2. **ネットワーク越しに実行可能** → 世界中どこからでも攻撃できる
3. **CVSSスコアが9.8** → セキュリティの世界では「ほぼ最悪レベル」

### 影響を受ける組織は？

Splunk Enterpriseは主に企業・官公庁・病院・金融機関など「重要なシステムを守る立場」の組織が使っています。これらの組織のSplunkが乗っ取られると：

- 📂 機密データの盗み取り
- 🔒 システムへの完全なアクセス権の取得
- 💥 ランサムウェア（身代金要求型ウイルス）の展開
- 🕵️ 監視システム自体の無効化・改ざん

といった被害が起こりえます。「セキュリティを守るためのソフト自体が乗っ取られる」という最悪のシナリオです。

### 現時点では？

記事執筆時点では、**実際にこの脆弱性を悪用した攻撃は確認されていません**。しかし、watchTowr Labsが攻撃手順の技術的な詳細を公開してしまったため、悪意のある攻撃者がその情報をもとに攻撃を試みるリスクが高まっています。

## 対策・今後の展望

### 今すぐやるべきこと

もしSplunk Enterpriseを使っている場合は、**今すぐバージョンを確認し、アップデートしてください**。

| あなたのバージョン | やること |
|---|---|
| 10.0.0 〜 10.0.6 | **10.0.7にアップデート** |
| 10.2.0 〜 10.2.3 | **10.2.4にアップデート** |
| 10.4以降 | 影響なし（念のため確認を） |
| Splunk Cloud | 影響なし |

### すぐにアップデートできない場合

- PostgreSQLのサイドカーサービスへのネットワークアクセスを、**ファイアウォール（外部からの通信を遮断する壁）で制限する**
- 不審なアクセスや動作がないか、ログを注意深く監視する

### 今後の動向

技術的な攻撃手順がすでに公開されているため、セキュリティ専門家たちは「攻撃が近く始まる可能性が高い」と警戒しています。Splunkユーザーは一刻も早いアップデートが推奨されます。

## 過去記事との関連

以前、「**Palo Alto社のVPN接続ソフトの重大な脆弱性が実際の攻撃に悪用されている**」というニュースを解説しました。今回のSplunkの脆弱性も、構造的に似た問題を抱えています。

どちらも共通しているのは、**「企業のネットワークやシステムを守るためのセキュリティ製品自体に穴が空いてしまった」**という点です。こういったセキュリティ製品は、多くの重要な組織で使われているため、一つの脆弱性が非常に広範囲に影響を与えます。

また、Palo Altoの脆弱性は「すでに実際の攻撃に使われている」状況でしたが、今回のSplunkの件は「まだ攻撃は確認されていないが、技術的な詳細が公開されてしまった」段階です。過去の事例から見ると、詳細が公開された後に攻撃が急増するパターンが多いため、今が対応のタイムリミットと言えます。

## 用語解説

| 用語 | 意味 |
|---|---|
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやシステムのセキュリティ上の欠陥・弱点 |
| **CVE（Common Vulnerabilities and Exposures）** | 脆弱性に付けられる国際的な識別番号。「CVE-年-番号」の形式 |
| **CVSS（Common Vulnerability Scoring System）** | 脆弱性の深刻度を0〜10点で評価するスコアシステム。9.8は「緊急」レベル |
| **認証（Authentication）** | IDやパスワードなどで「誰であるか」を確認する仕組み |
| **リモートコード実行（RCE）** | 遠隔地から対象コンピューターで任意のプログラムを実行できる攻撃 |
| **PostgreSQL** | オープンソースのデータベース管理システム |
| **エンドポイント** | ここではAPIの「窓口」のこと。特定のURLにアクセスすると機能が実行される |
| **バックアップ/リストア** | データの「保存/復元」のこと |
| **lo_export** | PostgreSQLの機能で、データベース内のデータをファイルとして書き出すもの |
| **Pythonスクリプト** | Python言語で書かれたプログラムファイル |
| **ファイアウォール** | 外部からの不正な通信を遮断するセキュリティの「壁」 |
| **ランサムウェア** | ファイルを暗号化して使えなくし、解除と引き換えに身代金を要求するウイルス |
| **サイドカーサービス** | メインのアプリを補助するために並走する小さなサービスプログラム |
