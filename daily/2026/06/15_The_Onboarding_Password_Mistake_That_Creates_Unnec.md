# 入社初日のパスワード管理ミスが生み出す不要なリスク

**元記事**: [The Onboarding Password Mistake That Creates Unnecessary Risk](https://inl03.netline.com/ltr6/?_m=3n.009a.4004.sp0ao46r89.322a)
**解説日**: 2025年7月14日

---

## 背景知識

このニュースを理解するために、まず「オンボーディング」という言葉を説明します。

**オンボーディング（Onboarding）** とは、新入社員が会社に入ったとき、仕事に必要なパソコン・アカウント・システムへのアクセス権限などを準備して渡す「入社手続き」のことです。学校で言えば、入学初日に教科書や学生証が配られる感じをイメージしてください。

この手続きの中で必ず発生するのが **「最初のパスワードを新入社員に伝える」** という作業です。これが今回の記事のテーマです。

> 💡 **ポイント**: パスワードは「鍵」のようなもの。玄関の鍵をどうやって新居の住人に渡すか、という問題に似ています。郵便で送る？電話で伝える？どれも完璧ではありませんよね。

---

## 何が起きたのか

### 「仮パスワード」が生み出す危険な穴

多くの会社では、新入社員に最初のパスワード（仮パスワード）を渡すとき、以下のような方法をとっています：

| 方法 | 例 |
|------|-----|
| メールで送る | 「あなたの初期パスワードは〇〇です」 |
| SMSで送る | テキストメッセージで通知 |
| 口頭で伝える | 電話や対面で教える |

これらの方法には **大きな問題**があります。

1. **メール・SMSの場合**：もし途中でメッセージが盗み見られたり、別の人に転送されてしまったら？攻撃者がそのパスワードで会社のシステムに侵入できてしまいます。

2. **口頭の場合**：上司や第三者を通じてパスワードを伝言するうちに、意図せず漏れてしまうリスクがあります。

3. **最大の問題**：仮パスワードが「仮」のままにならないこと。忙しい新入社員が「後で変えよう」と思いつつ、結局ずっと変えないケースが多発しています。

> 🔑 **例え話**: 引っ越し業者に家の合鍵を渡したのに、引っ越し後もその鍵を回収し忘れたようなもの。「まあいっか」で放置すると、後で大変なことになります。

## 技術的な詳細

### なぜ仮パスワードは危険なのか？

仮パスワードには、以下のような「弱さ」が最初から組み込まれています：

```
❌ 仮パスワードの特徴
- 大量の新入社員に配るため、シンプルで覚えやすいものが多い
  例: "Welcome2024" や "Company123" など
- 推測されやすいパターンで作られることが多い
- セキュリティより「配りやすさ」が優先されている
```

攻撃者（ハッカー）にとって、このような弱いパスワードは「開けっ放しの窓」も同然です。

### より安全な解決策：自分でパスワードを設定する

記事では **「Specops First Day Password」** という製品が紹介されています。これは、会社が仮パスワードを配布する必要をなくす仕組みです。

**仕組みはこうです：**

```
従来の方法:
  会社がパスワードを作成 → メール/SMSで送信 → 新入社員がログイン

新しい方法:
  新入社員が本人確認 → 自分でパスワードを設定 → ログイン
```

具体的には、新入社員が個人のメールアドレスや電話番号で **本人確認** を行い、自分自身でパスワードを最初から設定します。会社側が仮パスワードを作って渡す必要がなくなるわけです。

> 🏦 **例え話**: 銀行のキャッシュカードの暗証番号を銀行員が決めて郵送するのではなく、ATMで自分が最初に設定するイメージです。

## なぜ重要なのか

### 実際に起きた事件：アメリカの水道施設への攻撃

記事では、仮パスワード・デフォルトパスワードの放置がいかに危険かを示す実例が紹介されています。

**2023年11月、アメリカ・ペンシルベニア州の水道局「Aliquippa市水道局」が攻撃されました。**

- **攻撃者**: イランと関係があるとされるハクティビストグループ「Cyber Av3ngers」
  - ※ ハクティビスト＝政治的・社会的主張のためにサイバー攻撃を行うグループ
- **原因**: 工場や水道施設で使われる制御システムに、**初期設定のまま変更されていないデフォルトパスワード**が使われていた
- **影響**: 水道設備の制御システムへの不正アクセス（市民の生活インフラが標的に）

> ⚠️ **これが示すこと**: パスワードの管理ミスは、単なる会社の情報漏洩だけでなく、**社会インフラへの攻撃**につながる可能性があるのです。

### 影響の広がり

```
パスワードの管理ミス
    ↓
攻撃者が侵入
    ↓
・個人情報の流出
・会社のシステムが使えなくなる
・身代金要求（ランサムウェア）
・最悪の場合、社会インフラへの影響
```

## 対策・今後の展望

### 企業・組織が今すぐできること

| 対策 | 内容 |
|------|------|
| ✅ 仮パスワードを廃止する | 新入社員が自分でパスワードを設定する仕組みを導入 |
| ✅ 初回ログイン時に強制変更 | ログイン後、必ずパスワード変更を求める設定にする |
| ✅ 平文での送信を禁止 | パスワードをメール・SMSでそのまま送らない |
| ✅ デフォルトパスワードの一掃 | 機器・システムの出荷時パスワードを即座に変更 |
| ✅ 多要素認証の導入 | パスワードだけでなく、スマホ認証なども組み合わせる |

### 個人（あなた）ができること

- **「後で変えよう」は禁物**：パスワードの変更は後回しにしない
- **使い回しはNG**：同じパスワードを複数のサービスで使わない
- **初期パスワードはすぐ変える**：どんなサービスでも最初に変更する

## 用語解説

| 用語 | 解説 |
|------|------|
| **オンボーディング** | 新入社員が業務を開始するための準備・手続きのプロセス |
| **仮パスワード（テンポラリパスワード）** | 初回ログイン用に一時的に発行されるパスワード |
| **デフォルトパスワード** | 機器やソフトウェアの出荷・インストール時に設定されている初期パスワード（例: "admin"や"password"など） |
| **平文（プレーンテキスト）** | 暗号化されていない、そのまま読めるテキスト。メールで「パスワードは〇〇です」と書くのがこれにあたる |
| **ハクティビスト** | Hack（ハック）＋Activist（活動家）の造語。政治・社会的な主張のためにサイバー攻撃を行うグループ |
| **多要素認証（MFA）** | パスワード以外に、スマホへの通知や指紋認証なども組み合わせて本人確認をする方法 |
| **ランサムウェア** | システムを暗号化して使えなくし、解除のために身代金を要求するウイルスの一種 |
| **社会インフラ** | 電気・水道・ガスなど、社会生活を支える基盤となる設備やサービス |

---

> 📌 **まとめ**: パスワードの「配り方」と「変え忘れ」という一見小さなミスが、企業の情報流出から社会インフラへの攻撃まで、深刻な事態を招く可能性があります。「後で変えよう」という習慣を見直すことが、あなた自身と組織を守る第一歩です。
