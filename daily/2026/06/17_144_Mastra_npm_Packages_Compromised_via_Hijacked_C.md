# 144個のMastra npmパッケージが乗っ取られたアカウントによって汚染される

**元記事**: [144 Mastra npm Packages Compromised via Hijacked Contributor Account](https://inl03.netline.com/ltr6/?_m=3n.009a.4006.sp0ao46r89.325q)
**解説日**: 2025年6月（記事は2026年6月17日の出来事を報告）

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### 📦 npmとは？
**npm（Node Package Manager）** は、JavaScriptというプログラミング言語で作られた「便利な部品（パッケージ）」を共有・配布するための仕組みです。

料理に例えると、「自分でゼロからソースを作る代わりに、市販のソースを買ってきて使う」ようなイメージです。開発者は車輪の再発明をせずに、世界中の人が作った便利な部品をダウンロードして自分のプログラムに組み込めます。

### 🤖 Mastraとは？
**Mastra** は、AIアプリ（ChatGPTのようなシステム）を作るための人気のオープンソース（誰でも無料で使えるソフトウェア）フレームワークです。`@mastra/*` という名前のパッケージ群で構成されており、AI開発者に広く使われています。

### 🔗 サプライチェーン攻撃とは？
**サプライチェーン攻撃** とは、「直接ターゲットを攻撃する代わりに、ターゲットが使っている部品・材料を汚染する」攻撃手法です。

例え話で言うと：「レストランのシェフを直接毒殺しようとするのではなく、そのシェフが使う調味料の工場に毒を混入させる」ようなイメージです。攻撃者は一度に大量の被害者を狙えるため、非常に危険な手口です。

### 🏷️ 依存関係（Dependency）とは？
プログラムAがプログラムBの機能を使っているとき、「AはBに依存している」といいます。npmパッケージは他のパッケージを依存関係として使うことがよくあります。これが今回の攻撃のカギになります。

---

## 何が起きたのか

2026年6月17日、**88分間**という短時間で、以下のことが起きました。

1. 攻撃者が `ehindero` という **元Mastra開発者のnpmアカウントを乗っ取った**
2. そのアカウントを使って、**144個のMastraパッケージを一気に悪意ある版に書き換えた**
3. 書き換えの手口は「`easy-day-js` という罠のライブラリを依存関係に追加する」というものだった
4. この `easy-day-js` には **仮想通貨を盗むマルウェア（悪意のあるソフトウェア）** が仕込まれていた

**攻撃の準備**についても判明しています。攻撃者は事前に `easy-day-js` というパッケージを「完全に正常で便利な日付ライブラリ（`dayjs` のコピー）」として公開し、翌日（約18時間後）にそっと悪意あるコードを追加しています。これは**ウイルス検知システムをすり抜けるための巧妙な準備**です。

## 技術的な詳細

### 攻撃の流れを段階的に解説

```
【攻撃の流れ】

STEP 1: 準備
  攻撃者が "easy-day-js" という
  「一見無害な」日付ライブラリを公開
  → 最初はクリーンな状態

      ↓ 18時間後...

STEP 2: 罠を仕掛ける
  "easy-day-js" に悪意あるコードを追加
  （※難読化＝わかりにくく書き換えた状態で）

      ↓

STEP 3: 汚染パッケージの大量公開
  乗っ取ったアカウント(ehindero)で
  144個のMastraパッケージに
  "easy-day-js" を依存関係として追加

      ↓

STEP 4: 被害者がインストール
  開発者が npm install を実行
  → postinstallフックが起動
    （インストール後に自動で実行される処理）

      ↓

STEP 5: 第1段階 ペイロード実行
  攻撃者のサーバー(23.254.164.92)から
  第2段階のマルウェアをダウンロード
  ※TLS証明書検証を無効化して通信

      ↓

STEP 6: 痕跡消去
  ローダー（第1段階）が自分自身を削除
  バックグラウンドで静かに動き続ける

      ↓

STEP 7: 情報窃取
  ブラウザの履歴を収集
  160種類以上の仮想通貨ウォレットを狙う
  Windows/Mac/Linux すべてに対応
  盗んだ情報をC2サーバー(23.254.164.123)へ送信
```

### 特に巧妙なポイント

| テクニック | 説明 | 効果 |
|-----------|------|------|
| **クリーン版デコイ** | 最初は無害なライブラリとして公開 | セキュリティスキャンをすり抜ける |
| **難読化コード** | コードを人間が読みにくい形に変換 | 中身を分析されにくくする |
| **postinstallフック** | インストール時に自動実行 | 気づかれずに起動できる |
| **実行時ダウンロード** | 悪意あるコードを後から取得 | パッケージに直接悪いコードが入っていない |
| **自己削除** | 第1段階のローダーが消える | フォレンジック（デジタル捜査）を困難にする |
| **永続化** | OSが起動するたびに自動実行される仕組みを設置 | パッケージを削除しても生き残る |

### アカウント乗っ取りの問題点

`ehindero` アカウントは **かつてMastraに貢献していた開発者** のものでした。その人が貢献をやめた後も、**パッケージを公開できる権限（スコープアクセス）が削除されていなかった**ため、攻撃者に悪用されました。

これは「会社を辞めた社員のIDカードが無効化されていなかった」ようなセキュリティの穴です。

## なぜ重要なのか

### 🎯 特に危険な理由

MastraはAI開発向けのフレームワークです。AI開発環境には次のような**超重要な情報**が詰まっていることが多いです：

- **APIキー**（OpenAIやAWSなどのサービスを使うためのパスワードのようなもの）
- **クラウドの認証情報**（AWSやGCPなどのクラウドサービスへのアクセス権）
- **データベースのパスワード**
- **仮想通貨ウォレットの情報**

こういった情報が盗まれると、**莫大な金銭的被害や情報漏洩**につながる可能性があります。

### 📊 影響の規模

- 汚染されたパッケージ数：**144個**
- 攻撃にかかった時間：わずか **88分**
- 対応OS：**Windows・macOS・Linux すべて**
- 標的の仮想通貨ウォレット：**160種類以上**

### ⚠️ インストール後も危険が続く

JFrog社の指摘によれば、「たとえ最初の悪意あるパッケージを削除しても、第2段階のプロセスはすでに動いていて、永続化されている可能性がある」とのことです。

つまり**「気づいて消せばOK」ではない**という点が非常に恐ろしいところです。

## 対策・今後の展望

### 🚨 すでに影響を受けた可能性がある場合

もし問題のあるバージョンをインストールした場合：

1. **そのマシン（パソコン・CI環境など）は「感染済み」として扱う**
2. **APIキー・パスワード・認証情報をすべて変更する**（ローテーション）
3. **安全なバージョンにロールバック**（以前の正常な状態に戻す）
4. **システム全体のセキュリティ監査を実施**する

### 🛡️ 将来的な防止策

**開発者・組織向け**

| 対策 | 説明 |
|------|------|
| **使われなくなった貢献者の権限を削除** | 退職・離脱したメンバーのアクセス権を即座に無効化する |
| **SLSA認証（来歴証明）を必須にする** | パッケージが正規のCI/CDから来たことを証明する仕組みを強制する |
| **`npm audit signatures` を実行** | パッケージの署名を検証して改ざんを検知する |
| **依存関係の定期的な監査** | 使っているパッケージに怪しいものが混入していないか定期チェック |

**ポイント解説：SLSA（サプライチェーン完全性）とは？**
「このパッケージは正規の開発チームが、正規のビルド環境から公開したものです」という証明書のような仕組みです。今回、Mastraは証明書を生成していましたが「**証明書のないパッケージを拒否する設定**」にしていなかったため、攻撃者が証明書なしでパッケージを公開できてしまいました。

### 📌 現状の対応

npmはすでに主要なパッケージの悪意あるバージョンを削除し、正常なバージョンに戻しています。

## 過去記事との関連

今回紹介した過去記事はありませんが、この攻撃は**ソフトウェアサプライチェーン攻撃**の典型的な手口を組み合わせたものです。過去にも：

- **SolarWinds事件（2020年）**：ソフトウェアのアップデート機能を通じて米国政府機関が攻撃された
- **event-stream事件（2018年）**：人気npmパッケージのメンテナーが変わり、仮想通貨を盗むコードが追加された
- **XZ Utils事件（2024年）**：Linuxの圧縮ツールにバックドアが仕込まれた

…など、サプライチェーンを狙った攻撃は年々巧妙になっています。今回の事件もその流れの中にある**最新の事例**です。

## 用語解説

| 用語 | わかりやすい説明 |
|------|----------------|
| **npm** | JavaScriptの部品（パッケージ）を共有・ダウンロードする仕組み。「アプリストア」のようなもの |
| **パッケージ** | 再利用できるプログラムの部品。レシピで言う「市販の調味料」 |
| **依存関係（Dependency）** | あるプログラムが使っている他のパッケージ。「このプログラムはあのパッケージに依存している」 |
| **サプライチェーン攻撃** | ターゲット本体でなく、使っている部品・材料を汚染する攻撃 |
| **マルウェア** | 悪意を持って作られたソフトウェアの総称（ウイルス・トロイの木馬など） |
| **RAT（リモートアクセストロイの木馬）** | 攻撃者がリモートで感染したPCを操作できるようにするマルウェア |
| **postinstallフック** | パッケージインストール後に自動で実行されるスクリプト（処理） |
| **難読化（Obfuscation）** | コードを読みにくく変換して解析されにくくすること |
| **ペイロード** | マルウェアの「本体」となる悪意ある処理・コード |
| **C2サーバー** | 「Command & Control」の略。攻撃者がマルウェアに命令を出したり盗んだ情報を受け取ったりするサーバー |
| **永続化（Persistence）** | PCを再起動しても自動的にマルウェアが起動し続ける仕組みを作ること |
| **フォレンジック** | デジタル犯罪捜査。コンピュータに残った証拠を調べること |
| **SLSA** | ソフトウェアの「来歴証明」の仕組み。正規の場所から作られたことを証明する |
| **CI/CD** | ソフトウェアの自動ビルド・テスト・公開の仕組み（Continuous Integration/Delivery） |
| **スコープアクセス** | npmで特定の名前空間（@mastra/など）にパッケージを公開できる権限 |
| **TLS証明書検証** | 通信相手が本物かどうか確認するセキュリティ機能。今回はこれを無効化して怪しい通信を行った |
