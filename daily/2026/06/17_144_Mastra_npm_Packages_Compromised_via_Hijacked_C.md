# Mastraのnpmパッケージ144個がハッキングされた事件

**元記事**: [144 Mastra npm Packages Compromised via Hijacked Contributor Account](https://inl03.netline.com/ltr6/?_m=3n.009a.4006.sp0ao46r89.325q)
**解説日**: 2025年6月19日

---

## 背景知識

このニュースを理解するために、まずいくつかの前提知識を整理しましょう。

### 📦 npmとは？
**npm（Node Package Manager）**とは、JavaScriptのプログラムを作るときに便利な「部品（ライブラリ）」を共有・配布するための仕組みです。

料理に例えると、**「世界中のシェフが作ったレシピ・調味料を自由にダウンロードできるオンライン食材庫」**のようなものです。プログラマーは毎回ゼロから書かず、npmから必要な部品をダウンロードして使います。

### 🔗 依存関係（dependency）とは？
ソフトウェアAがソフトウェアBの機能を使っている場合、「AはBに依存している」と言います。

例えば「カレーライス」を作るのに「市販のルー」を使うようなもの。自分のプログラムが動くために、他の誰かが作ったパッケージが必要な状態です。

### 🏗️ サプライチェーン攻撃とは？
**ソフトウェアサプライチェーン攻撃**とは、ターゲットのソフトウェアを直接狙うのではなく、「そのソフトウェアが使っている部品（依存パッケージ）」に悪意あるコードを仕込む攻撃です。

工場に例えると、**完成品を直接壊すのではなく、材料の仕入れ先に毒を混入させる**イメージです。

### 🤖 Mastraとは？
**Mastra**は、AIアプリケーションを作るためのオープンソースのJavaScript/TypeScriptフレームワークです。多くの開発者やクラウドサービスで使われており、`@mastra/*`という名前空間で100個以上のパッケージが公開されています。

---

## 何が起きたのか

2026年6月17日、**Mastraに関連する144個のnpmパッケージが一斉に悪意ある改ざんを受けました。**

事件の流れをまとめると：

```
① 攻撃者が「ehindero」という元Mastra開発者のnpmアカウントを乗っ取る
        ↓
② 「easy-day-js」という偽の日付ライブラリをnpmに公開（一見無害なコピー）
        ↓
③ 翌日、easy-day-jsに悪意あるコードを追加
        ↓
④ 乗っ取ったアカウントで144個のMastraパッケージに
   「easy-day-js」を依存関係として追加・再公開（わずか88分で完了！）
        ↓
⑤ 開発者がMastraパッケージをインストールすると
   自動的にeasy-day-jsも一緒にインストールされ、マルウェアが動作
```

## 技術的な詳細

### 🎭 ステップ1：偽ライブラリの準備（えさの用意）

攻撃者は「**easy-day-js**」というパッケージを公開しました。これは「**dayjs**」という本物の有名な日付処理ライブラリの**完全なコピー**です。

最初は無害な状態で公開することで、セキュリティスキャンをすり抜けます。翌日、悪意あるコードを追加しました。

> 🍎 例え話：最初は普通のリンゴジュースとして販売しておき、翌日こっそり毒を混入させるようなイメージです。

### 🪝 ステップ2：postinstallフックで自動実行

npmには「**postinstall**」という仕組みがあります。これはパッケージをインストールした**直後に自動でコードを実行する機能**です。

攻撃者はこれを悪用し、インストールと同時にマルウェアが起動するようにしました。

### 🎁 ステップ3：二段階のマルウェア（入れ子構造）

マルウェアは2段階に分かれています：

| 段階 | 内容 |
|------|------|
| **第1段階** | 難読化（読みにくくしたコード）されたローダー。外部サーバーから本体をダウンロード |
| **第2段階** | 実際の情報窃取マルウェア本体 |

こうすることで、パッケージ自体にはほぼコードが入っておらず、セキュリティスキャンをかわしやすくなります。

### 🦠 ステップ4：マルウェアの能力

最終的に動作するマルウェアには以下の機能があります：

- 🌐 **ブラウザ履歴の盗み取り**
- 💰 **160種類以上の暗号通貨ウォレットの情報を窃取**
- 🔄 **Windows・macOS・Linuxすべてで自動起動（持続化）**
- 📡 **C2サーバー（攻撃者のコマンドセンター）への情報送信**
- 🎮 **攻撃者からのリモートコマンド実行**
- 🗑️ **証拠隠滅のための自己削除**

> 💡 **C2サーバー（Command & Control Server）**：攻撃者がマルウェアに命令を送ったり、盗んだデータを受け取ったりするための「司令部」サーバーです。

### 🧹 ステップ5：痕跡を消す

マルウェアは自分自身を削除し、バックグラウンドで静かに動作し続けます。「第1段階のパッケージを削除しても、第2段階はすでに動いていて、持続化もされている」という非常に厄介な設計です。

## なぜ重要なのか

### 🎯 攻撃対象が絶妙に選ばれている

MastraはAIアプリ開発に使われるフレームワークです。AIアプリの開発環境には：

- **クラウドサービスのAPIキー**（AWSやGCPなどへのアクセス権）
- **データベースのパスワード**
- **本番環境の認証情報**
- **暗号通貨ウォレットの鍵**

…といった超重要な情報が保存されていることが多いです。

### ⚡ 88分で144パッケージの改ざんは「自動化の脅威」

攻撃者は88分という短時間で144個のパッケージを一気に改ざんしました。これは**自動化スクリプト**を使っているからこそ可能なことで、人力では不可能なスピードです。セキュリティ側の対応が追いつきにくい状況を意味します。

### 🔑 退職した開発者のアカウント権限が残っていた

乗っ取られた「ehindero」アカウントは**元Mastraの貢献者**のものでした。その人がプロジェクトを離れた後も、**npmのスコープ（公開権限）が削除されていなかった**ため、攻撃者に悪用されました。

これは「退職した社員のIDカードが有効のままになっていた」ようなミスです。

## 対策・今後の展望

### 🚨 もし影響を受けたパッケージをインストールしていたら

1. **そのPCやCI環境は「侵害済み」として扱う**
2. **安全なバージョンにロールバック（元に戻す）する**
3. **その環境に保存されていたすべての認証情報・APIキーを今すぐ無効化して再発行する**
4. **不審なプロセスが動いていないか確認する**

### 🛡️ 開発者・企業が今後取るべき対策

| 対策 | 内容 |
|------|------|
| **SLSA来歴の確認を必須に** | パッケージがCI（自動ビルド）から正しく公開されたことを証明する仕組みを義務化する |
| **npm audit signatures** | パッケージの署名を検証し、非公式な方法で公開されたものを拒否する |
| **退職者のアクセス権を即時削除** | プロジェクトを離れた開発者のnpmスコープ権限を必ず取り消す |
| **依存パッケージの監視** | 新しい依存関係が追加されたときにアラートを出す仕組みを導入する |

### 📰 npm側の対応

npmはすでに**悪意あるバージョンを削除**し、主要パッケージの最新タグを安全なバージョンに戻しました。

## 過去記事との関連

今回の事件は、いわゆる**「ソフトウェアサプライチェーン攻撃」**の典型例です。

過去にも同様の手口として、**SolarWinds事件**（2020年）や**XZ Utils事件**（2024年）のように、広く使われているソフトウェアの配布経路を狙った攻撃が世界を騒がせてきました。

今回の特徴は「AI開発フレームワーク」という**新興・高価値ターゲット**が狙われた点で、AI開発の普及に伴い、この種の攻撃がますます増加することが予想されます。

## 用語解説

| 用語 | 意味 |
|------|------|
| **npm** | JavaScriptのパッケージ（部品）を共有・配布するためのシステム |
| **パッケージ** | プログラムの部品として再利用できるコードのまとまり |
| **依存関係（dependency）** | あるソフトウェアが動くために必要な別のソフトウェアとの関係 |
| **サプライチェーン攻撃** | ソフトウェアの材料（依存パッケージ）に悪意あるコードを混入する攻撃 |
| **postinstallフック** | npmパッケージのインストール直後に自動実行されるスクリプト |
| **難読化（obfuscation）** | コードを読みにくく変換して、解析・検知を困難にする手法 |
| **ドロッパー/ローダー** | 本体のマルウェアをダウンロード・実行するための小さなプログラム |
| **C2サーバー** | 攻撃者がマルウェアを遠隔操作するための司令塔サーバー |
| **RAT（Remote Access Trojan）** | 遠隔操作機能を持つトロイの木馬型マルウェア |
| **SLSA来歴証明** | ソフトウェアが正規のビルドプロセスで作られたことを証明する仕組み |
| **TLS証明書の検証無効化** | 通信の安全確認をオフにすること。攻撃者との通信を怪しまれずに行うための手法 |
| **持続化（persistence）** | PCを再起動してもマルウェアが自動で起動し続けるようにする仕組み |
| **スコープ（npm scope）** | `@mastra/*`のような名前空間で、パッケージをグループ化する仕組み |

---

> ⚠️ **まとめ**：今回の事件は「退職した開発者のアカウント権限が残っていた」というヒューマンエラーが出発点でした。技術的に高度な攻撃も、そもそもの入口は「アクセス権の管理ミス」という基本的なミスです。**「使われなくなった権限はすぐに削除する」**—これはセキュリティの基本中の基本として、ぜひ覚えておきましょう。
