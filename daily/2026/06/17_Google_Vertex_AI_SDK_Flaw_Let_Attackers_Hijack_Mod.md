# Google Vertex AI SDKの欠陥：攻撃者がAIモデルのアップロードを乗っ取れる「バケット横取り」攻撃

**元記事**: [Google Vertex AI SDK Flaw Let Attackers Hijack Model Uploads via Bucket Squatting](https://inl03.netline.com/ltr6/?_m=3n.009a.4006.sp0ao46r89.3268)
**解説日**: 2026年6月19日

---

## 背景知識

このニュースを理解するために、まず3つの概念を押さえておきましょう。

### 🤖 Vertex AI とは？
**Google Cloud が提供するAI開発プラットフォーム**です。企業や開発者が機械学習モデル（画像認識・翻訳・予測などを行うAIプログラム）を作って、クラウド上で動かすためのサービスです。

### 🪣 Cloud Storage「バケット」とは？
Google Cloudが提供するファイル置き場です。Amazonの段ボール箱のように「バケット（bucket＝バケツ）」という単位でデータを保管します。重要なのは、**バケットの名前は世界中でひとつしか使えない**（グローバルユニーク）という点です。これが今回の事件の核心です。

### 🐍 Pickleとは？
Python（プログラミング言語）でAIモデルを保存するときによく使われる形式です。便利な反面、**ファイルを読み込んだだけでプログラムが実行される**という危険な性質を持っています。ちょうど「開けるとバネで何かが飛び出る箱」のようなものです。

---

## 何が起きたのか

セキュリティ企業 **Palo Alto Networks の Unit 42 チーム**が、Google の AI 開発ツール（Vertex AI SDK）に深刻な欠陥を発見しました。

この欠陥を悪用すると、攻撃者は以下のことができてしまいます：

> **被害者のAIモデルを、自分が仕込んだ悪意あるモデルにすり替えて、Google のサーバー内でコードを実行する**

しかも怖いのは、攻撃者に必要なものが非常に少ないことです：

| 必要なもの | 状況 |
|---|---|
| 被害者のパスワード | ❌ 不要 |
| フィッシング詐欺 | ❌ 不要 |
| 被害者PCへの侵入 | ❌ 不要 |
| 被害者のプロジェクトID | ✅ 必要（でも多くは公開されている） |
| 自分のGoogle Cloudアカウント | ✅ 必要 |

Googleにはすでに報告され、修正済みです。SDKをバージョン **1.148.0 以降** に更新することで対処できます。

## 技術的な詳細

### 攻撃の仕組み：「Pickle in the Middle（ピクルス・イン・ザ・ミドル）」

Unit 42 はこの攻撃を **「Pickle in the Middle」** と名付けました。通信を途中で横取りする「中間者攻撃」と、Pickleファイルの危険性を組み合わせた名前です。

---

#### 🏠 例え話で理解しよう

引っ越し業者（Vertex AI SDK）が荷物（AIモデル）を届けるとき、こんな手順で動くとします：

1. 「○○倉庫が空いてるか確認する」
2. 「空いてたら荷物を預ける」
3. 「後でその倉庫から荷物を引き取る」

問題は「**その倉庫が本当に依頼者のものか確認しない**」ことでした。

攻撃者が先に「○○倉庫」という名前の場所を作っておけば、荷物は自動的に攻撃者の倉庫に届いてしまいます。

---

#### 🔢 実際のステップ

```
① 攻撃者が被害者のプロジェクトIDを調べる
   　（例：「myproject-12345」）

② SDKが生成するバケット名を予測する
   　（例：「myproject-12345-vertex-staging-us-central1」）

③ 攻撃者が先にその名前でバケットを自分のプロジェクトに作成する

④ 被害者がAIモデルをアップロードすると...
   　→ 被害者のSDKが「バケット存在確認」→ 「存在する！」→ 攻撃者のバケットにアップロード

⑤ 攻撃者が2.5秒以内に正規モデルを悪意あるPickleファイルに差し替える

⑥ Vertex AIが悪意あるモデルを読み込み → 攻撃者のコードが実行される
```

#### ⏱ 時間との戦い

Unit 42 の計測では、アップロードからVertex AIが読み込むまでわずか **2.5秒**。攻撃者のプログラムは **1.4秒** で差し替えを完了させました。これは「Cloud Functions（クラウドで動く自動プログラム）」を使った自動化のおかげです。

---

#### 💀 実行後に何が盗めるか

悪意あるコードが実行されると、攻撃者は以下の情報を入手できました：

- 🔑 **OAuthトークン**（Googleサービスへのアクセス権証明書）
- 🧠 **他のAIモデルの学習済みデータ**
- 📊 **BigQueryのメタデータ**（データベース情報）
- 📋 **アクセスリストやテナントログ**
- 🖥 **内部のコンテナ情報**（Google内部の構成情報）

## なぜ重要なのか

### 🎯 影響が大きい理由

**1. 被害者は何も気づかない**
SDKが「自動でバケットを選んでくれる」便利な機能を使っているだけなので、被害者には異常が見えません。

**2. 攻撃条件が現実的**
新しいプロジェクトでは「デフォルトのバケットがまだ存在しない」ことが多く、攻撃が成立しやすい状況です。

**3. AIサプライチェーン攻撃**
提供するAIモデルが悪意あるものに差し替えられることで、そのモデルを使うユーザー全員に被害が広がる可能性があります。これは「ソフトウェアのサプライチェーン攻撃」のAI版です。

**4. Google内部インフラへの侵入**
Google が管理するサーバー内でコードが動くため、通常ではアクセスできない情報まで取得できてしまいます。

## 対策・今後の展望

### ✅ 今すぐできる対策

#### 【最重要】SDKをアップデートする
```bash
pip install --upgrade google-cloud-aiplatform
# バージョン 1.148.0 以上にすること
```

#### 【推奨】バケットを明示的に指定する
```python
# ❌ 危険：デフォルトに任せる
model.upload(...)

# ✅ 安全：自分が管理するバケットを明示
model.upload(staging_bucket="gs://自分が管理するバケット名/", ...)
```

#### 【確認箇所】SDKが使われているすべての場所をチェック
- Jupyter Notebook（分析環境）
- CI/CDジョブ（自動テスト・デプロイ環境）
- 学習パイプライン
- 本番環境のサービス

### 🔧 Googleが施した修正の内容

| バージョン | 修正内容 |
|---|---|
| v1.144.0（3月31日） | バケット名にランダムな文字列（uuid4）を追加 |
| v1.148.0（4月15日） | バケットの所有者確認機能を追加（完全修正） |

## 過去記事との関連

以前、**144個のnpmパッケージがハッキングされた事件**（Mastraの事件）を解説しましたが、今回の事件はそれと共通する「**ソフトウェアのサプライチェーン攻撃**」の文脈で理解できます。

開発者が使うツールやSDK（開発キット）を狙い、その中に悪意あるコードを仕込む or 成果物をすり替えることで、最終的な製品を汚染するという手口です。

また、記事中でも触れられていますが、今年2月にも **CVE-2026-2473** という別の「バケット横取り」脆弱性がVertex AIで修正されており、**同じサービスで同じ種類の欠陥が繰り返し発見されている**点は非常に重要なシグナルです。「設計思想そのものに問題があった」可能性を示しています。

## 用語解説

| 用語 | 意味 |
|---|---|
| **SDK（Software Development Kit）** | ソフトウェアを開発するための道具セット。今回はPython用のGoogle AI開発ツール |
| **バケット（Bucket）** | Google Cloudのファイル保管場所。名前は世界中で唯一のものでなければならない |
| **バケット・スクワッティング（Bucket Squatting）** | 他人が使いそうなバケット名を先取りして登録する行為。ドメイン名の「サイバースクワッティング」のクラウド版 |
| **Pickle / joblib** | PythonでAIモデルを保存する形式。読み込み時にコードが実行されるリスクがある |
| **OAuthトークン** | Googleサービスへのアクセスを許可する「一時的な通行証」 |
| **Cloud Functions** | クラウド上で特定のイベントをきっかけに自動実行されるプログラム |
| **テナント** | クラウドサービスを使う一組織・一グループのこと |
| **CVE** | セキュリティ脆弱性に付与される公式番号（Common Vulnerabilities and Exposures） |
| **Bug Bounty（バグバウンティ）** | 脆弱性を発見・報告した人に報奨金を払う制度 |
| **サプライチェーン攻撃** | ソフトウェアの製造・配布過程を狙い、製品に悪意あるコードを混入させる攻撃 |

---

> 💡 **まとめ**：「便利な自動設定」を信頼しすぎると、攻撃者に予測されて悪用されることがあります。クラウドサービスでは「明示的に設定する」習慣が、セキュリティの基本中の基本です。
