# Google Vertex AI SDKの欠陥：「バケット乗っ取り」でAIモデルを改ざんできる攻撃が発覚

**元記事**: [Google Vertex AI SDK Flaw Let Attackers Hijack Model Uploads via Bucket Squatting](https://inl03.netline.com/ltr6/?_m=3n.009a.4006.sp0ao46r89.3268)
**解説日**: 2026年6月19日

---

## 背景知識

このニュースを理解するために、まず4つの概念を押さえておきましょう。

### 🤖 Vertex AI（バーテックスAI）とは？
GoogleのクラウドサービスGoogle Cloud上で、**機械学習（AI）モデルを作って動かせるプラットフォーム**です。企業や開発者がAIを本番環境で使うために利用します。「SDK（Software Development Kit）」とは、このサービスを使うためのプログラム用ツールキットのことです。今回はPythonというプログラミング言語向けのSDKに問題がありました。

### 🪣 Cloud Storage バケットとは？
ファイルをインターネット上に保存できる**クラウドの「箱」**です。USBメモリのクラウド版だと思ってください。Googleの場合、この「箱」に名前をつけて使います。重要なポイントは、**世界中で同じ名前のバケットは1つしか作れない（名前がグローバルで一意）**ということです。

### 🎣 バケット・スクワッティングとは？
「スクワッティング」とは、本来の持ち主より先に名前を取ってしまう行為です。バケット・スクワッティングとは、**相手が使うはずのバケット名を先に自分で登録してしまう**攻撃手法です。ドメイン名の「サイバースクワッティング」と同じ発想です。

### 🥒 Pickle（ピクル）とは？
Pythonのデータ保存形式の一つで、AIモデルの保存によく使われます。便利な反面、**Pickleファイルを読み込むだけでコード（プログラム）が実行されてしまう**という危険な特性があります。悪意あるPickleファイルを読み込ませれば、攻撃者のコードが動いてしまいます。

---

## 何が起きたのか

セキュリティ研究チーム「Palo Alto Networks Unit 42」が、Google Vertex AIのPython SDKに**深刻な脆弱性（セキュリティの穴）**を発見しました。

この脆弱性を使うと、攻撃者は**被害者のAIモデルに悪意あるコードを仕込み、Google社内のサーバー上で実行させる**ことができます。

しかも恐ろしいのは、攻撃に必要なものが非常に少ないことです：

| 必要なもの | 詳細 |
|---|---|
| ✅ 自分のGoogle Cloudアカウント | 無料〜格安で取得可能 |
| ✅ 被害者のプロジェクトID | 多くの場合、公開されている |
| ❌ 被害者のパスワード | 不要！ |
| ❌ フィッシング詐欺 | 不要！ |
| ❌ 被害者システムへの侵入 | 不要！ |

この攻撃は**「Pickle in the Middle（ピクル・イン・ザ・ミドル）」**と名付けられました。実際に悪用された形跡はなく、Googleはすでに修正済みです。

## 技術的な詳細

攻撃の流れを、**宅配便の荷物の「すり替え」**に例えて説明します。

### 攻撃のステップ

```
【通常のモデルアップロードの流れ】

開発者                     SDK                      Vertex AI
  |                         |                           |
  |--- モデルをアップロード -->|                           |
  |                         |-- 一時保存バケットに保存 -->|
  |                         |                           |
  |                         |           <-- ファイル読み込み--|
  |                         |                           |
  |                   ✅ 正常なAIモデルが動く             |
```

```
【攻撃者がいる場合】

開発者                     SDK                   攻撃者バケット        Vertex AI
  |                         |                         |                  |
  |--- モデルをアップロード -->|                         |                  |
  |                     [バケット名を予測]               |                  |
  |                         |--- ファイルを保存 -------->|                  |
  |                         |                  [2.5秒以内に悪意あるファイルにすり替え]
  |                         |                         |                  |
  |                         |                         |<-- ファイル読み込み--|
  |                         |                         |                  |
  |                                          ⚠️ 攻撃者のコードが実行される！
```

### なぜバケット名が予測できたのか？

SDKがバケット名を自動生成するとき、このようなルールを使っていました：

```
バケット名 = "プロジェクトID" + "-vertex-staging-" + "リージョン名"
例: mycompany-project-vertex-staging-us-central1
```

プロジェクトIDは公開情報であることが多く、リージョン（地域）も限られています。つまり、**名前が完全に予測可能**でした。

さらに問題だったのは、SDKがバケットの「存在確認」はするものの、**「自分のものかどうかの確認」をしていなかった**ことです。

> 🏠 例え話：宅配ロッカーに荷物を入れるとき、「A-123号室のロッカーが存在するか」は確認するが、「そのロッカーが自分のものか」は確認しない……という状態です。

### 攻撃成功後に何ができたか？

攻撃者がサーバー内で実行できたコードは、以下の情報を盗み出すことに成功しました：

- 🔑 **OAuthトークン**（他のサービスにアクセスできる認証キー）
- 🤖 **他のAIモデルの学習済みデータ**
- 📊 **BigQueryのメタデータ**（データベース情報）
- 📋 **アクセスリストや内部ログ**
- 🖥️ **内部コンテナ情報**

## なぜ重要なのか

### 🎯 影響を受ける可能性がある人
- Vertex AI SDK for Python（バージョン1.147.0以前）を使っている開発者・企業
- 特に、新しいリージョンでVertex AIを使い始めた人
- `staging_bucket`パラメータを設定していない人

### 💥 起きうる被害

| 被害の種類 | 内容 |
|---|---|
| **AIモデルの汚染** | 悪意あるモデルに差し替えられる（AIポイズニング） |
| **情報漏洩** | 学習データや内部情報が盗まれる |
| **コード実行** | Google社内インフラで攻撃者のコードが動く |
| **他サービスへの侵入** | 盗んだトークンで別のシステムへ連鎖攻撃 |

### ⏱️ タイミングの問題
攻撃のタイムリミットはわずか**約2.5秒**。しかし攻撃者はCloud Function（クラウド上の自動処理）を使うことで**1.4秒でファイルを差し替え**ることに成功しています。人間が手動でやるのは不可能でも、プログラムなら十分に可能です。

## 対策・今後の展望

### ✅ 今すぐやるべきこと

**1. SDKをアップデートする（最優先！）**
```bash
pip install --upgrade google-cloud-aiplatform>=1.148.0
```
バージョン1.148.0以降では、バケットの「所有者確認」が追加されています。

**2. 自分でバケットを指定する**
```python
# ❌ 危険な使い方（バケットを指定しない）
model.upload()

# ✅ 安全な使い方（自分のバケットを明示的に指定）
model.upload(staging_bucket="gs://自分が管理するバケット名")
```

**3. SDKが使われているすべての場所を確認する**
本番サーバーだけでなく、以下も確認を：
- Jupyter Notebook
- CI/CDパイプライン（自動テスト・デプロイ環境）
- 学習用スクリプト

### 🔧 Googleの対応
| 日付 | 対応内容 |
|---|---|
| 2026年3月5日 | Unit 42がGoogleに報告 |
| 2026年3月31日 | v1.144.0でバケット名にランダム文字列を追加 |
| 2026年4月15日 | v1.148.0でバケット所有者の確認機能を追加（完全修正） |

## 過去記事との関連

以前、**144個のnpmパッケージが乗っ取られたアカウントによって汚染された事件**や、**Joomlaの脆弱性**を解説しましたが、今回の事件にも共通するテーマがあります。それは「**信頼していたものが実は改ざんされていた**」というサプライチェーン攻撃の発想です。

また、記事でも触れられているとおり、これはVertex AIにおける**バケット・スクワッティング系の脆弱性の2件目**です。1件目は2026年2月にCVE-2026-2473として修正された「Vertex AI Experiments」の同種の問題でした。同じプラットフォームで似たような穴が繰り返し見つかっているという点は、開発者・利用者ともに注意が必要です。

## 用語解説

| 用語 | 意味 |
|---|---|
| **Vertex AI** | GoogleのAI開発・運用プラットフォーム |
| **SDK** | ソフトウェア開発キット。特定のサービスを使うためのプログラムツール群 |
| **Cloud Storage バケット** | クラウド上のファイル保存用「箱」。世界で名前が一意 |
| **バケット・スクワッティング** | 相手が使う予定のバケット名を先に取る攻撃 |
| **Pickle / joblib** | Pythonでデータ・AIモデルを保存する形式。読み込み時にコードが実行される危険性あり |
| **OAuthトークン** | 各種サービスへのアクセス権を証明する「一時的な鍵」 |
| **Cloud Function** | イベントをきっかけに自動で動くクラウド上のプログラム |
| **CVE** | 脆弱性に割り振られる識別番号（Common Vulnerabilities and Exposures） |
| **Unit 42** | Palo Alto Networksのセキュリティ研究チーム |
| **バグバウンティプログラム** | 脆弱性を発見・報告した人に報奨金を払う制度 |
| **CI/CDパイプライン** | ソフトウェアの自動テスト・自動デプロイの仕組み |
| **テナント** | クラウド上で同じインフラを使う別々の利用者・組織 |
