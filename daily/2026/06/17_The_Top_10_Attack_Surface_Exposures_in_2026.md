## 背景知識

まず、この記事を理解するためのポイントをおさえましょう！

### 🏠「攻撃対象領域（アタックサーフェス）」って何？

企業のシステムを「家」にたとえると、インターネットはその家の「外の世界」です。
家には「玄関」「窓」「裏口」など、出入り口がいくつもありますよね。
セキュリティの世界では、**外から侵入できる可能性のある入口・隙間の総数**のことを「攻撃対象領域（アタックサーフェス）」と呼びます。

出入り口が多ければ多いほど、どこかから不正侵入されるリスクが上がります。

### 🔐「インターネットに公開されている」と何が問題なの？

企業のサーバーやデータベースには、「外からアクセスできるもの」と「社内だけで使うもの」があります。
社内専用のシステムが**うっかりインターネット上に公開された状態**になっていると、世界中の攻撃者から丸見えになってしまいます。
まるで、金庫室のドアを道路に面した場所に設置してしまうようなものです。

## 何が起きたのか

セキュリティ企業「Intruder」が、**3,000社の企業システムの「公開されている入口」を調査**した結果をまとめたレポートが発表されました。

その結果は、かなり深刻なものでした👇

| 調査結果 | 割合 |
|---|---|
| 管理画面（HTTPパネル）が外部公開されていた企業 | **60%** |
| 危険なポート・サービスが公開されていた企業 | **49%** |
| データベースが直接インターネットから見えた企業 | **42%** |
| 公開されてはいけないファイルや情報が見えた企業 | **30%** |

つまり、**調査対象の半数以上の企業が、本来外に出すべきでない「入口」を開けっぱなし**にしていたということです！

## 技術的な詳細

### 🏆 危険な公開状態トップ10

調査で判明した「よくある危険な公開状態」ランキングです。

| 順位 | 公開されていたもの | 割合 |
|---|---|---|

| 2位 | Postgresデータベース | 16% |
| 3位 | APIドキュメント | 15% |
| 4位 | WordPressの管理画面 | 15% |
| 5位 | リモートデスクトップ（RDP） | 11% |
| 6位 | SNMPサービス | 9% |
| 7位 | phpMyAdmin管理画面 | 8% |
| 8位 | UPnPサービス | 8% |
| 9位 | NTPサービス | 7% |
| 10位 | RPCポートマッパー | 7% |

### 🗄️ 1位・2位：データベースの露出（MySQL・Postgres）

データベースとは、**会員情報・パスワード・注文履歴などの大切なデータを管理する「倉庫」**のことです。
この倉庫がインターネットから直接見える状態になっていると、攻撃者が「パスワードを総当たりで試す攻撃（ブルートフォース）」をかけてきます。

2020年に起きた「PLEASE_READ_ME」というランサムウェア攻撃では、**25万以上のMySQLデータベース**がこの方法で被害を受けました😱

### 🔑 5位：リモートデスクトップ（RDP）の露出

RDPとは、**遠隔地から会社のパソコンをまるごと操作できる機能**です（テレワークでも使われます）。
これが外部に公開されていると、攻撃者がID・パスワードを推測しながら不正ログインを試みます。
2019年の「BlueKeep」脆弱性では、**100万台近いシステム**が危険にさらされました。

### 📡 6位以降：「社内専用」のはずのサービスたち

SNMP・UPnP・NTP・RPCは、もともと**社内ネットワーク専用**に設計された古い通信サービスです。
家のリモコン（テレビの裏側の赤外線センサー）が外に向いているようなもので、外部に公開されることは想定されていませんでした。
しかし、設定ミスで外部から見えてしまっているケースが後を絶ちません。

## なぜ重要なのか

### ⏱️ 攻撃までの時間が「1日」に短縮された

記事では「**time-to-exploit（脆弱性が発見されてから悪用されるまでの時間）が1日にまで縮まった**」と書かれています。

昔は新しいセキュリティの穴が見つかっても、攻撃者が実際に使えるツールを作るのに数週間かかっていました。
今は、AIやツールの発展により**翌日には悪用が始まる**ことも珍しくありません。

「気づいてから対処する」では間に合わない時代になっているのです。

### 🔓「MongoBleed」という最新の脆弱性も紹介

記事では今年発見された「MongoBleed」という脆弱性も紹介されています。
これは、**パスワードなしでサーバーのメモリ（一時記憶領域）から認証情報やセッショントークンを盗み取れる**という非常に深刻な欠陥です。
インターネットに公開されているサービスは、このような脆弱性が出た瞬間に**全企業が即座に危険**にさらされます。

## 対策・今後の展望

### ✅ まず「なぜ公開されているのか」を問い直す

記事が強調しているのは、単に「パッチ（修正プログラム）を当てる」だけでなく、

> **「そもそも、なぜそのサービスがインターネットに公開されているのか？」**

を問い直すことの大切さです。

公開する必要がないなら、**最初から「見えない」状態にする（アタックサーフェスの削減）**が最善策です。

### 🛡️ 具体的な対策のヒント

- **データベースはVPNや社内ネットワーク経由でのみアクセス可能にする**
- **管理画面はIPアドレス制限をかけ、特定の場所からしかアクセスできなくする**
- **使っていない古いサービスは無効化する**
- **定期的に「自社のシステムが外から何に見えているか」を確認する**

企業のIT担当者は、定期的に「攻撃者の目線で自社を見る」訓練が必要です。

## 用語解説

| 用語 | 意味 |
|---|---|
| **アタックサーフェス（攻撃対象領域）** | 外部の攻撃者が侵入を試みることができる、システムの入口・隙間の総数 |
| **ブルートフォース攻撃** | パスワードを機械的に何度も試して当てようとする「総当たり攻撃」 |
| **RDP（リモートデスクトップ）** | 遠隔地からパソコンを操作する機能。テレワークでも使われる |
| **データベース（MySQL・Postgres）** | データを整理・保管するシステム。会員情報や注文履歴などが入っている |
| **ランサムウェア** | データを暗号化して「身代金を払わないと返さない」と脅迫するウイルス |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやシステムの「セキュリティ上の欠陥・バグ」 |
| **パッチ** | 脆弱性を修正するための「修正プログラム」 |
| **SNMP・UPnP・NTP・RPC** | 社内ネットワーク向けに作られた通信サービス。外部公開は想定外 |
| **APIドキュメント** | システム間の連携方法を説明した設計書。内部仕様が書かれていることも多い |
| **セッショントークン** | ログイン状態を維持するための「合言葉」のようなデータ |
| **アタックサーフェス削減** | 不要な公開サービスを閉じ、攻撃者が狙える入口を少なくすること |
