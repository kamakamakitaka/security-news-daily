# 2026年、組織が「うっかり外部にさらしている」危険な設定トップ10

**元記事**: [The Top 10 Attack Surface Exposures in 2026](https://inl03.netline.com/ltr6/?_m=3n.009a.4006.sp0ao46r89.3258)
**解説日**: 2025年6月

---

## 背景知識

このニュースを理解するために、まず「攻撃者がどうやって組織に侵入するか」のイメージを持ちましょう。

### 🏠 例え話：組織のシステムは「建物」に例えられる

- **インターネット** ＝ 建物の外の道路・公道
- **社内システム** ＝ 建物の内部（本来は関係者しか入れない）
- **ファイアウォール（防火壁）** ＝ 建物の壁や玄関のドア
- **攻撃面（アタックサーフェス）** ＝ 外から見える・触れる窓やドアの数

「攻撃面が広い」ということは、「建物の窓が多すぎて、どこかの鍵をかけ忘れている可能性が高い」状態です。

### 🔑 なぜ設定ミスが危険なのか？

セキュリティの侵害（ブリーチ）は、映画のような「天才ハッカーが暗号を解読する」シーンばかりではありません。むしろ多くの場合：

1. **管理画面が誰でもアクセスできる状態になっていた**
2. **昔のパスワードが使い回されていた**
3. **「内部用」のサービスが誤ってインターネットに公開されていた**

…という、もっと地味な「うっかりミス」から始まります。

---

## 何が起きたのか

セキュリティ企業「Intruder（イントルーダー）」が、**3,000組織の「攻撃面」を分析**し、「本来インターネットに公開すべきでないのに、うっかり公開されているサービス」をまとめたレポートを発表しました。

### 📊 全体像の衝撃的な数字

| 問題の種類 | 該当する組織の割合 |
|---|---|
| 管理画面（HTTP パネル）が外部に公開 | **60%（約6割！）** |
| 危険なポート・サービスが公開 | **49%（約半数）** |
| データベースが直接インターネットから到達可能 | **42%（約4割）** |
| 公開すべきでないファイル・情報が公開 | **30%（約3割）** |

つまり、**調査した組織の過半数が、何らかの「うっかり公開」をしている**という驚くべき結果です。

## 技術的な詳細

ワースト10の中から、特に重要なものを詳しく解説します。

### 💾 1〜2位：データベースの直接公開（MySQL・Postgres）

**データベース**とは、組織の大切なデータ（顧客情報・注文履歴・パスワードなど）を保管している「金庫室」のような存在です。

本来、この金庫室は：
```
インターネット → Webサーバー（受付） → アプリケーション → データベース（金庫室）
```
という順番で、**間にいくつかの「壁」を挟んで守られているべき**です。

ところが実態は：
```
インターネット → データベース（金庫室）← 直接攻撃可能！
```
という状態になってしまっている組織が26%も存在します。

> 💡 **過去の実例**：2020年に起きた「PLEASE_READ_ME」というランサムウェア（身代金要求型ウイルス）攻撃では、こうして公開されたMySQLデータベース**25万件以上**が侵害されました。攻撃者は弱いパスワードを機械的に試し続ける「ブルートフォース攻撃（総当たり攻撃）」で侵入しています。

---

### 📄 3位：APIドキュメントの公開

**API（Application Programming Interface）** とは、「システム同士が会話するための窓口」です。例えば、天気アプリが気象情報サービスからデータを取得する仕組みがAPIです。

**APIドキュメント**とは、「このAPIにはこういう命令を送ると、こういう情報が返ってくる」という仕様書のことです。

公開用APIのドキュメントなら問題ありませんが、**「管理者専用API」や「内部システム用API」のドキュメントが誰でも見られる状態**になっていると…

- 「こうすれば管理者権限を取れる」
- 「この命令を送れば非公開データにアクセスできる」

…という情報を攻撃者に教えてしまうことになります。

> 💡 まるで「この建物の合鍵はここに置いてあります」と看板を立てているようなものです。

---

### 🖥️ 5位：リモートデスクトップ（RDP）の公開

**RDP（Remote Desktop Protocol）** とは、会社のパソコンを遠隔から操作する仕組みです。在宅勤務などで「会社のPCを家から操作する」ときに使われます。

これが公開されていると、攻撃者が**パスワードを次々と試す「ブルートフォース攻撃」**でログインを試みます。成功すれば、会社のパソコンを外から乗っ取られます。

> 💡 **過去の実例**：2019年に発見された「BlueKeep」という脆弱性では、**約100万台のシステム**が即座に攻撃可能な状態になりました。ランサムウェア攻撃の入口として、今でも最もよく使われる手口のひとつです。

---

### 📡 6〜10位：「内部専用」なのに外部公開されているサービス

| サービス | 本来の用途 |
|---|---|
| **SNMP** | ネットワーク機器（ルーターなど）の状態を監視する内部用プロトコル |
| **UPnP** | 家庭内ネットワークの機器が自動設定し合う仕組み |
| **NTP** | 機器の時刻を同期させる仕組み |
| **RPC** | プログラム同士が内部で通信する仕組み |

これらはすべて「**社内ネットワークの中だけで使う**」ことを前提に設計されたものです。インターネット側からアクセスできる状態は、**設計者が全く想定していない異常事態**です。

---

### ⚡ 「脆弱性公開から1日で攻撃開始」の怖さ

記事中に「time-to-exploit（悪用までの時間）が1日になった」とあります。

かつては：
1. 脆弱性が発見される
2. セキュリティ研究者が分析・公表
3. 企業がパッチ（修正プログラム）を作成
4. 管理者がパッチを適用

この一連の流れに**数週間〜数ヶ月**の余裕がありました。

今は攻撃者の技術力と自動化が進み、**公表の翌日には攻撃ツールが出回る**ことも珍しくありません。だからこそ「そもそも公開しなければ攻撃されない」という考え方が重要なのです。

---

## なぜ重要なのか

### 🎯 「パッチ当て」だけでは足りない

多くの組織は「脆弱性が見つかったら修正プログラムを当てる（パッチ適用）」という対策を重視しています。もちろんそれも大切ですが…

> 「なぜ最初からそのサービスがインターネットに公開されていたのか？」

という問いに答えなければ、根本的な解決にはなりません。

修正プログラムを当てても、「公開すべきでないサービスが公開されている」状態が続く限り、次の脆弱性が見つかったときにまた同じ危険にさらされます。

### 📈 規模を問わず影響がある

このレポートでは、大企業・中小企業・業界を問わずこの問題が広く見られると指摘しています。「うちは小さい会社だから狙われない」は通用しません。攻撃者は**自動ツールでインターネット全体をスキャン**しており、規模に関係なく脆弱な設定を見つけ出します。

## 対策・今後の展望

### ✅ 今すぐできる・考えるべきこと

**1. 「そもそも公開が必要か？」を問い直す（攻撃面の縮小）**
- データベースは絶対にインターネットに直接公開しない
- 管理画面はVPN（仮想プライベートネットワーク）経由でのみアクセス可能にする
- 使っていないサービスはオフにする

> 💡 「鍵をかける」だけでなく「窓そのものを塞ぐ」発想です

**2. 攻撃面管理（Attack Surface Management）の実践**
- 定期的に「自組織のどのサービスが外部から見えているか」を確認する
- Intruderのようなツールを使って、外部から見たときの自分の状態をチェックする

**3. パスワード管理の強化**
- RDPやデータベースに強力なパスワードを設定する
- 複数サービスでの使い回しをやめる
- 多要素認証（MFA）を導入する

**4. パッチ適用は引き続き迅速に**
- 攻撃までの時間が1日に縮まった今、パッチ情報が出たらすぐに対応するプロセスを整える

## 過去記事との関連

以前、「**敵対的露出検証（Adversarial Exposure Validation）**がセキュリティの見える化を確かな優先順位付けに変える」という記事を解説しました。

あの記事では「自分たちの弱点がどこにあるかを**攻撃者の目線で検証し**、何から先に直すべきかを判断する」考え方を紹介しました。

今回の記事は、まさにその「見える化」の実態データです。

```
前回の記事：「攻撃者目線で弱点を検証・優先順位をつけよう」
     ↓
今回の記事：「実際に3,000組織を調べたら、こんな弱点が多かった」
```

「敵対的露出検証」の考え方と、今回のワースト10は深く結びついています。**どれだけ高度な検証をしても、そもそも公開すべきでないサービスを閉じていなければ意味がない**——今回の記事はその現実を数字で突きつけています。

## 用語解説

| 用語 | 意味 |
|---|---|
| **攻撃面（アタックサーフェス）** | 攻撃者がアクセス・攻撃できる可能性のある「入口」の総数・範囲 |
| **脆弱性（ぜいじゃくせい）** | システムのセキュリティ上の欠陥・弱点 |
| **ゼロデイ脆弱性** | まだ修正プログラムが存在しない、発見されたばかりの脆弱性 |
| **ブルートフォース攻撃** | パスワードを機械的に大量に試し続ける「総当たり攻撃」 |
| **ランサムウェア** | ファイルを暗号化して使えなくし、元に戻す代わりに身代金を要求するウイルス |
| **パッチ** | ソフトウェアの脆弱性を修正するための更新プログラム |
| **RDP** | Remote Desktop Protocol。PCを遠隔から操作する仕組み |
| **MySQL / Postgres** | よく使われるデータベースソフトウェアの名前 |
| **API** | システム同士がデータをやり取りするための「窓口」 |
| **SNMP / UPnP / NTP / RPC** | いずれも「社内ネットワーク専用」に設計された古くからのサービス・プロトコル |
| **VPN** | Virtual Private Network。インターネット上に「社内専用の安全な通路」を作る技術 |
| **多要素認証（MFA）** | パスワードに加えて、スマホへの確認コードなど複数の方法で本人確認する仕組み |
| **攻撃面縮小（Attack Surface Reduction）** | 不要なサービスを閉じるなどして、攻撃者が入れる「入口」を減らすこと |

---

> 📌 **まとめ**
> 
> 「サイバー攻撃は高度な技術でしか防げない」というイメージがありますが、現実には**「公開すべきでないものを公開してしまっている」という基本的なミスが6割の組織に存在**します。まずは「窓を塞ぐ」——余計な入口を作らないことが、最も確実な防御の第一歩です。
