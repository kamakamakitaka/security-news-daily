# Active Directoryの脆弱性はパッチを当てるだけでは解決しない理由

**元記事**: [Why Active Directory Vulnerabilities Demand More Than a Patch](https://inl03.netline.com/ltr6/?_m=3n.009a.4006.sp0ao46r89.325w)
**解説日**: 2025年7月11日

---

## 背景知識

まず、このニュースを理解するための基礎知識を整理しましょう。

### 🏢 Active Directory（アクティブ ディレクトリ）とは？

会社や学校のコンピューターネットワークを想像してください。社員や生徒が何百人もいると、「誰がどのパソコンにログインできるか」「誰がどのファイルを見られるか」を一人ひとり管理するのは大変ですよね。

そこで登場するのが **Active Directory（AD）** です。Microsoftが作った「社内ネットワークの管理者」のようなシステムで、以下をまとめて管理します：

- 👤 **誰がログインできるか**（認証）
- 🔑 **何にアクセスできるか**（権限管理）
- 🖥️ **どのパソコン・サーバーが存在するか**（機器管理）

ほとんどの企業がこのシステムを使っているため、**ここが攻撃されると会社全体が危険にさらされます**。

### 🎫 Kerberosとは？

Kerberosは、ネットワーク内でパスワードを毎回送らずに「本人確認」をするための仕組みです。

> **わかりやすい例え：**
> 遊園地の「フリーパス」に似ています。入口で一度本人確認をすると「フリーパスチケット（Kerberosチケット）」がもらえて、その後は各アトラクションでチケットを見せるだけで入れます。いちいち入口に戻る必要はありません。

### 🔖 SPNとは？

**SPN（Service Principal Name）**は、ネットワーク上のサービス（メールサーバー、ファイルサーバーなど）に付けられた「住所＋名前」のようなものです。Kerberosはこれを使って「どのサービスにアクセスするか」を特定します。

### 📊 CVSSスコアとは？

脆弱性（セキュリティの穴）の危険度を0〜10点で表したスコアです。

| スコア | 危険度 |
|--------|--------|
| 0〜3.9 | 低い |
| 4.0〜6.9 | 中程度 |
| 7.0〜8.9 | **高い** |
| 9.0〜10 | 致命的 |

今回の脆弱性は **8.8点（HIGH）** で、かなり危険なレベルです。

## 何が起きたのか

**CVE-2026-25177**（CVEは脆弱性の管理番号）という、Microsoftの**Active Directory**に関する重大なセキュリティの穴が発見・公表されました。

### 事件の概要

```
🚨 発見された問題
├── 対象：Microsoft Active Directory Domain Services
├── 危険度：HIGH（CVSSスコア 8.8）
├── 内容：権限を不正に昇格できる（低い権限から高い権限へ）
└── 特徴：特別な操作や高い権限がなくても悪用できる
```

**「権限昇格（Privilege Escalation）」** というのは、たとえるなら「アルバイトの社員証しか持っていないのに、社長室に入れるようになってしまう」ような状態です。

## 技術的な詳細

### 攻撃の仕組みをわかりやすく解説

```
通常の流れ：
社員(ユーザー) → 「メールサーバーに接続したい」
              → ADに問い合わせ
              → 正しいKerberosチケットを発行
              → メールサーバーに接続 ✅

攻撃者の悪用：
攻撃者 → 一般社員アカウントを乗っ取る
       → SPNを改ざん（偽の住所を登録）
       → 他の社員が「メールサーバーに接続したい」と要求
       → ADが間違ったチケットを発行してしまう
       → サービスが止まる、または弱い認証方式に切り替わる 💥
```

### ステップ・バイ・ステップで見てみると

**Step 1** 🔓 攻撃者が一般ユーザーのアカウントを乗っ取る  
↓  
**Step 2** 📝 そのアカウントが持つ「SPNを書き換える権限」を使う  
↓  
**Step 3** 🎭 本物のサービスと同じSPN（住所）を偽のものとして登録する  
↓  
**Step 4** 🎫 他のユーザーがそのサービスにアクセスしようとすると、ADが誤ったチケットを発行  
↓  
**Step 5** 💥 2つの結果のどちらかが起こる：
- サービスが使えなくなる（**DoS攻撃**：サービス妨害）
- より弱い認証方式「NTLM」に切り替わり、さらなる攻撃が可能になる

### NTLMって何が問題？

NTLMは古い認証方式で、Kerberosより安全性が低く、**パスワードのハッシュ値（暗号化されたパスワード）を盗んで悪用する「Pass-the-Hash攻撃」**などに弱いです。

> **例え話：** Kerberosが「ICカード認証」なら、NTLMは「古いシンプルな暗証番号認証」のようなイメージです。

## なぜ重要なのか

### 🌊 被害の「爆風範囲（Blast Radius）」が広すぎる

記事では「blast radius（爆風範囲）」という言葉が使われています。爆発で言うと「どこまで被害が広がるか」ということ。今回の脆弱性が特に危険な理由がここにあります。

```
一つのアカウントが乗っ取られると...

一般社員のPC
    ↓ 権限昇格
部署の共有フォルダ
    ↓ 横移動（Lateral Movement）
他部署のサーバー
    ↓ さらに権限昇格
ドメインコントローラー（AD本体）
    ↓ 完全制御
会社全体のすべてのシステム 💀
```

### 📊 影響を受ける規模

Active Directoryは**世界中の企業の約90%**が使っていると言われています。つまり、この脆弱性は非常に多くの組織に影響します。

### ⚠️ パッチを当てても問題が残る理由

記事の核心はここです。「パッチ（修正プログラム）を当てるだけでは不十分」と言っています。

なぜかというと：

| 問題 | 内容 |
|------|------|
| **過剰な権限** | 必要以上の権限を持つアカウントが多数存在する |
| **管理されていないサービスアカウント** | 使われているかどうか不明なアカウントが放置されている |
| **設定の不統一** | ある部署では厳しく設定、別の部署ではゆるゆる設定 |

> **例え話：** 家の鍵のコピーを必要以上に多くの人に渡してしまっている状態です。鍵の種類を変えても（パッチ）、古い合鍵を回収しなければ（権限の整理）、危険は続きます。

## 対策・今後の展望

### 🔧 今すぐできること（優先度：高）

#### 1. パッチを当てる（必須！）
Microsoftが提供する修正プログラムをすぐに全てのドメインコントローラーに適用する。これは絶対にやらなければならない最低限の対処です。

#### 2. 最小権限の原則を徹底する

> **「最小権限の原則（Least Privilege）」** とは：
> それぞれのアカウントに、仕事に必要な最小限の権限だけを与えること。

```
❌ 悪い例：全社員に管理者権限を与える
✅ 良い例：一般社員は必要なフォルダだけアクセス可能
```

#### 3. SPNの書き換え権限を持つアカウントを特定・制限する

誰がSPNを変更できるかを確認し、不要な権限を削除する。

### 🔍 中長期的な対策

#### 4. 統一した可視性の確保

```
オンプレミスAD（社内サーバー）
    +
Entra ID（旧Azure AD：クラウド）
    +
Microsoft 365
    ↓
全体を一元管理・監視する
```

バラバラに管理するのではなく、全体を一つの目で見渡せる体制を作ることが重要です。

#### 5. 定期的な権限の棚卸し

- 使われていないアカウントの削除
- 過剰な権限の見直し
- サービスアカウントの管理

### 🏁 まとめると

```
短期：パッチを当てる ← 今すぐ！
中期：権限の整理・最小権限の徹底
長期：AD全体のガバナンス（管理体制）の見直し
```

## 過去記事との関連

今回の記事は特定の「事件」ではなく、新しい脆弱性の発見をきっかけに**Active Directoryのセキュリティ全般の問題**を解説するものです。

過去にも以下のような関連する問題が話題になっています：
- **Pass-the-Hash攻撃**（NTLMの弱点を突く攻撃）
- **Kerberoasting**（SPNを使ったKerberosチケットへの攻撃）
- **DCSync攻撃**（Active Directoryを丸ごと盗む攻撃）

これらはすべて「Active Directoryの権限管理が甘い」という同じ根っこの問題から派生しています。今回の脆弱性も、その流れの一つと言えます。

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **Active Directory (AD)** | アクティブ ディレクトリ | Microsoftの社内ネットワーク管理システム |
| **CVE** | シーブイイー | 脆弱性の管理番号（Common Vulnerabilities and Exposures） |
| **CVSS** | シーブイエスエス | 脆弱性の危険度スコア（0〜10点） |
| **権限昇格** | けんげんしょうかく | 低い権限から高い権限を不正に取得すること |
| **横移動 (Lateral Movement)** | よこいどう | 一つのPCから別のPCへと侵入を広げること |
| **Kerberos** | ケルベロス | ネットワーク内の安全な認証システム |
| **NTLM** | エヌティーエルエム | 古い認証方式。Kerberosより安全性が低い |
| **SPN** | エスピーエヌ | ネットワークサービスの「名前と住所」 |
| **ドメインコントローラー** | - | Active Directoryの中心サーバー。これが乗っ取られると全滅 |
| **最小権限の原則** | さいしょうけんげん | 必要最低限の権限だけ与えるセキュリティの基本原則 |
| **パッチ** | - | ソフトウェアの修正プログラム。セキュリティホールを塞ぐもの |
| **DoS攻撃** | ディーオーエス | サービスを使えなくする攻撃（Denial of Service） |
| **ドメイン** | - | Active Directoryで管理されるネットワークの単位 |
| **Blast Radius** | ブラストレイディウス | 攻撃が成功した場合の被害範囲 |
