# Beats Studio Budsの盗聴脆弱性とiPhoneチップの修正不可能な欠陥をAppleが公表

**元記事**: [Apple Patches Beats Studio Buds Flaw Letting Nearby Attackers Spy via Microphone](https://inl03.netline.com/ltr6/?_m=3n.009a.4008.sp0ao46r89.328i)
**解説日**: 2026年6月20日

---

## 背景知識

このニュースを理解するために、いくつかの基本的な仕組みを押さえておきましょう。

### Bluetoothとペアリングってなに？

**Bluetooth（ブルートゥース）** は、スマートフォンとイヤホンなどを無線でつなぐ通信技術です。半径10〜100メートル程度の近距離で使います。  
**ペアリング** とは、「このイヤホンをこのスマホに接続してOK」という「握手」の手続きのことで、普通は本人の許可（ボタン操作など）が必要です。

### BootROM（ブートロム）ってなに？

スマートフォンが起動するとき、最初に実行される超基礎的なプログラムが入った**読み取り専用のメモリ**です。「設計図の原本」みたいなもので、一度製造したら書き換えができません。だから、ここに欠陥があると修正パッチを当てることができません。

### CVSSスコアってなに？

**CVSS（Common Vulnerability Scoring System）** は、セキュリティの弱点（脆弱性）の深刻さを0〜10点で表すスコアです。今回の8.8点は「高深刻度」にあたります。

---

## 何が起きたのか

今回の記事では、**2つの独立したセキュリティ問題**が報告されています。

### 問題①：Beats Studio Budsで盗聴できる脆弱性

Appleのワイヤレスイヤホン「**Beats Studio Buds**」に、近くにいる攻撃者がマイクを通じてユーザーの音声を盗み聞きできる脆弱性が発見されました。

- 脆弱性ID：**CVE-2025-20701**（深刻度スコア：8.8／10）
- 原因：Bluetooth接続を管理するチップ（Airoha社製）のソフトウェアに「承認チェックの不備」があった
- **ユーザーの許可なし**にペアリング（接続）できてしまう
- **修正済み**：Beats Firmwareアップデート 1B211 で対応

### 問題②：iPhoneのチップに修正不可能な欠陥

iPhone XSなどに使われる**Apple A12・A13チップ**に、BootROM（起動プログラム）レベルの脆弱性が発見されました。

- 発見者：ヨーロッパのサイバーセキュリティ企業「Paradigm Shift」
- PoC（実証コード）の名前：**usbliter8**
- **ハードウェアそのものの欠陥**なので、ソフトウェアアップデートで修正できない
- 影響機種：A12チップ搭載機（iPhone XS/XS Max/XRなど）、A13搭載機（iPhone 11シリーズなど）

## 技術的な詳細

### Beats Studio Budsの脆弱性の仕組み

```
通常のBluetooth接続の流れ：
  スマホ → 「つないでいいですか？」 → イヤホン → 「ユーザーが許可しました！OK」

脆弱性がある場合：
  攻撃者 → 「つないでいいですか？」 → イヤホン → 「OK（チェックしていない）」
```

本来は「ユーザーが許可したか」を確認する手順があるはずですが、Airoha社のBluetooth SDKというソフトウェア部品にその確認が抜けていました。

その結果：
- まだペアリングされていないイヤホンのマイクにアクセスできる
- イヤホンのメモリ（RAM・フラッシュ）の読み書きができる
- さらに「スマホとイヤホンの信頼関係」を乗っ取り、スマホへの攻撃にも発展できる

攻撃者に必要な条件は **「Bluetooth電波が届く範囲にいること」だけ**というのが怖いところです。

### A12/A13チップの脆弱性の仕組み

こちらは少し複雑ですが、わかりやすく説明します。

```
USB接続時のデータのやり取りのイメージ：

正常な場合：
  パソコン → 大きなデータパケット → iPhone → バッファ（一時保管場所）に入れる → 処理する

攻撃の場合：
  攻撃者 → わざと小さいデータ → iPhone → バッファが想定より少ししか埋まらない
  → 「バッファ不足（アンダーフロー）」が起きる
  → この隙間に悪意あるコードを差し込める！
```

**バッファアンダーフロー**とは、コップに想定より少ない水しか入っていないのに「満タンだ」と誤解してしまうような状態です。この誤認を利用して、悪意あるプログラムを実行できてしまいます。

A11チップではこの問題が起きない理由：A11は受信のたびに「一時保管場所の位置をリセット」するプログラムが手動で組まれていたから。A12/A13ではその処理が省かれ、代わりの保護機構も不十分でした。

## なぜ重要なのか

### Beats Studio Budsの問題

- 🎧 **日常的な盗聴リスク**：カフェや電車の中で、知らないうちに会話を盗み聞きされる可能性
- 📱 **スマホへの連鎖攻撃**：イヤホンを踏み台にしてスマホへ侵入するシナリオも現実的
- 🏭 **他社製品にも影響**：同じAiroha社のチップを使うJabra製品など他社イヤホンにも同様の問題があり、Jabraはすでに2025年12月に修正済み

### A12/A13チップの問題

- 🔒 **修正不可能**：ハードウェアの欠陥なので、Appleはソフトウェアアップデートでは直せない
- 📱 **影響機種が多い**：iPhone XS〜iPhone 11シリーズなど、まだ使っている人が多い世代
- 💻 **過去の有名事例と同様**：以前発見された「**checkm8（チェックメイト）**」という同種の脆弱性（iPhone 4s〜iPhone X対象）と並ぶレベルの深刻さ
- 🔗 **チェーン・オブ・トラスト（信頼の連鎖）の破壊**：起動時の「正規のソフトだけを動かす」という保護機構が崩れ、不正なOSやスパイウェアをインストールされる可能性

## 対策・今後の展望

### Beats Studio Budsユーザーがやるべきこと

| 対策 | 方法 |
|------|------|
| ✅ ファームウェアを更新する | iOSの「Beats」アプリから自動更新を確認 |
| ✅ 使わないときはケースに入れる | ペアリング待機状態を最小限にする |
| ⚠️ 公共の場での取り扱いに注意 | ペアリング操作は人の多い場所を避ける |

### A12/A13チップのiPhoneユーザーがやるべきこと

残念ながら、**ソフトウェアの修正はできません**。

- 🆙 **最も効果的な対策は新しいiPhoneへの買い替え**（A14以降のチップ搭載機種）
- 🚫 **知らないUSBケーブルやデバイスをつながない**（攻撃にはUSB接続が必要）
- 🔒 **iPhoneを物理的に守る**（攻撃者がデバイスに直接アクセスする必要がある）

> 💡 **ポイント**：今回のA12/A13の脆弱性は、悪用するのに**物理的にiPhoneを手に取る必要がある**ため、遠隔から勝手に攻撃されるリスクは比較的低いです。スマホを他人に渡さない、置きっぱなしにしないことが重要です。

## 用語解説

| 用語 | 説明 |
|------|------|
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやハードウェアのセキュリティ上の欠陥・弱点 |
| **CVE** | 脆弱性に付けられる世界共通の識別番号（例：CVE-2025-20701）|
| **CVSSスコア** | 脆弱性の深刻さを0〜10点で表す指標。8以上は「高深刻度」|
| **Bluetooth SDK** | Bluetoothを使うアプリを作るための部品集（ソフトウェア開発キット）|
| **ペアリング** | 2つのBluetooth機器を「つないでOK」と認識させる接続手続き |
| **BootROM / SecureROM** | スマホ起動時に最初に動く、書き換え不可能なプログラムが入ったメモリ |
| **バッファアンダーフロー** | データの一時保管場所が想定より少ししか埋まらない状態。これを悪用して不正なコードを実行できる |
| **PoC（概念実証コード）** | 「この攻撃が本当に可能だ」と実証するために作られたサンプルコード |
| **チェーン・オブ・トラスト** | 起動時に「正規のソフトだけを動かす」ための連続した認証の仕組み |
| **checkm8** | 過去に発見されたiPhone（A5〜A11チップ）対象のBootROM脆弱性。今回のusbliter8と同種 |
| **Airoha SoC** | Beats等のイヤホンに使われているBluetoothチップのメーカー・製品 |
| **DART（DMA Address Remap Table）** | メモリのアクセス管理を行うハードウェアの仕組み |
