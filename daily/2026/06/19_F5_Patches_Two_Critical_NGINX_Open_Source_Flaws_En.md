# F5がNGINXの重大な脆弱性2件を修正 — 遠隔からコードを実行される恐れ

**元記事**: [F5 Patches Two Critical NGINX Open Source Flaws Enabling Remote Code Execution](https://inl03.netline.com/ltr6/?_m=3n.009a.4008.sp0ao46r89.328o)
**解説日**: 2026年7月

---

## 背景知識

まず、このニュースを理解するための基礎知識をおさえておきましょう。

### 🌐 NGINXって何？
**NGINX（エンジンエックス）** は、世界中のウェブサイトを支える「ウェブサーバーソフトウェア」の一つです。  
イメージとしては、**インターネットの交通整理係** のような存在。あなたがWebサイトにアクセスするとき、裏側でNGINXがリクエストを受け取り、適切なページを返してくれています。

世界中の数百万以上のサーバーで動いており、大手企業やクラウドサービスでも広く使われています。

### 🏢 F5って何？
**F5（エフファイブ）** は、ネットワーク機器やセキュリティ製品を作るアメリカのIT企業です。NGINXを開発・管理している会社でもあります。

### 🔒 HTTP/3・QUICって何？
Webページを読み込むときの「通信のルール（プロトコル）」の最新版です。  
- **HTTP/1.1 → HTTP/2 → HTTP/3** と進化してきており、HTTP/3が最も新しく高速です。
- **QUIC（クイック）** はHTTP/3が使う通信方式で、より速く安全な通信を実現します。

### 🛡️ ASLRって何？
**ASLR（Address Space Layout Randomization＝アドレス空間配置ランダム化）** は、OSが持つセキュリティ機能の一つです。  
プログラムがメモリ上のどこに配置されるかをランダムにすることで、攻撃者が「ここを狙えばいい」と特定しにくくする仕組みです。  
**家の中のタンスや金庫の位置を毎日ランダムに変える** ようなイメージです。

---

## 何が起きたのか

F5社は、自社製品 **NGINX Open Source** に存在する **重大な脆弱性（セキュリティの穴）を2件発見・修正** しました。

この2つの脆弱性は、**インターネット越しに攻撃者がサーバーを乗っ取れる**（リモートコード実行）可能性があるという、非常に深刻なものです。

| 脆弱性ID | 危険度スコア | 問題のある機能 |
|---|---|---|
| CVE-2026-42530 | 9.2 / 10 (超危険) | HTTP/3 QUICモジュール |
| CVE-2026-42055 | 9.2 / 10 (超危険) | HTTPプロキシ・gRPCモジュール |

> 💡 **CVE（Common Vulnerabilities and Exposures）** とは、脆弱性に付けられる「通し番号」のようなものです。世界共通の識別番号で、「どの脆弱性のことか」を明確にするために使われます。

## 技術的な詳細

### 🔴 CVE-2026-42530：「使用後解放（Use-After-Free）」の脆弱性

#### どんな問題？
これは **「Use-After-Free（ユーズ・アフター・フリー）」** と呼ばれる種類のバグです。

📦 **わかりやすい例え：**  
> 引越しで荷物を運び出した後（メモリを解放した後）、誰かが間違えてその部屋に入り込んで勝手に作業を始めてしまう状態です。本来は誰も使ってはいけない「空き部屋」なのに、そこに不正アクセスできてしまう、という状態です。

#### どうやって悪用される？
- 攻撃者がNGINXに **細工した（不正な）HTTP/3通信** を送りつける
- 特定の処理（QPackエンコーダーストリームの再開）をトリガーにして、解放済みのメモリ領域に不正なコードを差し込む
- 特に **ASLRが無効なシステム** か、ASLRを回避できる場合に、コードの実行が成功してしまう

---

### 🔴 CVE-2026-42055：「ヒープバッファオーバーフロー」の脆弱性

#### どんな問題？
**「Heap-based Buffer Overflow（ヒープベース・バッファオーバーフロー）」** というバグです。

📦 **わかりやすい例え：**  
> コップに水を注ぎすぎて溢れてしまい、隣のコップにまで流れ込んでしまう状態です。メモリ上の「決まった入れ物（バッファ）」に大きすぎるデータを送り込むことで、隣のメモリ領域を上書きし、不正な動作を引き起こします。

#### どうやって悪用される？
以下の3つの条件が同時に揃っているNGINXサーバーが標的になります：

1. HTTP/2通信を中継する設定（`proxy_http_version 2`または`grpc_pass`）が有効
2. 不正なヘッダーを無視する設定（`ignore_invalid_headers`）が **オフ（off）**
3. 大きなクライアントヘッダーバッファの設定（`large_client_header_buffers`）が **2MB超**

この条件下で攻撃者が細工したリクエストを送ると、バッファが溢れてコードを実行される可能性があります。

## なぜ重要なのか

### 📊 影響範囲がとても広い
NGINXは世界中で使われているため、影響を受ける製品・バージョンが非常に多いです。

**影響を受ける主な製品（一部）：**
- NGINX Open Source（バージョン1.30.x〜1.31.x）
- NGINX Plus（R33〜R36など）
- NGINX Gateway Fabric（2.0.0〜2.6.3など）
- NGINX Ingress Controller（3.5.0〜5.5.0など）
- NGINX App Protect WAF（WAF＝Webアプリファイアウォール）
- など多数

### 😨 ログイン不要で攻撃できる
この脆弱性の最も怖い点は、**「認証なし（unauthenticated）」** で攻撃できることです。  
つまり、攻撃者はアカウントやパスワードを持っていなくても、インターネット越しにサーバーを攻撃できてしまいます。

### ⚡ 過去にも実際に悪用された前例がある
記事によると、**先月も同様のNGINXの重大な脆弱性（CVE-2026-42945、別名「NGINX Rift」）** が公開直後から実際に攻撃者に悪用されたという報告がありました。今回も同様の事態が起きる可能性があります。

## 対策・今後の展望

### ✅ 今すぐできる対策

#### CVE-2026-42530 の場合
- **最善策：** NGINXを修正済みバージョンにアップデートする（NGINX Open Source 1.31.2など）
- **緊急回避策：** HTTP/3機能を無効にする

#### CVE-2026-42055 の場合
- **最善策：** 同じく修正済みバージョンにアップデートする
- **緊急回避策：** 以下のどちらか
  - 設定ファイルから `ignore_invalid_headers off;` の記述を削除する
  - `large_client_header_buffers` のサイズを2MB未満に下げる

### 🔄 修正済みバージョン（主なもの）
| 製品 | 修正バージョン |
|---|---|
| NGINX Open Source | 1.31.2 / 1.30.3 |
| NGINX Plus | 37.0.2.1 / R36 P6 |
| NGINX Gateway Fabric | 2.6.4 |

> ⚠️ **NGINXを使っているシステム管理者の方へ：** 今すぐバージョンを確認し、アップデートを行うことを強くおすすめします！

## 用語解説

| 用語 | 意味 |
|---|---|
| **NGINX（エンジンエックス）** | 世界中で広く使われているウェブサーバーソフトウェア |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアのセキュリティ上の弱点・穴 |
| **CVE** | 脆弱性に付けられる世界共通の識別番号 |
| **CVSS スコア** | 脆弱性の危険度を0〜10で表した数値（10が最も危険） |
| **リモートコード実行（RCE）** | 攻撃者がネットワーク越しにサーバー上で任意のプログラムを動かせること |
| **Use-After-Free** | 解放済みのメモリ領域を誤って使い続けることで起きるバグ |
| **ヒープバッファオーバーフロー** | メモリの「入れ物」に入りきらないデータを詰め込み、隣のメモリを上書きするバグ |
| **ASLR** | メモリの配置をランダムにして攻撃者が狙いを定めにくくするOS機能 |
| **HTTP/3・QUIC** | 最新世代のWeb通信プロトコル（ルール）。高速・低遅延が特徴 |
| **認証なし（unauthenticated）** | ログインやパスワードなしに攻撃できること。より危険な状態を意味する |
| **プロキシ** | クライアントとサーバーの間に入って通信を中継する仕組み |
| **WAF（Web Application Firewall）** | Webアプリへの不正なアクセスを検知・遮断するセキュリティ機能 |
| **パッチ** | ソフトウェアのバグや脆弱性を修正するための更新プログラム |
