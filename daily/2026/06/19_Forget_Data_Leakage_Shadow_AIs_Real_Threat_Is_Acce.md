# データ漏洩よりも怖い！「シャドーAI」の本当の脅威はアクセス権限の管理にある

**元記事**: [Forget Data Leakage: Shadow AI's Real Threat Is Access Control](https://inl03.netline.com/ltr6/?_m=3n.009a.4008.sp0ao46r89.3280)
**解説日**: 2025年6月20日

---

## 背景知識

まずこの記事を理解するために必要な基本的な概念を説明します。

### 🤖 AIエージェントって何？
普通のAI（ChatGPTなど）は「質問したら答えてくれる」だけの受け身な存在です。しかし最近登場した「**AIエージェント**」は、自分で判断して**行動する**AIです。たとえば「このシステムのエラーを直しておいて」と頼むと、自分でログを調べて、設定を変えて、報告書を書くところまで自動でやってしまいます。

### 🕵️ シャドーITって何？
会社が公式に認めていないのに、社員が勝手に使っているソフトやサービスのことです。「会社のパソコンに私物のアプリをこっそり入れる」ようなイメージです。これをAIでやっているのが「**シャドーAI**」です。

### 🔑 アクセス制御（アクセスコントロール）って何？
「誰が、何に、どこまでアクセスできるか」を管理する仕組みです。たとえば学校で言えば、「生徒は職員室に入れない」「先生は成績データを見られる」といったルールのことです。

### 🗝️ 認証情報（クレデンシャル）って何？
システムにログインするためのIDやパスワードのことです。AIエージェントもシステムを操作するために、この認証情報を使います。

## 何が起きたのか

### 最初の心配は「データの貼り付け」だった

少し前まで、企業のセキュリティ担当者が心配していたのはこういうことでした：

> 「社員が顧客情報をChatGPTにコピペしてしまった！情報が外部に漏れる！」

これに対して、企業は「AIツールへのアクセスを禁止する」「使用ルールを作る」「データ漏洩防止のシステムを入れる」などの対策をしました。

### でも、問題はすでに「次のステージ」に移っていた

この記事が伝えているのは、**脅威の本質が変わってしまった**ということです。

今や社員たちは、部門ごとに「AIエージェント」を自分たちで作って動かしています。そしてそのAIエージェントが、会社の重要なシステムに接続され、**自律的にさまざまな操作を行っている**のです。

```
【昔の問題】
社員 → AIに顧客データをコピペ → 情報漏洩のリスク

【今の問題】
AIエージェント（自律型） → 会社の複数システムに接続
　　　├── Salesforce（顧客管理）
　　　├── GitHub（プログラムのソース管理）
　　　├── Slack（社内チャット）
　　　└── Snowflake（データ分析）
　　　　　→ データを読む・書く・削除する操作を自動実行！
```

## 技術的な詳細

### AIエージェントは「受け身のツール」ではなく「行動する存在」

従来の社内ツールは「人間が使う道具」でした。しかしAIエージェントは違います。自分で判断して、複数のシステムを次々と操作できます。

たとえば「システム障害を自動で直すAIエージェント」は、こんな動きをします：

1. ログ（記録）を読む
2. 監視システムに問い合わせる
3. インフラの設定を変更する
4. チケット（問い合わせ票）を発行する
5. 自動化パイプラインを起動する
6. エンジニアチームに通知する

これらすべてを**人間の許可なく、連続して自動実行**するのです。

### なぜ権限が危険な状態になるのか

```
【権限が膨らむ仕組み】

1. 社員Aが「ちょっと試しに」AIエージェントを作る
        ↓
2. うまく動かすために、広い権限を与える（面倒だから）
        ↓
3. 便利なので、チームに広まる
        ↓
4. 社員Aが別の部署に異動・退職
        ↓
5. AIエージェントは誰も管理しないまま動き続ける
        ↓
6. 元の社員レベルの権限で、誰も知らないまま稼働中…😱
```

しかも、このAIエージェントは「サービスアカウント」（システム専用のIDのようなもの）で動いていることが多く、誰もきちんと権限を確認していない状態になりがちです。

### 既存のセキュリティ対策が届かない理由

| 対策 | 人間向けには有効 | AIエージェントには？ |
|---|---|---|
| 「AIサイトへのアクセスをブロック」 | ✅ 有効 | ❌ すでに社内で動いているので無意味 |
| データ漏洩防止ルール | ✅ 有効 | ❌ 人間の行動を想定した設計 |
| ネットワーク監視 | ✅ 有効 | ❌ AIの動きは複雑すぎて検知困難 |

## なぜ重要なのか

### 🔥 影響の大きさを「学校」で例えてみると

> 学校で例えるなら、「生徒が答えを誰かに教えた（データ漏洩）」から、「合鍵を持ったロボットが誰も見ていない夜中に学校中の部屋を自由に出入りしている（アクセス制御の問題）」に変わったようなイメージです。

### 具体的に何が怖いのか

- **データを読むだけでなく、書き換えたり削除したりできる**
- **誰が作ったかわからないAIエージェントが、社内を動き回っている**
- **作った社員が会社を辞めた後も、AIエージェントは動き続ける**
- **セキュリティチームがそのAIエージェントの存在すら把握できていない**

Token Security社とCloud Security Alliance（クラウドセキュリティ連合）の調査でも、こうした「管理されていないAIエージェント」が企業内に広く存在していることが明らかになっています。

## 対策・今後の展望

### 記事が提案する「シャドーAIの棚卸し」のための6つの問い

企業のセキュリティ担当者が自問すべき確認ポイントが紹介されています：

| # | 確認項目 | なぜ重要か |
|---|---|---|
| 1 | **どこでAIエージェントが作られているか？** | 公式ツール以外にも拡張機能や開発ツールで作られる |
| 2 | **誰が所有・利用できるか？** | 管理者がいないと責任の所在が不明になる |
| 3 | **どのリソースに接続されているか？** | 接続先が多いほどリスクが高い |
| 4 | **どんな権限を持っているか？** | 必要以上の権限は削除すべき |
| 5 | **いつ最後に使われたか？** | 使われていないエージェントは削除する |
| 6 | **誰がそのエージェントを監視しているか？** | 無人のエージェントは危険 |

### セキュリティチームに求められること

- 「**人間のアカウント**」だけでなく「**AIエージェントのアカウント（非人間ID）**」も管理する
- AIエージェントにも「最小権限の原則」（必要最低限の権限しか与えない）を適用する
- 定期的にAIエージェントの棚卸しを行う

## 用語解説

| 用語 | 意味 |
|---|---|
| **シャドーAI** | 会社が公式に許可していないAIツールを社員が勝手に使うこと |
| **AIエージェント** | 人間の指示がなくても自律的に判断・行動するAI |
| **アクセス制御** | 「誰が何にアクセスできるか」を管理する仕組み |
| **認証情報（クレデンシャル）** | システムにログインするためのID・パスワード等 |
| **IAM（アイデンティティ管理）** | 社員やシステムのアクセス権限を一元管理する仕組み |
| **DLP（データ漏洩防止）** | 機密データが外部に出ないよう監視・制御するシステム |
| **サービスアカウント** | 人間ではなく、システムやプログラムが使う専用のID |
| **最小権限の原則** | 必要な作業に必要な最低限の権限だけを与えるセキュリティの考え方 |
| **MCP（Model Context Protocol）** | AIエージェントが外部ツールと連携するための仕組み |
| **API** | 異なるソフトウェア同士が情報をやり取りするための窓口 |

---

> 💡 **まとめ**：AIが「使う道具」から「自分で動く存在」に変わったことで、セキュリティの問題も「情報漏洩」から「誰も管理していないAIが会社の中を自由に動き回る」という新しいステージに移りました。企業はAIエージェントも「社員のアカウント」と同じように、きちんと把握・管理する必要があります。
