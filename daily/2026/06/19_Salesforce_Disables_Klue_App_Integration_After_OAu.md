# SalesforceがKlueアプリ連携を停止！OAuthトークン悪用で顧客データが流出

**元記事**: [Salesforce Disables Klue App Integration After OAuth Token Abuse Exposes Customer Data](https://inl03.netline.com/ltr6/?_m=3n.009a.4008.sp0ao46r89.328c)
**解説日**: 2026年6月20日

---

## 背景知識

このニュースを理解するために、まずいくつかの重要な概念を説明します。

### 🏢 登場する会社・サービスとは？

| 名前 | 役割 |
|------|------|
| **Salesforce** | 世界最大級の「顧客管理ツール(CRM)」。企業の営業担当者が顧客情報・商談・見積もりなどを管理するクラウドサービス |
| **Klue** | 競合他社の情報を分析・まとめてくれるツール。「ライバル会社はこんな戦略をとってる！」という情報を提供するサービス |
| **Huntress** | サイバーセキュリティ企業。今回の被害を受けた会社の一つ |

### 🔑 「OAuthトークン」って何？

OAuthトークンは、**デジタルの「合鍵」** のようなものです。

> **例え話**：マンションの管理会社（Klue）に「配達業者（連携サービス）が入れるように」とマスターキーを預けたとします。ところが、そのマスターキーが泥棒に盗まれてしまったら、泥棒はそのマスターキーを使って住人（顧客企業）の部屋に勝手に入れてしまいます。

OAuthとは、パスワードを直接渡さずに「このアプリに○○へのアクセスを許可する」という仕組みです。SNSで「Googleアカウントでログイン」するときに使われているものと同じ技術です。

### 🔗 「アプリ連携（インテグレーション）」とは？

異なるサービス同士をつなぎ合わせる仕組みのことです。

```
[Salesforce の顧客データ]
        ↕ 連携（OAuthトークンで認証）
[Klue の競合分析ツール]
```

Klueは、SalesforceのデータをKlueに取り込んで分析するために、OAuthトークンを使って接続していました。

### 🎯 何が盗まれたのか？

Huntressが公開した情報によると、盗まれたデータは以下の通りです：

- ✅ ビジネス連絡先（取引先の名前・メールなど）
- ✅ 価格見積もり
- ✅ 営業関連のメッセージやデータ

一方、以下のデータは**影響を受けていない**とのことです：

- ❌ 脅威情報（セキュリティ関連データ）
- ❌ パスワード
- ❌ クレジットカード情報
- ❌ エンジニアリングデータ

### 🐍 Pythonスクリプトを使った自動攻撃

セキュリティ会社ReliaQuestの調査によると、攻撃者はPythonというプログラミング言語で書いたスクリプト（自動処理プログラム）を使って、大量のデータを効率よく盗み出していました。

> **例え話**：図書館から本を盗む泥棒が、一冊一冊手で運ぶのではなく、台車を使って大量に一気に持ち出したようなイメージです。

## なぜ重要なのか

### 💥 この事件の怖いポイント3つ

#### ① 「信頼された連携」が攻撃の入り口になった

Klueは正規のSalesforce連携アプリでした。つまり、**セキュリティの穴ではなく「正規の機能」が悪用された**わけです。Salesforce自身は「我々のプラットフォームに脆弱性があったわけではない」と明言しています。

#### ② 「放置されたアカウント」が命取りに

攻撃の最初のきっかけは、**Klueが昔テスト用に作って使わなくなったアカウント**でした。削除し忘れていたこのアカウントが、何年も後に攻撃の入り口になってしまったのです。

> セキュリティの世界では「使っていないアカウントや権限は削除する」というのが基本中の基本ですが、それが守られていませんでした。

#### ③ 「1社の侵害」が「多数の企業への攻撃」に発展した

Klue1社が攻撃されただけで、Klueのサービスを使っていた**複数の企業のデータが芋づる式に漏れました**。これを「**サプライチェーン攻撃**」と言います。

## 対策・今後の展望

### ✅ Klueが実施した緊急対応

- 侵害されたアカウントとOAuthトークンをすべて**無効化**
- 不正に仕込まれたコードを**削除**
- 外部からのリモートアクセスを**遮断**
- 影響を受けた連携機能を**停止**
- 包括的な調査を**開始**

### 🛡️ 私たちが学べる教訓

| 教訓 | 具体的な対策 |
|------|-------------|
| 使わなくなったアカウントは即削除 | 定期的にアカウントを棚卸しする |
| OAuthトークンは定期的に更新・見直す | 不要な連携アプリは接続を切る |
| 連携アプリにも最小限の権限のみ付与 | 必要なデータだけにアクセスできるよう設定 |
| 不審な通信を監視する | ログを定期的にチェックする |

### 🔮 今後の動向

攻撃グループ「Icarus」は2026年4月から活動を開始したばかりで、今のところ2社が被害を受けています。セキュリティ研究者は、この攻撃手口が過去の大規模攻撃グループ（**ShinyHunters**や**UNC6395**）と似ていると指摘しており、今後も同様の手口による攻撃が続く可能性があります。

## 過去記事との関連

以前、「**シャドーAI**」についての記事を解説しましたが、あの記事では「社員が会社の許可なく外部AIサービスにデータを渡してしまうリスク」を扱っていました。

今回の事件はそれと似た構造を持っています。**「正規に許可されたアプリ連携（インテグレーション）」が攻撃の入り口になった**という点で、「外部サービスへのアクセス権限をどう管理するか」という共通の課題があります。

> シャドーAIの問題も今回のOAuthトークン悪用も、根本には「**アクセス権限の管理が甘い**」という同じ弱点があります。どんなに便利なツールでも、セキュリティ管理がずさんだと大きな事故につながります。

## 用語解説

| 用語 | 意味 |
|------|------|
| **Salesforce** | 世界最大級の顧客管理クラウドサービス(CRM) |
| **OAuth（オーオース）トークン** | パスワードを使わずにアプリ間のアクセスを許可するデジタルの「合鍵」 |
| **インテグレーション（アプリ連携）** | 異なるサービスやアプリをつなぎ合わせる仕組み |
| **CRM（顧客管理システム）** | Customer Relationship Management。顧客情報や営業活動を管理するシステム |
| **エクストーション（恐喝）グループ** | データを盗み「公開されたくければ金を払え」と脅す犯罪グループ |
| **サプライチェーン攻撃** | 直接ターゲットを攻撃するのではなく、ターゲットが使っているサービスや製品を経由して攻撃する手口 |
| **レガシー（古い）クレデンシャル** | 昔作られてそのまま放置されている認証情報（アカウントやパスワード） |
| **REST API** | サービス間でデータをやり取りするための通信の仕組み |
| **Icarus（イカロス）** | 今回の攻撃を行ったとされる攻撃グループの名称（ギリシャ神話の「太陽に近づきすぎて墜落したイカロス」から） |
| **ReliaQuest** | 今回の攻撃を詳しく分析したセキュリティ企業 |
