# ClaudeをOktaやMicrosoft 365と同じように管理できるようになった

**元記事**: [You Can Now Govern Claude the Same Way You Govern Okta and M365](https://inl03.netline.com/ltr6/?_m=3n.009a.4008.sp0ao46r89.3286)
**解説日**: 2025年6月20日

---

## 背景知識

このニュースを理解するために、まずいくつかの言葉を説明します。

### 🤖 Claudeとは？
**Claude（クロード）**は、Anthropicという会社が作ったAIアシスタントです。ChatGPTと同じような「AIチャットツール」で、文章を書いたり、質問に答えたり、コードを書いたりしてくれます。最近、多くの会社が仕事でClaudeを使い始めています。

### 🔑 Oktaとは？
**Okta（オクタ）**は「誰がどのシステムにアクセスできるか」を管理する会社のツールです。たとえば、「Aさんは経理システムだけ使える」「Bさんは全システム使える」というルールを一元管理します。学校で言えば「生徒証」みたいなもので、持っている人だけが特定の場所に入れる仕組みです。

### 📦 Microsoft 365（M365）とは？
**Microsoft 365**はWordやExcel、Teamsなどのビジネスツールをまとめたサービスです。多くの会社で使われており、「誰がどのファイルを見られるか」「どんな操作ができるか」を管理する仕組みが整っています。

### 🏢 「ガバナンス（Governance）」って何？
「ガバナンス」とは、簡単に言うと**「ルールを作って、ちゃんと守られているか監視すること」**です。会社のIT部門が「誰が何のツールを使えるか」「何をしていいか・ダメか」を管理することを指します。

---

## 何が起きたのか

今回のニュースのポイントは一言でまとめると、

> **「AIツールのClaudeを、これまで普通のビジネスソフトと同じ方法でセキュリティ管理できるようになった」**

ということです。

これまで企業は、OktaやMicrosoft 365のような一般的なビジネスツールについては、しっかりとしたルール管理の仕組みがありました。たとえば：

- 「このユーザーはこのデータにしかアクセスできない」
- 「ログイン履歴をすべて記録する」
- 「不審な操作があったら警告を出す」

しかし、**ClaudeのようなAIツールはこうした管理の枠の外にある**ことが多く、「誰がAIに何を聞いているか」「AIがどんな情報を扱っているか」が把握しにくい状態でした。

それが今回、**ClaudeをOktaやM365と同じ管理基盤に乗せられる**ようになった、というのが今回の発表の核心です。

## 技術的な詳細

少し詳しく仕組みを説明します。

### 🗂️ 統合管理とは？

企業のIT管理者は「SCIM（スキム）」や「SSO（シングルサインオン）」と呼ばれる仕組みを使って、社員のアカウントやアクセス権限を一元管理しています。

```
【イメージ図】

社員Aさん
  ↓
【Okta（管理センター）】
  ↓               ↓              ↓
メール         経理ソフト      ← 今まではここまで
(M365)        (社内システム)
  
  ↓（今回追加！）
Claude（AI）   ← 同じ管理の枠に入った！
```

### 🔒 何が管理できるようになったのか

具体的には以下のような管理が可能になったと考えられます：

| 管理項目 | 内容 |
|---------|------|
| **アクセス制御** | 誰がClaudeを使えるか制限できる |
| **ログ記録** | 誰がいつClaudeに何を聞いたか記録できる |
| **ポリシー適用** | 「このチームはClaudeで社外秘情報を扱ってはいけない」などのルールを設定できる |
| **アカウント管理** | 退職した社員のClaudeアクセスを自動で無効化できる |

### 📋 ポリシーエンジンとの統合
OktaやM365には「ポリシーエンジン」という「ルール自動チェック機能」があります。これがClaudeにも適用できるようになると、たとえば：

> 「新入社員は機密プロジェクトのデータをClaudeに入力できない」

というルールを、システムが自動的に強制してくれます。人間が一つひとつチェックしなくていいので、ミスや見落としが減ります。

## なぜ重要なのか

### 😰 これまでの問題点

AIツールは「便利だから」という理由で、IT部門の管理外で勝手に使われることが多くありました（これを**シャドーAI**と呼びます）。

たとえばこんなことが起きていました：

- 社員が気づかず**社外秘の情報をAIに入力**してしまう
- 退職した社員のアカウントが**AIツールに残り続ける**
- 誰がAIに何を聞いたか**記録が残らない**ため、情報漏洩が起きても原因がわからない

### ✅ 今回の発表で何が変わるか

ClaudeがOktaやM365と同じ管理下に置かれることで：

1. **情報漏洩リスクの低下** → 誰が何の情報をAIに渡したか追跡できる
2. **コンプライアンスの強化** → 法律や社内規定に沿ったAI利用を強制できる
3. **管理コストの削減** → 新しいツールを覚えなくても、既存の仕組みでAIも管理できる

### 🌍 社会的な意味

AIが「特別な別世界のツール」から、**「普通のビジネスインフラの一部」**として扱われるようになったことを意味します。これはAIが企業の中に本格的に根付いてきた証拠とも言えます。

## 対策・今後の展望

### 企業がすべきこと

| やること | 内容 |
|---------|------|
| **AIツールの棚卸し** | 社内でどんなAIツールが使われているか把握する |
| **ガバナンスポリシーの策定** | AIに対して「何を入力してよいか・ダメか」のルール作り |
| **既存管理ツールとの統合** | OktaやM365を使っているならClaudeとの統合を検討する |
| **社員教育** | AIに機密情報を入力することのリスクを教育する |

### 🔮 今後の展望

今回のClaudeの対応は「AIガバナンス（AI管理）」という分野の大きな一歩です。今後は：

- 他のAIツール（ChatGPT Enterpriseなど）も同様の管理体制に対応していく
- 政府や規制機関が「AIの使用記録を義務化」する動きが加速する
- 「AIを安全に使える企業」と「そうでない企業」の差が開いていく

可能性があります。
