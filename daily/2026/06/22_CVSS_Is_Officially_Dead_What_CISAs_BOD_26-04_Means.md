## 背景知識

まず、このニュースを理解するために必要な3つのキーワードを説明します。

---

### 🔢 CVSSとは？「脆弱性の危険度スコア」

**CVSS（Common Vulnerability Scoring System＝共通脆弱性評価システム）** とは、ソフトウェアの「セキュリティの穴（脆弱性）」がどれくらい危険かを **0〜10点** で数値化する仕組みです。

```
スコア例：
0.0 〜 3.9 → 低（Low）
4.0 〜 6.9 → 中（Medium）
7.0 〜 8.9 → 高（High）
9.0 〜10.0 → 緊急（Critical）
```

**わかりやすい例え**で言うと、「家の鍵の壊れやすさを10点満点で評価する」ようなものです。
- スコア9点 → 「鍵が完全になく、誰でも入れる状態」
- スコア3点 → 「鍵が少し古くなっているが、すぐには壊されない状態」

CVSSは世界中のIT企業・政府機関が「どのセキュリティ問題を先に直すか」を判断する**共通の物差し**として、約20年間使われてきました。

---

### 🏛️ CISAとは？「アメリカのサイバーセキュリティ庁」

**CISA（Cybersecurity and Infrastructure Security Agency）** は、アメリカ政府のサイバーセキュリティ専門機関です。日本で言えば「内閣サイバーセキュリティセンター（NISC）」に近い存在で、国全体のデジタルセキュリティを守る役割を担っています。

CISAが出す指令は、**アメリカ政府機関に対して法的拘束力**を持ちます。そして世界中の企業もその動向を参考にするため、実質的に**グローバルスタンダード**に影響を与えます。

---

### 📋 BOD（Binding Operational Directive）とは？「強制力のある運用指令」

**BOD（バインディング・オペレーショナル・ディレクティブ）** とは、CISAがアメリカ連邦政府機関に出す「**必ず従わなければならない指示書**」です。

過去の有名なBODの例：
- **BOD 22-01**：既知の脆弱性は〇日以内に必ず修正せよ
- **BOD 23-02**：インターネットに直接つながる管理画面を保護せよ

今回の **BOD 26-04** は、脆弱性の「優先順位付け」のルールを根本から変える内容です。

---

## 何が起きたのか

### 📰 一言で言うと

> 「CISAが、脆弱性の危険度を判断する際に **CVSSスコアだけに頼るのをやめる** という公式指令を出した」

---

### 具体的に何が変わるのか

これまでの流れ（旧来の方法）：

```
脆弱性が発見される
　　↓
CVSSスコアが計算される（例：8.5点 → 「高」）
　　↓
スコアが高い順に修正作業をする
```

これからの流れ（BOD 26-04以降）：

```
脆弱性が発見される
　　↓
複数の要素で総合評価する
　　├─ 実際に攻撃に使われているか？（KEV：既知悪用脆弱性）
　　├─ 自分たちのシステムに本当に影響があるか？
　　├─ 攻撃が成功する可能性はどのくらいか？（EPSS）
　　└─ ビジネス上の影響はどれくらいか？
　　↓
「実際のリスク」に基づいて優先順位を決める
```

---

### なぜ「CVSSが死んだ」と言われるのか？

タイトルの「CVSS is Officially Dead（CVSSは正式に死んだ）」は少し刺激的な表現ですが、意味するのは：

- CVSSが**完全になくなる**わけではない
- しかし**CVSSスコアだけを見て優先順位を決める時代は終わった**
- 政府機関が公式に「CVSSだけでは不十分」と認めた

ということです。

## 技術的な詳細

### CVSSの何が問題だったのか？

CVSSには長年、業界から批判がありました。

#### 問題① 「スコアが高くても攻撃されないケースが多い」

🏠 **例え話**：
「家の窓の鍵が古い（CVSSスコア8点）」でも、その家が**人里離れた山奥**にあれば、実際に泥棒が来るリスクは低いですよね。

CVSSは「理論上の危険度」を測りますが、「あなたの環境で本当に危険か」は考慮しません。

実際のデータとして：
> CVSSスコアが「高（High）」以上の脆弱性のうち、実際に攻撃に悪用されるのは **約5〜10%程度** と言われています。

つまり、高スコアの脆弱性をすべて同じ優先度で対応しようとすると、**本当に危険なものへの対応が遅れる**可能性があります。

---

#### 問題② 「脆弱性の数が爆発的に増えすぎた」

```
2019年: 約17,000件
2021年: 約20,000件
2023年: 約29,000件
2024年: 約40,000件超（過去最多）
```

毎日100件以上の新しい脆弱性が報告される現代では、「CVSSが高いものを全部直す」という戦略は**現実的に不可能**になってきています。

---

#### 問題③ 「同じ脆弱性でも組織によってリスクが違う」

例えば、Windowsの管理ツールに脆弱性が見つかったとします。

| 組織の種類 | 実際のリスク |
|------------|-------------|
| その管理ツールを使っている病院 | 非常に高い |
| その管理ツールを使っていない学校 | ほぼゼロ |
| クラウドのみで運営するスタートアップ | 低い |

CVSSは「脆弱性そのもの」のスコアなので、**あなたの組織にとっての危険度**は教えてくれません。

---

### BOD 26-04が推進する新しいアプローチ

#### 🗂️ KEV（Known Exploited Vulnerabilities）カタログの活用

CISAが管理する「**実際に攻撃に使われている脆弱性のリスト**」です。

```
考え方：
CVSSスコアが6点でも、KEVに載っているなら → 最優先で対応
CVSSスコアが9点でも、KEVに載っていないなら → 急がなくても良いかも
```

---

#### 📊 EPSS（Exploit Prediction Scoring System）の活用

**EPSS（エクスプロイト予測スコアリングシステム）** は、「この脆弱性が今後30日以内に実際の攻撃に使われる確率」をAIで計算するシステムです。

```
例：
CVSSスコア8.0 + EPSS 0.3%  → 理論上は危険だが、実際には使われにくい
CVSSスコア6.5 + EPSS 85%   → スコアは中程度だが、今すぐ攻撃されるリスクが高い！
```

**野球で例えると**、CVSSは「バッターの過去の打率」、EPSSは「今日の試合でヒットを打つ確率の予測」のようなものです。

---

#### 🏢 組織固有のコンテキスト評価

新しいアプローチでは、以下のような「自分たちの状況」も考慮します：

- そのシステムはインターネットに公開されているか？
- そのシステムが止まると、業務にどれくらい影響があるか？
- そのシステムには別の防御策（ファイアウォールなど）があるか？

## なぜ重要なのか

### 🌍 世界への影響

CISAの指令はアメリカ政府機関向けですが、実際には：

1. **アメリカ政府と取引する企業**は同様の対応を求められる可能性がある
2. **日本のセキュリティ基準**もアメリカの動向を参考に作られることが多い
3. **グローバルなセキュリティ製品・サービス**がこの基準に合わせてアップデートされる

つまり、他人事ではありません。

---

### 🏥 特に影響を受ける業界

| 業界 | 理由 |
|------|------|
| 医療・病院 | 命に関わるシステムを守る必要がある |
| 金融・銀行 | 政府規制と連動しやすい |
| 重要インフラ（電力・水道） | 国家安全保障に直結 |
| ITベンダー・セキュリティ企業 | 製品・サービスの見直しが必要 |

---

### 💡 私たちの日常生活への影響

直接的な影響は感じにくいですが、長期的には：

> 「セキュリティ担当者が本当に危険な脆弱性を先に直せるようになる」

→ 私たちが使うサービス・アプリが、より安全になる可能性が上がります。

## 対策・今後の展望

### 企業・組織が今すぐできること

#### ① CVSSスコア「だけ」での判断をやめる

```
改善前: CVSSスコアが7以上は全部1週間以内に対応
改善後: KEVに載っているものを最優先、EPSSも参考にする
```

#### ② CISAのKEVカタログを定期確認する

KEVカタログは無料で公開されており、誰でも確認できます：
- 🔗 [CISA KEVカタログ（公式）](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)

#### ③ 「リスクベース脆弱性管理（RBVM）」の考え方を導入する

**RBVM（Risk-Based Vulnerability Management）** とは、「すべての脆弱性を同列に扱わず、自分たちのビジネスへの実際のリスクで優先順位をつける」アプローチです。

---

### 今後の展望

| 時期 | 予想される動き |
|------|---------------|
| 2025年 | アメリカ政府機関がBOD 26-04への対応を開始 |
| 2026年 | 民間企業への影響が本格化 |
| 近い将来 | 日本・EUなど各国の規制もリスクベース評価に移行していく可能性 |

CVSSが完全になくなるわけではなく、**CVSSは「入門情報」、実際の判断は複合的な評価で**という形に進化していくでしょう。

---

## 過去記事との関連

今回のニュースは単独の出来事ではなく、ここ数年のセキュリティ業界の大きな流れの一部です。

- **2021年〜**: CISAがKEVカタログの運用を開始し、「実際に使われている脆弱性」への注目が高まった
- **2022年**: BOD 22-01で「既知の脆弱性は期限内に必ず直せ」という義務化が始まった
- **2023年〜**: EPSSの精度向上により、「将来の攻撃予測」が現実的なツールになった
- **2025年 BOD 26-04**: これらの流れが集大成として、公式に「CVSSだけの時代の終わり」を宣言

**一言で言えば**：セキュリティの世界が「理論上の危険度」から「現実のリスク」を重視する方向に、ついに公式に舵を切った歴史的な転換点です。

| **CVSS** | シーブイエスエス | 脆弱性の危険度を0〜10点で数値化するスコアシステム |
| **CISA** | シーサ | アメリカのサイバーセキュリティ・社会基盤安全保障庁 |

| **RBVM** | アールビーブイエム | 実際のビジネスリスクに基づいて脆弱性の優先順位を決める手法 |

| **パッチ** | - | ソフトウェアの欠陥を修正するための更新プログラム |
| **重要インフラ** | - | 電力・水道・交通・通信など社会の基盤となるシステム |

---

> 📝 **まとめ**：CVSSという「テストの点数だけで合否を決める」ような仕組みから、「実際の試験会場の状況や過去の傾向も総合的に見て判断する」仕組みへ。セキュリティの優先順位付けが、より賢く・現実的になる転換点です。
