# 29年前のバグ「Squidbleed」：Squidプロキシが他人のHTTP通信内容を漏らす脆弱性

**元記事**: [29-Year-Old Squid Proxy Bug 'Squidbleed' Can Leak Cleartext HTTP Requests](https://inl03.netline.com/ltr6/?_m=3n.009a.4011.sp0ao46r89.32d6)
**解説日**: 2026年6月24日

---

## 背景知識

このニュースを理解するために、まず3つの基本的な概念を押さえておきましょう。

### 🔄 プロキシサーバーとは？
「プロキシ（Proxy）」とは、**あなたのパソコンとインターネットの間に立つ「中継役」のサーバー**のことです。

```
あなたのPC → プロキシサーバー → インターネット（Webサイト等）
```

学校や会社のネットワーク、公衆Wi-Fiなどでは、利用者全員のアクセスを一度プロキシサーバーに集めてから、外のネットワークに送り出すことがよくあります。これにより、アクセス制限やセキュリティチェック、通信の記録などができます。

**Squid（イカ）** はその中でも世界中で広く使われている、オープンソース（無料で公開されている）のプロキシソフトウェアです。

### 📂 FTPとは？
「FTP（File Transfer Protocol）」は、**ファイルを送受信するための古い通信規格**です。今は主にHTTPSが使われていますが、昔は多くのサイトでFTPが使われていました。Squidはデフォルト（初期設定）でFTPにも対応しています。

### 💧 Heartbleed（ハートブリード）とは？
2014年に発見された有名な脆弱性で、**サーバーのメモリ（一時記憶領域）から、他のユーザーのパスワードなど機密情報がダダ漏れになる**という衝撃的なバグでした。今回の「Squidbleed」はそれと似た仕組みであることから、この名前が付けられました。

---

## 何が起きたのか

セキュリティ研究チーム「Calif.io」が、**Squidプロキシに29年間誰にも気づかれていなかった重大なバグ**を発見し、2026年6月に公開しました。

このバグを悪用すると、**同じプロキシを使っている他のユーザーのHTTP通信内容（IDやパスワード、セッショントークンなど）を盗み見ることができます。**

- 🔍 **CVE番号**: CVE-2026-47729（脆弱性の公式識別番号）
- 📅 **バグの起源**: なんと**1997年**（29年前！）のコード変更が原因
- ⚠️ **現状**: デフォルト設定のまま使っているSquidサーバーは今も危険な状態
- 🧪 **実証コード（PoC）**: すでに公開済み（悪用の可能性あり）
- 🌐 **実被害**: 記事執筆時点では実際の攻撃は報告されていない

## 技術的な詳細

### 🐛 バグはどこにある？

バグは**SquidのFTPディレクトリ一覧を読み取る処理（パーサー）**の中にあります。

少し具体的に説明しましょう。

FTPサーバーに接続すると、フォルダの中身の一覧（ファイル名、日時など）が返ってきます。Squidはそのリストを読み取って処理します。

```
（例：FTPの一覧表示）
-rw-r--r-- 1 user group 1234 Jan 01 2020 filename.txt
```

昔の特殊なサーバー（NetWareというサーバーOS）が余分なスペースを入れることがあったため、Squidのコードにはそのスペースを読み飛ばす処理が入っていました。

### 🚨 何が問題なのか？

攻撃者が**わざと壊れた一覧データを返す偽のFTPサーバー**を用意します。具体的には、**ファイル名がない一覧行**を送ります。

```
（通常）日時 + ファイル名
（攻撃用）日時 + ファイル名なし← ここが罠！
```

ファイル名がないと、Squidのコードは「次の文字を読む」ループが**止まれなくなります**。

これはちょうど、本を読んでいてページが終わっても止まらずに、次の本の内容まで読み続けてしまうようなイメージです📚。

```
本来のメモリ領域           はみ出して読んでしまう領域
[FTPの一覧データ     ][他のユーザーのHTTPリクエスト...]
 ↑ここまで読むはずが→→→→→→→→→→→→→→→→→→→→→→→→→→ここまで読んでしまう！
```

### 💾 なぜ他のユーザーの情報が漏れるのか？

Squidは処理済みのメモリ領域を**「ゼロクリア（初期化）せずに再利用」**します。つまり、直前に別のユーザーのHTTPリクエスト（通信内容）を処理していた4KBのメモリ領域には、**そのユーザーの情報がまだ残っています**。

攻撃者のFTPデータは先頭の数バイトしか上書きしないため、**残りの部分をそのまま「ファイル名」として読み取って攻撃者に返してしまいます**。

実際の攻撃デモでは、被害者の `Authorization: ` ヘッダー（認証情報）が取得できたと報告されています。これがあれば、**被害者になりすますことができます**。

## なぜ重要なのか

### 影響を受ける環境
このバグが特に危険なのは、以下のような**「共有ネットワーク」**です：

| 環境 | リスク |
|------|--------|
| 🏫 学校のネットワーク | 生徒全員が同じプロキシを使う |
| 🏢 会社・オフィス | 社員の認証情報が狙われる |
| 📶 公衆Wi-Fi | 誰でも同じプロキシに接続できる |

### 条件の整理
ただし、攻撃にはいくつかの条件が必要です：

✅ 攻撃者が**同じプロキシを使える権限**を持っていること（学校のLAN内の別の生徒など）
✅ 被害者が**HTTP（暗号化なし）通信**をしていること（HTTPSは基本的に安全）
✅ プロキシが**FTPをデフォルト設定で有効にしている**こと
✅ 攻撃者が**port 21でFTPサーバーを立てられる**こと

HTTPSで暗号化されたサイトは基本的には安全ですが、**プロキシがSSL/TLSの暗号を解除してチェックする設定（SSL インスペクション）**になっている場合は、HTTPS通信も危険です。

### 深刻度スコア
CVSS（脆弱性の深刻度を数値化したもの）は**6.5（10点満点）で「中程度」**。条件が必要なため最高レベルではありませんが、十分に注意が必要です。

## 対策・今後の展望

### 🛡️ 今すぐできる対策

#### 【最優先・最も確実】FTPを無効化する
研究者たちが最も強くすすめているのが、**SquidでFTPを完全にオフにすること**です。

> 「ChromeなどのブラウザはすでにFTPのサポートを廃止しており、現在のネットワークでFTPの通信はほとんどない。無効化しても影響はほぼなく、攻撃の入口を完全に塞げる」

設定ファイル（`squid.conf`）に以下を追加することで無効化できます：
```
acl FTP proto FTP
http_access deny FTP
```

#### 【パッチ（修正プログラム）を適用する】
- 修正済みバージョン: **Squid 7.7以降**（7.6は情報が錯綜中のため要確認）
- パッチの内容：`FtpGateway.cc` というファイルに「ファイル名がなかったらループを止める」という1行チェックが追加された
- Debianなどのディストリビューション（Linuxの種類）は独自ビルドを配布しているため、バージョン番号だけでなく**実際のコードが修正されているかも確認が必要**

### 🤖 AIがバグ発見に貢献
今回、バグを見つけたのは研究者だけではありませんでした。Anthropic社のAI「Claude Mythos Preview」が、この`strchr`の問題点をほぼ即座に指摘したとのこと。以前解説した[OpenAIのGPT-5.5-Cyber](https://inl03.netline.com/ltr6/?_m=3n.009a.4011.sp0...)と同様、**AIがセキュリティの穴を見つけ出すツールとして急速に進化**していることがわかります。

研究チームは「SquidのFTPコード以外にも、まだ問題箇所が残っているかもしれない」と示唆しており、今後も調査が続く見込みです。

## 用語解説

| 用語 | 意味 |
|------|------|
| **プロキシサーバー** | ユーザーとインターネットの間に立つ中継サーバー |
| **Squid** | 広く使われているオープンソースのプロキシソフトウェア |
| **FTP** | ファイル転送用の古い通信プロトコル（規格） |
| **HTTP/HTTPS** | Webの通信規格。HTTPは暗号化なし、HTTPSは暗号化あり |
| **ヒープオーバーリード** | メモリの読み取り範囲を超えて、隣のデータまで読んでしまうバグ |
| **CVE番号** | 脆弱性を世界共通で管理するための識別番号 |
| **セッショントークン** | ログイン状態を維持するための「合言葉」のようなデータ |
| **Authorizationヘッダー** | HTTP通信に含まれる認証情報（IDやパスワードの代わりになるトークン等） |
| **CVSS** | 脆弱性の深刻度を0〜10で数値化した指標 |
| **PoC（概念実証コード）** | 脆弱性が実際に悪用できることを示すサンプルプログラム |
| **ゼロクリア** | 使い終わったメモリ領域を0で上書きして初期化すること |
| **SSL インスペクション** | プロキシがHTTPS通信を一度解読して検査する仕組み |
| **Heartbleed** | 2014年に発見されたOpenSSLの重大な脆弱性。メモリ漏洩系バグの代名詞 |
