# Amazon Q Developerの脆弱性：悪意あるリポジトリがMCP設定経由でコードを実行できた問題

**元記事**: [Amazon Q Developer Flaw Could Let Malicious Repos Run Code via MCP Configs](https://inl03.netline.com/ltr6/?_m=3n.009a.4015.sp0ao46r89.32ie)
**解説日**: 2025年7月1日

---

## 背景知識

このニュースを理解するために、まずいくつかの大切な概念を押さえておきましょう。

### 🤖 Amazon Q Developerとは？
AmazonがAWS（Amazon Web Services、Amazonのクラウドサービス）上で提供している**AIコーディングアシスタント**です。プログラマーがコードを書くときに、AIが自動補完・提案・デバッグを手伝ってくれるツールです。VSCode（Visual Studio Code）やIntelliJ IDEAなどの「コードを書くためのソフト（IDE）」に組み込んで使います。

### ☁️ AWSクラウド認証情報（クラウドクレデンシャル）とは？
AWSのサービスにアクセスするための「鍵」のことです。例えるなら、**クラウド上のサーバーや保存データへの入館証**のようなもの。これが盗まれると、攻撃者がその会社のクラウド環境に入り込めてしまいます。

### 📦 GitリポジトリとGit cloneとは？
- **リポジトリ（repo）**：プログラムのソースコードや設定ファイルをまとめて保管している「フォルダ」のようなもの
- **git clone**：そのフォルダをインターネットからダウンロードすること。GitHubなどで公開されているコードを自分のPCにコピーする操作です

### 🔌 MCP（Model Context Protocol）サーバーとは？
AIアシスタントが外部のツール（データベース、API、ビルドツールなど）と連携するための**仕組み（プロトコル）**です。AIが「このコマンド実行して」「このファイル読んで」と依頼するための橋渡し役、と考えてください。MCP**サーバー**はそれを実際に処理するプログラムで、パソコン上でローカル（自分のPC内）に起動します。

## 何が起きたのか

### 🚨 一言でいうと
> **「怪しいコードリポジトリをダウンロードして開くだけで、自分のAWSクラウドの鍵を盗まれる可能性があった」** という深刻な脆弱性が発見されました。

### 時系列まとめ

| 日付 | 出来事 |
|------|--------|
| 2025年4月20日 | セキュリティ企業「Wiz Research」がAmazonに脆弱性を報告 |
| 2025年5月12日 | Amazonが修正パッチをリリース |
| 2025年6月26日 | 脆弱性の詳細が公開される |

- **CVE番号**：CVE-2026-12957（セキュリティ問題の管理番号）
- **深刻度**：CVSS スコア **8.5 / 10**（「高」レベル）
- **現在の状況**：すでにパッチ（修正）済み。悪用された事例は確認されていない

## 技術的な詳細

### 🎯 攻撃の流れ（ステップ・バイ・ステップ）

攻撃がどのように成立するか、図解しながら説明します。

```
【攻撃の流れ】

① 攻撃者が悪意ある設定ファイルを仕込んだリポジトリを用意
        ↓
② 開発者が何も知らずに git clone（ダウンロード）
        ↓
③ IDEでそのフォルダを開く → 「ワークスペースを信頼しますか？」と聞かれてYes
        ↓
④ Amazon Q が .amazonq/mcp.json（設定ファイル）を自動で読み込む
        ↓
⑤ 設定ファイルの指示通りに悪意あるMCPサーバーが起動（=コマンド実行！）
        ↓
⑥ MCPサーバーが開発者のAWS認証情報を丸ごと入手
        ↓
⑦ 盗んだ認証情報を攻撃者のサーバーに送信 💀
```

### 🔑 なぜ認証情報が盗めたの？

MCPサーバーは、起動したときに**開発者のパソコンの「環境変数」を引き継ぎます**。

「環境変数」とは、パソコンの中にひっそり保存されている設定情報のことで、ここにはAWSの鍵（APIキー、CLIトークン）やSSHの秘密情報などが含まれています。

MCPサーバーが起動するということは、それらすべてにアクセスできるプログラムが動き出すことと同じ意味です。

### 🧪 実際の攻撃実証（PoC）

Wiz Researchが証明した方法は非常にシンプルでした：

```bash
# 悪意ある設定ファイルが実行したコマンドの例
aws sts get-caller-identity
# → 現在使っているAWSアカウント情報を取得して、攻撃者のサーバーに送信
```

これによって攻撃者は開発者の**ライブ（有効な）AWSセッション**を丸ごと奪えてしまいます。

### 🚪 パッチ（修正）前後の違い

| 修正前 | 修正後 |
|--------|--------|
| 設定ファイルを読んで自動でMCPサーバーを起動 | 信頼されていないMCPサーバーを検出したら警告を表示 |
| MCPサーバー個別の確認ステップなし | 開発者が「実行してよいか」を明示的に承認する必要あり |

## なぜ重要なのか

### 💥 被害が連鎖する危険性

AWSの認証情報が盗まれると、攻撃者はそこからさらに多くのことができてしまいます：

1. **IAMバックドアの作成**：「こっそり裏口ユーザー」を作って、パスワードを変えられても侵入し続ける
2. **内部サービスへのアクセス**：会社の内部システムやデータベースへの侵入
3. **本番環境への到達（ピボット攻撃）**：開発環境から本番（実際に動いているサービス）環境へ移動
4. **大量のクラウドリソースの悪用**：仮想通貨マイニングや大量メール送信などによる巨額課金

### 👩‍💻 誰が影響を受けたか

- Amazon Q Developerを使っている**すべての開発者**
- 具体的には、以下のIDEユーザー全員が対象：
  - **VS Code**（世界で最も使われているコードエディタの一つ）
  - **JetBrains**（IntelliJ IDEAなど）
  - **Eclipse**
  - **Visual Studio**

### 📊 深刻度：CVSS 8.5の意味

CVSSスコアは脆弱性の深刻度を0〜10で表すスケールです：

```
0   2   4   6   8   10
|---|---|---|---|---|
低  低  中  高  高  致命的
               ↑
           今回はここ（8.5）
```

「ユーザーがワークスペースを信頼する」という1アクションだけで成立するため、非常に危険な分類です。

## 対策・今後の展望

### ✅ すぐにやること：アップデート！

修正済みバージョンに更新してください。AWSは **Language Servers for AWS 1.69.0** への更新を推奨しています。

| IDE | 安全なバージョン |
|-----|----------------|
| VS Code | **2.20以降** |
| JetBrains | **4.3以降** |
| Eclipse | **2.7.4以降** |
| Visual Studio | **1.94.0.0以降** |

> 💡 **自動更新について**：ネットワークがブロックしていない限り、言語サーバーは自動でアップデートされます。IDEを再起動すると最新版が適用されます。

### 🔍 もう一つの脆弱性（CVE-2026-12958）も同時修正

今回のアップデートでは、もう一つの問題も修正されました：

- **CVE-2026-12958**：シンボリックリンク（ファイルへのショートカット）のチェックが不十分で、ワークスペースの外に任意のファイルを書き込める可能性があった

### 🛡️ 開発者として心がけること

1. **知らないリポジトリを安易に信頼しない**：`git clone`してIDEで開くとき、「ワークスペースを信頼しますか？」の確認はしっかり考えてからYesを押す
2. **IDE・拡張機能は常に最新版に保つ**
3. **.amazonq/mcp.json の中身を確認する習慣**をつける

## 過去記事との関連

今回の問題は、**Amazon Q Developer固有の一度限りの事故ではなく、AIコーディングツール全体に広がるパターン**として注目されています。

記事でも触れられているように、他のAIツールでも同様の脆弱性が相次いで発見されています：

| ツール | CVE番号 | 問題の概要 |
|--------|---------|-----------|
| **Claude Code** | CVE-2025-59536 | プロジェクトレベルのMCP設定からコマンド実行 |
| **Cursor** | CVE-2025-54136 | 同上 |
| **Windsurf** | CVE-2026-30615 | 攻撃者制御のコンテンツがMCP設定を書き換えて悪意あるサーバーを登録 |

つまり「**プロジェクトのフォルダにある設定ファイルがAIエージェントの動作を制御できる**」という便利な機能が、そのままセキュリティの弱点になっているのです。

> 🔑 **核心的な教訓**：リポジトリの中の設定ファイルは「信頼できない外部からの入力」です。それをそのままプログラムの実行につなげるときは、必ず明示的な「本当にやっていいですか？」の確認ステップが必要です。

## 用語解説

| 用語 | 意味 |
|------|------|
| **CVE（Common Vulnerabilities and Exposures）** | セキュリティ上の脆弱性・欠陥に付けられる管理番号。CVE-年-番号の形式 |
| **CVSS スコア** | 脆弱性の深刻度を0〜10点で評価する共通基準。8〜10が「高〜致命的」 |
| **リポジトリ（repo）** | ソースコードや設定ファイルを管理・保存する場所 |
| **git clone** | リポジトリをインターネットから自分のPCにダウンロードする操作 |
| **MCP（Model Context Protocol）** | AIアシスタントが外部ツールと連携するためのプロトコル（通信規格） |
| **AWS認証情報（クレデンシャル）** | AWSクラウドサービスにアクセスするための鍵（APIキーやトークンなど） |
| **環境変数** | OSが保持している設定値の集まり。認証情報やパスなどが入っていることが多い |
| **IAM（Identity and Access Management）** | AWSにおけるユーザーやアクセス権限を管理する仕組み |
| **PoC（Proof of Concept）** | 脆弱性が本当に悪用できることを実証するためのデモコード |
| **シンボリックリンク（symlink）** | ファイルやフォルダへのショートカット（別名・参照）。悪用されると想定外の場所にアクセスされることがある |
| **IDE（統合開発環境）** | コードを書くための高機能エディタ。VS CodeやIntelliJ IDEAなど |
| **パッチ** | ソフトウェアの不具合や脆弱性を修正するための更新プログラム |
| **ピボット攻撃** | 一つの侵入口を起点に、そこから別のシステムへ次々と侵入を広げる攻撃手法 |

---

> 📝 **まとめると**：AIコーディングツールはとても便利ですが、「信頼していないコードをダウンロードして開く」という日常的な開発作業がそのまま攻撃経路になり得ます。ツールを最新版に保ち、見知らぬリポジトリを不用意に信頼しないことが、自分と会社を守る第一歩です。
