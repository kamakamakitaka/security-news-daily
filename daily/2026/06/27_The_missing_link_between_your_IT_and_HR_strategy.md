## 背景知識

まず、この記事のタイトルにある **「IT」** と **「HR」** という2つの言葉を理解しましょう。

| 用語 | 正式名称 | 意味 |
|------|----------|------|
| **IT** | Information Technology | 情報技術。パソコン・ネットワーク・システムの管理など |
| **HR** | Human Resources | 人事部門。採用・退職・異動などの人員管理 |

### なぜこの2つが関係するの？

会社の中では、**人の動き（HR）とシステムのアクセス権（IT）は密接に連動しています**。

たとえば、こんな場面を想像してみてください：

```
👤 田中さんが入社した
  → HR部門が採用を決定
  → IT部門がパソコン・メールアカウント・社内システムを用意

👤 鈴木さんが退職した
  → HR部門が退職手続きを処理
  → IT部門がすべてのアクセス権を削除 ← ⚠️ここが問題になりやすい！
```

この **「HR部門がやること」と「IT部門がやること」の連携がうまくできていないと、セキュリティの大きな穴になる** のです。

---

## 何が起きたのか

この記事は、特定の「事件」ではなく、**多くの企業が抱える構造的な問題**を指摘しています。

### 典型的な問題シナリオ

```
😱 よくある危険な状況の例

1. 社員が退職したのに、アカウントが生き続けている
   → 元社員が外部から会社のシステムに不正アクセスできる状態

2. 部署異動したのに、以前の部署のファイルも見られる
   → 不必要な情報にアクセスできてしまう（「最小権限の原則」違反）

3. 派遣・アルバイトが終了したのに、システムへのアクセスが残っている
   → 気づかれにくく、長期間放置されやすい
```

これらはすべて、**HR（人事）とIT（システム管理）の情報共有が遅れたり、漏れたりすること**で起きます。

## 技術的な詳細

### 「アクセス権管理」って何？

アクセス権とは、「誰が・何を・どこまで使えるか」を決めるルールのことです。

学校で例えると：

```
🏫 学校のシステムに例えると...

・校長先生 → すべての部屋のカギを持っている
・先生      → 職員室・自分の教室のカギを持っている
・生徒      → 自分のロッカーのカギだけ持っている

もし卒業した先輩のカギが返却されていなかったら？
→ 卒業後もこっそり学校に入れてしまう！
```

### IT×HR連携の理想的な仕組み（Identity Lifecycle Management）

```
[入社]
HR系システムで採用決定
      ↓ 自動連携
ITシステムがアカウント作成・権限付与

[異動]
HR系システムで部署変更
      ↓ 自動連携
ITシステムが権限を更新

[退職]
HR系システムで退職処理
      ↓ 自動連携（即日！）
ITシステムが全アクセスを無効化 ✅
```

このような自動連携の仕組みを **「IDライフサイクル管理」** と呼びます。

## なぜ重要なのか

### 数字で見るリスク

セキュリティの世界では、こんな統計がよく報告されています：

- **内部不正・元社員による不正アクセス**は、セキュリティインシデントの大きな原因のひとつ
- 退職した社員のアカウントが残っている期間は、平均で**数週間〜数ヶ月**に及ぶケースも
- アクセス権の棚卸しを**定期的にやっている企業は少数派**

### なぜ連携が難しいの？

```
HR部門の言い分：
「退職の手続きは複雑で、IT部門への通知まで手が回らない」

IT部門の言い分：
「HR部門から連絡が来ないと、誰が辞めたかわからない」

→ 両者の間に"落とし穴"ができる
```

これが記事タイトルの **「Missing Link（欠けているつながり）」** です！

## 対策・今後の展望

### 今すぐできる対策

#### 🔑 企業レベルでの対策

| 対策 | 内容 |
|------|------|
| **SSOの導入** | Single Sign-On（シングルサインオン）。一か所でアカウントを無効化すれば、全サービスへのアクセスが止まる |
| **自動プロビジョニング** | HR情報が更新されたら、ITシステムも自動的に更新される仕組み |
| **定期的なアクセス権レビュー** | 四半期ごとなど定期的に「誰が何にアクセスできるか」を確認する |
| **オフボーディングチェックリスト** | 退職時の手順を標準化し、漏れをなくす |

#### 💡 個人でも意識できること

```
✅ 退職・転職するとき：
会社のアカウントで個人的な情報を保存しない
（逆に言うと、会社は即座にアクセスを止める権利がある）

✅ 職場のシステムを使うとき：
「なぜ自分はこのシステムにアクセスできるのか」を意識する
不要なアクセス権は返上することが理想的
```

### 今後のトレンド

最近は **「IAM（Identity and Access Management：アイデンティティとアクセスの管理）」** というツールが注目されています。これはHRとITを自動でつなぐ橋渡し役になる技術です。

## 用語解説

| 用語 | わかりやすい説明 |
|------|----------------|
| **HR（Human Resources）** | 人事部門。採用・退職・異動など「人」を管理する部門 |
| **IT（Information Technology）** | 情報技術。社内のパソコンやシステムを管理する部門 |
| **アクセス権** | 「誰がどのシステム・ファイルを使えるか」の許可 |
| **SSO（シングルサインオン）** | 1回のログインで複数のサービスを使える仕組み。無効化も一括でできる |
| **プロビジョニング** | アカウントや権限を自動的に作成・変更・削除すること |
| **IAM** | Identity and Access Management。誰が何にアクセスできるかを一元管理する仕組み |
| **オフボーディング** | 社員が退職するときの手続き全般（入社時は「オンボーディング」） |
| **最小権限の原則** | 仕事に必要な最低限のアクセス権だけを与えるというセキュリティの考え方 |
| **IDライフサイクル管理** | 社員のアカウントを入社から退社まで一貫して管理する仕組み |

## まとめ

> 🎯 **一言でまとめると**
> 
> 「人事部門（HR）とIT部門が連携できていないと、退職した社員のアカウントが残り続けてセキュリティの穴になる。これを防ぐには、人の動きとシステムのアクセス権を自動でつなぐ仕組みが必要」

セキュリティというと「ウイルス対策」や「パスワード管理」が思い浮かびがちですが、実は**「誰が・いつ・何にアクセスできるか」という人の管理**もとても重要なのです。
