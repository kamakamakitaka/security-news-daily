# 今のデータの動き方に、多くのシステムはついていけていない

**元記事**: [Most Systems Weren't Designed For How Data Moves Today](https://inl03.netline.com/ltr6/?_m=3n.009a.4016.sp0ao46r89.32ja)
**解説日**: 2025年7月14日

## 背景知識

### 昔のシステムとデータの動き方

少し前まで、会社や組織のデータは「**社内のサーバー**」という一つの場所にまとめて保管されていました。

🏢 **昔のイメージ**：
```
社員のパソコン → 社内ネットワーク → 社内サーバー（一か所に全データ）
```

この構造であれば、「社内ネットワークへの入り口さえ守れば、データは安全」という考え方が成り立ちました。まるで**お城の城壁を守れば中は安全**、という発想です。

---

### 今のデータの動き方（これが大きく変わった！）

しかし今は、データがあちこちに散らばって動き回っています。

☁️ **今のイメージ**：
```
社員のスマホ
  ↕
社員の自宅PC  →  クラウドサービスA（例：Google Drive）
  ↕                    ↕
社員のオフィスPC →  クラウドサービスB（例：Salesforce）
                        ↕
                   外部の取引先システム
                        ↕
                   AIサービス（ChatGPTなど）
```

データが**クラウド**（インターネット上のサービス）、**スマホ**、**テレワーク環境**、**外部パートナー**など、様々な場所を行き来するようになりました。

これを「**データの分散化**」と呼びます。

---

## 何が起きたのか

### 問題の核心：「昔の設計のまま使い続けているシステム」が危ない

多くの企業・組織では、**10〜20年前に設計されたシステム**をそのまま使い続けています。

当時の設計者たちは、まさか：
- 社員が自宅から会社のデータにアクセスするとは思っていなかった
- データがAIサービスに送られるとは思っていなかった
- スマホで機密情報を扱うとは思っていなかった

…わけです。

その結果、**古い設計のシステムが、現代の複雑なデータの流れに対応できず、セキュリティの「穴」が生まれている**という問題が起きています。

### 具体的にどんな「穴」があるの？

| 昔の想定 | 今の現実 | 生まれる問題 |
|---------|---------|-------------|
| 社内からしかアクセスしない | 自宅・カフェ・海外からもアクセス | 誰がアクセスしているか確認が難しい |
| データは社内サーバーにある | クラウドにある | 管理の責任範囲が曖昧になる |
| 人間だけがデータを扱う | AIも自動でデータを読み書きする | AIが何をしているか把握できない |
| アクセスする端末は会社支給PC | 個人スマホでもアクセス | セキュリティ設定がバラバラ |

## 技術的な詳細

### 🔑 キーワード①：「境界型セキュリティ」の限界

昔のセキュリティは「**境界型（ペリメーター型）**」と呼ばれるものでした。

```
【昔の考え方】
外の世界 | 城壁（ファイアウォール） | 安全な社内
         ←ここさえ守れば大丈夫→
```

**ファイアウォール**（防火壁）とは、不正なアクセスを遮断するシステムのこと。

でも今は「城壁の外にもデータがある」状態なので、城壁を守るだけでは意味がなくなっています。

---

### 🔑 キーワード②：「ゼロトラスト」という新しい考え方

そこで生まれたのが「**ゼロトラスト（Zero Trust）**」という概念。

> 「誰も信用しない。常に確認する」

という考え方です。

```
【新しい考え方：ゼロトラスト】
アクセスのたびに確認：
  「本当にあなた？」（本人確認）
  「このデータ、見ていいの？」（権限確認）
  「この端末、安全？」（デバイス確認）
```

社内からのアクセスでも、社外からのアクセスでも、**毎回同じように厳しくチェック**します。

---

### 🔑 キーワード③：データが「見えない」問題

今、多くの企業で深刻なのが「**シャドーIT**」と呼ばれる問題です。

**シャドーIT**とは：会社が許可していないアプリやサービスを、社員が勝手に使うこと。

例えば：
- 「LINEで取引先に資料を送っちゃえ」
- 「ChatGPTに会社の資料を貼り付けて要約させよう」
- 「個人のDropboxに仕事のファイルを保存しておこう」

これをやられると、**データがどこにあるか会社側が把握できなくなります**。

---

## なぜ重要なのか

### 📊 影響を受ける範囲は？

これは特定の会社だけの問題ではありません。**ほぼすべての企業・組織**が直面している課題です。

特に影響が大きいのは：

- 🏥 **医療機関**：患者の個人情報が多く、昔のシステムを使い続けているところが多い
- 🏦 **金融機関**：古い基幹システムが多く、クラウド化が遅れている
- 🏫 **学校・大学**：コロナ以降、急にオンライン化が進み、セキュリティが追いついていない
- 🏛️ **行政機関**：古い法律や規制の縛りで、システム更新が難しい

### 実際に起きた事故の例（イメージ）

```
① 社員がクラウドサービスに会社の資料をアップロード
        ↓
② そのクラウドサービスのセキュリティ設定が甘かった
        ↓
③ 誰でもアクセスできる状態になっていた
        ↓
④ 顧客の個人情報が漏えい！
```

このような事故が、世界中で頻繁に起きています。

---

## 対策・今後の展望

### ✅ 企業・組織がとるべき対策

**① データの「地図」を作る（データマッピング）**
- 「自社のデータが今どこにあるか」を全部把握する
- どのデータが重要か分類する

**② ゼロトラストの導入**
- アクセスのたびに本人確認・権限確認を行う
- 「社内だから安全」という考えを捨てる

**③ データの暗号化**
- データを**暗号化**（特定の鍵がないと読めない状態にする）して保存・送信する
- 万が一盗まれても読めない状態にする

**④ 社員への教育**
- 「シャドーIT」の危険性を教える
- セキュリティを「面倒なもの」ではなく「必要なもの」として理解してもらう

### 🔮 今後の方向性

```
現在の課題              →    目指す姿
-------------------------------------------
データがどこにあるか    →    リアルタイムで把握できる
不正アクセスに気づくのが遅い → AIが自動で異常を検知
人間が設定ミスをする    →    自動で安全な設定を維持
```

特に**DSPM（Data Security Posture Management）**と呼ばれる、データのセキュリティ状態を自動で管理する技術が注目されています。

## 用語解説

| 用語 | 意味 |
|------|------|
| **クラウド** | インターネット上にあるサーバーやサービス全般（Google Drive、AWSなど） |
| **ファイアウォール** | 不正なネットワーク通信を遮断するシステム。「防火壁」とも呼ぶ |
| **境界型セキュリティ** | 社内と社外の「境界」を守ることでセキュリティを確保する昔ながらの考え方 |
| **ゼロトラスト** | 「誰も信用しない」を前提に、常にアクセスを検証するセキュリティの考え方 |
| **シャドーIT** | 会社が許可していないアプリ・サービスを社員が業務で使うこと |
| **暗号化** | データを特殊な方法で変換し、鍵がないと読めない状態にすること |
| **データマッピング** | 自社のデータがどこにあるかを把握・整理すること |
| **DSPM** | データのセキュリティ状態を自動で管理・監視する技術 |
| **基幹システム** | 企業の業務の中心となる重要なシステム（会計、販売管理など） |
| **エンドポイント** | ネットワークに接続されるPCやスマホなどの端末のこと |

---

> 💡 **まとめ**：データが「一か所にある」時代は終わり、「あちこちに散らばって動く」時代になりました。でも多くのシステムは昔の設計のまま。この「ズレ」がセキュリティの大きなリスクを生んでいます。大切なのは「データが今どこにあるか把握すること」と「どこからのアクセスも疑ってかかること」です。
