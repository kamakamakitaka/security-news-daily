# AirDropとQuick Shareの欠陥により、近くにいる攻撃者がクラッシュを引き起こしたりチェックを回避できる問題が発覚

**元記事**: [AirDrop and Quick Share Flaws Let Nearby Attackers Trigger Crashes and Bypass Checks](https://inl03.netline.com/ltr6/?_m=3n.009a.4017.sp0ao46r89.32ku)
**解説日**: 2025年7月1日

---

## 背景知識

まず、今回の記事を理解するために必要なキーワードを整理しましょう。

### AirDropとは？
AppleのiPhoneやMacなどに搭載されている「ファイルを無線で近くの人に送る機能」です。ケーブルも共通のWi-Fiも不要で、Bluetoothや独自の無線技術を使って写真や動画などを送ることができます。

### Quick Shareとは？
AndroidやWindowsに搭載されている、AirDropと同じような「近距離ファイル共有機能」です。Samsung（サムスン）のスマホや、GoogleのWindows用アプリに組み込まれています。

### 「クラッシュ」って何がまずいの？
ソフトウェアが「クラッシュ（crash）」するとは、プログラムが異常終了してしまうことです。アプリが強制終了するイメージです。意図的に引き起こせる場合、それは攻撃として悪用される可能性があります。

### 脆弱性（ぜいじゃくせい）とは？
ソフトウェアやシステムにある「セキュリティ上の穴」のことです。鍵のかかった家のドアに、こっそり開けられる隙間があるようなイメージです。

---

## 何が起きたのか

ドイツの研究機関「CISPA Helmholtz情報セキュリティセンター」の研究者2人（Arash Ale EbrahimさんとNils Ole Tippenhauer さん）が、**AirDropに3つ、Quick Shareに3つ、合計6つのセキュリティの欠陥**を発見しました。

ポイントをひとことで言うと：

> 📡 **近くにいるだけで（Wi-Fiやケーブル接続不要）、スマホやPCの共有機能を壊したり、セキュリティの仕組みを回避できる**

というものです。

現時点でこれらの欠陥が実際に悪用された報告はありませんが、50億台以上のApple・Androidデバイスに影響する可能性があるため、非常に重要な発見とされています。

## 技術的な詳細

### 🍎 AirDropの3つの欠陥

**共通の結果：** 3つとも「`sharingd`（シェアリングデーモン）」というバックグラウンドプログラムをクラッシュさせます。

> 💡 **`sharingd`とは？**
> Appleデバイスの裏側で静かに動いているプログラムで、AirDropだけでなく、**AirPlay（テレビへの映像送信）・Handoff（デバイス間の作業引き継ぎ）・Universal Clipboard（コピーの共有）・Continuity Camera（iPhoneをカメラとして使う機能）・NameDrop（名刺交換機能）** もすべて管理しています。つまり、これが落ちると関連機能がまとめて使えなくなります。

**欠陥①（最もシンプルな攻撃）：**
AirDropを「全員から受信」に設定しているデバイスに、**壊れた（不正な形式の）リクエストを約2秒に1回送り続けるだけ**で、AirDropを含む各種機能がずっと使えない状態にできます。正規のファイル転送もブロックされます。

**欠陥②・③（より広範な影響）：**
2つはAppleの共通部品（フレームワーク）にある欠陥で、中でも深刻なのが：

- **「スタックオーバーフロー」という種類のバグ**：200層ほど入れ子（ネスト）になったXMLファイルを送ると、データを処理する部品が破綻してクラッシュします。

> 💡 **スタックオーバーフローのたとえ話：**
> コンピュータが計算する作業をメモ帳に書き込んでいくイメージで、そのメモ帳（スタック）に書けないほどの量を詰め込もうとして、あふれてしまう（オーバーフロー）状態です。

この欠陥はAirDropだけでなく、**macOS・iOS・watchOS・tvOS・visionOSで動く、XMLファイルを開くあらゆるAppleアプリ**にも影響する可能性があります。

---

### 🤖 Quick Shareの3つの欠陥

**Samsung製Quick Shareの2つの欠陥：**

ファイルを安全に送受信するためには「ハンドシェイク（握手）」と呼ばれる、お互いを確認し合う手順が必要です。

> 💡 **ハンドシェイクのたとえ話：**
> 秘密のクラブに入るとき「合言葉は？」→「桜！」→「よし入れ」という確認手順のようなものです。

- **欠陥①：** 本人確認（認証）が終わる前に、確認されていないデバイスが接続を乗っ取れる
- **欠陥②：** 暗号化された通信が始まった後でも、一部の制御メッセージが**暗号化されずに**やり取りされてしまう

同じWi-Fiにつながった攻撃者がこれを利用すると、接続状態を操作したり、接続先のIPアドレス（インターネット上の住所）を偽のものに変えたりできます。

**Google製Quick Share for Windowsの欠陥（最も深刻）：**

- **「メモリの解放後使用（Use After Free）」というバグ**：2つの接続が同時に起きたとき、すでに捨てたはずのメモリ（記憶領域）を使い続けてしまう問題です。

> 💡 **たとえ話：** ゴミ箱に捨てた紙に書いてあったことを、まだ有効なメモとして読み込んでしまうようなイメージです。

さらに深刻なのが、Windowsにある「**Control Flow Guard（CFG）**」という防御機能がこのアプリでは**オフになっている**こと。この防御機能は、バグを悪用して攻撃者がプログラムの動きを乗っ取るのを防ぐものです。研究者たちは実際のクラッシュを確認しましたが、悪用するための完全な攻撃コードは作っていません。

## なぜ重要なのか

| 観点 | 内容 |
|------|------|
| **影響範囲** | Apple・Androidデバイス合計50億台以上 |
| **攻撃の簡単さ** | 近くにいるだけ、事前の接続不要 |
| **被害の種類** | サービス停止・セキュリティ回避・場合によっては乗っ取りの可能性 |
| **連鎖被害** | AirDrop以外の複数機能もまとめてダウン |

特に怖いのは「**何も操作していないのに攻撃される**」という点です。カフェや電車の中など、知らない人が近くにいる場所で、自分のデバイスの機能が突然止まる可能性があります。

## 対策・今後の展望

### 現時点での修正状況

| 対象 | 状況 |
|------|------|
| AirDropの欠陥①（1つ） | ✅ Appleがパッチ（修正プログラム）を配布済み・CVE番号も発行 |
| AirDropの欠陥②③（2つ） | 🔄 現在、調整中の開示（修正前に相談しながら公表する手順）の段階 |
| Quick Share for Windows | ✅ Googleが報奨金を支払い、修正コードも適用済み（CVE番号は未発行） |
| Samsung Quick Shareの2つ | 🔍 Googleに引き継がれ、調査中 |

> 💡 **CVEとは？**
> 「Common Vulnerabilities and Exposures」の略で、脆弱性に割り当てられる世界共通の識別番号です。「この脆弱性はCVE-XXXX-XXXXです」と言えば世界中で通じます。

### あなたができる対策

1. **AirDropの設定を見直す**
   - 「全員から受信」になっている場合は「連絡先のみ」または「受信しない」に変更する
   - 設定 → 一般 → AirDrop

2. **OSを最新にアップデートする**
   - AppleもGoogleも修正を進めているため、アップデートが最大の防御策

3. **不要なときはWi-FiやBluetoothをオフにする**
   - 攻撃には無線が必要なため、使わないときはオフにするだけでリスクを下げられます

## 用語解説

| 用語 | 説明 |
|------|------|
| **AirDrop** | Apple製デバイス間でファイルを無線送信する機能 |
| **Quick Share** | Android・Windows間でファイルを無線送信する機能 |
| **脆弱性** | ソフトウェアにあるセキュリティ上の穴 |
| **クラッシュ** | プログラムが異常終了すること |
| **sharingd** | AppleのAirDropなど共有機能を管理するバックグラウンドプログラム |
| **スタックオーバーフロー** | 処理用のメモリ領域があふれてしまうバグ |
| **ハンドシェイク** | 通信を始める前にお互いを確認し合う手順 |
| **Use After Free** | 解放済みのメモリを誤って使い続けるバグ |
| **Control Flow Guard (CFG)** | Windowsのバグ悪用を防ぐ防御機能 |
| **CVE** | 脆弱性に割り振られる世界共通の識別番号 |
| **パッチ** | 脆弱性を修正するプログラムの更新 |
| **バウンティ（報奨金）** | 脆弱性を報告した研究者にメーカーが支払う謝礼金 |
| **フレームワーク** | 複数のアプリが共通して使うソフトウェアの部品集 |
| **coordinated disclosure（調整中の開示）** | 修正が完了するまで、メーカーと相談しながら段階的に脆弱性を公表する手順 |
