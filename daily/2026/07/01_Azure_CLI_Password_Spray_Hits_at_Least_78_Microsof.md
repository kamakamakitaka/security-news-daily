# AzureのCLIを狙った大規模パスワード攻撃！8100万回以上の試行で78アカウントが乗っ取られた

**元記事**: [Azure CLI Password Spray Hits at Least 78 Microsoft Accounts in 81M+ Attempts](https://inl03.netline.com/ltr6/?_m=3n.009a.4018.sp0ao46r89.32mk)
**解説日**: 2026年7月8日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### 🏢 Microsoft Azure（マイクロソフト・アジュール）とは？
MicrosoftがインターネットのVer.2.0として提供する「クラウドサービス」です。企業がサーバーやデータをインターネット上で管理するためのプラットフォームで、世界中の多くの企業が業務で使っています。学校で例えるなら「全校生徒が使える巨大なオンラインストレージと計算機」のようなイメージです。

### 💻 Azure CLI（コマンドライン インターフェース）とは？
AzureをキーボードでコマンドをタイプしてAzureを操作するための「テキストベースの操作ツール」です。エンジニアや管理者がよく使います。スマホのアプリではなく、昔ながらの「文字で命令を入力する画面」と思ってください。

### 🔑 パスワードスプレー攻撃とは？
「パスワードを何度も試す攻撃」の一種ですが、少し特殊なやり方です。

- **普通のブルートフォース攻撃**: 1つのアカウントに対して、パスワードを何千回も試す
- **パスワードスプレー攻撃**: 「よく使われるパスワード（例：Password123）」を大量のアカウントに対して一斉に試す

後者のほうが「短期間に同じアカウントへの試行回数が少ない」ので、セキュリティシステムに検知されにくいという特徴があります。

### 🛡️ MFA（多要素認証）とは？
パスワードだけでなく、スマホへの通知確認など「複数の方法で本人確認をする仕組み」です。銀行アプリのログイン時にSMSで数字コードが届くのがその一例。パスワードが漏れても、スマホがなければログインできないため安全性が高まります。

## 何が起きたのか

2026年6月12日〜26日の約2週間、**Microsoftのクラウドサービス「Azure」を狙った大規模な自動攻撃**が発生しました。

📊 **被害の規模**
| 項目 | 数字 |
|------|------|
| ログイン試行回数 | **8100万回以上** |
| 乗っ取られたアカウント数 | **78件** |
| 被害を受けた組織数 | **64組織** |
| 最も多い1日の被害 | **6月22日：23社・30アカウント** |

攻撃は特定の業界を狙ったものではなく、**「過去に流出したパスワードのリスト」を使って手当たり次第に試した**ものとみられています。まるで「どこかの鍵に合う可能性のある合鍵を、とにかく全部の鍵穴に差し込んでいく」ようなイメージです。

## 技術的な詳細

### 🔓 ROPC（Resource Owner Password Credentials）とは？

今回の攻撃で最も重要なポイントが「**ROPC（ロック）**」という古い認証方式の悪用です。

**普通のログインの流れ（安全な方式）**
```
ユーザー → Microsoftのログイン画面 → パスワード確認 → MFA確認 → ログイン成功
```

**ROPCを使ったログインの流れ（古い方式）**
```
ユーザー → アプリに直接パスワードを入力 → アプリがMicrosoftに送信 → トークン発行 → ログイン成功
```

ROPCは「OAuth 2.0」という認証の仕組みの中の**古いやり方**で、現在はすでに「使うのを推奨しない（deprecated＝非推奨）」とされています。しかし、Azureのシステムはまだこの方式でのログインを受け付けているため、攻撃者に悪用されてしまいました。

**なぜROPCがまずいのか？**

ROPCの本質的な問題は、**MFAを「すり抜ける」可能性がある**という点です。

通常のMFAの設定は「Webブラウザでのログイン」や「特定のアプリ」を想定して設定されていることが多いです。ところがROPCという「古いルート」を使ったAzure CLIからのログインは、そのMFA設定の**「対象外」になってしまっているケース**がありました。

**家の鍵で例えると：**
> 「玄関の鍵（MFA）はしっかりかけたけど、裏口（Azure CLI経由のROPC）はそもそも鍵の対象外だった」という状態です。

### ⚠️ MFAをすり抜けた3つのパターン

1. **「特定のアプリのみ」にMFAを設定していた** → Azure CLIがその対象外だった
2. **「管理者のみ」にMFAを設定していた** → 一般ユーザーは対象外だった
3. **「社外からのアクセスのみ」にMFAを設定していた** → 特定の条件下で適用されなかった

また、**8社はMFAが全く設定されていなかった**ことも明らかになっています。

## なぜ重要なのか

### 📈 攻撃の規模が桁違い
セキュリティ企業Huntressによると、この種の攻撃は**前と比べて155倍以上に急増**しています。月あたり平均約1,964回の失敗した攻撃が1つの組織に対して行われているというデータも出ています。

### 🏢 「MFAを設定していたのに被害にあった」企業が多い
「MFAを設定しているから安心」と思っていた企業でも被害が出た点が今回の特に重大なポイントです。**セキュリティ設定に「穴」があった**ことが明らかになりました。

### 🔍 古いパスワードが狙われた
攻撃で使われたのは「**過去にどこかから流出したパスワードのリスト**」です。何年も前に別のサービスで流出したパスワードを、ずっと変えていない場合に危険です。「使い回しパスワード」や「昔から変えていないパスワード」がいかに危険かを示しています。

## 対策・今後の展望

セキュリティ企業Huntressは以下の対策を推奨しています。

### ✅ 企業・組織向けの具体的な対策

**① MFAを「全員・全アプリ・全接続方法」に適用する**
> 「特定の人だけ」「特定のアプリだけ」ではなく、**全ての条件で** MFAを要求するよう設定を見直す。

**② ROPCフローをブロックする**
> Azure CLIのROPCを使ったログインを、条件付きアクセスポリシーで明示的にブロックする。

**③ 古いパスワードを使い回さない・定期的に変更する**
> 流出パスワードリストに載っているものが狙われるため、過去に別サービスで使ったパスワードの使い回しは絶対NG。

### 👦 一般の人・高校生でもできる対策

| 対策 | 具体的な行動 |
|------|------------|
| パスワードの使い回しをやめる | サービスごとに異なるパスワードを設定 |
| MFAを設定する | Google、Microsoft、SNSなど全てで有効化 |
| パスワードマネージャーを使う | 複雑なパスワードを安全に管理 |
| 流出確認サービスを使う | [HaveIBeenPwned](https://haveibeenpwned.com/) などで自分のメールが流出していないか確認 |

## 用語解説

| 用語 | 意味 |
|------|------|
| **Azure** | Microsoftが提供するクラウドサービス |
| **CLI（コマンドライン インターフェース）** | テキストコマンドでコンピュータを操作するツール |
| **パスワードスプレー攻撃** | よく使われるパスワードを大量のアカウントに試す攻撃 |
| **MFA（多要素認証）** | パスワード＋スマホ確認など、複数の方法で本人確認する仕組み |
| **OAuth（オーオース）** | アプリがユーザーの代わりに認証するための標準的な仕組み |
| **ROPC** | OAuthの古い認証方式。パスワードをアプリに直接渡す |
| **deprecated（非推奨）** | 「もう使わないでください」と公式に宣言された古い機能 |
| **Conditional Access Policy（CAP）** | 「どんな条件でアクセスを許可するか」を定めるセキュリティルール |
| **アクセストークン** | 「ログイン済みです」を証明するデジタルの通行証 |
| **IPv6** | インターネット上の住所（IPアドレス）の新しい形式 |
| **ASN（自律システム番号）** | インターネット上のネットワークに割り当てられた番号 |
| **クレデンシャル** | ログインに使うID・パスワードなどの認証情報 |

---
