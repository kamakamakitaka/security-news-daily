# AIエージェントには「身元管理の仕組み」が対応できていない

**元記事**: [Identity Lifecycle Management Wasn't Built for AI Agents](https://inl03.netline.com/ltr6/?_m=3n.009a.4019.sp0ao46r89.32n4)
**解説日**: 2025年7月

---

## 背景知識

まず、この記事を理解するために必要な基本的な考え方を整理しましょう。

### 「IDライフサイクル管理」って何？

会社で働く人を想像してください。

1. **入社するとき** → 会社のパソコン、メール、各種システムへのアクセス権が与えられる
2. **部署が変わるとき** → アクセスできるシステムが変わる
3. **退職するとき** → すべてのアクセス権が削除される

この「入社→異動→退職」に合わせてシステムへのアクセス権を管理することを「**IDライフサイクル管理**（Identity Lifecycle Management）」と呼びます。

図で表すと：

```
入社(Joiner) → 異動(Mover) → 退職(Leaver)
   ↓               ↓              ↓
アクセス付与   アクセス変更   アクセス削除
```

### 「AIエージェント」って何？

最近、企業の中で「AIエージェント」と呼ばれる**自律的に動くAIプログラム**が急増しています。

- ChatGPTのようなAIが、メールを送ったり、データを集めたり、システムを操作したりする「自動で動く仕組み」
- 人間の代わりに仕事をするので、**会社のシステムにアクセスする権限が必要**
- でも…AIには「入社日」も「上司」も「退職日」もありません

> 🎭 **例え話**: 会社に「幽霊社員」が現れたようなイメージです。勝手にシステムを使えるのに、社員名簿には載っていない存在です。

## 何が起きたのか

この記事は、**企業のセキュリティ専門家に向けた警告レポート**です。

具体的に指摘されている問題は：

**「今の身元管理の仕組みは、AIエージェントのことを全く考えて作られていない」**

というものです。

従来の管理システム（IGA：Identity Governance and Administration ＝ 身元管理・統制ツール）は、以下を前提として設計されています。

| 前提 | 内容 |
|------|------|
| ✅ 人間がいる | 必ず「人」が紐付いている |
| ✅ 人事記録がある | 入社日・役職・部署が記録されている |
| ✅ 上司がいる | 誰かが責任を持つ |
| ✅ 退職日がある | いつかアクセス権が削除される |

しかし、AIエージェントには**これらが一切ない**のです。

---

## 技術的な詳細

### 従来の仕組みはどう動いているか

人間の場合、こんな流れで管理されます：

```
人事システム(Workday等)
      ↓ 「山田さんが入社しました」
Active Directory(認証システム)
      ↓ アカウント作成
各種業務システム
（メール・ファイル共有・ERPなど）
```

- **Workday/SAP SuccessFactors**：大企業が使う人事管理システム（社員の情報を一元管理）
- **Active Directory**：Windowsの「社員証発行機」のようなもの。誰がどこにアクセスできるかを管理する
- **IGA（統合ガバナンスツール）**：全体を監視して、「この人はこのシステムを使っていいか」を判断するセキュリティ管理ツール

### AIエージェントの場合、何が問題なのか

AIエージェントは**人事システムを通らずに生まれます**。

```
エンジニアがコードを書く
      ↓
自動デプロイパイプライン（CI/CDツール）
      ↓
いきなり本番環境でシステムにアクセスし始める
      ↓
人事記録？上司？退職日？→ 全部ない！
```

> 🔍 **具体的な問題点**
> 
> - **誰が作ったか不明確**: エンジニアが試しに作ったAIが、そのまま動き続けることがある
> - **アクセス権の見直しができない**: 「上司が承認する」という仕組みが使えない（上司がいないから）
> - **削除のタイミングがわからない**: 退職日がないので、いつアクセス権を消せばいいかわからない
> - **監査ログが追えない**: 何かあったとき、「誰の責任か」が特定できない

## なぜ重要なのか

### 🚨 セキュリティ上のリスク

**1. 「幽霊アカウント」問題**
AIエージェントが持つアクセス権は、誰も気づかないまま残り続ける可能性があります。これは攻撃者に悪用される「抜け穴」になります。

**2. 法律・規制への違反リスク**
- **SOX法**（企業の不正を防ぐアメリカの法律）
- **HIPAA**（医療情報の保護に関する法律）
- **PCI DSS**（クレジットカード情報の保護基準）

これらの規制は「誰がどのシステムにアクセスしたか証明できること」を求めています。AIエージェントの管理ができていないと、**監査で失格になる**可能性があります。

**3. AIエージェントは急増している**

> 🏢 今や大企業では、**AIエージェントの数が人間の社員数を超える**ケースも出てきています。管理できないIDが爆発的に増えているのです。

## 対策・今後の展望

記事では直接的な対策方法も示唆されています。現在のセキュリティ専門家が考えるべきことをまとめます。

### ✅ 今すぐできること

**1. AIエージェントの棚卸しをする**
- 自社の環境にどんなAIエージェントが存在するか把握する
- 「AIエージェント台帳」を作る（人間の社員名簿と同じように）

**2. 「オーナー」を決める**
- AIエージェントにも必ず「責任を持つ人間」を設定する
- 例：「このAIは○○チームの△△さんが管理者」

**3. アクセス権を最小限にする（最小権限の原則）**
- AIエージェントには「必要最小限のアクセス権だけ」を与える
- 人間なら「入社してすぐ全権限」はありえないですよね？AIも同じ

### 🔮 今後の展望

- 既存のIGAツール（SailPoint、Saviynt等）がAIエージェント対応の機能を追加し始めている
- **「AIエージェント専用のIDガバナンス」**という新しい分野が生まれつつある
- セキュリティ業界全体で「AIのID管理」の標準ルール作りが急務になっている

AIセキュリティの分野では、以前から「AIに与える権限をどう管理するか」という議論が続いています。今回の記事はその議論が「実際の企業システム管理」という具体的なレベルまで降りてきたことを示しており、**AI活用が進む企業にとってより身近な問題**になってきたことを意味しています。

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **IDライフサイクル管理** | - | 社員のアカウントを「入社〜退社」まで管理する仕組み |
| **IGA** | アイジーエー | Identity Governance and Administration。ID管理・統制ツールの総称 |
| **AIエージェント** | - | 自律的に判断して行動するAIプログラム |
| **Active Directory** | アクティブディレクトリ | Microsoftのアカウント・アクセス権管理システム |
| **Workday / SAP SuccessFactors** | - | 大企業向け人事管理クラウドサービス |
| **プロビジョニング** | - | アカウントやアクセス権を「作って与える」こと |
| **デプロビジョニング** | - | アカウントやアクセス権を「削除する」こと |
| **RBAC** | アールバック | Role-Based Access Control。役割に応じてアクセス権を決める方式 |
| **SOX法** | ソックスほう | 企業の財務情報の正確性を保証するアメリカの法律 |
| **HIPAA** | ヒパー | 医療情報の取り扱いに関するアメリカの法律 |
| **PCI DSS** | ピーシーアイディーエスエス | クレジットカード情報保護の国際基準 |
| **最小権限の原則** | - | 必要最小限のアクセス権だけを与えるセキュリティの基本原則 |
| **Joiner/Mover/Leaver** | ジョイナー/ムーバー/リーバー | 入社/異動/退社。IDライフサイクルの3つの主要イベント |

---

> 💡 **まとめ**: AIがどんどん「会社のシステムを使う存在」になっているのに、セキュリティの仕組みはまだ「人間専用」のまま。これは今後の企業セキュリティの大きな課題です。AIを使う便利さと、セキュリティを守ることのバランスが問われています。
