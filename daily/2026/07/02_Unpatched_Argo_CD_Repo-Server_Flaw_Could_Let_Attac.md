# パッチなしの重大欠陥：Argo CDの脆弱性でKubernetesクラスター全体が乗っ取られる危険性

**元記事**: [Unpatched Argo CD Repo-Server Flaw Could Let Attackers Take Over Kubernetes Clusters](https://inl03.netline.com/ltr6/?_m=3n.009a.4019.sp0ao46r89.32o4)
**解説日**: 2026年7月3日

---

## 背景知識

まず、この記事を理解するための基礎知識を整理しましょう。難しい言葉が多いですが、順番に説明します。

### 🏗️ Kubernetesとは？

**Kubernetes（クバネティス）** とは、たくさんのアプリケーション（プログラム）を大量のサーバー上で自動的に管理・動かすための仕組みです。

> 🏢 **例え話**：大きなビルの「管理システム」だと思ってください。「どの部屋（サーバー）でどのテナント（アプリ）を動かすか」を自動的に調整してくれます。大企業やクラウドサービスでよく使われています。

Kubernetes内では、アプリは **「Pod（ポッド）」** という単位で動いています。Podとは、アプリの「最小の実行単位」です。

### 🚀 Argo CDとは？

**Argo CD** は、Kubernetesにアプリを「自動でデプロイ（配置・展開）」するためのツールです。

> 🍱 **例え話**：「お弁当の自動配達システム」みたいなものです。「GitHubなどにある設計書（マニフェスト）を読んで、その通りにアプリを自動で並べてくれる」係です。世界中の多くの企業が使っている、非常に人気の高いツールです。

### 📁 repo-server（レポサーバー）とは？

Argo CDの中の部品のひとつで、**GitHubなどのリポジトリ（ファイルの保管場所）からデータを読み取り、設計書を作る担当**です。

### 🔒 認証（Authentication）とは？

「あなたは誰ですか？」と確認する仕組みです。ログインのID・パスワードがその典型例です。**認証なし＝誰でも入れてしまう状態**です。

## 何が起きたのか

セキュリティ調査会社の **Synacktiv（シナクティブ）** が、Argo CDの **repo-server（レポサーバー）** という部品に、**深刻な脆弱性（セキュリティの穴）** を発見しました。

### 🚨 問題のポイントをまとめると：

| 項目 | 内容 |
|------|------|
| 発見者 | Synacktiv社 |
| 報告時期 | 2025年1月 |
| 現在の状況 | **約18ヶ月経過してもパッチ（修正版）なし** |
| 深刻度 | Kubernetesクラスター全体の乗っ取りが可能 |
| CVE番号 | **なし**（まだ正式な脆弱性番号も未割り当て） |

Synacktivは2025年1月にArgo CDの開発者たちへ報告しましたが、**約1年半後の今も修正されていない**ため、ユーザーへの警告として詳細を公開しました。

> ⚠️ **これは非常に異例なことです**。通常、脆弱性は報告から数ヶ月以内に修正されます。18ヶ月もパッチが出ないのは深刻なサインです。

## 技術的な詳細

### 🔓 ステップ1：「鍵のかかっていないドア」を見つける

repo-serverの内部には **gRPC（ジーアールピーシー）** という通信サービスがあります。これが**完全に認証なし**、つまり「誰でも自由に話しかけられる状態」になっています。

> 🏠 **例え話**：会社の重要な部屋に、鍵も警備員もいない入口があるようなものです。

### 🎭 ステップ2：「Kustomize」という仕組みを悪用する

Argo CDは **Kustomize（カスタマイズ）** というツールを使って、リポジトリのファイルを設計書に変換します。

このKustomizeには `--helm-command` というオプションがあり、本来は「Helmというプログラムを呼び出す場所」を指定するものです。

攻撃者はこのオプションを悪用して、**攻撃者が用意した悪意あるスクリプト（プログラム）** に向け替えることができます。

```
本来の流れ：
リポジトリのファイル → Kustomize → Helm（正規のプログラム）→ 設計書

攻撃後の流れ：
リポジトリのファイル → Kustomize → 悪意あるスクリプト（攻撃者製）→ 🔥
```

### 🌐 ステップ3：「内部ネットワーク」はデフォルトで守られていない

「内部ネットワーク」と聞くと「外から入れないなら安全では？」と思いますよね。しかし、Argo CDをインストールする際によく使われる **Helmチャート（インストール用パッケージ）** では、ネットワークの壁（ネットワークポリシー）が**デフォルトでオフ**になっています。

つまり、クラスター内の**どこか1つのPodでも乗っ取られれば**、そこからrepo-serverに攻撃できてしまいます。

> 🏢 **例え話**：ビルの中に入れれば、鍵のない重要な部屋に誰でも入れてしまう状態です。

### 💣 ステップ4：Redisキャッシュを汚染する（最終的な乗っ取り）

repo-serverへのアクセスに成功した攻撃者は、次のような流れでクラスター全体を乗っ取れます：

```
① repo-serverのコードを実行
     ↓
② 環境変数からRedisのパスワードを盗む
     ↓
③ Redisキャッシュ（デプロイ情報の一時保存場所）に悪意あるデータを書き込む
     ↓
④ 次の自動同期タイミングで、Argo CDが攻撃者の用意したアプリを展開してしまう
     ↓
⑤ クラスター全体の乗っ取り完了 🔥
```

> 🧃 **例え話**：配達システムの「次に届けるリスト」を書き換えて、爆弾を配達させてしまうようなイメージです。

## なぜ重要なのか

### 📊 影響の大きさ

- **Argo CDは世界中の企業・組織で使われているツール**です。
- Kubernetesクラスターは、企業の重要なサービスやデータを動かしている心臓部です。
- 乗っ取られると、**全サービスの停止・データ盗難・改ざん**などが起きる可能性があります。

### 😰 特に怖い点

1. **認証不要**：ユーザー名もパスワードも不要で攻撃できる
2. **パッチなし**：現時点で修正版が存在しない
3. **デフォルト設定が危険**：多くの人が気づかず危険な設定のまま使っている
4. **過去の脆弱性が復活**：2024年に修正されたはずの欠陥（CVE-2024-31989）が再び悪用可能になっている

### 🔄 Argo CDの「繰り返すパターン」

記事では、Argo CDのセキュリティ問題が繰り返し起きていることも指摘されています：

| 時期 | 脆弱性 | 内容 |
|------|--------|------|
| 2024年 | CVE-2024-31989 | Redisにパスワードなし → キャッシュ汚染が可能 |
| 2025年9月 | CVE-2025-55190 | 読み取り専用トークンでGit認証情報が盗める |
| 2026年5月 | CVE-2026-42880 | 読み取り専用ユーザーがKubernetesの秘密情報を読める |
| 現在 | 未割当 | 認証なしでコード実行・クラスター乗っ取り |

## 対策・今後の展望

### ✅ 今すぐできる対策

**修正版がない今、できることは「ネットワークの壁を正しく設定すること」です。**

#### 1. ネットワークポリシーを有効にする

Argo CDには守りの仕組み（ネットワークポリシー）が用意されていますが、**Helmでインストールした場合はデフォルトでオフ**になっています。手動でオンにする必要があります。

#### 2. 現在の設定を確認する

以下のコマンドで確認できます（Kubernetesの管理者向け）：

```bash
kubectl get networkpolicy -A
```

> ✅ **安全な状態**：repo-serverやRedisを含む各コンポーネントのネットワークポリシーが表示される  
> ❌ **危険な状態**：ポリシーが表示されない（または少ない）

#### 3. 攻撃テストツールに注意

Synacktivは攻撃を自動化するツール **「argo-cdown」** を作成しています。現在は公開を自粛していますが、後日GitHubで公開される予定です。管理者はこのツールで**自分の環境をテスト**することが推奨されています。

### 🔮 今後の展望

- パッチが出るまでは**ネットワーク隔離が唯一の本格的な防衛策**
- Argo CDの開発チームがいつ修正するかは不明
- 今後、攻撃ツールが公開されれば攻撃リスクがさらに高まる可能性あり

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **Kubernetes** | クバネティス | 多数のサーバーでアプリを自動管理するシステム |
| **Argo CD** | アルゴ シーディー | Kubernetesへのアプリ自動展開ツール |
| **repo-server** | レポサーバー | Argo CDの部品。Gitからデータを読む担当 |
| **gRPC** | ジーアールピーシー | プログラム同士が通信するための仕組み |
| **認証（Authentication）** | にんしょう | 「あなたは誰か」を確認する仕組み。ログイン等 |
| **マニフェスト** | まにふぇすと | Kubernetesの「設計書」。何をどう動かすか書かれたファイル |
| **Kustomize** | カスタマイズ | Kubernetesの設定ファイルを加工するツール |
| **Helm / Helmチャート** | ヘルム | Kubernetesアプリのパッケージ管理ツール |
| **Redis** | レディス | データを一時的に高速保存するキャッシュシステム |
| **ネットワークポリシー** | ねっとわーくぽりしー | どのPodがどのPodと通信できるか制限するルール |

| **CVE** | シーブイイー | 脆弱性に付けられる公式の識別番号 |
| **パッチ** | ぱっち | バグや脆弱性を修正するためのソフトウェア更新 |
| **キャッシュポイズニング** | きゃっしゅぽいずにんぐ | 一時保存データに悪意ある情報を書き込む攻撃 |
