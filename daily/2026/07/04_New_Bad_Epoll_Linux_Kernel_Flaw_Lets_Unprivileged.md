# 「Bad Epoll」：普通のユーザーが管理者権限を乗っ取れるLinuxの重大な欠陥、Androidにも影響

**元記事**: [New "Bad Epoll" Linux Kernel Flaw Lets Unprivileged Users Gain Root, Hits Android](https://inl03.netline.com/ltr6/?_m=3n.009a.4021.sp0ao46r89.32qe)
**解説日**: 2026年7月

---

## 背景知識

まず、このニュースを理解するために必要な基礎知識をおさえましょう。

### 🐧 Linuxとは？
Linuxは、パソコンやサーバー、Androidスマートフォンなど、世界中の無数のデバイスで使われているOS（オペレーティングシステム）の一種です。Windowsと同じ「コンピューターを動かすための土台ソフト」ですが、サーバーやスマートフォンではLinuxが圧倒的に多く使われています。

### 🔑 「root（ルート）」とは？
コンピューターには「管理者」と「一般ユーザー」という権限の区別があります。  
- **一般ユーザー**：自分のファイルしか触れない、システムの設定は変えられない  
- **root（管理者）**：何でもできる。システム全体を自由に操作できる「神様アカウント」

> 🏫 **例え話**：学校で例えると、一般ユーザーは「生徒」、rootは「すべての鍵を持つ校長先生」のようなものです。生徒が勝手に校長室に入れるようになってしまうのが今回の問題です。

### ⚙️ 「カーネル」とは？
OSの中でも最も重要な「核」の部分です。ハードウェア（CPU・メモリなど）とアプリの橋渡し役で、ここに欠陥があると影響が非常に大きくなります。

### 📡 「epoll（イーポール）」とは？
Linuxの機能の一つで、「複数のファイルやネットワーク接続を同時に監視する」仕組みです。WebブラウザやWebサーバーなど、多くのソフトウェアが使っており、**無効にすることができません**。

---

## 何が起きたのか

セキュリティ研究者のJaeyoung Chung氏が、Linuxカーネルに**「Bad Epoll」**（CVE-2026-46242）という重大な脆弱性（セキュリティの弱点）を発見しました。

この欠陥を悪用すると：

- ✅ **特別な権限がない普通のユーザー**でも…
- ✅ **root（管理者）権限を奪い取れる**

しかも成功率は**約99%** という非常に高い確率です。

影響を受けるのは：
| 対象 | 影響 |
|------|------|
| Linuxデスクトップ・サーバー | あり |
| Androidスマートフォン（カーネル6.4以降） | あり |
| Pixel 8などの古いAndroid（カーネル6.1系） | なし |

すでに修正パッチは公開されており、実際の攻撃への悪用は現時点では確認されていません。

## 技術的な詳細

### 🐛 「Use-After-Free（ユーズ・アフター・フリー）」バグとは？

今回の欠陥の種類は **「Use-After-Free（解放後使用）」** と呼ばれるものです。

> 🏠 **例え話**：引越し業者（プログラムA）が「この部屋はもう使わない」と鍵を返した（メモリを解放した）のに、別の業者（プログラムB）がまだその部屋に荷物を運び込んでいる（メモリに書き込んでいる）状態です。この混乱を悪用して、第三者が「もう空き部屋のはず」の部屋に不正に侵入するイメージです。

### ⏱️ 「レースコンディション」とは？

このバグは**タイミングの問題**でもあります。

カーネルの2つの処理が「ほぼ同時に」同じメモリ領域を操作しようとする「衝突の瞬間」が、わずか**6命令分（ナノ秒以下）**という超短時間しか開きません。

> 🏁 **例え話**：交差点に信号がなく、2台の車がほぼ同時に通過しようとする瞬間だけ衝突が起きる、というイメージです。その瞬間を狙うのは普通は難しいのですが…

Chung氏はこの「衝突の窓」を**人工的に広げる技術**を開発し、さらにクラッシュなしに何度もリトライできるようにしました。その結果、成功率が約99%に達しました。

### 🔒 Chromeのサンドボックスも突破できる？

Chromeブラウザは「サンドボックス」という隔離された環境でWebページを処理しており、たとえ悪意あるWebサイトを開いても、OSへのダメージを防ぐ仕組みがあります。

ところが今回の欠陥は、**そのサンドボックスの内側からでも発動できる**とされており、これが特に危険視されています。

## なぜ重要なのか

### 🌐 影響範囲がとても広い

- Linuxはサーバーの約96%、Androidは世界スマートフォンの約70%以上で使われています
- epollはあらゆるLinuxソフトに組み込まれており、無効化できません

### 🤖 AIが見つけた欠陥の「兄弟」だった

実は今回の欠陥と同じコードの箇所に、Anthropic社（OpenAIのライバル企業）の最強AIモデル「Mythos」が別の欠陥（CVE-2026-43074）を発見していました。

しかしAIはこの「Bad Epoll」を**見逃していました**。

Chung氏が考える理由は2つ：
1. **タイミングの窓が極端に狭く**、コードを読むだけでは見つけにくい
2. 最初のバグを修正した後、このバグはカーネルの検出ツール（KASAN）に引っかかりにくくなる

> 💡 これは「AIは万能ではなく、人間の研究者との協力が依然として重要」という教訓でもあります。

### 📋 Linux脆弱性の「悪いシリーズ」の一員

今年はLinuxカーネルの特権昇格バグ（一般ユーザーがroot権限を取る攻撃）が多発しています：

| 名前 | 状況 |
|------|------|
| Copy Fail | CISAの「悪用済み脆弱性リスト」入り済み |
| Dirty Frag / DirtyClone | 今年発覚 |
| Bad Epoll | 今回（悪用未確認） |
| Bad Binder / Bad IO_uring | 過去のAndroid被害事例 |

## 対策・今後の展望

### ✅ すぐにできる対策

| 対象者 | 対策 |
|--------|------|
| **Linuxサーバー・デスクトップ管理者** | カーネルパッチ `a6dc643c6931` を適用する |
| **Linuxディストリビューション利用者** | OS（Ubuntu、Federoaなど）のアップデートを適用する |
| **Androidユーザー** | セキュリティアップデートが来たら速やかに適用する |
| **Pixel 8などカーネル6.1系の端末** | 現時点では影響なし |

> ⚠️ **workaround（回避策）はありません**。epollは無効にできないため、パッチ適用が唯一の対策です。

### 🔮 今後の動向

- Androidへの攻撃コードは現在も開発中とのことで、今後公開される可能性があります
- 実際の攻撃への悪用はまだ確認されていませんが、注意が必要です
- AIによるバグ発見はすでに実用レベルに達しており、今後さらに加速するでしょう

以前、**数百万台の組み込み機器（IoT機器など）に使われるファイルシステムの未修正欠陥**についてお伝えしましたが、今回もLinuxベースのシステムに関わる話題です。

組み込み機器の欠陥が「修正パッチが届きにくいデバイス」の問題であったのに対し、今回の Bad Epoll は**広範なLinuxシステム全般**に影響します。共通しているのは「私たちの身の回りのあらゆるデバイスがLinuxで動いており、そのセキュリティは継続的な注意が必要だ」という点です。

## 用語解説

| 用語 | 意味 |
|------|------|
| **CVE** | セキュリティの欠陥に付けられる世界共通の番号（例：CVE-2026-46242） |
| **root** | Linuxの最高管理者権限。何でもできる「神様アカウント」 |
| **カーネル** | OSの核となる部分。ハードウェアとソフトの橋渡し役 |
| **epoll** | 複数の接続を同時監視するLinuxの標準機能 |
| **Use-After-Free** | 解放済みのメモリ領域を誤って使い続けるバグ |
| **レースコンディション** | 複数の処理が「競走」して衝突するタイミングのバグ |
| **権限昇格** | 一般ユーザーが管理者権限を不正に取得すること |
| **サンドボックス** | ソフトをOSから隔離して被害を限定する安全機構 |
| **KASAN** | Linuxカーネルのメモリバグ検出ツール |
| **PoC（Proof of Concept）** | 脆弱性が実際に悪用できることを示す実証コード |
| **ゼロデイ** | 修正パッチが存在しない状態で公開・悪用される脆弱性 |
| **CISA** | 米国のサイバーセキュリティ機関。既知の悪用脆弱性リストを管理 |

---

> 📌 **まとめ**：今回の「Bad Epoll」は、LinuxおよびAndroidに存在する非常に深刻な欠陥で、普通のユーザーが管理者権限を奪える攻撃が約99%の確率で成功します。修正パッチはすでに公開されているため、**OSやスマートフォンのアップデートを忘れずに行いましょう**。これは今すぐできる最も重要な対策です。
