# 北朝鮮ハッカーが「PolinRider作戦」で108個の悪意あるパッケージを公開

**元記事**: [North Korean Hackers Publish 108 Malicious Packages and Extensions in PolinRider Campaign](https://inl03.netline.com/ltr6/?_m=3n.009a.4021.sp0ao46r89.32pw)
**解説日**: 2026年4月

---

## 背景知識

まず、この記事を理解するためにいくつかの基本的な概念を押さえておきましょう。

### 📦 パッケージ・ライブラリとは？
プログラムを作るとき、エンジニアはすべてを自分で書くわけではありません。「ライブラリ」や「パッケージ」と呼ばれる、誰かが作った便利な部品を組み合わせて開発します。料理で言えば、「出汁（だし）の素」のようなものです。毎回イチから出汁を取らなくても、市販の素を使えば時短できますよね。

### 🏪 パッケージレジストリとは？
パッケージが公開されている「お店」のようなものです。今回の記事に出てくる**npm**（JavaScriptのパッケージ置き場）、**Go**（Googleが作った言語のパッケージ置き場）、**Packagist**（PHPのパッケージ置き場）などがあります。世界中の開発者がここから自由にダウンロードして使えます。

### 🛠️ VS Code（ビジュアル・スタジオ・コード）とは？
Microsoftが作った、非常に人気のある「コードエディタ（プログラムを書くためのソフト）」です。世界中の開発者が日常的に使っています。

### 🔗 GitHubとは？
プログラムのソースコード（設計図）を保存・共有するためのウェブサービスです。世界中のエンジニアが自分の作ったプログラムを公開したり、チームで共同作業をしたりしています。

## 何が起きたのか

### 🇰🇵 北朝鮮ハッカーによる大規模な「毒入りパッケージ」ばらまき事件

北朝鮮と関係があるとされるハッカーグループが、**「PolinRider（ポリンライダー）」** という名前の作戦を展開しています。

この作戦では以下のことが確認されています：

- **108個**の悪意あるパッケージや拡張機能を複数のプラットフォームに公開
- **1,951個**のGitHubリポジトリ（プログラムの保管場所）を乗っ取り
- **1,047人**のGitHubアカウント所有者が被害に遭う
- 2026年3月に最初に発見され、**現在も進行中**

> 🍎 **たとえ話**: スーパーで売っているリンゴを誰かがこっそり農薬漬けにして棚に戻すイメージです。見た目は普通のリンゴなのに、食べると危険。同じように、普通に見えるプログラムの部品に「毒（マルウェア）」が仕込まれています。

## 技術的な詳細

### 🎭 ステップ1：偽の求人で近づく（Contagious Interview作戦）

このグループは以前から「Contagious Interview（コンタジャス・インタビュー）」という手口を使っています。

1. LinkedInやGitHubで**偽の採用担当者を演じる**
2. ソフトウェア開発者や暗号通貨関係者に「求人」と称して近づく
3. **AI生成の偽社員プロフィール**まで用意した架空の会社を作る
4. 「採用面接のテスト」として悪意あるコードを実行させる

> 👔 **たとえ話**: 「うちの会社に就職しませんか？入社テストとしてこのアプリを動かしてみてください」と言って、実はウイルス入りのアプリを渡す詐欺師のイメージです。

### 💉 ステップ2：正規のパッケージに「毒を混入」

ハッカーたちは**正規のパッケージ管理者アカウントを乗っ取り**、本物のプログラムに悪意あるコードをこっそり混ぜ込みます。

どうやってアカウントを乗っ取るかというと：
- **失効したドメイン（使われなくなったウェブアドレス）** を取得して、パスワードリセット機能を悪用
- 別のアカウント回復手段を使う

盗んだパスワードは使っていないのが巧妙なポイントです。

### 🦠 ステップ3：悪意あるコードの動作

インストールされると、マルウェアは以下の動作をします：

1. **特定のファイルを探す**（`app.js`、`babel.config.js` など開発でよく使うファイル）
2. 見つけたファイルに**悪意あるJavaScriptコードを追記**
3. **Windowsのバッチスクリプト**（自動操作ファイル）を使って、変更した痕跡を消す
4. 変更が「元々の作者がやったこと」に見えるよう**Git履歴を改ざん**する

### 🔗 ステップ4：ブロックチェーンを使った指令受信

最終的なマルウェア（悪意あるソフト）は、なんと**ブロックチェーン（仮想通貨技術）** を使って指令を受け取ります：

- TRON、Aptos、BNB Smart Chain などのサービスに接続
- 暗号化された「第二段階の悪意あるプログラム」を受け取る
- 展開されるのは **DEV#POPPER RAT**（遠隔操作ウイルス）と **OmniStealer**（情報窃取ツール）

> 🕵️ **たとえ話**: 普通の手紙（メールなど）は監視されるかもしれないので、仮想通貨の取引記録に暗号メッセージを隠して連絡する、スパイ映画のような手口です。

### 🎨 ステップ5：発見されにくくする工夫

- 悪意あるコードを**大量の空白（スペース）で隠す**（コードの端の方に追記して目立たなくする）
- **偽のフォントファイル（.woff2）** に見せかけて隠す
- **GitHubの変更履歴を書き換えて**、古くから存在したコードのように偽装する
- **VS Codeのタスクファイル**を使って、フォルダを開いただけで自動実行させる

## なぜ重要なのか

### 🌍 影響の広さ

| 対象 | 規模 |
|------|------|
| 悪意あるパッケージ数 | 108個 |
| 悪意あるリリース版数 | 162個 |
| 乗っ取られたGitHubリポジトリ | 1,951個 |
| 被害を受けたアカウント所有者 | 1,047人 |

### ⚠️ 「サプライチェーン攻撃」の恐ろしさ

これは**サプライチェーン攻撃**と呼ばれる非常に危険な手口です。

> 🏭 **たとえ話**: 工場（パッケージ開発者）→ 問屋（GitHubやnpm）→ お店（開発者が利用）→ 消費者（一般ユーザー）という流通の中で、「工場」の段階でウイルスを混入させるイメージです。

一度信頼された部品に毒が混入されると、**それを使った何千ものアプリ・サービス**が一気に汚染されます。被害を受けた開発者が知らずに悪意あるコードを含むアプリを公開し、さらに多くの一般ユーザーに広がる可能性があります。

### 👀 「見た目は安全」が最も危ない

- GitHubの変更履歴が改ざんされているため、**目で見ても安全か判断できない**
- 有名・信頼されているパッケージが狙われるため、**警戒心が下がりやすい**
- 2023年から続く継続的な活動で、**手口がどんどん巧妙になっている**

## 対策・今後の展望

### 👩‍💻 開発者向けの対策

1. **パッケージのバージョンを固定する**
   使うパッケージのバージョンを明示して、勝手に更新されないようにしましょう。

2. **GitHubのリポジトリ活動ログを確認する**
   コミット履歴（変更記録）だけでなく、**リポジトリの活動ログ全体**を確認することが重要です（ハッカーはコミット履歴を改ざんできますが、活動ログは変更できません）。

3. **VS Codeの拡張機能を慎重に選ぶ**
   公式マーケットプレイス経由でも、レビュー数・評価を確認してから入れましょう。

4. **知らない人からの「求人・テスト依頼」に注意する**
   LinkedInなどで突然求人が来て「このコードを動かして」と言われたら要注意です。

5. **セキュリティスキャンツールの導入**
   Socketなどのセキュリティツールを使って、パッケージの安全性を自動チェックしましょう。

### 🔮 今後の展望

- 攻撃者は**現在も新しいパッケージを公開し続けている**
- ブロックチェーンを指令サーバーとして使う手法は、従来のブロック手段が効きにくい
- AIを使った偽プロフィールの精度が上がり、**偽の採用担当者を見破るのが難しくなっている**

## 過去記事との関連

今回の「PolinRider作戦」は、以前から報告されている北朝鮮の**「Contagious Interview（コンタジャス・インタビュー）」** という作戦の延長線上にあります。

- **2023年〜**: Contagious Interviewとして偽求人攻撃が確認され始める
- **2026年3月**: PolinRiderとして新たな局面（GitHubへの大規模侵入）が発見される
- **現在**: TaskJackerという別グループとも合流し、攻撃規模が拡大中

まるで一つの犯罪組織が、時間をかけて手口を進化させているようなイメージです。単発の攻撃ではなく、**組織的・継続的な国家レベルの活動**である点が特に危険です。

## 用語解説

| 用語 | 説明 |
|------|------|
| **マルウェア** | 悪意を持って作られたソフトウェアの総称。ウイルスも含む |
| **npm** | JavaScriptのプログラム部品を管理・配布するシステム |
| **Packagist / Composer** | PHP言語のパッケージ管理システム |
| **Goモジュール** | Go言語のパッケージ管理システム |
| **リポジトリ** | プログラムのソースコードを保存している場所 |
| **サプライチェーン攻撃** | 製品・サービスの「部品の流通経路」を狙う攻撃 |
| **難読化（obfuscation）** | コードを読みにくくして内容を隠す技術 |
| **RAT（Remote Access Trojan）** | 遠隔操作を可能にするウイルス |
| **BeaverTail** | Contagious Interview作戦で使われるJavaScript製マルウェア |
| **OmniStealer** | パスワードや個人情報を盗むツール |
| **ブロックチェーン** | 改ざんが難しい分散型のデータ記録技術（仮想通貨にも使われる） |
| **Git履歴** | プログラムの変更記録。「いつ・誰が・何を変えたか」がわかる |
| **VS Codeタスクファイル** | VS Codeが自動で実行するコマンドを定義したファイル |
| **失効ドメイン乗っ取り** | 使われなくなったウェブアドレスを取得し、関連アカウントの回復に悪用する手口 |

---

> 💬 **まとめ**: 北朝鮮のハッカーが「偽の求人」→「パッケージへの毒混入」→「ブロックチェーン経由での指令」という多段階の巧妙な手口で、世界中のソフトウェア開発者を狙っています。「信頼できると思っていたプログラムの部品が実は危険だった」という点が、この攻撃の最も恐ろしいところです。
