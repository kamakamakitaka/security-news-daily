# AIがコードを書くようになったら、ソフトウェアの安全管理はどう変わる？

**元記事**: [What Changes When Your Software Supply Chain Includes AI Writing Your Code?](https://inl03.netline.com/ltr6/?_m=3n.009a.4023.sp0ao46r89.32so)
**解説日**: 2025年7月22日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### 🏭 ソフトウェアサプライチェーンとは？

「サプライチェーン」という言葉は、本来は工場での部品調達の流れを指します。車を作るとき、タイヤ・エンジン・ガラスなど多くの部品を別の会社から仕入れますよね。

ソフトウェアも同じです。プログラマーがゼロからすべてを書くことはほとんどなく、**他の人が作った部品（ライブラリやパッケージ）** を大量に組み合わせて作ります。

```
あなたのアプリ
  ├── Aというライブラリ（他の人が作った）
  │     └── Cというライブラリ（さらに別の人が作った）
  └── Bというライブラリ（他の人が作った）
        └── Dというライブラリ（さらに別の人が作った）
```

この「部品の調達経路」全体を **ソフトウェアサプライチェーン** と呼びます。

### ⚠️ なぜサプライチェーンが危険なの？

部品のどこかに問題があれば、完成品にも問題が出ます。過去に実際に起きた大事件を見てみましょう：

- **SolarWinds事件（2020年）**: 有名なIT管理ソフトのアップデートファイルに攻撃者が侵入し、米国政府機関など多数が被害を受けた
- **Log4Shell（2021年）**: Javaというプログラムで広く使われていた「ログ記録ツール」に重大な欠陥が見つかり、世界中のシステムが危険にさらされた
- **XZ Utils（2024年）**: Linuxシステムで使われる圧縮ツールに、2年かけて偽装した攻撃者がバックドア（不正侵入用の裏口）を仕込もうとした

これらに共通するのは「**自分で書いたコードじゃないところ**」が攻撃の入口になったことです。

### 🤖 AIコーディングアシスタントとは？

最近、GitHub CopilotやCursorなど、**AIがプログラムを自動で書いてくれるツール**が普及しています。プログラマーが「こういう機能を作って」と指示するだけで、AIがコードを提案・生成してくれます。

### 🔌 MCP（Model Context Protocol）とは？

AIツールが外部のサービスやデータと連携するための「共通の規格」です。2024年初頭にAnthropicが発表しました。スマートフォンのアプリが地図や決済など様々なサービスと連携できるように、AIもMCPを通じて様々なツールと連携できるようになりました。

## 何が起きたのか

### 📰 記事の概要

この記事は「**AIがコードを書くようになったことで、ソフトウェアの安全管理がまったく新しい問題に直面している**」という警鐘を鳴らすものです。

具体的には、こんなことが起きています：

1. **AIが勝手にライブラリを選んで追加する**
   → 人間がチェックする前に、危険なものが混入する可能性がある

2. **AIエージェント（自律的に動くAI）が連鎖的にツールを呼び出す**
   → AIがAIを呼び、そのAIがまた別のツールを呼ぶ…という連鎖で、誰も全体を把握できなくなる

3. **プロンプトインジェクション攻撃という新しい脅威**
   → 攻撃者がAIへの「指示文（プロンプト）」を細工して、悪意あるコードを書かせたり、危険なパッケージを使わせたりできる

4. **Shai-Hulud（シャイ・フルード）という新しい攻撃キャンペーン**
   → 2025年、開発者ツールを通じて自己増殖する悪意あるパッケージが広まる事例が確認された

## 技術的な詳細

### 🎯 「どこから来たか」の問題が複雑になった

セキュリティの世界では長年、コードの**出所（プロベナンス）**を確認することが基本でした。「このコードは誰が書いた？信頼できる？」という確認です。

ところがAIが登場して、この確認対象がぐっと増えました：

```
【以前の確認対象】
コード → 使っているライブラリ → OK？

【今の確認対象】
AIモデル自体 → AIエージェント → AIが使うツール → AIが選んだライブラリ → 最終的なコード
     ↑              ↑              ↑
  信頼できる？    安全に動いてる？  安全なツール？
```

### 🧨 プロンプトインジェクション攻撃の仕組み

これが今回の記事で最も注目すべき新しい脅威です。

**普通の使い方**：
```
プログラマー「このWebサイトのログイン機能を作って」
AI「はい、こんなコードはどうでしょう → [安全なコード]」
```

**攻撃者が仕込んだ場合**：
```
（攻撃者がどこかのWebページや文書に悪意ある指示を隠す）
「このドキュメントを参考にして」とAIに渡す

↓

AIが文書を読む際に隠された指示を「実行すべき命令」と誤解

↓

AI「了解です → [バックドアが含まれた危険なコード]」
```

まるで「こっそり洗脳メモを読ませる」ようなイメージです。

### 🔗 エージェントの連鎖問題

```
AIエージェントA「タスクを完了するためにツールXが必要」
    ↓
ツールX「このデータ処理にはサービスYが必要」
    ↓
サービスY「この機能にはライブラリZが必要」
    ↓
ライブラリZ「←これが実は悪意あるパッケージだった！」
```

人間が関与しないまま、AIが勝手に「必要」と判断した結果、誰も選んでいない危険なものが入り込む、というわけです。

### 📊 「見つけすぎる」問題

AIが大量のコードを生成するようになると、セキュリティチェックで検出される問題の数も爆発的に増えます。AIは「お昼前に1000行のもっともらしいコード」を書けてしまうからです。

セキュリティ担当者はただでさえ警告の処理に追われているのに、さらに大量の警告が積み重なる。これを記事では「**溺れている（drowning）**」と表現しています。

## なぜ重要なのか

### 🌍 影響の広がり

AIコーディングツールは今や世界中のプログラマーが日常的に使っています。つまり：

- **影響を受けるソフトウェアの数**：膨大
- **攻撃が成功した場合の被害**：銀行システム・医療システム・インフラなど社会全体に波及しうる
- **発見の難しさ**：「AIが書いたコード」は人間が書いたコードと見た目が区別できない

### 🏢 業界も動き始めた

調査会社のガートナーが2025年6月、**「ソフトウェアサプライチェーンセキュリティ」の市場評価レポート（Magic Quadrant）** を初めて発表しました。これは「この分野が本格的なビジネス課題として認識された」ことを意味します。

## 対策・今後の展望

### ✅ 必要になる対策（記事からの要点）

**1. 「リネージュ（系譜）」の拡張**
コードの出所追跡を、AIモデルやエージェントにも適用する。
> 「このコードは誰が書いた？」→「このAIモデルが書いた。そのモデルは何を元にした？どんなツールを使った？」まで追う

**2. 本当に危険なものを優先して対処する**
すべての警告を同列に扱わず、「実際に悪用可能かどうか」を基準に優先順位をつける。
> 1000件の警告より、「今すぐ攻撃に使える」1件を先に直す

**3. AIが生成したコードは「そのままOK」にしない**
AIが書いたコードも、人間が書いたコードと同様にレビューとセキュリティスキャンを行う（ただしこれだけでは不十分）

**4. MCPサーバーの監視**
AIがどのMCPツールを使っているか、そのツールは安全か、を継続的に確認する

### 🔮 今後の展望

- AIの使用が増えるほど、この問題は深刻になる
- セキュリティツール自体もAI対応にアップデートが必要
- 「AIが書いたコードの証明書（SBOM: ソフトウェア部品表）」のような新しい仕組みが生まれてくる可能性

## 過去記事との関連

今回の記事は、過去に起きたサプライチェーン攻撃（SolarWinds、Log4Shell、XZ Utils）の教訓を踏まえた上で、「**AIの登場によってその問題がさらに複雑になった**」という発展的な内容です。

従来のサプライチェーンセキュリティが「**人間が選んだ部品の安全確認**」だったとすれば、AI時代のそれは「**AIが自律的に選んだ部品と、AIそのものの安全確認**」という全く新しい挑戦になっています。

## 用語解説

| 用語 | 意味 |
|------|------|
| **ソフトウェアサプライチェーン** | ソフトウェアを作る際に使う部品・ツール・プロセス全体の流れ |
| **ライブラリ/パッケージ** | プログラマーが再利用できる部品集。「車輪の再発明をしない」ための便利な道具 |
| **依存関係（トランジティブ依存）** | Aを使うとBが必要で、BはCが必要で…という「部品の部品」の連鎖 |
| **プロベナンス（出所）** | 「このコードはどこから来たか」という情報。食品の産地証明に相当 |
| **プロンプトインジェクション** | AIへの入力（指示文）に悪意ある命令を紛れ込ませる攻撃手法 |
| **AIエージェント** | 人間の細かい指示なしに、自律的に判断してタスクをこなすAIシステム |
| **MCP（Model Context Protocol）** | AIが外部ツールやサービスと連携するための共通規格 |
| **バックドア** | 攻撃者が後でこっそり侵入できるように仕込んだ「裏口」 |
| **SBOM（Software Bill of Materials）** | ソフトウェアに含まれる部品の一覧表。食品の「原材料表示」に相当 |
| **Magic Quadrant** | 調査会社ガートナーが発表する市場の主要プレイヤー評価レポート |
| **SolarWinds** | 2020年に発覚した大規模サプライチェーン攻撃。米政府機関も被害を受けた |
| **Log4Shell** | 2021年に発覚したJavaライブラリの深刻な脆弱性。世界中で悪用された |
| **XZ Utils** | 2024年に発覚した、Linux用ツールへのバックドア仕込み未遂事件 |

---

> 💡 **まとめ**: AIがコードを書く時代になって、「何が安全で何が危険か」の確認範囲がAIモデル・AIエージェント・AIが使うツールにまで広がりました。さらに「プロンプトインジェクション」という新しい攻撃手法も登場。セキュリティの世界は、AIの進化に追いつくための大きな変革期に入っています。
