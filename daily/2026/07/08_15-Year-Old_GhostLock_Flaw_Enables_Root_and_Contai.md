# 15年間見つからなかった「幽霊の鍵穴」——ほぼすべてのLinuxに影響する深刻な脆弱性「GhostLock」

**元記事**: [15-Year-Old GhostLock Flaw Enables Root and Container Escape on Most Linux Distros](https://inl03.netline.com/ltr6/?_m=3n.009a.4024.sp0ao46r89.32uw)
**解説日**: 2025年7月10日

---

## 背景知識

まず、このニュースを理解するためにいくつかの基本的な概念を押さえておきましょう。

### Linuxとは？
スマホ（Android）、Webサーバー、クラウドサービス、スパコンなど、世界中のあらゆる場所で動いているOS（基本ソフト）です。Windowsと並んで世界で最も普及しているOSのひとつで、インターネットのサーバーの大半はLinuxで動いています。

### 「カーネル」って何？
OSの中でも一番深い場所にある「心臓部」のプログラムです。ハードウェア（CPU・メモリなど）と、アプリの橋渡しをしています。カーネルに穴（脆弱性）があると、システム全体が危険にさらされます。

### 「root（ルート）」って何？
Linuxにおける「全能の管理者アカウント」のことです。どんなファイルも読み書きでき、どんな設定も変更できる、いわば「合鍵」を持った存在です。普通のユーザーがrootになれてしまうのは、「アルバイトの店員が、本来は社長しか開けられない金庫を開けられてしまう」ような状態です。

### 「コンテナ」って何？
アプリを安全に隔離して動かす仕組みで、「プログラムの個室」のようなものです。DockerやKubernetesなどが有名です。「個室を抜け出すこと（コンテナエスケープ）」ができると、他の人の部屋（システム全体）に侵入できてしまいます。

### 「use-after-free（解放済みメモリ参照）」って何？
メモリ（作業用の棚）を「もう使わない」と返却した後に、誤ってその場所を参照してしまうバグのことです。返却後に誰かが別のものを置いた棚を、古い「棚番号」を使って見に行ってしまうイメージです。

## 何が起きたのか

セキュリティ企業 **Nebula Security** が、Linuxカーネルに**15年以上前から存在していた重大な脆弱性**を発見・公表しました。この脆弱性は **「GhostLock（幽霊の鍵穴）」**（CVE-2026-43499）と名付けられています。

### 発見の経緯をざっくり言うと
- 2011年以来、ほぼすべてのLinuxに欠陥が潜んでいた
- Nebula社のAI搭載バグ発見ツール「**VEGA**」がこの欠陥を発見
- GoogleのセキュリティコンテストプログラムでNebula社に**約1,370万円（92,337ドル）**の賞金が贈られた
- 現在までに実際に悪用された事例は確認されていないが、**攻撃のサンプルコードが公開されてしまっている**

## 技術的な詳細

### バグの仕組みをわかりやすく解説

#### 🔄 まず「ロック（lock）」の仕組みを理解しよう

Linuxカーネルでは、複数のプログラムが同時に同じデータを触らないよう「順番待ち」の仕組みがあります。これが**ロック（lock）**です。図書館で「今この本は貸し出し中」と管理するようなものです。

そして、急ぎの作業が「重要度の低い作業」の後ろで待たされないよう、**優先度を管理する仕組み（優先度継承）**も存在します。

#### 🐛 どこに欠陥があったのか

ロックを取得しようとした作業が「行き詰まって断念する」という**ごく稀なケース**があります。

このとき、後片付けのプログラムが「**タイミングを間違えて動き出し、間違った作業の記録を消してしまう**」というバグが起きます。

その結果、カーネルは**「すでに返却・再利用されたメモリの場所」を指し示す古いメモ（ポインタ）**を持ち続けてしまいます。これが **use-after-free** 脆弱性の発生です。

#### ⚡ 攻撃者はこれをどう使うのか

Nebula社は、この小さなミスを「足がかり」にして、いくつかの巧みな手順を重ねることで、**自分たちのコードを「root（全能の管理者）」として実行させる**ことに成功しています。

- 攻撃に必要なもの：**すでにそのマシンにログインしていること**（それだけでOK！）
- 特別な権限・特殊な設定・ネットワーク接続：**不要**
- 成功率：**97%**
- 攻撃にかかる時間：**わずか約5秒**

コンテナ（隔離環境）の中からでも脱出できるため、クラウドサービスなども危険にさらされます。

## なぜ重要なのか

### 影響の大きさ

| 項目 | 内容 |
|------|------|
| 影響するOS | Ubuntu, Debian, Red Hat, Fedora などほぼ全Linuxディストリビューション |
| 脆弱性が存在した期間 | **2011年〜2025年**（約15年間！） |
| 危険度スコア | **7.8 / 10（高）** |
| 攻撃コードの公開 | **あり**（誰でも実行可能な状態） |

### 特に危ない環境
- 🌩️ **クラウドサーバー**（複数のユーザーが同居している）
- 📦 **コンテナ環境**（Docker, Kubernetes など）
- 🔄 **CI/CDランナー**（ソフトウェアの自動テスト・ビルド環境）

これらの環境では「すでにログインしている（または侵入した）」攻撃者が、簡単にシステム全体を乗っ取れてしまいます。

### 今年の「Linux特権昇格バグ」の流行

GhostLockは、2026年に次々と発見されているLinux権限昇格バグのひとつに過ぎません。

- **Bad Epoll**（CVE-2026-46242）：同じコード領域にある脆弱性。なんとAndroidにも影響。
- **Copy Fail**（CVE-2026-31431）：すでに実際の攻撃で使われており、米国CISAの危険リストに掲載済み。

共通点は、**2011年頃から存在する古い仕組みに、AIツールが目を向けるまで誰も気づかなかった**という点です。

### 「IonStack」という2段階攻撃チェーン

さらに恐ろしいのが、Nebula社が「**IonStack（アイオンスタック）**」と呼ぶ組み合わせ攻撃です。

```
[Step 1] CVE-2026-10702（Firefoxの脆弱性）
         ↓ ブラウザ内でコードを実行し、サンドボックスを脱出
         
[Step 2] GhostLock（Linuxカーネルの脆弱性）
         ↓ OSの最高権限(root)を乗っ取る
         
[結果] ウェブサイトを見るだけでPC全体を乗っ取られる可能性
```

つまり、悪意のあるWebサイトを訪問するだけで、最終的にパソコン全体を完全に制御されるという**2段階攻撃**が理論上成立してしまいます。

## 対策・今後の展望

### ✅ 今すぐやるべきこと

**1. Linuxカーネルを最新版にアップデートする（最重要！）**

```bash
# Ubuntuの場合
sudo apt update && sudo apt upgrade

# Red Hat / Fedoraの場合
sudo dnf update
```

> ⚠️ **注意**：最初のパッチ（修正版）には別のクラッシュバグ（CVE-2026-53166）が含まれていました。そのため、**最新の修正版（3bfdc63936dd）が含まれるパッケージ**を確認してからアップデートしてください。

**2. 自分のディストリビューションのセキュリティ情報を確認する**
- Ubuntu：24.04・22.04・20.04 LTSは2025年7月初旬時点でまだ対応中のものあり
- 「パッチが来ているだろう」と思い込まず、**公式アドバイザリで確認**してください

**3. 優先的にパッチを当てる環境**
- 🥇 クラウドサーバー・マルチテナント環境
- 🥇 コンテナ・Docker・Kubernetes
- 🥇 CIランナー・自動テスト環境

### 🛡️ 完全ではないが効果のある緩和策

| 設定名 | 効果 |
|--------|------|
| `RANDOMIZE_KSTACK_OFFSET` | 攻撃を難しくする（根本解決ではない） |
| `STATIC_USERMODE_HELPER` | 同上 |

これらはあくまで「攻撃を難しくする」だけで、**根本的な解決にはなりません**。必ずパッチ適用を。

### 📱 Firefoxユーザーへの注意

IonStackの第1段階として悪用されるFirefoxの脆弱性（CVE-2026-10702）も同時に修正されているはずですので、**ブラウザも必ず最新版に更新**してください。

## 過去記事との関連

以前、**中国系ハッカー集団UAT-7810が新マルウェア「LONGLEASH」で攻撃網を拡大している**というニュースを解説しました。国家レベルの高度な攻撃者たちは、常に新しい侵入経路を探しています。

今回のGhostLockのような「ローカル権限昇格（すでに侵入した後にroot権限を得る）」バグは、まさに「最初の侵入を果たした後の仕上げ」として使われる典型的な技術です。

UAT-7810のような高度な脅威グループが、GhostLockのような脆弱性を組み合わせて使う可能性は十分に考えられます。「個別の脆弱性」だけでなく、**こうした脆弱性が組み合わされて使われる**という観点でセキュリティを考えることがますます重要になっています。

## 用語解説

| 用語 | 解説 |
|------|------|
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやシステムの「欠陥・穴」のこと |
| **CVE** | 脆弱性に割り振られる世界共通の「管理番号」。CVE-2026-43499のように表記する |
| **Linux カーネル** | LinuxのOS機能の中核となる最も重要なプログラム |
| **root（ルート）** | Linuxの「全能の管理者」アカウント。何でもできる |
| **権限昇格（特権昇格）** | 一般ユーザーがroot等の高い権限を不正に得ること |
| **use-after-free** | 解放したメモリを誤って再参照するバグ。攻撃に使われやすい |
| **コンテナ** | アプリを隔離して動かす仕組み（Dockerなど） |
| **コンテナエスケープ** | コンテナの隔離を突破してホストシステムに侵入すること |
| **ディストリビューション（distro）** | LinuxのOS配布パッケージ（Ubuntu, Fedora, Debianなど） |
| **バグバウンティ** | 脆弱性を発見・報告した研究者に報奨金を払う制度 |
| **VEGA** | Nebula社が開発したAI搭載の自動バグ発見ツール |
| **CI/CDランナー** | ソフトウェアを自動でテスト・ビルドする環境 |
| **サンドボックス** | プログラムの動作を安全な領域に閉じ込める仕組み |
| **ポインタ** | メモリ上の場所を指し示す「住所メモ」のようなもの |
| **CISA** | 米国のサイバーセキュリティ・インフラ安全保障局 |
