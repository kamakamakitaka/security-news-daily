# 休眠中のGitHubアカウントを使って企業の組織情報を密かに調査する攻撃が発覚

**元記事**: [Dormant GitHub Accounts Help Attackers Blend In While Mapping Corporate Orgs](https://inl03.netline.com/ltr6/?_m=3n.009a.4026.sp0ao46r89.32y0)
**解説日**: 2026年7月10日

---

## 背景知識

まず、この記事を理解するためのキーワードを説明します。

### 🐙 GitHubとは？
**GitHub（ギットハブ）**は、プログラマーがソースコード（プログラムの設計図）を保存・共有・共同作業するためのサービスです。世界中の企業や開発者が使っており、「コードの倉庫」とイメージしてください。企業はここにソフトウェアのコードを置いており、チームのメンバー情報なども管理されています。

### 🔌 APIとは？
**API（エーピーアイ）**は、プログラム同士が会話するための「窓口」です。たとえばGitHubのAPIを使えば、「この会社のリポジトリ一覧を見せて」「このユーザーのフォロワーは誰？」といった質問をプログラムで自動的にできます。

### 📦 リポジトリとは？
コードや資料をまとめて保存する「フォルダ」のようなものです。「パブリック（公開）」と「プライベート（非公開）」の2種類があります。

### 👻 ゴーストアカウントとは？
作ったはいいが、ほとんど使われていない「幽霊アカウント」のことです。今回の記事では、**2〜5年前に作って放置していたアカウント**を悪用するという手口が登場します。

---

## 何が起きたのか

セキュリティ企業**Datadog Security Labs**が、企業のGitHub組織情報を密かに調べ回る**複数の攻撃キャンペーン**を発見・警告しました。

### 🔍 攻撃の全体像をひとことで言うと…

> 「数年前に作って放置していたGitHubアカウントを大量に使い、企業のメンバー構成・リポジトリ・活動状況をコッソリ自動収集している」

というものです。まるで、**町内の家を一軒一軒まわって「どんな人が住んでいるか」を記録するストーカー行為**をプログラムで自動化しているイメージです。

### 具体的に攻撃者がやっていること
- 50以上の「休眠アカウント（ゴーストアカウント）」を武器化
- 盗まれた、または漏洩したアクセストークン（後述）を使用
- GitHub APIを通じて以下の情報を自動収集：
  - 📁 企業の公開リポジトリ一覧
  - 👥 メンバーのフォロー・フォロワー関係
  - ⭐ スターをつけたリポジトリや活動履歴
  - 🏢 組織のメンバー構成

さらに一部では、**非公開（プライベート）リポジトリのクローン（丸ごとコピー）**にまで成功しています。

## 技術的な詳細

### 🧠 なぜ「古いアカウント」を使うのか？

ここが今回の攻撃のもっとも巧妙な点です。

新しいアカウントを作ってすぐ大量のAPIリクエストを送ると、「怪しい！」と検知されやすくなります。しかし**2〜5年前に作って長期間放置したアカウント**を使えば、「昔からいる普通のユーザー」に見せかけられるのです。

```
🆕 新しいアカウント → 「急に大量アクセス！？不審だ」と検知されやすい
👴 古いアカウント  → 「昔からいるユーザーがAPIを叩いてるだけ」に見える
```

まるで**「転校してきたばかりの生徒が怪しいことをすると目立つが、3年前から学校にいる生徒なら目立ちにくい」**という人間の心理と同じ発想です。

### 🔑 PAT（個人アクセストークン）の悪用

**PAT（パーソナル・アクセス・トークン）**とは、GitHubにログインするための「合い言葉」のようなものです。正規ユーザーのPATが何らかの形で漏洩すると、攻撃者はその人に「なりすまして」APIを使えます。

### 📡 認証なしでもアクセスできてしまう問題

GitHubのAPIの多くは、**ログインしなくても使える（認証不要）**という特性があります。つまり、公開されている情報であれば誰でも自動収集できてしまうのです。これは利便性のための仕様ですが、悪用されると危険です。

### 🕵️ どうやって「普通に見せる」か

攻撃者は**カスタムのユーザーエージェント**（「このブラウザ/アプリからアクセスしています」という識別情報）を使い、まるで普通のツールがアクセスしているように偽装しています。

## なぜ重要なのか

### 🎯 これは「下調べ」フェーズ

今回の攻撃自体は情報収集が主目的ですが、これは**本格的な攻撃の前準備（偵察）**として非常に危険です。

```
情報収集（今回）
   ↓
「あの会社はこんなコードを使ってる」
「このメンバーがこのプロジェクトを担当してる」
   ↓
標的型フィッシング詐欺・不正アクセスに活用
```

たとえば：
- 「A社はXXライブラリを使っている」→そのライブラリの脆弱性を攻撃
- 「B社のエンジニアCさんはこのプロジェクトを管理している」→Cさんを狙ったフィッシングメール送信

### 📊 影響範囲の大きさ

- 対象は**複数の企業にまたがる組織的な攻撃**
- 一部では**非公開コードの盗難**も確認済み
- 個々のリクエストは「普通に見える」ため、検知が非常に難しい

Datadogは「個々のリクエスト単体では怪しくない。問題は、複数のアカウントが何週間もかけて複数の企業を同時に調べ回っている"群れとしての動き"にある」と指摘しています。

## 対策・今後の展望

### ✅ 企業・開発者が取るべき対策

| 対策 | 詳細 |
|------|------|
| **PATを定期的に更新・削除する** | 使わなくなったトークンは速やかに無効化 |
| **PATをコードに直書きしない** | うっかりGitHubに上げてしまい漏洩するケースが多い |
| **組織のアクセス権限を最小限に** | 必要な人だけに必要な権限を付与する |
| **APIアクセスログを監視する** | 不審なアクセスパターンを検知できる体制を |
| **プライベートリポジトリの棚卸し** | 本当に必要な情報だけを置く |

### 🔍 個人でできること
- 自分のGitHubアカウントで発行したPATを確認し、不要なものを削除する
- **Settings → Developer settings → Personal access tokens** から確認できます

### 🔮 今後の展望
Datadogは今回のような「低速・分散型の情報収集攻撃」は今後も増えると予測しています。AIを使った自動化でさらに巧妙になる可能性もあり、**GitHubのような開発者プラットフォームへの攻撃は要注意**です。

今回の攻撃も、企業の内部構造・使用技術・担当者情報を集めることで、次の攻撃（ランサムウェアや標的型攻撃）に役立てようとしている可能性があります。また、暗号資産ウォレット攻撃の記事でも触れたように、**「準備段階の偵察」がいかに重要か**という点でつながっています。攻撃者は常に「いきなり攻撃」ではなく、**念入りな下調べ**から始めるのです。

## 用語解説

| 用語 | 意味 |
|------|------|
| **GitHub** | プログラムのコードを共有・管理するサービス |
| **API** | プログラム同士が情報をやり取りするための窓口 |
| **リポジトリ（Repository）** | コードや資料をまとめて保存するフォルダのようなもの |
| **ゴーストアカウント** | 作ったまま長期間放置されていた幽霊のようなアカウント |
| **PAT（Personal Access Token）** | GitHubにアクセスするための合い言葉・鍵のようなもの |
| **OAuthトークン** | 「このアプリにGitHubへのアクセスを許可する」ための認証情報 |
| **エニュメレーション（Enumeration）** | 情報を一つひとつ列挙・収集すること。「偵察」に近い |
| **クローン（Clone）** | リポジトリを丸ごとコピーすること |
| **GraphQL** | APIへの質問（クエリ）を柔軟に書ける言語 |
| **ユーザーエージェント** | 「どのブラウザ・アプリからアクセスしているか」を示す識別情報 |
| **偵察（Reconnaissance）** | 攻撃の前段階として行う情報収集活動 |
