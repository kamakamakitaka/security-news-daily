# ハッカーのサーバーが丸見え！「WP-SHELLSTORM」が数千のWordPressサイトに裏口を仕掛けていた

**元記事**: [Exposed Hacker Server Reveals WP-SHELLSTORM Backdooring Thousands of WordPress Sites](https://inl03.netline.com/ltr6/?_m=3n.009a.4026.sp0ao46r89.32xc)
**解説日**: 2026年7月12日

---

## 背景知識

このニュースを理解するために、いくつかの基本的な概念を押さえておきましょう。

### 🌐 WordPressって何？
**WordPress（ワードプレス）** は、世界中のウェブサイトの約40%以上で使われている、ウェブサイトを作るためのソフトウェアです。ブログ、企業サイト、ショッピングサイトなど、さまざまなサイトがWordPressで動いています。「プラグイン」と呼ばれる追加機能を入れることで、自由にカスタマイズできるのが特徴です。

### 🔌 プラグインとは？
スマートフォンのアプリと同じようなイメージです。WordPressに「キャッシュ機能」や「フォーム機能」などを追加するための小さなプログラムのことです。ただし、アプリと同様に、古いバージョンのままにしておくとセキュリティの穴（脆弱性）が生まれることがあります。

### 🚪 バックドア（裏口）とは？
家の「勝手口」のようなものです。本来の入口（ログイン画面など）を通らずに、攻撃者が秘密裏にサーバーに侵入し続けられる「隠し通路」のことです。

### 🐚 ウェブシェルとは？
攻撃者がサーバーに植え付ける、小さな悪意のあるプログラムです。これが仕込まれると、攻撃者はインターネット越しにそのサーバーを自由に操作できるようになります。家の中に「遠隔操作できるドアノブ」を仕掛けられるようなイメージです。

### 🔍 CVE（シーブイイー）とは？
「Common Vulnerabilities and Exposures」の略で、発見されたセキュリティの脆弱性（穴）に付けられる世界共通の番号です。例えば「CVE-2026-3844」という番号が付くと、世界中のセキュリティ専門家がその脆弱性を識別・追跡できます。

## 何が起きたのか

### ハッカー自身が「うっかりミス」をした

あるサイバー犯罪グループが、自分たちが使っていた**攻撃用サーバーを、パスワードなしでインターネットに公開したまま3週間も放置**してしまいました。

このサーバーの中には、グループの「犯行の一部始終」が記録されていました：

- 🔧 ハッキングに使うツール一式
- 📋 攻撃対象のウェブサイトリスト（なんと**140万件以上！**）
- 📜 攻撃の実行ログ（何をやったかの記録）
- ⚙️ 攻撃の設定ファイルなど

このサーバーを2つのセキュリティ調査チームが発見しました：
- **SOCRadar**（セキュリティ会社）が2026年6月11日に発見
- **Ctrl-Alt-Intel**が同じディレクトリを発見し、6月22日に公開

なぜ公開状態になったかというと、**攻撃者が「Pythonの簡易ウェブサーバー」というファイル転送用の機能を使ったまま、止め忘れて22日間も動かし続けていた**からです。プロのハッカーでも、こんな初歩的なミスをするのです。

### このグループの正体は？「WP-SHELLSTORM」

このグループは **「WP-SHELLSTORM（ダブリューピー・シェルストーム）」** と名付けられ、その手口は：

1. WordPressなどのサイトの古いプラグインの脆弱性を利用して侵入
2. ウェブシェル（裏口プログラム）を仕掛ける
3. その「侵入済みサイトへのアクセス権」を**他の犯罪者に販売**する

という「**ウェブシェル・アクセス・ブローカー**（不正アクセス権の転売業者）」ビジネスを行っていました。

## 技術的な詳細

### 攻撃の流れ（ステップごとに解説）

```
① FOFAという中国製の「インターネット検索エンジン」で脆弱なサイトを大量にリストアップ
        ↓
② 自動スキャナーで、古いプラグインを使っているサイトを特定
        ↓
③ 27種類の既知の脆弱性を使って自動的に攻撃
        ↓
④ 成功したサイトに「down.php」というウェブシェルを設置
        ↓
⑤ そのアクセス権を他の犯罪者に販売 💰
```

### 主な攻撃対象となったプラグインの脆弱性

| 脆弱性 | 対象 | 攻撃試行数 | 成功数 |
|--------|------|-----------|--------|
| CVE-2026-3844（Breezeプラグインの欠陥） | WordPress | 45,000件以上 | 17,000件以上 |
| JCE Editorの欠陥 | Joomla | 560,000件以上 | **わずか77件** |

※ Joomlaの攻撃は56万件試みて77件しか成功しなかった。これは「ターゲット数＝被害数ではない」という重要な事実を示しています。

### 使われた悪意のあるツール

**「down.php」（メインのウェブシェル）**
- **4重の難読化**（コードを読めなくする処理）が施されており、セキュリティソフトに検知されにくくなっています
- 中国製のオープンソースウェブシェル「BestShell」をベースに作られています
- できることは以下の通り：
  - ファイルの操作・盗み見
  - サーバー上でのコマンド実行
  - ネットワーク内部への侵入拡大
  - セキュリティソフトの確認

**「SNOWLIGHT + VShell」（攻撃者自身のリモートアクセス用）**
- VShellというツールは、プロセスの名前を **`[kworker/0:2]`** というLinuxシステムの正規のプロセスに偽装して隠れます
- これは家に泥棒が入って、住んでいる人の家族のふりをしているようなものです

> 🔍 **注目ポイント**: このSNOWLIGHT→VShellという攻撃の組み合わせは、2025年4月に中国の国家支援ハッカーグループ「**UNC5174**」との関連が指摘されていました。ただし、VShell自体は広く一般に使われるツールなので、断定はできません。

## なぜ重要なのか

### 📊 数字のカラクリに注意！

「**140万サイトが標的に！**」という見出しは怖く聞こえますが、実態は異なります：

- **140万件** → 攻撃者が用意した「ターゲットリスト」の数（スキャンしただけ）
- **25,195件** → 実際に侵害されたと確認されたサイト数（Ctrl-Alt-Intel調べ）
- **5,700件以上** → 現在も生きているウェブシェルが確認されたサイト数（SOCRadar調べ）

> 💡 **大切な教訓**: 「スキャンされた＝ハッキングされた」ではありません！セキュリティニュースの「大きな数字」には、常に注意して読む必要があります。

### 🏪 「アクセス権の転売市場」という問題

このグループが怖いのは、単にサイトに侵入するだけでなく、その**侵入済みサイトへのアクセス権をダークウェブで売買している**点です。つまり：

- 最初に侵入したグループとは別の犯罪者が、そのサーバーを使って
  - ランサムウェア（身代金要求型ウイルス）を展開したり
  - 個人情報を盗んだり
  - フィッシングサイトを作ったり
  
することができてしまいます。被害のサイクルが広がりやすいのです。

## 対策・今後の展望

### ✅ WordPressサイト管理者向けチェックリスト

**今すぐ確認してください！**

- [ ] **プラグインを最新版に更新する**（特にBreezeプラグインをお使いの方は必須）
- [ ] **Breezeプラグインの設定を確認する**：「Host Files Locally – Gravatars」という設定がオンになっていたら要注意（この設定がオンのサイトのみ脆弱）
- [ ] **Joomlaを使っている場合はJCE Editorを更新する**
- [ ] **使っていないプラグインは削除する**（脆弱性を減らすため）
- [ ] **ファイルの変更を監視する仕組みを導入する**（不審なファイルが追加されたら気づけるように）
- [ ] **サーバーのログを確認する**（不審なアクセスがないか）

### 🛡️ 一般的なウェブセキュリティの教訓

1. **ソフトウェアは常に最新に保つ**（スマホのアップデートと同じ感覚で）
2. **使わないサービスは放置しない**（攻撃者も同じミスをしていた）
3. **セキュリティスキャンを定期的に実施する**
4. **WAF（ウェブアプリケーションファイアウォール）を導入する**

### 🔮 今後の動向

このグループの活動が詳しく分析されたことで、セキュリティ企業や研究者が対策を強化しています。使われたウェブシェルの特徴（シグネチャ）が公開されたため、セキュリティソフトによる検出がしやすくなっています。ただし、攻撃者側もすぐにツールを変更するため、継続的な監視が重要です。

## 過去記事との関連

以前、「**パッチなし！xquicの欠陥「xring」で、HTTPサーバーが遠隔からクラッシュさせられる**」という記事で、**パッチ（修正プログラム）が当たっていない脆弱性**の危険性について解説しました。

今回のWP-SHELLSTORM事件でも、**古いバージョンのプラグインの脆弱性**（すでに修正プログラムが存在するにもかかわらず更新されていないもの）が主な攻撃経路になっています。

共通するメッセージは明確です：「**既知の脆弱性に対するパッチ（更新）を怠ることが、実際の大規模被害に直結する**」ということです。

xquicの記事ではサーバーをクラッシュさせる「妨害攻撃」でしたが、今回は**サイトに裏口を仕掛けて転売する「侵入・収益化攻撃」**と、被害の形は違えど、「更新を怠る」という同じ根本原因がある点で深く関連しています。

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **WordPress** | ワードプレス | 世界で最も使われているウェブサイト作成ソフト |
| **Joomla** | ジュームラ | WordPressと同様のウェブサイト作成ソフト |
| **プラグイン** | ぷらぐいん | ソフトウェアに機能を追加する小さなプログラム（スマホのアプリに相当） |
| **ウェブシェル** | うぇぶしぇる | サーバーに仕込む遠隔操作用の悪意のあるスクリプト |
| **バックドア** | ばっくどあ | 正規の手続きを経ずに侵入できる「隠し通路」 |
| **脆弱性（CVE）** | ぜいじゃくせい | ソフトウェアのセキュリティ上の欠陥・穴 |
| **難読化** | なんどくか | コードを読めなくして解析を困難にする処理 |
| **FOFA** | フォーファ | インターネットに公開されているシステムを検索できる中国製の検索エンジン（Shodan類似） |
| **SOCRadar** | ソックレーダー | 脅威インテリジェンス（サイバー攻撃情報の収集・分析）を提供するセキュリティ企業 |
| **UNC5174** | ユーエヌシー5174 | 中国の国家支援を受けていると疑われるハッカーグループ |
| **アクセス・ブローカー** | あくせすぶろーかー | 不正侵入したシステムへのアクセス権を他の犯罪者に売る「転売業者」 |
| **VShell** | ブイシェル | プロセス名を偽装して隠れる遠隔操作ツール |
| **SNOWLIGHT** | スノーライト | VShellをインストールするための「ドロッパー」プログラム |
| **WAF** | ワフ | Web Application Firewall。ウェブへの不正なアクセスを遮断する防壁 |

> 💬 **まとめ**: ハッカー自身の「うっかりミス」から、大規模なサイト侵害作戦の全貌が明らかになりました。WordPressを使っているなら、**プラグインの更新を怠らない**ことが最大の防御です。「140万件が標的」という数字に惑わされず、「実際に侵害されたのはその一部」という事実も冷静に読み取ることが、正しいセキュリティリテラシーです。
