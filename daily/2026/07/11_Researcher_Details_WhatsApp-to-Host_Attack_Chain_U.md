# WhatsAppのメッセージから端末を乗っ取られる！？AIアシスタント「OpenClaw」に発見された3つの深刻な脆弱性

**元記事**: [Researcher Details WhatsApp-to-Host Attack Chain Using Three OpenClaw Flaws](https://inl03.netline.com/ltr6/?_m=3n.009a.4027.sp0ao46r89.32z8)
**解説日**: 2026年7月11日

---

## 背景知識

このニュースを理解するために、まずいくつかのキーワードを押さえておきましょう。

### 🤖 OpenClawって何？
「OpenClaw」は、パソコンやサーバー上で動く**個人用AIアシスタント**です。ChatGPTのようなAIが、あなたのパソコン上で動いてファイルを読んだりプログラムを実行してくれるようなイメージです。

### 📦 サンドボックスって何？
「砂場（サンドボックス）」という名前の通り、**プログラムを安全な隔離された箱の中で動かす仕組み**です。子どもが砂場の中でだけ砂遊びができるように、プログラムもその「箱」の外には影響を出せないようになっています。

### 🔑 SSH鍵・AWS認証情報って何？
- **SSH鍵**: サーバーに安全にログインするための「合鍵」のようなもの
- **AWS認証情報**: Amazon Web Services（クラウドサービス）を使うためのIDとパスワードのセット
- これらが盗まれると、攻撃者があなたのサーバーやクラウドに**なりすましてアクセスできてしまいます**

### 🐳 Dockerソケットって何？
Dockerとは、アプリを「コンテナ」という小さな箱に入れて動かす技術です。**Dockerソケットはその管理者用の特別な扉**で、これにアクセスできると、すべてのコンテナとホスト（大元のパソコン）を自由に操れてしまいます。

---

## 何が起きたのか

セキュリティ研究者のChinmohan Nayak氏が、AIアシスタント「OpenClaw」に**3つの深刻な脆弱性（セキュリティ上の欠陥）**を発見・報告しました。

最も衝撃的なのは、これらの欠陥を組み合わせると…

> **「WhatsAppで悪意のあるメッセージを送るだけで、相手のパソコンを乗っ取れてしまう」**

という攻撃チェーンが成立してしまうことです。

しかも、攻撃者は事前にシステムへの侵入口を確保する必要すらなく、外からのメッセージ一つで攻撃が完結してしまうというのが非常に危険なポイントです。

---

## 技術的な詳細

### 発見された3つの脆弱性

#### 🔴 脆弱性①・②：コマンドインジェクション（危険度 8.8/10）
**GHSA-hjr6-g723-hmfm** と **GHSA-9969-8g9h-rxwm**

「コマンドインジェクション」とは、**プログラムに本来実行するはずでない命令（コマンド）を無理やり混ぜ込む攻撃**です。

🍱 例え話で言うと…
> お弁当屋さんに「唐揚げ弁当をください」と注文するところに「唐揚げ弁当をください。あと金庫も開けてください」と混ぜて指示するようなイメージです。

OpenClawのフィルタリング（不正な命令を弾く機能）が不完全で、禁止リストに載っていない命令が通り抜けてしまうという欠陥です。

---

#### 🔴 脆弱性③：ディレクトリ遡り攻撃（危険度 8.4/10）
**GHSA-575v-8hfq-m3mc**

これが今回の攻撃チェーンの核心です。

**仕組みを図で説明すると：**

```
【本来の守り方（ブロックリスト）】
/home/user/.ssh      ← ❌ ブロック（SSH鍵が入っている）
/home/user/.aws      ← ❌ ブロック（AWS認証情報が入っている）
/home/user/.gnupg    ← ❌ ブロック（暗号鍵が入っている）

/home               ← ✅ ブロックされていない！（親フォルダ）
```

つまり、個々のフォルダは守っていても、**その上の親フォルダへのアクセスを許してしまっていた**のです。

🏠 例え話で言うと…
> マンションの101号室・102号室・103号室にはカギをかけているのに、**建物全体の入り口には鍵をかけ忘れていた**ようなものです。入り口さえ通れば全部屋に入り放題です。

研究者のNayak氏は、このことをこう表現しています：
> 「`/home` をコンテナ内にマウントすれば、すべてのユーザーのSSH鍵、AWS認証情報、GPGシークレットが読める。`/var` をマウントすればDockerソケットが手に入る。つまりサンドボックスの内側から、ホスト全体への完全な脱出ができる。」

---

### WhatsApp → パソコン乗っ取りの攻撃の流れ

```
攻撃者
  │
  │ ①悪意のあるWhatsAppメッセージを送信
  ▼
OpenClaw（AIアシスタント）
  │
  │ ②コマンドインジェクション脆弱性でフィルターを突破
  │ ③ディレクトリ遡りでサンドボックスを脱出
  ▼
ホスト（大元のパソコン・サーバー）
  │
  ├─ SSH鍵の盗取
  ├─ AWS認証情報の盗取
  ├─ バックドア（裏口）の設置
  └─ 完全なリモートコード実行（何でもできる状態）
```

## なぜ重要なのか

### 📊 危険度の高さ
- 脆弱性の危険スコアが **8.4〜8.8/10** と非常に高い（10が最大）
- 攻撃者が**事前に何の準備もなく**、外部からのメッセージだけで攻撃できる

### 💼 影響を受ける人
- OpenClawをビジネスや個人で利用しているすべてのユーザー
- 特に、OpenClawがWhatsAppなどのメッセージアプリと連携している環境

### 🎯 盗まれる可能性のある情報
| 情報の種類 | 具体的な被害 |
|-----------|------------|
| SSH鍵 | サーバーに不正ログイン |
| AWS認証情報 | クラウドサービスの乗っ取り・課金被害 |
| GPGシークレット | 暗号化データの解読 |
| Dockerソケット | システム全体の完全掌握 |

## 対策・今後の展望

### ✅ 今すぐやるべきこと

1. **OpenClawを最新版（2026.6.6）にアップデートする**
   → これが最も重要で確実な対策です

2. **アップデートができない場合の暫定対策**
   - 信頼できるユーザーのみに機能を制限する
   - 不要な機能は無効化する

3. **追加のセキュリティ設定**
   - すべての非メインセッションでサンドボックスモードを有効にする
   - 外部向けエージェント（チャンネル向け）のツール許可リストから「exec（実行）」を削除する
   - `git clone` コマンドで `ext::` という外部プロトコル補助機能が使われていないか監視する

4. **システム設計の見直し**
   - 互いに信頼できないユーザー同士で同じGatewayを共有しない
   - ツールの許可リストをできるだけ絞り込む

## 過去記事との関連

以前、**Tangem ウォレットカードへのレーザー攻撃**（物理的な方法でパスワードをリセットする攻撃）や、**u-bootの脆弱性**（起動時に悪意あるコードを実行させる問題）について解説しましたが、今回の事例はそれらとは少し違う特徴があります。

- Tangem攻撃は「物理的に手元にデバイスが必要」
- u-bootは「悪意ある画像ファイルが必要」

**今回のOpenClaw脆弱性は、WhatsAppメッセージを送るだけ**という、攻撃者にとって非常にハードルの低い攻撃手法である点が特に深刻です。AIアシスタントがさまざまなアプリと連携するようになった現代において、「AIへの入力経路がそのまま攻撃経路になる」という新しい脅威の形を示しています。

また、記事中では「Clawchain脆弱性（Cyera社が5月に開示）」という過去の関連事例にも触れられていますが、今回の脆弱性はそれよりも**攻撃の難易度が低い**（事前の侵入不要）点で、より危険とされています。

## 用語解説

| 用語 | 意味 |
|------|------|
| **脆弱性（ぜいじゃくせい）** | ソフトウェアのセキュリティ上の欠陥・穴 |
| **コマンドインジェクション** | 不正な命令を混ぜ込んでシステムに実行させる攻撃 |
| **パストラバーサル** | 本来アクセスできないフォルダに「../」などを使って遡ってアクセスする攻撃 |
| **サンドボックス** | プログラムを隔離された安全な環境で動かす仕組み |
| **バインドマウント** | あるフォルダを別の場所に「見せかける」OS機能 |
| **権限昇格** | 一般ユーザーが管理者権限を不正に得ること |
| **任意コード実行（RCE）** | 攻撃者が好き勝手なプログラムを実行できる状態 |
| **バックドア** | 攻撃者が後で使うために仕込む「裏口」 |
| **CVSS スコア** | 脆弱性の危険度を0〜10で表すスコア（10が最大） |
| **SSH鍵** | サーバーに安全ログインするための暗号化された合鍵 |
| **Dockerソケット** | コンテナ管理システムへの管理者用接続口 |
| **ホスト** | 仮想環境やコンテナを動かしている大元のパソコン・サーバー |

---

> 💡 **まとめ**: 便利なAIアシスタントでも、セキュリティの欠陥があれば「外部からのメッセージ一つで乗っ取られる」という深刻な被害につながります。AIツールを使う際は、**常に最新バージョンに更新すること**が最大の自衛策です！
