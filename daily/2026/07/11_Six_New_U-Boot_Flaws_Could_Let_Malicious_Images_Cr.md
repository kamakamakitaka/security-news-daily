# U-Bootの新たな6つの欠陥 — 悪意ある画像がデバイスをクラッシュさせたり、起動時にコードを実行させる可能性

**元記事**: [Six New U-Boot Flaws Could Let Malicious Images Crash Devices or Run Code at Boot](https://inl03.netline.com/ltr6/?_m=3n.009a.4027.sp0ao46r89.32yw)
**解説日**: 2026年7月14日

---

## 背景知識

まず、この記事を理解するために必要な「コンピュータが起動するときに何が起きているか」を押さえておきましょう。

### コンピュータが起動するまでの流れ

パソコンやスマホの電源を入れると、いきなりWindowsやAndroidが動くわけではありません。実は**3段階**のプロセスがあります。

```
電源ON
  ↓
①【ブートローダー】が起動
  ↓
②【OS（オペレーティングシステム）】が起動
  ↓
③【アプリ・サービス】が動き始める
```

**ブートローダー**とは、「OSを呼び出す係」の小さなプログラムです。家に例えると、「玄関の鍵を開けて、住人を起こしに行く係」のようなものです。

### U-Bootとは何か？

**U-Boot（ユーブート）**は、世界中のさまざまな機器で使われているオープンソース（誰でも使えるように公開された）のブートローダーです。

- 🏠 家庭用Wi-Fiルーター
- 📷 防犯カメラ・スマートカメラ
- 🖥️ データセンターのサーバー管理チップ
- 📱 組み込み機器（工場の機械など）

パソコン以外の「賢い電子機器」の多くに入っています。2013年ごろから使われており、非常に多くの製品に組み込まれています。

### 「署名チェック」とは？

U-Bootには重要な安全機能があります。OSを読み込む前に「このソフトウェアは本物か？」を確認する**デジタル署名チェック**です。

> 💡 デジタル署名 = 「このソフトは正規メーカーが作ったものですよ」という電子的な証明書

本来は、署名チェックに合格したソフトだけを起動させることで、ウイルスが入り込むのを防ぐ仕組みです。

## 何が起きたのか

セキュリティ専門会社の**Binarly（バイナリー）**が、U-Bootに**6つの新しい欠陥（バグ）**を発見しました。

### 6つのバグの種類

| バグID | 種類 | 危険度 |
|--------|------|--------|
| BRLY-2026-037 | コード実行（攻撃者のプログラムを走らせる） | ⚠️ 最高 |
| BRLY-2026-038 | コード実行（同上） | ⚠️ 最高 |
| BRLY-2026-039 | クラッシュ（機器を落とす） | 🔴 高 |
| BRLY-2026-040 | クラッシュ（機器を落とす） | 🔴 高 |
| BRLY-2026-041 | クラッシュ（機器を落とす） | 🔴 高 |
| BRLY-2026-042 | クラッシュ（機器を落とす） | 🔴 高 |

重要なポイントは、**「署名チェックが完了する前の段階で」これらのバグが発動する**ことです。

つまり、「本物かどうか確認する前に、偽物に攻撃される」という状況です。

## 技術的な詳細

少し難しいですが、できるだけわかりやすく説明します！

### そもそも何を読み込んでいるのか？ — FITイメージとは

U-Bootは **FIT（Flattened Image Tree＝フラット化イメージツリー）** という「起動に必要なファイルをまとめたパッケージ」を読み込みます。

> 📦 FITイメージ = OSの本体・設定ファイル・その他の部品を一つの箱にまとめたもの

この箱に「デジタル署名」が付いていて、U-Bootはその署名を確認してからOSを起動するはずです。

**今回の問題は、この「確認する処理の中」にバグがあった**ことです。

---

### コード実行バグ（BRLY-2026-037 / 038）の仕組み

このバグの根本原因は、**「おかしな値をチェックしないまま使ってしまう」**という処理ミスです。

#### 具体的に何が起きるか

```
U-Bootが壊れた（細工された）FITイメージを読み込む
  ↓
「ファイル名を調べる」処理（fdt_get_name）を呼び出す
  ↓
壊れたデータなので「ゼロ（null）」と「マイナスの長さ」が返ってくる
  ↓
⚠️ U-Bootはこの異常な値をチェックせずにそのまま使ってしまう！
```

**バグ037の場合：**
- ゼロ（nullポインタ）のアドレスにデータをコピーしようとする
- 「アドレス0番地」にアクセスできる機器では、**スタックバッファオーバーフロー**が発生
- 攻撃者のコードが動いてしまう

**バグ038の場合：**
- マイナスの長さを使ってメモリ上を「逆方向」に進んでしまう
- 重要な「帰り道の情報（リターンアドレス）」を上書きしてしまう
- 攻撃者のコードにジャンプさせられる

> 🏗️ 例え話：  
> 設計図に「部屋の広さ：マイナス5畳」と書いてあった。  
> 普通ならエラーにするが、チェックせずに施工しようとしたら、  
> 隣の部屋の壁を壊して別の場所に侵入できてしまった。

---

### クラッシュ系バグ（BRLY-2026-039〜042）の仕組み

これらは「機器を落とす」タイプです。コードは実行されませんが、機器が動かなくなります。

| バグ | 原因 |
|------|------|
| 039・041 | 攻撃者が指定したサイズや位置を信用して、データの範囲外を読みに行く |
| 040 | 古い形式のデータが返す「ゼロのアドレス（nullポインタ）」をそのまま使って落ちる |
| 042 | 深入れ子（マトリョーシカ人形のような構造）のデータで、処理が自分自身を延々と呼び出してスタック（作業メモリ）を使い切って落ちる |

> 🪆 バグ042の例え：  
> 「この箱を開けて」→「その中の箱を開けて」→「さらにその中の箱を...」  
> を延々と繰り返させて、U-Bootのメモリを全部使い切って倒す

## なぜ重要なのか

### ① ブートローダーの欠陥は「すべての土台」を崩す

ブートローダーはOSより先に動きます。ここが乗っ取られると：

```
ブートローダーが乗っ取られる
  ↓
悪意あるOSや悪意あるソフトを読み込ませられる
  ↓
ウイルス対策ソフトも、OSのセキュリティ機能も、何も見えない
  ↓
完全に支配された状態に
```

> 🏠 家の例え：  
> 玄関の鍵（ブートローダー）が偽物にすり替えられたら、  
> 部屋の中の鍵（OSのセキュリティ）をいくら強くしても意味がない

### ② 影響を受ける機器が膨大

このバグは**2013年から現在まで50以上のバージョン**に存在していました。U-Bootを使った製品は世界中に無数にあります。

### ③ 回復が非常に困難

ブートローダーが完全に乗っ取られた機器を修復するには、**物理的に機器を分解してメモリチップを書き直す**必要があります。リモートでの修復はほぼ不可能です。

### ④ リモートからの攻撃も可能な場合がある

今回の欠陥に直接触れるには「悪意ある画像を起動パスに置く」必要があります。通常は物理アクセスが必要ですが——

Binaryの以前の研究では、**Supermicroのサーバー管理チップ（BMC）**に対して、ネットワーク経由でリモートから悪意あるファームウェアを書き込める手法が示されていました。同じことが今回の欠陥でも起きる可能性があります。

## 対策・今後の展望

### 現状（2026年7月時点）

- ✅ U-Boot本体へのパッチ（修正）は**2026年6月に適用済み**
- ❌ ただし、次の安定版リリース（v2026.07）は4月に締め切られていたため、修正が**間に合わなかった**
- 📅 修正が含まれる次のバージョン **v2026.10** は**2026年10月リリース予定**

### 各立場での対応

#### 🏭 機器メーカー・開発者向け

> CVE番号（共通の脆弱性番号）がまだ割り当てられていないため、番号での追跡はできません。  
> **Binaryのアドバイザリーページのリンクから直接パッチを取得してください。**

- 公式リリースを待たず、今すぐアップストリーム（U-Boot本家）の修正コミットを適用する
- 各アドバイザリー（BRLY-2026-037〜042）のページのリンクを参照する

#### 🏠 一般ユーザー向け

- 自分では直接対処できない場合がほとんどです
- **ルーターやカメラなどのファームウェア更新通知を見逃さない**
- メーカーからアップデートが来たら、速やかに適用する
- 不要なリモート管理機能（外部からの管理画面へのアクセス）をオフにする

#### 🔍 当面の安心材料

現時点では**実際の攻撃での悪用は報告されていません**。また、攻撃のためには「悪意ある画像を起動パスに届ける」という手順が必要で、ハードルがゼロではありません。

## 過去記事との関連

以前、**Zimbraというメールシステムの深刻な脆弱性**（細工されたメールで悪意あるコードが実行される問題）や、**GitHubアカウントの乗っ取りによる悪意あるパッケージ配布**の事件を解説しました。

今回の記事と共通するテーマは**「信頼の連鎖（Chain of Trust）」への攻撃**です。

- Zimbraの件 → メールという「信頼できるはずの通信」を悪用
- GitHubの件 → 公式リポジトリという「信頼できるはずの配布元」を悪用
- **今回のU-Boot** → デジタル署名チェックという「信頼を確認する仕組みそのもの」の前段階を攻撃

どのケースも、「安全だと信じているもの」を狙う点が共通しています。セキュリティにおいて「信頼の土台」を守ることがいかに重要かを示すニュースが続いています。

## 用語解説

| 用語 | 説明 |
|------|------|
| **U-Boot** | 家電・ルーター・サーバーなど多様な機器で使われるオープンソースのブートローダー |
| **ブートローダー** | 電源ON後に最初に動く小さなプログラム。OSを呼び出す係 |
| **FITイメージ** | 起動に必要なファイルをまとめたパッケージ形式（Flattened Image Tree） |
| **デジタル署名** | 「このソフトは正規品です」という電子的な証明書 |
| **バッファオーバーフロー** | データの入れ物（バッファ）から溢れたデータが隣のメモリを上書きしてしまう現象 |
| **nullポインタ** | 「何も指していない」ことを表す特殊な値（ゼロ）。チェックせず使うと誤動作する |
| **スタック** | プログラムが作業中に一時的にデータを置く記憶領域 |
| **リターンアドレス** | 関数（処理のまとまり）が終わったあとに「どこに戻るか」を記録した情報 |
| **ファームウェア** | 機器本体に書き込まれているソフトウェア（OSより低いレベルで動く） |
| **CVE** | 脆弱性に割り当てられる共通の識別番号（例：CVE-2024-12345） |
| **アップストリーム** | ソフトウェアの「大元（本家）」のこと |
| **Binarly** | ファームウェアのセキュリティ分析を専門とするセキュリティ企業 |
| **BMC（Baseboard Management Controller）** | サーバーの電源が切れていても遠隔管理できる専用チップ |
| **概念実証（PoC）** | 「この脆弱性は実際に悪用できます」と示すためのサンプルコード・手順 |

---

> 💬 **まとめ**  
> U-Bootという「機器の起動を担う基礎プログラム」に、2013年から存在していた6つの欠陥が見つかりました。特に危険な2つは、セキュリティチェックが走る前に攻撃者のコードを実行させられるもので、発覚しにくく修復も困難です。修正版は10月リリース予定のため、機器メーカーは今すぐパッチを適用し、一般ユーザーはファームウェア更新を怠らないことが大切です。
