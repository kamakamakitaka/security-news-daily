# 緊急事態：Progress社がShareFileユーザーに「サーバーをシャットダウンせよ」と命令

**元記事**: [URGENT - Progress Tells ShareFile Customers to Shut Down Storage Zone Controllers Over Security Threat](https://inl03.netline.com/ltr6/?_m=3n.009a.4027.sp0ao46r89.32ye)
**解説日**: 2025年7月11日

---

## 背景知識

このニュースを理解するために、まずいくつかの仕組みを説明しましょう。

### ShareFileってなに？

**ShareFile**は、企業が使うファイル共有サービスです。Googleドライブのビジネス版と思ってください。もともとCitrix（サイトリックス）という会社が作り、2024年にProgress Software（プログレス・ソフトウェア）という会社が買収しました。

### Storage Zone Controller（ストレージゾーンコントローラー）ってなに？

ShareFileには2つの使い方があります。

```
【パターン①：クラウドのみ】
ファイル → ShareFileのクラウド（インターネット上）
           ↑ 普通の使い方。今回は影響なし。

【パターン②：Storage Zone Controller使用】
ファイル → 自社のサーバー（Storage Zone Controller）
               ↕ ShareFileのクラウドと連携
           ↑ 今回の問題はここ！
```

**Storage Zone Controller（SZC）** は、会社が自分のオフィス内に設置するサーバーです。「ファイルは自社で管理したいけど、ShareFileの便利な機能も使いたい」という企業が使います。銀行や病院など、セキュリティ要件が厳しい企業に多いタイプです。

このサーバーは**インターネットから直接アクセスできる場所**に置かれることが多く、便利な反面、攻撃者からも狙われやすいという弱点があります。

### 「シャットダウンせよ」という命令の重大性

通常、セキュリティの問題が見つかった場合、企業は「修正プログラム（パッチ）を当ててください」と言います。しかし今回はそうではなく、**「すぐにサーバーを停止せよ」** と命令しました。これは非常に異例で深刻な事態を示しています。

## 何が起きたのか

### 事件の流れ

1. **Progress社が「信頼できる外部からのセキュリティ脅威」を把握**
   - 具体的な脅威の内容は未公表
   - 誰が背後にいるかも不明

2. **影響を受けるアカウントへのアクセスを一時的に無効化**
   - "念のため"として実施

3. **Storage Zone Controllerを使っている顧客にメールで通知**
   - 「Windowsサーバーをシャットダウンしてください」と指示

4. **顧客がそのメールをReddit（掲示板サイト）に投稿して公になった**（2025年7月10日）

5. **Progress社がステータスページで障害を認め、調査中と発表**

現時点では、**不正アクセスやデータ漏洩の証拠はない**とProgress社は述べています。ただし、「サーバー内で何も起きていない」とまでは言っていません。言葉を非常に慎重に選んでいる点が気になります。

---

## 技術的な詳細

### なぜ「パッチを当てろ」ではなく「シャットダウンせよ」なのか？

これが今回の核心です。

```
【通常の対応】
脆弱性発見 → 修正プログラム作成 → 「パッチを適用してください」

【今回の対応】
脅威を把握 → まだ修正プログラムがない？ → 「とにかく止めてください！」
```

「シャットダウン命令」が出た理由として考えられるのは：

| 可能性 | 説明 |
|--------|------|
| **ゼロデイ脆弱性** | まだ修正方法が見つかっていない新しい欠陥 |
| **盗まれた認証情報** | パッチでは解決できない「鍵の盗難」的な問題 |
| **Progress社側の問題** | サービス提供側に何らかの異常がある |

### 攻撃者が狙うポイント

Storage Zone ControllerはWindowsサーバー上で動くソフトウェアで、インターネットに面した場所に設置されます。攻撃者にとっては以下の理由で魅力的なターゲットです：

- 🎯 インターネットから直接アクセス可能
- 🎯 企業の重要なファイルが保存されている
- 🎯 過去にも同様の脆弱性が存在した実績がある

### 確認すべき不審なサイン

記事では、もしSZCを運用している場合に確認すべきことが書かれています：

- **`.aspx`ファイル**（ウェブアプリのファイル）が見覚えのない場所にないか
  - 攻撃者がサーバーを乗っ取った際に残す「バックドア（裏口）」の可能性
- **ログ（操作記録）**の保存と確認

## なぜ重要なのか

### 影響を受ける対象

| 対象 | 影響 |
|------|------|
| クラウドのみのShareFileユーザー | **影響なし** |
| Storage Zone Controllerユーザー | **サービス停止中・要注意** |

### 深刻さのポイント

**① 修正方法がまだない（可能性が高い）**
パッチなしでシャットダウン命令が出るのは異例中の異例です。

**② 企業の重要データが対象**
SZCを使う企業は金融・医療・法律など、機密性の高いデータを扱う大企業が多いです。

**③ Progress社の"黒歴史"と重なる**
2023年、同社の別製品「MOVEit（ムーブイット）」が大規模なゼロデイ攻撃を受け、**2,700以上の組織**が被害を受けました。世界規模の大事件でした。今回も同様の事態になる可能性があります。

---

## 対策・今後の展望

### ✅ 今すぐやるべきこと（SZCユーザー向け）

**Step 1：シャットダウン命令に従う**
Progress社からの指示通り、Storage Zone Controllerをオフラインにする。「大げさじゃない？」と思っても、安全が確認されるまでは動かさないこと。

**Step 2：バージョンを確認する**
```
推奨バージョン：
- 5.x系 → 5.12.4以降
- 6.x系 → いずれかの6.xリリース
```
ただし、**これをやっても再起動の許可ではありません**。今回の脅威への対処かどうかは不明です。

**Step 3：インターネットからアクセスできる状態なら「インシデント対応」を開始**

インシデント対応とは、「事件が起きたかもしれない」という前提での調査・対応手続きのことです。

```
① ログを保存する（証拠保全）
② 不審な.aspxファイルがないか確認
③ 社内のセキュリティ担当または外部専門家に連絡
```

> ⚠️ 「サーバーが普通に動いているように見える＝安全」ではありません！
> 攻撃者は痕跡を消す技術を持っているため、見た目だけでは判断できません。

### 🔮 今後の展望

- Progress社が脅威の内容と再起動の条件を発表するまで待機が必要
- 最悪の場合、2023年のMOVEit事件のような大規模被害につながる可能性がある
- セキュリティ専門機関（CISAなど）からの追加情報に注目

## 過去記事との関連

今回の事件には、過去の重要な出来事との関連があります。

### 2023年：CVE-2023-24489（ShareFile/Citrix時代）

ShareFileがまだCitrixの製品だった2023年に、同じStorage Zones Controllerに**認証なしで攻撃できる脆弱性（CVE-2023-24489）** が発見・悪用されました。

> 💡「認証なし」＝ パスワードなしで攻撃できるということ。鍵のかかっていないドアから誰でも入れる状態です。

アメリカのサイバーセキュリティ機関CISAが「積極的に悪用されている」と警告し、Citrixはパッチ未適用のコントローラーをShareFileクラウドから切断しました。**今回のProgress社の対応とほぼ同じ手順です。**

### 2023年：MOVEit事件

Progress社（当時はまだShareFileを持っていなかった）の別製品「MOVEit Transfer」に存在したゼロデイ脆弱性が、**Clopランサムウェアグループ**によって悪用されました。2,700以上の組織が影響を受けた、史上最大規模のファイル転送ソフト攻撃のひとつです。

### 2025年4月：Storage Zone Controllerの重大な脆弱性2件

セキュリティ研究機関watchTowrが2025年4月にStorage Zone Controllerの深刻な欠陥2件を公開し、Progress社は3月にパッチを提供済みです。今回の脅威との関連はまだ不明です。

---

**まとめると、Progress社はShareFile買収後も含めて、重大なセキュリティ問題への対応が続いている状況です。** 今回の事件が過去のMOVEit規模になるかどうかは、今後の情報公開次第です。

## 用語解説

| 用語 | 読み方 | 説明 |
|------|--------|------|
| **ShareFile** | シェアファイル | Progress社が提供するビジネス向けファイル共有サービス |
| **Storage Zone Controller (SZC)** | ストレージゾーンコントローラー | 企業が自社内に設置するShareFile用サーバー |
| **Progress Software** | プログレス・ソフトウェア | ShareFileやMOVEitを持つアメリカのソフトウェア企業 |
| **脆弱性（ぜいじゃくせい）** | — | ソフトウェアに存在するセキュリティ上の欠陥・弱点 |
| **ゼロデイ脆弱性** | ゼロデイ | まだ修正プログラムが存在しない、発見されたばかりの脆弱性 |
| **パッチ** | — | ソフトウェアの欠陥を修正するプログラム。「修正プログラム」とも |
| **CVE** | シーブイイー | 脆弱性に付けられる世界共通の識別番号（例：CVE-2023-24489）|
| **CISA** | シーサ | アメリカのサイバーセキュリティ・インフラセキュリティ庁。日本のIPAに相当 |
| **MOVEit** | ムーブイット | Progress社のファイル転送ソフト。2023年に大規模攻撃の被害を受けた |
| **Clopグループ** | クロップ | ランサムウェア攻撃で知られるサイバー犯罪グループ |
| **インシデント対応** | — | セキュリティ事故が起きた（可能性がある）場合の調査・対処手順 |
| **バックドア** | — | 攻撃者が侵入後に残す「裏口」。後から自由に入れるようにするもの |
| **ログ** | — | システムの操作・通信記録。「誰がいつ何をしたか」の履歴 |
| **.aspxファイル** | ドットエーエスピーエックス | Windowsのウェブアプリで使われるファイル形式。不審な場所にあれば攻撃の痕跡の可能性 |
| **認証なし（Unauthenticated）** | — | パスワードなど本人確認なしに攻撃できること。非常に危険な状態 |
| **オフライン** | — | インターネットや社内ネットワークから切断された状態 |
