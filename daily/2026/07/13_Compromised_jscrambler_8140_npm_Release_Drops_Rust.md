# jscramblerパッケージへの不正侵入：インストールするだけで情報が盗まれる！

**元記事**: [Compromised jscrambler 8.14.0 npm Release Drops Rust Infostealer During Install](https://inl03.netline.com/ltr6/?_m=3n.009a.4028.sp0ao46r89.330g)
**解説日**: 2025年7月14日

---

## 背景知識

このニュースを理解するために、いくつかの重要な概念を先に説明します。

### 📦 npmパッケージとは？
プログラマーが使う「便利な部品の宅配便」のようなものです。世界中の開発者が作ったプログラムの部品（パッケージ）が「npm（Node Package Manager）」というサービスに登録されており、コマンド一発でダウンロードして自分のプログラムに組み込めます。

> **例え**: レシピ本を見て料理するとき、「市販のルー」を買ってくるようなイメージです。一から作らなくていい、既製品の部品を使います。

### 🔧 jscramblerとは？
JavaScriptというプログラム言語で書かれたコードを「読みにくくする（難読化する）」ツールです。自分のプログラムのソースコードが丸見えにならないよう、保護するために使われます。週に約15,800回ダウンロードされる、開発者に広く使われているツールです。

### 🏗️ CI（継続的インテグレーション）とは？
コードを変更するたびに自動でビルド（プログラムの組み立て）やテストをしてくれる自動化の仕組みです。企業の開発現場では、AWSやGoogle Cloudなど、本番環境へのアクセスキーをこの環境に保存していることが多くあります。

### 🦠 インフォスティーラーとは？
「情報を盗む（steal）」マルウェア（悪意あるソフト）のことです。パスワード、認証キー、ウォレット情報などを密かに収集して、攻撃者のサーバーに送信します。

---

## 何が起きたのか

2025年7月11日、人気のnpmパッケージ「**jscrambler**」のバージョン**8.14.0**が公開されました。しかし、このバージョンには**悪意のあるコードが仕込まれていました**。

😱 **最も怖いポイント：インストールするだけで攻撃が実行される！**

通常、マルウェアに感染するには「変なファイルをダウンロードして実行する」という操作が必要です。しかし今回は、`npm install jscrambler` というインストールコマンドを打つだけで、ウイルスが自動的に動き出します。

セキュリティ企業「**Socket**」は、このパッケージが公開されてからわずか**6分後**に危険を検知しました。しかし、その6分の間にダウンロードした人・システムは、すでに攻撃の被害を受けている可能性があります。

> **重要**: 前バージョン（8.13.0）には一切この問題はありません。

## 技術的な詳細

### 🎭 どうやって悪意あるコードが紛れ込んだのか

本来のjscramblerのGitHubリポジトリ（ソースコードの保管場所）には、バージョン8.14.0に対応するコード変更が**一切存在しません**。

つまり、**正規の開発者のnpmアカウントかビルドの仕組みが何者かに乗っ取られ**、勝手に偽バージョンが公開された可能性が高いです。

```
正規の流れ:  GitHub(コード変更) → レビュー → タグ付け → npm公開
今回の流れ:  ???               →           → npm公開 ← ここに不正侵入
```

### 🔩 攻撃の仕組みを段階的に解説

**① 偽バージョンに追加されたファイル**

パッケージの中に、こっそり2つのファイルが追加されていました：
- `setup.js`：実行役（小さなローダープログラム）
- `intro.js`：名前はJavaScriptっぽいですが、実態は**約7.8MBのウイルス本体**（Windows・macOS・Linux用の3種類が圧縮して格納）

**② プレインストールフックによる自動実行**

npmには「インストール前に特定のコードを実行する」機能（preinstall hook）があります。これを悪用し、インストールと同時にウイルスが動き出す仕掛けになっています。

> **例え**: 宅配ボックスに荷物が届いた瞬間、自動的にドアが開いて何者かが家に侵入するイメージです。

**③ ウイルスの動作**

```
インストール実行
  ↓
setup.jsが起動
  ↓
使用中のOS（Windows/Mac/Linux）を確認
  ↓
対応するウイルス本体を一時フォルダにランダムな名前で保存
  ↓
バックグラウンドで密かに実行開始
  ↓
情報を収集 → TLS暗号化通信で攻撃者サーバーへ送信
```

### 🎯 何が盗まれるのか

このウイルス（**Rustというプログラム言語で作られたインフォスティーラー**）が狙う情報は非常に広範囲です：

| カテゴリ | 具体的な標的 |
|----------|------------|
| ☁️ クラウド認証情報 | AWS・Azure・Google Cloudのアクセスキー |
| 💰 暗号通貨 | MetaMask・Phantom・Exodusのウォレット・シードフレーズ |
| 🔐 パスワード管理 | Bitwardenのパスワード保管庫 |
| 🌐 ブラウザ | 保存されたパスワード・Cookieすべて |
| 💬 コミュニケーション | Discord・Slack・Telegram・Steamのセッション情報 |
| 🤖 AIツール | Claude Desktop・Cursor・VS Code・WindsurfなどのAPIキー |

**特に開発者のAIツールを狙っているのが新しい傾向です！**  
最近の開発者はAIコーディングツールのAPIキーを設定ファイルに保存しており、そこも標的になっています。

### ⚡ さらに危険な機能：カーネルレベルへの侵入（Linux）

Linuxでは、ウイルスが「**eBPF**」という技術を使ってOSの核心部分（カーネル）に侵入する機能も持っています。

> **例え**: 普通の泥棒は家の中を荒らすだけですが、eBPFを使うと家の「配電盤」そのものを乗っ取れるイメージです。これにより、ファイルへのアクセスだけでなく、OS全体を監視・制御できる可能性があります。

### 🔄 再起動後も生き残る持続性（Persistence）

感染したらパソコンを再起動しても消えません：

- **Windows**: 「1分ごとに再起動する」隠しタスクを登録
- **macOS**: ログイン時に自動起動するLaunchAgentを設置

さらに、Torネットワーク（匿名通信網）を使った通信も確認されており、攻撃者の特定を困難にしています。

## なぜ重要なのか

### 🎯 「広く薄く」ではなく「狭く深く」を狙う攻撃

過去の大規模npmサプライチェーン攻撃（後述）では、何十億ものダウンロードを誇るパッケージが標的でした。しかし今回は週15,800ダウンロードと比較的小規模です。

**それでも危険な理由**：このパッケージは**開発者やCIサーバー**が使います。そこには…
- 本番環境のクラウドアクセスキー
- デプロイ用トークン（サーバーに変更を適用する権限）
- ソースコード全体

…が集まっています。1台の開発・CI環境に侵入できれば、その会社の**インフラ全体を乗っ取れる可能性**があります。

> **例え**: コンビニの全店舗を1店ずつ狙うのではなく、全店舗を管理する「本部のサーバー室」を1か所狙うイメージです。

### 🏭 サプライチェーン攻撃の脅威

今回の攻撃は「**ソフトウェアサプライチェーン攻撃**」と呼ばれるものです。

信頼している部品（パッケージ）に毒を盛ることで、その部品を使う全員を一度に攻撃できます。セキュリティの専門家が最も警戒している攻撃手法の一つです。

## 対策・今後の展望

### ✅ 今すぐできる確認・対策

**① バージョンを確認する**
```bash
# インストール済みのjscramblerのバージョン確認
npm list jscrambler
```
バージョン `8.14.0` が表示された場合は要注意！

**② 安全なバージョンに戻す**
```bash
npm install jscrambler@8.13.0
```

**③ 認証情報のローテーション（変更）**
もし`8.14.0`をインストールしてしまった場合は：
- AWSなどのクラウドのアクセスキーを即座に無効化・再発行
- パスワードマネージャーのマスターパスワードを変更
- ブラウザの保存パスワードを全変更
- Discord・Slack等のセッションを全てログアウト・再ログイン
- AIツールのAPIキーを再発行

**④ 開発チームへの共有**
CI/CDパイプラインでこのパッケージを使っていた場合は、チーム全体に即座に通知してください。

### 🔮 今後の展望

- jscramblerのnpmアカウントまたはビルドパイプラインへの不正アクセスの原因調査が続いています
- Linux上でのeBPFの具体的な動作についても解析が進められています
- このような攻撃を防ぐため、npmのセキュリティ強化（多要素認証の義務化など）が求められています

## 過去記事との関連

記事内では、過去の類似事件にも触れています。

- **Shai-Huludワーム事件（昨年9月）**: インストールフックからトークンを盗み、何百ものパッケージに感染を広げたワームです。今回と非常によく似た手口が使われています。

- **chalk・debugパッケージ乗っ取り事件**: 広く使われているパッケージのメンテナー（管理者）のアカウントがフィッシング詐欺（偽のメールなどで騙してパスワードを盗む手口）で乗っ取られ、暗号通貨の送金先が書き換えられた事件です。

今回の事件は、こうした**「信頼できるパッケージの乗っ取り」という手口が繰り返されている**ことを示しています。もはや「有名パッケージだから安心」という考えは通用しない時代です。

## 用語解説

| 用語 | 説明 |
|------|------|
| **npm** | Node.jsのパッケージ管理サービス。世界最大のソフトウェアパッケージ置き場 |
| **インフォスティーラー** | 情報を盗むマルウェア（悪意のあるソフトウェア） |
| **Rust** | パフォーマンスが高くセキュリティ意識の高いプログラム言語。ウイルスにも使われるようになっている |
| **preinstall hook** | パッケージインストール前に自動で実行されるスクリプト |
| **eBPF** | Linuxカーネル内でプログラムを直接動かせる高度な技術。本来は性能監視等に使う |
| **カーネル** | OSの核心部分。すべてのハードウェアやソフトウェアを管理する「司令塔」 |
| **TLS** | インターネット通信を暗号化する仕組み（HTTPSのS部分） |
| **サプライチェーン攻撃** | 信頼されたソフトウェアの部品・流通経路を狙う攻撃 |
| **CI/CD** | コードの変更を自動でビルド・テスト・デプロイする仕組み |
| **LaunchAgent** | macOSでログイン時に自動起動するプログラムの設定 |
| **シードフレーズ** | 暗号通貨ウォレットの回復に使う12〜24個の単語。これが漏れるとウォレット全喪失 |
| **Torネットワーク** | 通信を匿名化するネットワーク。攻撃者の追跡を困難にするために悪用される |
| **難読化（jscrambler本来の機能）** | ソースコードを読みにくくして、第三者に解析されにくくすること |

---

> 💡 **まとめ**: 今回の事件は「信頼しているツールを使うだけで感染する」という怖さを示しています。開発者はパッケージのバージョン管理を厳格に行い、インストール直後に不審な動作がないか確認する習慣が重要です。また、クラウドの認証キーは定期的に変更し、CIサーバーに必要以上の権限を与えないことも大切な対策です。
