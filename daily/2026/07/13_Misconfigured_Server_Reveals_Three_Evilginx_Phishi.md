# 設定ミスのサーバーが暴露した3つのフィッシング詐欺作戦 ～Microsoft 365を狙う攻撃者たちの素顔～

**元記事**: [Misconfigured Server Reveals Three Evilginx Phishing Operations Targeting Microsoft 365](https://inl03.netline.com/ltr6/?_m=3n.009a.4028.sp0ao46r89.330a)
**解説日**: 2026年7月14日

---

## 背景知識

このニュースを理解するために、いくつかのポイントを押さえておきましょう。

### Microsoft 365とは？
Wordや Excel、OutlookなどのOfficeアプリをクラウドで使えるサービスです。世界中の企業が仕事で使っているため、攻撃者にとっては「ここを乗っ取れば企業の機密情報が手に入る」超魅力的なターゲットです。

### MFA（多要素認証）とは？
パスワードだけでなく、「スマホへの通知を承認する」「ワンタイムパスワードを入力する」など**複数の方法で本人確認をする仕組み**です。  
「鍵が1本だとピッキングされやすいから、鍵を2本にする」イメージですね。

### フィッシング詐欺とは？
本物そっくりの偽のログインページに誘導して、IDやパスワードを盗む詐欺です。「釣り（fishing）」に例えられます。

### 「AiTM（Adversary-in-the-Middle）攻撃」とは？
攻撃者があなたとMicrosoftの「中間に入り」、やり取りをこっそり中継する攻撃です。  
郵便屋さんのふりをして手紙を開封し、中身を盗み見てから相手に渡す…そんなイメージです。MFAを設定していても突破できてしまう、厄介な手口です。

### Evilginxとは？
AiTM攻撃を自動化するための**オープンソース（誰でも使えるように公開された）ツール**です。もともとはセキュリティの研究用に作られましたが、悪用されてしまっています。

---

## 何が起きたのか

フランスのセキュリティ企業「Lexfo」が、インターネットを定期的に調査していたところ、**とあるサーバーがうっかり丸見えになっている**のを発見しました（2026年4月末）。

サーバーの場所はハンガリーのブダペスト（IPアドレス：185.163.204[.]7）。

このサーバーを調べると、驚くべきことが次々と判明しました。

- **攻撃者の作業履歴（コマンド履歴）がそのまま残っていた**
- **フィッシング詐欺のツール一式が丸ごとさらされていた**
- **盗んだIDや情報のログも残っていた**
- **攻撃者が使うTelegramのログインファイルまであった**

さらに、このサーバーから糸をたぐっていくと、**3つの別々のフィッシング詐欺グループ**が関与していることが明らかになりました。

### 3人の攻撃者たち

| ハンドル名 | 出身 | 手口の特徴 |
|---|---|---|
| **codemado** | エジプト | プロキシ型のAiTM攻撃 |
| **mail-argenta** | ナイジェリア | 高度にカスタマイズされたEvilginx |
| **saroula01** | 不明 | Microsoftの正規機能を悪用 |

## 技術的な詳細

### 🔑 発覚のきっかけ：「ディレクトリリスティング」のミス

攻撃者codemadoは、自分のサーバーで `python3 -m http.server 8080` というコマンドを実行したままにしていました。  
これは「ウェブサーバーを起動して、フォルダの中身を誰でも見られる状態にする」コマンドです。

🏠 **例えるなら...**  
泥棒が作業場（アジト）を持っているのに、「見学自由！扉全開！」の看板を出してしまったようなものです。

この操作履歴は `.bash_history`（コマンドの操作ログ）にも残っており、研究者たちはそこから全ての手がかりを得ました。

---

### 👤 攻撃者①「codemado」の手口

- **2018年**からVoIPやハッキングフォーラムで活動するエジプト人とみられる人物
- 「picis[.]net」というドメインでMicrosoft 365への攻撃プラットフォームを運営
- 「**MaDoO Blaster**」という自作の大量メール送信ツールで収益化
- 攻撃は2026年4月20日に開始。発覚後も継続していた
- **フランスと北米の企業アカウントを繰り返し攻撃**

---

### 👤 攻撃者②「mail-argenta」の手口（Evilginxを改造）

ナイジェリア人とみられるこの攻撃者は、Evilginxをかなり高度にカスタマイズしていました。

**改造のポイント：**
- ブラウザのセキュリティチェック（SRI：Subresource Integrity）を回避するためHTMLの属性名を変更
- URLの経路でフィッシングと検出されないよう書き換えエンジンを追加
- 被害者のメールアドレスをあらかじめ入力しておき、「途中で離脱する人」を減らす工夫

**最も怖いポイント：**  
盗んだMicrosoftのセッションクッキー（ログイン済みの証明書のようなもの）に**1年間の有効期限**をセットしていました。  

🍪 **クッキーって何？**  
「この人はちゃんとログインした人です」という証明をブラウザが保存しておく仕組みです。これを盗まれると、パスワードを変えても攻撃者がログインし続けられます。

実際に、そのリポジトリには**2027年6月30日まで有効な盗まれたクッキー**が残っていました。

また、この攻撃者自身も「インフォスティーラー」（情報を盗むマルウェア）の被害に遭っており、自分のパスワードがデータ漏洩リストに載っていたことが判明。しかもそのパスワードを複数の場所で使い回していたため、あっという間に身元が特定されました。

---

### 👤 攻撃者③「saroula01」の手口（最も巧妙）

この人物が使ったのは「**OAuth デバイスコードフロー攻撃**」という手法。3人の中で最も多くのアカウントを侵害していました。

**普通のAiTM攻撃と何が違うのか？**

通常のAiTM攻撃は「偽のMicrosoftログインページ」に誘導しますが、saroula01の手法は**本物のMicrosoftページを使わせます**。

🎮 **仕組みをわかりやすく説明すると...**

1. 攻撃者が「Microsoft Authenticator風」の偽ページを作る
2. 被害者に「このコード（デバイスコード）を `microsoft.com/devicelogin` に入力してください」と指示
3. 被害者は**本物のMicrosoftのページ**でMFAも含めてちゃんとログインする
4. しかしそのコードを生成したのは攻撃者なので、ログインの権限（トークン）が攻撃者の手に渡る

要するに「被害者に本物の作業をさせて、その結果だけを横取りする」恐ろしい手口です。  
被害者が「本物のMicrosoftのページで操作した」という事実があるため、非常に気づきにくいのが特徴です。

## なぜ重要なのか

### ①「MFAさえ設定すれば安全」は過信だった

今回の3つの攻撃は、どれもMFA（多要素認証）を**突破**しています。「MFAを設定しているから大丈夫」という思い込みは危険です。

### ②攻撃ツールは誰でも入手できる

EvilginxはGitHub（プログラムを公開・共有するサービス）から誰でも無料でダウンロードできます。今回の攻撃者3人は全員このツールを流用していました。技術力がなくても攻撃ができてしまう時代になっています。

### ③1年以上も気づかれずに活動していた

最大の攻撃グループは**1年以上**フィッシング詐欺を続けており、ターゲットは主に企業のメールアカウントでした。発覚後も攻撃を続けていたほど大胆です。

### ④攻撃者も失敗する…でも油断は禁物

今回は「設定ミス」という凡ミスで発覚しましたが、次の攻撃者は同じミスをしないかもしれません。

## 対策・今後の展望

### 企業・組織向けの対策

| 対策 | 説明 |
|---|---|
| **CAE（継続的アクセス評価）対応のポリシー設定** | クッキーが盗まれても、すぐ無効化できる仕組み |
| **FIDO2/パスキーの導入** | フィッシングに引っかからない物理キーや生体認証 |
| **条件付きアクセスポリシーの強化** | 「いつも使っていない場所からのログインは拒否」などのルール設定 |
| **デバイスコードフローの制限** | 必要ない場合は、そもそもこの認証方式を無効化する |
| **セッションの有効期間を短く設定** | クッキーが盗まれても、早く無効になるようにする |

### 個人でできる対策

- 🔍 不審なURLやページには絶対にIDとパスワードを入力しない
- 📱 「デバイスコードを入力してください」という指示には特に注意
- 🔑 重要なサービスは**パスキー（Passkey）**や**FIDO2対応の物理キー**を使う
- 🔄 パスワードの使い回しをしない（mail-argentaが自分のパスワードで身元を特定されたように、使い回しは致命的）

## 用語解説

| 用語 | 解説 |
|---|---|
| **Evilginx** | フィッシング攻撃を自動化するオープンソースツール。本来はセキュリティ研究用 |
| **AiTM（Adversary-in-the-Middle）** | 攻撃者が通信の中間に入り込み、ログイン情報を横取りする攻撃手法 |
| **MFA（多要素認証）** | パスワード以外の追加認証（スマホ通知・ワンタイムパスワードなど）で本人確認する仕組み |
| **セッションクッキー** | 「ログイン済み」であることを証明するブラウザに保存された情報。盗まれると不正ログインに使われる |
| **ディレクトリリスティング** | サーバーのフォルダ内のファイル一覧を外部から見られる状態。設定ミスで起きることが多い |
| **OAuth デバイスコードフロー** | テレビなどの入力しにくいデバイスでログインするための正規の認証方式。悪用される場合がある |
| **CAE（継続的アクセス評価）** | クッキーが盗まれた際でも、リアルタイムでアクセスを無効化できるMicrosoft 365の機能 |
| **.bash_history** | Linuxで実行したコマンドの履歴が自動保存されるファイル。今回はこれが証拠になった |
| **SRI（Subresource Integrity）** | Webページが読み込むファイルが改ざんされていないか確認するセキュリティ機能 |
| **インフォスティーラー** | パスワードやクッキーなどの情報を密かに盗み出すマルウェア（悪意あるソフト） |
| **RMM（Remote Monitoring and Management）** | 遠隔からPCを操作・管理するツール。正規のITツールだが悪用されることも |
| **FIDO2/パスキー** | フィッシングに引っかからない、次世代の安全な認証技術 |

---

> 💡 **まとめると...**  
> 攻撃者が「うっかりサーバーを丸見えにした」という凡ミスから、3つのフィッシング詐欺グループの実態が明らかになりました。MFAを突破する高度な技術が、誰でも使えるオープンソースツールで実現されている現実は、企業・個人問わず要注意です。特に「デバイスコードを入力してください」という指示には最大限警戒してください。
