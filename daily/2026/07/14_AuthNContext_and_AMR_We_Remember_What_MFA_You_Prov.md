# ログインの「質」を伝える仕組み：AMRとAuthnContextとは？

**元記事**: [AuthNContext and AMR, We Remember What MFA You Provided Last Summer!](https://inl03.netline.com/ltr6/?_m=3n.009a.4029.sp0ao46r89.331u)
**解説日**: 2025年7月15日

---

## 背景知識

まず、この記事を理解するための基礎知識をおさらいしましょう。

### 「ログイン」って実は奥が深い

私たちが普段スマホやPCでログインするとき、こんな方法を使いますよね？

- 📝 パスワードを入力する
- 📱 スマホに届く6桁のコードを入力する（ワンタイムパスワード）
- 👆 指紋や顔で認証する（生体認証）
- 🔑 ICカードや物理的なセキュリティキーを使う

これらは「認証方法」と呼ばれています。そして**複数の方法を組み合わせること**を「多要素認証（MFA）」といいます。

> 💡 **MFA（多要素認証）とは？**  
> 「パスワード＋スマホへのコード」のように、2種類以上の方法でログインすること。一つが漏れても、もう一つがあるから安全性が高まる仕組みです。

### 「シングルサインオン（SSO）」って何？

学校や会社では、一度ログインするだけで複数のサービス（メール・ファイル共有・出欠管理など）を使えることがありますよね。これが「シングルサインオン（SSO）」です。

> 💡 **例え：テーマパークのパスポート**  
> テーマパークで入口で一度チケットを確認してもらえば、園内のアトラクションを自由に回れる、あのイメージです。

## 何が起きたのか

今回の記事は「セキュリティ事件」の話ではなく、**ログインの仕組みを深く理解するための解説記事**です。

テーマは次の疑問です：

> **「ログインしたこと」だけでなく、「どうやってログインしたか」をシステム間で正確に伝えるにはどうすればいいの？**

インターネットが発展するにつれて、扱うデータがどんどん重要になりました。

| 昔のネット | 今のネット |
|---|---|
| 掲示板、チャット | 給与明細、医療記録、税務書類 |
| ログインできればOK | **どのレベルの認証か**が重要 |

「パスワードだけでログイン」と「ICカード＋指紋でログイン」は、**結果（ログイン成功）は同じでも安全性が全然違う**のに、昔のシステムはその違いを伝える方法を持っていませんでした。

そこで登場したのが、**AuthnContext（SAML）** と **AMR／ACR（OpenID Connect）** という仕組みです。

## 技術的な詳細

### 登場人物を整理しよう

```
【主な登場人物】
・SAML（サムル）       → 企業・学校向けのログイン連携の規格（古め）
・OpenID Connect       → 現代のWeb・スマホ向けのログイン連携の規格（新しめ）
・AuthnContext         → SAMLが使う「認証の説明書」
・AMR                  → OpenID Connectが使う「使った認証方法リスト」
・ACR                  → OpenID Connectが使う「認証の強さレベル」
```

---

### ① AuthnContext（SAML）：認証の「説明書」

SAMLは主に企業や大学のSSOで使われる規格です。その中の **AuthnContext（認証コンテキスト）** は、ログインがどんな方法で行われたかをシステムに伝えます。

> 💡 **空港のセキュリティで例えると...**
>
> 「この人は保安検査を通過しました」だけでなく、  
> 「一般レーン」「顔認証ゲート」「追加書類チェックあり」まで伝える、  
> そんな詳細な情報カードのようなものです。

この情報をもとに、アクセスできるサービスや操作の範囲を変えることができます。

---

### ② AMR（Authentication Methods References）：使った方法の「リスト」

OpenID Connectは、スマホアプリやクラウドサービスに対応した現代的な規格です。その中の **AMR（認証方法への参照）** は、ログインに使った方法を短いコードで表します。

| コード | 意味 |
|---|---|
| `pwd` | パスワード |
| `otp` | ワンタイムパスワード（SMSや認証アプリのコード） |
| `fpt` | 指紋認証 |
| `hwk` | ハードウェアキー（物理的なセキュリティキー） |

これらのコードは **RFC 8176** という国際標準で定められており、世界中のシステムが同じ言葉で話せるようになっています。

> 💡 **共通言語の大切さ**  
> たとえば日本語で「一時パスワードを使った」と書いても、海外のシステムには伝わりません。`otp`という共通コードがあれば、どの国のシステムも理解できます。

---

### ③ ACR（Authentication Context Class Reference）：認証の「強さレベル」

AMRが「何を使ったか」なら、**ACR（認証コンテキストクラス参照）** は「どれくらい強い認証か」を表します。

> 💡 **わかりやすい例え：スポーツのランク**
>
> 柔道で「黒帯」という結果は同じでも、「練習方法（AMR）」は人によって違います。  
> でも「黒帯レベル（ACR）」という基準さえ満たせば、試合に出られる。  
> そんなイメージです。

```
【具体例】
「レベル2の認証」を要求するサービスがある場合...

・A社：パスワード + SMSコード → レベル2達成 ✅
・B社：パスワード + 指紋認証   → レベル2達成 ✅

方法（AMR）は違うけど、レベル（ACR）は同じ！
```

---

### 全体の流れをまとめると

```
ユーザーがログイン
        ↓
認証プロバイダー（例：Googleや学校のシステム）が認証する
        ↓
「どうやって認証したか」をAMR/ACR/AuthnContextで記録
        ↓
各サービスに「ログイン済み＋認証の質の情報」を伝える
        ↓
サービスが「この認証の強さなら、この操作を許可しよう」と判断
```

## なぜ重要なのか

### 「ログイン＝OK」ではもう通用しない時代

たとえば、給与の振り込み先を変更する操作と、お知らせを閲覧する操作では、必要なセキュリティレベルが全然違いますよね。

```
【悪い例：認証の質を無視したシステム】
パスワードだけでログイン ─→ 給与振込先の変更ができてしまう 😱

【良い例：認証の質を考慮したシステム】
パスワードだけ → お知らせの閲覧だけOK
パスワード + 指紋 → 給与振込先の変更もOK 👍
```

AMR/ACRやAuthnContextがあることで、**「認証の強さ」に応じた細かいアクセス制御**ができるようになります。

### リスクの高い操作に「再認証」を要求できる

ネットバンキングでよくある「送金の前にもう一度パスワードを入力してください」というやつ、あれもこの考え方の応用です。

## 対策・今後の展望

この記事は攻撃に関するニュースではないため、「防御方法」というよりも**「良いシステム設計のヒント」**として読むのがポイントです。

### システムを作る・選ぶ立場の人へ

✅ **認証の強さに応じたアクセス制御を設計する**  
　単に「ログインしているか」だけでなく、「どの認証方法を使ったか」で制御を変える

✅ **高リスクな操作には強い認証を要求する**  
　個人情報の変更・支払い・管理者操作などは、強い認証（MFA）を必須にする

✅ **標準規格（AMR/ACR/AuthnContext）を活用する**  
　独自の仕組みを作るより、国際標準を使うことで他システムとの連携がスムーズになる

### 一般ユーザーとして意識すること

🔐 重要なサービスでは必ず **多要素認証（MFA）を設定する**  
　パスワードだけでは「弱い認証」として扱われる時代になっています。

## 用語解説

| 用語 | 読み方 | 意味 |
|---|---|---|
| **MFA** | エムエフエー | 多要素認証。パスワード＋別の方法を組み合わせるログイン方式 |
| **SSO** | エスエスオー | シングルサインオン。一度のログインで複数サービスを使える仕組み |
| **SAML** | サムル | 主に企業・学校向けのSSO規格。XMLという形式を使う |
| **OpenID Connect** | オープンアイディーコネクト | 現代的なSSO規格。スマホやWeb APIに適している |
| **AuthnContext** | オースンコンテキスト | SAMLで使われる「どんな認証をしたか」の情報 |
| **AMR** | エーエムアール | OpenID Connectで使われる「使った認証方法のリスト」 |
| **ACR** | エーシーアール | OpenID Connectで使われる「認証の強さのレベル」 |
| **RFC 8176** | アールエフシー8176 | AMRの値を世界共通で定めた国際標準文書 |
| **OTP** | オーティーピー | ワンタイムパスワード。一度しか使えない使い捨てのパスワード |
| **IAM** | アイエーエム | Identity and Access Management（アイデンティティとアクセスの管理）の略 |
| **OAuth** | オーオース | アプリ間でアクセス権限を安全に渡すための仕組み |

---

> 🎯 **今回のポイントまとめ**
> - ログインは「できた・できない」だけでなく、**「どうやってログインしたか」が重要**な時代
> - AMR・ACR・AuthnContextは、その「ログインの質」をシステム間で正確に伝えるための仕組み
> - 重要な操作ほど、強い認証（指紋・ハードウェアキーなど）を要求する設計が求められる
> - 一般ユーザーとしては、**MFAの設定**がいちばん手軽で効果的な対策！
