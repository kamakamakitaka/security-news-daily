# PenteraがAIセキュリティを「本物の証拠」で強化する仕組み

**元記事**: [How Pentera Turns AI Security Workflows into Validation Engines](https://inl03.netline.com/ltr6/?_m=3n.009a.4029.sp0ao46r89.3316)
**解説日**: 2025年7月

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえましょう。

### 🏢 企業のセキュリティ管理ってどんなもの？

大きな会社のITシステムは、まるで「大きな城」のようなものです。その城には、たくさんの入口（ネットワーク、クラウド、社員のアカウントなど）があり、セキュリティチームは「どこかに穴が開いていないか？」を常にチェックしています。

### 🤖 AIがセキュリティに使われ始めた

最近では、AIが「どの穴が危ないか？」を自動的に判断して、セキュリティ担当者に教えてくれるようになりました。でも、ここに大きな問題があります。

### 🔍 「脆弱性スキャナー」とは？

「脆弱性スキャナー（ぜいじゃくせいスキャナー）」とは、システムの弱点を自動的に探し出すツールです。健康診断で血液検査をするように、システムを検査して「ここが弱い！」という箇所をリストアップします。

ただし、スキャナーは「弱点の一覧」を出すだけで、**「実際に攻撃者がそこから侵入できるか？」は教えてくれません**。

### 🧩 CVSS スコアとは？

CVSSスコアとは、脆弱性（セキュリティの弱点）の危険度を0〜10点で表した数値です。10点に近いほど危険とされています。でも、「スコアが高い＝必ず危険」とは限らないことが、この記事のポイントです。

---

## 何が起きたのか

セキュリティ企業の **Pentera（ペンテラ）** が、AIセキュリティの「大きな弱点」を解決しようとしている、というニュースです。

### 現状の問題：AIが「推測」で動いている

現在、多くの企業では次のような流れでセキュリティ対策をしています。

```
スキャナーが弱点を発見
    ↓
AIが「これが危ない！」とランク付け
    ↓
セキュリティ担当者が対応
```

一見よさそうに見えますが、実はこれには大きな落とし穴があります。

### 具体例で考えてみましょう

学校の建物で例えると…

| AIが言うこと | 実際の状況 |
|------------|-----------|
| 「3階の窓が開いてる！危険！」| でも3階には鍵のかかった鉄格子がある → 実は侵入できない |
| 「1階の窓も開いてる（危険度：中）」| でも実は外から直接入れて、さらに職員室にも繋がっている → 超危険！ |

つまり、**「危険そうに見えるもの」と「本当に危険なもの」が違う**ことがよくあるんです。

## 技術的な詳細

### 🔗 攻撃者は「弱点をつなげて」侵入する

攻撃者はひとつの大きな穴から侵入するとは限りません。むしろ、**小さな穴をいくつもつなげて**、最終的に重要なシステムへたどり着きます。

```
小さな脆弱性A → 社員アカウントを乗っ取る
        ↓
社員アカウントを使って内部ネットワークへ
        ↓
内部ネットワークから別のシステムへ侵入
        ↓
最終的に機密データを盗む 😱
```

これを**「攻撃チェーン（アタックパス）」**と呼びます。

### 🛡️ Penteraが提案する「バリデーション（検証）」

Penteraは「スキャンして終わり」ではなく、**「実際に攻撃してみて、本当に侵入できるか確認する」**アプローチを取ります。

これを「**ペネトレーションテスト（侵入テスト）**」と言います。白衣のお医者さんではなく、**「ニセの泥棒さんを雇って、本当に家に入れるか試してもらう」**イメージです。

Penteraが実際の攻撃テストで確認すること：

```
✅ どんな攻撃手法が使われたか
✅ どのシステムに到達できたか
✅ どんなパスワードが入手できたか
✅ どんな権限（管理者権限など）が取れたか
✅ どの大事なデータが危険にさらされているか
✅ 最終的に何が達成できたか
```

### 🤝 MCPサーバーって何？

記事の後半で「MCP（Model Context Protocol）サーバー」という話が出てきます。

これは、**PenteraのテストデータをAIアシスタントが直接読めるようにする「橋渡し役」**です。

```
Penteraのテスト結果
    ↓（MCPサーバーが橋渡し）
AIアシスタントが参照
    ↓
「このセキュリティホールは実際に使われます、
  今すぐ修正してください！」と根拠ある提言
```

## なぜ重要なのか

### ⏰ 時間と労力の無駄遣いを防ぐ

セキュリティチームは毎日、膨大な数の「警告」を処理しています。実際には危険じゃない警告に時間を使っていると、**本当に危険な脆弱性への対応が遅れてしまいます**。

### 📊 AIの「推測」から「証拠」へ

| 今まで | Pentera導入後 |
|-------|-------------|
| AIが危険そうなものを推測 | AIが実際に危険と証明されたものを提示 |
| 「たぶんこれが危ない」 | 「これは実際に攻撃できると確認済み」 |
| 対応の優先度が曖昧 | 対応の優先度が明確 |

### 🔄 ワークフローの変化

```
【今まで】
見つける → 推測する → 優先順位付け → チケット発行

【Pentera後】
検証する → 証明する → 優先順位付け → 修正する → 再テスト
```

「修正後にまたテストする」という**サイクル**が生まれるのが特に重要です。

## 対策・今後の展望

### 企業のセキュリティ担当者へ

1. **スキャンだけで満足しない**
   脆弱性スキャナーの結果は「調査の入口」。「本当に攻撃できるか？」まで確認することが大切です。

2. **攻撃チェーンを意識する**
   ひとつの弱点だけ見るのではなく、「複数の弱点がつながったら？」という視点を持ちましょう。

3. **AIには根拠あるデータを与える**
   AIは賢いですが、入力データの質に結果が左右されます。「検証済みの証拠」をAIに渡すことで、初めて信頼できる提言が得られます。

### 今後の業界の動き

- AIがセキュリティに深く関わる流れは止まらない
- 「AIによる自動検証」の重要性がさらに高まる
- 攻撃者もAIを使うようになるため、**防御側もAI×実証テストの組み合わせ**が標準になっていく可能性が高い

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **脆弱性（ぜいじゃくせい）** | ぜいじゃくせい | システムのセキュリティ上の弱点・穴 |
| **バリデーション** | ばりでーしょん | 「本当に正しいか？」を実際に確認・検証すること |
| **ペネトレーションテスト** | ぺねとれーしょんてすと | 許可を得た上で実際に攻撃を試みて、セキュリティを検証するテスト |
| **CVSS スコア** | シーブイエスエス | 脆弱性の危険度を0〜10で表した国際的な指標 |
| **アタックパス（攻撃チェーン）** | あたっくぱす | 攻撃者が複数の弱点をつなげて目的を達成するルート |
| **スキャナー** | すきゃなー | システムの弱点を自動的に探し出すツール |
| **MCP（Model Context Protocol）** | えむしーぴー | AIがさまざまなデータソースに接続するための通信規格 |
| **リメディエーション** | りめでぃえーしょん | 脆弱性を修正・対処すること |
| **クラウド** | くらうど | インターネット経由で使うコンピュータ資源やサービス |
| **権限（特権アクセス）** | けんげん | システムで「何ができるか」を決めるアクセス許可の範囲 |

> 💡 **まとめると…**
>
> AIがセキュリティを助けてくれるのは良いことですが、「推測」ではなく「本当に攻撃できると証明されたデータ」をAIに与えないと意味がありません。Penteraは「実際に攻撃してみる」テストを行い、その結果をAIに渡すことで、セキュリティチームが本当に危ない穴を素早く修正できるようにしよう、という取り組みを進めています。
