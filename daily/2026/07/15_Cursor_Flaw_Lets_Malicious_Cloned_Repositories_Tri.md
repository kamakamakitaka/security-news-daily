# Cursorの欠陥：悪意あるクローンリポジトリがWindowsでコードを勝手に実行できる

**元記事**: [Cursor Flaw Lets Malicious Cloned Repositories Trigger Windows Code Execution](https://inl03.netline.com/ltr6/?_m=3n.009a.4030.sp0ao46r89.3332)
**解説日**: 2026年7月16日

---

## 背景知識

まず、このニュースを理解するために必要な言葉を整理しましょう。

### Cursor（カーソル）とは？
「Cursor」は、プログラマーがコードを書くための**AIアシスト付きエディタ（コード編集ソフト）**です。ChatGPTのようなAIが組み込まれており、「このコードを直して」とお願いするだけで自動でプログラムを修正・生成してくれる、今とても人気の開発ツールです。

### Gitとは？
「Git（ギット）」は、プログラムのソースコードを**バージョン管理する仕組み**です。「ファイルの変更履歴を記録して、チームで共有できるシステム」とイメージしてください。GitHubなどのサービスで公開・共有されています。

### リポジトリ（Repository）とは？
「リポジトリ」とは、**プロジェクトのファイルや履歴をまとめたフォルダ**のことです。GitHubで「誰かのプロジェクトをダウンロードする」ことを「クローン（clone）する」と言います。

### .exeファイルとは？
「.exe」はWindows上で**実行できるプログラムファイル**の拡張子です。ダブルクリックすれば起動します。でも今回の問題では、クリックすら不要でした……。

---

## 何が起きたのか

> 🚨 **一言まとめ**: Cursorで他人のプロジェクトを開くだけで、そのフォルダに仕込まれた悪意あるプログラムが**自動で実行されてしまう**欠陥が発見されました。

具体的な流れはこうです：

1. 攻撃者が `git.exe` という名前の**悪意あるプログラム**を、GitHubなどに公開しているプロジェクトのフォルダに紛れ込ませる
2. 被害者がそのプロジェクトをクローン（ダウンロード）して、Cursorで開く
3. **Cursorが自動的にその `git.exe` を起動してしまう**
4. 攻撃者のプログラムが被害者のパソコン上で実行される

重要なのは、**「開くだけ」で発動する**という点です。怪しいファイルをクリックした、ダブルクリックした、といった操作は一切不要です。

この脆弱性はセキュリティ企業「Mindgard（マインドガード）」が2025年12月15日に発見・報告しましたが、**2026年7月時点でもパッチ（修正プログラム）は存在しません。**

---

## 技術的な詳細

### なぜCursorは勝手に `git.exe` を起動するの？

Cursorはプロジェクトを開いたとき、「このプロジェクトがGitで管理されているか確認する」ためにGitコマンドを実行します。

このとき、Cursorは `git.exe` を**複数の場所から探します**。その探す場所の中に、**プロジェクトのフォルダ自身（ルートディレクトリ）**が含まれているのです。

```
Cursorがgitを探す順番（例）
1. システムのGitインストール先
2. 環境変数PATHに登録された場所
3. ⚠️ プロジェクトのフォルダ直下  ← ここが問題！
```

つまり、攻撃者がフォルダに `git.exe` という名前のファイルを置いておけば、**本物のGitより先に呼び出されてしまう**可能性があるのです。

### 実証実験（PoC）の内容

Mindgardが実際に試した方法は非常にシンプルです：

- **Windowsの電卓アプリ（Calculator）** を `git.exe` という名前に変えてプロジェクトに入れる
- GitHubにアップロードする
- クローンしてCursorで開く
- → 電卓が**自動でどんどん起動し続ける**

もちろん電卓は無害ですが、これが「パスワードを盗むプログラム」や「ランサムウェア（身代金要求ウイルス）」だったら？と考えると恐ろしいですね。

### 何をされる可能性がある？

プログラムはあなたのアカウントの権限で実行されるため：

| 危険なこと | 具体例 |
|-----------|--------|
| ソースコードの盗難 | あなたが書いているプログラムが全部盗まれる |
| SSHキーの盗難 | サーバーへの「鍵」が盗まれ、不正アクセスに使われる |
| クラウドトークンの盗難 | AWS・Azureなどクラウドサービスに不正ログインされる |
| ファイルの暗号化・削除 | ランサムウェアによる被害 |

しかも、プロジェクトを開いている間は**ずっと繰り返し実行され続ける**という特徴があります。

## なぜ重要なのか

### 「普通の行動」が攻撃のトリガーになる

開発者にとって「GitHubからプロジェクトをクローンしてCursorで開く」というのは**毎日何度もやる普通の作業**です。「怪しいメールの添付ファイルを開かなければ安全」という従来の常識が通用しません。

### AIコーディングツールの普及がリスクを拡大

CursorのようなAIエディタは今、世界中のエンジニアに急速に普及しています。つまり、**潜在的な被害者の数が非常に多い**ということです。

### 修正されていないのに公開された

Mindgardは**7ヶ月間**Cursorに対応を求め続けましたが、まともな返答がありませんでした。そのため技術的な詳細を公開することを決めました。これは「**責任ある脆弱性開示（Responsible Disclosure）**」の観点で議論を呼んでいます。

- Cursorは最初の報告をスコープ外（対応しなくていい問題）として却下
- Mindgardが異議を申し立てて再調査
- その後も2月・3月・4月と問い合わせを続けたが、返答なし
- CVE（共通脆弱性識別番号）も未割り当て

---

## 対策・今後の展望

### 現時点で使える対策（パッチがないため、すべて回避策です）

#### 🥇 最も安全な方法
**知らない人のリポジトリは、仮想マシン（VM）やWindows Sandboxで開く**

「Windows Sandbox」はWindowsに標準搭載されている使い捨て環境です。そこでCursorを使えば、悪意あるプログラムが実行されても本体のパソコンには影響しません。

#### 🔍 開く前にチェックする
クローンしたフォルダの中を確認し、以下のファイルが**あったら開かない**：

```
⚠️ 危険なファイル名（プロジェクトルートにあったら要注意）
- git.exe
- node.exe
- npx.exe
- where.exe
```

これらの実行ファイル（.exe）がプロジェクトの中にある理由は通常ありません。

#### 🏢 会社・学校のPC向け（管理者向け）
- **AppLocker** や **Windows App Control** という機能を使って、特定のフォルダ内の.exeファイルを実行禁止にする
- EDR（エンドポイント検知・対応）ツールで監視する

### 今後の展望

- Cursorがパッチを出すまで、この脆弱性は残り続ける
- CVEが割り当てられれば、業界全体での認知が広まる
- 同様の問題が他のAIコーディングエディタにも存在する可能性がある

## 用語解説

| 用語 | 意味 |
|------|------|
| **Cursor** | AIアシスト機能付きのコードエディタ（プログラミング用テキスト編集ソフト） |
| **Git** | プログラムのバージョン管理システム |
| **リポジトリ（Repository）** | プロジェクトのファイルと履歴をまとめたフォルダ |
| **クローン（Clone）** | GitHubなどからプロジェクトをまるごとダウンロードすること |
| **任意コード実行（RCE）** | 攻撃者が好きなプログラムを被害者のPCで動かせる状態。最も危険な脆弱性の一つ |
| **PoC（Proof of Concept）** | 「実際にこの脆弱性は悪用できますよ」と証明するためのデモプログラム |
| **パッチ** | ソフトウェアの欠陥を修正するためのアップデート |
| **CVE** | 脆弱性に付けられる世界共通の識別番号（例：CVE-2024-XXXX） |
| **SSHキー** | サーバーにログインするための電子的な「鍵」 |
| **クラウドトークン** | AWSなどのクラウドサービスを使うための認証情報 |
| **AppLocker** | Windowsの機能で、実行できるプログラムを制限できる |
| **EDR** | パソコンへの攻撃をリアルタイムで検知・対応するセキュリティツール |
| **Windows Sandbox** | Windowsに標準搭載の使い捨て仮想環境。閉じれば中の変化が消える |
| **責任ある開示** | 脆弱性を発見したとき、すぐ公開せず開発者に先に知らせて修正の機会を与えること |

---

> 💡 **今日の教訓**: 「知らない人のコードを開くだけで感染する」時代が来ています。GitHubから気軽にクローンする前に、ファイルの中身を確認する習慣をつけましょう。そして、怪しいリポジトリはサンドボックス環境で開くことが身を守る一番の方法です。
