# AIが加速させる広告タグの「承認ギャップ」問題とは？

**元記事**: [New Webinar: Closing the Approval Gap in AI-Era Ad Tech](https://inl03.netline.com/ltr6/?_m=3n.009a.4030.sp0ao46r89.332w)
**解説日**: 2025年7月16日

---

## 背景知識

まず、このニュースを理解するためにいくつかの基本的な仕組みを押さえておきましょう。

### 🏷️ マーケティングタグ（広告タグ）って何？
ウェブサイトには、訪問者の行動を分析したり、広告を表示したりするために「タグ」と呼ばれる小さなプログラム（JavaScriptコード）が埋め込まれています。例えば「このページを何人が見たか」「どのボタンを押したか」を計測するのに使われます。Google AnalyticsやSNSの「いいね」ボタンなども、広い意味ではこの一種です。

### 🧩 サードパーティ・フォースパーティって？
| 呼び方 | 意味 | 例え話 |
|--------|------|--------|
| **ファーストパーティ** | サイトの運営者自身が書いたコード | 家の住人 |
| **サードパーティ** | 承認した外部ベンダー（業者）のコード | 招いたお客さん |
| **フォースパーティ** | そのお客さんがさらに連れてきた人のコード | **お客さんが無断で連れてきた友達** |

ここが今回のニュースの核心です！

### 🤖 AIと広告テクノロジーの関係
最近の広告システムはAIを使って、ユーザーの好みに合わせた広告を「超高速」で切り替えたり、新しいデータの連携を自動で設定したりします。これが便利な反面、「どんなコードが動いているか把握しきれない」という問題を生み出しています。

---

## 何が起きたのか

セキュリティ企業「**Reflectiz**」と広告配信プラットフォーム「**Taboola**（タブーラ）」が共同で、ウェブサイトのセキュリティに潜む「**承認ギャップ（Approval Gap）**」という問題を解説するウェビナー（オンラインセミナー）を公開しました。

### 承認ギャップとは？
簡単に言うと、こういう状況です：

```
【よくある流れ】
セキュリティ担当者：「このAという広告タグ、安全か確認した。OK！」
                         ↓
実際にブラウザで動いていること：
  A（承認済み）→ Bを読み込む → CとDを読み込む → EとFとGを読み込む...
                    ↑
           誰も審査していない！
```

「承認したコード（A）」と「実際に動いているコード（A＋B＋C＋D...）」の**差（ギャップ）**が、セキュリティの抜け穴になっているのです。

## 技術的な詳細

### 🔗 タグの連鎖（チェーン）の仕組み

広告タグは、ロシアのマトリョーシカ人形のように、次々と別のスクリプトを呼び出す仕組みを持っています。

1. あなたのサイトが**承認した広告タグA**を読み込む
2. タグAが自動で**別の会社のタグB**を読み込む（これがサードパーティ）
3. タグBがさらに**タグCとD**を読み込む（これがフォースパーティ）
4. 気づけば、**誰も審査していないコード**がお客さんのブラウザ上で動いている

### 😱 これがなぜ怖いのか
ブラウザ上で動くこれらのコードは、**同じページにある全ての情報にアクセスできます**。つまり：

- 📝 入力フォームに打ち込んだ名前・住所・メールアドレス
- 💳 クレジットカード番号（決済ページ）
- 🛒 購入履歴・行動履歴

これらが「承認した覚えのないコード」にも筒抜けになる可能性があるのです。

### 🤖 AIがこの問題を加速させている理由
> 「AIを使った広告技術は、機械の速さで新しい連携・通信・データの流れを作り出すため、先月に承認したものが、もう存在しないシステムを指している可能性がある」

以前は担当者が手作業でタグを追加していたので変化がゆっくりでしたが、AIによって**タグの構成が自動で頻繁に変わる**ようになりました。一度審査してもすぐ陳腐化してしまうのです。

### 📊 深刻さを示すデータ
Reflectizの調査レポートによると：
> **小売業のセキュリティリスクの53%が、追跡ツールの過剰使用に起因している**

## なぜ重要なのか

### 組織の「縦割り問題」が生む隙間
この問題の根本には、**部署間の優先順位の違い**があります：

| 部署 | 最優先すること | 結果 |
|------|--------------|------|
| **マーケティング部門** | スピード・成果 | どんどんタグを追加する |
| **セキュリティ部門** | 安全・慎重な審査 | じっくり時間をかけて確認する |

この「承認ギャップ」に入り込んだ未確認のコードは**誰も責任者がおらず**、ファイアウォール（不正アクセスを防ぐ壁）や WAF（ウェブアプリケーション攻撃防御システム）をすり抜けてしまいます。なぜなら、「一時点での承認」は通過しているからです。

### 被害の規模
Taboolaは**毎日6億人のユーザー**・**9,000のパートナーサイト**に広告を配信しています。このような大規模なプラットフォームが関わるということは、一つの問題が世界中のサイトに波及する可能性があることを示しています。

## 対策・今後の展望

### ✅ 5つの必須質問（ベンダーに必ず聞くべきこと）
記事では、広告ベンダーに聞くべき5つの質問が紹介されています（詳細はウェビナー内）。最初の質問はこれです：

> **「あなたのタグは他にどんなコードを読み込みますか？それは誰が審査しましたか？」**

記事によると、今すぐベンダーに聞けば、ほとんどの場合**少なくとも1つには答えられない**とのこと。それ自体がリスクの指標になります。

### 🔄 「継続的な監視」が鍵
Taboolaのプロダクトディレクター、オムリ・アリアフ氏はこう言っています：
> 「最初の承認はゴールではない。継続的な監視・サンドボックス（安全な検証環境）・セキュリティ基準の維持が必要。一回のチェックでは不十分だ」

つまり、対策の方向性は以下の通りです：

```
❌ 悪い対策：「一度審査したからOK」で終わり
✅ 良い対策：常時・自動で「今何が動いているか」を可視化し続ける
```

### 🛡️ 具体的なアプローチ
1. **継続的なウェブ監視ツール**の導入（Reflectizのようなサービス）
2. マーケティング部門とセキュリティ部門の**情報共有の仕組み**を作る
3. 新しいタグを追加する際の**承認フロー**を整備する
4. **定期的なサプライチェーン（タグの連鎖）の棚卸し**を実施する

## 用語解説

| 用語 | 意味 |
|------|------|
| **マーケティングタグ（広告タグ）** | ウェブサイトに埋め込まれる、分析・広告用の小さなプログラム |
| **サードパーティコード** | 自分たちではなく、外部の業者が提供するプログラム |
| **フォースパーティコード** | サードパーティがさらに呼び出す、孫・ひ孫に当たる外部プログラム |
| **承認ギャップ（Approval Gap）** | 審査・承認した内容と、実際に動いているものの差 |
| **クライアントサイド** | サーバーではなく、ユーザーのブラウザ側で動く処理のこと |
| **WAF** | Web Application Firewall。ウェブアプリへの攻撃を検知・遮断する仕組み |
| **サンドボックス** | 本番環境に影響を与えず、安全にコードをテスト・検証できる隔離環境 |
| **デジタルサプライチェーン** | ウェブサイトで使われる外部コード・ツールの連鎖全体 |
| **ウェビナー** | Web + Seminar。インターネット上で開催されるセミナー |
| **Taboola（タブーラ）** | ウェブサイトのコンテンツ推薦・広告配信を行う大手プラットフォーム |
| **Reflectiz** | ウェブサイト上の外部スクリプトを監視・分析するセキュリティ企業 |

---

> 💡 **まとめると…**
> 「一度安全確認したから大丈夫」は、現代の広告技術の世界では通用しません。承認したコードが裏でどんどん別のコードを呼び出し、あなたのサイトを訪れたユーザーの個人情報や決済情報が知らない業者に見えてしまう可能性があります。AIの登場でこの変化はさらに速くなっており、**継続的な監視**が現代の必須セキュリティ対策になっています。
