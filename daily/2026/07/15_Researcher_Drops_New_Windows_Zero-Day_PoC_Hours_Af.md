# Windowsのゼロデイ脆弱性が、パッチ公開直後に研究者によって公開された

**元記事**: [Researcher Drops New Windows Zero-Day PoC Hours After Microsoft Patch Tuesday](https://inl03.netline.com/ltr6/?_m=3n.009a.4030.sp0ao46r89.332k)
**解説日**: 2026年7月9日

---

## 背景知識

このニュースを理解するために、まず以下のキーワードを押さえておきましょう。

### 🔑 Windowsのユーザープロファイルサービス（ProfSvc）とは？
Windowsには「ユーザープロファイルサービス」というシステムの部品があります。これは、パソコンにログインするときに「あなたのデスクトップの壁紙はこれ」「あなたのアプリ設定はこれ」という**個人ごとの環境を管理する係**のようなものです。とても重要なシステムの根幹部分です。

### 🔑 「ハイブ（Hive）」とは？
Windowsには「レジストリ」と呼ばれる設定データベースがあります（アプリの設定やシステムの情報が大量に入った巨大な設定ファイルの集まりです）。「ハイブ」はそのレジストリの**ファイルのかたまり（単位）**のことです。`usrclass.dat` などがその一例です。

### 🔑 PoC（Proof of Concept）とは？
「本当にこの脆弱性を使って攻撃できるよ」と証明するための**サンプルプログラム（実証コード）**のことです。PoCが公開されると、悪意ある人物がそれを悪用するリスクが一気に高まります。

### 🔑 ゼロデイ脆弱性とは？
ソフトウェアの欠陥（バグ）のうち、**修正プログラム（パッチ）がまだ存在しない状態のもの**を「ゼロデイ脆弱性」と呼びます。「対応できる日がゼロ日しかない」という意味からきています。

### 🔑 Patch Tuesday（パッチチューズデー）とは？
Microsoftが毎月第2火曜日に定期的にセキュリティ修正プログラムを配布する日のことです。世界中のWindowsユーザーにとって重要な「安全更新の日」です。

### 🔑 権限昇格（Privilege Escalation）とは？
普通のユーザーが本来持てないはずの**管理者権限を不正に取得すること**です。家の鍵を持っていない人が、裏口のバグを使って合鍵を作るようなイメージです。

## 何が起きたのか

「Chaotic Eclipse（カオティック・エクリプス）」または「Nightmare-Eclipse（ナイトメア・エクリプス）」という名前で知られるセキュリティ研究者が、**「LegacyHive（レガシーハイブ）」と名付けたPoC（実証コード）を公開しました。**

タイミングが問題です。Microsoftが2026年7月のPatch Tuesdayで大量の修正プログラムを配布した**わずか数時間後**に、この研究者は新たな脆弱性を公開したのです。

この脆弱性は以下の特徴を持ちます：

- 対象：**現在サポートされているすべてのWindowsデスクトップ・サーバーバージョン**（最新の2026年7月パッチ適用済み環境も含む！）
- 種類：**権限昇格の脆弱性**（一般ユーザーが管理者権限を得られてしまう）
- 場所：Windowsの**ユーザープロファイルサービス（ProfSvc）**

さらに同じ月のPatch Tuesdayでは、**過去最多の622件**もの脆弱性に対する修正プログラムが配布されました。その中には、すでに実際の攻撃に悪用されている脆弱性（SharePointとActive Directory関連）も含まれていました。

## 技術的な詳細

### LegacyHiveの仕組み

```
一般ユーザー（権限が弱い）
    ↓
ProfSvcの脆弱性を悪用
    ↓
別のユーザーのレジストリハイブを
不正に「マウント（読み込み・接続）」できる
    ↓
本来アクセスできないはずのデータや権限を取得
```

わかりやすく言うと…

> 🏠 **アパートで例えると：**
> 各部屋（ユーザーアカウント）には鍵がかかっています。管理人（ユーザープロファイルサービス）は全部屋の鍵を管理しています。この脆弱性は、**管理人の鍵管理の欠陥を突いて、他の部屋の鍵を勝手に複製・使用できてしまう**ようなものです。

研究者は「本来のエクスプロイト（攻撃コード）は追加のユーザー認証も不要で、`usrclass.dat`以外のどんなハイブにもアクセスできる」と述べており、**今回公開したPoCは意図的に機能を制限した**ものだと説明しています（これ以上悪用されないための配慮です）。

### SharePoint・Active Directoryの脆弱性

- **CVE-2026-56164**（SharePoint Server）：認証なしで本来は認証が必要な機能にアクセスできてしまう
- **CVE-2026-56155**（Active Directory）：権限昇格の脆弱性

> 🏢 **会社で例えると：**
> 社員証をかざさなくても社長室に入れてしまうバグ、のようなものです。

これらはすでに**実際の攻撃者に悪用されている**ことが確認されており、特に危険度が高いとされています。

## なぜ重要なのか

### ① 最新パッチを当てても守れない
LegacyHiveは**2026年7月の最新パッチを適用した環境でも動作します**。つまり、「ちゃんと更新してるから大丈夫」が通じない状況です。

### ② Microsoftと研究者の対立が深刻
この研究者とMicrosoftは少なくとも2026年4月から激しく対立しています。研究者は「Microsoftとのコミュニケーションが崩壊した」として、Microsoftがパッチを作る前に脆弱性の詳細を公開し続けています。これまでに公開されたMicrosoft Defender関連の脆弱性3件は、**公開直後から実際の攻撃に悪用**されました。

> ⚖️ **この対立について：**
> セキュリティ研究者がベンダー（ソフトウェア会社）に脆弱性を報告し、パッチが出るまで公開を控える慣行を「責任ある開示（Responsible Disclosure）」と言います。今回の研究者はこのルールを破っており、倫理的に問題があるという見方もあります。一方で「Microsoftが無視するから仕方ない」という意見もあり、業界内でも議論になっています。

### ③ SharePointへの攻撃はすでに現実の脅威
米国のセキュリティ機関CISAは、SharePoint Serverの脆弱性への対応を**政府機関に義務付け**（期限：7月17日・28日）。これほど緊急性が高い指定は珍しいことです。

### ④ 脆弱性の数が過去最多
2026年のPatch Tuesdayは622件という記録的な件数の修正を配布。「AIの普及で脆弱性の発見・報告が爆発的に増えている」と専門家も指摘しています。

## 対策・今後の展望

### ✅ 今すぐできること

| 対策 | 内容 |
|------|------|
| **Windows Updateを実行する** | LegacyHiveはパッチ未提供ですが、他の622件の修正を適用することが重要です |
| **SharePoint Serverの管理者へ** | 直ちに2026年7月のパッチを適用。CISAの期限（7月17〜28日）を厳守 |
| **不審なログインの監視** | 権限昇格を試みる不審な動作がないか、ログを確認する |
| **最小権限の原則を徹底** | ユーザーに必要以上の権限を与えない設定にする |

### 🔮 今後の展望

- MicrosoftはLegacyHiveについて調査中と発表していますが、パッチが出るまでの間は脆弱性がむき出しの状態です
- Chaotic Eclipse研究者とMicrosoftの対立がどう解決するかによって、今後も同様の「奇襲的な公開」が続く可能性があります
- AIによる脆弱性発見の加速が続く中、パッチ対応のスピードが追いつかない状況が慢性化するかもしれません

## 用語解説

| 用語 | 説明 |
|------|------|
| **ゼロデイ脆弱性** | パッチ（修正プログラム）がまだ存在しないソフトウェアの欠陥 |
| **PoC（Proof of Concept）** | 脆弱性が実際に悪用できることを証明するサンプルコード |
| **権限昇格** | 一般ユーザーが管理者権限を不正に取得すること |
| **ProfSvc（ユーザープロファイルサービス）** | Windowsのユーザー環境を管理するシステムの核心部品 |
| **ハイブ（Hive）** | Windowsのレジストリを構成するファイルの単位 |
| **マウント** | ファイルやドライブをシステムに接続して使用可能な状態にすること |
| **Patch Tuesday** | Microsoftが毎月第2火曜日に行うセキュリティ更新の配布日 |
| **CVE番号** | 脆弱性に付けられる国際的な管理番号（例：CVE-2026-56164） |
| **CVSS スコア** | 脆弱性の深刻度を0〜10点で表す指標（10に近いほど危険） |
| **SharePoint Server** | Microsoftの企業向けファイル共有・コラボレーションシステム |
| **Active Directory** | 企業ネットワークのユーザー認証・管理を行うシステム |
| **CISA** | 米国のサイバーセキュリティ・インフラセキュリティ庁 |
| **KEV（既知の悪用済み脆弱性カタログ）** | CISAが管理する「実際に攻撃に使われた脆弱性リスト」 |
| **RCE（リモートコード実行）** | 遠隔からコンピュータ上でプログラムを実行できてしまう攻撃 |
| **責任ある開示** | 脆弱性をベンダーがパッチを出すまで公開しないという業界の慣行 |

> 💡 **まとめると：**
> 「Windowsに新たな抜け穴が見つかったけど、まだ修正プログラムがない。しかも最新の更新を当てていても防げない。さらに会社の共有サーバー（SharePoint）への攻撃はすでに現実に起きている」という、なかなか深刻な状況です。できることは「とにかく更新プログラムを適用する」と「不審な動きを監視する」の2点が基本です！
