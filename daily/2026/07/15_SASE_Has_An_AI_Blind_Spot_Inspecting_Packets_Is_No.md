# SASEにはAIの盲点がある。パケットを検査するだけでは、もう十分ではない

**元記事**: [SASE Has An AI Blind Spot. Inspecting Packets Is No Longer Enough.](https://inl03.netline.com/ltr6/?_m=3n.009a.4030.sp0ao46r89.332e)
**解説日**: 2025年7月11日

---

## 背景知識

まず、この記事を理解するためにいくつかの基本的なことを押さえておきましょう。

### 🏢 企業のネットワークセキュリティとは？

会社のパソコンがインターネットに繋がるとき、「そのデータは安全か？」を確認する仕組みが必要です。昔は社員が全員オフィスにいたので、建物の入口に「門番（ファイアウォール）」を置けば、外部からの攻撃を防げました。

しかし今は、社員がカフェや自宅からも仕事をします。クラウド（インターネット上のサービス）も使います。「門番を入口に置く」だけでは守りきれなくなりました。

### 🛡️ SASEって何？

**SASE（サシー）** とは「Secure Access Service Edge（セキュア・アクセス・サービス・エッジ）」の略で、簡単に言うと：

> 「どこからでも安全にインターネットやクラウドを使えるようにする、クラウド型のセキュリティの仕組み」

イメージとしては、**「インターネットと社員の間にあるクラウド上の検問所」** です。社員が送受信するデータをその検問所で一度チェックしてから通す、という仕組みです。

### 🤖 生成AIの普及

最近、ChatGPTのような生成AI（文章や画像を自動で作るAI）を仕事で使う人が急増しています。「このコードを最適化して」「この資料を要約して」とAIに投げかけて仕事を効率化しているわけです。

### 🔒 TLSとHTTPS

皆さんがウェブサイトを見るとき、URLの先頭に「https://」とありますよね。あの「s」は「Secure（安全）」の意味で、**TLS（Transport Layer Security）** という技術で通信が暗号化されています。最新版の **TLS 1.3** は特に強力な暗号化が施されています。

## 何が起きたのか

この記事は「事件」ではなく、**セキュリティ業界の構造的な問題の警告**です。

ひとことで言うと：

> **「従来のSASEというセキュリティの仕組みが、AIや最新のウェブ技術の前では機能しなくなってきている」**

という問題提起です。

具体的に何が変わったかというと：

| 昔の状況 | 今の状況 |
|---------|---------|
| 社員がブラウザで普通にウェブを見る | 社員がAIに会社の機密情報を貼り付ける |
| データのやり取りが比較的シンプル | AIエージェントが自動で内部文書を読み、データを動かす |
| 暗号化が弱く、途中で検査しやすかった | TLS 1.3など強力な暗号化で途中検査が困難 |

## 技術的な詳細

### 🔍 従来のSASEの仕組みと限界

従来のSASEは、こんな流れで動いていました：

```
社員のPC → クラウドの検問所（プロキシ）→ 検査・チェック → インターネット
```

**「プロキシ（Proxy）」** とは代理人のことで、社員の代わりにインターネットにアクセスして、データを受け取り、安全かどうかチェックしてから社員に渡す仕組みです。

しかし、ここで問題が発生しています。

#### 問題①：強力な暗号化が邪魔をする

最新の通信技術（**TLS 1.3** や **証明書ピンニング**）は、「通信経路の途中で第三者が覗く」ことを防ぐように設計されています。これはもともと悪い人が盗み見をできないようにするためのものですが、セキュリティの検問所（プロキシ）も「第三者」として弾かれてしまいます。

🏠 **例え話**：
> 郵便局員（プロキシ）が「荷物の中身を確認しますね」と言っても、「この封筒は差出人と宛先しか開けられないように特殊な鍵がかかっています」と弾き返されるイメージです。

結果として、企業のIT担当者は「このアプリは検査をスキップさせよう（バイパス例外）」というルールをどんどん追加しなければならなくなり、気づけば**セキュリティの穴だらけ**になっていきます。

#### 問題②：迂回路による速度低下

遠くにあるクラウドの検問所を経由するということは、データが無駄な寄り道をするということ。これによって：

- アプリが遅くなる
- ビデオ通話がカクつく

記事ではこれを **「迂回税（Detour Tax）」** と呼んでいます。

🚗 **例え話**：
> 目的地まで10分の距離を、毎回わざわざ30分かかる遠回りで行くようなものです。社員はイライラして、検査を回避する「抜け道（シャドーIT）」を探し始めます。

#### 問題③：AIの「意図の瞬間」が見えない

これが最も深刻な問題です。

従来のプロキシは「どこに通信しているか」は見えます。でも「何を送っているか（内容）」は暗号化で見えません。

さらに問題なのが、**AIエージェント**（自動でタスクをこなすAIプログラム）の登場です。

```
AIエージェント → 社内の機密文書を読む → 外部のAIサービスに送信
       ↑
 プロキシには「普通のHTTPS通信」にしか見えない！
```

プロキシがデータを確認する頃には、**すでに機密情報がAIに送られた後**なのです。記事ではこれを **「意図の瞬間（Moment of Intent）が過ぎてしまっている」** と表現しています。

---

### 🆕 新しいアーキテクチャ：端末側での検査

この問題を解決するために提案されているのが、**「検査する場所を変える」** というアプローチです。

**従来**：データがインターネットに出た後、クラウドの検問所で検査
**新しい方式**：データが端末（PC・スマホ）を出る前に検査

```
【従来】
社員のPC → データ送信 → クラウド検問所でチェック → AI/外部サービス
                              ↑
                         もう手遅れ…

【新方式】
社員のPC（ここでチェック！） → 問題なければ直接送信 → AI/外部サービス
         ↑
    送信前に止められる！
```

この新しい考え方は **「Perfect Packet（完璧なパケット）アーキテクチャ」** と呼ばれています。

具体的には：
- **コピー・貼り付けの中身**をデバイス上でリアルタイムに検査
- 問題がなければ直接送信（余計な寄り道なし）
- 問題がありそうなときだけクラウドの詳細検査を呼び出す

## なぜ重要なのか

### 🚨 企業の機密情報が漏れる可能性

社員が「このコードを最適化して」とChatGPTに貼り付けると、それが会社の極秘プログラムだったとしても、従来のセキュリティシステムでは止めることができません。

### 📈 AIの普及でリスクが急拡大

生成AIを使う社員が増えれば増えるほど、この問題は深刻になります。さらに、人間が操作するだけでなく、**AIが自動でデータを移動させる（AIエージェント）** 時代になると、人間が気づく前に情報が流出する危険があります。

### ⚠️ セキュリティと利便性のジレンマ

記事では、企業が直面するジレンマをこう表現しています：

> **「AIを完全にブロックするか、完全に許可するか」の二択しかない**

- ブロックすれば：社員が勝手に個人のスマホや外部サービスを使う「シャドーIT」が増える
- 許可すれば：何が送られているかまったく見えない

どちらも危険という、八方塞がりの状況です。

## 対策・今後の展望

### ✅ 企業ができること（今すぐ）

1. **社員教育**：「会社の情報を生成AIに貼り付けない」という基本ルールの徹底
2. **使用可能なAIツールの明示**：公式に認められたAIサービスのリストを作る
3. **ブラウザ拡張機能の管理**：勝手にインストールできる拡張機能を制限する

### 🔮 セキュリティ業界の方向性

記事が示す今後のトレンドは：

| 従来 | これから |
|------|---------|
| クラウドの検問所でまとめてチェック | 端末の上でリアルタイムにチェック |
| 全部のトラフィックを迂回させる | 信頼できる通信は直接送信（90%は直通） |
| パケット（データの塊）を見る | 「何をしようとしているか（意図）」を見る |

セキュリティの重心が「ネットワーク（通信経路）」から「エンドポイント（端末・ブラウザ）」に移っていく流れです。

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **SASE** | サシー | Secure Access Service Edge。クラウド型のネットワークセキュリティの仕組み |
| **プロキシ（Proxy）** | プロキシ | 代理人。ユーザーの代わりにインターネットへアクセスし、通信を中継・検査するサーバー |
| **TLS 1.3** | ティーエルエス1.3 | 通信を暗号化する最新規格。非常に強力で途中での傍受が困難 |
| **証明書ピンニング** | - | 「この通信はこの証明書だけを信頼する」と固定する技術。中間者による傍受をブロック |
| **LLM** | エルエルエム | Large Language Model（大規模言語モデル）。ChatGPTなどの生成AIの核となる技術 |
| **AIエージェント** | - | 人間の指示なしに自律的にタスクをこなすAIプログラム |
| **MCP（Model Context Protocol）** | エムシーピー | AIが外部のツールやデータにアクセスするための通信規格 |
| **シャドーIT** | - | 会社が公式に認めていないツールやサービスを社員が勝手に使うこと |
| **バイパス例外** | - | セキュリティ検査をスキップさせるための特例設定 |
| **パケット** | - | インターネット上を流れるデータの小さな塊 |
| **エンドポイント** | - | 通信の端末側。社員のPCやスマホのこと |
| **HTTP/3** | エイチティーティーピー3 | ウェブ通信の最新規格。従来より高速で、途中での傍受が難しい |

---

> 💡 **まとめ**：AIが仕事に入り込んだことで、従来の「通信の途中でチェックする」セキュリティが限界を迎えています。これからは「端末の上で送信前にチェックする」という新しい考え方へのシフトが必要で、セキュリティ業界全体が変革期を迎えているというお話でした。
