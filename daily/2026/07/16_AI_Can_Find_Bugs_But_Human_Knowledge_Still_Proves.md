# AIはバグを見つけられる、でも「本当に危険か」を判断するのはまだ人間の仕事

**元記事**: [AI Can Find Bugs, But Human Knowledge Still Proves Them](https://inl03.netline.com/ltr6/?_m=3n.009a.4031.sp0ao46r89.334a)
**解説日**: 2025年7月17日

---

## 背景知識

このニュースを読む前に、いくつかの言葉を押さえておきましょう。

### 🔐 オフェンシブセキュリティ（攻撃的セキュリティ）とは？
セキュリティの世界には「守る側」と「攻める側」があります。**オフェンシブセキュリティ**とは、悪い人がやるような攻撃を「わざと先にやってみる」ことで、システムの弱点を見つける仕事のことです。いわば「プロの泥棒役」として、鍵の弱さを調べるイメージです。

### 🐛 脆弱性（バグ）レポートとは？
ソフトウェアに危険な欠陥（脆弱性）を発見したとき、それを報告する文書です。「どこに問題があるか」「どれくらい危険か」「実際に攻撃できるか」などを書きます。

### 💰 バグバウンティプログラムとは？
企業が「うちのシステムの脆弱性を見つけてくれたら報酬を払います！」と募集する制度です。腕に覚えのあるセキュリティ研究者が世界中から参加します。

### 🤖 AI支援ツールとは？
コードを自動的に読んで「ここが怪しいですよ」と指摘してくれるAIのことです。ChatGPTのようなAIが、セキュリティ検査に使われるようになっています。

## 何が起きたのか

> 「AIはバグを大量に見つけてくれるけど、それが**本当に危険かどうか**を証明するのはまだ人間の仕事だ」

という問題提起の記事です。

具体的に起きていることはこうです：

1. **AIツールが普及**して、コードを読んで「ここに脆弱性がありそう」と大量に指摘できるようになった
2. その結果、**"それっぽい"脆弱性レポートが大量に量産**されるようになった
3. しかし、それらの多くは**「本当に攻撃できるか」が確認されていない**
4. バグバウンティプログラムには**粗雑なAI生成レポートが殺到**し、審査担当者が大変な目に遭っている
5. 「**AIが出力した = 本物の脆弱性**」ではない、という当たり前の事実が改めて問われている

## 技術的な詳細

### 🔍「怪しそう」と「本当に危険」は全然違う

AIは次のようなことが得意です：

| AIが得意なこと | 具体例 |
|---|---|
| コードを素早く読む | 何万行のコードを数秒でスキャン |
| パターンを見つける | 「ここにSQLインジェクションの可能性がある」と指摘 |
| 報告書を書く | 読みやすい説明文を自動生成 |

でも、こんなことは**人間でないと難しい**のです：

**例えば「SQLインジェクション」（データベースに不正な命令を送り込む攻撃）を疑ったとして…**

```
AIが見つけること：「ユーザーの入力がデータベースの命令に使われている！危険かも！」

人間が確認すること：
  ✅ その入力は実際に攻撃者が操作できる場所にあるか？
  ✅ ログインしないとアクセスできない場所では？
  ✅ 入力する前に危険な文字を除去していないか？
  ✅ 実際に不正な命令を送り込めるか、試して確認できるか？
  ✅ もし攻撃できても、実際に被害が出るか？
```

AIは「可能性がある」と言えますが、「**実際に攻撃が成功する**」ことを証明するのは、今でも人間の専門知識が必要なのです。

### 🏭 AIが生み出す「大量の警告」問題

学校のテストに例えると：

> 📝 「答えっぽいもの」をたくさん書けば点が取れる…わけではないですよね。
> AIは「答えっぽい脆弱性レポート」を大量に生成できますが、**正解かどうかは別問題**です。

セキュリティチームはすでに毎日大量の警告に埋もれています。AIによる「それっぽいレポート」が増えると、本当に危険な問題が**ノイズに埋もれてしまう**危険があります。

### 📋 本物のレポートが答えるべき質問

記事によると、きちんとした脆弱性レポートは以下を明確にする必要があります：

- **何が起きたか**（何の脆弱性か）
- **どうやって再現するか**（手順を示せるか）
- **攻撃者は何をコントロールできるか**
- **どの境界線を越えたか**（どこからどこへ侵入できるか）
- **実際の被害は何か**（情報漏洩？システム破壊？）

## なぜ重要なのか

### 🚨 「偽の安心」と「偽の危機」の両方が危険

❌ **偽の危機（False Positive）の問題**
AIが「危険！」と言ったのに実際は安全 → セキュリティチームが無駄な作業をする → 本当の危険を見逃す

❌ **偽の安心（False Negative）の問題**
AIが「安全」と判断したのに実際は危険 → 攻撃者に侵入される

### 👔 企業・組織への影響

- セキュリティ担当者が**偽のレポート処理に時間を取られ**、本物の対応が遅れる
- バグバウンティプログラムが**機能しなくなる**可能性（Bugcrowdはすでにポリシー変更を余儀なくされた）
- 経営層が「AIが検査したから安全」と**誤解する**リスク

### 🎯 セキュリティ業界の未来像

記事が言いたいことをひと言でまとめると：

> 💬 「AIで大量のレポートを出せる人」より、「**本当に危険かどうかを証明できる人**」の価値がこれからも高まる

## 対策・今後の展望

### ✅ セキュリティチームができること

| 対策 | 内容 |
|---|---|
| **検証ステップの義務化** | AIが見つけた問題を必ず人間が「実際に攻撃できるか」確認する |
| **報告基準の明確化** | 「再現手順がないレポートは受け付けない」などのルール作り |
| **AIを補助ツールとして使う** | AIは「手がかりを広げるツール」として使い、最終判断は人間が行う |

### 📚 セキュリティを学ぶ人への示唆

AIツールを使いこなすだけでなく、**なぜそれが危険なのかを説明できる知識**（ネットワーク、プログラミング、システムの仕組みなど）が今後も重要です。

### 🔮 今後の展望

- バグバウンティプログラムは**AI生成レポートのフィルタリング強化**を進める
- 「AIで調査 → 人間が証明」という**ハイブリッドな手法**が標準になっていく
- 「証明できる人材」の価値がさらに高まる

## 過去記事との関連

以前、「**AIエージェントを騙して勝手に買い物や不正コマンドを実行させる攻撃（データインジェクション攻撃）**」について解説しました。

あの記事では「**AIが攻撃される側**」の話でしたが、今回は「**AIが攻撃に使われる側**」の話です。

つまり、AIはセキュリティの世界で**攻撃にも防御にも使われる両刃の剣**になっています。

```
前回の記事：AIが「騙される」問題
  → AIエージェントが悪意ある指示を実行してしまう

今回の記事：AIが「誤った情報を出す」問題
  → AIが「危険そう」なものを「本当に危険」と誤認させてしまう
```

どちらも根っこにある問題は同じ：「**AIの出力を盲信してはいけない**」ということです。

## 用語解説

| 用語 | 意味 |
|---|---|
| **オフェンシブセキュリティ** | 攻撃者と同じ手法でシステムの弱点を探す、プロの「攻める」セキュリティ活動 |
| **脆弱性（バグ）** | ソフトウェアやシステムにある、攻撃者に悪用される可能性がある欠陥 |
| **バグバウンティ** | 脆弱性を発見・報告した人に報酬を出す企業プログラム |
| **SQLインジェクション** | データベースに不正な命令を送り込む古典的な攻撃手法 |
| **SSRF** | サーバーを騙して、本来アクセスできない内部システムに通信させる攻撃 |
| **PoC（Proof of Concept）** | 「この脆弱性は本当に攻撃できる」と証明するためのサンプルコードや手順 |
| **False Positive（誤検知）** | 本当は安全なのに「危険」と判断してしまうこと |
| **トリアージ** | 医療用語から転用。報告された問題の優先度を仕分けする作業 |
| **攻撃面（アタックサーフェス）** | 攻撃者が狙える可能性がある、システムの露出している部分の総称 |
| **Bugcrowd** | 世界最大級のバグバウンティプラットフォームの一つ |

> 🎓 **まとめ**
> AIはセキュリティの「調査スピード」を劇的に上げてくれます。でも「これは本当に危険か？」を証明するのは、今もこれからも**人間の知識と経験**が必要です。道具が進化しても、それを使いこなす人間の判断力の大切さは変わらない、というメッセージの記事でした。
