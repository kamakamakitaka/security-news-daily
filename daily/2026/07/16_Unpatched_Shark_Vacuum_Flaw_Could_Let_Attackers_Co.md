# ロボット掃除機「Shark」の欠陥で、他人の掃除機を乗っ取れる！？

**元記事**: [Unpatched Shark Vacuum Flaw Could Let Attackers Control Other Vacuums Region-Wide](https://inl03.netline.com/ltr6/?_m=3n.009a.4031.sp0ao46r89.334g)
**解説日**: 2025年7月16日

---

## 背景知識

このニュースを理解するために、いくつかの基本的な概念を説明します。

### 🤖 IoT（アイオーティー）とは？
「Internet of Things（モノのインターネット）」の略です。ロボット掃除機・スマート冷蔵庫・スマートスピーカーなど、インターネットにつながる家電製品のことをまとめてIoT機器と呼びます。便利な反面、**ネットワーク経由で攻撃される危険性**もあります。

### ☁️ AWS（Amazon Web Services）とは？
Amazonが提供するクラウドサービスです。多くの企業がサーバーの代わりに使っています。Sharkの掃除機も、スマートフォンアプリと通信するためにAWSを使っています。

### 🔑 デジタル証明書（Certificate）とは？
「このデバイスは本物ですよ」と証明するための電子的な身分証明書です。銀行のATMカードのようなイメージで、サービスにアクセスする際に「あなたは正規のユーザーですか？」を確認するために使います。

### 📋 デバイスシャドウとは？
AWSがIoT機器の「現在の状態」をクラウド上に保存する仕組みです。「掃除機は今どの部屋にいるか」「電源はONか」などの情報が入っています。ここに**コマンド（命令）**を書き込むことで、デバイスを操作できます。

## 何が起きたのか

セキュリティ研究者「tokay0」さんが、**SharkNinja社のロボット掃除機「Shark RV2320EDUS」に深刻なセキュリティ欠陥**を発見し、公開しました。

### 問題の核心を一言で言うと…
> **1台の掃除機から取り出した「鍵（証明書）」を使って、同じAWSリージョン（地域）にある他の人の掃除機を全部操作できてしまう**

という問題です。

### 具体的に何ができてしまうのか？

| できてしまうこと | どのくらい怖いか |
|---|---|
| 他人の掃除機のカメラ映像をリアルタイムで見る | 🔴 家の中が丸見え！ |
| 掃除機を遠隔で動かす | 🔴 家の中を自由に探索される |
| 家の間取りマップを読み取る | 🔴 家の構造がバレる |
| Wi-Fiのパスワードを盗む | 🔴 家のネットワーク全体が危険に！ |
| 任意のコマンド（命令）を実行する | 🔴 最悪、踏み台にされる |

研究者は**自分で購入した掃除機のみ**でテストを行い、2025年3月にSharkNinja社に報告しましたが、記事執筆時点（4ヶ月以上経過）でもまだ修正されていません。

## 技術的な詳細

難しく聞こえますが、順を追って説明します。

### 🪛 ステップ1：掃除機を物理的に開けて「鍵」を盗む

まず、掃除機をドライバーで分解します。中にある基板（マザーボード）には**UARTピン**という小さな端子があります。

> **UARTピン**：電子機器の内部と直接会話するための「デバッグ用端子」。開発者がテストするために使う端子ですが、セキュリティ対策がなければ誰でも使えてしまいます。

この端子に接続すると、**パスワードなしで管理者（root）権限のシェル**が手に入ります。

> **rootシェル**：パソコンで言う「管理者モード」のコマンド画面。何でもできる最高権限です。

そこから `/mnt/res/vapp/certs/` というフォルダにある**証明書（鍵）ファイル**を取り出せます。

```
掃除機を開ける → UART端子に接続 → パスワードなしでroot権限取得 → 証明書を盗む
```

### 🔓 ステップ2：盗んだ「鍵」でクラウドに不正アクセス

本来、証明書は「その掃除機だけ」に使えるはずです。ところが、**Sharkのクラウド設定（ポリシー）が間違っていて**、その証明書で「すべての掃除機」の情報にアクセスできてしまいます。

マンションのマスターキーで例えると…

```
🔑 普通の鍵   → 自分の部屋だけ開けられる（正しい設定）
🗝️ マスターキー → 全部屋を開けられる（Sharkの証明書の状態）
```

AWSにはこういう設定ミスを検出する仕組み（**Device Defender**）があり、`IOT_POLICY_OVERLY_PERMISSIVE_CHECK`という「危険度：重大」の警告として検出できます。つまり、**AWSが「この設定は危険です」と警告しているのに、設定が直されていなかった**ということです。

### 💻 ステップ3：他人の掃除機にコマンドを送る

AWSの仕組みで `$aws/things/#` というトピック（チャンネルのようなもの）を購読（受信登録）すると、**全掃除機の通信が見えてしまいます**。

さらに、デバイスシャドウの中にある `Exec_Command` というフィールドに好きな命令を書き込むと、掃除機がそれをそのまま実行してしまいます（`execute_command` → `popen` という関数で処理）。

> **popen**：プログラムの中からシステムコマンドを実行する関数。使い方を誤るとセキュリティホールになります。

研究者は実際に、別のモデル（AV1102ARUS）に**リバースシェル**を送り込み、カメラ映像をリアルタイムで取得することに成功しました。

> **リバースシェル**：攻撃者が標的のコンピュータを遠隔操作できる状態にすること。ドアを内側から開けてもらうイメージ。

## なぜ重要なのか

### 📊 影響を受けるデバイスの規模

研究者が1つのAWSリージョンを**24時間監視**した結果：

- **約152万台**のSharkデバイスを確認
- そのうち**約67万台（44%）**が攻撃可能なコマンドハンドラーを持っていると判明

「数百万台」という数字は誇張かもしれませんが、それでも**数十万台規模**での影響が確認されています。

### 🏠 プライバシーへの深刻な影響

ロボット掃除機は家の中を動き回ります。つまり：

- **カメラ**が家の中を映す
- **マップ機能**が家の間取りを記録する
- **Wi-Fiパスワード**が平文（暗号化なし）で保存されている

これらすべてが外部に漏れる可能性があります。

### ⏰ 4ヶ月以上放置されている

研究者は2025年3月1日に報告し、詳細を3月11日に送付。しかし：

- 4月27日：「確認中」と回答
- 7月3日：「完了予定日を知らせる」と回答
- 記事執筆時点：**まだ修正なし**

この「報告してから修正まで長期間かかる（または放置される）」問題は、IoT業界全体の課題です。

## 対策・今後の展望

### 👤 ユーザーができること（残念ながら限られます）

現時点でSharkの掃除機ユーザーが取れる対策は少ないですが、以下を心がけましょう：

1. **掃除機専用のWi-Fiネットワーク（IoTセグメント）を作る**
   - 家のメインWi-Fiと掃除機用Wi-Fiを分けることで、パスワードが盗まれても被害を最小化できます

2. **ファームウェアの更新を常に確認する**
   - SharkNinja社が修正を出したら、すぐに適用しましょう

3. **外出中のカメラ機能使用に注意する**
   - 修正前はカメラ機能を最小限にすることも一つの判断です

### 🏢 メーカー・AWS側がすべきこと

| やるべき対策 | 説明 |
|---|---|
| **証明書ポリシーの修正** | 各デバイスが「自分の情報だけ」にアクセスできるよう制限する |
| **UART端子のセキュリティ強化** | パスワード設定や物理的なアクセス制限 |
| **Exec_Commandフィールドの削除または制限** | 任意コマンド実行機能を安全な方法に変更する |
| **AWS Device Defenderの活用** | AWSがすでに警告している設定ミスを修正する |

### 🔮 今後の展望

SharkNinja社が迅速に修正を行うかどうかが焦点です。研究者がこの問題を公開したことで、**他の悪意ある攻撃者がこの方法を真似するリスク**も上がっています。「公開による圧力」でメーカーが動くことを期待するしかない状況です。

## 過去記事との関連

以前、**「攻撃までの時間が30日から30分に短縮された」**という記事を解説しました。今回のShark掃除機の問題も、攻撃手法が公開されてしまったことで、**悪意ある攻撃者が同じ手法を試すまでの時間が一気に短くなった**と考えられます。

また、**「政府ウェブサイトが乗っ取られ攻撃の踏み台にされた」**事件でも触れましたが、今回の掃除機も「踏み台」として使われるリスクがあります。掃除機が家のWi-Fiに接続されているため、掃除機を乗っ取ることで**家のネットワーク全体への侵入口**になりかねません。

IoT機器のセキュリティは「弱いリンク」として狙われやすく、これらの記事は共通して「**身近な機器ほど油断しがち**」という教訓を示しています。

## 用語解説

| 用語 | 意味 |
|---|---|
| **IoT** | インターネットに接続された家電・機器の総称（ロボット掃除機、スマートスピーカーなど） |
| **AWS（Amazon Web Services）** | Amazonのクラウドサービス。多くの企業がサーバーとして利用 |
| **デジタル証明書** | 「このデバイスは本物」と証明する電子的な身分証明書 |
| **デバイスシャドウ** | AWSがクラウド上にデバイスの状態を保存する仕組み |
| **UARTピン** | 電子機器のデバッグ用端子。セキュリティ対策がないと不正アクセスの入口になる |
| **rootシェル** | 管理者最高権限でコマンドを実行できる状態 |
| **リバースシェル** | 攻撃者が標的の機器を遠隔操作できる状態にすること |
| **popen** | プログラム内からシステムコマンドを実行する関数。悪用されやすい |
| **ファームウェア** | 機器を動かすための基本的なソフトウェア（機器専用のOS） |
| **Device Defender** | AWSが提供するIoT機器のセキュリティ監査サービス |
| **平文（ひらぶん）** | 暗号化されていない、そのまま読めるデータ。Wi-Fiパスワードが平文で保存されているのは非常に危険 |
| **リージョン** | AWSのデータセンターが置かれている地域区分（日本、米国東部、など） |

---

> ⚠️ **まとめ**：ロボット掃除機は「賢い家電」ですが、セキュリティが甘いと**カメラ・マップ・Wi-Fiパスワードという非常に個人的な情報**が丸ごと盗まれるリスクがあります。IoT機器を購入する際は、メーカーがセキュリティアップデートを継続的に提供しているかどうかも確認しましょう！
