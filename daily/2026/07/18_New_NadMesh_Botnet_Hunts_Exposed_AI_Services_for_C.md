# 「NadMesh」ボットネット：AIサービスを狙ってクラウドの鍵やKubernetesトークンを盗む新たな脅威

**元記事**: [New NadMesh Botnet Hunts Exposed AI Services for Cloud Keys and Kubernetes Tokens](https://inl03.netline.com/ltr6/?_m=3n.009a.4033.sp0ao46r89.3378)
**解説日**: 2025年7月18日

---

## 背景知識

まず、この記事を理解するためにいくつかの基本的な概念を押さえておきましょう。

### 🤖 AIサービスって何？
最近、企業や開発者が「自前のAI環境」を構築するためのツールをインターネット上に公開することが増えています。記事に出てくる以下のツールがその代表例です：

- **ComfyUI / Gradio** → AIで画像を生成するツール（例：「プロンプトを入力して絵を描いてもらう」アプリ）
- **Ollama / Open WebUI** → ChatGPTのようなAIを自分のパソコンやサーバーで動かすためのツール
- **n8n / Langflow** → 複数のAIやサービスを組み合わせて自動化ワークフローを作るツール

これらは便利ですが、**「とりあえず動かして、後でセキュリティを設定しよう」** という状態のままインターネットに公開されてしまうことがよくあります。

### ☁️ クラウドの「鍵」って何？
AWSなどのクラウドサービスを使うときには、「**APIキー**」という特別なパスワードのような文字列が必要です。これを持っていれば、クラウド上のサーバーを起動したり、データを取り出したり、費用を発生させたりできます。まさに「家の鍵」のようなものです。

### 🚢 Kubernetesって何？
**Kubernetes（クーベネティス）** は、大量のプログラムを多数のサーバーでまとめて管理するためのシステムです。大規模なWebサービスの裏側でよく使われています。「**サービスアカウントトークン**」はそのシステムに入るための通行証のようなものです。

### 🦠 ボットネットって何？
**ボットネット** とは、攻撃者に乗っ取られたコンピューターが大量につながって、一斉に悪意ある活動を行うネットワークのことです。ゾンビ映画のように、感染したコンピューターが攻撃者の命令に従って動き続けます。

---

## 何が起きたのか

2025年7月初旬、セキュリティ研究機関の**QiAnXin XLab**（奇安信）が「**NadMesh（ナドメッシュ）**」という新しいボットネットを発見・公開しました。

### 事件の概要

```
【攻撃者の狙い】
インターネット上に"うっかり公開されてしまっている"AIサービスを探し出す
        ↓
AIサービスのサーバーに侵入する
        ↓
そのサーバーに保存されている「クラウドの鍵」や「Kubernetesの通行証」を盗む
        ↓
盗んだ鍵を使って、クラウド環境をさらに荒らす・悪用する
```

攻撃者自身のダッシュボード（管理画面）には、驚くべき数字が記録されていました：

- **3,811個** のAWS（クラウドサービス）のAPIキーを入手済み
- **47回** の認証情報（パスワード等）の収集に成功
- **41回** のAIモデルの目録作成に成功

## 技術的な詳細

### 🔍 どうやって標的を見つけるの？

NadMeshは**Shodan（ショーダン）** というインターネット全体を検索できる特殊なサービスを使って、セキュリティ設定が甘いAIサービスを自動的に探し出します。

> 💡 **Shodanのイメージ**: Googleが「Webページ」を検索するのと同じように、Shodanは「インターネットに公開されているサービスやシステム」を検索できるツールです。セキュリティ研究者も使いますが、攻撃者にも悪用されます。

スキャンのルールも巧妙です：

- ヒットしたサーバーがある範囲（サブネット）は、**5分ごと** に再スキャン
- 過去24時間以内に「危険」と判定されたIPアドレスは、**15分ごと** に再スキャン
- 10回侵入を試みてもまったく反応がないサーバーは「**研究者のハニーポット**（おとりサーバー）」だと判断して自動的にスキャン対象から外す

> 💡 **ハニーポットのイメージ**: 攻撃者を誘き寄せるために研究者が意図的に設置する"おとり"のサーバー。攻撃者の手口を観察するために使います。

### 💰 何を盗むの？

侵入に成功したサーバーから、以下の情報を自動的に収集して攻撃者のもとに送ります：

| 盗む情報 | どこにあるか | わかりやすい例え |
|---|---|---|
| AWSアクセスキー | `~/.aws/config` ファイル | クラウドへの合鍵 |
| 環境変数に入ったAPIキー | サーバーの環境設定 | ドアの暗証番号 |
| Kubernetesトークン | サービスアカウント設定 | 社内システムの社員証 |
| Dockerの認証情報 | `~/.docker/config.json` | コンテナ管理の鍵束 |

### ⚔️ 主な攻撃手法

XLabが実際に観測した攻撃の内訳はこうなっています：

```
Docker APIへの不正アクセス    30.31%  ████████████
Jenkinsへの不正コード実行     22.28%  █████████
Telnetの弱いパスワード攻撃    10.36%  ████
Redisデータベースへの攻撃      8.29%  ███
MCP経由のコマンド実行          0.78%  （小さいが存在する）
```

### 🆕 新しい攻撃対象：MCP（エムシーピー）

特に注目すべきは**MCP（Model Context Protocol）** への攻撃です。

> 💡 **MCPとは**: AIアシスタントが外部のツールやサービスを操作できるようにするための「共通ルール（プロトコル）」です。たとえば「AIがファイルを読んだり、コマンドを実行したりできるようにする仕組み」です。

**問題点**: MCPの仕様では、認証（ログイン確認）の仕組みが**後から追加されたオプション機能**であり、多くの環境でスキップされています。

- 2025年4月28日時点で、インターネット上に **12,520個** のMCPサービスが公開されていた
- 2025年5月6日には **21,000個以上** に急増
- そのうち約90個が「コマンドを実行できるツール」を持っていた
- 39個では、そのツールの名前が `execute_command`（コマンドを実行するツール）という、まさにNadMeshが狙う名前だった

## なぜ重要なのか

### 🎯 狙われているのはサーバーそのものではない

XLabの研究者が指摘した最も重要なポイントはここです：

> **「攻撃者が欲しいのは、サーバー自体ではなく、そこに保存されているクラウドの認証情報とKubernetesの権限だ」**

つまり、侵入したサーバーは「踏み台」に過ぎません。そこから盗んだ鍵を使って、企業のクラウド全体に被害が広がる可能性があります。

### 💸 実際にどんな被害が起きる？

- クラウド上の大量のサーバーを勝手に起動されて**巨額の請求が発生**
- 保存されているデータの**流出・盗難**
- 競合他社の情報を探るための**スパイ行為**
- DeepSeek、GLM、Kimiなどの**AIモデルAPIを勝手に使われる**（費用が発生）

### 📈 急速な拡大

攻撃の規模は急激に拡大しており、6月末にはほぼゼロだったのが、7月第1週には**1日あたり約139台**のIPアドレスがNadMeshに感染した状態で観測されています。

## 対策・今後の展望

### ✅ AIサービスを運用している人・企業へ

1. **ファイアウォールを必ず設定する**
   - ComfyUI、Ollama、n8nなどのAIツールは、**インターネットに直接公開しないこと**
   - 必要な人だけがアクセスできるようにVPN（仮想プライベートネットワーク）を使う

2. **APIキーを環境変数やファイルに保存したままにしない**
   - `.env` ファイルや `~/.aws/config` は定期的に確認する
   - 不要になったAPIキーはすぐに無効化する

3. **MCPサービスには認証を必ず設定する**
   - 「オプション機能だから」とスキップしない
   - `execute_command` のような危険なツールは公開しない

4. **定期的なセキュリティスキャン**
   - 自分のサービスがインターネットから見えているかを確認する

### 🔮 今後の動向

- AIサービスの急増に伴い、この種の攻撃は今後さらに増加すると予想されます
- MCPのセキュリティ標準化が急務となっています
- ボットネット自体も複数バージョン（v30.0〜v33.8）が並行稼働しており、継続的に進化しています

## 過去記事との関連

以前、**WordPressの「wp2shell」欠陥**（ログイン不要でサーバーを乗っ取れる脆弱性）と**OpenSSLの「HollowByte」欠陥**（たった11バイトでサーバーをフリーズさせる攻撃）について解説しました。

今回のNadMeshボットネットは、これらと共通した「現代のサイバー攻撃のトレンド」を示しています：

> **「新しい・便利なツールが急速に普及する一方、セキュリティ設定が追いつかない隙を攻撃者は見逃さない」**

- wp2shellはWordPressという「広く使われているCMS」の隙を突きました
- NadMeshは「急速に普及するAIサービス」の隙を突いています

どの事件も「**セキュリティは後回し**」になりがちな環境が生み出した問題という点で一致しています。

## 用語解説

| 用語 | 読み方 | 意味 |
|---|---|---|
| **ボットネット** | ボットネット | 攻撃者に乗っ取られたコンピューターの集団。命令を受けて一斉に悪事を働く |
| **AWS APIキー** | エーダブリューエス・エーピーアイキー | AmazonのクラウドサービスAWSを操作するための「合鍵」 |
| **Kubernetes** | クーベネティス | 大量のプログラムを多数のサーバーで管理するシステム |
| **Shodan** | ショーダン | インターネットに公開されているシステムを検索できるツール |
| **MCP** | エムシーピー | AIアシスタントが外部ツールを操作するための共通ルール |
| **環境変数** | かんきょうへんすう | サーバープログラムが参照する設定値の保存場所 |
| **ハニーポット** | ハニーポット | 攻撃者をおびき寄せる"おとり"サーバー。研究目的で使用 |
| **Docker** | ドッカー | アプリケーションを「コンテナ」という箱に入れて動かす仕組み |
| **Jenkins** | ジェンキンス | ソフトウェア開発の自動化ツール。狙われやすい |
| **Redis** | レディス | 高速なデータ保存システム。設定が甘いと攻撃される |
| **Go言語** | ゴーげんご | Googleが開発したプログラミング言語。ボットネットの作成に使われた |
| **JSON-RPC** | ジェイソンアールピーシー | ネットワーク越しに処理を呼び出すための通信形式 |

---

> 🔐 **まとめ**: 「とりあえず動かす」が一番危ない。AIツールを公開するときは、**ファイアウォール設定→認証設定→APIキーの管理** の3点を必ず確認しましょう！
