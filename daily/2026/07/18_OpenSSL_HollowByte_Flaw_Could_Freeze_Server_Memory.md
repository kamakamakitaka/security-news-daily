# OpenSSL「HollowByte」欠陥：たった11バイトのデータでサーバーのメモリを凍りつかせる攻撃

**元記事**: [OpenSSL HollowByte Flaw Could Freeze Server Memory with 11-Byte TLS Requests](https://inl03.netline.com/ltr6/?_m=3n.009a.4033.sp0ao46r89.336q)
**解説日**: 2025年7月19日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえましょう。

### 🔐 OpenSSLって何？
**OpenSSL**（オープンエスエスエル）とは、インターネット上の通信を「暗号化（誰にも読めない状態にすること）」するためのソフトウェアです。ウェブサイトのURLが「**https**://」で始まっているとき、その裏側でOpenSSLのような仕組みが動いていることが多いです。世界中の膨大な数のサーバー（ウェブサービスを動かすコンピューター）がこれを使っています。

### 🤝 TLSハンドシェイクって何？
**TLS**（Transport Layer Security）は、インターネット通信を安全にするための「プロトコル（通信のルール）」です。あなたがウェブサイトにアクセスするとき、まずブラウザとサーバーの間で「どうやって安全に話すか」を確認し合う作業が行われます。これを「**ハンドシェイク（握手）**」と呼びます。

> 🤝 イメージ：電話をかけたとき、まず「もしもし？」「はい、〇〇です」と確認し合うような作業のこと

### 💾 メモリって何？
**メモリ（RAM）**は、コンピューターが作業するための「作業机」のようなものです。机が大きいほどたくさんの作業を同時にできますが、机がいっぱいになると新しい作業ができなくなります。サーバーも同じで、メモリが足りなくなると処理が止まります。

### 🐛 DoS攻撃って何？
**DoS攻撃**（Denial of Service Attack、サービス拒否攻撃）とは、サーバーに大量の負荷をかけて、普通のユーザーが使えなくしてしまう攻撃です。お店のレジに「嫌がらせ目的の客」が延々と並び続けて、本当のお客さんが買い物できなくなるようなイメージです。

---

## 何が起きたのか

セキュリティ会社「**Okta（オクタ）**」のセキュリティ調査チームが、OpenSSLに深刻な欠陥を発見し、「**HollowByte（ホロウバイト）**」と名付けました。

この欠陥のポイントは、たった**11バイト**（テキストメッセージ数文字分のデータ量！）を送るだけで、サーバーに最大**131キロバイト（KB）** のメモリを「無駄に確保させ続ける」ことができるというものです。

> 📦 イメージ：「荷物が届く予定なので、大きな倉庫を空けておいてください」とウソをついて倉庫を占領し、荷物は永遠に届けないような攻撃

しかも厄介なことに、**一度占領されたメモリはサーバーを再起動するまで戻ってこない**という性質があります。

## 技術的な詳細

### 攻撃の仕組み

```
攻撃者                          サーバー（OpenSSL）
   |                                  |
   |--- 「ヘッダー(11バイト)」送信 -->|
   |  「本文は131KBあります！」と嘘をつく
   |                                  |
   |                     メモリを131KB確保して待機...
   |                                  |
   |（接続をブツっと切断）            |
   |                                  |
   |             「あれ、本文が来ない？まあいいや」
   |                              (でもメモリは戻らない！)
```

**なぜこうなるのか？**

TLSのハンドシェイクメッセージには「**ヘッダー（4バイトの見出し部分）**」があり、その中に「このメッセージの本文は〇〇バイトある」という情報が含まれます。

古いバージョンのOpenSSLは、**実際に本文が届く前に、ヘッダーに書かれたサイズを信じてメモリを確保してしまっていました**。これが問題の根本です。

> 🏠 イメージ：「100人分の席を用意してください」という予約電話を信じて、実際に確認もせず100人分の席を空けてしまったレストランのようなもの

### なぜメモリが「凍りつく」のか？

ここからが特に厄介な部分です。

Linuxサーバーでよく使われる「**glibc（ジーリブシー）**」というシステムには、効率化のためにメモリの「使いまわし」をする仕組みがあります。一度使ったメモリをすぐ返却せず、「また使うかもしれないから手元に置いておく」という動作をします。

攻撃者はこれを悪用します。**毎回少しずつサイズを変えながら大量に接続→切断を繰り返す**ことで、メモリの断片がバラバラになり（これを「**メモリの断片化（フラグメンテーション）**」と言います）、使いまわしが難しくなります。

**Oktaの実験結果**：
| サーバーのメモリ | 攻撃後の状態 |
|---|---|
| 1GB | 547MBが「凍りついた状態」でサーバーがクラッシュ |
| 16GB | 4GB（25%）が動かせなくなった |

## なぜ重要なのか

### ⚠️ 影響の大きさ

1. **OpenSSLは世界中で使われている** → 多数のウェブサーバーが対象になりうる
2. **認証不要で攻撃できる** → ログイン情報なしで誰でも攻撃できる
3. **通常の防御をすり抜ける** → 「同時接続数の上限を設ける」という一般的な対策が効かない

### 😮 CVE（脆弱性識別番号）がない問題

通常、セキュリティの欠陥が見つかると「**CVE**（Common Vulnerabilities and Exposures）」という番号が割り当てられます。これがあると、セキュリティスキャナーが自動的に「あなたのサーバーは危険です」と教えてくれます。

ところがOpenSSLは、この欠陥を「脆弱性ではなくバグ修正・強化」として扱い、**CVE番号を付けなかった**のです。

> 😱 これは何を意味するか？
> → 自動スキャンツールは「この問題」を検出できない
> → システム管理者が自分でOpenSSLのバージョンを確認しない限り、気づけない

**Okta（発見者）の主張**：「メモリが戻ってこない時点で、これは立派な脆弱性だ」
**OpenSSL側の主張**：「1接続あたり131KBは小さな量であり、すべてのTLSサーバーは接続ごとにメモリを使う。これは仕様の範囲内」

→ 現在も見解の相違が続いています。

## 対策・今後の展望

### ✅ 今すぐできる対策

**最優先：OpenSSLを最新バージョンにアップデートする**

修正済みバージョン（2025年6月9日リリース）：

| バージョン系列 | 修正バージョン |
|---|---|
| OpenSSL 4.0系 | **4.0.1** |
| OpenSSL 3.6系 | **3.6.3** |
| OpenSSL 3.5系 | **3.5.7** |
| OpenSSL 3.4系 | **3.4.6** |
| OpenSSL 3.0系 | **3.0.21** |

> ⚠️ 注意：古いOpenSSL 1.1.1や1.0.2への修正が適用されるかは、現時点で不明です。

### 🛡️ その他の対策

- **サーバーの監視強化**：メモリ使用量が異常に増えていないか定期的にチェックする
- **定期的な再起動スケジュール**：完全には防げないが、メモリをリセットする機会を作る
- **ネットワークレベルのフィルタリング**：不審な接続元からのトラフィックを制限する

### 🔍 今後の動向

- Okta・The Hacker News（セキュリティメディア）がOpenSSLに正式な見解を問い合わせ中
- 「glibc以外の環境（Windowsなど）では同じ影響が出るか？」も未確認
- 公開されたエクスプロイトコード（攻撃を実証するプログラム）は2025年7月18日時点では存在しないが、今後公開される可能性はある

## 過去記事との関連

以前、**WordPressの「wp2shell」脆弱性**（ログイン不要でサーバーを乗っ取れる欠陥）についてお伝えしました。

今回のHollowByteも同様に「**認証なし・ログイン不要**」で攻撃できる点が共通しています。ただし、wp2shellがサーバーを「乗っ取る（コードを実行する）」攻撃だったのに対し、HollowByteはサーバーを「使えなくする（メモリを枯渇させる）」攻撃です。

どちらも「**攻撃のハードルが異常に低い**」という点で危険度が高く、一般ユーザーの使うサービスが突然使えなくなるリスクにつながります。こうした攻撃からサービスを守るためには、**システム管理者が常にソフトウェアを最新状態に保つこと**が最も基本的な対策となります。

## 用語解説

| 用語 | 意味 |
|---|---|
| **OpenSSL** | インターネット通信を暗号化するためのオープンソースソフトウェア |
| **TLS** | インターネット通信を安全にする「暗号化プロトコル（通信ルール）」。HTTPSの「S」の部分 |
| **ハンドシェイク** | 通信を始める前にブラウザとサーバーが「安全な話し方」を確認し合う手順 |
| **DoS攻撃** | サーバーを過負荷にして使えなくする攻撃（Denial of Service） |
| **メモリ（RAM）** | コンピューターの「作業机」。作業用の一時的なデータを置く場所 |
| **glibc** | Linuxで広く使われるシステムライブラリ。メモリ管理の仕組みを含む |
| **メモリの断片化** | メモリがバラバラな小さな塊に分かれて、まとまったサイズとして使えなくなる状態 |
| **CVE** | セキュリティ欠陥に付けられる世界共通の識別番号。スキャンツールがこれを元に危険を検出する |
| **OOM-kill** | メモリ不足（Out of Memory）でOSがプロセスを強制終了させること |
| **ヘッダー** | データの「見出し部分」。「本文は〇〇バイトある」などの情報が入っている |
| **バイト** | データの単位。1バイト＝1文字程度のデータ量。1KB＝1024バイト |
| **Okta** | 米国の大手セキュリティ・認証管理サービス企業。今回の発見者 |

---

> 💡 **まとめ**：「ウソのサイズ情報を送るだけ」という単純な方法で、サーバーのメモリを永続的に占領できる欠陥が発見されました。修正パッチは公開済みですが、CVE番号がないため自動ツールで検出できず、管理者が自分で気づいて対応する必要があります。OpenSSLを使っているシステムは、今すぐバージョンを確認しましょう。
