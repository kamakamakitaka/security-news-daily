# 「Nデイ」が「N時間」になった。パッチを速く当てるだけでは、もう守れない。

**元記事**: [N-day is Becoming N-Hour. Patching Faster Won't Save You.](https://inl03.netline.com/ltr6/?_m=3n.009a.4035.sp0ao46r89.339i)
**解説日**: 2025年7月11日

---

## 背景知識

この記事を理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### 🔧 セキュリティパッチって何？

ソフトウェア（アプリやOS）には、発見された「穴（脆弱性）」を塞ぐための修正プログラムが定期的に配布されます。これを「セキュリティパッチ」といいます。

たとえば「Windowsの更新プログラム」や「Chromeのアップデート」がこれにあたります。

### 🕳️ 脆弱性（ぜいじゃくせい）って何？

ソフトウェアに存在するプログラムの「バグ（欠陥）」のうち、悪用されるとシステムへの不正侵入やデータ盗取につながるものを「脆弱性」といいます。

### ⏱️ 「Nデイ攻撃」って何？

- **ゼロデイ攻撃**：まだ誰もパッチを作っていない脆弱性を突く攻撃
- **Nデイ攻撃**：パッチが**すでに公開されている**脆弱性を突く攻撃

「N」は「何日か経った（N日後）」という意味です。パッチが出た後でも、まだ更新していないシステムを狙います。

### 🤖 AIと「リバースエンジニアリング」

リバースエンジニアリングとは、「完成品を分解して、仕組みを逆に解析すること」です。

パッチ（修正プログラム）をリバースエンジニアリングすると、「どこに穴があったか」がわかってしまいます。それを使って攻撃ツール（エクスプロイト）を作ることができます。

## 何が起きたのか

### AIがパッチから「攻撃ツール」を超高速で作れることが判明しました

AIで有名なAnthropicという会社（ChatGPTを作ったOpenAIと競合する会社）が、自社のAI「Claude Opus（クロード）」の最新モデル「Mythos Preview」を使って、衝撃的な実験を行いました。

#### 🦊 Firefoxでの実験結果

| 条件 | 結果 |
|------|------|
| 使ったもの | パッチの「差分（変更箇所）」のみ |
| 対象 | Firefoxの18個のパッチ |
| 成果 | 8個の「実際に動く攻撃ツール」を自動生成 |
| **最速記録** | **パッチ公開から1時間以内に最初の攻撃ツール完成** |

しかもこの時、Firefoxの新バージョン（パッチ入り）はまだ**18日後にリリース予定**でした。つまり、パッチが世に出た瞬間に攻撃準備が整ってしまったのです。

#### 🪟 Windowsでの実験結果

| 条件 | 結果 |
|------|------|
| 使ったもの | ソースコードなし、バイナリ（機械語）のみ |
| 対象 | Windowsカーネルの21個のバグ |
| 成果 | 18個の「クラッシュ実証コード」、8個の「最高権限奪取チェーン」 |
| **最速記録** | **31分で完成** |
| コスト | 1つあたり約**2,000ドル（約30万円）**のAI処理費用 |

さらに怖いのは、その中の1つは「悪用される可能性：低」とMicrosoftが評価していたバグだったことです。この評価は「人間の研究者が調べた場合」を想定したものでしたが、AIには通用しませんでした。

## 技術的な詳細

### 🔍 パッチは「攻撃の地図」にもなる

パッチが配布されると、プログラムの「修正前」と「修正後」の差分（diff）が技術者に見えます。

```
修正前のコード: バグがある状態
修正後のコード: バグが塞がれた状態
↓
差分を見れば「どこに穴があったか」が一目瞭然！
```

これは例えると、**「ここに落とし穴があったので塞ぎました」という看板を立てるようなもの**です。その看板を見れば、悪意を持つ人が「じゃあ、まだ塞いでない場所を狙おう」とわかってしまいます。

### ⏱️ タイムラインの崩壊

従来（2〜3年前まで）：

```
パッチ公開 → 数週間〜数ヶ月 → 攻撃ツール完成 → 攻撃開始
（この間に管理者がパッチを当てられた）
```

現在（AI時代）：

```
パッチ公開 → 1時間以内 → 攻撃ツール完成 → 攻撃開始
（管理者がパッチを当てる前に攻撃される）
```

### 📊 現実の数字を見ると…

記事では怖いデータが紹介されています：

- 既知の脆弱性を修正するまでの**中央値：43日間**（前年より悪化！）
- 完全に修正される脆弱性は**全体の26%のみ**
- 1週間以内に修正できるのは**30〜40%だけ**
- 脆弱性が**1日以内に悪用される**ケースが2026年の平均（2024年は約53日）
- 毎日新しい脆弱性が**約135件**も報告されている（前年比40%増）

## なぜ重要なのか

### 🚨 「速くパッチを当てる」戦略が根本から崩れた

これまでセキュリティの世界では「パッチが出たらすぐ当てる」が鉄則でした。しかし今や、パッチが公開された瞬間にAIが攻撃ツールを作れるため：

> **パッチを当てる速さよりも、AIが攻撃ツールを作る速さの方が圧倒的に速い**

という状況になってしまいました。

### 🏢 企業や組織への影響

パッチを当てるには現実的な障害があります：

- **テスト期間が必要**（新しいパッチが他のシステムを壊さないか確認）
- **メンテナンス時間が必要**（サービスを止めてアップデートする「メンテナンスウィンドウ」）
- **サービス停止リスク**（24時間動き続けるシステムはすぐには止められない）

これらを考えると、1時間以内にパッチを当てることは、ほぼ不可能です。

### 🎯 「Vulnpocalypse（ヴァルンポカリプス）」という警告

研究者たちは新しい概念を提唱しています：

> **AIが脆弱性の公開を、防御側が対応するより速く武器化できる転換点** = 「Vulnpocalypse」

「Vulnerability（脆弱性）」+「Apocalypse（終末）」を合わせた造語で、脆弱性対応の世界が根本的に変わってしまったことを示しています。

## 対策・今後の展望

### ✅ 「パッチを速く当てる」から「本当に危険な脆弱性を見極める」へ

記事は「速くパッチを当てることをやめろ」と言っているわけではありません。方針の転換を訴えています：

#### ❌ 古い考え方
> 「全部の脆弱性にパッチを当てろ」

#### ✅ 新しい考え方
> 「**自分の環境で実際に攻撃できる脆弱性**はどれか？ 攻撃されたとき、自分の防御で止められるか？ それを証明できるか？」

### 🛡️ 具体的に何をすればいいか

1. **優先順位づけ**
   すべての脆弱性が同等の危険ではありません。自分のシステムで**実際に悪用できるか**を確認することが重要です。

2. **多層防御（レイヤードディフェンス）**
   パッチだけに頼らず、侵入を前提とした複数の防御層を用意する。

3. **検証（バリデーション）**
   「このパッチが当たっていれば安全」と仮定するのではなく、**実際に攻撃できないか確認する**。

4. **継続的なモニタリング**
   パッチを当てる速度より、**異常な動きをいち早く検知して対応する**体制の整備。

### 📱 私たちが今日からできること

- OSやアプリの**自動更新をON**にする（できる限り早くパッチを当てることは今でも重要）
- 使っていないソフトは**アンインストール**する（攻撃対象を減らす）
- 重要なデータは**バックアップ**を取る（攻撃を受けても被害を最小化）

## 用語解説

| 用語 | 意味 |
|------|------|
| **パッチ** | ソフトウェアの欠陥を修正するための更新プログラム |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアに存在する、悪用可能なバグや欠陥 |
| **ゼロデイ攻撃** | まだパッチが存在しない脆弱性を突く攻撃 |
| **Nデイ攻撃** | パッチが公開済みの脆弱性を、まだ更新していないシステムに対して行う攻撃 |
| **エクスプロイト** | 脆弱性を実際に攻撃するために作られたツールやコード |
| **リバースエンジニアリング** | 完成品を逆に分解・解析して、仕組みを理解すること |
| **diff（差分）** | プログラムの修正前と修正後の変更箇所を示したもの |
| **CVE** | 脆弱性に付けられる世界共通の識別番号（例：CVE-2025-12345） |
| **SYSTEM権限** | Windowsにおける最高レベルの管理者権限 |
| **Vulnpocalypse** | AIが脆弱性公開を即座に武器化できる転換点を指す造語 |
| **カーネル** | OSの核心部分。ここを乗っ取られると全権限を奪われる |
| **多層防御** | パッチだけでなく、複数の防御手段を組み合わせる考え方 |
| **DBIR** | Verizon社が毎年発表するデータ侵害調査報告書 |
