# 新型ランサムウェア「ENCFORGE」がAIモデルファイルを狙い撃ち！Langflowの脆弱性を悪用した攻撃を解説

**元記事**: [New ENCFORGE Ransomware Targets AI Model Files in Langflow RCE Attack](https://inl03.netline.com/ltr6/?_m=3n.009a.4035.sp0ao46r89.33a6)
**解説日**: 2025年7月21日

---

## 背景知識

まず、このニュースを理解するために必要なキーワードをざっくり説明しますね。

### 🤖 Langflow（ラングフロー）とは？
AIを使ったシステムを「ブロックを組み合わせるように」簡単に作れるツールです。プログラミングに詳しくなくても、AIアプリのパーツをつなぎ合わせて動かすことができます。企業が「AIエージェント（自動で動くAI）」を開発するときによく使われています。

### 💰 ランサムウェアとは？
「身代金要求型ウイルス」のことです。ファイルを暗号化（鍵をかけて読めなく）して、「お金を払ったら鍵を渡してあげる」と脅すマルウェア（悪意のあるプログラム）です。病院や学校、企業が被害を受けることが多く、日本でも毎年大きなニュースになっています。

### 🧠 AIモデルファイルとは？
AIが「学習した結果」を保存したファイルです。たとえばChatGPTのような大規模AIを作るには、何か月もかけて大量のデータで学習させます。その学習結果（＝モデルファイル）はとても高価な資産で、消えたり使えなくなったりすると企業に莫大な損害が出ます。

### 🔐 RCE（リモートコード実行）とは？
遠く離れた場所から、対象のサーバーに「好き勝手な命令（コード）を実行させられる」攻撃のことです。家のドアに鍵がかかっていないどころか、「どんな命令でも聞く使用人」が玄関に立っているようなイメージです。

---

## 何が起きたのか

セキュリティ企業「Sysdig（シスディグ）」の研究者が、**「JADEPUFFER（ジェイドパファー）」** という攻撃グループによる新しい攻撃を発見しました。

この攻撃グループは以前にも同じサーバーを攻撃しており、今回は **「ENCFORGE（エンクフォージ）」** という新型ランサムウェアを使って、**AIシステムのファイルを丸ごと暗号化して使えなくする**という手口を使いました。

攻撃の流れをざっくりまとめると：

```
① Langflowの脆弱性（CVE-2025-3248）を悪用してサーバーに侵入
     ↓
② サーバー内を探り回ってパスワードなどを収集
     ↓
③ ENCFORGEランサムウェアをダウンロード・実行
     ↓
④ AIモデルファイルをすべて暗号化して身代金を要求
```

## 技術的な詳細

### 🚪 侵入口：Langflowの深刻な脆弱性

Langflowのバージョン1.3.0より古いものには、**「認証なしで誰でもPythonコードを実行できる」** という致命的な欠陥（CVE-2025-3248）がありました。

> **例え話で説明すると…**
> お店のレジに「店員に言わなくても誰でも操作できるボタン」があって、しかもそのボタンを押すと「金庫を開ける」「防犯カメラを止める」など何でもできる状態です。

この脆弱性の危険度スコアは **9.8/10.0** という超高評価（危険度が高いほどスコアが高い）。アメリカの政府機関CISAも「実際に悪用されている」として警告リストに載せています。

### 🦠 ENCFORGEランサムウェアの仕組み

ENCFORGEは「Go言語」で作られたプログラムで、以下のような特徴があります：

#### 狙うファイルの種類（約180種類！）
| ファイルの種類 | 具体例 |
|---|---|
| PyTorch・TensorFlowのモデル | `.pt`, `.pth`, `.ckpt` |
| Hugging Faceのモデル | `.safetensors` |
| ローカルLLM用モデル | `.gguf`, `.ggml` |
| ベクターデータベース | FAISSインデックス |
| 学習データ | Parquet, Arrowファイル |

これはただの「なんでも暗号化するウイルス」ではなく、**明らかにAI開発環境を意図的に狙っています**。「LoRAファインチューニングアダプター」など、AI開発者しか知らないマニアックなファイル形式まで名指しで狙っているからです。

#### 暗号化の方法
- **AES-256-CTR**という強力な方式でファイルを暗号化
- ファイル全体ではなく「一部分だけ」暗号化することで素早く処理（LockBitなど有名ランサムウェアと同じ手法）
- 暗号化されたファイルには `.locked` という拡張子がつく

#### 身代金メモ
`README`、`HOW_TO_DECRYPT`、`README_DECRYPT` という名前のファイルを残し、連絡先として `e78393397@proton.me` というメールアドレスを記載。このアドレスは前回の攻撃でも使われており、同じ犯人だと特定できる手がかりになっています。

#### 巧妙な隠れ方
攻撃者のサーバーでは `/.lockd`（ドットから始まるファイル名）として隠されており、通常のファイル一覧には表示されないようになっています。これはLinuxの「隠しファイル」の仕組みを悪用したものです。

## なぜ重要なのか

### 🎯 AIを狙った攻撃は新時代の脅威

今までのランサムウェアは「会社の書類」「顧客データ」などを狙うことが多かったです。しかし今回は**AIモデルファイルという、まったく新しい種類の"資産"**が標的になりました。

AIモデルの学習には：
- 💸 数千万〜数億円のコスト
- ⏱️ 数週間〜数か月の時間
- 🖥️ 大量の高性能コンピューター

が必要です。これが一瞬で使えなくなれば、被害は計り知れません。

### ⚠️ 検知が難しかった

セキュリティ解析ツールにかけても、**発見時点では「ウイルスなし」と判定されていました**。つまり、既存のウイルス対策ソフトでは防げなかった可能性があります。

### 🔄 攻撃グループが"進化"している

JADEPUFFERは最初の攻撃で「簡易的な自作スクリプト」を使っていましたが、今回は「専用に設計されたランサムウェア」を使いました。攻撃者が着実にレベルアップしていることを示しています。

## 対策・今後の展望

### ✅ 今すぐできる対策

1. **Langflowをバージョン1.3.0以上に更新する**
   これが最優先！古いバージョンを使い続けることは「玄関を開けっぱなしにすること」と同じです。

2. **AIモデルファイルのバックアップを取る**
   重要なモデルファイルは「ネットワークにつながっていない場所」にも保存しましょう。

3. **Dockerソケットへのアクセスを制限する**
   今回の攻撃では `/var/run/docker.sock` が悪用されました。コンテナの権限設定を見直しましょう。

4. **不審なプロセスやファイルを監視する**
   `.locked` 拡張子のファイルが突然増えていないか定期的に確認することが有効です。

5. **ゼロトラスト設計を心がける**
   「内部だから信頼する」ではなく、「すべてのアクセスを確認する」という考え方が重要です。

### 🔭 今後の動向

AI開発ツールを狙う攻撃は今後さらに増えると予想されます。AI産業が急速に成長するにつれ、「AIの資産を人質にする」ビジネスモデルが攻撃者にとって魅力的になっているからです。AI開発をしている企業は特に警戒が必要です。

## 用語解説

| 用語 | 意味 |
|---|---|
| **Langflow** | AIアプリをビジュアルで作れるオープンソースツール |
| **ランサムウェア** | ファイルを暗号化して身代金を要求するウイルス |
| **RCE（リモートコード実行）** | 遠隔からサーバーに任意の命令を実行させる攻撃 |
| **CVE-2025-3248** | 今回悪用されたLangflowの脆弱性の識別番号 |
| **CVSS 9.8** | 脆弱性の危険度スコア（10点満点中9.8は超危険） |
| **CISA** | アメリカのサイバーセキュリティ機関 |
| **AES-256-CTR** | 非常に強力な暗号化方式（解読はほぼ不可能） |
| **Go言語** | Googleが開発したプログラミング言語。コンパクトで高速 |
| **UPX** | 実行ファイルを圧縮するツール（解析を難しくするためにも使われる） |
| **Docker / Dockerソケット** | アプリをコンテナという仮想環境で動かす技術。ソケットを乗っ取ると全コンテナを操作できる |
| **GGUF/GGML** | ローカルPCでAIを動かすためのモデルファイル形式 |
| **LoRAアダプター** | 既存のAIモデルを少ないコストで追加学習させるためのファイル |
| **JADEPUFFER** | 今回の攻撃グループの名称（セキュリティ研究者がつけたコードネーム） |
| **ENCFORGE** | 今回発見された新型ランサムウェアの名称 |
| **C2サーバー（C&C）** | 攻撃者がマルウェアに命令を送るための「指令サーバー」 |
