# AWS Kiroの欠陥：毒入りウェブページが設定ファイルを書き換えてコードを実行できた

**元記事**: [AWS Kiro Flaw Let a Poisoned Web Page Rewrite Its Config and Run Code](https://inl03.netline.com/ltr6/?_m=3n.009a.4036.sp0ao46r89.33bq)
**解説日**: 2026年7月22日

---

## 背景知識

まず、この記事を理解するために必要なキーワードを整理しましょう。

### 🤖 Kiro（キロ）とは？
AWSが開発した「AIアシスタント付きのプログラミング専用ソフト（IDE）」です。プログラマーが「このファイルを読んでまとめて」「このWebページを見てコードを書いて」と頼むと、AIが自動で作業してくれます。便利な反面、AIが「自分でファイルを読んだり書いたりできる」という強力な権限を持っています。

### ⚙️ MCP（Model Context Protocol）とは？
AIがどんな外部ツールを使えるかを定義する仕組みです。「AIにこのプログラムを使わせてよい」という許可リストのようなものです。Kiroでは `~/.kiro/settings/mcp.json` というファイルにその設定が書かれています。

### 💉 プロンプトインジェクション（Prompt Injection）とは？
AIへの「指示文（プロンプト）」に、ユーザーが気づかないうちに悪意ある命令を混ぜ込む攻撃手法です。たとえば、AIに「このページを要約して」と頼んだとき、そのページに見えない形で「ついでにこの悪いコードも実行して！」という指示が隠されていた場合、AIがそれに従ってしまうことがあります。

### 🔐 リモートコード実行（RCE: Remote Code Execution）とは？
攻撃者が、遠隔から被害者のコンピュータ上で自由にプログラムを動かせてしまう脆弱性です。最も危険な攻撃の一つで、「コンピュータを乗っ取られた」状態に近いです。

---

## 何が起きたのか

セキュリティ企業の **Intezer** と **Kodem Security** が共同で、AWSのAIプログラミングツール「Kiro」に深刻な脆弱性（セキュリティの穴）を発見しました。

**ひと言で言うと：**
> 「悪意ある文字が仕込まれたWebページをKiroに読ませるだけで、攻撃者がそのコンピュータを乗っ取れてしまう」

具体的に何が起きるかというと：

1. 開発者が「このAPIのドキュメントページを要約して」とKiroに頼む
2. そのページに、肉眼では見えない極小の白文字で悪意ある命令が書かれている
3. KiroのAIがその隠し命令を読み取り、設定ファイル（mcp.json）を勝手に書き換える
4. 書き換えられた設定ファイルを元に、攻撃者のコードがコンピュータ上で実行される
5. 開発者は何もおかしいことに気づかない

AWSはすでにこの問題を修正済みです。

## 技術的な詳細

### 👁️ 見えない文字で命令を隠す

攻撃者はWebページに次のようなCSSスタイルで文字を隠します：

```html
<span style="color:#fff; font-size:1px;">
  [ここに悪意ある命令を書く]
</span>
```

- 文字色が白（背景と同じ）
- 文字サイズが1ピクセル（ほぼ見えない）

人間がページを見ても、普通のAPIドキュメントにしか見えません。でも**AIは画面を「見る」のではなく、HTMLのテキストを「読む」**ので、この隠し文字もしっかり読んでしまいます。

### ⚠️ 承認なしに設定ファイルが書き換わる

Kiroには本来「危険な操作をするときは開発者に確認する」という安全機能があります。でも問題が2つありました：

1. **`mcp.json` ファイルへの書き込みは確認なしでOKだった**（`fsWrite`ツールで承認不要）
2. **確認ポップアップが表示されても、設定は関係なく反映されてしまっていた**（「キャンセル」を押しても止まらない！）

これはまるで、「鍵を閉めても、扉が関係なく開いてしまう」ような状態です。

### 🔄 攻撃の流れ（わかりやすい図解）

```
[攻撃者]
  ↓ 毒入りWebページを用意
[開発者] → 「このページを要約して」とKiroに依頼
  ↓
[Kiro] → ページを読む → 隠し命令を発見
  ↓
[Kiro] → mcp.jsonを悪意ある設定に書き換える（承認なし）
  ↓
[Kiro] → 設定を自動リロード → 攻撃者のコードが起動
  ↓
[攻撃者] → 開発者のPCを遠隔操作できる状態に！
```

### 📊 実証実験（PoC）で確認されたこと

研究者たちは実際に攻撃が成功することを確認しました。実験では「ホスト名・ユーザー名・OSの種類を10秒ごとに送信する」という比較的軽い動作を確認するに留めましたが、理論上は以下のことが可能です：

- パスワードやソースコードの盗難
- マルウェア（悪意あるプログラム）の埋め込み
- 社内ネットワークへの侵入

## なぜ重要なのか

### 🎯 狙われるのは「開発者」

開発者のPCには非常に価値の高い情報が集まっています：
- 企業のソースコード（製品の設計図）
- AWS・GitHubなどのアクセスキー
- データベースのパスワード
- 社内システムへのアクセス権限

開発者1人のPCが乗っ取られるだけで、企業全体が危険にさらされる可能性があります。

### 😰 ユーザーは何もできない

この攻撃の怖い点は、**開発者が正しい行動を取っていても防げない**ことです：

- 「信頼できそうなドキュメントページを読んだだけ」
- 「ポップアップが出たのでキャンセルを押した」

それでも攻撃は成功してしまいます。これはユーザーの不注意の問題ではなく、ツール自体の設計上の欠陥です。

### 🔁 同じ種類のバグが繰り返されている

記事によると、これはKiroで**何度も繰り返されている同じ種類の問題**です：

| 時期 | 発見者 | 問題のファイル | 対応 |
|------|--------|--------------|------|
| 2025年7月（リリース当日） | Johann Rehberger | mcp.json | 一部モードのみ修正 |
| 2026年初頭 | Cymulate | .vscode/tasks.json | CVE番号付きで修正 |
| 2026年2月 | Intezer/Kodem | mcp.json | 修正済み（CVEなし） |

## 対策・今後の展望

### ✅ 今すぐできる対策

1. **Kiroを最新バージョンにアップデートする**
   - AWSはすでにパッチ（修正プログラム）をリリース済みです
   - バージョン0.9.2（macOS）・0.10.16（Ubuntu）以前は影響を受けています

2. **AIに読ませるWebページに注意する**
   - 出所不明なWebページをAIに読み込ませない
   - 特に外部の非公式ドキュメントには注意

3. **AIツールには最小限の権限しか与えない**
   - 「なんでもできるAI」より「必要なことだけできるAI」の方が安全です

### 🔮 今後の展望

この問題は「AIが自律的に行動できるツール」全般に共通する課題を示しています。AIがより賢くなればなるほど、「人間のチェックを飛ばして動く」場面が増え、セキュリティリスクも高まります。

業界全体として、**「AIが外部コンテンツを読み込むときの安全ルール」を標準化する必要がある**と多くの専門家が指摘しています。

## 過去記事との関連

以前、「**Microsoft Azure DevOps MCPの脆弱性：隠しコメントがAIレビュアーを乗っ取る**」について解説しました。あの記事でも「AIが読み込んだ内容に隠された命令が混じっていた」という同じ種類の攻撃が登場しましたね。

今回のKiroの問題も、根本的な仕組みは同じ「プロンプトインジェクション」です。

> **AIが外部のコンテンツ（Webページ、コメント、ドキュメントなど）を読み込む場面では、その中に悪意ある命令が隠されている可能性がある**

という教訓は、KiroでもAzure DevOpsでも共通しています。AIツールが普及するにつれて、この種の攻撃は増え続けると予想されます。「AIを使う便利さ」と「AIを悪用されるリスク」のバランスをどう取るかが、今後のセキュリティの大きなテーマになっています。

## 用語解説

| 用語 | 意味 |
|------|------|
| **IDE（統合開発環境）** | プログラマーがコードを書くための専用ソフト。VS CodeやXcodeなどが有名 |
| **Kiro** | AWSが開発したAI搭載のIDE。AIが自動でコードを書いたりファイルを操作したりできる |
| **MCP（Model Context Protocol）** | AIがどんな外部ツールを使えるかを定義するルール。設定はmcp.jsonに記述される |
| **プロンプトインジェクション** | AIへの指示文に悪意ある命令を混ぜ込む攻撃 |
| **RCE（リモートコード実行）** | 攻撃者が遠隔から被害者のPCでプログラムを動かせる最も危険な脆弱性の一つ |
| **PoC（概念実証）** | 「この攻撃が本当に可能か」を実際に試して証明する実験 |
| **CVE** | セキュリティの脆弱性に付けられる世界共通の識別番号（例：CVE-2026-10591） |
| **fsWrite** | Kiroがファイルを書き込む際に使うツール機能 |
| **Autopilotモード** | KiroのデフォルトのAI自律動作モード。ユーザーの確認なしにいろいろな操作をする |
| **Supervisedモード** | KiroのAI補助モード。重要な操作の前に確認を求める（より安全だが制限あり） |
| **CSS** | Webページの見た目を変えるためのプログラミング言語 |
| **パッチ** | セキュリティの穴を塞ぐための修正プログラム |
