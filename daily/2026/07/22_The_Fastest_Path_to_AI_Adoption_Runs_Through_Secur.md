# AIの導入を一番スムーズに進められるのはセキュリティチームだった

**元記事**: [The Fastest Path to AI Adoption Runs Through Security](https://inl03.netline.com/ltr6/?_m=3n.009a.4036.sp0ao46r89.33aq)
**解説日**: 2025年7月11日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### 🏢 企業のセキュリティチームって何をしているの？
会社の中には「セキュリティチーム」と呼ばれる人たちがいます。彼らの仕事は、会社のデータや情報システムを守ること。新しいソフトウェアやサービスを使う前に「これは安全か？」を審査するのも、重要な仕事の一つです。

### 🤖 「AIツール」って具体的にどんなもの？
最近、職場でよく使われているAIツールには、たとえばこんなものがあります：
- **ChatGPT** などの文章作成アシスタント
- **GitHub Copilot** などのプログラムコードを自動で書いてくれるツール
- **Otter.ai** などの会議を自動で文字起こし・要約してくれるツール

### 🔒 「シャドーAI」って何？
会社が正式に許可していないのに、従業員が勝手に使っているAIツールのことです。「シャドー（影）」という言葉が示す通り、会社のセキュリティチームには見えていない状態で使われています。

> **例え話**：学校が「スマホ禁止」と言っているのに、こっそり授業中にスマホを使っている生徒がいる状態に似ています。ルールを守っていないのと同じです。

### 🔑 「OAuth」って何？
**OAuth（オー・オース）**とは、あるアプリが別のサービスのデータにアクセスするときの「鍵の渡し方のルール」のことです。

> **例え話**：「Googleアカウントでログイン」ボタンを押したことありますよね？あれがOAuthの仕組みです。便利な反面、そのアプリにGoogleドライブの中身を全部見られてしまう可能性があります。

### 👔 「CISO」って誰？
**CISO（シーアイエスオー）**とは「Chief Information Security Officer（最高情報セキュリティ責任者）」の略。会社全体のセキュリティを統括するトップの人です。

## 何が起きたのか

この記事は、ある重要な変化について語っています。

**「AIをどんどん使いたい社員」vs「安全を守りたいセキュリティチーム」**という対立が、今まさに多くの企業で起きています。

マッキンゼー（世界的に有名なコンサルティング会社）の調査によると、**職場で何らかのAIツールを使っている社員は全体の76%**にのぼります（去年は55%でした）。たった1年で急増していますね。

しかし問題があります。これらのAIツールの多くは、**セキュリティチームによる審査を受けていない**のです。

## 技術的な詳細

### 😤 今まで起きていた「いたちごっこ」

従来のセキュリティチームの対応はこんな感じでした：

```
① 社員が便利なAIツールを発見して使い始める
         ↓
② セキュリティチームが「危険かも！」とブロック（使用禁止）
         ↓
③ 社員が「じゃあ別の方法で…」と抜け道を数日で見つける
         ↓
④ ① に戻る（繰り返し）
```

なぜこうなるかというと、**スピードの問題**があります。

| ルートの種類 | かかる時間 |
|---|---|
| 公式の承認ルート（セキュリティチームが審査）| 約6週間 |
| 抜け道（非公式に使い始める）| 約6分 |

6週間と6分なら、社員がどちらを選ぶかは明らかですよね。

### ✅ 「うまくいっているセキュリティチーム」は何が違うの？

記事が紹介している**賢いアプローチ**はこうです：

#### 1. 「禁止」より「整備」を優先する
まず使って良いAIツールのリストを作り、**社員が速やかにアクセスできる公式ルート**を用意する。

#### 2. 「現状把握」を最初にやる
- 今どんなAIツールが社内で動いているか
- 誰がどのツールを使っているか
- 各ツールはどのデータにアクセスできるか

これを**OAuthの監査（チェック）**や**ブラウザの監視ツール**で把握します。

#### 3. AIポリシー（使用ルール）の4つの要素

効果的なAI使用ルールには以下が必要です：

| 要素 | 内容 |
|---|---|
| ① 承認済みツールのリスト | 使って良いAIツールと、それへのアクセス方法 |
| ② 禁止データの明示 | AIツールに入れてはいけない情報の種類 |
| ③ 学習オプトアウトの確認 | 承認済みツールが社員の入力データを学習に使わないかの確認 |
| ④ 申請プロセス | 新しいツールを使いたいときの申請方法と、回答までの期限 |

#### 4. 「理由」を説明することが超重要！

ここが最大のポイントです。ルールを「ダメなものはダメ」と伝えるだけでなく、**なぜそのルールがあるのかを説明する**ことが大切です。

> **例え話**：「廊下は走っちゃダメ！」とだけ言われると、先生がいないときは走ってしまいますよね。でも「廊下を走ると誰かとぶつかってケガをする危険があるから」と理由を知ると、自然に気をつけるようになります。

記事では具体例として、「生産性ツールをGoogleワークスペースと連携させると、共有ドライブの中身を第三者のサービス業者に丸ごと渡してしまう可能性がある」という**リスクの理由**を社員に伝えることが重要だと述べています。

## なぜ重要なのか

### 📊 数字で見る深刻さ
- 職場でAIを使う社員：**76%**（前年比+21ポイント）
- その多くが**セキュリティ審査なし**で使用中

### 🔥 何が危険なの？
未審査のAIツールを使うリスクは、大きく3つあります：

1. **情報漏洩のリスク**
   社員が機密情報をAIに入力すると、そのデータが外部サーバーに送られる場合があります。

2. **第三者へのアクセス許可問題**
   OAuthを使ったアプリは、知らないうちに会社の重要ファイルへのアクセス権を持ってしまうことがあります。

3. **見えないリスク（ガバナンスの欠如）**
   セキュリティチームがどのツールが使われているか把握できなければ、問題が起きてから対応するしかなくなります。

### 🌟 うまくいくとどうなる？
逆に、セキュリティチームが「使いやすい公式ルート」を整備すると：
- **シャドーAIが自然に減る**（便利な公式ルートがあれば、抜け道を使う理由がなくなる）
- **セキュリティチームの信頼度が上がる**
- **セキュリティチームが会社の経営戦略の議論に参加できるようになる**

## 対策・今後の展望

### 🛡️ 企業がすべき具体的な対策

#### STEP 1：現状の「見える化」
まず社内でどんなAIツールが使われているかを把握する。OAuthの監査や監視ツールを使う。

#### STEP 2：「使ってOKリスト」を作る
承認済みAIツールのリストを公開し、社員が速やかにアクセスできるようにする。

#### STEP 3：申請の仕組みを作る
新しいAIツールを使いたい社員が申請できる窓口を設け、**回答期限を設けて守る**。

#### STEP 4：理由つきのポリシーを周知する
「なぜこのルールが必要か」を丁寧に説明する。一度読んで終わりではなく、日常的に意識できる習慣につなげる。

### 🔮 今後の動向
AI技術の進化は止まりません。記事では「どんなガバナンスの取り組みをしても、AIの導入は加速し続ける」と述べています。

この流れに乗り遅れないためには、セキュリティチームが**「禁止する番人」から「安全な道を整備するガイド」**に変わっていく必要があります。

## 用語解説

| 用語 | 意味 |
|---|---|
| **AI governance（AIガバナンス）** | AIツールの使い方に関するルールや管理の仕組み全体 |
| **シャドーAI（Shadow AI）** | 会社が公式に許可していないのに社員が勝手に使っているAIツール |
| **CISO（シーアイエスオー）** | Chief Information Security Officer。会社のセキュリティ責任者の最高位 |
| **OAuth（オー・オース）** | あるアプリが別のサービスのデータへアクセスする許可を与える仕組み |
| **オプトアウト** | 何かに参加しない（断る）選択をすること。ここでは「AIがユーザーの入力データを学習に使わない設定」を指す |
| **ガバナンス** | 組織がルールや方針に従って適切に管理・運営されているかどうか |
| **McKinsey（マッキンゼー）** | 世界的に有名な経営コンサルティング会社。信頼性の高いビジネス調査データを多数発表している |
| **バックログ（承認待ち）** | 処理を待っている仕事や申請が積み重なっている状態 |
| **ポリシー** | 組織の方針・ルール・規則のこと |
