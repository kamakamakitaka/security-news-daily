# GitHub Actionsのランナーが攻撃に悪用！cPanelサーバーを狙った大規模キャンペーン

**元記事**: [Attackers Weaponize GitHub Actions Runners to Target cPanel and WHM Servers](https://inl03.netline.com/ltr6/?_m=3n.009a.4037.sp0ao46r89.33ca)
**解説日**: 2025年7月14日

---

## 背景知識

このニュースを理解するために、まず関係するサービスや仕組みを整理しましょう。

### 🏠 cPanelとWHMって何？
**cPanel（シーパネル）** と **WHM（Web Host Manager）** は、ウェブサイトをホスティング（インターネット上で公開）するためのサーバー管理ツールです。

> 🏫 **例え話**: cPanelは「マンションの自分の部屋の鍵」、WHMは「マンション全体を管理するオーナー用の鍵束」のようなものです。WHMに侵入されると、そのサーバー上のすべてのサイトを乗っ取れてしまいます。

世界中のレンタルサーバー会社が使っており、非常に多くのウェブサイトの管理基盤になっています。

---

### 📦 GitHubとPackagistって何？
- **GitHub（ギットハブ）**: プログラマーがコード（プログラム）を保存・公開・共有するためのプラットフォーム。世界中の開発者が使っています。
- **Packagist（パッカジスト）**: PHP言語のプログラムで使う「部品（ライブラリ）」を集めたカタログサイト。料理レシピで言えば「食材の宅配サービス」のようなもので、開発者が必要なパーツをダウンロードして使えます。

---

### ⚙️ GitHub Actionsって何？
**GitHub Actions（ギットハブ アクション）** は、GitHubが提供する「自動作業ツール」です。コードが変更されたとき、自動でテストを実行したりすることができます。

> 🤖 **例え話**: 「コードが更新されたら自動でチェックする番犬」のようなイメージです。今回はこの「番犬」が攻撃者に乗っ取られて、悪さをする道具にされてしまいました。

---

### 👤 dinushchathuryaって誰？
スリランカ出身の正規のPHP開発者で、スリランカの郵便区域や病院情報などをまとめたライブラリを公開していた、無害な開発者です。この人のアカウントが今回の攻撃に悪用されました。

---

## 何が起きたのか

2026年7月12〜13日（記事の日付）、攻撃者が **dinushchathuryaという正規の開発者のGitHubアカウントに不正アクセス** し、その人が公開していた10個のPHPライブラリのコードに **悪意のある自動作業ファイル（ワークフロー）を大量に仕込みました**。

### 📋 被害を受けたライブラリ（10個）
| ライブラリ名 | 内容 |
|---|---|
| nationality-list | 国籍リスト |
| srilankan-divisional-secretariats | スリランカの行政区域情報 |
| srilankan-gn-divisions | スリランカの地区情報 |
| srilankan-local-authorities | スリランカの地方自治情報 |
| srilankan-mobile-number-validator | スリランカの電話番号バリデーター |
| srilankan-state-hospitals | スリランカの国立病院情報 |
| srilankan-universities | スリランカの大学情報 |
| uk-mobile-number-validator | イギリスの電話番号バリデーター |
| uk-post-code | イギリスの郵便番号情報 |
| websmslk | SMS送信サービス |

これらのライブラリは **Packagistを経由して自動的に同期** され、悪意のあるコードが広まりました。

### 😮 巧妙なポイント
一般的なこの手の攻撃は「悪意あるパッケージをダウンロードした人のPC」で悪いことが起きます。しかし今回は違います。**GitHubのサーバー（GitHub-hosted runners）上で攻撃を実行** するという、非常に巧妙な手口でした。

## 技術的な詳細

### 🔧 攻撃の流れ（ステップバイステップ）

```
①  攻撃者がdinushchathuryaのGitHubアカウントを乗っ取る
        ↓
②  10個のライブラリに合計583個の悪意あるワークフローファイルを仕込む
        ↓
③  コードが更新されると、GitHubのサーバー（ランナー）が自動起動
        ↓
④  攻撃者のサーバー（43.228.157.68）から攻撃ツールをダウンロード
        ↓
⑤  インターネット上のcPanel/WHMサーバーを自動スキャン・攻撃
        ↓
⑥  脆弱なサーバーから認証情報などを根こそぎ盗む
        ↓
⑦  結果を攻撃者のサーバーに送信
```

### 🔍 何を盗もうとしたのか
攻撃ツールが狙っていた情報は以下の通りです：

- 🔑 **AWSの認証情報** → クラウドサービスへのアクセス権
- 🔑 **GitHubやGitLabのトークン** → 他の開発者リポジトリへのアクセス権
- 🤖 **OpenAIやGoogle APIキー** → AI・クラウドサービスの利用権（課金も含む）
- 💳 **Stripeキー** → 決済サービスへのアクセス
- 📧 **SendGrid/Mailgunの認証情報** → メール送信サービス（スパム送信に悪用可能）
- 🗄️ **データベース情報** → サイトのユーザー情報など
- 🖥️ **SSH情報** → サーバーへのリモートアクセス権

### 🎯 悪用された脆弱性：CVE-2026-41940
今回の攻撃では **「認証バイパス脆弱性」** が悪用されました。

> 🔓 **例え話**: 本来、cPanelにログインするには正しいパスワードが必要です。しかしこの脆弱性を使うと、パスワードなしで「こんにちは、私は管理者です！」と嘘をついてログインできてしまいます。

### 🌐 規模の大きさ
- 仕込まれた悪意あるワークフローファイルの数：**583個**（10パッケージ合計）
- GitHubに存在する同様のワークフローファイルの数：**約6,100個**（！）
- これは「dinushchathurya」だけでなく、**もっと広い範囲に及ぶキャンペーン** であることを示しています

## なぜ重要なのか

### 💡 これが特に危険な3つの理由

#### 1. 「信頼されたインフラ」を悪用している
GitHubは世界中の開発者が信頼して使うサービスです。そのGitHubのサーバーを攻撃の踏み台にすることで、**一般的なセキュリティ対策をすり抜けやすく**なります。企業のファイアウォール（防火壁）も「GitHubからの通信」は通すことが多いからです。

#### 2. 攻撃者のコストがほぼゼロ
GitHubはコードのテストに使えるサーバー（ランナー）を **無料で提供** しています。攻撃者はこれを利用することで、自分でサーバーを用意するコストをゼロにして大規模な攻撃ができてしまいます。

> 💸 **例え話**: レンタカーを使って犯罪を行うようなもの。自分の車（サーバー）を持たなくていいので足がつきにくく、コストもかかりません。

#### 3. 正規の開発者が「踏み台」にされた
無実のdinushchathuryaさんのアカウントが悪用されました。このような攻撃は、開発者の評判を傷つけるだけでなく、**そのライブラリを信頼して使っていた開発者・企業にも被害が及ぶ可能性**があります。

### 📊 影響を受ける可能性があるのは？
- cPanelを使っているウェブホスティング会社・サーバー管理者
- dinushchathuryaのライブラリを使っているPHP開発者・企業
- GitHubをCI/CDとして使っているすべての開発者（広義には）

## 対策・今後の展望

### ✅ サーバー管理者ができること

| 対策 | 説明 |
|---|---|
| **cPanelを最新版に更新** | CVE-2026-41940のパッチ（修正プログラム）を適用する |
| **ログの確認** | 不審なアクセスがないか定期的にログをチェック |
| **多要素認証（MFA）の有効化** | パスワードだけでなく、スマホアプリなどによる二重認証を設定 |
| **不要なポートを閉じる** | cPanelのアクセスを特定のIPアドレスに制限する |

### ✅ PHP開発者ができること

| 対策 | 説明 |
|---|---|
| **dependabotなどの利用** | 依存パッケージの変更を自動監視する |
| **開発版（dev版）を本番環境で使わない** | 今回は「development version」が標的になった |
| **パッケージのハッシュ値を確認** | パッケージが改ざんされていないか確認する |

### ✅ GitHub使用者（開発者・企業）ができること

| 対策 | 説明 |
|---|---|
| **GitHub Actionsのワークフローを定期的に監査** | 知らないうちに不審なワークフローが追加されていないか確認 |
| **外部から追加されたActions設定を信頼しない** | 第三者のワークフローは特に注意して確認する |
| **GitHubアカウントに多要素認証を設定** | アカウント乗っ取りを防ぐ最も基本的な対策 |

### 🔭 今後の展望
- GitHubはこのような「ランナーの悪用」に対する対策を強化することが求められています
- 今回は1人の開発者だけでなく、**約6,100個ものワークフローファイル**が確認されており、まだ全貌が明らかではありません
- オープンソース（公開されたコード）のセキュリティ監視がますます重要になっています

## 用語解説

| 用語 | 読み方 | 説明 |
|---|---|---|
| **cPanel** | シーパネル | ウェブサーバー管理ツール。ウェブサイトのファイル管理やメール設定などができる |
| **WHM** | ダブリューエイチエム | Web Host Managerの略。複数のcPanelアカウントをまとめて管理できる上位管理ツール |
| **GitHub Actions** | ギットハブ アクション | コードの変更を検知して自動でタスクを実行する仕組み |
| **ランナー（Runner）** | — | GitHub Actionsが実際に動作する仮想サーバー（コンピューター） |
| **Packagist** | パッカジスト | PHPのライブラリ（部品）を配布するサービス |
| **ワークフロー（Workflow）** | — | GitHub Actionsの自動実行手順を記述したファイル（YAML形式） |
| **CVE** | シーブイイー | セキュリティの脆弱性（弱点）に付けられる識別番号 |
| **認証バイパス** | — | 本来必要なパスワード認証などを不正にスキップする攻撃手法 |
| **C2サーバー** | シーツーサーバー | Command and Controlの略。攻撃者が感染させたシステムを遠隔操作するためのサーバー |
| **SSH** | エスエスエイチ | サーバーに遠隔接続するための暗号化通信の仕組み |
| **APIキー** | エーピーアイキー | サービスを利用するための「パスポート」のようなもの。漏れると他人に利用され課金される恐れも |
| **サプライチェーン攻撃** | — | ソフトウェアの「製造〜流通」の過程を狙う攻撃。正規のパッケージに悪意あるコードを混入する手法 |
| **YAML** | ヤムル | 設定ファイルを書くための記法の一種。GitHub Actionsのワークフロー定義に使われる |
| **トークン** | — | パスワードの代わりに使う認証情報。漏れるとサービスへの不正アクセスに使われる |

---

> 💬 **まとめ**: 今回の攻撃で特に怖いのは、「信頼できる開発者のライブラリ」と「信頼できるGitHubのサーバー」という**二重の信頼を悪用した点**です。普通の人から見ると「正規の場所から正規の作業をしているように見える」のに、実際は大規模な攻撃が行われているという、非常に巧妙な手口です。開発者の方はもちろん、ウェブサーバーを管理している方は早急な対応が必要です。
