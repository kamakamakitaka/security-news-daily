# 合成ID詐欺がマシンIDにも忍び寄っている

**元記事**: [How Synthetic Identity Fraud is Coming for Machine Identities](https://inl03.netline.com/ltr6/?_m=3n.009a.4037.sp0ao46r89.33c4)
**解説日**: 2025年7月

---

## 背景知識

この記事を理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### 🧑 「普通のID盗難」とは？
私たちが日常でよく聞く「個人情報の盗難」は、実在する人（あなたや私）の名前・住所・マイナンバーなどを盗んで、その人になりすますことです。たとえば、盗んだ情報でクレジットカードを作られたり、銀行口座を不正利用されたりします。

### 🤖 「マシンID（Non-Human Identity / NHI）」とは？
企業のITシステムでは、**人間だけでなくプログラムやサービス自体にも「ID（身分証）」が与えられています**。
- Webサーバーがデータベースにアクセスするための「サービスアカウント」
- アプリ同士が連携するための「APIキー」
- 自動処理プログラムが使う「資格情報」

これらを総称して「マシンID（非人間型ID）」と呼びます。大企業では、こういったマシンIDが**数万〜数十万個**存在することも珍しくありません。

### 🏢 「ドメインコントローラー」とは？
会社のパソコン環境では、「誰がどのファイルにアクセスできるか」を一元管理するサーバーがあります。それが**ドメインコントローラー**です。学校でいうと「先生が管理する出席簿・権限リスト」のようなものです。

## 何が起きたのか

### 📰 記事の概要

この記事は「**合成ID詐欺（Synthetic Identity Fraud）という手口が、マシンIDの世界でも起きつつある**」という警告を発しています。

> **合成ID詐欺とは？**
> 実在する人のIDを「盗む」のではなく、複数の本物の情報と偽の情報を組み合わせて「存在しない人物のIDを作り上げる」手口です。

たとえるなら……

> 🎭 「田中太郎さんの生年月日」＋「鈴木花子さんの住所」＋「架空の名前」を組み合わせて、
> 実在しない「山田一郎さん」を作り上げ、そのIDでローンを組んだり悪用したりする

本物のIDを盗むわけではないので、**被害者が気づきにくい**のが最大の特徴です。

### 💻 マシンIDでも同じことが起きている

攻撃者は既存のサービスアカウントを乗っ取るのではなく、**「最初から存在しているように見せかけた偽のマシンIDを作り出す」** ことができます。

たとえば…
- 会社のシステムに「`svc-backup-prod-01`」というアカウントが100個あるとします
- 攻撃者が「`svc-backup-prod-02`」という**偽のアカウント**を紛れ込ませます
- 管理者が数万件のリストをザッと確認しても、気づかずスルーしてしまいます

## 技術的な詳細

### 🔧 偽マシンIDを作る3つの手口

#### 1️⃣ 不正サービスアカウントの作成（Rogue Service Account）
> **一言で言うと**: 「もっともらしい偽の社員証を作って社内に紛れ込む」

攻撃者がシステムへの侵入に成功した後、既存のアカウントと**見た目がそっくりな新しいアカウント**を作成します。

- 命名規則（名前のルール）に合わせる
- 権限の種類も本物っぽく設定する
- 誰も盗まれた被害者がいないので、アラートが鳴らない

#### 2️⃣ DCShadow（ディーシーシャドウ）
> **一言で言うと**: 「偽の「校長室」を作って、そこから出る指示を全校に従わせる」

ドメインコントローラー（学校の出席簿・権限管理サーバー）になりすますという**高度な手口**です。

- 攻撃者は偽のドメインコントローラーを一時的に登録する
- 偽サーバーからの指示が「信頼できる本物のサーバーからの更新」に見える
- その偽サーバーが発行した変更内容は、システム全体に広がってしまう

⚠️ この手口には、すでに管理者レベルの権限を持っている必要があります。

#### 3️⃣ シャドウクレデンシャル（Shadow Credentials）
> **一言で言うと**: 「他人のロッカーに合鍵を密かに追加する」

既存の正規アカウントに、攻撃者が**こっそり自分だけが使える認証情報を追加**します。

- アカウント自体は本物のまま変わらない
- 攻撃者は「裏口の鍵」を手に入れた状態になる
- 見た目は正常なので最も発見しにくい

## なぜ重要なのか

### ⚠️ 問題の深刻さ

| 問題点 | 内容 |
|-------|------|
| 被害者がいない | 本物のIDを盗まれた人がいないので、気づく人がいない |
| 膨大な数 | 大企業では数万のマシンIDがあり、偽物が紛れやすい |
| 長期潜伏 | 検知されずに長時間、じわじわと権限や信頼を積み上げられる |
| 正常に見える | 命名規則・権限・場所すべてが「本物らしく」設定される |

### 🎯 狙われやすい状況

- **管理が追いついていない組織**（クラウド化・デジタル化が急速に進んでいる）
- **誰がどのマシンIDを管理しているか不明確**な環境
- **古いアカウントの棚卸しができていない**企業

現代の企業では、人間のIDよりもマシンIDの方が**圧倒的に数が多い**ため、この問題は年々深刻になっています。

## 対策・今後の展望

### 🛡️ できること・すべきこと

#### ✅ マシンIDの「棚卸し（インベントリ管理）」
> 「社内に存在するすべてのマシンIDを把握する」
- どのIDが、誰（どのチーム）が管理しているかを明確にする
- 定期的にリストを見直し、不審なIDがないか確認する

#### ✅ オーナーシップの明確化
> 「マシンIDにも必ず担当者を割り当てる」
- 各マシンIDに「人間の責任者」を決める
- 担当者がいないIDは即座に調査・削除する

#### ✅ 最小権限の原則（Least Privilege）
> 「マシンIDには必要最低限の権限だけ与える」
- 偽IDが作られても、権限が少なければ被害を最小限に抑えられる

#### ✅ 異常検知の強化
> 「新しいマシンIDが作られたら自動でアラートを出す」
- 誰がIDを作ったか、いつ作ったか、ログを記録する
- 承認プロセスなしに作られたIDを検知できる仕組みを整える

#### ✅ 将来の動向
- クラウド環境の普及でマシンIDの数はさらに増加が予想される
- AIを使った異常なID行動の検出技術が注目されつつある
- 「NHI（非人間型ID）ガバナンス」は2025年以降のセキュリティの重要課題になる見通し

## 用語解説

| 用語 | 意味 |
|------|------|
| **合成ID詐欺（Synthetic Identity Fraud）** | 実在しない偽の人物・アカウントを複数の情報から「作り上げる」詐欺手口 |
| **NHI（Non-Human Identity）** | プログラムやサービスが使う「マシンID」。人間ではなくシステムに割り当てられた身分証 |
| **サービスアカウント** | 特定のプログラムやサービスがシステムにアクセスするために使うID |
| **ドメインコントローラー** | 会社のIT環境でユーザーやコンピューターのアクセス権を一元管理するサーバー |
| **DCShadow** | 偽のドメインコントローラーを一時的に登録し、悪意ある変更を正規の通信に偽装する攻撃手法 |
| **シャドウクレデンシャル** | 既存の正規アカウントに、攻撃者だけが使える「裏口の認証情報」を密かに追加する手口 |
| **最小権限の原則** | ユーザーやシステムに必要最低限の権限だけ与えるセキュリティの基本方針 |
| **ガバナンス** | システムやIDを適切に管理・統制する仕組みのこと |
| **APIキー** | アプリ同士が安全に通信するための「合言葉（認証コード）」 |

> 💡 **まとめると...**
> 泥棒が「誰かの家の鍵を盗む」のではなく、「最初から自分のための合鍵を作って家に住み着く」ような攻撃が、企業のコンピューターシステムでも起きています。しかも相手が「機械のID」なので、普通の人が被害に気づくことすらできません。だからこそ、企業は「マシンIDも人間のIDと同じくらい厳重に管理する」必要があるのです。
