# 9年間見逃されていた！Linuxの深刻な脆弱性「RefluXFS」でroot権限が奪われる

**元記事**: [Nine-Year-Old RefluXFS Linux Flaw Gives Local Users Root on Default RHEL Installs](https://inl03.netline.com/ltr6/?_m=3n.009a.4037.sp0ao46r89.33cs)
**解説日**: 2026年7月23日

---

## 背景知識

このニュースを理解するために、いくつかの基本的な概念を押さえておきましょう。

### 🐧 Linuxとは？
Windowsと同じく「OS（オペレーティングシステム）」の一種です。サーバー（インターネット上のサービスを動かすコンピュータ）の世界では非常に多く使われており、皆さんが使うWebサービスの多くはLinux上で動いています。

### 👑 root（ルート）権限とは？
Linuxにおける「神様アカウント」のことです。コンピュータ上のすべてのファイルを読み書きしたり、どんな操作でも実行できる最高権限です。一般ユーザーはこの権限を持っていません。

### 📁 XFSファイルシステムとは？
ファイルシステムとは「データをディスクに保存・管理する仕組み」のことです。Windowsに「NTFS」という仕組みがあるように、Linuxには「XFS」「ext4」などの仕組みがあります。Red Hat系のLinuxではXFSがデフォルト（標準）でよく使われています。

### 🔒 権限（パーミッション）とは？
Linuxでは「このファイルは誰が読める？誰が書き換えられる？」という細かいルールを設定できます。たとえば「rootしか書き換えられない重要なファイル」などが存在します。

### 🏢 Red Hat Enterprise Linux（RHEL）とは？
企業向けの有名なLinuxです。銀行・病院・大企業のサーバーなど、重要なシステムに広く使われています。

---

## 何が起きたのか

2026年7月22日、「**RefluXFS**」という深刻なLinuxの脆弱性（セキュリティの欠陥）が公表されました。CVE番号は **CVE-2026-64600** です。

### 一言でいうと…
> 「一般ユーザー（root権限を持たない普通のユーザー）が、本来絶対に触れないはずのrootのファイルを書き換え、コンピュータの最高権限（root）を永続的に奪える」

という非常に危険な欠陥です。

### どれだけ古い問題？
このバグは **2017年のLinux 4.11** というバージョンから存在していたことが判明しました。なんと **9年間も気づかれずに潜んでいた** ことになります。

### 影響を受けるシステム
セキュリティ企業「Qualys（クォリス）」の調査によると、以下のような広く使われているLinuxのデフォルト（初期設定のまま）インストール環境が影響を受けます：

| 影響あり | 条件次第 |
|----------|----------|
| Red Hat Enterprise Linux 8/9/10 | Debian |
| CentOS Stream | Ubuntu |
| Rocky Linux / AlmaLinux | openSUSE |
| Amazon Linux 2023 | SLES |
| Fedora Server 31以降 | ※XFSをrootに使った場合のみ |

攻撃の実証テストでは、**デフォルトのRHEL 10.2環境でrootパスワードを消去することに成功**しており、しかも**10秒以内**に攻撃が成功することも確認されています。

## 技術的な詳細

少し難しいですが、できるだけわかりやすく説明します。

### 🗂️ reflinkとは？
XFSには「reflink（リフリンク）」という便利な機能があります。

📌 **例え話で説明：**
Googleドキュメントで「ファイルをコピー」するとき、実際にはデータを複製せず「同じデータを2つの名前で参照する」ことで、ディスク容量を節約できます。これがreflinkです。変更が加えられたときに初めて「本当のコピー」が作られます（これをCopy-on-Write＝COWと呼びます）。

### 🔑 攻撃の仕組み（ざっくり）

攻撃の流れを「鍵のかかった金庫を盗む」に例えて説明します：

```
① 攻撃者は「rootしか書けない重要ファイル（金庫）」のコピーを作る
   └─ 読み取り権限だけあればOK（FICLONEという操作を使う）

② コピーした時点では、コピーと本物は「同じ物理ディスクブロック（同じ場所）」を指している

③ 攻撃者は「コピーへの書き込み」と「内部のロック処理」を同時に競争させる
   └─ ロック（鍵）が一瞬外れる「すき間」を狙う

④ すき間の間に内部状態が変わるが、カーネル（OS中枢）は古い場所情報を使い続ける

⑤ 結果：攻撃者のデータが「本物のrootファイル」に書き込まれてしまう！
```

### ⚠️ なぜ検知されないのか？

この攻撃の恐ろしいところは：
- **ファイルのタイムスタンプ（更新日時）が変わらない**
- **権限設定が変わらない**
- **ログにも記録が残らない**
- **再起動しても効果が持続する**

まるで「証拠を残さずに金庫の中身を入れ替える泥棒」のようなものです。

### 🔬 技術的な詳細（もう少し踏み込んで）

問題の核心は「**チェックしてから使うまでの間にデータが変わってしまう**」という競合状態（Race Condition）です。

```
カーネルの処理：
1. 「このブロックは共有中か？」→ 確認する（正しい）
2. ロック（排他制御）を一時的に外す
3. [← ここで別のプロセスがブロックを移動！]
4. ロックを再取得する
5. 「さっき確認したブロックに書き込もう」← でも場所がもう変わってる！

結果: rootのファイルに書き込みが行われる
```

パッチ（修正版）では、ロックを外す前にシーケンス番号を記録し、再取得後に変化があればブロック情報を読み直すよう修正されています。

## なぜ重要なのか

### 📊 被害の深刻さ
この脆弱性は複数の点で非常に危険です：

1. **影響範囲が広い**：企業・クラウド・開発環境など世界中の多くのシステムに影響
2. **攻撃が速い**：10秒以内に成功することが実証済み
3. **痕跡が残らない**：攻撃されても気づきにくい
4. **永続的**：再起動しても攻撃者の変更が残る
5. **9年間放置**：長期間気づかれなかった根深い問題

### 🎯 特に危ないシーン
- 複数のユーザーが使う共有サーバー
- クラウド上のLinux仮想マシン
- CI/CD環境（ソフトウェアを自動でビルド・テストする環境）
- 信頼できないコードが実行される環境

## 対策・今後の展望

### ✅ 今すぐやること

**Step 1: 自分のシステムが影響を受けるか確認する**

ターミナル（コマンド入力画面）で以下を実行：
```bash
xfs_info / | grep reflink=
```
`reflink=1` と表示された場合は要注意です。

**Step 2: カーネルをアップデートする**

修正パッチは2026年7月16日にマージ（統合）済みです。各Linuxディストリビューションのアップデートを適用してください：

```bash
# Red Hat系の場合
sudo dnf update kernel

# 再起動
sudo reboot
```

**Step 3: 優先順位をつけてパッチ適用**

Qualysは以下の順で優先対応を推奨しています：
1. 外部から利用可能なサーバー
2. 複数ユーザーが使うマルチテナント環境
3. 信頼できないコードが動く環境

### 🔮 今後の動向
- 各Linuxベンダーはすでにバックポート（古いバージョンへの修正適用）を開始しています
- 企業向けサポートを受けているRHELユーザーはRed Hatからの公式パッチを待ちましょう
- 修正版カーネルへの更新が最善策です

## 過去記事との関連

今回の記事は、以前解説した記事とは直接のつながりはありませんが、共通したテーマがあります。

以前「**GitHubのActions Runnersを使ったcPanelサーバーへの攻撃**」を解説しましたが、あの攻撃でも「正規の仕組みを悪用してサーバーに侵入する」という手法が使われていました。今回の RefluXFS も「正規のLinux機能（reflink）を使って権限を奪う」という点で共通しています。

こうした「**本来正当な機能の隙をついた攻撃**」は、シグネチャベース（既知の攻撃パターンのリスト）の検知ツールでは見つけにくく、特に厄介です。ログにも痕跡が残らない今回の脆弱性は、その典型例といえるでしょう。

## 用語解説

| 用語 | 意味 |
|------|------|
| **脆弱性（ぜいじゃくせい）** | ソフトウェアのセキュリティ上の欠陥・弱点 |
| **CVE** | 脆弱性に付けられる世界共通の管理番号（CVE-年-番号） |
| **root権限** | Linuxの最高管理者権限。何でも操作できる |
| **XFS** | Linuxで使われるファイルシステム（データ管理の仕組み）の一種 |
| **reflink** | ファイルをコピーするとき、実際のデータをコピーせず参照先だけ増やす仕組み |
| **Copy-on-Write（COW）** | 書き込みが発生したときだけ実際にデータをコピーする仕組み |
| **Race Condition（競合状態）** | 複数の処理が「どちらが先に実行されるか」によってバグが起きる問題 |
| **カーネル** | OSの中核部分。ハードウェアとソフトウェアの橋渡しをする |
| **パッチ** | バグや脆弱性を修正するためのプログラムの更新 |
| **バックポート** | 新しいバージョンの修正を、古いバージョンに移植すること |
| **setuid** | 実行したユーザーではなく、ファイルの所有者の権限で動くプログラムの仕組み |
| **マルチテナント** | 複数のユーザー・組織が同じサーバーを共有する環境 |
| **CI/CD** | ソフトウェアのビルド・テスト・デプロイを自動化する仕組み |
| **/etc/passwd** | Linuxのユーザー情報を管理する重要なファイル |
| **Direct I/O** | OSのキャッシュを使わず、直接ディスクに読み書きする方式 |
