# 新しい「内部の脅威」には心拍がない：AIエージェントが動くとき、特権アクセスをどう守るか

**元記事**: [The New Insider Has No Pulse: Securing Privilege When the Actor Is an AI Agent](https://inl03.netline.com/ltr6/?_m=3n.009a.4037.sp0ao46r89.33cy)
**解説日**: 2026年7月23日

## 背景知識

このニュースを理解するために、まず「**アクセス権（特権）**」という考え方から説明します。

### 🏢 会社のビルで考えてみよう

会社のビルに入るとき、社員は「社員証（バッジ）」を持っています。この社員証には「どの部屋に入れるか」が記録されていて、総務の人は総務室に、エンジニアはサーバー室に入れる、という仕組みです。

コンピューターの世界も同じです。

- **ユーザーID・パスワード** ＝ 社員証
- **アクセス権（権限）** ＝ 「どの部屋（データやシステム）に入れるか」
- **特権アクセス** ＝ 「どこでも入れるマスターキー」のような強力な権限

### 🤖 AIエージェントって何？

最近登場した「**AIエージェント**」とは、人間が指示しなくても自分で考えて行動できるAIのことです。例えば：

- 「来週のミーティングを全部スケジュールして」と頼むと、カレンダーを開いて、メールを送って、会議室を予約して……と自動でやってくれる
- セキュリティの世界では「怪しい通信を見つけたら自動でブロックして」という動きもできる

### 🔑 NHI（非人間ID）って何？

**NHI（Non-Human Identity＝非人間アイデンティティ）**とは、「人間ではなく、プログラムやシステムに与えられたID」のことです。

例えば：
- 天気予報アプリが気象データサービスにアクセスするための「**APIキー**（アプリ同士が会話するための合言葉）」
- 毎晩自動でバックアップを取るスクリプト（小さなプログラム）が使うパスワード

- 🔴 **レッドエージェント**：攻撃者の視点で弱点を探すAI
- 🔵 **ブルーエージェント**：脅威を見つけて封じ込めるAI

この2種類のAIが人間の代わりに、高速でサイバー攻撃に対応するという壮大な計画です。

そして**この計画の土台として最重要視されたのが「アイデンティティ（誰が・何者であるか）」と「信頼」**でした。

## 技術的な詳細

### 🚪 「不正アクセス」の本当の怖さ

セキュリティの専門家がインシデント（セキュリティ事故）を調査するとき、最初に確認するのは「**どんなウイルスが使われたか**」ではなく、「**誰の権限（クレデンシャル）が使われて、何にアクセスできたか**」だそうです。

> ドアをこじ開けること（攻撃）より、建物内を歩き回れること（特権）の方が本当の危険

これがこの記事の核心です。

### 😰 AIエージェントの「特権管理」の難しさ

従来のセキュリティは「**人間**」を前提に作られていました：

| 従来の前提 | AIエージェントの実態 |
|-----------|-----------------|
| 人間がログインして使う | 自動で瞬時に起動・認証する |
| 二段階認証（MFA）で本人確認 | APIキーやトークン（電子的な合言葉）で認証 |
| 退職したら権限を削除 | プロジェクト終了後も放置されがち |
| パスワードを定期的に変更 | 鍵が何年も変わらないことがある |

### 🔓 AIが使う「鍵」の問題点

AIエージェントがシステムにアクセスするには「**クレデンシャル（認証情報）**」が必要です。具体的には：

- **APIキー**：「合言葉」のような文字列
- **OAuthトークン**：「一時的な通行証」のようなもの
- **証明書**：デジタルの「身分証明書」

**😱 これらの問題点：**
1. **有効期限が長い（または無期限）**：何年も同じ鍵を使い続ける
2. **権限が広すぎる**：「必要最小限」ではなく「なんでもできる」権限
3. **管理されていない**：誰も把握していないまま存在し続ける
4. **最悪の場合、コードに直接書かれている**：ソースコードの中に「パスワード」が丸見えで書いてある状態

## なぜ重要なのか

### 📊 数の問題：NHIはすでに人間IDより多い

ほとんどの企業環境では、すでに「**人間のID < AIやシステムのID**」という状態になっています。そしてその差はどんどん広がっています。

例えば大企業では：
- 社員：1万人 → 人間のID：1万個
- システム・ボット・AIエージェント → ID：数十万個

管理する人間のIDが増えれば気づきやすいですが、AIのIDは「静かに」増えていくので見落としがちです。

### 💥 もし攻撃者に悪用されたら？

AIエージェントが強力な権限を持ち、それが悪用されると：

1. **AIが自律的に動く** → 攻撃者が直接操作しなくても被害が拡大
2. **速度が人間とは桁違い** → 人間が気づく前に大量のデータが盗まれる
3. **「誰が指示したか」がわかりにくい** → 原因究明（フォレンジック）が難しい

## 対策・今後の展望

### ✅ 今すぐできる対策・考え方

**① 最小権限の原則（ゼロトラスト）**
「必要な権限だけを、必要な期間だけ」与える。AIエージェントも例外なし。

> 例：お使いを頼む子どもに「家の全部の鍵」ではなく「玄関の鍵だけ」渡す感覚

**② クレデンシャル（認証情報）の棚卸し**
「うちの会社にはどんなAPIキーやトークンが存在するか」を把握する。
知らないIDは管理できない。

**③ 有効期限の設定と自動ローテーション**
鍵を定期的に自動で交換する仕組みを作る。

**④ AIエージェントの「オフボーディング」**
プロジェクト終了 → AIのIDも削除。人間の退職手続きと同じように。

**⑤ 監視と異常検知**
AIエージェントの行動を常にログ（記録）として残し、「おかしな動き」があればすぐにアラートが出る仕組みを。

### 🔮 今後の展望

2026年現在、業界と政府が同時に動き出したことで、「AIエージェントのID管理」は今後のセキュリティの最重要テーマになることが確実です。

- **標準化**：AIのID管理に関する業界標準が整備される
- **ツールの登場**：AIエージェント専用の「特権アクセス管理（PAM）」ツールが増える
- **法規制**：各国でAIのアクセス権に関する規制が生まれる可能性

## 用語解説

| 用語 | 意味 |
|------|------|
| **クレデンシャル** | 認証情報。パスワード、APIキー、証明書など「本人証明」に使うもの全般 |
| **APIキー** | アプリ同士が通信するための「合言葉」となる文字列 |
| **OAuthトークン** | 「このアプリにこの範囲のアクセスを許可する」という電子的な通行証 |
| **NHI（Non-Human Identity）** | 人間ではなく、プログラムやシステムに割り当てられたID |
| **AIエージェント** | 自律的に考えて行動できるAI。人間の指示なしにタスクをこなせる |
| **特権アクセス** | システムの重要部分に触れる、強力な権限のこと |
| **最小権限の原則** | 必要な作業に必要な権限だけを与えるというセキュリティの基本原則 |
| **ゼロトラスト** | 「誰も最初から信頼しない」という現代のセキュリティの考え方 |
| **フォレンジック** | セキュリティ事故の原因や経緯を調査・分析すること |
| **CREST** | サイバーセキュリティ企業の国際的な認定・資格機関 |
| **NCSC** | 英国国家サイバーセキュリティセンター。英国政府のサイバー防衛機関 |
| **オフボーディング** | 退職・終了時に権限やアカウントを削除するプロセス |

---

> 💡 **一言まとめ**：AIエージェントは「心拍のない新しい社員」。人間と同じように（いやそれ以上に厳しく）IDと権限を管理しないと、気づかないうちに「マスターキーを持ったまま野放し」になる危険がある。業界も政府もその問題にようやく本腰を入れ始めた、という転換点のニュースです。
