# Bingの画像検索に重大な脆弱性！細工した画像ファイルでMicrosoftのサーバーを乗っ取れた

**元記事**: [Bing Images Flaws Let Crafted SVGs Run Commands as SYSTEM on Microsoft's Servers](https://inl03.netline.com/ltr6/?_m=3n.009a.4038.sp0ao46r89.33do)
**解説日**: 2025年7月24日

---

## 背景知識

このニュースを理解するために、いくつかの基本的な概念を押さえておきましょう。

### 🖼️ SVGファイルとは？
普通の画像（JPEGやPNGなど）は「点の集まり」で絵を表現します。でもSVGは違います。SVGは**XMLというテキスト形式で書かれた画像ファイル**で、中身はコードに近いものです。

```
<!-- SVGファイルの中身のイメージ -->
<svg>
  <circle cx="50" cy="50" r="40" fill="red"/>
  <!-- こんなふうにテキストで図形を定義する -->
</svg>
```

SVGはコードに近いので、「他の画像を読み込む参照」なども記述できます。これが今回の脆弱性の核心になります。

### 🔧 ImageMagickとは？
画像を変換・処理するための有名なソフトウェアです。「JPEGをPNGに変換して」「画像のサイズを変えて」といった処理をサーバー側で行うのに広く使われています。Microsoftのサーバーも画像処理にこれ（または互換ソフト）を使っていました。

### 🤝 「デリゲート（delegate）」とは？
ImageMagickは自分だけでは処理できない特殊なファイル形式を、**外部プログラムに「代わりにやってくれ」と頼む仕組み**を持っています。これを「デリゲート（委任）」と呼びます。

例えるなら：
> 「店長（ImageMagick）が得意じゃない料理を、外部のシェフ（外部プログラム）に作ってもらう」ようなイメージです。

このとき、外部プログラムへの指示を**シェル（OSのコマンド実行環境）**経由で渡すことがあります。そこが今回の弱点でした。

### 🔑 「NT AUTHORITY\SYSTEM」「root」とは？
コンピューターの操作権限の最高レベルです。
- **SYSTEM**：Windowsで「神様レベルの権限」。なんでもできる。
- **root**：Linuxで同じく「神様レベルの権限」。

これらの権限でコードを実行できるということは、**そのサーバー上でなんでも自由にできる**ということを意味します。

### 📊 CVSSスコアとは？
脆弱性の深刻度を0〜10点で表すスコアです。今回は**9.8点（最高が10点）**。超危険な部類です。

## 何が起きたのか

セキュリティ調査会社「XBOW」が、**Bingの画像検索に2つの重大な脆弱性**を発見しました。

### 事件のあらすじ

```
攻撃者（調査者）
    ↓ 細工したSVGファイルを送る
Bingの画像検索サーバー
    ↓ 画像として処理しようとする
ImageMagick互換の画像処理プログラム
    ↓ 「デリゲート」機能でOSに命令を渡してしまう
Windowsなら SYSTEM権限、Linuxなら root権限でコマンド実行！ 😱
```

調査者がサーバー上で実行したコマンドの結果として確認されたもの：
- **Linuxサーバー**：`uid=0, gid=0`（rootであることを示す）
- **Windowsサーバー**：`whoami /all` の結果が `NT AUTHORITY\SYSTEM`、Windows Server 2022 Datacenterと判明

### 発見された2つの攻撃経路（CVE）

| CVE番号 | 攻撃方法 | 認証 |
|---|---|---|
| CVE-2026-32194 | 「画像で検索」機能に直接SVGをアップロード | 不要 |
| CVE-2026-32191 | 画像のURLをBingに渡してBingに取りに行かせる | 不要 |

どちらも**ログイン不要、特別な操作不要**で攻撃できる点が特に危険です。

### タイムライン

```
2026年3月19日  → Microsoftが修正完了＋CVE公開（すでにサーバー側で対処済み）
2025年7月23日  → XBOWが攻撃の詳細な仕組みを公開
2025年7月24日  → The Hacker Newsが記事を掲載
```

> ⚠️ CVEの番号が「2026年」になっているのは珍しいですが、記事の記載通りに表記しています。

## 技術的な詳細

### ステップ1：最初の手がかり「エラーメッセージ」

調査者がBingの「画像で検索」機能を調べていると、一部のサーバーが**500エラー（サーバーエラー）を返しながらも、URLを取りに行っていた**ことに気づきました。

これはどういうことか？「エラーは出るけど、裏では処理が続いている」ということ。これは怪しい！

### ステップ2：SVGの「参照」機能を悪用

SVGファイルは他の画像を参照（読み込み）することができます：

```xml
<svg>
  <!-- 他の画像を参照できる -->
  <image href="ここに何かを指定できる" />
</svg>
```

この`href`（参照先）に特殊な値を入れたらどうなるか？

### ステップ3：パイプ文字でシェルに命令を渡す

ImageMagickには `|コマンド` という書き方をすると、**ファイル名ではなくシェルコマンドとして実行する**という機能（デリゲート）があります。

```
# これはファイルを読む
/path/to/image.png

# 先頭に | をつけると...
|ls -la   ← これはシェルコマンドとして実行されてしまう！
```

Bingのサーバーではこのデリゲート機能が**有効なままになっていた**ため、SVGの中に書かれた参照先が `|whoami` のようなコマンドとして実行されてしまいました。

### ステップ4：結果を外部に送り出す

攻撃者（調査者）はこのようなペイロード（攻撃コード）を使いました：

```
一見普通の1ピクセルのSVG
  └─ 中に参照が仕込まれている
       └─ |コマンドを実行して結果をXBOWのサーバーに送信
```

`curl`（インターネットにデータを送るコマンド）を使って、コマンドの実行結果を自分たちのサーバーに送信させることで、**サーバーが完全に乗っ取れる状態**であることを証明しました。

### なぜBingが自分でURLを取りに行くのか？

Bingの「画像のURLで検索」機能は、**Bingのサーバーが指定されたURLの画像を取りに行く**という仕組みです。これを「SSRF（Server-Side Request Forgery：サーバーを踏み台にしてリクエストを送らせる攻撃）」の悪用と組み合わせることで、外部URLに仕込んだSVGを読み込ませることができました。

## なぜ重要なのか

### 影響の大きさ

```
深刻度: ★★★★★ (CVSSスコア 9.8/10)

影響したシステム:
  ✅ Bingの画像処理サーバー（Windows・Linux両方）
  ✅ 最高権限（SYSTEM/root）でのコマンド実行が可能
  ✅ 認証不要・ログイン不要
```

### 一般ユーザーへの影響は？

**現時点では、一般ユーザーが何かをする必要はありません。**

Microsoftがすでにサーバー側で修正を完了しています。スマホやPCにパッチを当てる必要もありません。

ただし、これが悪意のある第三者に発見されていたら：
- Bingの画像処理サーバーを完全制御
- 他のMicrosoft内部システムへの侵入の足がかり
- ユーザーデータへのアクセス

などが起きていた可能性があります（調査者は「読み取り専用のコマンドしか実行せず、顧客データには触れなかった」と説明しています）。

### 同じ問題が他にもある可能性

この脆弱性が怖いのは、**ImageMagickを使っている多くのサービスに同じリスクがある**という点です。画像のアップロードを受け付けるウェブサービスは無数にあります。

## 対策・今後の展望

### Bingユーザーがすること

**✅ 何もしなくてOK** です。Microsoftがすでにサーバー側で修正済みです。

### ウェブサービスの開発者・管理者向けの対策

記事では以下の3つの対策が示されています：

```
対策1: デリゲートを無効化する
→ ImageMagickで外部プログラムへの委任機能をオフにする

対策2: 受け付けるファイル形式を絞る
→ SVGなど危険な形式を受け付けないようにする

対策3: 画像処理サーバーをネットワークから隔離する
→ 万が一コマンドが実行されても、外部に結果を送れなくする
```

ImageMagickには `policy.xml` という設定ファイルがあり、危険な機能を制限できます：

```xml
<!-- policy.xmlの例 -->
<policy domain="delegate" rights="none" pattern="*" />
<!-- デリゲートを全て無効にする -->
```

### XBOWの「AI自動攻撃」について

今回脆弱性を発見したXBOWは**自律型の攻撃的セキュリティスタートアップ**です。つまり、AIを活用した自動化ツールでこの脆弱性を発見しました。今後、このようなAIによる自動脆弱性発見がセキュリティ業界でさらに普及していくと考えられます。

今回の記事は、以前解説したImageMagickやSSRF（サーバーを踏み台にした攻撃）に関するテーマと深く関連しています。画像処理ソフトウェアの脆弱性は**2016年のImageTragick**（ImageMagickの有名な脆弱性）から繰り返し問題になっており、今回もその系譜に連なる事例と言えます。「信頼できないデータを安全に処理する難しさ」は、セキュリティの永遠のテーマです。

## 用語解説

| 用語 | 意味 |
|------|------|
| **SVG** | テキスト（XML）で書かれた画像ファイル形式。コードに近い性質を持つ |
| **ImageMagick** | 画像変換・処理を行う有名なオープンソースソフトウェア |
| **デリゲート（delegate）** | ImageMagickが苦手な処理を外部プログラムに委任する仕組み |
| **シェル** | OSに命令（コマンド）を打ち込む環境。ターミナルや黒い画面とも呼ばれる |
| **コマンドインジェクション** | 本来コマンドを受け付けない場所に不正なコマンドを注入する攻撃 |
| **SSRF** | サーバーを踏み台にして、サーバー自身に不正なリクエストを送らせる攻撃 |
| **NT AUTHORITY\SYSTEM** | Windowsで最高レベルの管理者権限 |
| **root / uid=0** | Linuxで最高レベルの管理者権限 |
| **CVE** | 脆弱性に付けられる世界共通の識別番号（例：CVE-2026-32194） |
| **CVSSスコア** | 脆弱性の深刻度を0〜10で表すスコア。9.8は超危険 |
| **CWE-77/78** | コマンドインジェクション系の脆弱性を分類する番号 |
| **500エラー** | サーバー内部でエラーが発生したことを示すHTTPステータスコード |
| **curl** | コマンドラインでURLにアクセスしたりデータを送ったりするツール |
| **ペイロード** | 攻撃に使われる悪意のあるコードやデータのこと |
| **base64** | バイナリデータをテキストに変換するエンコード方式 |

> 💡 **まとめ**
> Bingの画像検索に「細工したSVGを送ると、Microsoftのサーバー上で神様レベルの権限でコマンドが実行できる」という超危険な脆弱性が見つかりました。しかしMicrosoftはすでにサーバー側で修正済みで、一般ユーザーの対応は不要です。画像処理という「普通の機能」が、設定ミス一つで重大な侵入口になり得るという、セキュリティの難しさを改めて示した事例です。
