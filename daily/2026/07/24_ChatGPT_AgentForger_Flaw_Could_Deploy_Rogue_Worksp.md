# ChatGPTの「エージェント偽造」脆弱性：フィッシングリンク1つで会社のAIを乗っ取れた！

**元記事**: [ChatGPT AgentForger Flaw Could Deploy Rogue Workspace Agents via a Phishing Link](https://inl03.netline.com/ltr6/?_m=3n.009a.4038.sp0ao46r89.33di)
**解説日**: 2025年6月

---

## 背景知識

まず、この記事を理解するためのポイントをいくつか押さえましょう。

### 🤖 ChatGPT「ワークスペースエージェント」って何？
ChatGPTには、個人で使うだけでなく、**会社の業務に組み込んで自動的に仕事をしてくれる「AIエージェント」**を作る機能があります。たとえば、

- メールを自動で読んで返信する
- Googleカレンダーの予定を整理する
- SlackやTeamsに自動投稿する

…といったことを、人間の代わりにAIが勝手にやってくれる仕組みです。

### 🔗 コネクタ（Connector）って何？
AIエージェントが「OutlookのメールをGoogleカレンダーと連携させる」ような作業をするために、**外部サービスと接続するための橋渡し役**がコネクタです。一度接続しておけば、AIが自動的にそのサービスを操作できるようになります。

### 🎣 フィッシング（Phishing）って何？
**本物そっくりの偽メールやリンクで、ユーザーを騙す攻撃手法**です。「釣り（fishing）」から来ており、ユーザーを"釣り上げる"イメージです。今回の場合、一見普通に見えるChatGPTのURLが罠になっていました。

### 🔄 CSRF（クロスサイトリクエストフォージェリ）って何？
少し難しい言葉ですが、簡単に言うと「**被害者のログイン済み状態を悪用して、勝手に操作させる攻撃**」です。  
例えるなら、「銀行にログイン中のAさんに、攻撃者が仕掛けたリンクをこっそりクリックさせて、Aさんの口座からお金を勝手に送金させる」ようなイメージです。

## 何が起きたのか

セキュリティ研究会社「Zenity Labs」が、**ChatGPTのエージェント作成機能（Agent Builder）に深刻な脆弱性（セキュリティ上の欠陥）**を発見しました。

この脆弱性は **「AgentForger（エージェント偽造者）」** と名付けられ、以下のことが可能でした：

> 😱 **会社員が何も知らずにリンクを1回クリックするだけで、攻撃者がその社員になりすますAIエージェントが会社内に自動で作られてしまう！**

この問題はOpenAIに報告され、**2026年6月8日に修正済み**です。

## 技術的な詳細

### 📋 攻撃の流れをステップで見てみよう

```
【攻撃者の準備】
↓
悪意のある命令を仕込んだChatGPTのURLを作成
（例: chatgpt.com/agents/studio/new?template_name=○○&initial_assistant_prompt=【悪の命令】）

↓
【被害者へ送付】
フィッシングメール等でそのURLを社員に送る
「参考資料です！」「確認してください！」など

↓
【被害者がクリック】
普通のChatGPTのリンクに見えるのでクリック

↓
【自動で以下が実行される（被害者は何もしていない）】
①  社員の認証情報でAgent Builderが開く
②  URLに埋め込まれた悪の命令が自動実行される
③  「チーフ・オブ・スタッフ」テンプレートで新しいAIエージェントが作成される
④  既存のコネクタ（Outlook, Gmail, Slackなど）が全部エージェントに接続される
⑤  「承認不要」設定にされる（使うたびに確認が出なくなる）
⑥  1時間ごとに自動実行されるスケジュールが設定される
⑦  即座に動き始める（プレビューモードで即起動）

↓
【その後ずっと】
攻撃者がメールに「TASK: ○○を調べろ」と書いて送ると
→ AIエージェントが自動で実行して結果を攻撃者に返信！
```

### 🔍 なぜこんな事が起きたの？

Agent BuilderはURLの中に設定情報を入れることができる仕組みになっていました。

```
通常の想定：
https://chatgpt.com/agents/studio/new?template_name=テンプレート名
↑ 「このテンプレートで始めてね」という便利な機能

悪用された場合：
https://chatgpt.com/agents/studio/new?template_name=chief-of-staff
  &initial_assistant_prompt=【ここに悪意のある命令が入る】
↑ URLにこっそり命令を入れられる！
```

しかも、このURLパラメータに入った命令は、**ページが読み込まれると自動的に実行されてしまった**のです。本来ならユーザーが「実行」ボタンを押すまで何もしないはずなのに……。

## なぜ重要なのか

### 😰 被害の深刻さを考えてみよう

| 項目 | 内容 |
|------|------|
| **必要な攻撃難易度** | 低い（リンクを送るだけ） |
| **被害者が気づくか** | ほぼ気づかない |
| **アクセスできる情報** | メール・カレンダー・ドライブ・チャット全部 |
| **持続期間** | 1時間ごとに永続的に動き続ける |
| **特別な技術は必要か** | 不要（URLを作るだけ） |

### 🏢 会社への影響
- 社員のメールをすべて読まれる
- 機密ファイルを盗まれる
- 社員になりすましてメッセージを送られる
- 攻撃者がいつでも会社内の情報にアクセスできる状態が続く

まるで、**会社の中に攻撃者のスパイロボットを設置されるようなもの**です。しかも設置したのは社員本人（騙されただけですが）。

## 対策・今後の展望

### ✅ OpenAIの対応
2026年6月8日にこの脆弱性は**修正済み**です。また、Agent Builder自体も2026年11月30日に廃止予定で、より安全な「Agents SDK」への移行が推奨されています。

### 🛡️ 私たちができる対策

1. **リンクは慎重にクリックする**  
   「普通のChatGPTのリンクだから安全」とは思わないこと。URLが長かったり、`?`以降に見慣れない文字列があったりしたら要注意！

2. **不要なコネクタは接続しない**  
   この攻撃は「すでにコネクタが接続されている」ことが条件でした。使っていない連携サービスは削除しておきましょう。

3. **AIエージェントの設定を定期的に確認する**  
   自分が作った覚えのないエージェントが動いていないかチェックする習慣を。

4. **セキュリティ意識の教育**  
   会社全体でフィッシングリンクへの注意を共有することが重要です。

## 用語解説

| 用語 | 意味 |
|------|------|
| **脆弱性（ぜいじゃくせい）** | ソフトウェアのセキュリティ上の欠陥・弱点のこと |
| **AIエージェント** | 人間の代わりに自律的に作業を行うAIプログラム |
| **フィッシング** | 本物そっくりの偽リンクや偽メールでユーザーを騙す攻撃 |
| **CSRF** | ログイン済みユーザーを騙して勝手に操作させる攻撃手法 |
| **コネクタ** | AIと外部サービス（GmailやSlackなど）をつなぐ接続機能 |
| **URLパラメータ** | URLの「?」以降に付け加えられる追加情報（設定値など） |
| **責任ある開示（Responsible Disclosure）** | 脆弱性を発見したとき、悪用される前に開発者に非公開で報告するルール |
| **AgentForger** | 今回の脆弱性につけられたコード名。「エージェントを偽造するもの」の意味 |
| **プレビューモード** | 本番公開前にエージェントをテストするための機能（今回は悪用された） |
| **永続化（ persistence）** | 攻撃者がシステムに長期間居座り続けられる状態にすること |
