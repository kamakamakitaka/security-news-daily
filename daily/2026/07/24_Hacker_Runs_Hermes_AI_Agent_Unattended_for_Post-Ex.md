# ハッカーがAIアシスタントを「自動操縦」でタイ財務省に侵入させた事件

**元記事**: [Hacker Runs Hermes AI Agent Unattended for Post-Exploitation at Thai Finance Ministry](https://inl03.netline.com/ltr6/?_m=3n.009a.4038.sp0ao46r89.33e6)
**解説日**: 2026年7月24日

---

## 背景知識

このニュースを理解するために、まず3つのポイントを押さえておきましょう。

### 🤖 AIエージェントとは？
最近流行りの「ChatGPT」のようなAIに、**自分でパソコンを操作する力**を持たせたものです。「このメールを送って」「このフォルダを調べて」と命令すると、AIが自動でやってくれます。今回使われた「**Hermes（ヘルメス）**」は、メール管理やちょっとした作業を自動でやってくれる、無料で公開されているAIアシスタントです。

### 🏛️ タイ財務省とは？
タイ（東南アジアの国）の国家財務を管理する政府機関で、税金の徴収や国の予算管理を担当しています。日本でいう「財務省＋国税庁」のようなところです。当然、国民の個人情報や財務データが大量に保存されています。

### 🔓 「侵入後の工作」とは？
ハッカーは最初の侵入だけでなく、**侵入後にできるだけ広くネットワークを調べ回り、より強い権限を手に入れようとする**作業も行います。この「侵入後の探索」のことを「Post-Exploitation（ポスト・エクスプロイテーション）」と呼びます。今回はその作業をAIに丸投げしたのが特徴です。

---

## 何が起きたのか

事件の流れをわかりやすく順番に説明します。

```
① ハッカーが何らかの方法でタイ財務省のネットワークに侵入
        ↓
② 省内のWebサーバーに「ウェブシェル（裏口）」を仕掛ける
        ↓
③ 別に借りたサーバーにHermes AIをインストール
        ↓
④ 「YOLOモード」をONにして、財務省のネットワークに向ける
        ↓
⑤ AIが自動で省内を探索・調査（人間は見ていない）
        ↓
⑥ AIのログが誤って外部から丸見えの状態に
        ↓
⑦ セキュリティ企業Hunt.ioと研究者が発見・報告（7月15日）
```

ひとことでいうと、**「AIを番犬ならぬ番泥棒として自動で働かせた」**事件です。

## 技術的な詳細

### 🔑 「YOLOモード」って何？

「YOLO」とは英語の「**You Only Live Once（人生は一度きり）**」の略で、ネットスラングでは「考えずにやっちゃえ！」という意味でも使われます。

Hermes AIには、危険な操作をしようとしたとき「本当にやりますか？」と人間に確認する機能が標準でついています。YOLOモードはその**確認を全部スキップ**して、AIが何でも勝手にやり続けるモードです。

```
通常モード: AIが操作を提案 → 人間が「OK」を押す → 実行
YOLOモード: AIが操作を提案 → 自動で即実行 ← ここが今回問題
```

公式ドキュメントには「**信頼できる、隔離された環境でのみ使うこと**」と書いてありますが、ハッカーはこれを攻撃に使いました。

### 🛠️ AIは省内で何をやったか

回収されたログには5つの行動記録が残っていました：

| 行動 | 内容 | たとえると |
|------|------|-----------|
| LinPEAS実行 | Linuxで「管理者権限を盗める穴」を自動で探すツール | 建物内の鍵のかかっていないドアを全部チェック |
| 権限ファイルの検索 | 特別な権限を持つファイルを探す | 合鍵が置いてある場所を探す |
| ファイルシステム調査 | フォルダ構造を丸ごと調べる | 建物の見取り図を作る |
| ウェブルートのクロール | Webサーバーのフォルダを全部読む | 受付の引き出しを全部開けて確認する |
| 人事記録フォルダの探索 | **2012年以降の職員の人事情報フォルダ**を発見・閲覧 | 社員名簿を全部見つけ出す |

### 💻 狙われた脆弱性

ハッカーが使ったツールには、2026年に発見された**新しいLinuxの脆弱性**（セキュリティの穴）4つが含まれていました：

- **CVE-2026-31431**（Copy Fail）
- **CVE-2026-43284 / CVE-2026-43500**（Dirty Frag）
- **CVE-2026-43503**（DirtyClone）

これらは「一般ユーザー権限から管理者（root）権限を奪える」タイプの脆弱性です。家のたとえでいうと、「普通の鍵で入った後、金庫の鍵も奪える」ようなものです。

### 📦 Hadoopの設定ミスも悪用

「**Hadoop（ハドゥープ）**」とは、大量のデータを管理するシステムです。デフォルト（初期設定のまま）だと**パスワードなしで誰でもログインできる**状態になっているため、これも狙われました。

> 🏠 たとえ話：新築マンションの宅配ボックスが「初期暗証番号のまま」で、誰でも開けられる状態にしていたようなものです。

## なぜ重要なのか

### 📌 ポイント1：AIが「人間の確認なし」で攻撃した初めての実例

これまでも「AIを使ったサイバー攻撃」は報告されていましたが、それらは**AIをだまして協力させる**必要がありました（AIの会社がおかしい動きに気づいてアカウントを止めることもできた）。

今回は違います。

```
従来の攻撃: AIサービス企業のサーバー上で動く → 監視される → アカウント停止の可能性あり
今回の攻撃: 自分のサーバーで動く → 誰も監視しない → 止められない
```

**AIが「完全に人間の管理なし」でサイバー攻撃の実働部隊になった事例**として、セキュリティ業界に衝撃を与えています。

### 📌 ポイント2：人間の作業を分担した

ハッカーとAIの役割分担が明確でした：

- **人間がやったこと**：最初の侵入、ターゲットの選定、カスタムパスワードリストの作成、内部パスの把握
- **AIがやったこと**：同じ作業を何度も繰り返す退屈なスキャン・探索作業

「頭脳（作戦）は人間、手足（実行）はAI」という構図です。これにより、ハッカーは**寝ている間でも攻撃が続く**状況を作れます。

### 📌 ポイント3：政府の個人情報が危険にさらされた

2012年以降の財務省職員の人事記録フォルダがAIに閲覧されています。今回のログには「ファイルが外部に送られた証拠」はありませんでしたが、**見られた事実は消えません**。

## 対策・今後の展望

### 🛡️ 組織・企業ができる対策

| 対策 | 内容 |
|------|------|
| **デフォルト設定を変える** | Hadoopなどパスワードなしのシステムはすぐにパスワードをかける |
| **AIエージェントの権限を制限する** | YOLOモードのような「確認なし自動実行」を業務で使わない |
| **ログの公開設定を確認する** | 今回は攻撃者自身のログが丸見えだった。自社のログも外から見えないか確認 |
| **Linuxの脆弱性にパッチを当てる** | 発見された4つのCVEに対応したアップデートをすぐ適用する |
| **ネットワーク内部の通信も監視する** | 侵入後の動きも検知できるように、内部通信もチェックする |

### 🔮 今後の動向

今回の事件は「**AIによる自動攻撃の時代の幕開け**」とも言えます。今後は：

- ハッカーが夜中寝ている間でもAIが攻撃を続ける
- AIを使うことで、初心者でも高度な攻撃ができてしまう可能性
- セキュリティ側もAIで自動防御する「AI vs AI」の戦いが加速する

タイのCERT（コンピュータ緊急対応チーム）には7月15日に通知済みですが、記事執筆時点（7月24日）ではまだ公式発表はありませんでした。

## 過去記事との関連

以前「**AIエージェントは『見えている』だけじゃダメ！セキュリティチームは『何をさせるか』を管理しなければならない**」という記事を解説しましたが、今回の事件はまさにその警告が現実になったケースです。

「AIエージェントが何をしているか見える」だけでは不十分で、「何をさせるか・させないかのルール（権限管理）」がなければ、今回のように攻撃ツールとして使われてしまいます。

また、「**ChatGPTのエージェント偽造脆弱性**」の記事でも触れたように、AIエージェントを取り巻くセキュリティリスクは急速に広がっています。AIが便利になればなるほど、悪用リスクも同時に高まるという流れが続いています。

## 用語解説

| 用語 | 説明 |
|------|------|
| **AIエージェント** | 人間の代わりにパソコンを自動操作できるAI |
| **Hermes（ヘルメス）** | 無料公開のAIアシスタント。メール管理などを自動化できる |
| **YOLOモード** | 危険な操作でも人間に確認せず自動実行するHermesの設定 |
| **Post-Exploitation** | サイバー攻撃で最初の侵入後に行う「内部探索・権限拡大」作業 |
| **ウェブシェル** | サーバーに仕掛ける「裏口」プログラム。遠隔でコマンドを実行できる |
| **LinPEAS** | Linuxで管理者権限を奪える穴を自動で探す定番ツール |
| **root権限** | Linuxで最強の管理者権限。何でもできてしまう |
| **Hadoop** | 大量データを管理するシステム。初期設定だと認証が不要な場合がある |
| **CVE** | 脆弱性に付けられる固有の識別番号（例：CVE-2026-31431） |
| **CERT** | コンピュータ緊急対応チーム。サイバー攻撃への対応を担う組織 |
| **ディレクトリリスティング** | Webサーバーのフォルダ内のファイル一覧が外から丸見えになる設定ミス |
| **Hunt.io** | 今回の攻撃ログを発見したセキュリティ調査会社 |

---

> 💬 **まとめ**：今回の事件は「AIが便利になった裏側のリスク」を象徴しています。AIは使い方次第で強力な攻撃ツールにもなります。セキュリティは「AIを導入したから安全」ではなく、「AIに何をさせるかを人間がきちんと管理する」ことがますます重要になっています。
