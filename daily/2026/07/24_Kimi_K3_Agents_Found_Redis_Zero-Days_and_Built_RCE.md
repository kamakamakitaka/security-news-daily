# Kimi K3 AIエージェントがRedisのゼロデイ脆弱性を発見し、攻撃コードまで作成した

**元記事**: [Kimi K3 Agents Found Redis Zero-Days and Built RCE Exploit, Researchers Say](https://inl03.netline.com/ltr6/?_m=3n.009a.4038.sp0ao46r89.33ei)
**解説日**: 2026年7月25日

---

## 背景知識

まず、このニュースを理解するためにいくつかの基本的な概念を押さえましょう。

### Redisって何？
**Redis（レディス）** とは、世界中のウェブサービスが使っている「超高速なデータ一時保存システム」です。  
たとえば、SNSでログインした情報を一時的に覚えておいたり、ショッピングサイトのカートの中身を記憶したりするのに使われています。TwitterやGitHubなど多くの有名サービスが使っている、非常にポピュラーなソフトウェアです。

### ゼロデイ脆弱性って何？
**ゼロデイ脆弱性（Zero-day vulnerability）** とは、ソフトウェアの開発者がまだ気づいていない、または修正パッチを出す前に発見されたセキュリティの穴のことです。  
「ゼロデイ」とは「対策がゼロ日しかない」という意味で、攻撃者に悪用されるリスクが非常に高い状態です。

### RCE（リモートコード実行）って何？
**RCE（Remote Code Execution）** とは、ネットワーク越しに他人のコンピューターで好き勝手なプログラムを実行できてしまう攻撃手法です。  
鍵のかかった金庫室に、外から電話一本でドアを開けさせるようなイメージです。最も危険な脆弱性の一種です。

### PoC（概念実証コード）って何？
**PoC（Proof of Concept）** とは、「この脆弱性は本当に悪用できますよ」と証明するために作られたデモ用の攻撃コードです。セキュリティ研究者が問題の深刻さを示すために公開することがありますが、悪用される危険もあります。

### AIエージェントって何？
**AIエージェント** とは、人間が指示しなくても自律的に考えて行動するAIシステムのことです。今回登場する「Kimi K3」は中国の企業が開発したAIです。

---

## 何が起きたのか

2026年7月23日、Redisは**7つのセキュリティアップデート**を一気にリリースしました。これは、セキュリティ研究者たちが**AIエージェント「Kimi K3」を使って**、Redisの複数バージョンに存在する深刻な脆弱性を発見し、さらに実際に攻撃できることを証明するコード（PoC）まで作り上げたためです。

影響を受けたRedisのバージョンは以下の通りです：
- Redis 6.2.22
- Redis 7.4.9
- Redis 8.6.4
- Redis 8.8.0

しかも驚くべきことに、**Redis 6.2.22と7.4.9はつい2ヶ月前（5月）にRedisが「安全な更新版」として配布したばかりのバージョン**でした。ユーザーが言われた通りにアップデートしたのに、実はそのバージョン自体に穴が空いていたという皮肉な状況です。

## 技術的な詳細

今回発見された攻撃経路（脆弱性の悪用方法）は主に2つあります。

### 🔴 攻撃経路①：Streamsの「共有NACKバグ」

これは少し複雑なので、**図書館の本の貸し出し管理**で例えてみます。

> 図書館のシステムで、同じ本を誤って2人に「貸し出し中」として登録してしまいました。  
> 1人目が本を返却するとシステムから記録が消えます（メモリ解放）。  
> でも2人目の記録はまだ残っていて、「返却済みの本」の記録を指し続けています（ダングリングポインタ）。  
> 2人目も返却しようとすると、すでに消えた記録をもう一度消そうとして、システムがクラッシュ・誤動作します（ダブルフリー）。

これが **「use-after-free（解放済みメモリへのアクセス）」** や **「double-free（二重解放）」** と呼ばれるメモリ管理のバグです。攻撃者はこの混乱状態を利用して、Redisが持つメモリ全体を自由に読み書きし、最終的にシステムコマンドを実行してしまいます。

### 🔴 攻撃経路②：RedisBloomの「TDigest境界外書き込みバグ」

こちらも例えで説明します。

> 引っ越しの際、「段ボール箱のサイズ」と「積める荷物の量」を別々のメモに書いたとします。  
> もし誰かが「積める荷物の量」のメモだけ偽造して「1000個入る」と書き換えたら…  
> 実際には10個しか入らない箱に1000個詰め込もうとして、隣の荷物まで壊れてしまいます。

これが **「Out-of-bounds Write（境界外書き込み）」** です。Redisが信頼してはいけない数値（攻撃者が操作できる値）を信頼してしまったため、本来書き込んではいけないメモリ領域にデータを書き込んでしまいます。これも最終的にはシステムコマンドの実行に利用されます。

### 💡 AIがやったこと
今回特に注目すべきは、これらの脆弱性を**AIエージェント「Kimi K3」が自律的に発見し、攻撃コードまで組み立てた**という点です。人間の研究者が何週間もかけてやるような作業を、AIが自動でこなしてしまいました。

## なぜ重要なのか

### 1. Redisは世界中で使われている
Redisはウェブサービスの「縁の下の力持ち」として非常に広く普及しています。影響を受けるシステムの数は膨大です。

### 2. 「安全だと思ってアップデートしたら穴があった」問題
5月に配布された「修正版」が実は不完全だったという事実は、ユーザーの信頼を揺るがします。

### 3. AIが攻撃の「武器製造」までできてしまう時代
これが最も重大なポイントかもしれません。従来、高度なセキュリティの脆弱性発見と攻撃コード開発は、豊富な知識を持つ専門家にしかできませんでした。しかし今回、**AIがそれを自動でやってのけた**という事実は、サイバーセキュリティの世界に大きな衝撃を与えています。

### 4. 現時点では実際の被害なし（7月24日時点）
幸いなことに、7月24日時点では実際に悪用された事例は報告されていません。しかし、PoC（攻撃デモコード）が公開されているため、時間の問題とも言えます。

## 対策・今後の展望

### ✅ すぐにやるべきこと（Redisを使っている事業者向け）

| 現在のバージョン | アップデート先 |
|---|---|
| Redis 6.2.x系 | Redis 6.2.23 |
| Redis 7.2.x系 | Redis 7.2.15 |
| Redis 7.4.x系 | Redis 7.4.10 |
| Redis 8.2.x系 | Redis 8.2.8 |
| Redis 8.4.x系 | Redis 8.4.5 |
| Redis 8.6.x系 | Redis 8.6.5 |
| Redis 8.8.x系 | Redis 8.8.1 |

### ✅ アップデートができない場合の応急処置
- **RESTORE コマンドの権限を制限する**：今回の攻撃経路は両方とも「RESTORE」というコマンドを必要とします。必要のないアカウントからこの権限を剥奪することで、リスクを大幅に下げられます。
- **外部ネットワークからのアクセスを遮断する**：信頼できないネットワークからRedisに直接アクセスできないようにする。

### 🔮 今後の展望
- **AIによる脆弱性発見は今後も加速する**：今回はKimi K3でしたが、同様のAIが攻撃者の手に渡れば、脆弱性発見のスピードが劇的に上がります。防御側も同様にAIを活用しなければ追いつけなくなります。
- **CVE（脆弱性番号）の整備**：今回はRedisの7月分の修正に対して正式なCVE番号やCVSSスコア（危険度の数値）が付与されていない状態が続いており、管理体制の整備が急務です。

## 用語解説

| 用語 | 読み方 | 意味 |
|---|---|---|
| **Redis** | レディス | 世界中のウェブサービスが使う高速データ保存システム |
| **ゼロデイ脆弱性** | ぜろでいぜいじゃくせい | 開発者がまだ修正していない未知のセキュリティの穴 |
| **RCE** | アールシーイー | Remote Code Execution。遠隔からコードを実行できる最も危険な攻撃の一種 |
| **PoC** | ピーオーシー | Proof of Concept。脆弱性が本当に使えることを証明するデモ攻撃コード |
| **Use-after-free** | ユーズアフターフリー | 一度解放したメモリ領域にアクセスしてしまうバグ |
| **Double-free** | ダブルフリー | 同じメモリ領域を2回解放しようとするバグ |
| **Out-of-bounds Write** | アウトオブバウンズライト | 確保したメモリの範囲を超えてデータを書き込んでしまうバグ |

| **CVE** | シーブイイー | 脆弱性に付けられる世界共通の識別番号（例：CVE-2026-XXXX） |
| **CVSS** | シーブイエスエス | 脆弱性の危険度を0〜10で数値化したスコア |
| **AIエージェント** | エーアイエージェント | 自律的に考えて行動するAIシステム |
| **Kimi K3** | キミケーさん | 中国の企業が開発したAI。今回の脆弱性発見に使われた |
| **RDB** | アールディービー | RedisのデータをファイルとしてHDD等に保存する形式 |
| **ダングリングポインタ** | だんぐりんぐぽいんた | すでに解放されたメモリを指し示したままになっているポインタ（参照）。危険な状態 |
