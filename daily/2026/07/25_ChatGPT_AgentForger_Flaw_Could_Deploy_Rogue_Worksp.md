# ChatGPT「AgentForger」脆弱性：フィッシングリンク1つで組織内にスパイAIエージェントを仕掛けられる欠陥が発見された

**元記事**: [ChatGPT AgentForger Flaw Could Deploy Rogue Workspace Agents via a Phishing Link](https://inl03.netline.com/ltr6/?_m=3n.009a.4039.sp0ao46r89.33g2)
**解説日**: 2026年7月25日

---

## 背景知識

このニュースを理解するために、いくつかのキーワードをまず押さえておきましょう。

### 🤖 ChatGPT Workspace Agents（チャットGPT ワークスペース エージェント）とは？
OpenAI（ChatGPTを作った会社）が企業向けに提供している機能です。簡単に言うと「自動でいろんな仕事をこなしてくれるAIロボット」のようなもので、メールの確認・カレンダーの管理・ファイルの整理などを**人間の代わりに自動でやってくれます**。企業の社員が使うSlackやGmail、Outlookなどのサービスと連携できます。

### 🏗️ Agent Builder（エージェント ビルダー）とは？
上記のAIエージェントを「ブロックを並べるように視覚的に組み立てられるツール」です。プログラミングの知識がなくても、ドラッグ＆ドロップ（マウスでつかんで動かす操作）でAIに自動処理をさせる手順を設定できます。

### 🎣 フィッシングリンクとは？
一見普通のURLに見えるけれど、クリックすると悪意ある処理が動き出す「偽のリンク」のことです。たとえば「Amazonからのお知らせ」に見せかけたリンクが典型例です。

### 🔄 CSRF（クロスサイト・リクエスト・フォージェリ）とは？
ログイン済みのユーザーに、**本人が意図しない操作を勝手にさせてしまう攻撃手法**です。銀行のサイトにログインしたまま悪意あるリンクをクリックすると、知らぬ間に送金手続きが実行される…といった攻撃がこれにあたります。

### 🔌 コネクター（Connector）とは？
ChatGPTとGmailやSlackなど他のサービスを「つなぎ合わせる橋」のようなものです。一度設定すると、ChatGPTが自動でメールを読んだり、カレンダーを操作したりできるようになります。

## 何が起きたのか

セキュリティ研究会社「Zenity Labs」が、**OpenAIのChatGPT Workspace Agentsに深刻な脆弱性（セキュリティ上の欠陥）を発見しました**。

この欠陥は **「AgentForger（エージェントフォージャー）」** と名付けられました。"Forge"には「偽造する」「不正に作り出す」という意味があります。

### 🚨 何が怖いのか、一言でいうと…

> **「普通のChatGPTのリンクに見せかけたURLを1つクリックするだけで、攻撃者が組織内に"スパイAIエージェント"を仕込めてしまう」**

という欠陥です。

### 📅 現在の状況
- 2026年6月8日にOpenAIが修正済み（パッチ適用完了）
- Zenity LabsがOpenAIに事前に報告し、公表前に直してもらう「責任ある開示」のプロセスを経ています
- Agent Builder自体は2026年11月30日をもって廃止予定（後継は「Agents SDK」）

## 技術的な詳細

では、この攻撃がどのように動いていたかを、ステップごとに見ていきましょう。

### 🔍 攻撃の仕組み（図解イメージ）

```
攻撃者
 └─→ 悪意あるURLを作成
       └─→ フィッシングメールなどで社員に送付
             └─→ 社員がリンクをクリック（ログイン済みのChatGPT）
                   └─→ 自動でスパイAIエージェントが作成・起動！
                         └─→ 毎時間、攻撃者の指示でメール・ファイルを盗み見
```

### 📌 ポイント1：URLにコマンドが仕込める

Agent BuilderのURLには、こんな形式でパラメーター（追加情報）を渡せることが判明しました：

```
chatgpt.com/agents/studio/new
  ?template_name=テンプレート名
  &initial_assistant_prompt=【ここに指示文】
```

通常、`initial_assistant_prompt`（最初にAIへ送る指示）はユーザーが自分で入力するものです。しかし調査により、**このURLをページが開いた瞬間に自動で実行してしまう**ことがわかりました。つまり、URLを見るだけで指示が動いてしまうのです。

> 🍔 **わかりやすい例えで言うと…**
> ハンバーガーショップのセルフオーダー端末で、「URLを開いただけで自動的に注文が確定してしまう」ようなイメージです。本来はボタンを押すはずなのに、勝手に処理が走ってしまう状態です。

### 📌 ポイント2：攻撃が成功する3つの条件

攻撃者がこの欠陥を使うには、ターゲット（被害者）が以下の3つを満たしている必要がありました：

| 条件 | 内容 |
|------|------|
| ① | ChatGPTにログイン済みであること |
| ② | Workspace Agentsを使える権限があること |
| ③ | GmailやSlackなど、少なくとも1つのコネクターが設定済みであること |

企業でChatGPTを本格活用しているユーザーは、この3条件をほぼ満たしていることが多く、**標的になりやすい状況**でした。

### 📌 ポイント3：AIエージェントが自動でやること

悪意あるURLを踏んでしまうと、AIエージェントが次の処理を**全自動で**実行します：

1. **「チーフ・オブ・スタッフ」テンプレートでエージェントを作成**
   （秘書的な役割を持つテンプレートを悪用）

2. **全コネクターに「承認不要」設定を適用**
   本来なら「このアプリを使っていいですか？」と確認が入るのに、その確認をオフにします

3. **1時間ごとに自動で動き続けるよう設定（=永続的な潜伏）**

4. **即座にプレビューモードで動き出す**
   テスト用のプレビューが「本番と同じく実際のデータにアクセスできてしまう」仕様を利用

5. **攻撃者のメールアドレスから「TASK」で始める件名のメールを受信するたびに、指示を実行して結果を攻撃者に送信**

> 🕵️ **わかりやすい例えで言うと…**
> 会社の中に、攻撃者の命令だけを聞くスパイ社員を「AIの姿で」こっそり雇ってしまうようなイメージです。そのスパイはメールやファイルを読み漁り、結果を外の攻撃者に報告し続けます。

## なぜ重要なのか

### 💥 1クリックで完結する点が異常に危険

通常のサイバー攻撃は、複数のステップが必要です（マルウェアのダウンロード→インストール→実行…など）。しかしこの攻撃は、**リンクを1回クリックするだけで攻撃が完了します**。メールやチャットで送られてきた「ちょっと怪しいけどChatGPTのリンクだし大丈夫か…」という一瞬の油断が致命傷になりえます。

### 🏢 企業の信頼境界線を内側から破る

企業のセキュリティは「外から守る壁」を想定して作られていることが多いです。しかしこの攻撃は、**正規の社員の権限を使って組織の内側から動く**ため、ファイアウォール（外部からの攻撃を防ぐ仕組み）などの従来の防御が機能しにくい点が深刻です。

### 📧 毎時間・継続的にデータが漏れる

AIエージェントが1時間ごとに自動起動するよう設定されるため、**発見されるまでの間、継続的に社内の情報（メール・ファイル・スケジュールなど）が攻撃者に送られ続けます**。

## 対策・今後の展望

### ✅ 現時点での対策

| 対策 | 内容 |
|------|------|
| **既に修正済み** | OpenAIが2026年6月8日にパッチを適用。現在は同様の攻撃は不可能 |
| **不審なリンクをクリックしない** | たとえChatGPTの公式URLに見えても、知らない人から送られたリンクは慎重に |
| **コネクターの設定を見直す** | 本当に必要なコネクターだけに絞り、不要なものは削除する |
| **エージェントの定期的な棚卸し** | 知らないうちに作られたエージェントがないか定期確認する |
| **Agent BuilderからAgents SDKへの移行** | OpenAIは2026年11月30日にAgent Builderを廃止。新しいSDKへの移行を推奨 |

### 🔮 今後の展望

AIエージェントが企業内に普及するにつれ、今回のような「**AIそのものを攻撃の道具に変える**」手口は増えていくと予想されます。AIが持つ「自律的に動く」「多くのシステムにアクセスできる」という強みが、裏返せばセキュリティ上のリスクになるためです。今後はAIセキュリティの専門分野（AIレッドチーム）がますます重要になるでしょう。

## 過去記事との関連

以前、**「BlueNoroffのZoomフィッシング詐欺」や「保険フィッシングのリアルタイム口座乗っ取り」**についてお伝えしました。

これらに共通するのは、**「フィッシング（だまし）から始まる攻撃」**という点です。

| 過去の事例 | 今回の事例 |
|-----------|-----------|
| Zoomの偽リンクで仮想通貨を狙う | ChatGPTの正規風URLでAIエージェントを悪用 |
| 保険サイトを偽造してリアルタイムで口座を乗っ取る | AIエージェントが継続的に自動で情報を盗み続ける |

これらの事例を見ると、攻撃者の手口が「**より巧妙に・より自動化されて・より長期間気づかれにくく**」進化しているのがわかります。今回の AgentForger はその最先端とも言える事例で、AIという新技術が攻撃側に悪用された点で特に注目に値します。

> 💡 **まとめると**：フィッシング攻撃の"進化形"として、AIツールそのものが武器に変わる時代になってきた、ということです。

## 用語解説

| 用語 | 説明 |
|------|------|
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやシステムにある「セキュリティ上の穴・欠陥」のこと |
| **フィッシングリンク** | 本物に見せかけた偽のURL。クリックすると悪意ある処理が動く |
| **CSRF（クロスサイト・リクエスト・フォージェリ）** | ログイン済みユーザーに、意図しない操作を勝手に実行させる攻撃手法 |
| **AIエージェント** | 人間の代わりに自律的にタスクをこなすAIプログラム |
| **Agent Builder** | ChatGPTのAIエージェントを視覚的に作成できるツール（2026年11月廃止予定） |
| **コネクター** | ChatGPTとGmail・Slack等の外部サービスをつなぐ連携機能 |
| **プレビューモード** | 本来はエージェントの動作確認用のテストモード（今回はこれが実害を生んだ） |
| **URLパラメーター** | URLの末尾に「?」以降で付け加えられる追加情報のこと |
| **責任ある開示（Responsible Disclosure）** | 脆弱性を発見した研究者が、公表前に開発元に報告して修正させるプロセス |
| **パッチ** | ソフトウェアの欠陥を修正するための更新プログラム |
| **AIレッドチーム** | AIシステムへの攻撃を模擬して安全性を検証する専門家チーム |
| **永続性（Persistence）** | 攻撃者がシステムに居続けるための仕組み。今回は「1時間ごと自動起動」がこれにあたる |
