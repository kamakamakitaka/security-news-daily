# GitHubが「3日間の待機期間」を追加！毒入りパッケージの自動取り込みを防ぐ新機能

**元記事**: [GitHub Adds 3-Day Dependabot Cooldown to Limit Poisoned Package Adoption](https://inl03.netline.com/ltr6/?_m=3n.009a.4040.sp0ao46r89.33gg)
**解説日**: 2025年7月11日

---

## 背景知識

このニュースを理解するために、まずいくつかの大切な概念を説明します。

### 📦 「パッケージ」「ライブラリ」って何？

プログラムを作るとき、すべての機能をゼロから自分で作ることはほとんどありません。  
たとえば「ログイン機能」や「画像を処理する機能」など、他の人がすでに作って公開しているプログラムの部品（＝**パッケージ**や**ライブラリ**）を使い回します。

> 🍕 例え話：ピザを作るとき、生地から手作りする人もいれば、スーパーで売っている既製品の生地を使う人もいますよね。プログラミングでも同じで、他の人が作ったパーツを組み合わせることがよくあります。

### 🔗 「依存関係（Dependency）」って何？

あなたのプログラムが「このパッケージがないと動かない」という関係のことを**依存関係**と言います。  
例えば、「私のアプリはA・B・Cのパッケージがないと動きません」という状態です。

### 🤖 「Dependabot（ディペンダボット）」って何？

GitHubが提供している自動化ツールで、あなたのプログラムが使っているパッケージが古くなったり、セキュリティの弱点（脆弱性）が見つかったりしたとき、**自動的に新しいバージョンに更新するよう提案してくれる**ロボットです。

> 🤖 例え話：「あなたのスマホのアプリの中に古いバージョンのものがあります。更新しましょうか？」と自動で教えてくれるお知らせ機能のイメージです。

### 💉 「毒入りパッケージ（Poisoned Package）」って何？

悪意を持った攻撃者が、人気のある正規パッケージに**こっそりウイルスや悪いコードを仕込んで**公開したものです。

> 💊 例え話：薬局に並んでいる市販薬に、誰かがこっそり毒を混ぜて元の場所に戻したようなイメージです。見た目は普通の薬（パッケージ）なのに、中身が危険になっています。

### 🏗️ 「サプライチェーン攻撃」って何？

直接システムを攻撃するのではなく、**そのシステムが使っている部品（パッケージ）に悪意あるコードを仕込む**攻撃手法です。多くのシステムが同じパッケージを使っているため、一度の攻撃で大きな被害が生まれます。

---

## 何が起きたのか

GitHubが、Dependabotに**「3日間のクールダウン（待機期間）」**という新機能を追加すると発表しました。

これまでのDependabotは、新しいバージョンのパッケージが公開されると、**すぐに**「このパッケージを更新しませんか？」と提案していました。

**新機能の動作：**
- 通常のバージョン更新 → **3日間待ってから**提案する
- セキュリティ上の緊急更新 → **これまで通りすぐに**提案する

---

## 技術的な詳細

### なぜ「3日間」なのか？

攻撃者が毒入りパッケージをばらまく際の典型的な手口は次のようなものです：

```
[攻撃の流れ]
1. 攻撃者が人気パッケージの偽バージョンを公開
        ↓（数時間〜数日）
2. Dependabotが「新バージョン出たよ！」と自動提案
        ↓
3. 多くのプロジェクトが自動的に毒入りバージョンを取り込む
        ↓
4. 運営側が気づいて毒入りパッケージを削除
        ↓
5. でも、すでに多くのシステムが感染済み😱
```

GitHubは3日間を「ちょうどいい待機時間（ゴルディロックスゾーン）」と表現しています。

> 🐻 「ゴルディロックス」とは、「三匹の熊」の童話に出てくる少女の名前。熱すぎず冷たすぎず「ちょうどいい」を意味する言葉として使われます。

- **短すぎる（例：1日）** → 攻撃者の毒パッケージが検出される前に取り込まれてしまう
- **長すぎる（例：30日）** → 重要なアップデートが遅れすぎてしまう
- **3日間** → 多くの攻撃をブロックでき、かつ更新の遅れも最小限 ✅

### 設定は変更できる

`dependabot.yml`という設定ファイルを書き換えることで、3日より短くも長くも設定できます。自分のプロジェクトに合わせた調整が可能です。

## なぜ重要なのか

### 📊 被害の規模感

多くの有名なパッケージは数千〜数万のプロジェクトで使われています。  
もし人気パッケージに毒が仕込まれ、Dependabotが素早く全プロジェクトに配布したら…

> 例え話：給食センターが全校分の食事を作っているとき、そこに毒が混入したら、一気に全生徒が被害を受けますよね。Dependabotはその「給食センター」的な役割を持っているため、攻撃の影響が爆発的に広がる可能性があります。

この「被害の広がり」を記事では **「ブラストレディアス（爆発半径）」** と表現しています。

### ⚠️ ただし、万能ではない

GitHubは正直に限界も認めています。この機能が**効かない攻撃**もあります：

| 攻撃の種類 | 3日間待機で防げる？ |
|---|---|
| 短期間で広まる毒入りパッケージ | ✅ 防げる |
| 長期間こっそり潜む悪意あるコード（バックドア） | ❌ 防げない |
| パッケージ開発者自身が意図的に悪意を仕込む（メンテナーサボタージュ） | ❌ 防げない |
| ビルドシステム全体への侵害 | ❌ 防げない |

## 対策・今後の展望

### GitHubが推奨する多層防御

GitHubは「3日間待機だけに頼らないでください」と強調しています。複数の防御策を組み合わせることが重要です：

1. **🔒 ロックファイルで依存関係を固定する**  
   「このバージョンのパッケージしか使わない」と厳密に指定するファイルを使う

2. **🚫 CI環境でインストールスクリプトを無効化する**  
   パッケージのインストール時に自動実行されるスクリプトを止める

3. **🔑 ビルド時のトークン（認証情報）の権限を最小限にする**  
   万が一漏れても被害が最小限になるように

4. **👀 更新内容を人間が確認してからマージする**  
   自動で取り込まず、人間が中身を確認する

### 他のサービスでも同様の動き

この記事では、同様の対策が他のサービスでも広がっていることが紹介されています：
- **VS Code**（Microsoftのコードエディタ）
- **Ruby・npm・Yarn**（各種プログラミング言語のパッケージ管理システム）
- **PyPI**（Pythonのパッケージ配布サービス）→ 公開から14日後はファイル追加を禁止

業界全体で、パッケージの安全性を高める方向に動いています。

## 過去記事との関連

今回の記事は単独のニュースですが、ソフトウェアの「サプライチェーン攻撃」は近年非常に注目されているテーマです。

代表的な過去事例として、**SolarWinds事件（2020年）**があります。ソフトウェアの更新ファイルに悪意あるコードが仕込まれ、米国政府機関を含む多くの組織が被害を受けました。この事件以来、「信頼しているものが実は危険」というサプライチェーン攻撃への対策が世界規模で強化されています。今回のDependabotの機能追加も、その流れの一つと言えます。

## 用語解説

| 用語 | 意味 |
|---|---|
| **Dependabot（ディペンダボット）** | GitHubが提供する、パッケージの自動更新提案ツール |
| **パッケージ / ライブラリ** | 他の開発者が作って公開している、プログラムの部品 |
| **依存関係（Dependency）** | 自分のプログラムが必要としている外部パッケージとの関係 |
| **プルリクエスト（PR）** | コードの変更を提案すること（「これに変えてみませんか？」という申請） |
| **クールダウン** | 動作するまでの待機期間 |
| **毒入りパッケージ（Poisoned Package）** | 悪意あるコードを仕込まれたパッケージ |
| **サプライチェーン攻撃** | システムが使う部品（パッケージ等）を経由した間接的な攻撃 |
| **ブラストレディアス（Blast Radius）** | 攻撃被害が広がる範囲・規模 |
| **バックドア** | こっそり仕込まれた「裏口」。攻撃者が後でシステムに不正侵入するための抜け穴 |
| **ロックファイル** | 使用するパッケージのバージョンを固定して記録するファイル |
| **PyPI（パイピーアイ）** | Pythonのプログラムで使うパッケージを配布する公式サービス |
| **トークン** | 認証に使う「デジタルの合言葉・鍵」 |

> 💡 **まとめると…**
> GitHubが「新しいパッケージをすぐに取り込まず、3日間様子を見る」機能を追加しました。これにより、悪意あるパッケージが短期間だけ出回ったとしても、自動的に取り込まれるリスクを減らせます。ただし完璧ではないので、複数の対策を組み合わせることが大切です！
