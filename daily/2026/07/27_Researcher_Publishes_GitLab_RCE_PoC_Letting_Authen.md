# GitLabに深刻な脆弱性！認証済みユーザーがサーバーを乗っ取れるRCEが公開された

**元記事**: [Researcher Publishes GitLab RCE PoC Letting Authenticated Users Run Commands as Git](https://inl03.netline.com/ltr6/?_m=3n.009a.4040.sp0ao46r89.33ha)
**解説日**: 2026年7月28日

---

## 背景知識

まずは、今回の記事を理解するために必要な用語・仕組みを整理しましょう。

### GitLabってなに？
GitLab（ギットラブ）は、プログラマーがコード（ソフトウェアの設計図）を保存・共有・管理するためのサービスです。GitHubに似たもので、企業や学校が「自分たちのサーバーで動かす自社版GitLab（セルフマネージド版）」を使っていることも多いです。

### RCE（リモートコード実行）ってなに？
RCE（Remote Code Execution）は、攻撃者がインターネット越しに、他人のサーバーで自分の好きなコマンド（命令）を実行できてしまう攻撃のことです。これはセキュリティ上、最も危険な部類の脆弱性です。

> 💡 例え話：鍵のかかった銀行の金庫室に、外から電話一本で扉を開けさせてしまうようなイメージです。

### PoC（概念実証コード）ってなに？
PoC（Proof of Concept）とは、「この脆弱性は本当に悪用できますよ」と証明するために作られた実際に動く攻撃コードのことです。研究者が公開することで、管理者に「急いでアップデートして！」と警告する目的があります。ただし悪用されるリスクもあります。

### Jupyter Notebookってなに？
データ分析や機械学習でよく使われる「対話形式のドキュメント」形式のファイルです（`.ipynb`という拡張子）。GitLabはこのファイルの中身を画面上で見やすく表示する機能を持っています。

### 「認証済みユーザー」ってどういう意味？
GitLabにログインできる正規のアカウントを持つ人のことです。外部の知らない人ではなく、「普通のメンバー」でも攻撃できてしまうという点が今回の深刻さのポイントです。

---

## 何が起きたのか

セキュリティ研究チーム「depthfirst」が、2026年7月24日に GitLab の深刻な脆弱性を突く**実際に動く攻撃コード（PoC）を公開**しました。

### 時系列まとめ

| 日付 | 出来事 |
|------|--------|
| 2026年6月10日 | GitLabがバグ修正パッチをリリース（**セキュリティ修正とは明記せず**） |
| 2026年7月24日 | depthfirstが攻撃コード（PoC）を公開 |

### 問題の核心：「セキュリティ修正」として告知されなかった

ここが特に重要です。GitLabは6月10日にこの問題を修正していたのですが、**「バグ修正」として分類し、セキュリティ上の問題とは明記しませんでした。**

CVE番号（脆弱性の識別番号）もなく、CVSS（危険度スコア）もなし。これにより、多くの管理者が「緊急ではない普通のアップデート」と判断し、適用を後回しにしてしまった可能性があります。

> 💡 例え話：家の玄関の鍵に欠陥があったのに、修理業者が「外観のちょっとした改善をしました」とだけ伝えて、実は鍵の欠陥を直していた、みたいな状況です。

## 技術的な詳細

少し難しいですが、できるだけわかりやすく説明します！

### 攻撃の流れ（ステップバイステップ）

```
①  攻撃者が「細工した Jupyter Notebookファイル」をリポジトリにアップロード
        ↓
②  GitLab がそのファイルの「差分（変更箇所）」を表示しようとする
        ↓
③  表示処理中に「メモリのアドレス（住所）」が画面に漏れ出す（情報漏洩）
        ↓
④  その情報を使って、メモリ上のライブラリの場所を特定
        ↓
⑤  さらに2つ目・3つ目の細工ファイルで、本命の攻撃コードを実行
        ↓
⑥  サーバー上で任意のコマンドが「git」アカウントとして実行される！
```

### 何が原因？

**Oj（オジェイ）** という、Ruby言語でJSONデータを高速処理するためのライブラリにバグが2つありました。このライブラリはCという低レベル言語で書かれており、**メモリ管理を手動でやっている部分**にバグが潜んでいました。

🐛 **バグ①：書き込みオーバーフロー**
1,024バイトの決まったサイズのメモリ領域を超えて書き込みができてしまう。これにより、プログラムの動作を乗っ取るための「足がかり」が作れます。

> 💡 例え話：マス目が10個しかないノートに、11個目以降も強引に書き込むことで、隣のページの内容を書き換えてしまうようなイメージ。

🐛 **バグ②：情報漏洩（ヒープポインタのリーク）**
本来はメモリの「住所（アドレス）」を秘密にしておく必要があるのに、それが画面に表示されてしまう。

### 「git」アカウントで実行される、の意味

攻撃が成功すると、コマンドは **`git`** というシステムアカウント名で実行されます。このアカウントがアクセスできるものは以下のとおりです：

- 📁 ソースコード（全プロジェクトのプログラム）
- 🔑 Railsシークレット（アプリの重要な設定情報・暗号鍵）
- 🔐 サービスの認証情報（パスワードや接続情報）
- 🔄 CI/CDデータ（自動ビルド・デプロイの設定や結果）
- 🌐 内部ネットワークのサービスへのアクセス

## なぜ重要なのか

### 影響を受ける範囲が非常に広い

- GitLab **CE（無償版）・EE（有償版）**、すべてのプラン（Free〜Ultimate）が対象
- バージョン **18.11.3** で実証されており、同じアーキテクチャ（x86-64）なら他のバージョンにも応用しやすい
- **管理者権限不要**、**被害者の操作不要**、**特別な設定不要**

### 「管理者じゃなくても攻撃できる」が特に危険

普通、深刻な攻撃には「管理者アカウント」や「特別な権限」が必要なことが多いです。しかし今回は、**プロジェクトにコードをアップロードできる普通のメンバーアカウント**があれば攻撃できてしまいます。

企業では、アルバイトや外部委託の開発者にも「普通のアカウント」を付与することが多く、内部不正やアカウント乗っ取りからの被害が広がりやすい状況です。

### セキュリティ開示の問題

今回、GitLabが修正をセキュリティ問題として明記しなかったことで、多くの管理者が気づかずにいた可能性があります。これは「開示の透明性」という観点から業界全体への警鐘にもなっています。

## 対策・今後の展望

### 今すぐやること：アップデート！

以下のバージョンに更新すれば、この脆弱性は修正されています。

| 修正済みバージョン |
|---|
| **18.10.8** |
| **18.11.5** |
| **19.0.2** |

### Helm / Kubernetes（コンテナ環境）を使っている人へ

⚠️ 注意点があります：
- **チャートのバージョン**や**Operatorのバージョン**ではなく、内部で動いている **`Webservice`イメージのGitLabバージョン**を確認してください
- バージョン **15.2〜18.9** はバックポート（古いバージョンへの修正提供）が**ありません**。サポート対象のバージョンに移行が必要です

### 回避策（アップデートできない場合）

残念ながら、今のところ**公式の設定変更による回避策は存在しません。**

研究者のWu氏は「Notebookの差分表示機能を完全に無効化するオプションは確認できていない」と述べており、**アップデート以外の確実な対策はない**状態です。どうしても更新できない場合は、GitLab社に直接問い合わせることが推奨されています。

## 過去記事との関連

以前、**「Fastjson 1.xのRCE脆弱性」**（パッチなしで攻撃が始まっているという記事）を解説しました。

今回のGitLab脆弱性と共通するテーマがあります：

> **「JSONパーサー（JSONデータを処理するライブラリ）にRCE脆弱性が見つかった」**

Fastjsonは**Java**のJSONライブラリ、今回のOjは**Ruby**のJSONライブラリと、言語は違いますが、**「外部から受け取ったデータを処理するライブラリ」が攻撃の入口になる**というパターンは共通しています。

また両記事とも、「脆弱性の開示と修正の告知が適切でなかった」という問題を孕んでおり、**セキュリティの透明性の重要性**という観点でも関連しています。

## 用語解説

| 用語 | 意味 |
|------|------|
| **RCE（リモートコード実行）** | 攻撃者が遠隔からサーバーで任意のコマンドを実行できる脆弱性 |
| **PoC（概念実証コード）** | 脆弱性が実際に悪用できることを証明する動作するコード |
| **GitLab** | コードを管理・共有するためのプラットフォーム。自社サーバーで運用できる |
| **セルフマネージド** | クラウドサービスではなく、自分たちのサーバーで運用すること |
| **Jupyter Notebook（.ipynb）** | データ分析などで使われる対話型ドキュメント形式のファイル |
| **Oj** | RubyでJSONを高速処理するためのライブラリ（C言語で書かれている） |
| **メモリ破壊（Memory Corruption）** | プログラムが本来触れてはいけないメモリ領域を書き換えてしまうバグ |
| **ヒープポインタ** | メモリ上の「住所」のようなもの。漏れると攻撃の手がかりになる |
| **CVE** | 脆弱性に付けられる世界共通の識別番号（例: CVE-2024-XXXX） |
| **CVSS** | 脆弱性の深刻度を0〜10点で数値化したスコア |
| **CI/CD** | コードを自動でテスト・配布（デプロイ）する仕組み |
| **x86-64** | WindowsやLinuxサーバーでよく使われるCPUのアーキテクチャ（設計方式） |
| **Puma** | RubyのWebアプリを動かすためのサーバープログラム |
| **バックポート** | 新しいバージョンの修正を古いバージョンにも適用すること |

---

> ⚡ **まとめると**：GitLabのJupyter Notebook表示機能に深刻なバグがあり、普通のユーザーアカウントでもサーバーを乗っ取れる。修正版は出ているが、セキュリティ問題として告知されなかったため気づいていない管理者が多い可能性がある。**今すぐバージョン確認とアップデートを！**
