# TELESHIMがTelegramを悪用！東アジア発の中東政府を狙ったサイバー攻撃

**元記事**: [TELESHIM Abuses Telegram for C2 in Attacks Against Middle East Governments](https://inl03.netline.com/ltr6/?_m=3n.009a.4040.sp0ao46r89.33ga)
**解説日**: 2025年7月14日

---

## 背景知識

まず、このニュースを理解するために必要な知識をいくつか説明しましょう。

### 📱 Telegramとは？
みなさんもご存知のように、Telegramはメッセージをやりとりするチャットアプリです。LINEやWhatsAppと似ていますが、**プログラムから自動でメッセージを送受信できる「API（アプリの機能を外部から使う仕組み）」**が充実していることで知られています。今回、この機能が悪用されました。

### 🕵️ C2（Command and Control）って何？
C2とは「指令センター」のようなものです。ハッカーが感染させたコンピューターに「次はこれをしろ」と命令を送ったり、盗んだ情報を受け取ったりする仕組みです。

> 🏠 例え話：悪の組織のボスが、スパイが潜入した建物に暗号メッセージを送って指示するイメージです。Telegramがその「暗号通信手段」として使われました。

### 🦠 マルウェアとは？
マルウェアとは、コンピューターに害を与える悪意あるソフトウェアの総称です。ウイルス、スパイウェアなどが含まれます。

### 🏛️ APT（高度持続型脅威）とは？
APTとは、国家や大きな組織が背後にいると思われる、非常に高度で長期間にわたるサイバー攻撃のことです。普通のハッカーではなく、「プロの諜報組織」が動いているイメージです。

---

## 何が起きたのか

セキュリティ企業「Zscaler ThreatLabz」が、**中東の政府機関を狙った新しいサイバー攻撃キャンペーン**を発見しました。

### 事件の概要をまとめると…

| 項目 | 内容 |
|------|------|
| 攻撃者の出身 | 東アジア（高い確信度）|
| 標的 | 中東の政府機関 |
| 発見時期 | 2025年7月初旬 |
| 主な活動時間帯 | 午前4時〜正午UTC（日本時間：午後1時〜午後9時）|
| 使用したマルウェア | TELESHIM、MIXEDKEY、BINDCLOAK |

特に注目すべきは、**普段みんなが使っているTelegramを隠れ蓑にして指令通信を行った**という点です。セキュリティシステムから見ると「普通のTelegramの通信」に見えてしまうため、検知が非常に難しくなります。

## 技術的な詳細

攻撃は複数のステップに分かれた、まるで「入れ子になったロシアのマトリョーシカ人形」のような構造になっています。

### 🪜 攻撃の流れ（ステップバイステップ）

```
【ステップ1】ISOファイルを開かせる
    ↓
【ステップ2】正規に見せかけたプログラムが悪意のあるDLLを読み込む
（DLLサイドローディング）
    ↓
【ステップ3】TELESHIM（バックドア）が起動
    ↓
【ステップ4】TelegramのAPIを通じてハッカーから命令を受け取る
    ↓
【ステップ5】追加のマルウェア(MIXEDKEY)をダウンロード・実行
    ↓
【ステップ6】暗号化されたファイルを解読して実行
    ↓
【ステップ7】最終的にBINDCLOAKが展開される
```

### 🔍 各マルウェアの役割

#### TELESHIM（テレシム）
- **役割**：最初に感染したPCに住み着く「バックドア（裏口）」
- **特徴**：Telegramを使って指令センターと通信する
- 感染したPCの**MACアドレス（機器の識別番号）**をハッカーに送信
- コマンドを実行し、結果を返送する
- セキュリティ分析環境（仮想マシンなど）を検知して、研究者に解析されないようにする

> 💡 **DLLサイドローディングとは？**
> Windowsでは、プログラムが動作するときに「DLLファイル」という部品を読み込みます。正規のソフトウェアが「正規のDLL」の代わりに「偽物のDLL」を読み込まされる攻撃手法です。信頼されたソフトの名前を借りて悪さをするため、検知が難しいです。

#### MIXEDKEY（ミックスドキー）
- **役割**：暗号化されたファイルを解読して実行する「鍵係」
- 感染したPCの**ボリュームシリアル番号**（HDDに割り当てられた固有の番号）を使って暗号を解く
- これにより、**狙ったPCでしかマルウェアが動かない**仕組みになっている

> 💡 **Environmental Keying（環境キーイング）とは？**
> 「鍵がそのPCの固有情報から生成される」ため、別のPCにコピーされても動作しません。セキュリティ研究者が自分のPCで解析しようとしても動かない、という巧妙な手口です。

#### BINDCLOAK（バインドクローク）
- **役割**：最終的に展開される本命の「諜報ツール」
- C++で書かれた64ビットのプログラム
- 外部サーバー（`cert.hypersnet[.]com`）に接続して、さらなる活動を行う

### 🛡️ 解析を妨げる高度な技術

このマルウェアは、セキュリティ研究者に解析されないよう様々な「難読化」技術を使っています。

| 技術名 | わかりやすい説明 |
|--------|-----------------|
| 文字列暗号化 | プログラム内の文字を暗号化して読めなくする |
| 制御フロー平坦化（CFF） | プログラムの処理の流れを複雑に絡ませて読みにくくする |
| 混合ブール演算（MBA） | 数学的な計算をわざと複雑に書いて解析を妨げる |
| 不透明述語 | 「常にTrue/False」になる無意味な条件分岐を大量に挿入して混乱させる |
| 仮想環境検知 | セキュリティ研究者が使う仮想マシンかどうかを判定する |

## なぜ重要なのか

### 🎯 標的が「政府機関」
今回の攻撃は、一般企業ではなく**中東の政府機関**が狙われました。政府が持つ機密情報（外交文書、安全保障情報など）が盗まれる可能性があり、国家安全保障レベルの深刻な問題です。

### 📱 「信頼されたサービス」の悪用という新しいトレンド
Telegramのような多くの人が使う正規サービスをC2通信に使うことで、**セキュリティ製品の検知をすり抜けます**。ファイアウォール（不正な通信を遮断するシステム）から見ると、ただのTelegramの通信に見えてしまうからです。

> 🚦 例え話：学校の先生が「怪しい車は止める」と正門でチェックしているとします。でも犯人がスクールバスに乗り込んで移動したら、怪しまれずに通れますよね。Telegramはまさに「スクールバス」として使われたわけです。

### 🌏 東アジア発のAPT攻撃
攻撃者の活動時間、IPアドレスの位置、使用言語の設定などから、**東アジア（おそらく中国周辺）出身の攻撃者**であると高い確信度で判断されています。ただし、現時点では既知の攻撃グループへの帰属はされていません。

## 対策・今後の展望

### ✅ 組織が取るべき対策

1. **ISOファイルの取り扱いに注意する**
   - 不明なISOファイルを開かない（今回の攻撃はISOファイルから始まります）
   - メールや外部メディアからのISOファイルは特に慎重に

2. **Telegram等のチャットアプリの業務利用を管理する**
   - 業務ネットワークからのTelegram APIアクセスを監視・制限する

3. **EDR（エンドポイント検出・対応）ツールを導入する**
   - 今回の攻撃者は特にEDRの回避を意識しているため、最新のEDRを適切に設定することが重要

4. **ネットワーク通信の異常を監視する**
   - 不審な外部サーバーへの通信がないかチェックする

5. **DLLサイドローディング対策**
   - ソフトウェアのインストール先やDLLの読み込み元を適切に管理する

### 🔮 今後の展望

- このマルウェアは**まだ既知の攻撃グループに紐付けられていない**ため、新しい攻撃グループの存在が疑われています
- Telegramのような信頼されたプラットフォームを悪用する手口は今後も増加すると予想されます
- セキュリティ企業による継続的な分析と、攻撃グループの特定が急がれます

## 用語解説

| 用語 | 説明 |
|------|------|
| **マルウェア** | コンピューターに害を与える悪意あるソフトウェアの総称 |
| **C2（Command and Control）** | 攻撃者がマルウェアに命令を送り、情報を受け取るための指令センター |
| **バックドア** | 攻撃者がいつでも侵入できるよう、コンピューターに仕掛けた「裏口」 |
| **APT** | 国家・大組織が背後にいる、高度で長期的なサイバー攻撃 |
| **DLL** | Windowsプログラムが使う「部品ファイル」のこと |
| **DLLサイドローディング** | 正規のソフトに偽物のDLLを読み込ませる攻撃手法 |
| **ISO ファイル** | CD/DVDなどのディスクの内容をまとめたファイル形式 |
| **難読化（オブファスケーション）** | プログラムを人間や解析ツールが読みにくくする技術 |
| **Environmental Keying** | 感染先の固有情報を暗号の鍵にする技術。別環境では動作しない |
| **MACアドレス** | ネットワーク機器に割り当てられた固有の識別番号 |
| **EDR** | コンピューターへの攻撃をリアルタイムで検知・対応するセキュリティツール |
| **XOR暗号** | データのビットを反転させるシンプルな暗号化手法 |
| **反射型ローダー（Reflective Loader）** | ファイルをディスクに書き込まずメモリ上で直接実行する技術 |
| **ファイアウォール** | ネットワークへの不正な侵入や通信を防ぐセキュリティの「壁」 |
