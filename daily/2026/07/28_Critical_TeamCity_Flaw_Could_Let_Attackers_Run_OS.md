# TeamCityの深刻な脆弱性：ログインなしでOSコマンドを実行できる欠陥が発覚

**元記事**: [Critical TeamCity Flaw Could Let Attackers Run OS Commands Without Logging In](https://inl03.netline.com/ltr6/?_m=3n.009a.4041.sp0ao46r89.33hu)
**解説日**: 2025年7月17日

---

## 背景知識

### TeamCityって何？

**TeamCity（チームシティ）**は、JetBrains（ジェットブレインズ）というチェコのソフトウェア会社が作った「**CI/CDツール**」です。

> 💡 **CI/CDツールとは？**
> ソフトウェア開発では、プログラマーが書いたコードを自動的にテスト・ビルド（組み立て）・デプロイ（公開）する作業が必要です。これを自動化してくれるのがCI/CDツールです。
> 工場の「組み立てライン」のようなイメージです。コードを流し込むと、自動でテストして完成品にしてくれます。

TeamCityは世界中の企業の**開発チームが日常的に使っているシステム**で、社内サーバーにインストールして使う「**オンプレミス版**」（自社設備で動かすタイプ）があります。

### 「認証なし」がなぜ危険？

通常、重要なシステムにアクセスするには**ログイン（認証）**が必要です。
しかし今回の脆弱性は、**ログインをスキップして**直接システムに命令を送れてしまいます。

> 🏠 **例え話**：
> 家の鍵（＝ログイン認証）を持っていなくても、裏口から入れてしまうような欠陥が見つかった、というイメージです。しかも入るだけでなく、家の中のすべての電化製品を自由に操作できてしまう状態です。

---

## 何が起きたのか

2025年7月10日、**Antoni Tremblay（アントニ・トランブレイ）**というセキュリティ研究者が、TeamCityのオンプレミス版に**深刻な脆弱性（セキュリティ上の欠陥）**を発見し、JetBrainsに報告しました。

JetBrainsはこの報告を受けてすぐに調査・修正を行い、現在は**修正済みバージョンの提供と注意喚起**を行っています。

### ポイントまとめ
| 項目 | 内容 |
|------|------|
| 脆弱性ID | CVE-2026-63077 |
| 深刻度スコア | **9.8 / 10**（ほぼ最高レベル） |
| 影響範囲 | TeamCity オンプレミス版 **全バージョン** |
| 修正バージョン | 2025.11.7 / 2026.1.3 |
| 野外での悪用 | **現時点では確認されていない** |

> ⚠️ **CVSSスコア9.8とは？**
> CVSS（Common Vulnerability Scoring System）は脆弱性の危険度を0〜10で表すスコアです。9.8は「**Critical（致命的）**」レベルで、ほぼ最大の危険度を意味します。

## 技術的な詳細

### どうやって攻撃が成立するの？

今回の攻撃の流れを、できるだけわかりやすく説明します。

```
【攻撃の流れ】

① 攻撃者がインターネット経由でTeamCityサーバーに接続（HTTP/HTTPS）
         ↓
② 「エージェントポーリングプロトコル」という通信経路を悪用
         ↓
③ 本来必要なログイン認証チェックをスキップ（バイパス）
         ↓
④ サーバー上で自由にOSコマンドを実行できてしまう
```

> 💡 **エージェントポーリングプロトコルとは？**
> TeamCityでは「エージェント」と呼ばれる作業ロボットが、サーバーに「次の仕事はありますか？」と定期的に問い合わせる仕組みがあります。この通信経路（プロトコル）に認証チェックの抜け穴があったのです。

> 💡 **OSコマンドとは？**
> コンピューターのOS（WindowsやLinuxなど）に対して直接命令を出すことです。「ファイルを削除しろ」「外部に情報を送れ」「新しいユーザーを作れ」など、何でもできてしまいます。

### 攻撃が成功すると何が起きる？

- 🔑 TeamCity内に保存されている**パスワードや認証情報の流出**
- ⚙️ サーバーの**設定ファイルの改ざん**
- 📦 ビルドされた**ソフトウェアへの悪意あるコードの埋め込み**（サプライチェーン攻撃）
- 🖥️ **サーバーの乗っ取り・破壊**

特に「ソフトウェアへの悪意あるコードの埋め込み」は、**そのソフトを使うユーザー全員に被害が及ぶ可能性**があるため、非常に深刻です。

## なぜ重要なのか

### TeamCityを狙う攻撃は過去にも起きている

TeamCityは以前から攻撃者に狙われやすいターゲットです。**2023〜2024年にも複数の重大な脆弱性が発見・悪用**されており、ロシアや北朝鮮の国家支援型ハッカーグループが実際にTeamCityの脆弱性を悪用した事例が確認されています。

### 開発ツールが狙われると「川上」から汚染できる

TeamCityのようなCI/CDツールを乗っ取ることは、攻撃者にとって**非常に効率的**です。

> 🏭 **例え話**：
> 食品工場（CI/CDサーバー）に毒を混ぜれば、スーパーに並ぶ全商品（リリースされるソフトウェア）が汚染されます。消費者（エンドユーザー）を一人一人狙うよりも、工場を一つ乗っ取る方がずっと影響が大きいですよね。

これを**「サプライチェーン攻撃（供給網攻撃）」**と呼びます。

### 深刻度スコア9.8の意味

- **認証不要**（誰でも攻撃できる）
- **リモートから実行可能**（物理的に近くにいる必要がない）
- **全バージョンが対象**（古いバージョンを使っていれば全員アウト）

これらの条件が重なるため、最高レベルに近い危険度になっています。

## 対策・今後の展望

### すぐにやるべきこと

#### ✅ 対策①：アップデートを適用する（最優先）
修正済みバージョンに今すぐアップデートしてください。

- **2025.11.7** または **2026.1.3** 以上にアップデート
- アップデートが難しい場合は、**セキュリティパッチプラグイン**（2017.1以降のバージョンに対応）を適用する

> JetBrainsは「パッチプラグインはこの脆弱性だけを修正するもの。他のセキュリティ修正も含む最新バージョンへのアップグレードを常に推奨する」と述べています。

#### ✅ 対策②：VPN経由のアクセスに限定する
TeamCityサーバーをインターネットに直接公開しないようにして、**VPN（仮想プライベートネットワーク）**経由でのみアクセスできるようにする。

> 💡 **VPNとは？**
> インターネット上に「秘密のトンネル」を作る技術です。社内ネットワークにいる人しかアクセスできないようにできます。

#### ✅ 対策③：アクセス制限の強化
- ログイン画面やAPIを不必要にインターネットに公開しない
- ファイアウォール（通信の門番）でアクセス元を制限する

### JetBrainsの注意喚起より

> 「TeamCityのログイン画面やREST APIを公開するだけでも、新たに発見された脆弱性の攻撃経路になり得ます」

→ 「見せるだけなら大丈夫」は通用しないということです。

## 過去記事との関連

TeamCityの脆弱性は今回が初めてではありません。

- **2023年10月（CVE-2023-42793）**：認証バイパスの脆弱性が発見され、ロシアのAPT29（コージーベア）などが悪用
- **2024年3月（CVE-2024-27198）**：再び認証バイパスが発見され、広範な攻撃が観測される

このように、TeamCityは**「狙われやすいシステム」として攻撃者に認識されている**ため、今後も継続的な監視とアップデートが不可欠です。

今回はまだ「野外での悪用は確認されていない」とのことですが、過去の事例では**公開から数日〜数週間で攻撃が始まる**ことが多いため、**早急な対応が求められます**。

## 用語解説

| 用語 | 説明 |
|------|------|
| **TeamCity** | JetBrainsが開発したCI/CDツール。ソフトウェアの自動ビルド・テスト・デプロイを行う |
| **CI/CD** | Continuous Integration / Continuous Delivery。ソフトウェア開発の自動化パイプライン |
| **オンプレミス** | 自社のサーバーにインストールして運用する形態（クラウドの反対） |
| **脆弱性（ぜいじゃくせい）** | システムのセキュリティ上の欠陥・弱点 |
| **CVE** | Common Vulnerabilities and Exposures。脆弱性に付けられる世界共通のID番号 |
| **CVSSスコア** | 脆弱性の深刻度を0〜10で表すスコア。9.0以上は「Critical（致命的）」 |
| **認証バイパス** | 本来必要なログイン認証をスキップして不正にアクセスすること |
| **任意コード実行（RCE）** | 攻撃者が任意のプログラムをリモートから実行できる状態 |
| **OSコマンド** | コンピューターのOS（Windows/Linux等）に直接出す命令 |
| **エージェントポーリング** | TeamCityのエージェントがサーバーに定期的に仕事を問い合わせる仕組み |
| **サプライチェーン攻撃** | ソフトウェアの製造・配布の過程（供給網）に悪意あるコードを混入させる攻撃 |
| **VPN** | Virtual Private Network。安全な暗号化通信トンネルを作る技術 |
| **REST API** | システム間でデータをやり取りするためのインターフェース |
| **APT（国家支援型ハッカー）** | 特定の国家の支援を受けて活動する高度なハッカーグループ |

> 🔒 **まとめ**
> TeamCityに「ログインなしでOSを操作できる」という超深刻な脆弱性が発見されました。まだ実際の攻撃は確認されていませんが、過去の事例から**早急なアップデートが必須**です。開発ツールが狙われると、そこから作られるソフトウェア全体に影響が及ぶ「サプライチェーン攻撃」に発展する恐れもあります。
