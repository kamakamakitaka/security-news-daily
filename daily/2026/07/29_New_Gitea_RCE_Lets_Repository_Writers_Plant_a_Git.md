# GiteaのRCE脆弱性：リポジトリ書き込み権限でシェルコマンドを実行できる重大な欠陥が発覚

**元記事**: [New Gitea RCE Lets Repository Writers Plant a Git Hook to Run Shell Commands](https://inl03.netline.com/ltr6/?_m=3n.009a.4042.sp0ao46r89.33k2)
**解説日**: 2026年7月30日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を説明します。

### 🗂️ Gitとは？
**Git（ギット）** は、プログラムのソースコード（設計図）を管理するためのツールです。「いつ・誰が・どこを変えたか」を記録できるので、チームで開発するときに欠かせません。

### 🏠 Giteaとは？
**Gitea（ギッティア）** は、GitHubに似たサービスを**自分のサーバーで動かせる**ソフトウェアです。企業や個人が「社内専用GitHub」を作るときに使います。世界中でたくさんの組織が使っています。

### 🪝 Gitフック（Git Hook）とは？
Gitには「**フック（Hook）**」という仕組みがあります。これは「特定の操作が行われたときに自動的に実行されるプログラム」のことです。  
例えば：「コードが保存されたとき → 自動テストを走らせる」のような使い方ができます。  
**フックはサーバー上でシェルコマンド（OSへの命令）を実行できる**ため、悪用されると非常に危険です。

### 💥 RCE（Remote Code Execution）とは？
**RCE（リモートコード実行）** は、「遠く離れた場所から、サーバー上で自由にコマンドを実行できてしまう」という最も深刻な脆弱性の一種です。家の鍵を渡してしまうようなイメージです。

### 🔧 パッチ（Patch）とは？
プログラムの修正内容を「差分」として記録したファイルです。「ここを削除して、ここを追加して」という指示書のようなものです。

## 何が起きたのか

Giteaに**非常に深刻なセキュリティの穴（脆弱性）**が見つかりました。

| 項目 | 内容 |
|------|------|
| 脆弱性番号 | CVE-2026-60004 |
| 深刻度スコア | **9.8 / 10.0**（ほぼ最大） |
| 影響バージョン | Gitea 1.17以降〜1.27.1未満 |
| 修正バージョン | **1.27.1**（2026年7月27日リリース） |
| 発見者 | セキュリティ研究者 Shai Rod（別名：NightRang3r）氏 |

### 問題の本質をひとことで言うと？

> 「**普通のユーザーアカウントさえ作れば、サーバーを乗っ取れる**」

しかも、Giteaはデフォルト（初期設定）でユーザー登録を誰でもできるようにしているため、**外部の攻撃者が新規アカウントを作るだけで攻撃を開始できる**状態でした。

## 技術的な詳細

### 🔍 攻撃の仕組みをわかりやすく説明

攻撃の手順を「泥棒が建物に侵入する」ことに例えて説明します。

```
① 攻撃者が無料で普通のアカウントを作成
   （= 建物の見学者として入館証をもらう）
        ↓
② 自分のリポジトリを作成
   （= 建物内の荷物置き場を借りる）
        ↓
③ 悪意のある「パッチ」を2回送りつける
   （= 特殊な荷物をわざと2回搬入して、警備システムを混乱させる）
        ↓
④ 混乱した処理の隙に、実行可能なファイルを
   Gitフックの場所に置くことができてしまう
   （= 混乱に乗じて、マスターキーを鍵置き場に隠す）
        ↓
⑤ Gitがインデックスを更新する際に
   そのフックが自動実行される！
   （= 次に建物のシステムが起動したとき、隠したマスターキーが使われる）
        ↓
⑥ 攻撃者がサーバー上で好きなコマンドを実行できる
   （= 建物全体を自由に動き回れる状態に）
```

### 🛠️ 技術的な詳細（もう少し詳しく）

問題があった場所は `POST /api/v1/repos/{owner}/{repo}/diffpatch` というAPI（プログラム同士が会話する窓口）です。

1. このAPIは「パッチを適用する」機能を持っています
2. パッチ処理に**共有の一時クローン（仮の作業場所）** を使っていました
3. この一時クローンが「**ベアリポジトリ（bare repository）**」という特殊な形式だったことが問題でした

> 📌 **ベアリポジトリとは？**  
> 通常のGitリポジトリは「作業フォルダ」と「管理フォルダ(.git)」が分かれています。しかしベアリポジトリは「管理フォルダだけ」の構造で、**ルート（一番上の階層）がそのままGitの管理ディレクトリ**になります。

4. 同じパッチを**2回**送ることで「add/add衝突（競合）」が発生します
5. Git 2.32以降の「三方向マージ（3-way fallback）」機能が発動し、ファイルが意図しない場所（`hooks/post-index-change`）に書き込まれます
6. この場所こそが**Gitフックのディレクトリ**！→ 自動実行される

### 😮 巧妙な点

- 攻撃の証拠となる「外部への通信」が不要
- コマンドの実行結果をGitオブジェクト（Gitの仕組み自体）に格納して取り出す
- 攻撃ツール（PoC）も既に公開済み

## なぜ重要なのか

### 🚨 深刻度が高い理由

**1. 攻撃のハードルが低すぎる**

```
必要なもの：
✅ 無料でアカウントを作れるGiteaサーバーへのアクセス
✅ それだけ！（事前の特別な権限は不要）
```

**2. 被害の範囲が広い**

成功した場合、攻撃者が手に入れられるもの：

| 取得できる情報・権限 | 具体例 |
|-------------------|--------|
| アプリケーションの秘密情報 | APIキー、暗号化キー |
| データベースの情報 | ユーザーデータ、パスワード |
| OAuth認証情報 | GoogleやGitHubとの連携情報 |
| 内部ネットワークへのアクセス | 社内システムへの侵入 |
| 全リポジトリの内容 | 全ソースコードの閲覧・改ざん |

**3. 公開されたPoC（攻撃実証コード）**

修正パッチと同時に攻撃方法の証拠コードも公開されてしまっているため、**技術的な知識が少ない攻撃者でも悪用できる**可能性があります。

**4. 変更履歴への隠れ方が問題**

修正がリリースノートの「SECURITY（セキュリティ）」欄ではなく「**MISC（その他）**」に「コードのリファクタリング」として記載されていたため、管理者が気づきにくい状況でした。

## 対策・今後の展望

### ✅ 今すぐやるべきこと

#### 最優先：アップデート
```
Gitea 1.27.1 以上にアップグレードする
→ これが唯一の完全な解決策
```

Giteaクラウド版を使っている場合は自動的にアップデートされています。

#### アップデートが難しい場合の一時的な対策

```
⚠️ 注意：これらは「応急処置」であり、完全な修正ではありません

1. 新規ユーザー登録を無効化する
   → 外部の攻撃者によるアカウント作成を防げる
   → ただし！既存のユーザーによる攻撃は防げない

2. リポジトリへの書き込み権限を最小限にする
   → 本当に必要なユーザーだけに絞る
```

### 🔧 Giteaが実施した技術的な修正

問題の根本原因だった「**一時クローンのベアリポジトリ形式**」を、通常の「**ノンベアリポジトリ**」に変更しました。これにより、`hooks/`ディレクトリへの意図しない書き込みが防がれます。

## 用語解説

| 用語 | 読み方 | 説明 |
|------|--------|------|
| **Gitea** | ギッティア | 自分のサーバーで動かせるGitホスティングサービス |
| **RCE** | アールシーイー | Remote Code Execution（遠隔コード実行）。外部から自由にサーバーコマンドを実行できる最も危険な脆弱性 |
| **CVE** | シーブイイー | Common Vulnerabilities and Exposures。脆弱性に付けられる世界共通の識別番号 |
| **CVSS** | シーブイエスエス | 脆弱性の深刻度を0〜10で表すスコア。9.8は「緊急レベル」 |
| **Gitフック** | ギットフック | Gitの操作に連動して自動実行されるプログラム |
| **ベアリポジトリ** | ベアリポジトリ | 作業フォルダを持たないGitリポジトリ。管理データだけの特殊形式 |
| **パッチ** | パッチ | プログラムの変更差分を記録したファイル |
| **PoC** | ピーオーシー | Proof of Concept。脆弱性が実際に悪用できることを証明するためのサンプルコード |
| **三方向マージ** | さんほうこうマージ | 2つの変更が衝突した際に自動解決を試みるGitの機能 |
| **API** | エーピーアイ | プログラム同士が通信するための窓口・インターフェース |
| **シェルコマンド** | シェルコマンド | OSに直接命令を送るテキスト形式の指示 |
| **OAuth** | オーオース | 「Googleでログイン」などの外部サービス連携に使う認証の仕組み |
