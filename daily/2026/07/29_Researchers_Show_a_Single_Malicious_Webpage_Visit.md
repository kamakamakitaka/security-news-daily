# 悪意あるウェブページを1回見るだけでTorブラウザが乗っ取られる脆弱性が発見された

**元記事**: [Researchers Show a Single Malicious Webpage Visit Can Compromise Tor Browser](https://inl03.netline.com/ltr6/?_m=3n.009a.4042.sp0ao46r89.33j2)
**解説日**: 2025年7月29日

---

## 背景知識

このニュースを理解するために、いくつかの基本的な概念を押さえておきましょう。

### 🦊 Firefoxとは？
Mozillaという非営利団体が開発している、世界中で広く使われているウェブブラウザです。ChromeやEdgeと並ぶ有名なブラウザのひとつです。

### 🧅 Tor（トーア）ブラウザとは？
Torブラウザは「匿名性」を重視した特殊なブラウザです。誰がどのサイトを見ているかをわかりにくくするために使われます。実はこのTorブラウザ、**Firefoxをベースに作られています**。なので、Firefoxに脆弱性（バグ）があると、Torブラウザにも影響が出ます。

### ⚡ JIT（ジャストインタイム）コンパイラとは？
ブラウザがJavaScript（ウェブサイトを動かすプログラム言語）を実行するとき、**よく使われる処理を高速化するために「機械語（コンピュータが直接理解できる命令）」に変換する仕組み**です。料理に例えると、「毎回レシピを見ながら作るのではなく、よく作る料理は手順を丸暗記する」ようなイメージです。速くなる代わりに、変換の際に間違いがあると危険なことが起きます。

### 🔒 サンドボックスとは？
ブラウザの中で動くプログラムを「箱の中」に閉じ込めて、パソコン全体に悪影響を与えないようにする安全機能です。遊び場（サンドボックス＝砂場）の中で遊んでいる間は外に出られない、というイメージです。

### 🛡️ CVEとは？
「Common Vulnerabilities and Exposures」の略で、**発見されたセキュリティの脆弱性に付けられる番号**です。例えば「CVE-2026-10702」のように表記され、世界共通で管理されています。

---

## 何が起きたのか

セキュリティ研究企業「**Nebula Security**」が、Firefoxに存在していた深刻な脆弱性（**CVE-2026-10702**）を発見・公表しました。

この脆弱性の最も怖い点は：

> **🚨 仕掛けられた悪意あるウェブページを「見るだけ」で攻撃が成立する**

ということです。

Nebula SecurityのCEO、エテン・ゾウ氏はこう述べています。
> 「特別な設定も、追加のユーザー操作も必要ありません。悪意あるウェブページを訪問するだけで発動します」

この脆弱性は **Firefox 147〜151.0.2** に存在し、**Firefox 151.0.3** で修正されました。Torブラウザも、脆弱なバージョンのFirefoxを組み込んでいたものはすべて影響を受けます。

さらに研究者たちは、この脆弱性を**「IonStack（アイオンスタック）」**という2段階の攻撃チェーンの「第1段階」として活用しました。**Android 17を搭載したARM64端末**（スマートフォン向け）では、ブラウザの乗っ取りから最終的にデバイスの**root権限（最高管理者権限）の奪取**まで可能であることが示されています。

## 技術的な詳細

少し難しいですが、できるだけわかりやすく解説します。

### 🐛 バグの原因：「読むだけ」のはずが「書き換え」も起きていた

Firefoxの中に `MObjectToIterator`（エムオブジェクトトゥイテレータ）という処理があります。これは「JavaScriptのオブジェクトを繰り返し処理できる形に変換する」操作です。

問題は、この処理が**メモリ（データを一時的に保存する場所）を書き換える可能性があるのに、JITコンパイラが「読むだけの安全な処理」として誤って認識していた**ことです。

図で表すと：

```
【本来の認識】 MObjectToIterator → 「読み取り専用」✅（安全だと思っていた）
【実際の動作】 MObjectToIterator → 「メモリを書き換えることもある」⚠️（危険！）
```

### 📦 「古いアドレス」を使い回してしまう問題

JITコンパイラには**「GVN（グローバル値番号付け）」**という最適化機能があります。これは「同じ計算は2回しなくていい、1回目の結果を使い回そう」という省エネ機能です。

ところが今回のバグでは：

1. JITが「このメモリのアドレスは変わらない（読み取り専用だから）」と誤判断
2. その間に実際にはメモリが書き換えられ、**古いアドレス（すでに無効）**が残る
3. JITがその**無効な古いアドレス**を「有効なもの」として使い続ける

本の棚に例えると：「本の場所が変わったのに、古い地図を信じてその場所に行ってしまう」ようなイメージです。

### 🔓 攻撃者はこれをどう悪用したか

Nebula Securityが公開した攻撃コードは、以下のステップで攻撃を行います：

| ステップ | 内容 | わかりやすく言うと |
|---------|------|----------------|
| ① | 解放されたメモリ領域を再確保 | 「使い終わった部屋」を不正に占拠 |
| ② | 隠しクラスポインタをリーク（漏洩） | 「建物の設計図」を盗み見る |
| ③ | 偽のオブジェクトを作成 | 「偽の鍵」を作る |
| ④ | `Uint8Array`を改ざんして任意メモリ読み書き | 「どの部屋にも入れる万能鍵」を手に入れる |
| ⑤（Android限定） | メモリ保護を変更し、WebAssembly関数をシェルコードにリダイレクト | 「セキュリティカメラをハック」してそのまま侵入 |

### 🔗 第2段階：GhostLock（ゴーストロック）

**CVE-2026-43499**、通称「**GhostLock**」はLinuxカーネル（OSの核心部分）の別の脆弱性です。

- **第1段階（CVE-2026-10702）**：ブラウザの「サンドボックスの箱」から脱出する
- **第2段階（GhostLock）**：Androidデバイスの**root権限**（最高管理者権限）を奪う

この2段階コンボにより、悪意あるページを見ただけでスマホが完全に乗っ取られる可能性があります。

## なぜ重要なのか

### 📊 影響の大きさ

- **Firefoxのユーザー数は世界で数億人規模**であり、バージョン147〜151.0.2を使っていたすべてのユーザーが対象
- **Torブラウザ**も影響を受けるため、プライバシーを重視して匿名ブラウジングをしていたユーザーも危険にさらされた
- **「見るだけで感染」**という攻撃の手軽さから、フィッシング攻撃（偽サイトへの誘導）などに悪用されやすい

### 🌐 現時点での状況

記事執筆時点（2026年7月28日）では、**実際にこの脆弱性が悪用された事例は確認されていません**。しかし、攻撃コードが公開されているため、今後悪用される可能性は否定できません。

### 💻 対象となるプラットフォーム

今回公開されたコードは主に**Android 17 / ARM64**向けですが、研究者によると「バグ自体はARM専用ではなく、x86（一般的なPC）でも動作する」とのことで、**PCユーザーも油断は禁物**です。

## 対策・今後の展望

### ✅ 今すぐやること

#### Firefox ユーザー
```
Firefox メニュー → ヘルプ → Firefoxについて → 自動更新を確認
```
**Firefox 151.0.3以降**にアップデートすることで、ブラウザ側の脆弱性は解消されます。

#### Torブラウザ ユーザー
- Torブラウザの**最新バージョンへのアップデート**が必要です
- Torプロジェクトの公式サイト（https://www.torproject.org）から最新版を確認してください

#### Firefox ESR（法人・組織向け長期サポート版）ユーザー
- **Firefox ESR 140.12**にはこの問題のあるコードが存在しないことが確認されています。影響なしの可能性が高いです。

### ⚠️ 注意！Firefoxを更新しても完全ではない

**GhostLock（CVE-2026-43499）はFirefoxのアップデートでは修正されません。** これはLinuxカーネル側の問題であり、AndroidのOSアップデートが別途必要になります。Androidデバイスをお持ちの方は、**OSアップデートも忘れずに確認**しましょう。

### 🔮 今後の展望

- MozillaはFirefox 151.0.3でブラウザ側の問題を修正済み
- Linuxカーネルのfutex（フューテックス）脆弱性（GhostLock）は別途対応が必要
- Nebula Securityはx86版の完全な攻撃チェーンもまだ開発中とのことで、今後の情報に注目が必要

## 過去記事との関連

今回の記事は単独の新しいニュースとなります。ただし、ブラウザのJIT脆弱性を使った攻撃は過去にも繰り返し問題になっており、「**ブラウザを最新版に保つことが最も重要なセキュリティ対策のひとつ**」という教訓は変わりません。特に今回のように「見るだけで感染」するタイプの攻撃は、2024〜2025年にかけてChromeやSafariでも類似の事例が報告されており、JITコンパイラの安全性はブラウザ開発における長年の課題となっています。

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **CVE** | シーブイイー | セキュリティ脆弱性に付けられる世界共通の管理番号 |
| **Tor Browser** | トーアブラウザ | 匿名通信を実現するFirefoxベースの特殊ブラウザ |
| **JIT コンパイラ** | ジャストインタイムコンパイラ | よく使われる処理を高速化するために機械語に変換する仕組み |
| **サンドボックス** | サンドボックス | プログラムを「箱の中」に閉じ込めて安全を保つ技術 |
| **レンダラープロセス** | レンダラープロセス | ウェブページを描画・表示するブラウザの処理部分 |
| **任意コード実行** | にんいコードじっこう | 攻撃者が好きな命令をパソコンに実行させられる状態（最も危険な種類の脆弱性） |
| **GVN** | ジーブイエヌ | 同じ計算を繰り返さないようにするJITの最適化機能 |
| **root権限** | ルートけんげん | OSのすべてを操作できる最高管理者の権限 |
| **ARM64** | エーアールエムろくよん | スマートフォンなどに使われるCPUの種類 |
| **WebAssembly** | ウェブアッセンブリ | ブラウザ上で高速に動くプログラム形式 |
| **futex** | フューテックス | Linuxカーネルの同期処理機能（今回GhostLockに悪用された） |
| **Firefox ESR** | ファイアフォックスイーエスアール | 企業・組織向けの長期サポート版Firefox |
| **シェルコード** | シェルコード | 攻撃者が実行させたい悪意ある機械語命令のかたまり |
