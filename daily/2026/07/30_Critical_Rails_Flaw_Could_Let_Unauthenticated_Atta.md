# Railsフレームワークの重大欠陥：画像アップロードからサーバーの秘密情報が丸見えに

**元記事**: [Critical Rails Flaw Could Let Unauthenticated Attackers Read Server Files via Image Uploads](https://inl03.netline.com/ltr6/?_m=3n.009a.4043.sp0ao46r89.33la)
**解説日**: 2026年7月31日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### Ruby on Rails（ルビー・オン・レールズ）とは？
「Rails」とは、**Webサービスやアプリを作るための人気のフレームワーク（開発の土台となる仕組み）** です。たとえば、TwitterやGitHubなど世界中の多くのWebサービスがRailsで作られてきました。日本でもたくさんのサービスに使われています。

### Active Storage（アクティブ・ストレージ）とは？
Railsに組み込まれている、**ファイルアップロードを管理する仕組み**です。ユーザーが写真や動画をアップロードするとき、裏側でActive Storageが動いています。

### libvips（リブビップス）とは？
アップロードされた画像を処理する（リサイズしたりサムネイルを作ったりする）**画像処理ライブラリ（ソフトウェア部品）** です。Rails 7.0以降でデフォルト（標準）として採用されています。

### サーバーの「秘密情報」って何？
Webサーバーには、動作に必要な大切な情報（パスワードや認証キーなど）が保存されています。これが外部に漏れると、**サーバーを乗っ取られたり、データベースに不正アクセスされたりする可能性**があります。鍵のかかった金庫の暗証番号が漏れるようなイメージです。

---

## 何が起きたのか

Ruby on Railsに**深刻なセキュリティ上の欠陥（脆弱性）**が発見され、修正パッチ（修正プログラム）がリリースされました。

この脆弱性（CVE-2026-66066）は**危険度スコア9.5（10点満点）** という非常に高いレベルに分類されています。

### 問題の核心をひと言で言うと…

> **「細工された画像ファイルをアップロードするだけで、ログインしていない攻撃者でもサーバー内のファイルを読み取れてしまう」**

つまり、サービスの会員でもない完全な部外者が、画像をアップロードする機能を悪用して、サーバーの中身を覗き見できてしまうということです。

### 影響を受けるバージョン
| バージョン | 影響 |
|---|---|
| Rails 7.0.0 〜 7.2.3.1 | ✅ 影響あり |
| Rails 8.0.0 〜 8.0.5 | ✅ 影響あり |
| Rails 8.1.0 〜 8.1.3 | ✅ 影響あり |
| Rails 6.x（libvipsを使っている場合のみ） | ⚠️ 条件付きで影響あり |

## 技術的な詳細

### 攻撃の仕組みをわかりやすく解説

**🏠 例え話で考えてみましょう**

あなたのマンションには「郵便物受付窓口」があります（＝画像アップロード機能）。住民以外でも荷物を預けられますが、受付係は荷物を機械的にチェックするだけです。

ある日、悪意ある人が「普通の荷物に見える、でも実は危険な特殊装置」を持ち込みます。受付係の機械（libvips）がその装置を処理しようとした瞬間、装置が起動してマンションの管理室（サーバー内部）の扉を開けてしまう…というイメージです。

### 実際の仕組みはこう

```
①攻撃者が「細工した特殊な画像ファイル」を作成
    ↓
②画像をアップロードすると、libvipsが処理を開始
    ↓
③libvipsには「安全でない（untrusted）」処理モードがあった
    ↓
④Active StorageがそのモードをブロックしていなかったⅡ
    ↓
⑤サーバー内のファイルが読み取られてしまう！
```

### 漏れてしまう情報の例
- 🔑 `secret_key_base`（Railsの最も重要な暗号鍵）
- 🗝️ Railsマスターキー
- 🗄️ データベースのパスワード
- ☁️ クラウドストレージの認証情報
- 🔌 外部サービスのAPIトークン

### さらに怖いこと：RCE（遠隔コード実行）の可能性

これらの秘密情報を入手した攻撃者は、さらに**RCE（Remote Code Execution＝サーバー上で好きなプログラムを実行できる状態）** に発展させられる可能性があります。

銀行の金庫の鍵を手に入れた上に、さらに金庫の中身を自由に操作できるようになるイメージです。

### 実証コードも公開されてしまった

2026年7月29日17:30(UTC)以降、GitHubに「この攻撃を再現できるコード」が第三者によって公開されました（The Hacker Newsは独自検証はしていないと注記しています）。こうした公開は、攻撃者が実際に悪用するハードルを大きく下げるため、**早急な対応がより一層重要**になっています。

## なぜ重要なのか

### 影響の大きさ

1. **ログイン不要で攻撃できる**
   通常の攻撃は「まずアカウントを乗っ取る」という手順が必要です。しかしこの攻撃は**完全な部外者でも実行可能**です。

2. **Railsは世界中で使われている**
   Rails 7.0以降が対象なので、世界中の非常に多くのWebサービスが潜在的に影響を受けます。

3. **「画像アップロード機能がある＝危険」という状況**
   普通のSNSや投稿サービスには当たり前にある機能が攻撃の入口になってしまいます。

4. **危険度スコア9.5/10**
   セキュリティの評価基準（CVSS）で10点満点中9.5という極めて高いスコアです。

## 対策・今後の展望

### 🛡️ 運営者・開発者がすべきこと

#### ステップ1：Railsを最新版にアップデート
| 現在のバージョン | 更新先 |
|---|---|
| Rails 7.2.x | **7.2.3.2** 以降 |
| Rails 8.0.x | **8.0.5.1** 以降 |
| Rails 8.1.x | **8.1.3.1** 以降 |

> ⚠️ Rails 7.1以前はサポート終了のため、修正パッチが出ません。**Rails 7.2.3.2以降への移行が必須**です。

#### ステップ2：ライブラリもアップデート
- libvips → **バージョン8.13以降**
- ruby-vips → **バージョン2.2.1以降**

#### ステップ3：秘密情報をすべてローテーション（更新）する
もし既に攻撃されていた可能性がある場合、以下をすべて変更する必要があります：
- `secret_key_base`（Railsの暗号鍵）
- マスターキーとその復号された認証情報
- データベースのパスワード
- クラウドストレージのサービスキー
- 外部サービスのAPIトークン

#### すぐにアップデートできない場合の一時対応
```
環境変数 VIPS_BLOCK_UNTRUSTED を設定する
（libvips 8.13以降が必要）
```

### ✅ 影響を受けない場合
- **MiniMagick**（libvipsの代わりの画像処理ソフト）を使っている場合は、この特定の攻撃パスの影響を受けません。

### 発見者への謝辞
この脆弱性は、**EthiackのAndré Baptista氏、Bruno Mendes氏、Rafael Castilho氏** と、**GMO Flatt SecurityのRyotaK氏** が独立して発見・報告しました。（GMO Flatt Securityは日本の会社です！）

## 過去記事との関連

以前、「**ロシアのハッカーがMicrosoftのWebメールの欠陥を悪用して、パスワードを変えても侵入し続ける**」という事件を解説しました。

今回のRailsの脆弱性とは直接の関連はありませんが、**共通する重要な教訓**があります：

> **「一度秘密情報が漏れたら、パスワードや認証キーを変えるだけでは不十分な場合がある」**

前回のMicrosoftの件では、パスワードを変えてもハッカーがアクセスを維持し続けました。今回のRailsの件でも、もし秘密鍵（`secret_key_base`）が盗まれると、それを使った攻撃を防ぐには**鍵そのものを更新（ローテーション）する**必要があります。

どちらのケースも、「侵害された可能性がある情報はすべて無効化・更新する」という対応の重要性を教えてくれています。

## 用語解説

| 用語 | 解説 |
|---|---|
| **Ruby on Rails（Rails）** | Webアプリを効率よく作るための開発フレームワーク（土台となる仕組み） |
| **Active Storage** | Railsに組み込まれたファイルアップロード管理機能 |
| **libvips** | 高速な画像処理ライブラリ（画像をリサイズ・変換するソフト部品） |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアのセキュリティ上の欠陥・弱点 |
| **CVE** | 脆弱性を識別・管理するための番号（世界共通の識別子） |
| **CVSS スコア** | 脆弱性の危険度を0〜10で数値化した評価指標 |
| **RCE（遠隔コード実行）** | 攻撃者がリモートからサーバー上で任意のプログラムを実行できる最も危険な攻撃 |
| **secret_key_base** | Railsアプリの最重要暗号鍵。セッション情報の署名などに使われる |
| **APIトークン** | 外部サービスにアクセスするためのパスワードのようなもの |
| **PoC（Proof of Concept）** | 攻撃が実際に機能することを証明するための実証コード |
| **パッチ** | セキュリティ上の問題を修正するための更新プログラム |
| **ローテーション** | パスワードや認証キーを新しいものに更新すること |
| **MiniMagick** | libvipsの代替となる別の画像処理ライブラリ |
| **フレームワーク** | ソフトウェア開発を効率化するための共通の土台・枠組み |
