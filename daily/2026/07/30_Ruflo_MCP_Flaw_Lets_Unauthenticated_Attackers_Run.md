# Rufloの重大欠陥：認証なしでコマンド実行＆AIの記憶を汚染できる脆弱性が発覚

**元記事**: [Ruflo MCP Flaw Lets Unauthenticated Attackers Run Commands and Poison AI Memory](https://inl03.netline.com/ltr6/?_m=3n.009a.4043.sp0ao46r89.33lg)
**解説日**: 2026-07-30

---

## 背景知識

このニュースを理解するために、いくつかのキーワードを先に押さえておきましょう。

### 🤖 AIエージェントって何？
ChatGPTのようなAIに「自分で考えて作業を実行する」能力を持たせたものを「AIエージェント」と言います。たとえば「このコードを書いて、テストして、サーバーにデプロイして」という複雑な作業を自動でこなしてくれるイメージです。

### 🧰 Ruflo（ルフロ）とは？
Rufloは、Claude（Anthropic社製AI）やCodex（OpenAI社製AI）といった有名なAIを組み合わせて、複数のAIエージェントをチームのように動かせるオープンソース（無料公開）のツールです。GitHubという開発者向けサイトで**66,500以上のスター（お気に入り登録）**を集めるほどの人気プロジェクトです。

### 🔌 MCP（Model Context Protocol）とは？
AIツール同士が「会話」するための共通の通信ルールのようなものです。「コマンドを実行して」「データベースを読んで」といった指示をAIに伝えるための窓口だと思ってください。

### 🚪 「認証なし」が何で危険なの？
自宅の玄関を想像してください。普通は鍵（パスワードや認証）がかかっていて、知らない人は入れません。でも「認証なし」というのは、その玄関に**鍵がついていない**状態。誰でも自由に入れてしまいます。

## 何が起きたのか

Noma Securityのセキュリティ研究チーム「Noma Labs」が、Rufloに**最高レベルの深刻度を持つ脆弱性（欠陥）**を発見しました。

- **脆弱性ID**: CVE-2026-59726（通称：**RufRoot**）
- **深刻度スコア**: **10.0満点中10.0**（これ以上ない最悪の評価）
- **影響を受けるバージョン**: バージョン3.16.3より前のすべて

ひとことで言うと：

> 🚨 **インターネットから誰でも（パスワードなしで）Rufloのサーバーに侵入し、好き放題コマンドを実行できた**

さらに悪いことに、侵入後は…
- AIが使うAPIキー（課金情報を含む「合言葉」）を盗める
- ユーザーとAIの会話内容をすべて読み取れる
- **AIの「記憶」に嘘の情報を書き込み、将来の回答を操作できる**

この「AIの記憶を汚染する」という攻撃は特に新しく危険な手口です。

---

## 技術的な詳細

### なぜこんな欠陥が生まれたの？

Rufloを動かすための設定ファイル（`docker-compose.yml`）に問題がありました。

```
【問題の設定】
ポート番号3001 → 0.0.0.0（全てのネットワークに公開）
```

**ポート**とは、建物に例えると「何番の窓口」かを示す番号です。`0.0.0.0`というのは「どこからでもアクセスOK」という意味。つまり、世界中のどこからでも3001番の窓口に自由にアクセスできる状態になっていました。

しかもその窓口には、233種類もの強力なツールが鍵なしで使える状態で並んでいました：

| ツールの例 | できること |
|---|---|
| `terminal_execute` | サーバーでコマンドを実行 |
| データベース操作 | 全会話データの読み書き |
| メモリストレージ | AIの記憶の読み書き |
| エージェント管理 | AIエージェントの起動・操作 |

### 攻撃の流れをわかりやすく

```
攻撃者のパソコン
    ↓
「ポート3001に、たった1回のHTTPリクエストを送る」
    ↓
Rufloサーバーに完全侵入
    ↓
① APIキーを盗む（お金を使い放題に）
② 全会話を読む（プライバシー侵害）
③ AIの記憶に悪意ある情報を書き込む（以後、全ユーザーへの回答を操作）
④ バックドア（裏口）を設置（後からいつでも再侵入できる）
```

### 「AIの記憶汚染」が特に怖い理由

たとえて言うなら、学校の図書館の参考書に**誰かが嘘の情報をこっそり書き込んだ**ようなもの。その本を参考にして宿題をする生徒全員が、間違った知識を持ってしまいます。

AIが将来のすべてのユーザーに対して「汚染された知識」をもとに回答し続けるため、攻撃者が既にいなくなった後でも被害が続く恐れがあります。

## なぜ重要なのか

### 📊 影響の大きさ

- GitHub上に66,500以上のスターを持つ人気プロジェクトなので、**世界中の多くの開発者・企業が使っている**可能性があります
- 深刻度スコア**10.0**は、セキュリティ評価で最も高い（最悪の）スコアです
- 「認証なし」なので、攻撃に高度な技術は不要。**誰でも悪用できる**

### 🆕 「AI特有」の新しい脅威

これまでのサイバー攻撃は「データを盗む」「サービスを止める」が主でしたが、今回は**「AIの思考・回答そのものを操作する」**という新しい次元の攻撃です。AIが社会のインフラに組み込まれていく中で、こうした攻撃の危険性はこれからますます高まります。

## 対策・今後の展望

### ✅ 開発者側の対応（すでに完了）

脆弱性が報告された**2026年6月30日の翌日（24時間以内）**に、開発者のReuven Cohen氏がパッチ（修正プログラム）をリリースしました。対応の速さは高く評価されています。

修正内容：
- MCPブリッジが**ループバック（自分自身）にのみ接続**するよう変更（外部から見えなくなった）
- `terminal_execute`に**認証チェック**を追加
- MongoDBデータベースに**認証を有効化**

### ⚠️ 今も旧バージョンを使っている人は今すぐ対応を！

| 対策 | 具体的な内容 |
|---|---|
| **バージョン更新** | Rufloをv3.16.3以上に更新する |
| **ポートを閉じる** | ファイアウォールでポート3001と27017を遮断 |
| **APIキーを変更** | LLMプロバイダーのAPIキーをすべて再発行 |
| **記憶データを確認** | AgentDBのパターンストアに不正なデータがないか確認 |
| **DB改ざん確認** | MongoDBに不審なデータがないか調査 |

## 過去記事との関連

以前、**Railsフレームワークの重大欠陥**（画像アップロードからサーバーの秘密情報が丸見えになる問題）について解説しました。

今回のRufloの欠陥と共通しているのは、どちらも**「本来守られているはずのサーバーへの入口が、意図せず外部に開放されていた」**という点です。

- Railsの欠陥 → 画像経由でファイルが読まれる
- Rufloの欠陥 → ネットワーク経由でコマンドが実行される

また、今回はAIシステムが対象という点で**一歩進んだ脅威**と言えます。単なる情報漏えいにとどまらず、「AIそのものを武器に変える」「AIの回答を操る」という、従来のセキュリティの常識では語れない攻撃が現実のものになってきています。

## 用語解説

| 用語 | 意味 |
|---|---|
| **脆弱性（ぜいじゃくせい）** | ソフトウェアのバグや設計ミスによる「セキュリティ上の欠陥」 |
| **CVE** | 脆弱性に付けられる世界共通のID番号（"Common Vulnerabilities and Exposures"の略） |
| **CVSSスコア** | 脆弱性の深刻さを0〜10で表す点数。10が最悪 |
| **MCP（Model Context Protocol）** | AIツール間の通信ルール。AIへの指示を伝える窓口 |
| **ポート** | ネットワーク通信の「窓口番号」。建物の入り口の番号のようなもの |
| **リモートコード実行（RCE）** | 遠くにある別のコンピューターでコマンド（命令）を実行できる攻撃 |
| **APIキー** | AIサービスなどを利用するための「合言葉」。盗まれると不正利用される |
| **バックドア** | 攻撃者が後からこっそり侵入するために設置する「裏口」 |
| **AIメモリポイズニング** | AIの記憶（学習データ）に嘘・悪意ある情報を書き込む攻撃 |
| **ループバックインターフェース** | 自分自身のコンピューターにのみ通信を許可する設定。外部から見えない |
| **オープンソース** | プログラムのソースコードが一般公開されているソフトウェア |
| **Docker / docker-compose** | アプリをまとめて動かすための仮想環境ツール。設定ファイルで動作を決める |

> 💡 **まとめると…**
> 人気AIツール「Ruflo」に、パスワードなしで誰でもサーバーを乗っ取れる最高レベルの欠陥が見つかりました。特に「AIの記憶を書き換えて、将来の全ユーザーへの回答を操る」という新しい攻撃が可能だった点が衝撃的です。すでに修正済みですが、旧バージョンを使っている方は今すぐ対応が必要です。AIが社会に広まるほど、AIそのものを狙ったサイバー攻撃も増えていくことを示す重要な事例です。
