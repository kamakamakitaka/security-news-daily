# VMwareの重大欠陥3つ発覚：認証突破・コード実行・VM脱出が可能に

**元記事**: [Three Critical VMware Flaws Allow Auth Bypass, Code Execution, and VM Escape](https://inl03.netline.com/ltr6/?_m=3n.009a.4043.sp0ao46r89.33lm)
**解説日**: 2026年7月31日

---

## 背景知識

まず、今回の記事を理解するために必要な「VMware」と「仮想化」の仕組みを説明しましょう。

### 🖥️ 仮想化って何？

皆さんのパソコンには「Windows」や「macOS」といったOSが入っていますよね。**仮想化**とは、1台の物理的なコンピュータの中に、あたかも複数台のコンピュータがあるかのように見せる技術です。

> **例え話**: 1軒の大きな家を、壁で仕切って複数の部屋（アパート）に分けるイメージです。各部屋（仮想マシン）はお互いに干渉しないように設計されています。

### 🏢 VMwareとは？

**VMware（ヴイエムウェア）** は、この「仮想化」を実現するソフトウェアを作っている会社（現在はBroadcomが買収）です。企業のサーバー管理に広く使われており、世界中の大企業・病院・銀行などが利用しています。

今回問題になった主な製品は以下の通りです：

| 製品名 | 役割 |
|--------|------|
| **VMware ESX（ESXi）** | 物理サーバー上で動く仮想化の「土台」となるソフト |
| **VMware vCenter** | 複数のESXiサーバーを一元管理するコントロールパネル |
| **VMware Workstation** | 個人のPCで仮想マシンを動かすソフト |
| **VMware Fusion** | Mac向けのWorkstationのようなソフト |

### 🔒 認証とは？

**認証（Authentication）** とは「あなたは誰ですか？」を確認する仕組みです。IDとパスワードを入力してログインするのが典型例です。

## 何が起きたのか

Broadcom社が、VMwareの主要製品に**合計5つの脆弱性（セキュリティの穴）** を発見・修正しました。そのうち**3つは「クリティカル（緊急）」** という最も深刻なレベルに分類されています。

### 発見された脆弱性の一覧

| 番号 | CVE番号 | 深刻度スコア | 内容 |
|------|---------|------------|------|
| ① | CVE-2026-59309 | 🔴 9.8/10 | vCenterの認証回避 |
| ② | CVE-2026-59310 | 🔴 9.8/10 | vCenterでの任意コード実行 |
| ③ | CVE-2026-47876 | 🔴 9.3/10 | VM脱出（ホストへのコード実行） |
| ④ | CVE-2026-41703 | 🟠 7.6/10 | 情報漏洩・サービス妨害 |
| ⑤ | CVE-2026-41709 | 🟡 2.7/10 | ログ記録の不備 |

> **CVSSスコアとは？**: 脆弱性の深刻さを0〜10点で表した数値です。10点に近いほど危険で、9点以上は「今すぐ対処必要」レベルです。

## 技術的な詳細

### 🚪 ①認証回避（CVE-2026-59309）スコア: 9.8

> **例え話**: 鍵がかかっているはずのドアを、鍵なしでそのまま開けられてしまうようなバグです。

**vCenter**（サーバー管理の司令塔）に、ネットワーク経由でアクセスできる攻撃者が、**パスワードなしでシステムに侵入できる**脆弱性です。

本来であれば「ID・パスワードを知っている人しか入れない」はずが、この欠陥を使うと**認証を丸ごとスキップ**できてしまいます。

---

### 📂 ②ディレクトリトラバーサル（CVE-2026-59310）スコア: 9.8

> **例え話**: 「1階のお部屋しか入れないはずのゲスト」が、特殊な方法で「立入禁止の地下室」にも入れてしまうようなバグです。

**ディレクトリトラバーサル**とは、ファイルのパス（場所）を巧みに操作して、本来アクセスできないはずのフォルダやファイルにたどり着く攻撃手法です。

この脆弱性を使うと、攻撃者はサーバー上で**任意のプログラムを実行（コード実行）** できてしまいます。つまりサーバーを乗っ取れるということです。

---

### 🏃 ③VM脱出（CVE-2026-47876）スコア: 9.3

これが今回最も技術的に興味深い脆弱性です。

> **例え話**: アパートの一室（仮想マシン）に住んでいる人が、壁をすり抜けて「建物全体の管理室（ホストサーバー）」に入り込んでしまうバグです。

仮想マシンは通常、**ホスト（土台となる本物のサーバー）から完全に隔離されている**はずです。しかし、`VMXNET3`という仮想ネットワークアダプタ（仮想マシンに仮想的なネットワーク接続を提供する部品）に「**境界外書き込み（Out-of-Bounds Write）**」という欠陥があります。

**境界外書き込みとは？**
コンピュータのメモリ（データを一時保存する場所）は、それぞれ決められた区画に分かれています。その「決められた区画の外」にデータを書き込んでしまうバグで、うまく利用されると攻撃者が**好きなプログラムを実行できる**状態になります。

仮想マシン内で管理者権限を持つ攻撃者が、この欠陥を使って**ホストサーバー上でコードを実行**できてしまいます。

---

### 📖 ④情報漏洩（CVE-2026-41703）スコア: 7.6

「**境界外読み取り（Out-of-Bounds Read）**」という欠陥で、読んではいけないメモリ領域のデータを読み取れてしまいます。パスワードや機密情報が漏れる可能性や、システムをダウンさせる（サービス妨害）可能性があります。

---

### 📝 ⑤ログ記録の不備（CVE-2026-41709）スコア: 2.7

管理者が特定の操作をしても、その記録（ログ）が残らない欠陥です。不正行為の証拠が消せてしまうため、内部不正やフォレンジック（デジタル証拠調査）の観点から問題です。

---

## なぜ重要なのか

### 🌍 影響範囲が非常に広い

VMwareの製品は、**世界中の企業・病院・銀行・政府機関**などで広く使われています。仮に攻撃者がこの脆弱性を悪用すると：

- 🏥 **病院** → 患者データの盗難・医療システムの停止
- 🏦 **銀行** → 金融情報の漏洩・不正送金
- 🏢 **企業** → 機密データの盗難・ランサムウェア（身代金要求型ウイルス）の被害

といった深刻な被害につながる可能性があります。

### ⚠️ 回避策（ワークアラウンド）が存在しない

通常、パッチ（修正プログラム）が適用できない場合の「応急処置」として回避策が提供されることがあります。しかし今回は**回避策なし**。つまり「パッチを当てる以外に守る方法がない」のです。

### ✅ 現時点での悪用は確認されていない

Broadcomは「現時点でこれらの脆弱性が実際に攻撃に使われた証拠はない」と述べています。ただし、「緊急変更」として**即時対応を求めています**。

## 対策・今後の展望

### ✅ 今すぐできる対策

**システム管理者向け**：

1. **パッチの即時適用** — Broadcomが提供している修正済みバージョンにアップデートする

| 対象製品 | 修正済みバージョン |
|----------|------------------|
| VMware vCenter 8.0 | 8.0 U3k |
| VMware Workstation | 26H1 |
| VMware Fusion | 26H1 |
| VMware ESXi (9.1系) | ESXi-9.1.0.0200-25557999 など |

2. **ネットワーク制限** — vCenterへのアクセスを信頼できるネットワークのみに限定する
3. **ログ監視の強化** — 不審なアクセスがないか監視を強化する

**一般ユーザー向け**：
- VMware Workstationを使っている場合は、**26H1にアップデート**することを確認してください

### 🔮 今後の展望

脆弱性が公開されると、悪意ある攻撃者がその情報を使って攻撃コードを作り始めます。過去の事例を見ると、公開から**数日〜数週間以内に実際の攻撃が始まること**が多いため、今すぐの対応が非常に重要です。

## 過去記事との関連

以前、**RailsフレームワークやRufloのMCP（AIツール）の重大欠陥**について解説しましたが、今回のVMwareの件と共通する重要なポイントがあります。

それは「**認証の回避（Auth Bypass）**」という攻撃手法です。Railsの欠陥でも「認証なしでサーバーのファイルが読める」という問題がありましたが、今回のVMwareでも同様に「認証を突破してシステムに侵入できる」脆弱性が含まれています。

また、Rufloの件では「AIの記憶を汚染する」という新しい攻撃手法が話題になりましたが、こうした**一見無害に見えるシステムの深部から攻撃が広がる**パターンは、今回の「VM脱出」とも共通する考え方です。仮想マシンという「隔離された空間」も、完全に安全とは言えないことが改めて示されました。

## 用語解説

| 用語 | 意味 |
|------|------|
| **VMware** | 仮想化ソフトウェアの大手メーカー（現在はBroadcomの傘下） |
| **仮想化** | 1台の物理サーバーを、複数台のコンピュータに見せる技術 |
| **仮想マシン（VM）** | 仮想化によって作られた「仮想のコンピュータ」 |
| **ホスト** | 仮想マシンを動かしている「本物の物理サーバー」 |
| **ESXi** | VMwareの仮想化を実現する基盤ソフトウェア |
| **vCenter** | 複数の仮想サーバーをまとめて管理するコントロールパネル |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアのセキュリティ上の欠陥・穴 |
| **認証回避（Auth Bypass）** | パスワードなどの認証を無効にして侵入する攻撃手法 |
| **ディレクトリトラバーサル** | ファイルのパスを操作して、本来アクセスできない場所に侵入する攻撃 |
| **VM脱出（VM Escape）** | 仮想マシンの隔離を破り、ホストサーバーに侵入する攻撃 |
| **境界外書き込み（Out-of-Bounds Write）** | メモリの決められた範囲の外にデータを書き込むバグ |
| **CVSSスコア** | 脆弱性の深刻さを0〜10点で表した国際的な指標 |
| **パッチ** | バグや脆弱性を修正するためのアップデートプログラム |
| **ランサムウェア** | データを暗号化して身代金を要求する悪意あるソフトウェア |
| **フォレンジック** | デジタル機器から証拠を調査・収集する技術 |
| **ワークアラウンド** | 根本的な修正ができない場合の「応急処置・回避策」 |
