# デバイスコードフィッシング：2026年最速で広がる脅威・6つの理由

**元記事**: [6 Reasons Why Device Code Phishing is the Fastest-Growing Threat of 2026](https://inl03.netline.com/ltr6/?_m=3n.009a.4044.sp0ao46r89.33m0)
**解説日**: 2025年7月

---

## 背景知識

まず、この記事を理解するために必要な「基本の仕組み」をおさえましょう。

### 🔑 ログインの「2つのステップ」とは？

私たちがWebサービスにログインするとき、実は**2つの別々のこと**が起きています。

1. **本人確認（認証）**: 「あなたは誰ですか？」→ パスワードや指紋で証明
2. **アクセス許可（認可）**: 「このアプリに情報を使わせていいですか？」→ 「許可する」ボタンを押す

これを管理する仕組みが **OAuth 2.0（オーオース）** というルールです。たとえば「Googleアカウントでログイン」ボタンを押したとき、裏側でこのOAuthが動いています。

### 📺 デバイスコードフローって何？

スマートテレビやゲーム機など、**キーボードがない機器**でNetflixやYouTubeにログインするとき、こんな経験はないですか？

```
画面に「ABC-1234」というコードが表示される
→ スマホやPCで「○○.com/activate」にアクセス
→ コードを入力して「許可する」を押す
→ テレビにログインできた！
```

これが **デバイスコードフロー** です。便利な仕組みですが、**この「コードを入力して許可する」という部分が攻撃に悪用されています**。

### 🎭 フィッシングとは？

**フィッシング（Phishing）** とは、本物そっくりの偽サイトや偽メールで、パスワードなどを騙し取る攻撃です。魚釣り（fishing）のように、餌で人を引っかけることから名前がついています。

### 🔐 MFA（多要素認証）とは？

パスワードだけでなく、**スマホへのSMSや認証アプリのコード**など、複数の方法で本人確認する仕組みです。「二段階認証」と言われることもあります。

## 何が起きたのか

### 急速に広がる新型攻撃

**デバイスコードフィッシング**という攻撃手法が、2026年に入って爆発的に増加しています。

時系列で見ると、その広がりの速さがよくわかります：

| 時期 | 出来事 |
|------|--------|
| 2020年 | 研究者がこの攻撃手法を最初に発見・報告 |
| 2024年 | **国家が関与するハッカー集団**（Storm-2372）が実際の攻撃に使い始める |
| 2025年 | ShinyHuntersというハッカー集団がSalesforceに大規模攻撃 |
| 2026年2月 | 「EvilTokens」という攻撃ツールキットが登場、一気に普及 |
| 2026年4月 | **1日に10〜15件の新しい攻撃キャンペーン**が確認される |
| 2026年4週間 | **700万件**もの攻撃をセキュリティ会社が検出 |

> 💡 **わかりやすく言うと**：研究者が「こんな攻撃が理論上できる」と発表してから4年後に国家レベルの攻撃に使われ、さらにその2年後には「誰でも買える攻撃ツール」になってしまった、ということです。

## 技術的な詳細

### 🎯 攻撃の手口：4ステップで理解しよう

```
【攻撃者】                    【被害者】

①攻撃者がデバイスコードを
　Microsoftから取得する
　（正規の手順で！）

②「あなたのアカウントを確認
　してください」といった
　フィッシングメールを送る
                              ③被害者がリンクをクリック
                              　「ABC-1234」というコードが
                              　表示される

                              ④被害者は本物のMicrosoftの
                              　ページ(aka.ms/devicelogin)に
                              　アクセスしてコードを入力
                              　→「許可する」を押す

⑤攻撃者のもとに
　「アクセストークン」が届く！
　→ 被害者のアカウントを
　　 自由に操作できる！
```

### 🚨 なぜMFA（二段階認証）が意味をなさないのか？

ここが最も怖いポイントです。

**通常のフィッシング攻撃の場合：**
- パスワードを盗む → でもMFAがあれば防げる ✅

**デバイスコードフィッシングの場合：**
- パスワードを盗まない！
- **本人が正規のMicrosoftページで「許可する」を押す**
- MFAは「本人確認」を守るが、「許可を与える行為」は守れない ❌

> 💡 **例え話で考えてみよう**
>
> 「玄関のカギ（MFA）」は突破していない。でも「部屋の鍵（アクセス許可）」は本人が開けてしまっている、という状況です。
>
> いくら玄関のセキュリティを強化しても、部屋の鍵を自分で渡してしまえば意味がありません。

### 🏭 「フィッシングのサービス化」が進んでいる

記事では **PhaaS（Phishing as a Service：サービスとしてのフィッシング）** という言葉が出てきます。

これは、攻撃ツールを**サブスクリプション形式で販売・提供**するビジネスモデルです。まるでNetflixのように「月額料金を払えば攻撃ツールが使える」という状況になっています。

- **Tycoon2FA**・**Kali365** などのツールが代表例
- デバイスコードフィッシングが「標準機能」として搭載されている
- 専門知識がなくても攻撃できてしまう

### 🤖 AIが攻撃ツールの開発を加速している

記事では「**LLM（大規模言語モデル）**」、つまりChatGPTのようなAIを使って攻撃ツールが作られていると指摘しています。

AIのおかげで、プログラミングの専門家でなくても短期間で攻撃ツールが作れるようになってしまいました。セキュリティ研究者が追いかけるより速く、新しいツールが次々と登場しています。

## なぜ重要なのか

### 📊 影響の大きさ

- **Microsoft 365、Teams、SharePoint** などビジネスで広く使われるサービスが標的
- **アクセストークン**（ログインし続けるための「通行証」）を盗まれると、パスワードを変えても攻撃者はしばらくアクセスし続けられる
- メールの盗み見・なりすましメール送信（BEC詐欺）・社内ファイルの流出などにつながる

### 🌍 誰でも被害に遭う可能性がある

個人ではなく、**企業・学校・行政機関**などが主な標的ですが、そこで働いたり学んだりしている私たち全員が間接的に影響を受けます。

## 対策・今後の展望

### ✅ 今すぐできる対策

#### 個人レベル
| 対策 | 内容 |
|------|------|
| **不審なコード入力を疑う** | 突然「このコードを入力してください」というメッセージが来たら要注意 |
| **送信元を確認する** | メールやメッセージの送り主が本当に正規の組織か確認する |
| **「許可する」を押す前に考える** | 見覚えのないアプリへの許可を求められたら絶対に押さない |

#### 組織・企業レベル
| 対策 | 内容 |
|------|------|
| **デバイスコードフローを無効化** | 必要ない場合はMicrosoft Entra IDの設定で機能自体をオフにする |
| **条件付きアクセスポリシー** | 管理されていない機器からのアクセスを制限する |
| **アクセストークンの監視** | 不審なトークン発行がないかリアルタイムで監視する |
| **社員教育** | この攻撃手法についてトレーニングを実施する |

### 🔮 今後の展望

記事では「2026年後半に入っても攻撃の勢いが衰える兆候はない」と報告しています。

- 攻撃ツールが**25種類以上**確認されており、さらに増加中
- AIによる開発加速で、防御側が追いつくのが困難
- セキュリティ業界全体での対応強化が急務

## 過去記事との関連

今回の記事は単独の解説ですが、背景として知っておくとよい流れがあります。

**AiTM（中間者）フィッシング → デバイスコードフィッシング** という進化の流れです。AiTMフィッシングは「ログイン時のトークンを盗む」手法でしたが、デバイスコードフィッシングはさらに一歩進んで「ログイン後の許可の仕組み」を悪用しています。攻撃手法は常に進化しており、過去の対策が通用しなくなることを示す典型的な例です。

## 用語解説

| 用語 | 意味 |
|------|------|
| **OAuth 2.0** | 「このアプリに自分のアカウント情報を使わせる」許可を管理する業界標準のルール |
| **デバイスコードフロー** | キーボードがない機器でログインするための仕組み。短いコードを別デバイスで入力して認証する |
| **アクセストークン** | ログイン後に発行される「入場チケット」のようなデータ。これがあればパスワード不要でサービスにアクセスできる |
| **MFA（多要素認証）** | パスワード＋別の認証方法（SMSコード・指紋など）を組み合わせた本人確認 |
| **フィッシング** | 本物そっくりの偽サイト・偽メールで個人情報を騙し取る攻撃 |
| **PhaaS** | Phishing as a Service。攻撃ツールをサブスクリプション販売するビジネスモデル |
| **BEC（ビジネスメール詐欺）** | 会社の担当者になりすまして、取引先などに不正送金させる詐欺 |
| **LLM** | ChatGPTのような大規模言語モデル（AI）。攻撃ツール開発にも悪用されている |
| **Storm-2372** | Microsoftが追跡している国家関与が疑われるハッカー集団 |
| **ShinyHunters** | 大規模なデータ漏洩攻撃で知られる犯罪ハッカー集団 |
| **パスキー（Passkey）** | パスワードの代わりに使う新しい認証技術。フィッシングに強いとされるが、今回の攻撃では効果がない |
| **AiTM（中間者攻撃）** | 通信の間に割り込んで情報を盗む攻撃手法 |

---

> 🔔 **まとめ**
>
> デバイスコードフィッシングは「MFAがあれば安全」という常識を覆す新しい攻撃手法です。攻撃者はあなたのパスワードを盗まず、**あなた自身に「許可する」ボタンを押させる**ことで、アカウントへのアクセス権を手に入れます。不審なコード入力の要求には絶対に応じないことが、今すぐできる最大の防御です。
