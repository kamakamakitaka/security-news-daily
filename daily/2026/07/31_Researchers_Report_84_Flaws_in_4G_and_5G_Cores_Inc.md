# 4Gと5Gの中核ネットワークに84件の欠陥が発見！セッションハイジャックの危険も

**元記事**: [Researchers Report 84 Flaws in 4G and 5G Cores, Including a Session Hijacking Flaw](https://inl03.netline.com/ltr6/?_m=3n.009a.4044.sp0ao46r89.33lu)
**解説日**: 2025年7月

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的なことを押さえておきましょう。

### 📱 4G・5Gの「コアネットワーク」って何？

皆さんがスマートフォンで動画を見たり、メッセージを送ったりするとき、電波は基地局を経由して「コアネットワーク（Core Network / CN）」と呼ばれる場所に届きます。

コアネットワークは、いわば**携帯通信の「心臓部」や「指令センター」**です。ここで「この人は誰？」「どこに繋げればいい？」「通信料はいくら？」などを管理しています。

```
あなたのスマホ
    ↓ (電波)
基地局（アンテナ）
    ↓ (インターネット回線)
コアネットワーク ← ★今回の問題はここ！
    ↓
インターネット全体
```

### 🔐 「信頼モデル」って何？

コアネットワークの内部では、たくさんのコンピューター（ネットワーク機能）が互いに通信しています。昔は「コアネットワークの中にいるなら、信頼できる仲間だ」という前提で設計されていました。これを**信頼モデル**と言います。

家に例えると、「家の中にいる人は全員家族だから、何でも話して大丈夫」というルールのようなものです。

しかし最近は、コアネットワークが**クラウド（インターネット上のサーバー）**で動かされるようになってきました。すると「家の中」と「外」の境界が曖昧になり、知らない人が「家の中」に入り込める可能性が生まれてしまいました。

---

## 何が起きたのか

シンガポールの**南洋理工大学（Nanyang Technological University）**の研究チームが、4G・5Gのコアネットワークに使われているオープンソースソフトウェア（誰でも使えるプログラム）を徹底的に調べた結果、**84件もの未知の脆弱性（セキュリティの穴）**を発見しました！

調査対象となったソフトウェアは以下の7つです：

| 規格 | 調査対象ソフトウェア |
|------|------------------|
| 4G (LTE) | Open5GS、OpenAirInterface |
| 5G | Open5GS、free5GC、OpenAirInterface、SD-Core、eUPF |

発見された84件のうち、**83件は実際に問題であることが確認**され、**81件にはCVE番号（脆弱性の公式ID番号）が割り当て**られました。

## 技術的な詳細

### 🕵️ どうやって欠陥を見つけたの？

研究チームは**AIを活用した自動調査システム「iFinder（アイファインダー）」**を開発しました。このシステムは、LLM（大規模言語モデル）という、ChatGPTのようなAI技術を使っています。

iFinder の動き方をざっくり説明すると：

1. **📚 過去の欠陥を学習** → 過去に報告されたセキュリティ問題を整理・分類する
2. **🔍 新しい欠陥を探す** → 学習した知識をもとに、新しいソフトウェアの問題を探す
3. **✅ 誤検知を排除** → 「コード」と「仕様書」を照らし合わせて、本当の問題だけを絞り込む
4. **💥 攻撃コードを自動生成** → 問題が実際に悪用できるか検証するための「PoC（概念実証）コード」を作る

### 🚨 「暗黙の信頼エラー（iTrue）」とは？

今回発見された欠陥は**「暗黙の信頼エラー（iTrue: implicit trust errors）」**と名付けられました。

問題の根っこは一つ：**「コアネットワーク内の機能どうしが、お互いを盲目的に信頼している」**こと。

具体的には、あるシステムが別のシステムから「メッセージ」を受け取ったとき、こんな確認を怠っていました：

- 📋 **形式チェックなし** → メッセージの書き方が正しいか確認しない
- 💬 **意味チェックなし** → メッセージの内容が正しいか確認しない
- 📦 **リソースチェックなし** → メッセージを処理できる余裕があるか確認しない

これは例えるなら、銀行員が「私は行員です」と言った人に対して、**社員証も確認せずに金庫を開けてしまう**ようなものです。

### 😈 攻撃者は何ができるの？

この欠陥を悪用されると、以下のような攻撃が可能になります：

#### 1. DoS攻撃（サービス妨害攻撃）
コアネットワークに大量の不正なメッセージを送り、**システムをダウンさせる**攻撃です。これが成功すると、そのキャリア（携帯会社）の**ユーザー全員が通信できなくなる**可能性があります。

#### 2. セッションハイジャック
「セッション」とは、あなたとネットワークの間の「通信のつながり」のことです。これを乗っ取ることで、**攻撃者があなたのふりをして通信を操作**できるようになります。

## なぜ重要なのか

### 🌍 影響が非常に広い

今回問題となったソフトウェア（Open5GS、free5GCなど）は、**研究機関や実際の商用サービスでも使われているオープンソースソフト**です。つまり、世界中の多くの場所で動いている可能性があります。

### ⚠️ 4Gの欠陥が5Gに「引き継がれている」

記事で特に気になるのが、**4Gの欠陥の一部が5Gにもそのまま受け継がれている**という事実です。

「5Gは新しいから安全」と思いがちですが、設計を引き継いでいる部分にはそのまま古い問題も残っている、ということです。これは**建て替えた家でも、基礎部分の欠陥がそのまま残っている**ようなイメージです。

### 🔓 クラウド化が攻撃対象を広げた

昔のコアネットワークは物理的に隔離された専用設備で動いていたため、外部から直接アクセスすることは困難でした。しかしクラウド化により、設定ミス（ミスコンフィギュレーション）があれば**インターネットから直接コアネットワークの内部機能に届いてしまう**リスクが生まれています。

## 対策・今後の展望

### 研究チームの発見を受けた動き

研究チームは各ソフトウェアの開発者に対して発見した欠陥を**責任ある開示（Responsible Disclosure）**の形で報告しており、多くはすでにCVE番号が割り当てられ、修正作業が進んでいます。

### 通信事業者・開発者ができること

| 対策 | 説明 |
|------|------|
| **メッセージの厳格な検証** | 受け取ったメッセージの形式・内容・リソースを必ずチェックする |
| **クラウド設定の見直し** | コアネットワーク内部のインターフェースがインターネットに露出しないよう設定を確認する |
| **ゼロトラストの導入** | 「内部にいても信頼しない」という考え方で設計し直す |
| **ソフトウェアの更新** | 修正パッチが出たらすぐに適用する |

### 一般ユーザーができること

残念ながら、今回の問題はコアネットワーク側の問題なので、**私たちエンドユーザーが直接できることはほとんどありません**。ただし、万が一大規模な障害が起きたときのために、以下の備えは有効です：

- 📶 **Wi-Fiと携帯回線の両方を持つ**（片方がダウンしても通信できるように）
- 🔔 **携帯会社の公式情報を確認する習慣をつける**

## 用語解説

| 用語 | 意味 |
|------|------|
| **コアネットワーク（CN）** | 携帯通信網の中核部分。認証・接続管理・課金などを行う「指令センター」 |
| **4G/LTE** | 第4世代の携帯通信規格。現在も広く使われている |
| **5G** | 第5世代の携帯通信規格。超高速・低遅延が特徴 |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやシステムのセキュリティ上の弱点・穴 |
| **DoS攻撃** | 大量のリクエストを送ってシステムをダウンさせる攻撃 |
| **セッションハイジャック** | 他人の通信セッションを乗っ取る攻撃。なりすましが可能になる |
| **CVE番号** | 世界共通の脆弱性識別番号。「CVE-2024-XXXX」のような形式 |
| **オープンソース** | ソースコード（プログラムの設計図）が公開されているソフトウェア |
| **LLM（大規模言語モデル）** | ChatGPTのような、大量のテキストで学習したAIモデル |
| **PoC（概念実証）** | 脆弱性が本当に悪用できるかを示すテスト用コード |
| **GTP-C / PFCP** | コアネットワーク内部で使われる通信プロトコル（決まりごと）の名前 |
| **暗黙の信頼エラー（iTrue）** | 相手を確認せずに盲目的に信頼してしまうことで生じるセキュリティの欠陥 |
| **ゼロトラスト** | 「誰も最初から信頼しない」という現代的なセキュリティの考え方 |
| **責任ある開示** | 発見した脆弱性を、悪用される前に開発者に報告して修正してもらうプロセス |
