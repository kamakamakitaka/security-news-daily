# ハッカーが広告会社のスクリプトを改ざん！仮想通貨の送り先アドレスを勝手に書き換える攻撃が発生

**元記事**: [Hackers Poison Adform Script to Swap Crypto Wallet Addresses Across Customer Sites](https://inl03.netline.com/ltr6/?_m=3n.009a.4045.sp0ao46r89.33n8)
**解説日**: 2025年7月28日

---

## 背景知識

まず、この記事を理解するためにいくつかの前提知識を整理しましょう。

### 🏗️ 広告テクノロジー会社ってどんな仕事をしてるの？
「Adform（アドフォーム）」は、ウェブサイトに広告を配信するための仕組みを提供する会社です。たとえば、あなたがニュースサイトを開いたときに表示されるバナー広告の裏側では、こういった会社のシステムが動いています。Adformは約1,800社のお客様（ウェブサイト運営者）に対してサービスを提供しており、1日に15億本もの広告を世界180カ国以上に配信している大きな会社です。

### 📜 JavaScriptファイルって何？
ウェブサイトをただの「文字と画像の表示」にとどまらず、「動く」ようにするためのプログラムです。ボタンを押したら何かが動く、文字を入力したらリアルタイムで検索候補が出る、といった動作はJavaScriptで作られています。ウェブサイトは外部の会社のJavaScriptを読み込んで使うことがよくあります。

### 💰 仮想通貨ウォレットアドレスって？
仮想通貨（ビットコインなど）を送金するときには、「ウォレットアドレス」と呼ばれる長い文字列（例：`1A2b3C4d...`）を相手に教えて、そこへ送金します。銀行口座番号のようなものです。**一度送ってしまうと、仮想通貨は基本的に取り戻せません。**

### 🔗 サプライチェーン攻撃って？
「サプライチェーン」とは「供給の連鎖」という意味です。たとえば、パン屋さんが使う小麦粉に毒を混ぜれば、そのパン屋さんのパンを食べた人全員が被害を受けます。IT分野でも同様で、**多くのサイトが共通で使っているプログラムファイルを1か所改ざんするだけで、それを使っている全サイトの利用者を攻撃できる**手法です。

---

## 何が起きたのか

2025年7月27日、広告テクノロジー企業「Adform」が提供するJavaScriptファイル（`trackpoint-async.js`）が、何者かによって**こっそり悪意のあるコードを追加する形で改ざんされました。**

このファイルはAdformのサービスを使っている多数のウェブサイトに自動的に読み込まれているため、**Adformのサーバー上のファイル1つを書き換えるだけで、契約している多数のサイトを訪問したユーザーに影響を与えることができてしまいました。**

具体的な被害の流れはこうです：

1. ユーザーが「仮想通貨取引所」や「ショッピングサイト」など、Adformのスクリプトを読み込んでいるウェブサイトを訪問する
2. 悪意のあるコードがバックグラウンドで動作する
3. ユーザーが仮想通貨の送金先として正しいウォレットアドレスをコピー＆ペーストしようとすると…
4. **攻撃者が用意した全く別のアドレスにこっそりすり替えられてしまう！**
5. 気づかずに送金すると、お金が攻撃者の手元へ

Adformはこの問題を7月27日に検知し、悪意のあるコードを削除して、影響を受けた顧客への通知と当局への報告を行いました。

## 技術的な詳細

### 🎯 攻撃の仕組みをわかりやすく解説

悪意のあるコードには**2つのブロック**が含まれていました。

---

#### ブロック①：クリップボード（コピー＆ペースト）を乗っ取る

> 💡「クリップボード」＝スマホやPCで「コピー」したとき、一時的にデータが保存される見えない場所

**やっていること：**
- ユーザーが何かをコピーしたことを監視している
- **4秒ごと**にクリップボードの中身をチェックする
- ビットコイン・イーサリアム・トロンのアドレスの形式と一致したら、**攻撃者のアドレスに書き換える**

セキュリティ研究者のKevin Beaumont氏はこう警告しています：
> 「アドレスが違うと気づいて、もう一度コピーし直しても、また書き換えられてしまう」

これは非常に厄介な特徴です。ユーザーが気づいて対処しようとしても、ページを開いている限り無効化されてしまうのです。

---

#### ブロック②：ページに直接入力した文字も書き換える

クリップボード経由じゃなくても危険でした。

- ウェブページ上のテキスト入力欄（フォーム）を監視している
- アドレスを**手打ちで入力**しても、ビットコインなどのアドレス形式と一致した瞬間に書き換える
- カーソルの位置まで自然に戻して、**ユーザーが気づかないように**偽装する
- コピー・切り取り・貼り付け・入力などのあらゆる操作を監視

つまり「コピペを使わなければ安全」でもなかったということです。

---

#### 🔐 コードの隠し方（難読化）
攻撃者はすり替えるアドレス文字列を「XOR暗号（6バイトのキーを使ったスクランブル処理）」で隠していました。これにより、ウイルス対策ソフトなどが一見して悪意のあるコードだと気づきにくくなっていました。実際、セキュリティ研究者が調べた時点では、VirusTotal（ウイルス検知サービス）でも検出されなかったと報告されています。

---

#### 📡 外部サーバーへの通信
コードはページが読み込まれると、`84.32.102[.]230:7744`という外部サーバーに対して、**「どのウェブサイトのどのページを見ているか」を送信しようとしていた**ことも確認されています。ただし、実際に情報が送信されたかどうかは現時点では不明です。

---

### 🏭 なぜ1ファイルの改ざんで多数のサイトに影響？

```
[攻撃者]
    ↓ 改ざん
[Adformのサーバー上のtrackpoint-async.js] ← ここ1か所だけ
    ↓ 自動で配信される
[サイトA] [サイトB] [サイトC] ... [サイトZ]
    ↓
[各サイトの訪問者 全員が影響を受ける]
```

Adformのドキュメントによると、このトラッキングコードはサイト全体に無条件で配置することができるため、1ファイルの汚染が非常に広範囲に伝播します。これが「**サプライチェーン攻撃**」の恐ろしさです。

## なぜ重要なのか

### 📊 影響の規模
- Adformは約**1,800社**の顧客を持ち、**180カ国以上**でサービスを展開
- 改ざんされたファイルを読み込んでいたサイトを訪問したユーザーは全員が潜在的な被害者

### ⚠️ 仮想通貨被害は取り戻せない
仮想通貨の送金は**基本的に取り消しができません**。間違ったアドレスに送ってしまったら、それで終わりです。攻撃者にとっては非常に「効率的な」詐欺の手口です。

### 🕰️ タイムラインが不明確
Adformは「7月27日が影響を受けた日」としていますが、セキュリティ研究者のBeaumont氏は「**過去1週間、悪意ある活動を確認していた**」と述べています。もし改ざんが数日前から始まっていたなら、被害規模は公式発表より大きい可能性があります。

### 🚫 まだわかっていないこと
- 何サイトがこのファイルを読み込んでいたか
- 何人のユーザーが影響を受けたか
- どうやって攻撃者はAdformのサーバーにアクセスできたのか
- 実際にいくら分の仮想通貨が盗まれたのか
- Adformの公式発表には「侵害の痕跡（IoC）」の情報が含まれていない

## 対策・今後の展望

### 🛡️ 今すぐできる対策

#### 7月27日にウェブを使っていた人へ
| 対策 | 理由 |
|------|------|
| **ブラウザのキャッシュを消す** | 改ざんされたファイルがキャッシュに残っている可能性があるため |
| **仮想通貨を送金した人は送付先を確認** | アドレスがすり替えられていなかったか確認する |
| **被害があれば当局に報告** | 証拠保全のためにも早めの対応を |

#### 今後の仮想通貨送金時の習慣として
- ✅ **送金前に、アドレスの最初と最後の数文字を必ず目視確認する**
- ✅ **QRコードを使って入力する（コピペや手入力を避ける）**
- ✅ **少額でテスト送金してから本送金する**
- ✅ **ページを一度閉じて再度開いてから送金する**（このマルウェアはページを閉じると機能停止するため）

#### ウェブサイト運営者・開発者向け
- 外部スクリプトの**整合性チェック（SRI: Subresource Integrity）** を導入する
  - これは「このスクリプトが想定通りの内容であるかを確認する仕組み」で、改ざんを検知できる
- 使用しているサードパーティスクリプトの定期的な監査

### 🔮 今後の展望
- 攻撃者がAdformのサーバーにどうやって侵入したかの調査結果が注目される
- 仮想通貨を狙ったサプライチェーン攻撃は今後も増加が予想される
- 広告テクノロジー業界全体でのセキュリティ強化が求められる

## 過去記事との関連

今回は過去の関連記事は参照していませんが、この種の攻撃は以前から存在する**「クリプトハイジャッキング」や「クリップボードハイジャッキング」**と呼ばれる手法の発展型です。また、**サプライチェーン攻撃**という観点では、2020年に世界を震撼させた「SolarWinds事件」（IT管理ソフトが改ざんされ、米国政府機関を含む多数の組織が被害を受けた事件）と同じ構造を持っています。「信頼しているものを経由した攻撃」は検知が非常に難しく、被害が拡大しやすいという共通の問題があります。

## 用語解説

| 用語 | 意味 |
|------|------|
| **JavaScript（ジャバスクリプト）** | ウェブページを動的に動かすためのプログラミング言語 |
| **ウォレットアドレス** | 仮想通貨の「口座番号」のような文字列。宛先を間違えると送金したお金は戻ってこない |
| **クリップボード** | コピー（Ctrl+C）したデータが一時保存される、PC・スマホ内の見えない領域 |
| **サプライチェーン攻撃** | 直接ターゲットを攻撃せず、ターゲットが信頼・利用しているソフトやサービスを経由して攻撃する手法 |
| **難読化（obfuscation）** | コードを読みにくく変換して、解析を妨害する技術 |
| **XOR暗号** | データを特定のキーで変換して隠す暗号化の一種。簡単に元に戻せるが、一見するとわからなくなる |
| **VirusTotal** | ファイルやURLが悪意のあるものかを複数のウイルス対策エンジンで一斉チェックできる無料サービス |
| **キャッシュ** | 一度読み込んだデータを手元に保存しておき、次回の読み込みを速くする仕組み |
| **IoC（Indicator of Compromise）** | 「侵害の痕跡」。攻撃に使われたIPアドレス、ファイル名、URLなど、攻撃を識別するための手がかり情報 |
| **SRI（Subresource Integrity）** | 外部スクリプトが改ざんされていないかをハッシュ値（データの指紋）で検証するウェブのセキュリティ機能 |
| **トラッキングコード** | ウェブサイトの訪問者数や行動を計測するために埋め込まれるプログラム |

---

> 💬 **まとめ一言**：今回の事件は「信頼している業者のファイルが汚染されていた」というサプライチェーン攻撃の典型例です。仮想通貨を扱う人は特に、**「送金前に必ずアドレスを目視確認する」** 習慣をつけることが最大の自衛策です。
