# 4G・5Gのネットワーク中枢に84件もの脆弱性！セッション乗っ取り攻撃も可能に

**元記事**: [Researchers Report 84 Flaws in 4G and 5G Cores, Including a Session Hijacking Flaw](https://inl03.netline.com/ltr6/?_m=3n.009a.4045.sp0ao46r89.33o8)
**解説日**: 2026年8月2日

---

## 背景知識

まず、このニュースを理解するために必要な「前提知識」を整理しましょう。

### 📱 4G・5Gって何？

みなさんが毎日スマートフォンで使っている「通信ネットワーク」のことです。LINEを送ったり、YouTubeを見たりするとき、スマホは基地局（アンテナ）を通じてインターネットにつながっていますよね。その通信規格が「4G（第4世代）」や「5G（第5世代）」です。

### 🏗️ 「コアネットワーク」って何？

通信ネットワークには「外から見える部分（基地局など）」と「中枢部分（コアネットワーク）」があります。コアネットワークは、言わば**通信の司令塔**です。

> 🏠 **たとえ話**: マンションに例えると…
> - **基地局** → マンションの玄関・エントランス（外から見える）
> - **コアネットワーク** → 管理室・電気・水道の配管（内部の重要インフラ）

コアネットワークは「内部の人しかアクセスできない安全な場所」として設計されています。でも最近、このコアネットワークがクラウド（インターネット上のサーバー）で動くようになってきており、これが問題の発端になっています。

### 🔑 「セッション」って何？

「セッション」とは、あなたがネットワークに接続してから切断するまでの**一連の通信のやり取り**のことです。

> 📞 **たとえ話**: 電話をかけてから切るまでの「一通話」に相当します。

「セッションハイジャック（乗っ取り）」とは、この通信セッションを攻撃者が横取りして、本人になりすます攻撃です。

## 何が起きたのか

シンガポールの**南洋理工大学（Nanyang Technological University）**の研究チームが、4G・5Gのコアネットワークに存在する**84件もの新たな脆弱性（セキュリティ上の弱点）**を発見しました！

### 発見された脆弱性の概要

| 項目 | 内容 |
|------|------|
| 発見された脆弱性の総数 | **84件** |
| うち確認済み | **83件** |
| CVE番号が割り振られたもの | **81件** |
| 対象となった実装 | 4G系2種類、5G系5種類（計7種類） |

> 💡 **CVE番号**とは？世界共通の脆弱性管理番号のこと。「この脆弱性はCVE-XXXX-XXXXです」と番号で管理されます。

### 調査対象となったシステム

研究チームは以下のオープンソース（誰でも使えるソフトウェア）の通信システムを調べました：

- **4G（LTE）系**: Open5GS、OpenAirInterface
- **5G系**: Open5GS、free5GC、OpenAirInterface、SD-Core、eUPF

これらは研究機関だけでなく、**実際の商用通信サービスでも使われている**ソフトウェアです。

## 技術的な詳細

### 🔓 根本的な原因：「暗黙の信頼」という設計上の問題

今回発見された脆弱性には、共通の原因がありました。それが「**暗黙の信頼（Implicit Trust）**」です。

> 🤝 **たとえ話**: 会社の社内システムで考えてみましょう。
> 「社内ネットワークからのアクセスなら、全部信頼できる！」と思って、パスワードなしでどのシステムにもアクセスできるようにしてしまった…。でも、もし悪者が社内ネットワークに侵入したら？全部やりたい放題になってしまいますよね。

コアネットワークも同じ問題を抱えています。「内部からの通信なら安全」という前提で設計されているため、**メッセージの中身をちゃんと確認せずに従ってしまう**のです。

### 🤖 AIを使った脆弱性発見システム「iFinder」

研究チームはこの問題を見つけるために、**LLM（大規模言語モデル）**というAI技術を活用したシステム「**iFinder**」を開発しました。

iFinderの動作は以下のステップで行われます：

```
① 既知の脆弱性を要約・分類する
        ↓
② そのパターンをもとに新しい脆弱性を自動探索する
        ↓
③ 誤検知（フォルスポジティブ）を排除する
        ↓
④ 実際に攻撃できるか確認する「概念実証コード」を自動生成する
        ↓
⑤ 実際のシステムで動かして結果を分析・改善する
```

> 🔍 **フォルスポジティブ（誤検知）**とは？「脆弱性があるように見えるけど、実は問題ない」という検知ミスのこと。これを取り除くことで、本当に危険な問題だけを特定します。

### 🎯 どんな攻撃ができるの？

発見された脆弱性を悪用すると、主に2種類の攻撃が可能になります：

#### 1. DoS攻撃（サービス妨害攻撃）
> 📵 **たとえ話**: 飲食店に「いたずら電話」を大量にかけて、本当のお客さんの電話がつながらないようにする嫌がらせ。通信サービスを使えなくする攻撃です。

#### 2. セッションハイジャック（通信の乗っ取り）
> 🎭 **たとえ話**: あなたがネットショッピングでログインした状態を横取りして、攻撃者があなたになりすましてしまう攻撃。

### 🔗 使われているプロトコル（通信規格）

問題が見つかったのは、主に2つの通信プロトコルです：

- **GTP-C（GPRS Tunnelling Protocol Control Plane）**: 通信のトンネルを管理するプロトコル
- **PFCP（Packet Forwarding Control Protocol）**: データの転送を制御するプロトコル

> 💡 **プロトコル**とは？コンピューター同士が「こういうルールで話しましょう」と決めた通信の約束事のことです。

### 📦 4Gから5Gに受け継がれた問題

注目すべきは、**5Gの脆弱性の一部が4Gから引き継がれている**ことです。新しい技術に移行する際に、古い問題もそのまま持ち込んでしまったわけです。

> 🏚️ **たとえ話**: 古い家の欠陥をそのまま新しい家の設計に流用してしまったようなものです。

## なぜ重要なのか

### 📡 あなたのスマホも関係している

4G・5Gは日本中で使われている通信インフラです。これに脆弱性があるということは、**私たちの日常通信に影響する可能性**があります。

### ☁️ クラウド化が問題を深刻にした

従来のコアネットワークは、物理的に隔離された専用設備で動いていたため、外部からアクセスすること自体が難しかったです。しかし最近は**クラウド（インターネット上のサーバー）**で動かすケースが増え、設定ミスなどがあると内部の重要な部分がインターネットから直接アクセスできてしまうリスクが生まれています。

### 📊 影響の規模

```
発見された脆弱性: 84件
└─ 確認済み: 83件（99%）
   └─ CVE登録済み: 81件（97%）

対象システム:
├─ 4G実装: 2種類
└─ 5G実装: 5種類
   計: 7種類の広く使われるオープンソースシステム
```

## 対策・今後の展望

### ⚠️ 攻撃が成立する条件

まず安心材料として、この攻撃が成功するには**いくつかの条件が必要**です：

1. 攻撃者がコアネットワーク部品のIPアドレスを知っている必要がある
2. 内部のコアネットワークインターフェースにアクセスできる必要がある
3. クラウド環境の設定ミスを悪用できる必要がある

つまり、**誰でも簡単にできる攻撃ではない**ですが、条件が揃ってしまうと危険なのも事実です。

### 🛡️ 取るべき対策

| 対策 | 内容 |
|------|------|
| **「ゼロトラスト」の導入** | 「内部からだから安全」という思い込みをやめ、全ての通信を検証する設計にする |
| **メッセージ検証の強化** | 受け取ったメッセージの形式・内容・リソースを必ずチェックする |
| **クラウド設定の見直し** | 内部インターフェースがインターネットに露出しないよう設定を厳重にする |
| **ソフトウェアの更新** | 各プロジェクトがパッチ（修正プログラム）を提供し次第、速やかに適用する |

### 🔮 今後の動向

- 研究チームは発見した脆弱性を各ソフトウェアの開発チームに報告済みです
- 81件はすでにCVE番号が割り振られており、修正対応が進んでいます
- AI（LLM）を使った脆弱性発見手法は今後もセキュリティ研究で活用が広がるでしょう

また、今回の研究でAI（LLM）を使って脆弱性を自動発見したことも注目ポイントです。AIが防御側の武器として活躍し始めている一方、悪用される可能性もあり、セキュリティの世界でAIの存在感はますます大きくなっています。

## 用語解説

| 用語 | 解説 |
|------|------|
| **4G / 5G** | 第4・第5世代の移動通信規格。スマホの通信に使われる |
| **コアネットワーク（CN）** | 通信ネットワークの中枢部分。通信の司令塔 |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやシステムのセキュリティ上の弱点・欠陥 |
| **DoS攻撃** | サービス妨害攻撃。大量のリクエストを送りシステムをダウンさせる |
| **セッションハイジャック** | 通信セッションを乗っ取り、他人になりすます攻撃 |
| **LLM** | Large Language Model（大規模言語モデル）。ChatGPTのようなAI技術 |
| **CVE** | Common Vulnerabilities and Exposures。世界共通の脆弱性管理番号 |
| **GTP-C** | コアネットワーク内でトンネル通信を管理するプロトコル |
| **PFCP** | コアネットワーク内でデータ転送を制御するプロトコル |
| **オープンソース** | ソースコード（設計図）が公開されており、誰でも利用・改変できるソフトウェア |
| **ゼロトラスト** | 「誰も信頼しない」を前提に、全アクセスを検証するセキュリティの考え方 |
| **フォルスポジティブ（誤検知）** | 実際は問題ないのに、問題があると誤って検知してしまうこと |
| **暗黙の信頼（Implicit Trust）** | 「この場所からの通信なら安全」と検証なしに信じてしまう設計上の問題 |
| **PoC（概念実証コード）** | 脆弱性が実際に悪用できることを示すためのサンプルプログラム |
