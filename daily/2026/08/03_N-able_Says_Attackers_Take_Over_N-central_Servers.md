# N-ableのN-centralサーバーが乗っ取られた事件：最初の修正では不十分だった

**元記事**: [N-able Says Attackers Take Over N-central Servers After Initial Fix Proves Incomplete](https://inl03.netline.com/ltr6/?_m=3n.009a.4046.sp0ao46r89.33pg)
**解説日**: 2026年8月4日

---

## 背景知識

このニュースを理解するために、まずいくつかの登場人物・仕組みを整理しましょう。

### 🏢 N-able（エヌエイブル）とは？
N-ableはITサービスを提供する企業が使う「管理ツール」を作っている会社です。たとえば、「うちの会社のパソコン100台を一括で管理したい」というニーズに応えるソフトウェアを作っています。

### 🖥️ N-centralとは？
N-ableが作った**リモート監視・管理プラットフォーム**です。簡単に言うと、「離れた場所にあるたくさんのパソコンを、一か所から遠隔で操作・管理できる司令塔」のようなものです。

> **例え話**: 学校の先生が教室の全生徒のタブレットを先生用パソコン1台から一括管理できるシステム、と思ってください。N-centralはその「先生用パソコン」にあたります。

### 🔑 認証バイパスとは？
本来ならID・パスワードを入力しないと入れない場所に、**その確認をすり抜けて侵入する方法**のことです。鍵をかけているはずのドアに、別の穴から入り込むようなイメージです。

### 🌐 Cloudflareトンネルとは？
Cloudflare（クラウドフレア）という企業が提供するサービスで、**インターネット上に「秘密の通路」を作る仕組み**です。この通路は「外向き（アウトバウンド）」に接続するため、ファイアウォール（防火壁）に穴を開けなくても使えるのが特徴です。

## 何が起きたのか

### 事件の流れを時系列で整理 📅

```
7月31日  N-ableが不審な動作を検知（ライセンスエラーが大量発生）
    ↓
調査開始 → 攻撃者がN-centralサーバーに管理者権限で侵入していたことが判明
    ↓
最初の修正パッチを公開（CVE-2026-18556 の対策 → バージョン2026.2）
    ↓
しかし！ → 別の経路で同じ脆弱性が悪用できることが発覚
    ↓
8月2日  新たなCVE（CVE-2026-18577）として追加修正パッチを公開
         → バージョン2026.3.1.7が「安全な最初のバージョン」と発表
```

### 攻撃者が何をしたか

攻撃者はN-centralサーバーに侵入した後、さらに**管理対象のパソコン（エンドポイント）にも侵入**し、そこに「Cloudflareトンネル」という秘密の通路を仕掛けました。

> **例え話**: 泥棒が学校の管理室（N-centralサーバー）に侵入し、そこから全教室（管理対象のパソコン）の合鍵を作り、さらに各教室に「見えない抜け道」を設置した、というイメージです。

## 技術的な詳細

### 攻撃の仕組みをステップごとに解説

#### ① 認証バイパスで侵入
攻撃者はID・パスワードなしでN-centralの**管理者アカウントを乗っ取る脆弱性**を悪用しました。これが **CVE-2026-18556**（深刻度スコア：8.2/10）です。

#### ② 管理対象のパソコンに侵入
N-centralには「Take Control（テイクコントロール）」という遠隔操作機能があります。攻撃者はこれを悪用して、N-centralで管理されている各パソコンにアクセスしました。

#### ③ 「秘密の抜け道」を設置
各パソコンに**Cloudflareトンネル**を「サービス」として登録しました。

| 特徴 | 説明 |
|------|------|
| 外向き通信 | ファイアウォールをすり抜けられる |
| サービスとして登録 | PCを再起動しても消えない |
| N-central経由不要 | N-centralを修正しても通路が残る |

> **ポイント**: これが最も厄介なところです。N-centralのパッチを当てても、**各パソコンに仕掛けられた抜け道は残り続ける**のです！

#### ④ 最初の修正が不完全だった
N-ableは最初にバージョン2026.2で修正したと思っていましたが、**別の経路（別の侵入口）**を使えば同じ攻撃ができることが判明。これが **CVE-2026-18577** として追加で登録されました。

## なぜ重要なのか

### 🎯 影響の大きさ

N-centralはIT企業が**複数の顧客のパソコンをまとめて管理するツール**です。つまり、N-centralが1台乗っ取られると…

```
攻撃者
  ↓ N-centralに侵入
N-centralサーバー（1台）
  ↓ Take Controlで操作
顧客A社のパソコン群
顧客B社のパソコン群
顧客C社のパソコン群
  ↦ すべてに被害が及ぶ可能性！
```

### 📊 実際の被害状況
- セキュリティ企業「Huntress（ハントレス）」の調査では、1つのパートナーアカウント配下の**9つの組織**が被害を受け、それぞれ1台ずつのパソコンに攻撃者が侵入していたことが確認されています
- フィンランドの国家サイバーセキュリティセンターも緊急勧告を発表

### 🚨 深刻な点まとめ
1. **管理者権限なしで侵入できた**（パスワード不要！）
2. **最初の修正が不完全だった**（信頼できると思ったら穴があった）
3. **再起動しても攻撃の痕跡が残る**（Cloudflareトンネルが生き続ける）
4. **N-centralを直しても被害が完全には消えない**（各PCの掃除が別途必要）

## 対策・今後の展望

### ✅ 今すぐやるべきこと（N-centralユーザー向け）

#### 1. バージョンを確認・更新する
- 🔴 **危険**: 2026.1以前、2026.2
- 🟡 **まだ危険**: 2026.3（最初の修正版だが不十分）
- 🟢 **安全**: **2026.3.1.7以降**

> N-ableのクラウドサービス（NCOD）を使っている場合は自動更新されますが、**自分でサーバーを立てている場合は手動更新が必要**です！

#### 2. 感染の痕跡を探す
N-ableが公開した「侵害の指標（IoC）」を確認しましょう：

| 確認項目 | 詳細 |
|----------|------|
| 不審なファイル | `svchost.exe` がユーザーの「ドキュメント」フォルダにある |
| 不審なサービス | `Cloudflared` という名前のサービスが登録されている |
| 不審な通信 | 以下のIPアドレスへの通信がある |

**攻撃者のIPアドレス（ブロック推奨）**:
- 173.249.252.200
- 87.249.138.34
- 37.19.210.32
- 37.153.90.88
- 92.118.112.181
- 68.235.46.214

> ⚠️ これらは **MullvadやNordVPNのVPN出口ノード**（匿名化サービスの出口）として確認されています。VPNを使って身元を隠していた可能性があります。

#### 3. 感染が確認された場合
- **悪意あるCloudflareトンネルサービスを各パソコンから手動で削除する**
- N-ableのサポートチームに連絡する
- 社内のセキュリティチームを巻き込む

### 🔮 今後の動向
- N-ableは現時点で脆弱性の技術的な詳細（どのコードに問題があったか）を公開していません
- The Hacker Newsが詳細を問い合わせ中で、続報が出る予定です

## 過去記事との関連

今回の記事と直接つながる過去記事はありませんが、以前解説した **「PNLD情報漏えい事件：イギリス警察・政府の連絡先情報がダークウェブに流出」** と共通するテーマがあります。

どちらも「**信頼されたシステム・組織が攻撃を受け、そこを踏み台にして大規模な被害につながる**」という構図です。N-central事件では「IT管理ツール」が踏み台にされ、多数の顧客企業が被害を受けました。PNLD事件では警察の情報システムが標的になりました。**「中心的な管理システムへの攻撃は被害が連鎖する」**という教訓は共通しています。

## 用語解説

| 用語 | 意味 |
|------|------|
| **N-central** | N-ableが提供するリモート監視・管理ツール。多数のPCを遠隔で一括管理できる |
| **認証バイパス（Authentication Bypass）** | ID・パスワードなどの本人確認をすり抜けてシステムに侵入する攻撃手法 |
| **CVE（シーブイイー）** | Common Vulnerabilities and Exposuresの略。発見されたセキュリティ上の欠陥に振られる番号 |
| **CVSS** | 脆弱性の深刻さを0〜10のスコアで表す国際標準。今回は8.2（かなり危険） |
| **Cloudflareトンネル** | ファイアウォールを回避して外部と通信できる「秘密の通路」を作るサービス |
| **エンドポイント** | ネットワークに接続されたパソコンやスマートフォンなどの端末 |
| **マネージドサービスプロバイダー（MSP）** | 複数の顧客企業のITシステムをまとめて管理するIT企業 |
| **IoC（侵害の指標）** | 攻撃を受けた証拠となるIPアドレス・ファイル名などの情報 |
| **VPN出口ノード** | VPN（匿名通信サービス）の通信が最終的に出てくるサーバー。身元を隠すために攻撃者がよく悪用する |
| **パッチ（Patch）** | ソフトウェアの欠陥を修正するための更新プログラム |
| **サービス（Windowsサービス）** | Windowsが起動した直後から自動的に動き続けるプログラム。再起動しても消えない |

---

> 💡 **今回の最大の教訓**: セキュリティの修正（パッチ）を当てることはとても重要ですが、「**一度の修正で終わりではない**」こと、そして「**サーバーを直しても、すでに感染した他のPCの掃除は別途必要**」という点を覚えておきましょう！
