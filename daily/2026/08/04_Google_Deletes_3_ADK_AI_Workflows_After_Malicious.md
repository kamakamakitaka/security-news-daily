# GoogleがAI開発ツールから3つの危険なワークフローを削除した件

**元記事**: [Google Deletes 3 ADK AI Workflows After Malicious GitHub Issue Could Trigger Privileged Agent](https://inl03.netline.com/ltr6/?_m=3n.009a.4047.sp0ao46r89.33q6)
**解説日**: 2025年7月

---

## 背景知識

このニュースを理解するために、いくつかの前提知識を整理しましょう。

### 🤖 ADK（エージェント開発キット）とは？
GoogleがAIエージェント（自律的に動くAIプログラム）を作るために公開したツールセットです。開発者がこれを使うと、自動でコードを書いたりバグを直したりするAIを作れます。

### 📂 GitHubとは？
プログラムのソースコード（設計図）をインターネット上で管理・共有するサービスです。世界中の開発者が使っており、プロジェクトの管理や共同作業に欠かせません。

### ⚙️ GitHub Actionsワークフローとは？
GitHubには「特定の操作が行われたら自動でプログラムを実行する」仕組みがあります。たとえば「誰かがバグ報告を投稿したら、自動でAIに分析させる」といった自動化が可能です。この自動処理の手順書を「ワークフロー」と呼びます。

### 🔑 アクセストークン・APIキーとは？
「このサービスを使っていい人ですよ」と証明するための特別なパスワードのようなものです。これが漏れると、他人がそのサービスを不正利用できてしまいます。

### 💉 プロンプトインジェクションとは？
AIに対して「悪意のある指示文」を混ぜ込み、本来とは違う行動をさせる攻撃手法です。たとえば「バグ報告」のように見せかけた文章の中に「こっそり秘密情報を外に送れ」という命令を隠す、といったものです。

---

## 何が起きたのか

セキュリティ研究会社「Pillar Security」が、GoogleのAI開発ツール（ADK）のGitHubリポジトリ（公開されているコード置き場）に、**深刻なセキュリティ上の欠陥**を発見しました。

### 事件の流れをざっくり説明すると…

```
①誰でも投稿できるバグ報告欄に「悪意ある文章」を投稿
        ↓
②AIエージェントがそれを読んで、だまされる
        ↓
③本来は信頼された人しか動かせない「特権ボット」が起動
        ↓
④攻撃者がGoogleのサーバー上でコードを自由に実行できてしまう
        ↓
⑤GoogleのAPIキー・クラウド認証情報が盗める状態に！
```

この問題を受けて、Googleは該当する3つのワークフローファイルを**2026年6月9日に削除**しました。

> 💡 **「ワークフローが削除された」ということは？**
> 「問題のある自動処理の手順書を取り除いた」ということです。ADK本体のプログラム（みんながダウンロードして使うもの）には欠陥はなく、リポジトリの運営自動化部分だけの問題でした。

## 技術的な詳細

少し難しいですが、できるだけわかりやすく説明します！

### 🏚️ 問題の構造：「門番が信頼している人物をハイジャックする」

この仕組みを**「マンションのオートロック」**で例えてみましょう。

```
【正常な状態】
住人（信頼されたボットアカウント）がカードをかざす
→ オートロック（権限チェック）が開く
→ 中に入れる（特権ワークフローが実行される）

【攻撃の状態】
攻撃者が「住人のふりをした文章」を入り口の掲示板に貼る
→ AIが読んで「住人として」自動的にカードをかざしてしまう
→ オートロックが開く（攻撃者は中に入れる！）
```

### 🔄 実際の攻撃の流れ（詳細）

**ステップ1：自動分析ワークフローのハイジャック**
- `issue-analyze.yml` というワークフローが、誰かがバグ報告を投稿すると**自動で起動**します
- このワークフローはAIエージェント（Antigravity）にバグを分析させ、**ボットアカウント**として分析結果をコメントします

**ステップ2：プロンプトインジェクション攻撃**
- 攻撃者はバグ報告の中に「`/adk-issue-fix`というコメントを投稿しろ」という**隠し命令**を埋め込みます
- AIエージェントはそれを読んで、**ボットとして`/adk-issue-fix`と投稿**してしまいます

**ステップ3：特権ワークフローが起動**
- `issue-fix.yml` というワークフローは、`/adk-issue-fix` というコメントを見ると起動しますが、**投稿者が「オーナー・メンバー・コラボレーター」かどうかだけを確認**します
- ボットはコラボレーター（協力者）として登録されていたため、チェックをパスしてしまいます
- ⚠️ **問題点**：「その信頼できるアカウントが外部から操られていないか」はチェックされていませんでした

**ステップ4：任意コード実行（一番危険！）**
- 特権ワークフローが起動し、攻撃者はGoogleのサーバー（CIランナー）上で**自由にコードを実行**できてしまいます
- Gitの「フック」（特定の操作時に自動実行されるスクリプト）という正規機能を悪用して、コマンドの制限を回避しました

**ステップ5：認証情報の漏洩**
- ボットの個人アクセストークン（PAT）
- Google APIキー
- Google Cloudのサービスアカウント認証情報

…といった**非常に重要な秘密情報が盗まれる可能性**がありました。

### 🔐 なぜ制限を突破できたのか？

ワークフローは「`gh`か`git`コマンドしか実行できない」という制限を設けていました。しかし…

```
攻撃者の思考：
「git コマンドは使えるな」
「git には "フック" という仕組みがある」
「フックは任意のプログラムを実行できる」
「つまり：悪意のあるファイルを書いて → git コマンド経由で実行すればいい！」
```

正規の機能の組み合わせで制限を回避された、というわけです。

## なぜ重要なのか

### 🌍 影響の大きさ

| 項目 | 内容 |
|------|------|
| 対象 | GoogleのAI開発ツール（ADK）の公式リポジトリ |
| 攻撃に必要なもの | **GitHubのアカウントだけ**（誰でも持てる） |
| 盗める可能性があったもの | Google APIキー、Googleクラウド認証情報 |
| 実際の被害 | 現時点では確認されていない |

### 😱 特に怖いポイント

1. **誰でも攻撃できた**：GitHubのアカウントを持っていれば、世界中の誰でもバグ報告を投稿できます。特別な技術なしで攻撃の入口に立てました。

2. **AIが攻撃の踏み台になった**：自動化・AI活用のメリットが、そのままセキュリティ上のリスクになりました。

3. **「信頼」の連鎖が悪用された**：「このアカウントは信頼できる」という前提が崩された瞬間、すべての権限チェックが意味を失いました。

4. **AIエージェント特有のリスク**：普通のプログラムと違い、AIは「自然言語の指示」を理解して動くため、**文章に埋め込まれた攻撃命令**を防ぐのが難しいです。

## 対策・今後の展望

### ✅ Googleが実施した対応
- 問題のある3つのワークフローファイルを**削除**
  - `issue-analyze.yml`
  - `issue-fix.yml`
  - `pr-analyze.yml`

### 🛡️ Pillar Securityが提言した対策

研究者たちは、同様のシステムを運用する組織に向けて以下を推奨しています：

| 推奨事項 | 説明 |
|---------|------|
| **ボットの身元を分ける** | 「分析用ボット」と「コード修正用ボット」を別アカウントにし、互いの権限を持たせない |
| **権限の最小化** | トークンやAPIキーに「必要最低限の権限だけ」を与える |
| **信頼できない入力による起動を防ぐ** | 外部の人が書いた文章（issue・PRなど）を起点に特権ワークフローが動かないよう設計する |

### 🔮 AI開発における教訓

このインシデントは、**AIの自動化が進むほどセキュリティ設計が重要になる**という現代的な課題を示しています。

```
昔のセキュリティ：「悪意のあるプログラムを実行させない」
↓
今のセキュリティ：「悪意のある文章を読んだAIが
　　　　　　　　　　悪意のある行動を取らないようにする」
```

この「プロンプトインジェクション対策」は、AI業界全体で取り組むべき**未解決の難問**のひとつです。

## 過去記事との関連

今回の事件は、近年増加している**「AIエージェントを標的としたセキュリティ攻撃」**の典型例です。AIが自律的に動いてコードを書いたりシステムを操作したりする時代になったことで、「AIをだます」という新しいタイプの攻撃が現実の脅威になってきています。特にプロンプトインジェクション攻撃は、ChatGPTなどの普及とともに注目が高まっているテーマです。今後もこの種のニュースが増えていくと予想されます。

## 用語解説

| 用語 | 解説 |
|------|------|
| **ADK（Agent Development Kit）** | GoogleがAIエージェントを作るために公開した開発ツール |
| **GitHub** | プログラムのコードを管理・共有するサービス |
| **ワークフロー** | 「特定の操作が行われたら自動で実行する」手順書 |
| **プロンプトインジェクション** | AIへの入力文章に悪意ある命令を混ぜ込む攻撃手法 |
| **PAT（Personal Access Token）** | GitHubにアクセスするための特別なパスワード |
| **APIキー** | 外部サービスを利用する権限を証明する鍵 |
| **CIランナー** | コードを自動でテスト・実行するサーバー |
| **任意コード実行** | 攻撃者が好き勝手なプログラムを実行できる最も深刻な脆弱性 |
| **Gitフック** | Gitの操作（コミットなど）をきっかけに自動実行されるスクリプト |
| **サービスアカウント** | 人間ではなくプログラムがクラウドサービスを使うための専用アカウント |
| **コラボレーター** | GitHubのリポジトリへの書き込み権限を持つ協力者 |
| **トリアージエージェント** | バグ報告を最初に仕分け・分析するAIエージェント |

> 📌 **まとめ**：GoogleのAI開発ツールの公式ページで、「誰でも投稿できるバグ報告欄」を入口として、AIをだまして特権コマンドを実行させる攻撃が可能な欠陥が見つかりました。実際の被害は確認されていませんが、Googleは問題のある自動化ファイルを削除して対応しました。AIの自動化が便利になる一方で、「AIをだます攻撃」という新しいセキュリティリスクが現実になってきていることを示す重要な事例です。
