# CISAが警告！AIを使った自動ハッキングで3つの重大脆弱性が悪用されている

**元記事**: [CISA Flags Langflow RCE, Tomcat, and N-central Flaws as Actively Exploited](https://inl03.netline.com/ltr6/?_m=3n.009a.4048.sp0ao46r89.33se)
**解説日**: 2026年8月6日

---

## 背景知識

このニュースを理解するために、いくつかのキーワードを先に説明しておきましょう。

### 🏛️ CISAって何？
**CISA（サイバーセキュリティ・インフラセキュリティ庁）** とは、アメリカ政府のサイバーセキュリティ専門機関です。日本でいうと「内閣サイバーセキュリティセンター（NISC）」に近い存在で、「この脆弱性は今まさに攻撃者に使われているぞ！」という警告を出す役割を担っています。

### 📋 KEVカタログって何？
**KEV（Known Exploited Vulnerabilities）カタログ** とは、「実際に悪用が確認されている脆弱性リスト」のことです。ここに載った脆弱性は「理論上危険」ではなく「今まさに攻撃に使われている」という意味で、特に深刻です。

### 🔧 今回問題になったソフトウェアは？

| ソフトウェア名 | 何に使うもの？ |
|---|---|
| **Langflow** | AIアプリを「ブロックを並べる感覚」で作れるオープンソースのツール |
| **Apache Tomcat** | WebサービスやWebアプリを動かすための有名なサーバーソフト |
| **N-able N-central** | 企業のITシステムをまとめて管理・監視するツール |

### 🤖 DeepSeekって何？
**DeepSeek** は中国発の高性能AI（大規模言語モデル）です。ChatGPTと同じような対話型AIですが、今回の記事では**攻撃者がこれをハッキングツールとして悪用した**という点が問題になっています。

---

## 何が起きたのか

2026年8月5日、CISAが「現在進行形で攻撃に使われている」として、**3つの脆弱性をKEVカタログに追加**しました。

### 追加された脆弱性の一覧

#### 1️⃣ CVE-2026-9198（深刻度：9.8/10 ← 超危険！）
- **対象**: Langflow（AIアプリ開発ツール）
- **内容**: ログインしていない攻撃者でも、サーバーを**完全に乗っ取れる**コード実行の脆弱性
- **修正済み**: 2026年7月・バージョン1.10.1で対応済み

> 🏠 **例え話**: 家の鍵を持っていない人でも、玄関から堂々と入り込んで家全体を自由に使えてしまう状態、と考えてください。

#### 2️⃣ CVE-2026-34486（深刻度：7.5/10）
- **対象**: Apache Tomcat（Webサーバー）
- **内容**: 本来は暗号化されているはずの通信を**暗号化なしで盗み見・改ざんできる**脆弱性
- **修正済み**: 2026年4月・複数バージョンで対応済み

> 📬 **例え話**: 封書（封をした手紙）で送っているつもりが、実はポスト投函の透明な袋で送られており、誰でも中身を読めてしまう状態です。

#### 3️⃣ CVE-2026-18556 / CVE-2026-18577（深刻度：8.2/10）
- **対象**: N-able N-central（IT管理ツール）
- **内容**: 認証（ログイン確認）を**スキップして管理者権限を取得**できる脆弱性
- **特記事項**: 最初のパッチ（修正プログラム）が不完全で、改めて2つ目のパッチも必要になった

> 🚪 **例え話**: 会社の入口に警備員がいるはずが、特定のセリフを言うだけで素通りできてしまう状態です。しかも最初の対策が甘くて、また別の抜け道ができてしまいました。

## 技術的な詳細

### 🤖 AIを使った自動ハッキングの手口（これが特に新しい！）

今回の記事で最も注目すべきは、**中国語を話す攻撃者グループ（"knaithe" / "KnYuan" という名前で活動）が、DeepSeekというAIを使って自動的にハッキングを行っていた**という点です。

攻撃の流れを図解すると、こんな感じです：

```
① 攻撃者がDeepSeek＋「Hermes Agent」というツールを使って自動攻撃を開始
        ↓
② まずLangflowの別の脆弱性(CVE-2026-33017)を試みる
        ↓
③ 失敗！（ターゲットのセキュリティ設定が厳しかった）
        ↓
④ AIが「じゃあ別の方法を探そう」と自動的に調査開始
        ↓
⑤ n8nなど他のソフトの脆弱性を自力で発見
        ↓
⑥ 新たな攻撃ルートで侵入成功
```

> 🎮 **例え話**: RPGゲームで「正面玄関から入れなかったら、AIが自動で裏口・窓・屋根・地下と全部試してくれる」ようなイメージです。しかも人間が何百時間もかかる調査を**わずか数分でやってしまう**のが怖いところです。

Palo Alto Networksのセキュリティチームは、この攻撃について次のように述べています：

> 「この攻撃者は460以上のターゲットへの攻撃を試み、自律型と手動の両方のテクニックを使っていた。AIが攻撃対象を絞り込むことで、計算コストを節約していたと考えられる。」

### 🌍 大規模なグローバル攻撃キャンペーン

別の中国系攻撃グループは、**100カ国以上の政府・企業インフラ**を狙って、「**SNOWLIGHT**」と呼ばれる悪意あるプログラムを仕掛けていました。

攻撃ツールキットの中身を確認すると：
- 🔍 偵察用パイプライン（ターゲット情報を自動収集）
- 💥 11種類の攻撃チェーン
- 🕳️ 2種類のトンネリングツール（通信を隠すツール）
- 🦠 4種類のマルウェアファミリー
- 海賊版の「GoCobaltStrike」（有名な攻撃ツールの中国語クラック版）

…など、非常に高度で組織的な攻撃であることがわかります。

## なぜ重要なのか

### ⚠️ 3つの理由で特に深刻

**① AIが攻撃を自動化・効率化している**
これまでのハッキングは「人間が手動で試す」ことが多かったのですが、今回はAIが**自律的に判断・学習しながら攻撃**しています。これは今後のサイバー攻撃の姿を大きく変える可能性があります。

**② 影響範囲が広すぎる**
- Apache Tomcatは世界中の無数のWebサービスで使われています
- Langflowは最近人気が急上昇しているAI開発ツールです
- N-central を使っている企業のIT管理者は、気づかずにシステムを乗っ取られるリスクがあります

**③ 460以上のターゲットへの攻撃が試みられた**
日本の企業・機関が対象に含まれている可能性も十分あります。

## 対策・今後の展望

### ✅ 今すぐできる対策

#### Langflowを使っている方
```
→ バージョン 1.10.1 以上にアップデートしてください！
→ インターネットに直接公開されているインスタンスは特に危険です
```

#### Apache Tomcatを使っている方
```
→ バージョン 11.0.21 / 10.1.54 / 9.0.117 以上にアップデートしてください！
```

#### N-able N-centralを使っている方
```
→ CVE-2026-18556 と CVE-2026-18577 両方のパッチを適用してください！
→ 最初のパッチだけでは不十分です！
```

### 🔮 今後の展望

今回の事件が示す「AI × ハッキング」の組み合わせは、今後さらに増えていくと予想されます。

- 攻撃者がAIを使って脆弱性を高速で発見・悪用する時代
- 防御側もAIを使ってリアルタイムで対応する時代

…へと、サイバーセキュリティの「戦場」が大きく変わりつつあります。セキュリティパッチの適用を**早く、確実に**行うことが、これまで以上に重要になってきています。

## 用語解説

| 用語 | 意味 |
|---|---|
| **CISA** | アメリカのサイバーセキュリティ専門政府機関 |
| **KEVカタログ** | 「実際に悪用が確認された脆弱性」のリスト |
| **CVE** | 脆弱性に振られる国際的な識別番号（例：CVE-2026-9198）|
| **CVSSスコア** | 脆弱性の深刻度を0〜10で表した数値。10に近いほど危険 |
| **RCE（Remote Code Execution）** | 遠隔からサーバー上で任意のコードを実行できる攻撃。最も危険な部類 |
| **認証バイパス** | ログイン認証をすり抜けて不正アクセスする攻撃 |
| **Langflow** | AIアプリをビジュアルに作れるオープンソースツール |
| **Apache Tomcat** | WebアプリやWebサービスを動かすオープンソースのWebサーバー |
| **N-able N-central** | 企業のITシステムを一元管理するリモート管理ツール |
| **DeepSeek** | 中国発の高性能AI。今回は攻撃者が悪用 |
| **Hermes Agent** | AIを使って自律的に攻撃を行うフレームワーク（今回悪用されたもの）|
| **SNOWLIGHT** | 今回の攻撃で使われた軽量なLinux向けマルウェア |
| **Cobalt Strike** | 本来はセキュリティテスト用の商用ツール。攻撃者にもよく悪用される |
| **C2（Command & Control）** | 攻撃者がマルウェアに指令を送るための指揮・制御サーバー |
| **トンネリング** | 通信を別の通信に「隠す」技術。攻撃の発覚を防ぐために使われる |
| **ドロッパー** | 本体のマルウェアをダウンロード・実行するための小さなプログラム |
