# ログインなしでサーバーのファイルが丸見え！GitEaの深刻な脆弱性

**元記事**: [Critical Gitea Flaw Let Unauthenticated Attackers Read Server Files via Org-Mode Markup](https://inl03.netline.com/ltr6/?_m=3n.009a.4048.sp0ao46r89.33rw)
**解説日**: 2026年8月6日

---

## 背景知識

まず、このニュースを理解するために必要な言葉をいくつか説明しましょう。

### 🗂️ Gitea（ギッティア）とは？
プログラマーたちが「ソースコード（プログラムの設計図）」を管理・共有するためのツールです。有名な「GitHub（ギットハブ）」と似たようなものですが、**自分のサーバーにインストールして使える**のが特徴です。企業や学校が「社内専用のGitHub」として使うことが多いです。

### 📁 ファイルサーバーとサービスアカウント
Giteaはサーバーというコンピューターの上で動いています。サーバー上には設定ファイルやデータベースのパスワードなど、重要なファイルがたくさんあります。Gitea自体もサーバー上で動くために「サービスアカウント（システム専用のアカウント）」を使っており、このアカウントがアクセスできるファイルはすべて危険にさらされた可能性があります。

### 📝 Org-mode（オルグモード）とは？
テキストを見やすく整形するための書き方のルールです。たとえばMarkdown（マークダウン）と似たようなもので、「`#+INCLUDE`」という命令を使うと**他のファイルの内容を読み込んで表示する**機能があります。今回はこの機能が悪用されました。

### 🔑 CVSSスコアとは？
脆弱性（セキュリティの弱点）の危険度を0〜10点で表したスコアです。10点が最も危険で、今回の脆弱性は**9.8点**という非常に高い危険度です。

---

## 何が起きたのか

Giteaのバージョン1.22.1から1.27.0に、**ログインしていない攻撃者でもサーバー内のファイルを自由に読み取れる**という深刻な脆弱性（CVE-2026-59774）が発見されました。

### ポイントをざっくりまとめると：

| 項目 | 内容 |
|------|------|
| 危険度 | 🔴 Critical（最高レベル）/ CVSSスコア 9.8 |
| 影響バージョン | Gitea 1.22.1 〜 1.27.0 |
| 攻撃に必要なもの | ログイン不要・公開リポジトリがあれば十分 |
| 修正バージョン | Gitea 1.27.1（修正済み） |
| 公式発表日 | 2026年8月2日 |

> 💡 「リポジトリ」とは、ソースコードや関連ファイルをまとめて保管する「フォルダのようなもの」です。

---

## 技術的な詳細

### 🏠 攻撃の入口：マークアップ変換機能

Giteaには、書いたテキストをきれいに表示するための機能（マークアップレンダリング）があります。このURLにアクセスすることで使えます：

```
POST /{リポジトリオーナー}/{リポジトリ名}/markup
```

この機能は「公開リポジトリ（誰でも見られるリポジトリ）」に対して、**ログインなしでも使える**仕様になっていました。

### 🔓 なぜ問題が起きたのか？

Gitea 1.27.0では、Org-mode形式のテキストを処理するために「go-org」というライブラリ（部品）を使っていました。

```
問題の流れ：
①  go-orgライブラリの初期設定がデフォルトのまま
　　　　↓
②  デフォルトの「ファイル読み込み機能」が有効なまま
　　　　↓
③  Org-modeの「#+INCLUDE」命令でサーバーのファイルパスを指定
　　　　↓
④  サーバー内の任意のファイルが攻撃者に返される！
```

たとえば、攻撃者が以下のようなテキストを送るだけで…

```org
#+INCLUDE: "/etc/passwd"
```

サーバーの重要なファイルの中身が丸見えになってしまいます。これは、図書館の司書に「この棚の本を読んで教えて」とお願いしたら、本来は見せてはいけない書庫の秘密文書まで読んでくれてしまうようなイメージです。

### 😨 さらに危険な「連鎖攻撃」の可能性

記事によると、ファイル読み取りだけでなく、**さらに危険な攻撃に発展する可能性**も指摘されています：

```
① app.ini（設定ファイル）を読み取る
　　↓
② INTERNAL_TOKEN（内部認証トークン）を入手
　　↓
③ Gitフックに悪意のあるコードを仕込む
　　↓
④ 誰かがリポジトリをダウンロードしたタイミングで実行！
```

> 💡「Gitフック」とはリポジトリの特定のタイミング（クローン時など）に自動で実行されるスクリプト（小プログラム）のことです。

ただし、この連鎖攻撃については現時点で実際の攻撃例は確認されていません。

### 🔧 修正方法

Gitea開発チームはバージョン1.27.1で修正しました。具体的には、`ReadFile`という関数（ファイルを読み込む命令）を**上書き（オーバーライド）**して、Org-modeの`#+INCLUDE`命令がサーバーのファイルシステムにアクセスできないようにしました。

## なぜ重要なのか

### 📊 影響の大きさ

- **ログイン不要**なので、世界中の誰でも攻撃を試みられる
- 「公開リポジトリ」さえあればOKなので、条件が非常に緩い
- **サービスアカウントが見られるファイルはすべて対象**になる
  - データベースのパスワード
  - 認証トークン（サービスへのアクセス証明書のようなもの）
  - SSHの秘密鍵（サーバーへのログイン情報）
  - その他の設定ファイル

### 📝 過去にも同様の問題が…

実は最近、Giteaではセキュリティ問題が続いています：
- **2026年5月**: 30,000以上の環境に影響するアクセス制御の欠陥（CVE-2026-27771）
- **2026年6月**: Dockerイメージの認証バイパス（CVE-2026-20896）→ 公開から13日後に攻撃が確認
- **今回（2026年8月）**: ファイル読み取り + リモートコード実行（CVE-2026-59774、CVE-2026-60004）

## 対策・今後の展望

### ✅ すぐにやるべきこと

**管理者向け（Giteaを運用している人）**

```
1. 【最優先】Gitea 1.27.1 にアップデートする
   ↓ クラウド版は自動更新されます
   ↓ 自分でサーバーを運用している人は手動で更新が必要！

2. ログを確認する
   → POSTリクエストが「/{owner}/{repo}/markup」に届いていないか確認

3. 不審なアクセスがあった場合は…
   → 以下の情報をすべて変更・無効化する
      ・内部トークン（INTERNAL_TOKEN）
      ・OAuthの認証情報
      ・JWTの署名情報
      ・データベースのパスワード
```

> 💡 「OAuth」「JWT」は、Webサービスの「本人確認に使う鍵」のようなものです。これが漏れると、なりすましが可能になります。

**一般ユーザー向け（Giteaを使っている人）**

```
→ 管理者に問い合わせて、バージョンが1.27.1以上か確認する
→ 心配な場合はパスワードを変更する
```

### 🔍 現状

- 2026年8月5日時点で、この脆弱性を悪用した攻撃は**報告されていない**
- CISA（米国サイバーセキュリティ機関）の「既知の悪用された脆弱性リスト」にはまだ掲載されていない
- ただし、修正前に脆弱性の概要が一部公開されていたため、早急な対応が推奨される

## 過去記事との関連

以前、**Linuxカーネルの「OVSwrap」脆弱性**（一般ユーザーが管理者権限を奪取できる欠陥）についてご紹介しましたが、今回のGiteaの脆弱性もそれと似た「権限を超えた操作が可能になる」タイプの問題です。

OVSwrapはすでにログインしているユーザーが必要でしたが、今回のGiteaの問題は**ログイン自体が不要**という点で、さらに深刻と言えます。どちらも「本来できないはずのことができてしまう」という本質的な問題は共通しており、ソフトウェアの設定や初期値（デフォルト値）の検証がいかに重要かを示す事例です。

## 用語解説

| 用語 | 説明 |
|------|------|
| **Gitea** | 自分のサーバーで運用できるGitHub的なサービス |
| **リポジトリ** | ソースコードやファイルをまとめて管理するフォルダのようなもの |
| **脆弱性（CVE）** | ソフトウェアのセキュリティ上の弱点。CVEは世界共通の識別番号 |
| **CVSSスコア** | 脆弱性の危険度を0〜10で表したスコア（10が最高危険度） |
| **Org-mode** | テキストをきれいに整形するための書き方の形式 |
| **#+INCLUDE** | Org-modeで他のファイルの内容を読み込む命令 |
| **サービスアカウント** | OSやアプリが自動で使うシステム専用のアカウント |
| **マークアップレンダリング** | テキストを解析して見やすく表示する処理 |
| **Gitフック** | Gitの特定操作をトリガーに自動実行されるスクリプト |
| **INTERNAL_TOKEN** | Gitea内部で認証に使う秘密の文字列 |
| **OAuth / JWT** | Webサービスで「本人確認」に使われる仕組みや証明書 |
| **CISA** | 米国のサイバーセキュリティ・インフラセキュリティ庁 |
| **リモートコード実行（RCE）** | 遠隔からサーバー上で任意のプログラムを実行できる攻撃 |
