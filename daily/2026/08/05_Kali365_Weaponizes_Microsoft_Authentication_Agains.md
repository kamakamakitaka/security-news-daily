# Kali365：マイクロソフトの本物の認証ページを悪用してアメリカ企業を狙う新たな脅威

**元記事**: [Kali365 Weaponizes Microsoft Authentication Against US Companies: New Enterprise Risk](https://inl03.netline.com/ltr6/?_m=3n.009a.4048.sp0ao46r89.33rk)
**解説日**: 2025年7月14日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な仕組みを押さえておきましょう。

### Microsoft 365とは？
マイクロソフトが提供するクラウドサービスの総称です。メール（Outlook）、ファイル共有（SharePoint・OneDrive）、文書作成（Word・Excelのオンライン版）などが含まれており、多くの会社で日常業務に使われています。「クラウド」とは、インターネット上にデータやサービスが置かれている仕組みのことです。

### デバイスコード認証とは？
通常、ログインはブラウザで「ID＋パスワード」を入力しますよね。でも、スマートTVやゲーム機など「文字入力が不便なデバイス」でもMicrosoftサービスを使えるように、別の方法があります。それが**デバイスコード認証**です。

仕組みはこうです：
1. 画面に短いコード（例：`ABCD-1234`）が表示される
2. スマホやPCで `microsoft.com/devicelogin` にアクセス
3. そのコードを入力する
4. ログイン完了！

テレビやゲーム機でYouTubeやNetflixにログインするときの「画面にコードが出るやつ」をイメージするとわかりやすいです。

### フィッシング詐欺とは？
本物そっくりの偽サイトや偽メールで、ユーザーをだましてパスワードや個人情報を盗む攻撃です。今回の攻撃はこれの「進化版」で、**本物のマイクロソフトのページを使う**という点がとても厄介です。

### OAuthトークンとは？
ログインが成功すると、マイクロソフトのサーバーは「この人は本物のユーザーです」という証明書のようなデータを発行します。これを**アクセストークン**といいます。このトークンを持っていれば、パスワードがなくてもサービスを使い続けることができます。「映画館の半券（入場証）」のようなものだと思ってください。

## 何が起きたのか

**「Kali365」という新しいフィッシング攻撃ツール（キット）が発見され、主にアメリカの企業を標的に、週80件以上の攻撃が確認されています。**

この攻撃が特別に危険な理由は、**マイクロソフトの「本物の」ログインページを悪用している**点です。被害者は偽サイトではなく、本当にマイクロソフトの正規ページでログインしているため、「怪しい」と気づきにくいのです。

まるで、本物の銀行の窓口で手続きをさせながら、裏で別の人間が口座を操作しているようなイメージです。

---

## 技術的な詳細

攻撃は3つのステップで行われます。

### ステップ1：おとりページを見せる（Lure）
攻撃者は、SharePoint・OneDrive・DocuSign（電子契約サービス）などの**本物そっくりの偽ページ**を用意します。社員がこのページにアクセスすると、「ログインが必要です」という画面が表示されます。

```
【イメージ】
偽のSharePointページ
「このドキュメントを見るにはログインしてください」
→ [ログインボタン]
```

### ステップ2：本物のマイクロソフトページへ誘導する（Microsoft Authentication）
ログインボタンを押すと、**本物の** `microsoft.com/devicelogin` に飛びます。そして画面に「このコードを入力してください」と表示されますが、**そのコードは攻撃者が用意したもの**です。

被害者は「本物のマイクロソフトのページだ、安全だ」と思ってコードを入力してしまいます。

```
【イメージ】
本物のマイクロソフトのページ（URLも本物！）
「コードを入力してください：WXYZ-9876」
← このコードは攻撃者が被害者に教えたもの
```

### ステップ3：トークンを盗む（OAuth Access）
被害者がコードを入力してログインを完了すると、マイクロソフトは「ログイン成功」のトークン（アクセスキー）を発行します。しかしそのトークンは、**攻撃者の手に渡ります**。

攻撃者はそのトークンを使って、被害者のメール・ファイル・クラウドデータに自由にアクセスできるようになります。しかも、トークンには「リフレッシュトークン」という仕組みがあり、**パスワードを変えても、しばらくはアクセスし続けられる**という問題があります。

```
【全体の流れ】
被害者：偽ページ → 本物のMSページ → コード入力 → ログイン完了（と思っている）
攻撃者：                         コードを渡す →           → トークン入手！
```

## なぜ重要なのか

この攻撃が企業にとって深刻な理由は、**一つのアカウントが乗っ取られるだけで、会社全体に被害が広がる**可能性があるからです。

| 被害の種類 | 具体的な内容 |
|-----------|-------------|
| **金銭的詐欺** | メールを操って、偽の請求書を送ったり、振込先を変えさせる「ビジネスメール詐欺（BEC）」 |
| **機密情報の漏洩** | 社内メール・顧客情報・機密文書が盗まれる |
| **業務妨害** | クラウドサービスが使えなくなり、日常業務がストップ |
| **対応コストの増大** | 攻撃の発見が遅れるほど、調査・復旧にかかる費用が膨らむ |
| **法的・信頼リスク** | 顧客データが漏れると、法律上の報告義務が発生し、会社の信頼が失われる |

特に、**普通のフィッシングより発見が難しい**という点が問題です。セキュリティソフトは「偽サイトへのアクセス」を検知しますが、本物のマイクロソフトページへのアクセスは正常な行動に見えてしまいます。

## 対策・今後の展望

### 個人・社員レベルでできること

1. **「コードを入力してください」には要注意**
   デバイスコードの入力を求められたとき、「自分がログインしようとしているのか？」を必ず確認しましょう。身に覚えのないコード入力要求は、絶対に行わないことです。

2. **URLだけでなく、操作の流れを疑う**
   「本物のURLだから安全」ではありません。**「なぜこの操作を求められているのか？」**を常に考えましょう。

3. **不審に思ったらすぐに報告**
   社内のIT担当者やセキュリティ部門にすぐ連絡しましょう。早期発見が被害を最小化します。

### 企業・IT担当者レベルでできること

- **条件付きアクセスポリシーの設定**：会社が管理していないデバイスからのデバイスコード認証をブロックする設定をMicrosoft Entra（旧Azure AD）で行う
- **最新の脅威情報（IOC）をSIEMやファイアウォールに取り込む**：攻撃者は頻繁にドメインやURLを変えるため、常に最新情報が必要
- **多要素認証（MFA）の徹底**：ただし、この攻撃はMFAをすり抜けることもあるため、それだけでは不十分

> 💡 **ポイント**：今回の攻撃は「メールフィルタリングだけでは防げない」と記事でも指摘されています。技術的な対策と、社員教育の両方が必要です。

## 用語解説

| 用語 | 解説 |
|------|------|
| **フィッシングキット（Phishing Kit）** | フィッシング攻撃を簡単に実行するための攻撃ツール一式。今回の「Kali365」がこれにあたる |
| **デバイスコード認証** | キーボード入力が不便なデバイス向けの、コードを使ったログイン方式 |
| **OAuthトークン / アクセストークン** | ログイン成功の証明として発行されるデジタルな「入場券」。これを持つと認証なしでサービスを使える |
| **リフレッシュトークン** | アクセストークンの有効期限が切れたときに、新しいトークンを取得するための鍵。長期間有効なことが多い |
| **IOC（Indicators of Compromise）** | 攻撃の痕跡や特徴を示す情報（悪意あるURLやIPアドレスなど）。セキュリティ機器に取り込んで検知に使う |
| **SIEM** | セキュリティイベントを一元管理・分析するシステム。会社のセキュリティ監視の中枢 |
| **SharePoint / OneDrive** | マイクロソフトのクラウドファイル共有サービス。今回の攻撃の「おとり」として使われた |
| **BEC（ビジネスメール詐欺）** | 企業の社員になりすまして、不正送金などを行う詐欺 |
| **MFA（多要素認証）** | パスワード以外にも、スマホの確認コードなど複数の認証要素を組み合わせたログイン方式 |
| **STIX/TAXII** | 脅威情報を共有するための標準フォーマットとプロトコル |

---

> 🔑 **まとめ**：Kali365は「本物のマイクロソフトのページを使う」という巧妙な手口で、メールフィルターやセキュリティソフトをすり抜けます。「本物のURLだから安全」という常識が通用しない攻撃です。「身に覚えのないコード入力要求には絶対に応じない」という意識を持つことが、最初の防衛線になります。
