# npmの「ワーム」が何百ものパッケージに感染！Claude CodeとVS Codeにも罠が仕掛けられていた

**元記事**: [Keyv-Linked npm Worm Poisons Hundreds of Packages, Plants Claude Code and VS Code Hooks](https://inl03.netline.com/ltr6/?_m=3n.009a.4048.sp0ao46r89.33sk)

## 背景知識

このニュースを理解するために、いくつかの基礎知識を整理しましょう。

### 📦 npm（エヌピーエム）って何？
**npm（Node Package Manager）** とは、JavaScriptというプログラミング言語で使われる「部品の倉庫」のようなものです。プログラマーが「ゼロから全部作る」のではなく、他の人が作った便利な部品（＝パッケージ）を借りてきて使えるようにするシステムです。

> 🍳 **料理で例えると**：カレーを作るとき、スパイスを一から調合する人は少なく、「市販のカレールー」を使いますよね。npmはその「カレールーの棚」のようなものです。世界中のプログラマーが棚に部品を置いており、誰でも取ってきて使えます。

### 🐛 ワームって何？
**ワーム（Worm）** は、コンピューターウイルスの一種で、**自分自身をコピーしながら広がっていく** 悪意のあるプログラムです。今回は「感染したパッケージが、さらに別のパッケージにも感染を広げる」という動き方をしました。

### 🔑 Keyv（キーヴィー）って何？
**Keyv** は、データを一時的に保存・管理するためのnpmパッケージです。多くのウェブアプリやシステムで使われている人気の部品で、これに感染が始まったことが今回の問題の出発点です。

### 🤖 Claude Code と VS Code って何？
- **VS Code（Visual Studio Code）**: Microsoftが作った、世界中のプログラマーが使う無料のコードエディタ（プログラムを書くためのアプリ）
- **Claude Code**: AI企業Anthropicが提供するAIコーディングアシスタント（AIがプログラミングを手伝うツール）

## 何が起きたのか

2026年8月4日、**npmという世界最大のJavaScript部品倉庫が大規模な感染被害を受けました**。

事の発端は `keyv@6.0.0` というパッケージの悪意ある公開です。このパッケージには、**見た目は普通の部品なのに、こっそり裏でパスワードや認証情報を盗み出すコードが仕込まれていました**。

さらに恐ろしいのは、そのパッケージが**自己増殖した**ことです。感染した開発者のコンピューターのnpm公開権限を使って、別のパッケージにも次々と感染を広げていきました。

被害の規模を調査機関ごとにまとめると：

| 調査機関 | 感染確認パッケージ数 |
|---------|----------------|
| SafeDep | 79パッケージ名 × 353バージョン |
| SafeDep（広域） | 353パッケージ名 × 442バージョン |
| Aikido | 868パッケージ名 × 1,381バージョン |

## 技術的な詳細

### 🪤 Step 1：罠の仕掛け方

攻撃者は `keyv@6.0.0` に **`preinstall`スクリプト** を仕込みました。

> 💡 **preinstallとは？**
> パッケージをインストールする「直前」に自動で実行されるプログラムのこと。ユーザーは何も知らずに「インストールボタンを押しただけ」なのに、裏で悪意のあるプログラムが動き出してしまいます。

```
普通のインストール：
「部品をダウンロード」→「使える状態にする」

今回の感染：
「部品をダウンロード」→【悪意のコードが自動実行！】→「使える状態にする」
```

### 🦠 Step 2：何を盗んでいたのか

感染したコードが収集していた情報は驚くほど広範囲でした：

- **GitHubのトークン**（ソースコードの管理サービスへのログイン鍵）
- **npmの公開権限**（パッケージを公開できる権限→これで感染が広がる！）
- **クラウドサービスの認証情報**（AWS、Googleクラウドなど）
- **データベースのパスワード**
- **Kubernetes（サーバー管理システム）の設定情報**
- **秘密鍵**（暗号通信に使う重要なデータ）
- **GitHub Actionsのメモリ内情報**（自動テスト・デプロイシステムのデータ）

### 🔄 Step 3：自己増殖の仕組み

> 🦠 **ウイルスの広がりで例えると**：
> 風邪をひいた人がドアノブを触る→次の人がそのドアノブを触って感染する、という連鎖と同じです。
>
> 今回の場合：感染した開発者のPC（npmの公開権限を持つ）→その権限を使って別のパッケージに感染コードを埋め込む→次の開発者がそのパッケージをインストールして感染…という連鎖が起きました。

### 🪝 Step 4：VS Code と Claude Code への罠

さらに今回の攻撃は **コードを書くツール自体にも罠を仕掛けていました**。

- **`.claude/settings.json`** に `SessionStart`フック（Claude Codeが起動したとき自動実行）
- **`.vscode/tasks.json`** に `folderOpen`タスク（VS Codeでフォルダを開いたとき自動実行）

> 🚪 **鍵のかかったドアで例えると**：
> インストール時の感染が「玄関から堂々と入る方法」だとすると、このフックは「裏口の鍵を仕掛けておく方法」です。インストールしなくてもリポジトリ（ソースコードの保管場所）を開くだけで実行される可能性がありました。

ただし、VS CodeもClaude Codeも「信頼していないワークスペースでは自動実行をブロックし、確認を求める」仕組みがあるため、**必ず感染するわけではありませんでした**。

## なぜ重要なのか

### 🌍 影響の大きさ
npmは世界中の開発者が毎日使うインフラです。今回感染した `keyv` や `flat-cache`、`cache-manager` などは、多くのウェブアプリの「縁の下の力持ち」として使われており、直接知らなくても間接的に使っていた可能性があります。

### 🔗 サプライチェーン攻撃という脅威
これは **「サプライチェーン攻撃」** と呼ばれる手口です。

> 🏭 **工場で例えると**：
> 車のブレーキパーツを作る小さな工場が不正部品を納入すると、その部品を使う大きな自動車メーカーも知らずに欠陥車を作ってしまいます。ソフトウェアも同じで、「信頼している部品」の中に悪意が混入されると、最終製品がどれだけ安全でも守れません。

### ⚡ CI/CD環境への感染が特に深刻
**CI/CD（継続的インテグレーション/継続的デリバリー）** とは、ソフトウェアを自動でテスト・公開するシステムです。ここに感染すると、**サービス全体の認証情報が一気に盗まれる**可能性があります。

## 対策・今後の展望

### 🚨 感染した可能性がある場合の対処（重要な順序あり！）

> ⚠️ **絶対に守るべき順序があります！**
> 今回の攻撃は「トークンが取り消された（ローテーションされた）タイミング」を監視して、攻撃者が用意したプログラムを動かす仕組みが含まれていました。**先に認証情報を変えると、攻撃者の罠を起動させてしまう危険があります！**

```
❌ 間違った順序：
トークン・パスワードを変える → 攻撃者の罠プログラムが起動！

✅ 正しい順序：
① マルウェアの「監視プログラム」を先に削除する
② その後でトークン・パスワードを変える
```

### 🛡️ 一般的な予防策

| 対策 | 内容 |
|------|------|
| **npm 12へのアップグレード** | npm 12はデフォルトで未承認のlifecycleスクリプトをブロックします |
| **lockfileの活用** | `package-lock.json`などで使用バージョンを固定し、意図しないアップデートを防ぐ |
| **最小権限の原則** | npm公開権限を持つアカウントは必要最小限に |
| **定期的なトークンの監査** | 使っていない認証情報は削除する |
| **ワークスペースの信頼設定** | VS CodeやClaude Codeで見知らぬプロジェクトを「信頼」しない |

### 🔍 感染確認の方法
- パッケージ名と **正確なバージョン番号** で確認（タグ（latestなど）は変わっているため信用できない）
- `lockfile`（バージョンを固定するファイル）を使って、実際にインストールされたバージョンを確認する

## 用語解説

| 用語 | 解説 |
|------|------|
| **npm** | JavaScriptの部品（パッケージ）を管理・公開する世界最大のレジストリ |
| **パッケージ** | プログラムの再利用できる部品のまとまり |
| **ワーム** | 自己増殖して広がるマルウェア（悪意のあるプログラム） |

| **トークン** | パスワードの代わりに使われる認証情報（文字列） |
