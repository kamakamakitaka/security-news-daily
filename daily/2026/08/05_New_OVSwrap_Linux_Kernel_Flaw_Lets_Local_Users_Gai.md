# Linux カーネルの「OVSwrap」脆弱性：一般ユーザーが管理者権限を奪取できる深刻な欠陥

**元記事**: [New OVSwrap Linux Kernel Flaw Lets Local Users Gain Root via Open vSwitch](https://inl03.netline.com/ltr6/?_m=3n.009a.4048.sp0ao46r89.33re)
**解説日**: 2025年7月29日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### 🐧 Linux カーネルって何？
**カーネル**とは、コンピューターのOS（オペレーティングシステム）の「心臓部」にあたるプログラムです。ハードウェア（CPU・メモリ・ネットワーク等）とソフトウェアの橋渡し役をしており、すべての操作はカーネルを経由します。LinuxはサーバーやクラウドなどのIT基盤で世界中で使われているOSです。

### 🌐 Open vSwitch（OVS）って何？
**Open vSwitch（オープン ブイスイッチ）**とは、仮想的なネットワークスイッチを作るためのソフトウェアです。  
現実の世界では、コンピューター同士をLANケーブルと「スイッチ（ハブ）」という機器でつなぎます。クラウド環境やデータセンターでは、仮想マシン（VM）同士をつなぐために、ソフトウェアで同じことをする必要があります。それが Open vSwitch の役割です。

> 🏫 **例え話**: 学校の教室で生徒同士が会話するとき、リアルの教室なら先生が間に立って整理します。クラウドの仮想マシンにとって、Open vSwitch はその「バーチャル先生」みたいな存在です。

### 👑 root（ルート）権限って何？
Linuxには「**root（ルート）**」という特別なユーザーアカウントがあります。Windowsで言う「管理者（Administrator）」に相当し、システム上のあらゆる操作が可能な「神様アカウント」です。  
通常の一般ユーザーは root になれないよう制限されています。今回の問題は、その制限を突破できてしまうというものです。

### 🧠 メモリ破壊（Memory Corruption）って何？
コンピューターのプログラムは、動作中に「メモリ（RAM）」にデータを書き込んで読み取ります。**メモリ破壊**とは、本来書いてはいけない場所に不正なデータを書き込んでしまうバグのことです。これを悪用されると、攻撃者がプログラムの動作を乗っ取ることができます。

## 何が起きたのか

2026年7月28日、セキュリティ研究者の **Asim Manizada（アシム・マニザダ）氏**が、Linux カーネルに潜む重大な脆弱性（セキュリティの欠陥）を公開しました。

この脆弱性は **「OVSwrap（オーブイエスラップ）」** と名付けられ、**CVE-2026-64531** という管理番号が付いています。

### 📊 深刻度は？
**CVSS スコア 7.8 / 10（「重要」レベル）**  
10点満点で7.8点という、かなり深刻な評価です。

### ⚠️ 何ができてしまうのか？
**一般ユーザー（通常の権限しかない人）が、root（神様権限）を乗っ取れてしまいます。**

しかも条件が非常に緩く：
- OVS の設定や起動は不要
- 特別なネットワーク設定も不要
- 多くの Linux ディストリビューション（バリエーション）のデフォルト設定で再現可能

という恐ろしい特徴があります。

## 技術的な詳細

少し難しいですが、できるだけわかりやすく説明します！

### 🔢 「16ビットの桁あふれ（オーバーフロー）」が根本原因

コンピューターは数字を「ビット」という単位で管理します。**16ビット**で表現できる最大の数は **65,535** です。

Open vSwitch は、ネットワークの「フロー（通信の流れ）」を処理するときに、データの長さを **16ビットの数値フィールド（`nla_len`）** に記録していました。

> 🧮 **例え話**: 65,535円までしか入力できないレジスターに、70,000円と打ち込もうとすると「4,465円」と表示されてしまう…そんな「桁あふれ」のイメージです。

### 📅 13年前からあったバグが、2025年に「解放」された

実は、この桁あふれを起こすコードは **13年前**から存在していました。しかし、当時は「1回の通信処理で生成できるデータ量を32KiB（キビバイト）に制限する」という別のコードが安全弁として機能していたため、問題が表面化しませんでした。

ところが **2025年3月**、その32KiBの制限が削除されました。理由は、OpenStack（クラウド基盤ソフト）などの大規模環境で予測不能なエラーを引き起こしていたからです。しかしその際、削除によって古いバグが「解放」されるというセキュリティリスクが見落とされてしまいました。

```
[状況のイメージ図]

2012年〜2025年3月
┌─────────────────────┐
│  危険なコード（バグ）  │ ← 13年間眠っていた
│  ↑                   │
│  32KiBの安全弁 🛡️    │ ← これが守っていた
└─────────────────────┘

2025年3月以降
┌─────────────────────┐
│  危険なコード（バグ）  │ ← 完全に露出！
│  ↑                   │
│  安全弁が削除された ❌ │
└─────────────────────┘
```

### 🔓 攻撃の流れ（3ステップ）

**① 権限昇格の準備**  
Linux には「ユーザー名前空間（user namespace）」という機能があり、一般ユーザーが「自分だけのミニ仮想空間」を作れます。攻撃者はこの空間の中で、限定的なネットワーク管理権限（`CAP_NET_ADMIN`）を手に入れます。

**② バグを意図的に発動させる**  
攻撃者は「CLONE アクション（通信の複製命令）」に大量の `conntrack（コントラック）サブアクション` を詰め込んで送ります。処理するとデータが65,535バイトを超え、16ビットフィールドが「桁あふれ」を起こします。

**③ メモリを乗っ取る**  
桁あふれ後、カーネルは壊れた長さデータを信じてしまい、**攻撃者が仕込んだ偽のデータをカーネル命令として実行してしまいます。** これにより：

| 手順 | 何をするか |
|------|-----------|
| カーネルポインタリーク | カーネル内の重要なアドレスを読み取る |
| 任意カーネル読み取り | カーネルメモリの任意の場所を読む |
| 資格情報の書き換え | ユーザーの権限情報（UID等）を0（=root）に書き換える |

研究者はこの攻撃を「ロジックバグ並みの安定性」と表現しており、複雑なメモリ操作なしに**ほぼ確実に成功する**としています。

## なぜ重要なのか

### 📢 影響を受けるディストリビューション（記事記載分）
非常に多くの主要 Linux 環境がデフォルト設定で影響を受けると確認されています：

- **AlmaLinux** 9・10
- **Alpine Linux** 3.22〜3.24
- **Amazon Linux** 2023
- **Arch Linux**
- **CentOS** など

これらはサーバー・クラウドインフラで広く使われているため、影響は非常に広範囲です。

### 🔐 既製の攻撃コードが公開済み
研究者は **約800種類のカーネルビルドに対応した攻撃コード（PoC）** を公開しています。  
つまり、攻撃者が「既製品の武器」を手に入れやすい状態にあります。

### 💥 ローカル権限昇格の怖さ
「ローカル攻撃（ログイン済みユーザーによる攻撃）」と聞くと「外部からの攻撃より安全では？」と思うかもしれません。しかし：

> - **クラウド環境**：別テナントのコンテナや VM からの攻撃起点になる可能性
> - **シェアードサーバー**：複数人が使うサーバーで、一人の悪意ある利用者が全体を掌握できてしまう
> - **侵害済み環境**：すでに一般ユーザーとして侵入した攻撃者が、さらに権限を昇格できる

という深刻なシナリオが考えられます。

## 対策・今後の展望

### ✅ 今すぐできる対策

**1. カーネルをアップデートする（最優先）**

修正済みのカーネルバージョンが公開されています：

| バージョン系列 | 修正済みバージョン |
|--------------|----------------|
| Linux 5.15.x | 5.15.212 以降 |
| Linux 6.1.x  | 6.1.178 以降 |
| Linux 6.6.x  | 6.6.145 以降 |
| Linux 6.12.x | 6.12.97 以降  |
| Linux 6.18.x | 6.18.40 以降  |
| Linux 7.1.x  | 7.1.5 以降    |

> ⚠️ **注意**: バージョン番号だけで判断せず、必ず**使用しているLinuxディストリビューション（Ubuntu, Red Hat等）の公式アップデート情報**を確認してください。各ディストリビューションは独自の修正を含む場合があります。

**2. アップデートが間に合わない場合の応急処置**

Open vSwitch が不要な環境では：

```bash
# カーネルモジュールのロードをブロックする
echo "install openvswitch /bin/false" >> /etc/modprobe.d/disable-ovs.conf

# すでにモジュールがロードされている場合はアンロード
sudo modprobe -r openvswitch
# ↑うまくいかない場合は再起動
```

> 💡 **ポイント**: `lsmod` コマンドで openvswitch が表示されなくても安全とは限りません。名前解決だけで自動ロードされる可能性があります。

**3. 影響を受けるかチェックする**
以下の条件が両方当てはまる場合は要注意です：
- ✅ OVS カーネルデータパスが利用可能
- ✅ 非特権ユーザー名前空間（unprivileged user namespaces）が有効

### 📅 修正の経緯
- **2026年6月19日**: 研究者が security@kernel.org に報告
- **2026年7月24日**: 上流（upstream）の修正がリリース
- **2026年7月28日**: 脆弱性が公開

> ⚠️ バージョン 6.13〜6.17、6.19、7.0 系列は**サポート終了（EOL）**のため、修正パッチが提供されません。これらを使用している場合は早急なバージョンアップが必要です。

## 過去記事との関連

今回は単独の解説となりますが、このニュースは **「Linux カーネルのローカル権限昇格脆弱性」** という類型の中でも特に注目すべきケースです。

一般的に Linux カーネルの権限昇格脆弱性は過去にも度々発見されており（例：Dirty COW / CVE-2016-5195 など）、その都度大きな影響を与えてきました。今回の OVSwrap が特に注目される点は：

1. **既製の攻撃コードが公開済み**で悪用ハードルが低い
2. **デフォルト設定の主要ディストリビューションで再現可能**
3. **13年前のコードが遠因**という「技術的負債」の問題

という複合的な要因があることです。

## 用語解説

| 用語 | 説明 |
|------|------|
| **Linux カーネル** | Linux OS の中核プログラム。ハードウェアとソフトウェアの橋渡し役 |
| **Open vSwitch (OVS)** | 仮想環境でネットワークスイッチを再現するソフトウェア |
| **root権限** | Linux の最高管理者権限。すべての操作が可能 |
| **CVE** | Common Vulnerabilities and Exposures の略。脆弱性の管理番号 |
| **CVSS スコア** | 脆弱性の深刻度を0〜10で数値化したもの |
| **メモリ破壊（Memory Corruption）** | 本来書いてはいけないメモリ領域に不正データを書き込むバグ |
| **整数オーバーフロー（桁あふれ）** | 数値が最大値を超えて、誤った値（例：0付近）に戻ってしまう現象 |
| **ローカル権限昇格** | すでにログイン済みのユーザーが、より高い権限（root等）を不正取得すること |
| **PoC（Proof of Concept）** | 脆弱性が実際に悪用可能なことを示す概念実証コード |
| **カーネルモジュール** | カーネルに機能を追加できる着脱可能なプログラム部品 |
| **ユーザー名前空間** | Linux の機能で、一般ユーザーが隔離された仮想空間を作れる仕組み |
| **Netlink** | Linux カーネルとユーザースペースが通信するための仕組み |
| **conntrack** | ネットワーク接続の状態を追跡する Linux カーネルの機能 |
| **EOL（End of Life）** | サポート終了。セキュリティ修正が提供されなくなる状態 |
| **技術的負債** | 過去の設計判断が後になって問題を引き起こすこと |
