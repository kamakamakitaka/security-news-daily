# AWS・Google・Vercelのエージェント基盤に欠陥——AIに許可を取らずにツールを動かせてしまう脆弱性が発見された

**元記事**: [AWS, Google, and Vercel Agent Flaws Let Attackers Trigger Tools Without Running the Model](https://inl03.netline.com/ltr6/?_m=3n.009a.4049.sp0ao46r89.33tm)
**解説日**: 2026年8月6日

---

## 背景知識

### 「AIエージェント」って何？

最近、ChatGPTのようなAI（人工知能）が単に会話するだけでなく、**自分でパソコンを操作したり、ファイルを作ったり、ウェブ検索したりできる**ようになってきました。これを **「AIエージェント」** と呼びます。

イメージとしては、こんな感じです：

```
あなた：「今日の天気を調べてレポートにまとめて」
　　　↓
AIエージェント：
  ① AIが考える（「天気API（気象情報サービス）を呼び出そう」）
  ② ツールを使う（天気APIを呼び出す）
  ③ 結果をまとめてレポートを作る
```

この「ツールを使う」という動作の**許可証がちゃんと確認されていなかった**のが今回の問題です。

### 関係する会社とサービス

| 会社 | 問題があったサービス |
|------|------|
| **AWS（Amazon）** | Bedrock AgentCore（クラウド上のAIエージェント基盤） |
| **Google** | Agent Development Kit（ADK）for Python（AIエージェントを作るツール） |
| **Vercel** | AI SDK（AIを使ったアプリを作るためのツール） |

### 「SDK」って何？

**SDK（Software Development Kit）** とは、アプリを作るための「道具セット」のことです。料理で例えると、包丁・まな板・鍋など調理器具がそろったセットのようなものです。

## 何が起きたのか

セキュリティ研究者の **Hedi Ingber氏とAviyam Ivgi氏**（会社「Stealth」の共同創業者）が、2026年8月5〜6日に開催された世界最大級のセキュリティカンファレンス **「Black Hat USA 2026」** でこの問題を発表しました。

彼らが発見した攻撃手法の名前は **「CoreBreak（コアブレイク）」** です。

### 問題の核心：「AIに相談しないでツールを動かせる」

普通のAIエージェントの動き方はこうです：

```
【正常な流れ】
攻撃者/ユーザー
　　↓ リクエスト送信
AIモデル（GPTなど）が考える ← ここで悪い命令をフィルタリング！
　　↓ 「このツールを使っていいよ」と判断
ツール実行（ファイル削除・外部サービス呼び出しなど）
```

ところが今回発見された脆弱性（セキュリティの穴）では：

```
【攻撃の流れ】
攻撃者
　　↓ 「AIが許可したように見せかけた偽の命令」を送る
AIモデルが判断する部分をスキップ！← フィルタリングが一切なし
　　↓
ツール実行（攻撃者の思い通りに！）
```

つまり、**「AIの頭脳」を完全に飛ばして、手足（ツール）だけを直接動かせてしまう**という穴です。

## 技術的な詳細

### 「ToolUse（ツール使用指示）」の偽造

AIエージェントでは、AIモデルが「このツールを使って」と決めたとき、**構造化されたデータ（ToolUseブロック）** をSDKに送ります。SDKはそれを受け取り、ツールを実行します。

問題は、**「そのToolUseブロックが本当にAIが作ったものかどうか」を確認していなかった**ことです。

🔑 **カギの例え話**
> 金庫を開けるカギがあるとします。
> 本来は「社長（AI）がOKを出したカギ」だけが使えるはずなのに、
> 誰かが社長のハンコを偽造したカギを作っても、
> 金庫の鍵穴が偽造かどうか確認しないで開けてしまった——
> それが今回の問題です。

### 各社の具体的な問題点

#### AWS（CVE-2026-18830、深刻度スコア8.6/10）
- **問題**: 認証済みユーザー（つまりアカウントを持っている人）が、リクエストの最後のメッセージに偽のToolUseブロックを差し込める
- **影響**: AIを動かさずに、任意のツールを直接実行できる
- **修正**: サーバー側で自動修正済み（利用者の対応不要）

#### Google（ADK）
- **問題**: 攻撃者がコントロールするセッションイベントや、ユーザーが書いた関数を通じて偽の指示を送り込める
- **修正**: **ADK 2.5.0** で修正済み

#### Vercel
- **問題**: すでに悪意あるコードがLinuxのサンドボックス（隔離された実行環境）の中で動いている場合に悪用可能
- **修正**: 
  - `@ai-sdk/harness-codex` バージョン **1.0.29** で修正
  - `@ai-sdk/harness-opencode` バージョン **1.0.28** で修正

### AWSのオープンソース部分（Strands）には穴が残っている

AWSのクラウドサービス側は修正されましたが、その土台となっているオープンソース（誰でも使える無料ソフト）の **「Strands」** のコードには、まだ同じような抜け道が残っています。

コード内には「**最新のメッセージにToolUseが含まれていたら、モデルの実行をスキップする**」というコメントと処理が書かれており、2026年8月5日時点でもその部分は修正されていませんでした。

さらに、この問題は **2026年4月にプルリクエスト（修正提案）が出されていた** にもかかわらず、6月19日に採用されないままクローズされていたことも判明しています。

## なぜ重要なのか

### AIエージェントのセキュリティの「新しい問題」

これまでのセキュリティ対策は、主に「AIに悪いことを言わせないようにする」（プロンプトインジェクション対策など）に集中していました。

しかし今回の脆弱性は全く違う視点からの攻撃です：

> ❌ 従来の発想：「AIをだまして悪いことを言わせよう」
> ✅ 今回の攻撃：「AIをそもそも通さなければ、AIのガードは意味がない」

### 被害の大きさはエージェントの「権限」次第

重要なポイントとして、**エージェントに何の権限も与えていなければ、攻撃者には何もできません**。

| エージェントの権限 | 攻撃の影響 |
|---|---|
| 天気を調べるだけ | ほぼ無害 |
| ファイルの読み書き | ファイル盗難・改ざん |
| メール送信 | なりすましメール送信 |
| 外部サービスの操作 | サービス悪用・データ流出 |

つまり「**AIエージェントに強力な権限を与えているほど危険**」ということになります。

### 影響を受ける人

- AWSのBedrock AgentCoreを使ってシステムを開発している企業・開発者
- GoogleのADK（バージョン2.5.0未満）を使っている開発者
- VercelのAI SDKを使ってコーディングエージェントを作っている開発者

## 対策・今後の展望

### すぐにやるべきこと

| 利用サービス | 対策 |
|---|---|
| **AWS Bedrock AgentCore** | ✅ 自動修正済み・対応不要 |
| **Google ADK** | 🔄 **ADK 2.5.0以上** にアップデート |
| **Vercel @ai-sdk/harness-codex** | 🔄 **バージョン1.0.29以上** にアップデート |
| **Vercel @ai-sdk/harness-opencode** | 🔄 **バージョン1.0.28以上** にアップデート |
| **Strands（オープンソース）** | ⚠️ 未修正のため、信頼できない入力を受け付けないよう設計を見直す |

### 開発者が意識すべきこと（最小権限の原則）

🏆 **セキュリティの鉄則：エージェントには必要最低限の権限だけ与える**

```
❌ 悪い例：何でもできるエージェント
   → ファイル削除・メール送信・外部API操作…なんでもOK

✅ 良い例：目的に絞ったエージェント
   → 「天気を調べる」だけの機能しか持たせない
```

### 今後の展望

AIエージェントは今後ますます広まり、より強力な権限を持つようになります。今回の「CoreBreak」のような**「AI本体を迂回する攻撃」**は、これからのAIセキュリティの重要な研究分野になるでしょう。

## 過去記事との関連

以前、**「OracleデータベースへのSQLインジェクション攻撃」** について解説しました。あの記事では「入力値のチェックが不十分だと、攻撃者に意図しない処理を実行させてしまう」という問題でした。

今回の「CoreBreak」も本質は同じで、**「入力値（ToolUseブロック）の出所（本当にAIが生成したものか）を確認していなかった」** ことが根本的な原因です。

どちらも **「信頼すべきでない入力を信頼してしまった」** という古典的なセキュリティの失敗パターンです。技術が新しくなっても、基本的なミスは変わらないということですね。

## 用語解説

| 用語 | 説明 |
|------|------|
| **AIエージェント** | 自律的に考えてツール（機能）を使い、タスクをこなすAIシステム |
| **SDK（Software Development Kit）** | アプリ開発のための道具セット |
| **ToolUseブロック** | AIが「このツールを使って」と伝えるための構造化されたデータ |
| **CVE** | 脆弱性に付けられる世界共通の識別番号（例：CVE-2026-18830） |
| **CVSS** | 脆弱性の深刻度を0〜10で表すスコア（8.6は「高」レベル） |
| **プロンプトインジェクション** | AIへの指示（プロンプト）に悪意ある命令を混ぜ込む攻撃 |
| **サンドボックス** | 外部への影響を制限した隔離された実行環境 |
| **オープンソース** | ソースコードが公開されており誰でも使えるソフトウェア |
| **プルリクエスト** | オープンソースプロジェクトへのコード修正提案 |
| **最小権限の原則** | 必要最低限の権限だけを与えるセキュリティの基本原則 |
| **Black Hat** | 世界最大級のサイバーセキュリティカンファレンス |
| **CoreBreak** | 今回発見された攻撃パターンの名称 |
