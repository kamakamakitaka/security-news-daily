# Apple iCloudプライベートリレーの欠陥で本当のIPアドレスがバレてしまう問題が発覚

**元記事**: [Apple iCloud Private Relay Can Expose Real IPs Through WebKit Proxy Bypasses](https://inl03.netline.com/ltr6/?_m=3n.009a.4049.sp0ao46r89.33sy)
**解説日**: 2025年7月10日

---

## 背景知識

まず、このニュースを理解するための基礎知識を押さえておきましょう。

### 🌐 IPアドレスとは？
インターネット上で「あなたのデバイス（スマホやPC）がどこにあるか」を示す番号です。住所のようなものです。IPアドレスがわかると、あなたが**どの国・地域から、どのサイトを見ているか**が第三者に把握されてしまう可能性があります。

### 🔒 iCloud プライベートリレーとは？
Appleが2021年に導入したプライバシー保護機能で、**iCloud+（有料プラン）** のユーザーが使えます。Safariでのウェブ通信を「2つの中継サーバー（リレー）」を通して行うことで、誰もあなたの本当のIPアドレスやアクセス先サイトを同時に知ることができない仕組みです。

> **例え話**：手紙を出すとき、自分で直接送らず、2人の仲介者（A→B→宛先）に渡すようなイメージです。AはあなたのIPを知っているけど宛先は知らない。Bは宛先を知っているけどあなたのIPは知らない。これにより誰にも全情報がわからない状態を作っています。

### 🔧 WebKitとは？
AppleのブラウザエンジンでSafariの「内側」にある部分です。重要なのは、**iPhoneやiPad（iOS/iPadOS）では、ChromeやFirefoxなどの他社ブラウザも、実はすべてWebKitを使って動いている**という点です。

### 🔑 パスキー（WebAuthn）とは？
パスワードの代わりに顔認証や指紋を使ってログインできる新しい仕組みです。「WebAuthn（ウェブオートン）」という技術が使われており、多くのサービスが対応を進めています。

---

## 何が起きたのか

セキュリティ研究者の**Talal Haj Bakry氏とTommy Mysk氏**が、iCloudプライベートリレーを使っていても、ユーザーの**本当のIPアドレスが漏れてしまう**欠陥を発見・公表しました。

原因はWebKitに含まれる**3つの機能のバグ**です。これらの機能が、プライベートリレーの「中継ルート」を迂回して、デバイスから**直接インターネットに通信してしまう**ことで、本当のIPアドレスがウェブサイト側に丸見えになってしまいます。

> **例え話**：せっかく2人の仲介者（A・B）を使って手紙を出そうとしているのに、一部の通信が「こっそり自分の住所を書いた直送便」で送られてしまっているようなイメージです。

---

## 技術的な詳細

問題のある3つの機能を、それぞれわかりやすく説明します。

### ① DNS プリフェッチ（先読み）
**DNS**とは「ウェブサイトの名前（例：google.com）をIPアドレスに変換する仕組み」です。プリフェッチはページを速く表示するために「先読み」する機能ですが、この処理がプロキシ（中継サーバー）を通らず**デバイスから直接**行われてしまいます。

### ② WebAuthn 関連オリジンリクエスト
パスキーでログインするとき、WebKitが「確認ファイル」を取りに行く通信も、プロキシを通らず直接デバイスから送信されます。**悪意のあるウェブサイトがWebAuthnを意図的に設定するだけ**で、ユーザーの本当のIPアドレスを取得できてしまいます。しかも**ユーザー側の操作は一切不要**です。

### ③ WebTransport
HTTP/3という新しい通信規格を使う機能ですが、こちらも**プロキシをスキップして直接接続**を確立してしまいます。

### 影響を受けるデバイス
| デバイス | 影響 |
|---|---|
| iPhone / iPad（iOS/iPadOS） | ⚠️ すべてのブラウザで影響あり |
| Mac（macOS） | ⚠️ WebKitベースのブラウザで影響あり |
| PC（Windows等）のChrome | ✅ 影響なし |
| VPN使用中 | ✅ 漏洩が軽減される |

## なぜ重要なのか

### 🎯 プライバシー保護ツールが「信用できない」状態に
iCloudプライベートリレーはそもそも「IPアドレスを隠すため」の機能です。その機能がオンになっていても本当のIPアドレスが漏れるなら、**有料サービスに対してユーザーは期待を裏切られている**ことになります。

### 😈 悪用されるシナリオ
特に怖いのは**WebAuthnを使った攻撃**です。

- 悪意のあるウェブサイトが、パスキー機能を「罠」として設定しておくだけ
- ユーザーがそのサイトを訪問すると…
- ユーザーは何も操作していないのに本当のIPアドレスが取得される

これにより、たとえばプライベートリレーで「匿名」のつもりでアクセスしていたユーザーを、**IPアドレスで特定・追跡**されるリスクがあります。

### 📱 iPhoneユーザーへの影響が大きい
iPhoneでは他社ブラウザもWebKitを使っているため、「Safariを使っていないから大丈夫」とはなりません。ChromeもEdgeもFirefoxも同様に影響を受けます。

## 対策・今後の展望

### ✅ 今すぐできること

1. **VPNを使う**：研究者によると、VPN使用中はこの漏洩が軽減されると報告されています
2. **iOSのアップデートを常に最新にする**：Appleが修正パッチを出した際に素早く適用できます
3. **自分が漏洩しているか確認する**：研究者が公開したテストサイト `leaks.psylo[.]app` で確認できます（接続して「Possible IP leaks」の欄を見てください）

### 🍎 Appleの対応は？
現時点ではAppleは「調査中」と述べており、まだ公式な修正パッチはリリースされていません。今後のiOS/macOSアップデートで修正が来ることが期待されます。

> **ポイント**：修正パッチが出たらすぐにアップデートしましょう！

## 過去記事との関連

実は、iCloudプライベートリレーのIPアドレス漏洩問題は**今回が初めてではありません**。

- **2021年（機能リリース直後）**：「WebRTC」という技術を使って本当のIPアドレスが漏洩する問題が発見されました（FingerprintJSによる報告）
- **最近**：Appleの「メールを隠す（Hide My Email）」機能でも、特定の条件下で本当のメールアドレスが漏洩する脆弱性が発見・修正されたばかりです

Appleのプライバシー系機能にはこのように繰り返し脆弱性が発見されており、**「機能を信頼しすぎない」「VPNと組み合わせる」「アップデートをこまめに行う**」という姿勢が大切だと言えます。

## 用語解説

| 用語 | 意味 |
|---|---|
| **IPアドレス** | インターネット上のデバイスの「住所」。場所や通信先の特定に使われる |
| **iCloudプライベートリレー** | AppleのiCloud+機能。2つの中継サーバーを使って通信を匿名化する |
| **WebKit** | Safariの内部エンジン。iOSでは全ブラウザが使用している |
| **プロキシ** | 通信の「中継サーバー」。本来の通信経路を隠すために使う |
| **DNS** | ウェブサイト名をIPアドレスに変換する仕組み（電話帳のようなもの） |
| **WebAuthn / パスキー** | パスワード不要でログインできる技術。指紋・顔認証などを利用 |
| **WebTransport** | HTTP/3を使った新しい通信方式 |
| **VPN** | 通信を暗号化・匿名化するツール。プライベートリレーと似た役割 |
| **PoC（概念実証）** | 「この攻撃は本当に成立する」と示すための実証コードやサイト |
| **脆弱性（ぜいじゃくせい）** | システムのセキュリティ上の弱点・欠陥のこと |
