# 中国製Zbtlinkルーターに「工場出荷時バックドア」——認証なしで管理者権限を奪われる危険性

**元記事**: [Chinese-Made Zbtlink Routers Ship With Backdoor That Opens Unauthenticated Root Shells](https://inl03.netline.com/ltr6/?_m=3n.009a.4049.sp0ao46r89.33ts)
**解説日**: 2025年7月

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### 🏠 ルーターとは？
インターネットと家庭内・社内ネットワークをつなぐ「玄関口」となる機械です。すべての通信がここを通るため、ルーターを乗っ取られると、ネットワーク上のあらゆる通信を覗き見たり改ざんしたりされる可能性があります。

### 🚪 バックドアとは？
「裏口」という意味で、正規のログイン手続きを踏まずに、こっそりシステムに侵入できる隠し経路のことです。泥棒がこっそり合鍵を作っておくようなイメージです。

### 👑 root権限とは？
Linuxというコンピューターの基本ソフト（OS）において、「なんでもできる最高管理者」の権限のことです。Windowsでいう「管理者権限」よりもさらに強力で、システムのあらゆる設定・ファイル・機能を自由に操作できます。

### 🖥️ C2（コマンド＆コントロール）インフラとは？
攻撃者が遠隔地から感染した機器に命令を送るためのサーバーです。「司令塔」のようなものです。

### 📡 ファームウェアとは？
機械（この場合はルーター）を動かすための基本的なプログラムです。パソコンのWindowsやmacOSに相当するもので、ルーターの全機能はここに詰まっています。

---

## 何が起きたのか

セキュリティ研究会社の**VulnCheck**が、中国のルーターメーカー「**Zbtlink（ZBTリンク）**」が製造・販売する**少なくとも20機種のルーター**に、「工場出荷時点から」バックドアが仕込まれていることを発見・公表しました。

この悪質な仕掛けは **ENDLESSDOORS（エンドレスドアーズ＝終わりなき扉）** と名付けられました。

### 🔑 ポイントをまとめると：

| 項目 | 内容 |
|------|------|
| 影響機種 | 20種以上のZbtlinkルーター |
| ファームウェア | 公式サイト掲載の全21個のファームウェアに含有 |
| 期間 | 2年以上にわたるファームウェアすべて |
| 危険度 | **最高レベル**（認証なしでroot権限を取得可能） |
| バックドアの動作 | **35秒ごと**に中国の司令塔サーバーへ自動接続 |

## 技術的な詳細

### 📦 バックドアの正体

バックドアの核心は「**rctl（remote control linux＝リモートコントロール Linux）**」という小さなプログラムです。

実は、このプログラムは**2015年1月14日にGitHub（ソフトウェア共有サービス）に公開されたオープンソースツール**です。それ以来、一度も更新されていない古いツールを、ルーターに密かに組み込んで使っているのです。

### 🎭 どうやって隠れているのか？

```
【正規のプロセス】 kworker（カーネルワーカー）
       ↑ そのフリをしている
【バックドア】    rctl（カスタマイズ版）
```

Linuxには「**kworker**」という、システムの裏側で普通に動く正規プロセス（プログラム）があります。バックドアはこれに**名前を偽装**して、管理者が見ても「普通のシステム動作だ」と思わせるよう隠れています。

### 📞 「電話帰宅」の仕組み

ルーターが起動すると、バックドアは自動的に動き始め、以下の流れで攻撃者のサーバーに接続を試みます：

```
ルーター起動
   ↓
バックドア自動起動（init.d スクリプト「skworker」経由）
   ↓
35秒ごとに司令塔サーバーへ「ハロー＋MACアドレス」を送信
   ↓
サーバーから命令を受け取る
   ↓
命令を「最高管理者権限（root）」で実行
```

### 🌐 接続先のサーバー（司令塔）

全機種が共通して以下の4つのサーバーに接続を試みます：

- `zbtctl.epplink[.]net`（中国系IPアドレス）
- `47.107.224[.]89`
- `online-string[.]com`
- `rbdg4nzqadui.wikaba[.]com`

### 💀 最も危険な点：認証が一切ない

通常、サーバーに接続する際はパスワードや証明書などで「正規の相手かどうか」を確認します（これを「認証」といいます）。

しかしENDLESSADOORSには**認証が一切ありません**。

```
【普通の安全な通信】
  ルーター ──「パスワードは？」──▶ サーバー
  ルーター ◀─「正解！接続OK」── サーバー

【ENDLESSDOORSの通信】
  ルーター ──「ハロー！MACアドレスはxxxx」──▶ サーバー
  ルーター ◀─ 「この命令をrootで実行せよ」── 誰でもOK
```

つまり、**通信経路の途中に割り込める人なら誰でも**、ルーターにroot権限でコマンド（命令）を送り込めてしまいます。

さらに恐ろしいのが「**rctlbash**」というコマンドです。これを送ると、ルーターは**インタラクティブなrootシェル**（最高管理者として自由にコマンドを打ち込める状態）を攻撃者に提供してしまいます。銀行の金庫の扉を開けたまま席を外すようなイメージです。

## なぜ重要なのか

### 🌍 影響の広がり

| 対象 | 詳細 |
|------|------|
| 影響機種 | CPE2801, WE1026-5G, WD, WE1326, WE2007, WE2008-DSIM, WE2416, WE3326, WE5927, WE5931, WE5931AC, WE826-T3-DSIM, WG108, WG1602, WG1608-DSIM, WG209, WG2105, WG2107, WG259, WG3526, Z8102AX-2DSIM |
| 公式サイトの全ファームウェア | 21個すべてに含まれている |
| バックドアの発動タイミング | **ルーターを買った瞬間から** |

### ⚠️ 「工場出荷時から」が特に深刻な理由

普通のウイルスやマルウェア（悪意あるソフト）は、ユーザーが何か不審なファイルを開いたり、不正なサイトを訪問したりすることで感染します。

しかし今回は**商品を買って箱から出した瞬間から、すでにバックドアが動いています**。ユーザーがどれだけ注意しても、完全に防ぐことができません。

### 🕵️ 企業・組織への影響

Zbtlinkのルーターは主に**法人向け（企業や組織）**に販売されているため、もし企業のネットワークで使われていれば：

- 社内の通信内容が丸見えにされる
- 社内システムへの不正アクセスの踏み台にされる
- ルーター経由で接続された機器すべてが危険にさらされる

## 対策・今後の展望

### 🔴 現状

VulnCheckが公表した時点で、Zbtlinkの公式サイトには以下のメッセージが掲載されました：

> 「特定のファームウェアにセキュリティ脆弱性が発見されました。予防措置として、影響を受けるファームウェアを一時的に公開停止しました。エンジニアチームが修正済みファームウェアの開発・検証に取り組んでいます。」

### 🤔 Zbtlink側の言い分

Zbtlinkの広報担当者は「**このバックドアはアフターサービス（購入後のサポート）のためだけのもの**」と説明し、「通常はサンプル機器にのみ搭載されている」と述べました。

しかし研究者たちは、公式サイトで公開されている**すべての**ファームウェアにこの機能が含まれていることを確認しており、「サンプルだけ」という説明とは矛盾しています。

### ✅ 今できる対策

1. **Zbtlinkのルーターを使っているか確認する**
   - 上記の機種一覧に自分の機器が含まれていないか確認

2. **インターネットへの露出を最小限にする**
   - ルーターの管理画面をインターネット側から見えないように設定

3. **修正済みファームウェアの公開を待つ**
   - Zbtlinkの公式サイトを定期的に確認し、修正版が公開されたら速やかにアップデート

4. **信頼できるメーカーの機器に買い替えを検討する**
   - 今回のようなリスクを避けるため、セキュリティ評価の高いメーカーの製品を選ぶことも一つの選択肢

> ⚠️ **重要**: 修正済みファームウェアが出るまでは、このルーターを重要なネットワーク（企業の基幹ネットワークなど）に使い続けることはリスクが高いと言えます。

## 過去記事との関連

以前、**AWS・Google・VercelのAIエージェント基盤の脆弱性**や**CryptoJSの欠陥による暗号資産盗難**について解説しましたが、今回の記事はそれらとは少し毛色が異なります。

- 過去の記事：ソフトウェア・サービスの「設計上のミス」による脆弱性
- **今回の記事：ハードウェア（物理的な機器）に意図的に仕込まれた疑いのある「バックドア」**

特に注目すべきは「**サプライチェーン攻撃（supply chain attack）**」という観点です。これは、製品が製造・流通される過程のどこかで悪意ある仕掛けを組み込む攻撃手法で、一度製品が市場に出回ると、発見・対処が非常に困難になります。ソフトウェアのライブラリ（部品）に脆弱性が入り込むケース（過去記事の話題）と、今回のようにハードウェアのファームウェアに仕込まれるケース、どちらも「信頼できるはずの供給元から危険なものが届く」という点で共通しています。

## 用語解説

| 用語 | 意味 |
|------|------|
| **バックドア** | 正規の認証を経ずにシステムに侵入できる隠し経路 |
| **ファームウェア** | 機器（ルーター等）を動かすための基本プログラム |
| **root権限** | Linuxシステムで最も強い「何でもできる」管理者権限 |
| **C2（コマンド＆コントロール）** | 攻撃者がマルウェアや侵入済み機器を遠隔操作するためのサーバー |
| **rctl** | 今回のバックドアの中心となる「Remote Control Linux」というプログラム |
| **シェル** | コンピューターへ文字でコマンド（命令）を送るインターフェース |
| **リバースシェル** | 通常とは逆に、標的側から攻撃者側に接続しにいく形式のシェル接続 |
| **kworker** | Linuxで正規に動くシステムプロセス。今回のバックドアはこれに偽装している |
| **init.d** | Linuxが起動するときに自動実行するプログラムを登録する仕組み |
| **MACアドレス** | ネットワーク機器に割り当てられた世界で唯一の識別番号 |
| **OEM/ODM** | 他社ブランド向けに製品を製造・設計する形式のビジネスモデル |
| **サプライチェーン攻撃** | 製品の製造・流通過程に悪意ある仕掛けを混入させる攻撃手法 |
| **VulnCheck** | 今回の調査を行ったアメリカのサイバーセキュリティ研究会社 |
