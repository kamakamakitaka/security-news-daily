# AIアシスト型ツール「HTTP Terminator」が新しいHTTP攻撃手法とApacheのゼロデイ脆弱性を発見

**元記事**: [AI-Assisted HTTP Terminator Finds Novel HTTP Desync Techniques and Apache Zero-Day](https://inl03.netline.com/ltr6/?_m=3n.009a.4050.sp0ao46r89.33uu)
**解説日**: 2026年8月7日

---

## 背景知識

このニュースを理解するために、まずWebの仕組みを簡単に説明します。

### Webサイトにアクセスするときの「裏側」

あなたがブラウザでWebサイトを開くとき、実はこんな流れで通信が行われています。

```
あなたのブラウザ
    ↓ リクエスト(「このページを見せて！」)
【フロントエンドサーバー】← まず最初にここが受け取る（受付係のようなもの）
    ↓
【バックエンドサーバー】← 実際の処理をする（本番の担当者のようなもの）
    ↓ レスポンス(「はい、これがページです！」)
あなたのブラウザ
```

フロントエンドとバックエンドが**2段構え**になっているのは、大量のアクセスを効率よく処理するためです。

### HTTPとは？

**HTTP（HyperText Transfer Protocol）** とは、ブラウザとサーバーがやり取りするときのルール（通信規約）です。手紙のフォーマットのようなもので、「どこにどんな情報を書くか」が決まっています。

### 「HTTP デシンク（Desync）攻撃」とは？

**デシンク（Desynchronization）** とは「同期が外れること」です。

フロントエンドとバックエンドが「このリクエストはここで終わり！」という認識がズレると、**一人のユーザーのリクエストの一部が、別のユーザーのリクエストにくっついてしまう**という怖い現象が起きます。

> **例え話**: 
> レストランで注文を伝える係（フロントエンド）と、料理を作る係（バックエンド）がいるとします。あなたが「ラーメン」と注文したのに、伝達がズレて「ラーメン＋隣のお客さんの個人情報」が調理係に届いてしまうイメージです。

### ゼロデイ脆弱性とは？

**ゼロデイ（Zero-Day）** とは、ソフトウェアの開発者がまだ知らない（＝修正パッチが存在しない）脆弱性のことです。攻撃者が先に発見した場合、防御側は「0日間（ゼロデイ）」しか対応の時間がありません。

## 何が起きたのか

セキュリティ企業 **PortSwigger**（Webセキュリティツール「Burp Suite」の開発元）の研究者 **James Kettle** 氏が、**「HTTP Terminator」** というAIを使った研究システムを開発しました。

このシステムが以下のことを成し遂げました：

- 🤖 **AIが自律的に**、3万件もの攻撃パターン候補を生成・検証
- 🌐 バグ報奨金プログラム等で許可を得た **3万のWebサイト** をテスト
- ⚠️ **約700サイト** に脆弱性を発見（銀行・政府機関・空港・セキュリティ製品を含む）
- 🔴 **Apache Traffic Server** という広く使われるソフトウェアに **ゼロデイ脆弱性**を発見（CVE-2026-63078）
- 💡 **「Shared-Parser Confusion（共有パーサー混乱）」** という新しい攻撃概念を提案

## 技術的な詳細

### 1. AIはどうやって攻撃パターンを見つけたのか？

HTTP Terminatorには **138本のHTTP・SMTPに関する技術仕様書（RFC）** を読み込ませました。

```
138本の技術仕様書
    ↓ 約1万5000の小さなかたまりに分割
    ↓ AIが発想のヒントとして活用
    ↓ 3万種類のユニークな攻撃候補を生成・テスト
```

> **RFC（Request for Comments）** とは、インターネットの通信ルールを定めた公式文書のことです。AIはこれを「教科書」として読んだわけです。

実装には **Claude（Anthropic社のAI）** が使われており、文書の解析と攻撃テストケースの生成を担当しています。

### 2. 新発見① 「ダングリングバイト（Dangling-Byte）」技術

従来のRQP（レスポンスキューポイズニング＝**応答の順番を狂わせる攻撃**）は、タイミングのズレ（競合状態）が発生して不安定でした。

AIが発見した「ダングリングバイト」は：

```
通常の攻撃:
  悪意のあるリクエスト → バックエンドが2つのレスポンスを用意
  ↓
  タイミングが合わないと失敗しやすい

ダングリングバイト:
  悪意のあるリクエスト（わざと1バイト足りない状態で送る）
  ↓
  バックエンドは「まだ待っている」状態に
  ↓
  次の被害者のリクエストが来たとき、その1バイトを補完
  ↓
  被害者のレスポンスが攻撃者に届いてしまう！
```

> **例え話**: 
> 引き出しに鍵をかけるとき、わざと鍵穴に細工して「次に鍵を差し込んだ人の鍵を複製できる」状態にするようなイメージです。

### 3. 新発見② 「Shared-Parser Confusion（共有パーサー混乱）」

サーバーが「レスポンス（返答）を読む処理」と「リクエスト（要求）を読む処理」を**使い回している**場合、本来リクエストに適用すべきでないルールが適用されてしまうという新概念です。

> これはAIが提案し、人間（Kettle氏）が確認・一般化したという**人間とAIの協働**で生まれた発見です。

### 4. Apacheのゼロデイ（CVE-2026-63078）

**Apache Traffic Server** は大規模なWebサービスで使われるキャッシュ・プロキシサーバーです。

人間が主導する調査の中で、**不正な形式のリクエスト**を送ることでデシンク攻撃が成功することが判明しました。この脆弱性はすでにパッチ（修正プログラム）が適用されています。

ただし、記事執筆時点では **CVEデータベースに公式記録が見当たらない** という検証上の問題も指摘されています。

## なぜ重要なのか

### 影響を受けた対象の深刻さ

今回の発見で脆弱と判明したサイトには：

| カテゴリ | リスク |
|----------|--------|
| 🏦 銀行 | 他人の口座情報・取引履歴の漏洩 |
| 🏛️ 政府機関 | 国民の個人情報漏洩、行政システムへの不正アクセス |
| ✈️ 空港 | 予約情報・セキュリティシステムへの影響 |
| 🔐 セキュリティ製品 | 守るべき製品自体が危険にさらされる |

### AIが「自律的に」セキュリティ研究を行った歴史的意義

今回の研究で特に注目すべきは、**AIが人間の直接的な指示なしに**複数の攻撃手法を発見・実証したことです。

```
AIが自律的に発見したもの:
  ✅ ダングリングバイト技術
  ✅ デュアルマッチングContent-Lengthパターン
  ✅ 200以上のWebサイトで有効だったContent-Typeの悪用手法

人間が必要だったもの:
  ⚠️ Apacheゼロデイの発見（人間主導）
  ⚠️ Shared-Parser Confusionの検証・一般化
```

Kettle氏は「私たち2人（人間とAI）のどちらか一方だけでは発見できなかった」と述べています。これはセキュリティ研究の**新しい時代の始まり**を示唆しています。

### RQP攻撃で何が盗まれるのか？

RQP（レスポンスキューポイズニング）が成功すると：

- 🍪 **セッションクッキー**（ログイン状態を保持する情報）
- 🔑 **APIキー**（サービスにアクセスするための秘密の鍵）
- 📄 **他人のページの内容**（個人情報を含む場合も）

が別のユーザーに流出する可能性があります。

## 対策・今後の展望

### PortSwiggerが推奨する対策

| 状況 | 推奨対策 |
|------|----------|
| 可能な場合 | **HTTP/1.1をアップストリームで使わない**（HTTP/2以降に移行する） |
| HTTP/1.1を外せない場合 | 許可するHTTPメソッドを**両方のレイヤーで厳格にホワイトリスト管理**する |
| 同上 | リクエストボディを持てるメソッドを**制限**する |

> **HTTP/1.1** は古いバージョンのHTTPで、デシンク攻撃が発生しやすい。**HTTP/2** はその問題が改善されています。

### オープンソース化

HTTP Terminatorは**オープンソースとして公開**されました。つまり、誰でもこのツールを使って自分のシステムの脆弱性を調査できます（許可を得たシステムに限ります）。

また、別チームが公開した **crlf-desyncs** や **crlf-powered-desync-scanner** というツールも、関連する攻撃手法の研究に使えます。

### AIのセキュリティ研究における将来

記事では **GPT-5.6 Sol** が「既知の手法を再発見するベンチマーク」で**30%の成功率**を示したとも述べられています。AIによるセキュリティ研究は急速に発展しており、今後さらに多くの脆弱性発見にAIが活用されると予想されます。

## 用語解説

| 用語 | 意味 |
|------|------|
| **HTTP** | ブラウザとサーバーが通信するためのルール（手紙のフォーマット） |
| **デシンク（Desync）** | フロントエンドとバックエンドの「どこでリクエストが終わるか」という認識のズレ |
| **フロントエンドサーバー** | ユーザーと直接やり取りする「受付係」のサーバー |
| **バックエンドサーバー** | 実際の処理を行う「本番担当」のサーバー |
| **RQP（レスポンスキューポイズニング）** | 他人へのレスポンスを攻撃者に届くように仕込む攻撃 |
| **ゼロデイ脆弱性** | 開発者がまだ知らない（修正パッチがない）セキュリティの欠陥 |
| **CVE** | セキュリティ脆弱性に付けられる公式の識別番号（例: CVE-2026-63078） |
| **RFC** | インターネットの通信ルールを定めた公式仕様書 |
| **セッションクッキー** | ログイン状態を維持するためにブラウザに保存される情報 |
| **APIキー** | サービスにアクセスするための「秘密の合言葉」 |
| **Apache Traffic Server** | Apacheが開発する大規模向けキャッシュ・プロキシサーバーソフト |
| **PortSwigger** | Burp Suiteを開発するWebセキュリティ専門企業 |
| **ホワイトリスト** | 「許可するもの」だけをリストアップして、それ以外を全て拒否する管理方法 |
| **ダングリングバイト** | わざと1バイト足りないリクエストを送り、次の被害者のリクエストで補完させる技術 |
| **Shared-Parser Confusion** | レスポンス処理のロジックをリクエスト処理に使い回してしまうことで生じる混乱を突く攻撃 |
