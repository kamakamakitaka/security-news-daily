# GitHubのissueを書くだけで企業の秘密情報が盗まれる？ Claude・Gemini・Codexの深刻な脆弱性

**元記事**: [Claude Code and Gemini CLI Flaws Let a GitHub Issue Reach CI Workflow Secrets](https://inl03.netline.com/ltr6/?_m=3n.009a.4050.sp0ao46r89.33v6)
**解説日**: 2026年8月8日

---

## 背景知識

まず、このニュースを理解するための前提知識を整理しましょう。

### 🤖 AIコーディングエージェントとは？

Claude Code（Anthropic社）、Gemini CLI（Google社）、Codex（OpenAI社）は、いずれも「AIがコードを自動で書いたり、レビューしたりしてくれるツール」です。  
たとえば「このバグを直して」と指示するだけで、AIが自動でコードを修正してくれます。

### ⚙️ CI（継続的インテグレーション）とは？

「CI（Continuous Integration）」は、コードを変更するたびに自動でテストやビルドを走らせる仕組みです。  
**例え話**：学校の提出物を出すと、先生が自動で採点してくれるシステムをイメージしてください。

### 🏃 CIランナーとは？

CIの処理を実際に実行する「作業員」のようなサーバーです。このサーバーは通常、パスワードやAPIキーなどの**機密情報（シークレット）**にアクセスできます。

### 🐙 GitHubのissueとは？

GitHubは開発者がコードを共有する場所。「issue（イシュー）」は、バグ報告や機能要望を書き込める掲示板のようなものです。**基本的には誰でも書き込めます**。

### 🔑 APIキーとは？

サービスを利用するための「合鍵」のようなもの。これが漏れると、他人があなたの名義でサービスを使い放題になります。

## 何が起きたのか

セキュリティ企業「Novee Security」が、2026年8月5日のハッキングカンファレンス「Black Hat USA」で衝撃的な発見を発表しました。

> **リポジトリに対して何の権限も持っていない外部の人間が、GitHubにissueを1件書き込むだけで、Anthropic・Googleの開発環境のサーバーでコードを実行できた。OpenAIでは、次のAIエージェントの実行を乗っ取ることができた。**

🚨 これは泥棒に例えると、**「郵便受けに手紙を入れるだけで、家の中に侵入できた」** ようなものです。

今回の発見では、**2つのCVE（脆弱性の正式番号）** が発行され、どちらもすでに修正済みです。

---

## 技術的な詳細

3つのツールそれぞれで、異なる攻撃手法が使われました。

---

### 🔴 Gemini CLI（最も深刻・CVSSスコア10.0 / 満点）

**CVE番号**: CVE-2026-12537

#### 何が問題だったか？

Gemini CLIには「コンテナランチャー」という、安全な実行環境（サンドボックス）を起動する部品があります。

```
攻撃の流れ（イメージ）：
1. 攻撃者が .gemini/.env という特殊なファイルを細工する
2. サンドボックスが起動する「前」にそのファイルが読み込まれる
3. ファイルの中に仕込まれた悪意あるコマンドがホストサーバーで実行される！
```

**例え話**：金庫（サンドボックス）に鍵をかける前に、金庫の設定ファイルに「鍵をかけるな」と書いておいたようなものです。

#### さらに問題だったこと

Gemini CLIには「このツールだけ使っていいよリスト（ツール許可リスト）」という機能がありましたが、**登録するときにしかチェックしていなかった**ため、実際に動くときは無チェックでした。

また `--yolo` というオプションを使うと、AIが要求するコマンドをすべて自動承認してしまっていました。

**修正バージョン**: Gemini CLI 0.39.1 / run-gemini-cli 0.1.22

---

### 🟠 Claude Code（CVSSスコア：NVDは9.1と評価）

**CVE番号**: CVE-2026-54316

#### 何が問題だったか？

**「Hugging Faceのダウンロードカウンター」がAPIキー盗み出しの「隠し通信路」に使われた**という、かなり巧妙な手口です。

```
攻撃の流れ（イメージ）：
1. 攻撃者が悪意あるコンテンツをClaude Codeの処理対象に混入させる
2. Claude CodeはAPIキーを1文字ずつHugging Faceのダウンロードリクエストに埋め込む
3. 攻撃者はそのリクエストログを見てAPIキーを復元する
```

**例え話**：電話を盗聴されている状況で、秘密の暗号文を図書館の本を1冊ずつ借りるという行為に変換して外部に送信するようなものです。

#### さらに見つかった問題（CVEなし）

Claude Codeのコマンドチェック機能には別の抜け穴もありました。

- コマンドの安全確認をする前に「シングルクォート（`'`）で囲まれた部分を取り除く」処理をする
- しかし、`git push --receive-pack` というgitコマンドの「フラグ（オプション）」に悪意あるコードを仕込むと、チェックをすり抜けてそのままサーバーに届いてしまう

こちらはまだ修正バージョンが公表されていません。

**修正バージョン**: Claude Code 2.1.163（影響バージョン：0.2.54〜2.1.163未満）

---

### 🟡 OpenAI Codex（CVEなし）

#### 何が問題だったか？

OpenAIのリポジトリでは、**1つのCI作業（ジョブ）の中でCodexを2回実行していた**ことが問題でした。

```
攻撃の流れ（イメージ）：
1回目のCodex実行 → AGENTS.md（指示ファイル）を書き換え可能
        ↓
2回目のCodex実行 → 書き換えられたAGENTS.mdを「自分への指示」として読み込む！
```

**例え話**：1人目のバイトが「次のバイトへの引き継ぎメモ」を書き換えられる状況で、悪意ある内容に書き換えて渡すようなものです。

OpenAIは「サンドボックスは仕様通りに動いていた」として製品バグとは認めず、ワークフロー（作業手順）レベルで修正しました。

## 3つの攻撃に共通する「本質的な問題」

Noveeのエンジニア、Elad Meged氏はこう表現しています：

> **「ハーネス（harness）は、AIモデルと現実世界の間にあるコードだ」**

「ハーネス」とは、AIモデルを実際の処理に接続する「つなぎ役のコード」のことです。3つの攻撃すべてに共通したパターンがありました：

```
【共通パターン】
ある部分が「この値は安全だ」とチェックする
        ↓
別の部分がその値を、より強い権限で実行する
        ↓
その間に悪意あるデータが紛れ込む 💥
```

## なぜ重要なのか

### 📊 影響の大きさ

| ツール | 深刻度 | 影響 |
|--------|--------|------|
| Gemini CLI | 🔴 CVSS 10.0（最高） | ホストサーバーで任意コード実行 |
| Claude Code | 🟠 CVSS 9.1（非常に高い） | APIキーの窃取 |
| Codex | 🟡 （CVEなし） | エージェント実行の乗っ取り |

### 🌍 なぜ社会的に重要か

1. **攻撃者に特別な権限が不要** — GitHubに誰でも書けるissueを投稿するだけで攻撃できた
2. **被害を受けるのが大企業のAIツール自身** — セキュリティ意識が高いはずのAI企業のツールでも脆弱性が見つかった
3. **AIツールの普及と並走するリスク** — 多くの企業がこれらのツールをCI/CDに導入し始めている

## 対策・今後の展望

### ✅ 今すぐできる対策

1. **Gemini CLI** → `0.39.1` 以上にアップデート
2. **run-gemini-cli** → `0.1.22` 以上にアップデート
3. **Claude Code** → `2.1.163` 以上にアップデート

### 🛡️ 組織・開発者向けの対策

- **外部ユーザーがトリガーできるワークフローを見直す**（誰でも実行できる処理に秘密情報を渡さない）
- **リポジトリの指示ファイル（AGENTS.mdなど）を「信頼できない入力」として扱う**
- **Codexは作業の最後のステップで実行する**（後続の特権ステップにファイルを残せなくする）
- **`--yolo` モードの使用を避ける**（すべてを自動承認するのは危険）

### 🔮 今後の展望

- CISAの「既知の悪用脆弱性カタログ」にはまだ登録されておらず、現時点での実被害は確認されていません
- しかし、Claude Codeの脆弱性の「再現環境」とされるリポジトリが6月18日から公開されていたことが判明しており、今後の悪用が懸念されます

## 用語解説

| 用語 | 説明 |
|------|------|
| **CI（継続的インテグレーション）** | コードを変更するたびに自動でテストを走らせる仕組み |
| **CIランナー** | CIの処理を実際に行うサーバー |
| **CVE** | 脆弱性に付けられる世界共通の識別番号（例：CVE-2026-12537） |
| **CVSS** | 脆弱性の深刻度を0〜10で評価するスコア（10が最大） |
| **APIキー** | サービスを利用するための合鍵のようなもの |
| **サンドボックス** | 外部に影響を与えないよう隔離された安全な実行環境 |
| **コンテナ** | アプリを独立した箱の中で動かす仮想化技術（Dockerなど） |
| **OSコマンドインジェクション** | 悪意ある命令をOSに実行させる攻撃手法 |
| **ハーネス（harness）** | AIモデルと実際の処理をつなぐ中間コード |
| **シークレット** | CI環境に保存された秘密情報（パスワードやAPIキーなど） |
| **AGENTS.md** | AIエージェントへの指示を書いたファイル |
| **--yolo** | すべてのAIの要求を自動承認するモード（非常に危険） |
| **Black Hat USA** | 世界最大級のセキュリティ専門家向けカンファレンス |
| **CISA** | アメリカのサイバーセキュリティ専門機関 |
| **NVD** | CVEの詳細情報を管理するアメリカの国家脆弱性データベース |
