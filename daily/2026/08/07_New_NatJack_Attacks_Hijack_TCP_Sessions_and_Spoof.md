# NATテーブルを悪用してTCP通信を乗っ取る新攻撃「NatJack」が発見される

**元記事**: [New NatJack Attacks Hijack TCP Sessions and Spoof DNS by Manipulating NAT Tables](https://inl03.netline.com/ltr6/?_m=3n.009a.4050.sp0ao46r89.33uo)
**解説日**: 2026年8月8日

---

## 背景知識

まず、このニュースを理解するためにいくつかの基礎知識を押さえておきましょう。

### 🏠 NATとは？「住所の変換係」

みなさんの家のWi-Fiルーターを想像してください。家の中にはスマホ・PC・タブレットなど複数の端末がありますが、インターネット側から見ると**「一つの家の住所（IPアドレス）」しか見えません**。

この「家の中の個別の部屋番号（プライベートIPアドレス）」と「外から見える住所（グローバルIPアドレス）」を変換する仕組みが **NAT（Network Address Translation＝ネットワークアドレス変換）** です。

```
【家の中（内側）】          【インターネット（外側）】
PC    (192.168.1.2) ─┐
スマホ (192.168.1.3) ─┤  NATルーター  ─── グローバルIPアドレス（1つ）
タブレット(192.168.1.4)─┘  (変換係)
```

### 📋 NATテーブルとは？「通信の管理台帳」

NATルーターは、誰がどこと通信しているかを記録した**「管理台帳（NATテーブル）」**を持っています。「部屋Aからの通信はポート5000番で外と繋がっている」といった情報が書いてあります。

### 🔗 TCPセッションとは？「電話の通話」

TCP（通信プロトコルの一種）による通信は、電話のように**「繋がった状態を保つ」**通信です。「セッション」とは、この「通話中の状態」のことです。

### 🌐 DNSとは？「電話帳」

DNS（Domain Name System）は、「google.com」のようなドメイン名を、コンピューターが理解できるIPアドレス（数字の住所）に変換する仕組みです。まるでインターネットの電話帳です。

## 何が起きたのか

セキュリティ研究者の**マルコム・スタッグ氏**が、**「NatJack（ナットジャック）」**と呼ばれる新しいサイバー攻撃の手法を発見しました。

2026年8月に開催された世界最大級のセキュリティ会議**「Black Hat USA 2026」**で発表されたこの研究によると、攻撃者が**NATの管理台帳（NATテーブル）を不正に操作する**ことで、以下の4つの悪いことができてしまうとわかりました。

| できてしまうこと | 例え話で言うと |
|---|---|
| ①他人のTCP通信を乗っ取る | 他人の電話に割り込んで会話を盗む |
| ②DNSの回答を偽装する | 電話帳を書き換えて偽の番号に誘導する |
| ③外部から見えるポート番号を暴く | 家の中の部屋番号を外部に漏らす |
| ④NATテーブルを埋め尽くして通信不能にする | 台帳を偽の記録で満杯にして新しい通信を妨害する |

WindowsとLinuxの両方で問題が確認され、それぞれに**CVE番号（脆弱性の識別番号）**が割り当てられました：

- **CVE-2026-56181**（危険度スコア8.3/10）：WindowsのHyper-V（仮想化機能）が使うNATの問題
- **CVE-2026-63913**（危険度スコア8.2/10）：LinuxのNetfilter conntrackの問題

> 💡 **CVSSスコア**とは？　脆弱性の深刻さを0〜10点で表したもので、**8点以上は「重大」レベル**です。

## 技術的な詳細

### 攻撃の前提条件

NatJackには重要な前提条件があります：
> **攻撃者が被害者と同じNATの内側にいる必要があります**

つまり、**同じWi-Fiやオフィスネットワークに接続している必要がある**ということです。外部からいきなり攻撃できるわけではありません。

```
【同じNATの内側】
  被害者のPC ───┐
  攻撃者のPC ───┤  NATルーター ─── インターネット
               ↑
         ここが攻撃の舞台！
```

### 攻撃の仕組み（4つの手口）

#### 手口① TCP通信の乗っ取り
NATテーブルの「被害者の通信記録」を書き換え、被害者宛ての通信が攻撃者のところに届くようにします。電話の転送設定を勝手に変えるようなイメージです。

#### 手口② DNSレスポンスの偽装
被害者がDNSサーバーに「google.comのIPアドレスを教えて」と聞いたとき、本物の返答が攻撃者のところに届くように細工し、代わりに**偽の返答（偽サイトのアドレス）**を被害者に送ります。

#### 手口③ ポート番号の暴露
被害者の通信に使われているポート番号（通信の「窓口番号」）を外部から見えるようにし、さらなる攻撃の足がかりにします。

#### 手口④ NATテーブルの枯渇攻撃
偽の通信記録をNATテーブルに大量に書き込んで台帳を満杯にし、正規のユーザーが新しい通信を始められなくする**DoS攻撃（サービス妨害攻撃）**です。

### Linuxの具体的な問題
特別に細工した「SYNパケット」（通信開始の信号）と「RSTパケット」（リセット信号）を送ることで、Linuxのconntrack（通信追跡機能）が正常な通信記録を誤って「終了済み」と判断してしまいます。

## なぜ重要なのか

### 🏢 企業内ネットワークへの影響が大きい

「同じNATの内側にいる必要がある」という条件は、一見すると制限に思えますが、**企業のオフィスネットワークやクラウド環境**では多くの端末が同じNATを共有しています。

```
【クラウド・オフィス環境での危険シナリオ】
悪意ある社員のPC ──┐
  重要サーバー   ──┤  社内NAT  ──── インターネット
  他の社員のPC  ──┘
    ↑
同じNAT内にいれば攻撃可能！
```

### 📊 広範囲な製品に影響

研究者が数十種類もの実際のネットワーク機器でテストしたところ、**複数のメーカーの製品が影響を受ける**ことが確認されました。また、以前の関連研究では67台中52台のルーターが脆弱だったというデータもあります。

### ⚠️ 完全な解決策がまだない

この攻撃の特性上、**一発で全部直せる魔法のパッチは存在しません**。WindowsとLinuxのパッチはそれぞれ公開されていますが、スタッグ氏自身も「Linuxのパッチはコードの問題は直しているが、攻撃の難易度を上げるだけで完全な解決ではない」と述べています。

## 対策・今後の展望

### ✅ 今すぐできる対策

#### 1. OSのアップデートを適用する
**Windows**の場合、以下のバージョンが修正済みです：
- Windows 11 24H2 → ビルド番号 26100.8875 以上
- Windows Server 2025 → ビルド番号 26100.33158 以上

**Linux**の場合、修正済みの安定版カーネルに更新する：
- 5.10.259, 5.15.210, 6.1.176, 6.6.143, 6.12.93, 6.18.35, 7.0.12, 7.1 以上

> 💡 「カーネル」とはLinuxの心臓部にあたるプログラムのことです。

#### 2. 信頼できない端末を分離する
「信用できない端末」と「重要なサーバーや端末」を**別々のネットワーク（別のNAT）に分ける**ことが推奨されています。

#### 3. 通信を暗号化する（内部でも！）
社内ネットワークの通信であっても**TLS/VPNなどで暗号化**することで、仮に通信を乗っ取られても内容を読まれにくくなります。

#### 4. IP Source Guardを活用する
これは、ネットワーク内で**偽のIPアドレスを使った通信を検出・遮断する仕組み**です（対応機器がある場合）。

### 🔮 今後の展望

- 現時点（2026年8月7日）では**実際の攻撃に使われた事例は確認されていません**
- しかし、研究が公開されたことで、悪用の可能性が高まるため、早急なパッチ適用が重要です
- NATの設計思想そのものへの根本的な見直しが業界全体で議論されることが予想されます

## 過去記事との関連

以前、「**18年間潜んでいたLinuxの重大バグ『SCTPHantom』**」について解説しましたが、今回のNatJackもLinuxの深部（カーネルのNetfilter conntrack）に関わる問題です。

共通点として：
- どちらも**Linuxの根幹部分（カーネル）**に存在する脆弱性
- どちらも**長年見落とされてきた設計上の問題**が原因

違いとして、前回のSCTPHantomはローカルユーザーが「神権限（root）」を取得するものでしたが、今回のNatJackは**ネットワーク通信そのものを操作する**点が異なります。どちらもLinuxシステムを使っている方には関係のある話ですので、OSのアップデートを定期的に行うことの重要性が改めて確認できます。

## 用語解説

| 用語 | 読み方 | 意味 |
|---|---|---|
| **NAT** | ナット | Network Address Translation。プライベートIPとグローバルIPを変換する仕組み |
| **NATテーブル** | ナットテーブル | NATが管理する通信の台帳。誰がどこと通信しているか記録している |
| **TCP** | ティーシーピー | 通信プロトコルの一種。電話のように接続状態を維持する信頼性の高い通信方式 |
| **セッション** | セッション | TCPによる「接続中の状態」。電話でいう「通話中」に相当 |
| **DNS** | ディーエヌエス | Domain Name System。ドメイン名をIPアドレスに変換するインターネットの電話帳 |
| **CVE** | シーブイイー | Common Vulnerabilities and Exposures。脆弱性に付けられる世界共通の識別番号 |
| **CVSSスコア** | シーブイエスエス | 脆弱性の深刻さを0〜10で示すスコア。8以上は重大レベル |
| **Hyper-V** | ハイパーブイ | Windowsに搭載された仮想マシン（PC内にPC）を作る機能 |
| **Netfilter conntrack** | ネットフィルター コントラック | Linuxカーネルが通信状態を追跡・管理する仕組み |
| **DoS攻撃** | ディーオーエス | Denial of Service Attack。サービスを使えなくする妨害攻撃 |
| **IP Source Guard** | アイピーソースガード | 偽のIPアドレスを使った通信を遮断するセキュリティ機能 |
| **Black Hat** | ブラックハット | 世界最大級のセキュリティ研究者向けカンファレンス（会議） |
| **PoC（Proof of Concept）** | ピーオーシー | 「本当に攻撃できる」ことを示す実証コードや実験 |

---

> 🛡️ **まとめると...**
> NatJackは、同じWi-Fiや社内ネットワークにいる攻撃者がNATの仕組みを悪用して通信を乗っ取る新しい攻撃手法です。企業ネットワークやクラウド環境への影響が大きく、根本的な解決策はまだありませんが、OSのアップデートとネットワークの適切な分離が有効な対策です。「社内ネットワークは安全」という思い込みを捨て、**内部通信も暗号化する**という考え方がより重要になってきています。
