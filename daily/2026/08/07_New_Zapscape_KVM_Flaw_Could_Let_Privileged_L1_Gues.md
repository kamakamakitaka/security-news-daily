# 仮想マシンの「檻」を破って脱出できる新たなLinuxの欠陥「Zapscape」が発見された

**元記事**: [New Zapscape KVM Flaw Could Let Privileged L1 Guest Code Escape to Linux Hosts](https://inl03.netline.com/ltr6/?_m=3n.009a.4050.sp0ao46r89.33vc)
**解説日**: 2026年8月8日

---

## 背景知識

このニュースを理解するために、まずいくつかの概念を押さえておきましょう。

### 🏠 仮想マシン（VM）って何？
コンピューターの中に、**ソフトウェアで作った「仮想のコンピューター」**を動かす技術です。1台の物理的なサーバーの上で、複数の「仮想コンピューター」を同時に動かせます。

> **例え話**: 大きなマンション（物理サーバー）の中に、それぞれ独立した部屋（仮想マシン）がある、とイメージしてください。部屋同士は壁で仕切られているので、隣の部屋に勝手に入れないはずです。

### 🔑 ホストとゲスト
- **ホスト**: 仮想マシンを動かしている「本物の」コンピューター（マンション自体）
- **ゲスト（L1）**: ホストの上で動いている仮想マシン（マンションの部屋）

### ⚙️ KVMって何？
**KVM（Kernel-based Virtual Machine）** は、Linuxに内蔵されている仮想化の仕組みです。ゲストマシンを管理する「仮想マシン管理人」のようなものです。

### 🪆 ネスト仮想化（入れ子の仮想化）
仮想マシンの中で、さらに仮想マシンを動かすことができる機能です。

> **例え話**: 部屋の中に、さらに小さな仕切り（L2ゲスト）を作ること。クラウドサービス会社がお客様に「あなた専用の仮想マシン」を提供する際によく使われます。

### 🧠 カーネル権限（root権限）
OSの「最高管理者」としての権限です。何でもできる「神アカウント」のようなものです。

## 何が起きたのか

セキュリティ研究者の **Hyunwoo Kim** さんが、Linuxカーネルに重大な欠陥を発見し、**「Zapscape（ザップスケープ）」** と名付けました。

### 問題の核心
ゲスト仮想マシン（L1）の中で**root権限（最高管理者権限）を持っている攻撃者**が、**仮想マシンの「壁」を破り抜けて**、外側の本物のコンピューター（ホスト）でroot権限のコマンドを実行できてしまう、というものです。

> **例え話**: マンションの住人（ゲストVM）が、本来は入れないはずの「管理人室（ホスト）」に侵入し、マンション全体をコントロールできてしまうイメージです。

### 識別番号
この脆弱性には **CVE-2026-64561** という番号が付けられています（CVEとは、脆弱性を世界共通で管理するための番号です）。

### 発見・修正の流れ
| 日付 | 出来事 |
|------|--------|
| 2026年7月11日 | Kimさんがkernel開発チームに報告 |
| 2026年7月21日 | 修正パッチが開発・統合される |

| 2026年8月4日 | CVE番号が割り当てられる |

## 技術的な詳細

少し難しいですが、できるだけわかりやすく説明します！

### シャドウMMUって何？
**MMU（Memory Management Unit）** はメモリの「住所管理係」のようなものです。仮想マシンの中では、ゲストが使う「仮想の住所」を本物のメモリの住所に変換する必要があります。KVMはこのために「**シャドウページテーブル**（影の住所録）」を使っています。

### バグの仕組み：「Use-After-Free（解放後使用）」

このバグは **「Use-After-Free（解放後使用）」** と呼ばれるタイプの脆弱性です。

> **例え話で説明**:
> 1. 図書館の本棚（メモリ）から本（データ）を借りた
> 2. 図書館員が「この本はもう使われていない」と判断して、棚から撤去＆廃棄した（メモリ解放）
> 3. でも借りた人は「まだ棚にある」と思ってそのページを読み続けた（解放後使用）
> 4. その棚には別の本が入れられ、でたらめな内容が「正しい情報」として処理される

### 具体的な流れ

```
[ゲストがページフォルト（メモリアクセスエラー）を起こす]
         ↓
[KVMがMMUページの回収処理を行う]
         ↓
[処理中のルートページが「無効」になる]
         ↓
[KVMが「無効チェック」をせずに処理を続ける] ← ここがバグ！
         ↓
[無効なルートの下に子ページが作られてしまう]
         ↓
[同じリンクが2つのリストに登録 → ページが解放されても参照が残る]
         ↓
[攻撃者がこれを悪用してホストで任意コードを実行]
```

### 修正内容
修正パッチ（`commit 2abd5287f083`）では、「ルートが無効かどうかのチェック」を**より後のタイミングで行うように**変更しました。もし無効になっていたら、処理を最初からやり直す（`RET_PF_RETRY`）ようにしたことで、問題が解消されました。

### 実証（PoC）について
Kimさんは実際にこの脆弱性を使って、ホストLinux上に `/Zapscape` という名前のファイルを**root権限で作成する**デモを成功させています。ただし、「すぐに実際の攻撃に使えるレベルではない」とも述べており、悪用には追加の作業が必要とのことです。

## なぜ重要なのか

### 🌩️ クラウドへの影響
AWSやGoogle Cloud、さくらのVPSなど、多くのクラウドサービスは**この仮想化技術の上で動いています**。もし攻撃者がある利用者のVMにroot権限でアクセスできたなら、理論上は他のユーザーのVMが動いているホストサーバー自体を乗っ取れる可能性があります。

### 📊 深刻度スコア
Red Hatによる評価: **CVSS 7.0（重要）**

> CVSSスコアは脆弱性の深刻度を0〜10で表す指標です。7.0は「重要（High）」レベルです。

### 影響を受けるシステム
- **Linux 5.9以降** のカーネル（後述の修正版を除く）
- **ネスト仮想化（nested virtualization）をゲストに公開している** KVMホスト
- AMDシステムは条件が少なくより影響を受けやすく、Intelシステムは特定条件（EPTページウォーク長4と5の両方が公開されている場合）で影響を受ける

### 影響を受ける修正済みバージョン
以下のバージョンに更新すれば安全です：
- Linux **6.6.148**
- Linux **6.12.101**
- Linux **6.18.42**
- Linux **7.1.6**
- Linux **7.2-rc5**

## 対策・今後の展望

### ✅ 今すぐできる対策

**1. カーネルをアップデートする**
上記の修正済みバージョンへの更新が最も重要です。

```bash
# Ubuntuの場合（例）
sudo apt update && sudo apt upgrade

# Red Hat/CentOSの場合（例）
sudo yum update kernel
```

**2. ネスト仮想化を無効化する（暫定対策）**
信頼できないゲストにネスト仮想化を公開している場合、一時的にこの機能を無効にすることでリスクを下げられます。

### ⚠️ Debian利用者への注意
2026年8月6日時点で、Debianの **bullseye・bookworm・trixie・forky** はまだ脆弱なバージョンが含まれています。**sid** は修正済み（7.1.6-1）です。各ディストリビューションの公式トラッカーを確認してください。

### 💡 Red Hatの注意点
Red Hatのパッケージは「バージョン番号が古くても、修正が内部に取り込まれている（バックポート）」場合があります。バージョン番号だけで判断せず、**公式のセキュリティアドバイザリを確認**しましょう。

### 今後の展望
現時点では「実際に攻撃に使われた事例（野良での悪用）」は報告されていません。しかし、公開されたPoC（実証コード）があるため、今後悪用される可能性は否定できません。**早急なアップデートが強く推奨されます。**

## 過去記事との関連

以前、**「SCTPHantom」**（18年間潜んでいたLinuxの重大バグ）について解説しましたが、今回の「Zapscape」も同じLinuxカーネルを舞台にした脆弱性です。

| | SCTPHantom | Zapscape |
|---|---|---|
| 対象 | Linuxカーネル（SCTP） | Linuxカーネル（KVM） |
| 影響 | ローカルユーザーがroot取得・コンテナ脱出 | ゲストVMからホストへ脱出 |
| 必要な権限 | ローカルユーザー権限 | ゲスト内のroot権限 |

どちらも「**本来越えてはいけない境界線を突破する**」という点で共通しています。Linuxカーネルのような巨大なソフトウェアでは、こうした「境界突破」型の脆弱性が繰り返し発見されており、継続的なアップデートの重要性を改めて示しています。

## 用語解説

| 用語 | 説明 |
|------|------|
| **KVM** | Linuxに内蔵された仮想化システム（Kernel-based Virtual Machine） |
| **L1ゲスト** | ホスト上で直接動いている仮想マシン（第1層のゲスト） |
| **ネスト仮想化** | 仮想マシンの中でさらに仮想マシンを動かす技術 |
| **シャドウMMU** | 仮想マシン用のメモリ住所変換を管理する仕組み |
| **Use-After-Free** | 解放済みのメモリを誤って使い続けてしまうバグの種類 |
| **PoC（Proof of Concept）** | 脆弱性が実際に悪用できることを示す実証コード |
| **CVE** | 脆弱性を世界共通で識別するための番号体系 |
| **CVSS** | 脆弱性の深刻度を0〜10で示すスコア |
| **root権限** | OSの最高管理者権限（何でもできる「神アカウント」） |
| **バックポート** | 新しいバージョンの修正を、古いバージョンに適用すること |
| **EPT** | Intel製CPUの仮想化支援機能の一つ（Extended Page Tables） |
| **AMD SVM/NPT** | AMD製CPUの仮想化支援機能 |
| **QEMU** | 仮想マシンのエミュレーターソフトウェア（今回は脆弱ではない） |

---

> 💬 **まとめ**: 「Zapscape」は、クラウドサービスなどで広く使われているLinuxの仮想化技術「KVM」に潜む欠陥です。仮想マシンという「檻」を突き破ってホストを乗っ取れる可能性があるため、サーバー管理者は早急なカーネルのアップデートが必要です。幸い、現時点では実際の攻撃事例は報告されておらず、修正パッチも公開済みです！
