# 18年間誰も気づかなかった！Linuxの欠陥でパソコンを乗っ取れる脆弱性が発見される

**元記事**: [18-Year-Old Linux SCTP Flaw Could Let Local Users Gain Root and Escape Containers](https://inl03.netline.com/ltr6/?_m=3n.009a.4051.sp0ao46r89.33wk)
**解説日**: 2026年8月9日

---

## 背景知識

まず、この記事を理解するために必要な基礎知識を整理しましょう。

### 🐧 Linuxとは？
Windowsと同じく「OS（オペレーティングシステム）」の一種です。サーバー（インターネットのサービスを支えるコンピューター）の世界では圧倒的なシェアを持っており、GoogleやAmazonのサービス、あなたが使っているスマートフォンのAndroidも、Linuxをベースにしています。

### 🔑 root（ルート）とは？
コンピューターの「最高管理者権限」のことです。家に例えると「合鍵を全部持っていて、どの部屋にも入れる状態」。rootになれば、そのコンピューター上で何でもできてしまいます。

### 📦 コンテナとは？
アプリケーションを「箱（コンテナ）」の中に閉じ込めて動かす技術です。DockerやKubernetesと呼ばれるツールがよく使われます。「箱の中のプログラムは、外（ホストマシン本体）には触れない」という前提で設計されており、クラウドサービスの基盤として広く普及しています。コンテナ脱出（エスケープ）とは、この「箱を破って外に出る」攻撃のことです。

### 🌐 SCTPとは？
インターネット通信のルールの一つ（プロトコル）です。普段よく使われるTCPやUDPに加えて、「一つの接続を複数のネットワーク経路で同時に使える」という特徴を持つ通信方式です。電話会社のネットワークなど一部の専門的な環境で使われています。

### 🐛 use-after-free（解放後使用）とは？
プログラムが「もう使い終わって返却したメモリ（記憶領域）」を、誤って再び参照してしまうバグです。返却済みの部屋の鍵で、別の人が入居した部屋を開けてしまうようなイメージです。攻撃者がこれを悪用すると、本来アクセスできないデータや機能に触れることができます。

## 何が起きたのか

中国のテクノロジー企業・Tencent（テンセント）のセキュリティ研究チーム「Zhuque Lab（朱雀ラボ）」が、**Linuxに18年前から存在していた重大な欠陥（脆弱性）** を発見しました。

この欠陥は **CVE-2026-64564** という識別番号が割り当てられ、発見者たちによって **「SCTPhantom（SCTファントム）」** という名前がつけられました。"Phantom（幽霊）"というのは「18年もの間、誰にも気づかれず潜んでいた」ことへのちなみです。

- 🗓️ **バグが生まれた時期**: 2008年（Linux 2.6.25）
- 🔍 **発見・公開**: 2026年8月6日
- 🔧 **修正版リリース**: 2026年8月3日（発見者が事前に開発チームに報告していたため、公開前に修正済み）
- ⚠️ **深刻度スコア**: 8.5 / 10（CVSS v4.0、Tencent評価）

研究チームは実際にこの欠陥を使って、**Debian 13・Ubuntu 24.04・Rocky Linux 9・RHEL 9・OpenCloudOSといった主要なLinuxディストリビューション（Linuxの種類）でroot権限の取得に成功**し、さらに**コンテナの外に脱出してホストマシンを乗っ取ることにも成功した**と報告しています。

## 技術的な詳細

### バグの仕組み（わかりやすく説明します）

SCTPには「動的アドレス再設定」という機能があります。これは「通信中に接続経路（アドレス）を追加・削除できる」機能です。

このバグは、**住所の確認と実際の行動で、別の住所を使ってしまう「取り違えミス」** が原因です。

具体的には、次のような悪意ある手順を踏みます：

```
1. 通信パケット（データの塊）の中に「あるアドレス」を入れる
2. 同じパケットの中で「そのアドレスを削除してくれ」と要求する
3. さらに「全アドレスを削除してくれ」というワイルドカード削除を要求する
```

> 🏠 **例え話で説明すると...**
> 
> 「AさんとBさんが共同で借りているマンションの部屋」を管理しているとします。
> 「B号室を解約します（Bを削除）」→「全部屋を解約します（ワイルドカード削除）」
> という手順を踏むと、管理システムが「すでに返却された鍵（解放済みメモリ）」を使って
> 別の部屋を開けようとしてしまう、というイメージです。

カーネル（OSの中枢）は削除リクエストを確認する際と、実際に処理する際で**異なるアドレスを参照してしまいます**。その結果、「すでに解放（返却）されたメモリ領域」を再び使ってしまう **use-after-free** が発生し、攻撃者がそのメモリ領域を悪用して、本来は持てないroot権限を得られてしまいます。

### コンテナ脱出のポイント

通常、コンテナ脱出には強力な権限（CAP_NET_ADMINなど）が必要とされていました。しかし研究チームは**その権限なしでも脱出できる方法を発見**し、8回の試行のうち6回（成功率75%）でホストマシンのroot権限取得に成功したと述べています。

## なぜ重要なのか

### 📌 主な影響ポイント

| 項目 | 内容 |
|------|------|
| 潜伏期間 | **18年間**（2008年〜2026年） |
| 影響対象 | 主要Linuxディストリビューションのほぼ全て |
| 攻撃成功時の権限 | **最高権限（root）** |
| コンテナ脱出 | 研究チームの環境では成功 |
| 既知の悪用報告 | 記事執筆時点では**なし** |

### ⚠️ ただし「条件がある」という点も重要

このバグには**「ローカル攻撃」という制限**があります。つまり、インターネット越しに遠隔から攻撃することはできず、**攻撃者がすでにそのシステムに何らかのアクセス権を持っている必要があります**。

また、**SCTPが使える状態（有効化されている）** であることも条件です。SCTPはデフォルトでは無効なシステムも多く、すべての環境が危険というわけではありません。

> 💡 **わかりやすく言うと...** マンションに例えると「すでにロビーには入れる状態の人が、合鍵を不正に作れる」という欠陥です。完全な外部の人には使えません。

### 🤖 AIがバグを発見した点も注目

Tencentはこのバグを「Corvus AI（コルバスAI）」というAIを使った自動解析パイプラインで発見したと述べています。同じく2026年7月に発見された「GhostLock」というバグも同様の手法で発見されており、**AIが長年見落とされてきたセキュリティ上の欠陥を次々と発掘する時代に入ってきた**ことを示しています。

## 対策・今後の展望

### ✅ 今すぐできる対策

#### 1. カーネルのアップデート
以下のバージョンで修正済みです：

- Linux 6.16.7
- Linux 6.15.42 ※記事では6.18.42と記載
- Linux 6.12.101
- Linux 6.6.148

> ⚠️ **注意！** ディストリビューション（UbuntuやDebianなど）はバージョン番号を変えずに修正を取り込む（バックポート）することがあります。バージョン番号だけで安全かどうかは判断できません。**必ず使っているOSのセキュリティ更新情報を確認してください。**

#### 2. SCTPモジュールを無効化する
SCTPを使っていないサーバーであれば、モジュール自体をブロックするのが最も確実な対策です。

```bash
# SCTPモジュールをブロックする例（/etc/modprobe.d/blacklist.confに追加）
blacklist sctp
```

#### 3. コンテナ環境の管理者は確認を
デフォルトのseccompプロファイル（セキュリティ設定）を適切に維持しているかを確認してください。

### 🔮 今後の動向

- 記事執筆時点（2026年8月7日）では、CISAの「既知の悪用済み脆弱性リスト」には未掲載
- 公開されたエクスプロイトコード（攻撃ツール）は確認されていない
- 同日に「Zapscape」というKVM（仮想マシン）脱出の欠陥も同時に修正されており、今後も継続した注意が必要

## 用語解説

| 用語 | 意味 |
|------|------|
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやシステムのセキュリティ上の弱点・欠陥 |
| **CVE** | 脆弱性に割り当てられる世界共通の識別番号（例: CVE-2026-64564） |
| **root** | Linuxにおける最高管理者権限。何でもできる状態 |
| **カーネル** | OSの中核部分。ハードウェアとソフトウェアの橋渡しをする |
| **SCTP** | インターネット通信プロトコルの一種。複数経路での通信が可能 |
| **use-after-free** | 解放済みのメモリ領域を誤って再利用するバグ。攻撃に悪用されやすい |
| **コンテナ** | アプリを隔離して動かす仮想化技術（例: Docker） |
| **コンテナ脱出** | コンテナの隔離を破ってホストマシンにアクセスする攻撃 |
| **バックポート** | 新バージョンへの更新なしに、古いバージョンへ修正だけを取り込むこと |
| **seccomp** | Linuxのシステムコール制限機能。コンテナのセキュリティ強化に使われる |
| **CVSS** | 脆弱性の深刻度を数値化するスコア（0〜10、高いほど危険） |
| **CISA KEV** | 米国政府機関が管理する「実際に攻撃に使われた脆弱性リスト」 |
| **CAP_NET_ADMIN** | Linuxのネットワーク設定変更に必要な権限 |
