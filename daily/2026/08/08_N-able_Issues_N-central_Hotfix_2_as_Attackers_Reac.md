# N-ableがN-centralの緊急修正パッチ第2弾を公開！攻撃者は管理下のシステムに侵入・居座り続けていた

**元記事**: [N-able Issues N-central Hotfix 2 as Attackers Reach Managed Systems and Persist](https://inl03.netline.com/ltr6/?_m=3n.009a.4051.sp0ao46r89.33w2)
**解説日**: 2026年8月8日

---

## 背景知識

このニュースを理解するために、まず「N-able」と「N-central」について知っておきましょう。

### N-ableとN-centralって何？

**N-able（エヌエイブル）** は、ITサービスを提供する会社（MSP：Managed Service Providerと呼ばれます）向けにツールを作っているソフトウェア企業です。

**N-central（エヌセントラル）** は、そのN-ableが作った **「RMMツール」** の一つです。

> 💡 **RMM（Remote Monitoring and Management）** とは？
> 「遠隔監視・管理」ツールのことです。ITの管理者が、離れた場所にあるたくさんのパソコンやサーバーを、まるで目の前にあるかのように監視・操作できるシステムです。
> 
> 🏫 **学校で例えると...**
> 先生が職員室にいながら、全教室のパソコンの状態を一画面で確認したり、問題があったら遠隔で修理できるようなシステムです。

### なぜRMMツールが狙われやすいのか？

RMMツールは **「多くのシステムへのマスターキー」** のような存在です。一つのRMMツールに侵入できれば、そのツールが管理している**すべての顧客のシステム**に一気にアクセスできてしまいます。これが攻撃者にとって非常に魅力的な標的になる理由です。

## 技術的な詳細

### 脆弱性の仕組み：「認証バイパス」って何？

今回の脆弱性（CVE-2026-18577）は **「認証バイパス（Authentication Bypass）」** と呼ばれる種類のものです。

> 💡 **認証バイパス** とは？
> 本来は「IDとパスワード」を正しく入力しないと入れない場所に、それをすり抜けて入ってしまう攻撃です。
> 
> 🔐 **鍵のかかったドアで例えると...**
> ドアを「鍵を使わずに」開けてしまう方法を見つけたようなものです。鍵がかかっていても、ドアの枠ごと外してしまうイメージです。

実は今回の脆弱性（CVE-2026-18577）は、**以前の脆弱性（CVE-2026-18556）を修正しようとしたが、直し方が不完全だった**ために生じた「修正ミスの脆弱性」でもあります。いわば「穴を塞いだつもりが、まだ隙間があった」状態です。

### 攻撃者がやったこと（ステップごとに解説）

**ステップ① 管理者権限を乗っ取る**
```
脆弱性を利用
    ↓
ログイン不要でN-centralサーバーに管理者としてアクセス
    ↓
「アカウント乗っ取り（Account Takeover）」完了
```

**ステップ② 管理下のシステムへ侵入**

N-centralには **「Take Control（テイクコントロール）」** という機能があります。これは本来、IT管理者が顧客のパソコンを遠隔操作するための正規の機能です。攻撃者はこの機能を悪用して、管理下にある多数のシステムに侵入しました。

> 🎮 **ゲームで例えると...**
> ゲームの管理者アカウントを乗っ取って、そのゲームに参加している全プレイヤーのキャラクターを自由に操作できるようになったイメージです。

**ステップ③ 「Cloudflareトンネル」で居座る仕掛けを作る**

ここが今回の攻撃で特に巧妙な部分です。

> 💡 **Cloudflareトンネル（Cloudflare Tunnel）** とは？
> 本来は「外部からシステムに安全にアクセスするための通信経路」を作るための正規サービスです。VPNに近いイメージで、正規の用途では多くの企業が使っています。

攻撃者はこのCloudflareトンネルを悪用して、**「隠し通路」** を作りました。

```
【通常の対処】
N-centralサーバーのアクセス権を取り消す → 攻撃者を追い出せる！

【今回の攻撃】
Cloudflareトンネル（隠し通路）を事前に仕掛けておく
    ↓
N-centralのアクセス権を取り消されても...
    ↓
隠し通路からいつでも戻ってこれる！（=「永続化・Persistence」）
```

> 🏠 **家の鍵で例えると...**
> 泥棒が家に入った後、こっそり「合鍵」を複製して隠しておき、正面玄関の鍵を変えられても、裏口の隠し鍵でいつでも入れるようにしておくようなイメージです。

## なぜ重要なのか

### 影響の大きさ

| 項目 | 内容 |
|------|------|
| 深刻度スコア | **8.2 / 10**（高い！） |
| 影響バージョン | N-central **2026.3.1.7より前の全バージョン** |
| 被害の種類 | 管理者権限の乗っ取り・管理下システムへの侵入・永続化 |
| CISAの評価 | **「実際に悪用されている」と公式認定** |

### なぜ「連鎖被害」が怖いのか

N-centralのようなRMMツールは、**一つの会社が複数の顧客のシステムを管理している**のが普通です。

```
N-centralサーバー（1台）
    ├── 顧客A社のシステム
    ├── 顧客B社のシステム
    ├── 顧客C社のシステム
    └── 顧客D社のシステム
```

つまり、N-centralサーバー1台が乗っ取られると、**そのサーバーが管理するすべての顧客のシステムが芋づる式に被害を受ける**可能性があります。これは「サプライチェーン攻撃」とも呼ばれ、近年非常に問題視されています。

## 対策・今後の展望

### ✅ 今すぐやるべきこと

**①【最重要】Hotfix 2（修正パッチ第2弾）を今すぐ適用する**

オンプレミス版（自社サーバーで運用）を使っている場合は、**バージョン 2026.3.1.10** に今すぐアップデートが必要です。

> ⚠️ 「Hotfix 1を適用した」だけでは**不十分**です！Hotfix 2は必ず別途適用してください。

**②【確認】侵害の痕跡（IoC）を確認する**

N-ableが公開している以下のIPアドレスから通信があった場合、**攻撃者が侵入した可能性**があります：

```
173.249.252.176 / 173.249.252.200
185.156.46.150 / 23.234.94.43
37.153.90.88 / 37.19.210.32
68.235.46.214 / 68.235.46.235
87.249.138.34 / 92.118.112.181
```

**③【確認ツール】カスタムサービステンプレートを使う**

N-ableが自動チェックツールを公開しています。ただし、N-able自身も言っているように「クリーンな結果が出ても、100%安全とは言い切れない」ので、ログの確認や環境の見直しも並行して行うことが重要です。

### 今後の展望

攻撃者は第1弾のパッチ公開後も**攻撃手口を進化させて継続攻撃**していることから、N-ableは引き続き調査・対応中です。新しい侵害の痕跡（IoC）が追加で公開される可能性があるため、定期的に情報を確認することが重要です。

## 用語解説

| 用語 | 解説 |
|------|------|
| **RMM（Remote Monitoring and Management）** | 遠隔でシステムを監視・管理するツールのこと |
| **MSP（Managed Service Provider）** | 他の企業のITシステムを代わりに管理・運用する会社 |
| **ゼロデイ脆弱性** | 発見されたばかりで、まだ修正パッチが存在しない脆弱性。攻撃者が修正前に悪用する |
| **CVE（Common Vulnerabilities and Exposures）** | 脆弱性に付けられる世界共通の識別番号（例：CVE-2026-18577） |
| **CVSSスコア** | 脆弱性の深刻度を0〜10点で示す指標。8.2は「重大」レベル |
| **認証バイパス（Authentication Bypass）** | 本来必要なIDやパスワードの確認を回避して不正アクセスする攻撃手法 |
| **アカウント乗っ取り（Account Takeover）** | 他人のアカウントを不正に支配下に置くこと |
| **Take Control（テイクコントロール）** | N-centralの遠隔操作機能。本来はIT管理者が使う正規の機能 |
| **Cloudflareトンネル** | 外部から安全に内部システムにアクセスするための正規サービス。今回は悪用された |
| **永続化（Persistence）** | 攻撃者が一度侵入したシステムに「追い出されても戻れる仕組み」を仕掛けること |
| **IoC（Indicator of Compromise）** | 侵害されたことを示す痕跡情報（不審なIPアドレスなど） |
| **CISA** | 米国のサイバーセキュリティ・インフラ安全保障局。日本のサイバーセキュリティ対策機関に相当 |
| **サプライチェーン攻撃** | 直接の標的ではなく、その標的と取引関係にある企業を踏み台にした攻撃 |
| **オンプレミス（On-premise）** | クラウドではなく、自社のサーバーにソフトウェアを設置して運用する形態 |
| **ホットフィックス（Hotfix）** | 緊急の問題を修正するために緊急リリースされるパッチ（修正プログラム） |
