# CSSを悪用したウェブメール攻撃：パスワードやトークンが盗まれる新手口

**元記事**: [New CSS Attacks Can Break Webmail Defenses to Steal Passwords and Tokens](https://inl03.netline.com/ltr6/?_m=3n.009a.4051.sp0ao46r89.33vq)
**解説日**: 2026年8月9日

---

## 背景知識

このニュースを理解するために、いくつかの基本的な概念を押さえておきましょう。

### 📧 ウェブメールとは？
GmailやYahoo Mailのように、**ブラウザ上で使えるメールサービス**のことです。アプリをインストールしなくてもインターネットにつながれば使えます。

### 🎨 CSS（シーエスエス）とは？
ウェブページの「見た目」を決めるための言語です。「この文字は赤くする」「この画像は右側に置く」といった見た目の指示をするものです。HTMLが「骨格」ならCSSは「服や化粧」のようなイメージです。

### 🛡️ サニタイザー（sanitizer）とは？
「消毒器」という意味で、セキュリティの世界では**危険なコードを無害化するフィルター**のことです。メールに悪意あるコードが含まれていても、ウェブメールサービスはこのフィルターで危険な部分を取り除いてから表示しようとします。

### 🔑 トークンとは？
パスワードの代わりに使われる「通行証」のようなものです。一度ログインすると発行され、「この人は本物だ」と証明するために使われます。銀行のATMカードのようなイメージです。

### 📦 iframeとは？
ウェブページの中に「別のウェブページ」を埋め込む箱のようなものです。安全のために、メール内容をこの箱に閉じ込めることで、外のページに影響を与えないようにする仕組みです。

## 何が起きたのか

セキュリティ企業「PortSwigger」の研究者である**ガレス・ヘイズ氏**が、2026年8月に開催された世界最大のセキュリティカンファレンス「**Black Hat USA 2026**」で、ウェブメールサービスを狙った新しい攻撃手法を発表しました。

### 🎯 影響を受けるサービス
- **Outlook**（マイクロソフト）
- **Gmail**（Google）
- **Fastmail**
- **Proton Mail**
- **Yahoo Mail**
- **AOL Mail**

つまり、世界中で何億人もの人が使っているメールサービスがターゲットになり得る、非常に影響範囲の広い発見です。

### 🚨 攻撃者にできること
| 攻撃内容 | わかりやすく言うと |
|---|---|
| パスワードの盗取 | 偽のログイン画面に入力したパスワードが盗まれる |
| トークンの漏洩 | 「通行証」が盗まれ、なりすましログインされる |
| アカウント乗っ取り | SNSなど連携サービスのアカウントを奪われる |
| AI操作 | メールを読むAIに悪意ある指令を送り込む |

なお、今回の発表は「こういう攻撃が可能です」という**研究・実証目的**のもので、実際に悪用されたという報告はありません。ただし、攻撃のサンプルコード（PoC）は公開されています。

## 技術的な詳細

ちょっと難しい話ですが、できるだけ例え話で説明します！

### 🔓 攻撃の基本的な考え方

ウェブメールには「**メールの中身**」と「**メールサービス本体の画面**」の間に壁があります。メールの中身がその壁を越えて、本体の画面を操作してしまうのが今回の攻撃の核心です。

> 🏠 例え話：マンションの部屋（メール）の中の人が、廊下（メールサービス本体）まで出てきて、エレベーターのボタン（本体の機能）を勝手に押す、というイメージです。

### ⚠️ 主な攻撃手口3つ

#### 1️⃣ Outlook＋Firefoxの「偽ログイン画面」攻撃
- CSSを使って、メールの中に**本物そっくりのMicrosoftログイン画面を偽装**します
- 受信者がパスワードを入力すると、それが攻撃者に送られてしまいます
- Firefoxブラウザの「選択肢を約1秒で処理する仕組み」を悪用して、**ほぼリアルタイムで**パスワードを盗みます

> 🎭 例え話：本物の銀行ATMに見せかけた「にせATM」を設置して、暗証番号を盗む犯罪に似ています

#### 2️⃣ Yahoo Mail＋AOL Mailの「コピー＆ペースト」攻撃
- 攻撃者がまず「Mediumというサービスへのログインメール」を送るよう仕掛けます
- 被害者に**悪意あるCSSをコピーさせて**、Yahoo/AOLのメール下書き画面に貼り付けさせます
- 貼り付けた瞬間、12文字のログイントークン（通行証）が少しずつ攻撃者のサーバーに送られ、最終的にトークン全体が復元されます
- 攻撃者はそのトークンを使ってMediumに被害者としてログインできます

> 📋 例え話：「このクーポンコードをコピーして貼り付けてね！」と言いながら、こっそり個人情報を盗み取る詐欺のようなイメージです

#### 3️⃣ Gmail＋AIアシスタントを使った「プロンプトインジェクション」攻撃
- GmailにはAIアシスタント「**Cowork（Claude搭載）**」が連携できます
- 攻撃者はSlackのトークン確認メールを送るよう仕掛け、**被害者がAIにメールを処理させると**、隠れた命令（プロンプトインジェクション）によってAIがSlackトークンを取り出し、HTMLの下書きに書き込みます
- 被害者がその下書きを開くと、トークンが漏洩します

> 🤖 例え話：「翻訳して」とAIに頼んだら、文章の中に隠れていた「翻訳後に銀行口座を送れ」という命令もAIが実行してしまう、という感じです

#### 4️⃣ Fastmail＋AIブラウザへの「視覚トリック」攻撃
- CSSを使って、**人間には「無害なテキスト」に見えるのに、AIには「隠れた命令」が見える**ように加工します
- OpenAIの「Atlas」というAIブラウザに対して、「テキストを翻訳して」と頼むと、隠れた命令が実行され、被害者の名前などの情報がURLに含まれて漏洩します

> 👁️ 例え話：紫外線ライトで見ないとわからない「隠し文字」で指令を書いて、紫外線で読めるロボット（AI）に実行させる、というトリックです

## なぜ重要なのか

### 🌍 影響範囲がとても広い
GmailやOutlookは世界で何億人もが毎日使っています。これらのサービスに存在する脆弱性（弱点）は、理論上は非常に多くの人に影響を与える可能性があります。

### 🆕 「CSS」が攻撃の主役という新しさ
これまでのウェブメール攻撃は主にJavaScript（ウェブの動きを作るプログラム言語）を使ったものが多かったため、ウェブメールサービスはJavaScriptを厳しく制限してきました。しかし今回の攻撃は**見た目を整えるだけのはずのCSSを悪用**しており、これは新しいアプローチです。

### 🤖 AIとの組み合わせで新しいリスク
メールを読んでくれるAIアシスタントは非常に便利ですが、今回の研究は「**AIも騙される**」ことを示しました。AIの普及とともに、このような攻撃のリスクも高まると考えられます。

### 📅 一部の脆弱性は発表時点でまだ修正されていない
研究発表（8月6日）時点で、**OutlookとGmailの一部の攻撃手法はまだ機能していた**と報告されています。これは現実の脅威として残っている可能性があることを意味します。

## 対策・今後の展望

### 👤 一般ユーザーができること

| 対策 | 説明 |
|---|---|
| 🔗 不審なメールのリンクを踏まない | 見知らぬ差出人からのメールは慎重に |
| 📋 不審なテキストをコピペしない | 「このコードをコピーして貼り付けて」という指示には注意 |
| 🔐 二段階認証を使う | パスワードが盗まれても追加の認証があれば被害を防ぎやすい |
| 🌐 ブラウザを最新版に保つ | Firefox等のブラウザのアップデートは常に行う |
| 🤖 AIアシスタントに重要なメールを処理させない | SlackやGitHubなどの認証メールは自分で確認する習慣を |

### 🏢 ウェブメール事業者への推奨（研究者より）
研究者は以下の対策を推奨しています：
- メールの中身を**サンドボックス化されたiframe**（隔離された箱）の中に閉じ込める
- CSS、カスタム属性、セレクトメニュー、画像リクエストを厳しく制限する

### 📰 各社の対応状況
- **Fastmail**: 2つのCSSバグを修正済み ✅
- **Proton Mail**: プロキシ経由の迂回が機能しなくなったと確認 ✅
- **Outlook**: ラベルの乗っ取りは発表時点でまだ機能中 ⚠️
- **Gmail**: image-set()の迂回は発表時点でまだ機能中 ⚠️
- **Atlas（OpenAI）**: 2026年8月9日にサービス終了予定 🔚

便利なAIツールが増えるほど、攻撃者にとって「AIを踏み台にする」という選択肢も増えていく——これは今後しばらく注目し続けるべきトレンドです。

## 用語解説

| 用語 | 説明 |
|---|---|
| **CSS** | ウェブページの見た目（色・配置・サイズなど）を決めるための言語 |
| **ウェブメール** | ブラウザ上で使えるメールサービス（Gmail、Outlookなど） |
| **サニタイザー** | 危険なコードを無害化するフィルター機能 |
| **トークン** | パスワードの代わりに使われる認証用の「通行証」文字列 |
| **iframe** | ウェブページ内に別のページを埋め込む「箱」。隔離に使われる |
| **PoC（Proof of Concept）** | 「こういう攻撃が実際に可能です」と証明するためのサンプルコード |
| **プロンプトインジェクション** | AIへの指示文に悪意ある命令を隠し込んで、AIを意図せず操作させる攻撃 |
| **CSP（Content Security Policy）** | ブラウザに「このサイトは外部の〇〇にしかアクセスしてはいけない」と制限をかける仕組み |
| **サンドボックス** | 悪影響が外に出ないよう、プログラムを隔離した環境で動かす仕組み |
| **Black Hat USA** | 世界最大規模のサイバーセキュリティカンファレンス（学会のようなもの） |
| **DOM** | ブラウザがウェブページを内部で管理するためのデータ構造 |
| **メディアクエリ** | 画面サイズなどの条件によってCSSを切り替える仕組み |

---

> 💬 **まとめ**：今回の研究は「メールを開いて読むだけで攻撃される可能性がある」という怖い内容ですが、複雑な条件が重なる必要があるため、すぐに全員が被害を受けるわけではありません。ただし、GmailやOutlookを使っているすべての人に関係する話なので、各サービスのアップデート情報に注目しておくことが大切です。特にAIとメールを組み合わせて使っている方は、今回の研究を念頭に置いて慎重に利用しましょう。
