# WordPressのログイン画面に重大な欠陥！管理者PCが乗っ取られる危険性

**元記事**: [New WordPress Pre-Auth XSS Could Lead to PHP Code Execution - Patch ASAP](https://inl03.netline.com/ltr6/?_m=3n.009a.4051.sp0ao46r89.33we)
**解説日**: 2026年8月9日

---

## 背景知識

まず、このニュースを理解するための基礎知識を整理しましょう。

### WordPressとは？
ウェブサイトを簡単に作れる「ブログ・サイト作成ツール」です。世界中のウェブサイトの約43%がWordPressで作られているとも言われており、個人ブログから企業サイトまで幅広く使われています。

### XSS（クロスサイトスクリプティング）とは？
一言でいうと「ウェブページに悪意あるプログラムを埋め込む攻撃」です。

> 🏫 **例え話**: 学校の掲示板（ウェブサイト）に、だれかがイタズラで「この掲示板を見たら自動的に個人情報を送信するプログラム」を貼り付けるイメージです。見た人が知らないうちに被害を受けます。

### 「ログイン前に攻撃できる（Pre-Auth）」とは？
通常、ウェブサービスへの攻撃にはまず「ログイン（認証）」が必要なことが多いです。しかし今回の欠陥は、**ログインしていない状態（=誰でも）**でも攻撃を仕掛けられてしまいます。

### PHPコード実行とは？
PHPとはWordPressが動いているサーバー側のプログラミング言語です。攻撃者がこれを「実行」できてしまうと、**サーバーを自由に操作できる状態**＝完全乗っ取りに近い状態になります。

---

## 何が起きたのか

WordPressのすべてのバージョンに影響する重大な脆弱性（セキュリティの穴）が発見・修正されました。

- **脆弱性の番号**: CVE-2026-64638（CVSS スコア: 8.9 / 10点満点中、かなり深刻）
- **発見者**: セキュリティ研究チーム「pwn.ai」
- **修正日**: 2026年8月6日（WordPress 7.0.3にてパッチ公開）

### 攻撃のシナリオをざっくり説明すると…

```
① 攻撃者が「罠のページ」を用意する
        ↓
② WordPressの管理者（サイト運営者）が
   そのページを1回クリックする
        ↓
③ 攻撃者がWordPressサーバーを
   自由に操作できるようになる
```

たった**1回のクリック**でサーバーを乗っ取られる可能性があるのです。

## 技術的な詳細

少し難しいですが、できるだけわかりやすく説明します。

### ステップ1：ログイン失敗ページへの罠の仕込み

WordPressでログインに失敗すると「ユーザー名またはパスワードが違います」というエラーページが表示されます。

このとき、入力した「ユーザー名」がそのままページに表示されます。

ここに問題がありました。WordPressは入力値を「危険なコード」として除去しようとするのですが、**2つの異なる除去ルールの間のスキマ**を突かれました。

> 🔍 **具体的には**: 
> - `<script>`のような危険タグは除去される
> - しかし`< script>`（<の後にスペースがある）のような書き方は、1つ目のルールでは「タグではなくただの文字列」とみなされ通過
> - 2つ目のルールでは「タグ」として解釈される
> 
> → 結果として**悪意あるHTMLがページに混入**してしまう

### ステップ2：WordPressの正規スクリプトを乗っ取る

WordPressのログインページには、パスワードリセット機能のために「user-profile.js」というプログラムが読み込まれています。

攻撃者は、ステップ1で混入させたコードを使って、**このWordPress純正のスクリプトの動作を乗っ取り**、攻撃者が指定したサーバーへの通信を発生させます。

> 🎮 **例え話**: ゲームのコントローラー（JavaScriptファイル）を乗っ取って、ゲーム内のキャラクター（WordPress）が攻撃者の指示通りに動くようにするイメージです。

### ステップ3：JavaScriptからPHPコード実行へ

「JSONP」というウェブの仕組みと、研究者Paulos Yibeloが2022年に発表した「SOME（Same Origin Method Execution）」という技術を組み合わせることで、最終的にサーバー側でPHPコードを実行できてしまいます。

研究者たちはこの攻撃チェーン全体を **「XSS2Shell（エックスエス・エス・トゥ・シェル）」** と呼んでいます。

### 攻撃の具体例
- 悪意あるプラグインをこっそりインストールする
- 任意のファイル（ZIPファイルなど）をサーバーにアップロードする

## なぜ重要なのか

### 影響範囲が非常に広い
- **WordPress 4.7以降のすべてのバージョン**が対象
- 世界中の何百万ものウェブサイトに影響

### 攻撃のハードルが低い
| 条件 | 内容 |
|------|------|
| 攻撃者に必要なもの | **なし**（ログイン不要） |
| 被害者に必要な操作 | 1回のクリックのみ |
| 特殊な環境設定 | 不要（デフォルト設定で動作） |

### セキュリティ機能を回避できる
通常、こういった攻撃を防ぐための仕組みに「**CSP（コンテンツセキュリティポリシー）**」があります。しかし研究者たちは、`strict-dynamic`という比較的強固なCSP設定でも**この攻撃を防げなかった**と報告しています。

## 対策・今後の展望

### ✅ 今すぐやるべきこと

**WordPressを最新版（7.0.3以上）にアップデートする！**

```
WordPressの管理画面 → ダッシュボード → 更新 → 今すぐ更新
```

- 自動更新が有効になっているサイトは、すでに自動的にパッチが当たっている可能性があります
- **WordPress 4.7より古いバージョン**は修正パッチが提供されないため、早急なバージョンアップが必要です

### ⚠️ 追加の注意点
- **WordPress管理者は見知らぬURLをクリックしない**こと（フィッシングメールや不審なリンクに注意）
- サイト管理者は**不要なプラグインや旧バージョンのWordPress**を放置しないこと
- ウェブ改ざん検知サービスの導入も有効です

### 今後の動向
WordPressを動かすAIシステムがこの脆弱性を約4日間で自動発見・再現したという点も注目されています。AIを使ったセキュリティ脆弱性の自動発見は今後ますます増えていくと考えられます。

## 過去記事との関連

以前、「**CSSを悪用したウェブメール攻撃**」について解説しました（2026年8月8日）。あの攻撃はCSSというウェブの「デザイン言語」を悪用してパスワードやトークンを盗むものでした。

今回のWordPress XSS攻撃も共通する考え方があります。それは「**本来、安全なはずの仕組みや言語を組み合わせることで予期しない攻撃ができてしまう**」という点です。

- CSS攻撃：デザイン用のCSSを使って情報を盗む
- 今回：ログイン処理・WordPressの正規スクリプト・JSONPを組み合わせてサーバーを乗っ取る

どちらも「悪用されると思っていなかった機能」が攻撃に使われており、**現代のウェブセキュリティの難しさ**を示しています。

## 用語解説

| 用語 | 意味 |
|------|------|
| **XSS（クロスサイトスクリプティング）** | ウェブページに悪意あるスクリプトを埋め込む攻撃手法 |
| **Pre-Auth（認証前）** | ログインしていない状態でも攻撃できること |
| **CVSS スコア** | 脆弱性の深刻度を0〜10で表す指標。8.9は「高（High）」 |
| **PHP** | WordPressがサーバー側で使っているプログラミング言語 |
| **RCE（リモートコード実行）** | 遠隔から任意のコードをサーバーで実行できる最も危険な攻撃 |
| **JSONP** | 異なるサイト間でデータをやり取りするためのウェブの仕組み |
| **CSP（コンテンツセキュリティポリシー）** | ブラウザに「どのスクリプトを実行してよいか」を伝えるセキュリティ設定 |
| **nonce（ノンス）** | 使い捨ての認証トークン。CSRF攻撃などを防ぐために使う |
| **ソーシャルエンジニアリング** | 人の心理を利用して騙し、情報や操作を引き出す攻撃手法 |
| **パッチ（Patch）** | ソフトウェアの欠陥を修正するための小さなアップデート |
| **SOME** | 同一オリジン内のメソッドを外部から呼び出す攻撃技術（2022年に発表） |
