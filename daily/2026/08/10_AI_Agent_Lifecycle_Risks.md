# AIエージェントのライフサイクルリスク：誰も管理していないAIが組織の中で動き続けている！

**元記事**: [AI Agent Lifecycle Risks](https://inl03.netline.com/ltr6/?_m=3n.009a.4052.sp0ao46r89.33xs)
**解説日**: 2025年8月10日

---

## 背景知識

まず、この記事を理解するために必要な言葉を整理しましょう。

### 🤖 AIエージェントって何？
「AIエージェント」とは、人間が直接操作しなくても**自動的に判断・行動するAIプログラム**のことです。たとえば「毎日午前3時に売上データを集計して報告書を作るAI」や「メールを自動で振り分けて返信するAI」などが該当します。最近は企業の中でこういったAIが大量に動いています。

### 🪪 「非人間アイデンティティ（Non-Human Identity）」って何？
コンピューターの世界では、システムにアクセスする「誰か」を「アイデンティティ（識別情報）」と呼びます。人間のアカウントだけでなく、**AIやプログラム・ツール自体にも「このシステムにアクセスしていいですよ」という証明書（IDやパスワードのようなもの）が与えられます**。これを「非人間アイデンティティ」と言います。

> 🏫 **例え話**：学校に例えると、生徒（人間）だけでなく、自動清掃ロボット（AI）にも「校内を移動していいよ」という通行証が発行されているイメージです。

### 🕵️ 「シャドーAI（Shadow AI）」って何？
IT部門や管理者が**知らないうちに、誰かが勝手に導入・稼働させているAI**のことです。「シャドーIT」（会社公認でないツールの無断使用）のAI版ですね。

|--------|------|

| **82%** | の組織で、誰も承認していない「シャドーAI」が発見されている |
| **21%** | しか、AIエージェントを適切に停止・廃止する手順を持っていない |

つまり、**多くの企業でAIが「放置」されている状態**が深刻な問題になっているという話です。

## 技術的な詳細

### AIエージェントがどうやって危険になるのか、ステップで見てみましょう

```
① AIエージェントが作られる（数分で完成！）
        ↓
② タスクをこなすために、どんどん「権限」を集めていく
   （例：メール読む権限、ファイル見る権限、外部サービスに接続する権限...）
        ↓
③ 使い終わっても、誰も削除・停止しない
        ↓
④ アクセス権限だけが残り続ける ← ⚠️ここが危険！
        ↓
⑤ 攻撃者がそのAIの権限を乗っ取れば、システム内を自由に動き回れる
```

### 🔑 「権限の肥大化」問題
AIエージェントは最初は小さな権限しか持っていなくても、仕事をこなすうちに**どんどん追加の権限を要求・取得**していきます。これを「クリープ（こっそり広がる）」と言います。

最終的には**本来必要以上の権限を持つAIが大量に存在**することになります。

> 🏫 **例え話**：アルバイトとして入った人が「ちょっと職務の範囲を広げていい？」と少しずつお願いし続けて、気づいたら社長室のカギまで持っている…という状態を想像してください。

## なぜ重要なのか

### 😱 数字で見ると怖さがわかる
- 社員1000人の会社なら、**約10万9000個**の非人間アイデンティティが存在している計算になります
- そのうちの多くは、誰も把握していない、管理されていない状態です

### 🎯 攻撃者にとっての「おいしいターゲット」
人間のアカウントは多要素認証（2段階認証）などで守られていることが多いですが、**AIエージェントのアカウントはそういったセキュリティ対策が手薄なことが多い**です。

攻撃者がAIエージェントの認証情報（IDやトークン）を盗めば：
- 機密データへのアクセス
- 社内システムの操作
- さらなる攻撃の踏み台

といった被害が起きる可能性があります。

### 🚪 「退場手続き」がない問題
人間の従業員が退職するとき、会社はそのアカウントを削除しますよね。でも**AIエージェントが不要になっても、79%の組織には適切な「廃止手順」がない**のです。ゾンビのように権限だけが生き続けます。

## 対策・今後の展望

### ✅ 企業がとるべき対策

**1. AIエージェントの棚卸し（インベントリ管理）**
> まず「うちの組織にどんなAIが動いているか」を全部リストアップしましょう。知らないうちに動いているシャドーAIがないか確認することが第一歩です。

**2. 最小権限の原則を守る**
> AIエージェントには「その仕事に必要な最小限の権限だけ」を与えるようにしましょう。「とりあえず全部アクセスできるようにしておこう」はNGです。

**3. ライフサイクル管理（誕生から廃止まで）**
> AIエージェントを作るときから、「いつ・どうやって停止するか」を決めておきましょう。不要になったAIはちゃんと権限ごと削除することが大切です。

**4. 定期的な監査**
> 定期的にAIエージェントの権限と動作を見直し、不審な動きがないかチェックしましょう。

### 🔮 今後の展望
Token SecurityのようなAI・非人間アイデンティティ専門のセキュリティツールが今後ますます注目されるでしょう。「AIを守るセキュリティ」という新しい分野が急成長しています。

## 過去記事との関連

以前、**「OpenAIの新AIモデル『Astra』がサイバー攻撃能力が高すぎて開発一時停止」** という記事を紹介しました。

あの記事では「AIが攻撃する側になる危険性」が話題でしたが、今回の記事は**「AIが攻撃される・悪用される側になる危険性」**に焦点を当てています。

```
前回：AI自体が強力な攻撃ツールになりうる（攻撃する側のリスク）
今回：管理されていないAIが攻撃者に悪用される（守る側のリスク）
```

AIのセキュリティリスクは「外から攻めてくる問題」だけでなく、**「内側で管理されずに広がっていく問題」**もあるということが、この2つの記事からよくわかります。AIが社会に広まるにつれて、セキュリティの課題も複雑になってきていますね。

## 用語解説

| 用語 | 意味 |
|------|------|
| **AIエージェント** | 自動的に判断・行動するAIプログラム。人間が逐一指示しなくても動く |
| **非人間アイデンティティ（Non-Human Identity）** | AIやプログラムに付与されるアクセス証明書・ID |
| **シャドーAI（Shadow AI）** | IT管理者や会社が把握・承認していない、無断で使われているAI |
| **権限（パーミッション）** | 「このデータにアクセスしていい」「この操作をしていい」という許可 |
| **最小権限の原則** | 必要最低限の権限だけを与えるセキュリティの基本ルール |
| **ライフサイクル管理** | システムやソフトウェアの「作成→運用→廃止」を適切に管理すること |
| **トークン（Token）** | パスワードの代わりに使われる認証用の電子的な「チケット」 |
| **CTO（Chief Technology Officer）** | 最高技術責任者。会社の技術方針を統括するトップ |
| **Unit 8200** | イスラエル軍の精鋭サイバーインテリジェンス部隊。世界トップクラスのサイバー専門家を多数輩出 |
