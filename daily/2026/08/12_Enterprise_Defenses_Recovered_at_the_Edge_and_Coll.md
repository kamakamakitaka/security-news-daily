# 企業の防御：外壁は回復したが、内側は崩壊していた

**元記事**: [Enterprise Defenses Recovered at the Edge and Collapsed Inside](https://inl03.netline.com/ltr6/?_m=3n.009a.4054.sp0ao46r89.33zw)
**解説日**: 2025年7月14日

---

## 背景知識

このニュースを理解するために、まず「企業のネットワークセキュリティ」の基本的な考え方を知っておきましょう。

### 🏰 お城で例えるネットワーク防御

企業のITセキュリティは、よく「お城」に例えられます。

```
【外側】                    【内側】
  ___________              ___________
 |           |            |           |
 |  ファイア  |   =====>  |  社内の   |
 | ウォール等 |  侵入成功  |  サーバー |
 |___________|            |___________|
  ↑ここを頑張って守る       ↑ここが今回の問題
  「境界防御（ペリメーター）」
```

- **境界防御（ペリメーター）**：お城の外壁・堀にあたる部分。ファイアウォールや入口のセキュリティチェックなど、外部からの攻撃を防ぐ仕組みのこと
- **内側（内部ネットワーク）**：お城の中。一度外壁を突破されると、攻撃者が自由に動き回れる可能性がある場所

### 🔍 知っておきたい用語（予習）

| 用語 | 簡単な説明 |
|------|-----------|
| **EDR** | パソコンやサーバーの中の怪しい動きを監視するセキュリティソフト |
| **LSASS** | Windowsがパスワード情報を管理するための重要なプログラム |
| **Mimikatz** | パスワードを盗み出すために攻撃者がよく使うツール（名前を覚えておいて！） |
| **ラテラルムーブメント** | 侵入後、攻撃者がネットワーク内の別のコンピューターへ移動すること |
| **リコナサンス（偵察）** | 攻撃前に「どんなシステムがあるか」を静かに調べること |
| **クレデンシャル（認証情報）** | IDやパスワードのこと |

## 何が起きたのか

セキュリティ会社「**Picus Labs**」が、2026年上半期に実施した**3億3,800万回以上の攻撃シミュレーション**（本物の企業環境を使ったテスト）の結果をまとめた「Blue Report 2026」を発表しました。

### 📊 主な発見

**🟢 良いニュース：外壁は強くなっている！**
- 境界防御（外側のセキュリティ）の平均有効率が **62% → 69%** に向上
- ログ記録（何が起きたかの記録）は4年間で最高の **58%** に達した

**🔴 悪いニュース：でも内側はボロボロ…**
- 攻撃者が一度内部に侵入した後の防御成功率は、たった **37%**
- つまり、内側では3回に1回しか攻撃を止められていない

```
外側の防御力： ██████████ 69%（2回に1回以上止める）
内側の防御力： ████░░░░░░ 37%（3回に1回しか止められない）
```

## 技術的な詳細

### 🔇 「うるさい攻撃」vs「静かな攻撃」：防御成功率の差が歴然

今回の報告書で最も衝撃的だったのは、**「攻撃の派手さ」と「防御の成功率」が強く連動している**という事実です。

#### 派手な（うるさい）攻撃 → よく止められる

| 攻撃の種類 | 説明 | 防御成功率 |
|-----------|------|-----------|
| ラテラルムーブメント（SMBExec等） | 別のPCへ移動する動き | **約90%** |
| UAC回避（権限昇格） | 管理者権限を不正取得 | **約85%** |

これらはEDR（端末監視ソフト）が長年対策してきた「目立つ攻撃」なので、うまく止められています。

#### 静かな攻撃 → ほとんど止められない 😱

| 攻撃の種類 | 説明 | 防御成功率 |
|-----------|------|-----------|
| 偵察・ネットワーク探索 | どんなPCやファイルがあるか調べる | **わずか10%** |
| クレデンシャル窃取（メモリから） | パスワードをメモリから盗む | **約22%** |
| クレデンシャル窃取（レジストリから） | パスワードをシステム設定から盗む | **1%未満** |

```
🎯 攻撃者の行動の流れ

[静かに偵察]  →  [パスワードを盗む]  →  [派手な行動を起こす]
  防御10%         防御1〜22%            防御85〜90%
  ↑ほぼ無防備↑    ↑ほぼ無防備↑         ↑ここだけ守れてる↑

問題は「静かな段階」で準備を整えられてしまうこと！
```

### 🎭 同じツール、3つの方法で防御率が激変する例

これを象徴する面白い実験結果があります。攻撃ツール「**Mimikatz（ミミカッツ）**」を使って、同じ目的（パスワードを盗む）を3つの方法で試したところ…

```
【方法①】有名な定番の手口でLSASSから盗む
→ 防御成功率：ほぼ100% ✅（シグネチャで即バレ）

【方法②】別のメモリ場所から盗む
→ 防御成功率：ほぼ0% ❌（静かすぎて気づかれない）

【方法③】レジストリ（設定ファイル）から盗む
→ 防御成功率：1%未満 ❌❌（普通の操作に見える）
```

#### なぜこんな差が生まれるの？

セキュリティソフトの多くは「**シグネチャ（署名）**」という仕組みで攻撃を検知します。

> 🎵 シグネチャとは…
> 「このパターンが来たら危険！」というブラックリストのようなもの。
> 例：「lsass.exeというプログラムのメモリを読もうとしたら即ブロック！」

でも、攻撃者がちょっと方法を変えると…

```
シグネチャが監視してるもの  → 「lsass.exeのメモリを読む行為」
攻撃者の新しい手口         → 「レジストリを読む行為（普通の操作と区別不可）」

= シグネチャが反応する条件が満たされない → 素通り！
```

さらに怖いのは、Mimikatz自体を使わなくても、**Windowsに最初から入っている正規のツール**でも同じことができてしまう点です。攻撃ツールを持ち込む必要さえないのです。

## なぜ重要なのか

### 🚨 「守れてる」という錯覚が最大の危険

この報告書が示す最大の問題点は、**企業がセキュリティの数字を見て安心してしまうリスク**です。

```
経営者「防御率69%に上がった！よし！」
        ↓でも実は…
侵入後の世界では防御率37%
特にパスワード窃取は1〜22%しか防げていない
```

### 📅 攻撃者の「静かな準備期間」

攻撃者は内部に入った後、以下のような「準備」をほぼ無抵抗で行えます：

1. ネットワーク内にどんなPCやサーバーがあるか地図を作る（偵察・防御率10%）
2. 管理者パスワードを静かに盗む（防御率1〜22%）
3. **準備が整ったら**、派手な攻撃（ランサムウェアの実行など）を開始

「派手な攻撃しか止められない」ということは、**準備を全部終わらせてから攻撃されたら手遅れ**ということです。

### 影響を受けるのは？

- 社内ネットワークを持つあらゆる企業・組織
- 特にクラウドと社内システムが混在する複雑な環境
- 「境界防御を頑張ってきたから大丈夫」と思っている組織が要注意

## 対策・今後の展望

### ✅ 今すぐできる対策のヒント

#### 1. 「侵入された前提」で考える（ゼロトラスト）
> 「外壁さえ守ればOK」という考えを捨て、「すでに内部に侵入者がいるかもしれない」という前提でセキュリティを設計する考え方

#### 2. 偵察行動を検知する仕組みを作る
- 社内ネットワークで「誰がどのPCを探索したか」のログを詳細に取る
- 通常と違うパターンの探索活動をアラートにする

#### 3. 「シグネチャ検知」だけに頼らない
- **振る舞い検知（UEBA）**：「このユーザーらしくない行動をしている」を検知する仕組みを導入
- 既知の攻撃パターンだけでなく、**行動の異常**を監視する

#### 4. 最小権限の原則を徹底する
- すべてのユーザーに「必要最小限の権限のみ」を与える
- 管理者パスワードが盗まれても被害を最小化

#### 5. 攻撃シミュレーションテストを定期実施
- 今回の報告書のように、自分たちのセキュリティを**実際に攻撃してテストする**ことが重要

### 🔮 今後の展望

攻撃者はますます「静かで目立たない手法」に移行していくと予想されます。防御側も、シグネチャ（パターンマッチング）だけでなく、**AIを使った異常行動の検知**に力を入れる方向に進化が必要です。

## 用語解説

| 用語 | 詳しい説明 |
|------|-----------|
| **ペリメーター（境界防御）** | ネットワークの外と内の境界を守るセキュリティ。ファイアウォールや入口認証など |
| **EDR** | Endpoint Detection and Response。PCやサーバー上の怪しい動きをリアルタイムで検知・対応するソフト |
| **LSASS** | Local Security Authority Subsystem Service。Windowsがログイン情報（パスワード等）を管理するプロセス。攻撃者の標的になりやすい |
| **Mimikatz** | セキュリティ研究者が作ったツールで、Windowsのメモリからパスワードを取得できる。攻撃者にもよく悪用される |
| **シグネチャ** | 「この特徴を持つものは危険」というセキュリティソフトのブラックリスト的なパターン定義 |
| **ラテラルムーブメント** | 侵入後、攻撃者がネットワーク内の別のコンピューターへ横移動すること |
| **リコナサンス（偵察）** | 攻撃前にターゲットのネットワーク構成や脆弱性を静かに調査する行為 |
| **クレデンシャル（認証情報）** | ユーザーIDやパスワード、認証トークンなど、ログインに必要な情報全般 |
| **レジストリ** | Windowsの設定情報をまとめて管理するデータベース。パスワード情報が保存されることもある |
| **UAC回避** | Windowsの「本当に実行していいですか？」確認機能（ユーザーアカウント制御）を騙して管理者権限を取得する手法 |
| **ゼロトラスト** | 「社内ネットワークだから安全」という前提を捨て、すべてのアクセスを常に検証するセキュリティの考え方 |
| **振る舞い検知（UEBA）** | 「このユーザーの行動が普段と違う」という異常を検知する技術。パターンを知らない新しい攻撃にも対応できる |

---

> 💡 **今日のまとめ**
> 
> 企業のセキュリティは「外壁の修復は進んでいるが、内側はガラガラ」な状態。
> 攻撃者は**静かに偵察してパスワードを盗む**段階がほぼノーガード（防御率1〜10%）であることを知っており、その「静かな準備」を終わらせてから一気に攻撃します。
> 「うるさい攻撃だけ止められる」防御は、最も重要な段階で機能していないのです。
