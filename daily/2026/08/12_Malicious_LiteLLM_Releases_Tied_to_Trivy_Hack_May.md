# 悪意あるLiteLLMリリースがTrivyハック事件と関連――2,100以上の組織が情報漏洩の可能性

**元記事**: [Malicious LiteLLM Releases Tied to Trivy Hack May Have Exposed 2,100+ Organizations](https://inl03.netline.com/ltr6/?_m=3n.009a.4054.sp0ao46r89.3408)
**解説日**: 2025年7月15日

---

## 背景知識

このニュースを理解するために、まずいくつかの重要な概念を説明します。

### 🧩 ソフトウェアの「パッケージ」って何？

プログラマーは、ゼロからすべてのコードを書くのではなく、他の人が作った便利な「部品（パッケージ）」を組み合わせてアプリを作ります。

料理で例えると、**「出来合いのソース」を買ってきて料理に使う**感覚です。このパッケージを配布する場所が「**PyPI（パイピーアイ）**」というPython言語専用の公式パッケージ置き場です。

> **PyPI（Python Package Index）**: Pythonプログラム用の「部品」を公開・配布するための公式サイト。世界中の開発者が利用しています。

### 🤖 LiteLLMとは？

**LiteLLM（ライトLLM）**は、ChatGPT（OpenAI）やClaudeなどのAIを、企業のシステムに繋げるための「橋渡し役」となるオープンソース（無料・公開）ソフトウェアです。AI開発をしている多くの企業が使っています。

### 🔑 「クレデンシャル（認証情報）」って何？

クレデンシャルとは、システムにログインするための**カギのような情報**の総称です。具体的には：
- パスワード
- APIキー（AIサービスを使うための特別な合言葉）
- SSHキー（サーバーにアクセスするための電子的な鍵）
- データベースのパスワード

### ⚙️ CI/CDって何？

**CI/CD（継続的インテグレーション／継続的デリバリー）**とは、プログラムを自動でビルド（組み立て）・テスト・公開する仕組みです。工場の**自動組み立てライン**のようなものです。このラインには多くの「カギ」（クレデンシャル）が使われています。

## 何が起きたのか

### 📦 「汚染された部品」が40分間、公式サイトに公開されていた

2025年3月24日、攻撃者たちがLiteLLMというパッケージの**偽バージョン（1.82.7と1.82.8）**をPyPIに公開しました。

この偽パッケージは**午前10時39分（UTC）から約40分間**だけ公開されていましたが、その間にインストールしたシステムでは、様々な「カギ（クレデンシャル）」が盗まれた可能性があります。

> 🏠 **例え話**: 鍵のコピーを作る業者が、ある日突然「偽物の業者」に入れ替わっていた。その間に「鍵を複製してもらった人」は、気づかないうちに家の合鍵を犯罪者に渡してしまった──そんなイメージです。

### 📊 被害の規模

セキュリティ調査会社の**CloudSEK**によると、攻撃者が収集したとみられる**約43万4,000ファイル**を分析した結果、**2,500以上の組織**が影響を受けた可能性があると判明。

名前が挙がっている組織の中には、**NVIDIA、Cisco、Deloitte、Volkswagen、FedEx、Siemens、X Corp（旧Twitter）**など、世界的な大企業も含まれています。

> ⚠️ **重要な注意**: これらの組織が「確実に被害を受けた」という証明ではありません。「そのシステムから取られたファイルが見つかった」という話です。

## 技術的な詳細

### 🕵️ どうやって情報を盗んだのか？

#### ステップ1: 悪意あるコードを仕込む

偽バージョン（1.82.8）には、**`litellm_init.pth`** という特殊なファイルが含まれていました。

このファイルの恐ろしい点は、**Pythonを起動するたびに自動で悪意あるコードが実行される**ことです。LiteLLMを直接使っていなくても、Pythonが動くだけで発動します。

> 🔌 **例え話**: コンセントにつなぐだけで自動で動く「盗聴器」が仕込まれた電源タップ。その電源タップを使っている機器は何でも影響を受けます。

#### ステップ2: 情報を収集する

悪意あるコードは以下の情報を収集しました：

| 収集対象 | 説明 |
|---------|------|
| 環境変数 | システムの設定情報（APIキーなどが含まれることが多い） |
| SSHキー | サーバーへのアクセス用の電子的な鍵 |
| クラウドの認証情報 | AWS・GCPなどのクラウドサービスへのアクセス情報 |
| Kubernetesトークン | サーバー管理システムへのアクセス情報 |
| データベースパスワード | データベースへのログイン情報 |
| AIサービスのAPIキー | OpenAI・Anthropicなどへのアクセスキー |

#### ステップ3: 攻撃者のサーバーに送信

盗んだ情報は暗号化されて、攻撃者が用意した**偽のサーバー**（`models.litellm[.]cloud`）に送られました。このドメインは本物のLiteLLMとは無関係です。

### 🔗 「気づかずにインストールされる」危険性

特に怖いのは、**LiteLLMを意識的にインストールしていなくても感染する可能性**があることです。

プログラムはA→B→Cのように「部品の部品」を使うことがあります（これを**推移的依存関係**と言います）。LiteLLMに依存する別のツールをインストールするだけで、気づかないうちにインストールされることがあります。

> 🍱 **例え話**: お弁当を買ったら、その中に使われていた食材の一部が問題のある業者から来ていた──自分は直接その業者と取引していないのに影響を受けるケースです。

## なぜ重要なのか

### 🌐 より大きなサプライチェーン攻撃の一部

このLiteLLM事件は単独の出来事ではなく、**「TeamPCP」**と呼ばれる大規模なサプライチェーン攻撃（ソフトウェアの製造・流通過程を狙う攻撃）の一部です。

Googleはこの攻撃グループを**「UNC6780」**として追跡しています。

同じグループはセキュリティツール「**Trivy（トリビー）**」にも攻撃を仕掛け、76ものバージョンに悪意あるコードを混入させました。

### ⏰ 「盗まれたカギ」は今も使える

盗まれたAPIキーやSSHキーは、**変更（ローテーション）しない限り永遠に有効**です。

3月に盗まれたカギが、何ヶ月も経った今も使える状態であれば、攻撃者はいつでもそのカギを使ってシステムに侵入できます。

**FBIも2025年7月2日に警告**を発し、「攻撃者は最初の侵入からかなり後になってから、盗んだ認証情報を悪用する可能性がある」と注意を促しています。

### 📋 CVEとCISAカタログへの追加

この一連の攻撃は**CVE-2026-33634**として登録され、アメリカの政府機関CISAの「既知の悪用された脆弱性カタログ」にも追加されました。これは非常に深刻な脆弱性として公式に認定されたことを意味します。

## 対策・今後の展望

### ✅ 今すぐやるべきこと

#### 1. 感染しているか確認する
- 3月24日にLiteLLMをインストール・更新した記録がないか確認
- バージョン **1.82.7** または **1.82.8** をインストールしていないか確認
- 依存関係として間接的にインストールされていた可能性も確認

#### 2. 認証情報を即座に変更（ローテーション）する
もし感染の可能性がある場合、以下を**すぐに変更**してください：

```
✔ クラウドサービスのAPIキー（AWS, GCP, Azureなど）
✔ AIサービスのAPIキー（OpenAI, Anthropicなど）
✔ SSHキー
✔ データベースのパスワード
✔ CI/CDシステムのトークン
```

> 💡 **ポイント**: 「盗まれた証拠がない」は「安全」ではありません。疑わしければ変更するのが鉄則です。

#### 3. 長期間有効なトークンを使わない

FBIとセキュリティ企業Aquaは、**長期間有効なトークンをやめて、短期間だけ有効な一時トークンに移行する**よう推奨しています。

> 🔑 **例え話**: 「マスターキー」を1本持つより、「その日だけ有効なキー」を毎日発行する方が、万が一盗まれても被害が少ない。

#### 4. バージョンを固定する（ピン留め）

パッケージのバージョンを固定（「バージョンピン留め」）することで、知らないうちに悪意あるバージョンにアップデートされるリスクを減らせます。

### 🔮 今後の展望

- Aqua SecurityやUnit 42などのセキュリティ企業が引き続き調査中
- AIツールを狙ったサプライチェーン攻撃は今後も増加が予想される
- オープンソースパッケージのセキュリティ審査強化が業界全体の課題に

## 過去記事との関連

今回の事件は、**Trivyスキャナーへのサプライチェーン攻撃（TeamPCP/UNC6780キャンペーン）**と同じ攻撃グループによるものです。Trivyは開発現場でよく使われるセキュリティスキャンツールで、そのバージョンタグ76個が一気に書き換えられるという大規模な攻撃が3月19日にありました。

今回のLiteLLM事件はその**5日後**に起きており、同じグループが開発ツールのエコシステム全体を標的にした組織的な攻撃であることが分かります。「ひとつのツールだけ気をつければいい」ではなく、**開発環境全体のセキュリティ**を見直す必要性を示しています。

## 用語解説

| 用語 | 説明 |
|------|------|
| **PyPI** | Pythonプログラムの部品（パッケージ）を公開・配布する公式サイト |
| **LiteLLM** | AIサービスと企業システムを繋ぐオープンソースの橋渡しソフト |
| **クレデンシャル** | パスワード・APIキーなど、システムにアクセスするための認証情報 |
| **APIキー** | 外部サービス（ChatGPTなど）を利用するための合言葉のような文字列 |
| **SSHキー** | サーバーに安全に接続するための電子的な鍵のペア |
| **Kubernetes（クーバネティス）** | 多数のサーバーを自動管理するシステム |
| **CI/CD** | プログラムを自動でビルド・テスト・公開する仕組み（自動製造ライン） |
| **サプライチェーン攻撃** | ソフトウェアの「部品」や「流通経路」を狙う攻撃 |
| **推移的依存関係** | 自分が使うソフトが、さらに別のソフトに依存している関係 |
| **ローテーション** | パスワードやキーを定期的に変更すること |
| **CVE** | 脆弱性に付けられる国際的な識別番号 |
| **CISA** | アメリカのサイバーセキュリティ・インフラセキュリティ庁 |
| **TeamPCP / UNC6780** | 今回の攻撃を行った攻撃グループの名称 |
| **Trivy（トリビー）** | コードの脆弱性を検出するセキュリティスキャンツール |
| **環境変数** | OSやアプリの動作設定を保存する変数。APIキーなど機密情報が含まれることが多い |

---

> 📌 **まとめ**: 開発者が日常的に使うAIツール「LiteLLM」の偽バージョンが40分間だけ公開され、その間にインストールした2,500以上の組織で認証情報が盗まれた可能性があります。盗まれたカギは変更しない限り永遠に有効なので、心当たりのある組織は**今すぐ認証情報を変更**することが最優先です。
