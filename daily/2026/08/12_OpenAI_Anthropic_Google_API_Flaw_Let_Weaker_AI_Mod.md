# OpenAI・Anthropic・Google APIの欠陥で、弱いAIモデルが強いAIモデルの「思考内容」を解読できてしまった

**元記事**: [OpenAI, Anthropic, Google API Flaw Let Weaker AI Models Decode Stronger Models' Reasoning](https://inl03.netline.com/ltr6/?_m=3n.009a.4054.sp0ao46r89.33zq)
**解説日**: 2025年7月

---

## 背景知識

このニュースを理解するために、いくつかの基本的な概念を押さえておきましょう。

### 🤖 AIの「推論モデル」って何？
最近のAI（ChatGPTやClaudeなど）には、**「答えを出す前にじっくり考える」機能**があります。これを「推論（Reasoning）」と呼びます。

たとえば難しい数学の問題を解くとき、AIは頭の中で「まずこう考えて、次にこうして…」と思考のプロセスを経てから最終的な答えを出します。この「頭の中の考え」の部分が今回の問題の核心です。

### 🔌 APIって何？
**API（Application Programming Interface）** とは、ソフトウェア同士が情報をやり取りするための「窓口」のことです。

> 💡 **例え話**: レストランで「メニューから料理を注文して、できた料理を受け取る」仕組みに似ています。APIを使えば、開発者は「ChatGPTに質問を送って、答えを受け取る」プログラムを作れます。

### 🔐 暗号化って何？
データを第三者に読めないように変換することです。

> 💡 **例え話**: 手紙の内容を「あいうえお→かきくけこ」のように文字をずらして書くようなイメージです。元のルールを知らないと読めません。

### 🧩 「推論ブロック（Reasoning Block）」って？
AIが考えた「思考のプロセス」をデータとしてまとめたものです。OpenAI・Anthropic・Googleはこの思考データを**暗号化した状態**でやり取りしています。ユーザーには直接見せない「隠し思考」として扱われています。

---

## 何が起きたのか

セキュリティ研究者たちが、OpenAI・Anthropic・Googleが提供するAI APIに**設計上の欠陥**を発見しました。

### 🔍 発見された問題の概要

| 項目 | 内容 |
|------|------|
| 影響企業 | OpenAI・Anthropic・Google |
| 問題の種類 | 推論ブロック（AIの思考データ）の不正な再利用 |
| 発見方法 | 学術研究論文「Stealing Reasoning Traces from Proprietary LLM APIs」 |
| 現状 | 2026年8月時点で主要な攻撃手法は修正済み |

### 何が漏れたか？
研究者たちは**6,708件の公開されたAIエージェントのログ**（AIが行動した記録）を分析し、そこから以下を発見しました：

- 🔑 **APIキー（認証のための鍵）**: 62件
- 🔒 **パスワード**: 33件
- 🎫 **アクセストークン（認証情報）**: 24件
- 🗝️ **プライベートキー（秘密鍵）**: 7件

合計で**315,320個の「思考ブロック」を解読**することに成功し、704件の個人情報に相当するデータを取り出しました。

## 技術的な詳細

少し難しいですが、できるだけわかりやすく説明します！

### 🏗️ 正常な仕組み（本来の設計）

```
ユーザー → APIリクエスト → AIモデル
                              ↓
                          [隠れた思考プロセス]（暗号化済み）
                              ↓
                          見える答え（普通のテキスト）
```

AIは「見える答え」だけをユーザーに返し、「思考プロセス」は暗号化されたまま保存されます。この暗号化データを次の会話でも再利用できるようになっています（会話の文脈を保つため）。

### 🚨 攻撃の仕組み

研究者が発見した問題は「**暗号化された思考ブロックが、別のセッションや別のユーザーのリクエストでも受け付けられてしまう**」というものです。

> 💡 **例え話で説明すると…**
> 
> あるホテルでは、ルームカードキーを「暗号化して記録」しています。ところが、あるお客さんが使ったカードキーのデータを別のお客さんが持ち込んでも、ホテルの端末が「まあいいか」と通してしまった…というイメージです。

### 🤝 「弱いモデルで強いモデルの思考を読む」方法

さらに驚くべきことに、研究者たちは**安価な（弱い）AIモデルに暗号化された思考ブロックを渡すことで、高性能AIの思考内容を「翻訳」させる**ことができました。

| 攻撃に使ったモデル（弱い側） | 読み取り対象（強い側） |
|---|---|
| Claude Haiku 4.5 | Claude（高性能版）の思考 |
| GPT-5.6 Luna | GPT（高性能版）の思考 |
| Gemini Robotics ER-1.6 | Gemini（高性能版）の思考 |

> 💡 **例え話**: 上級生が作った「暗号化されたノート」を下級生に渡したら、なぜか解読できてしまった…みたいな状況です。

### 📋 発見された4つの攻撃パターン

1. **モデル蒸留のための推論盗用**
   　→ 高性能AIの「考え方」を盗んで、安いAIを賢くする（知的財産の窃取）

2. **他ユーザーの公開ログからの個人情報抽出**
   　→ 誰かが公開したAIのログから、隠れた思考内のパスワードなどを抜き取る

3. **安全フィルターに隠れた有害コンテンツの回収**
   　→ AIが「表向きは安全な答え」を出しつつ、思考の中に隠した有害な内容を取り出す

4. **プロンプトインジェクションの隠蔽**
   　→ 悪意ある命令を「思考ブロック」の中に隠して、後から別のAIタスクに悪影響を与える

## なぜ重要なのか

### 💥 影響を受ける人・範囲

```
影響を受けやすいのは…

✅ AIエージェントのログを公開したことがある開発者
✅ APIキーやパスワードをAIに渡したことがある人
✅ 企業の機密情報をAIに処理させたことがある組織
```

> ⚠️ **重要**: 今回の問題は「すべてのAIユーザーが危険」というわけではありません。特に**ログを公開した開発者**が主なリスクを負います。

### 🌍 社会的な意味

この発見は、AI技術が広まるにつれて増える**新しいタイプのセキュリティリスク**を示しています。

- 「暗号化されているから安全」とは限らない
- AIの「見えない思考」の中にも機密情報が含まれうる
- 公開したログが予想外の形で悪用される可能性がある

### 🔬 「悪用された証拠はない」
重要な点として、今回の研究は**悪意ある攻撃者が実際に悪用した証拠はない**と述べています。あくまで研究者が「こういう攻撃ができますよ」と示したものです（いわゆる「責任ある情報開示」という形で各社に報告しています）。

---

## 対策・今後の展望

### 🛡️ 開発者向けの対策（記事が推奨する内容）

1. **推論ブロック（reasoning blocks）を共有ログから削除する**
   　→ AIのログを公開・共有するときは、思考データを取り除いてから

2. **生のAPIログをそのままリポジトリ（GitHubなど）にアップしない**
   　→ 見える文章を消しただけでは不十分！隠れた思考ブロックにも秘密が含まれる可能性あり

3. **APIキーやパスワードをAIに直接渡さない**
   　→ 可能な限り、機密情報はAIの会話の外で管理する

### 🏢 各社の対応

研究者からの報告を受けて、**OpenAI・Anthropic・Google・Microsoft・Hugging Faceが対策を実施**し、論文によれば**2026年8月時点で主要な攻撃手法は再現不可能**になっています。

> ✅ 「現在は修正済み」ではありますが、**設計思想の問題**が浮き彫りになったため、今後も類似の問題が出てくる可能性があります。

AI技術が企業や個人の業務に深く入り込む中で、「AIそのものへの攻撃」が新たな脅威として注目されつつある流れの中に今回の発見は位置づけられます。

## 用語解説

| 用語 | 意味 |
|------|------|
| **API（Application Programming Interface）** | ソフトウェア同士が情報をやり取りするための窓口・仕組み |
| **推論（Reasoning）** | AIが答えを出す前に行う「思考プロセス」。Chain-of-Thoughtとも呼ばれる |
| **推論ブロック（Reasoning Block）** | AIの思考プロセスをまとめたデータの塊。暗号化されて保存・やり取りされる |
| **暗号化（Encryption）** | データを第三者が読めない形式に変換すること |
| **モデル蒸留（Model Distillation）** | 高性能AIの「知識や思考パターン」を安価なAIに学習させて性能を上げる手法 |
| **プロンプトインジェクション** | AIへの入力（プロンプト）に悪意ある命令を混ぜ込む攻撃手法 |
| **APIキー** | APIを使う際の認証に使う「鍵」となる文字列。漏れると不正利用される |
| **アクセストークン** | サービスへのアクセス権を証明するデータ。パスワードの代わりに使われることも |
| **エージェントログ** | AIエージェント（自律的に行動するAI）が行った操作の記録 |
| **セッション** | ユーザーがシステムを使い始めてから終わるまでの一連の通信 |
| **責任ある情報開示（Responsible Disclosure）** | 脆弱性を発見した際に、公開前にまず企業に報告するセキュリティ倫理の慣行 |
| **LLM（Large Language Model）** | GPTやClaudeのような大規模言語モデル。大量のテキストデータで学習したAI |

---

> 📝 **まとめ**: 今回の発見は「暗号化＝完全に安全」ではないことを改めて示しました。特にAIを業務に使っている開発者は、「AIに何を教えたか」「どんなログを公開しているか」を見直すきっかけにしてください！
