# 「シールドブレイク」ゼロデイ攻撃：Windowsのウイルス対策ソフトを守るはずのパッチが突破された！

**元記事**: [ShieldBreak Zero-Day PoC Claims Microsoft Defender Patch Bypass With SYSTEM Access](https://inl03.netline.com/ltr6/?_m=3n.009a.4054.sp0ao46r89.340e)
**解説日**: 2026年8月13日

---

## 背景知識

まず、この記事を理解するために必要な言葉と仕組みを説明します。

### 🛡️ Microsoft Defenderって何？
**Microsoft Defender（マイクロソフト・ディフェンダー）** は、Windowsパソコンに最初から入っているウイルス対策ソフトです。パソコンを守るための「門番」のような存在です。

### 🔑 「SYSTEM権限」って何？
Windowsには「誰が何をできるか」を決めるランク制度があります。

| ランク | 説明 |
|--------|------|
| 一般ユーザー | 自分のファイルを読み書きできる |
| 管理者（Administrator） | パソコン全体の設定を変えられる |
| **SYSTEM** | **パソコン上で最も強力な権限。OSの核心部分にもアクセス可能** |

SYSTEM権限を悪用されると、パソコンを完全に乗っ取られたも同然です。

### 🔓 ゼロデイ脆弱性って何？
**ゼロデイ（Zero-Day）** とは「修正パッチが存在しない、発見されたばかりのセキュリティの穴」のことです。メーカーが対応するまでの間、攻撃者にやりたい放題にされてしまう危険な状態です。

### 🧪 PoC（概念実証コード）って何？
**PoC（Proof of Concept）** とは「この脆弱性は本当に悪用できますよ」と証明するためのサンプルプログラムです。セキュリティ研究者が警告のために公開することがありますが、悪用されるリスクもあります。

## 技術的な詳細

### RoguePlanetの仕組み（元の脆弱性）

元の脆弱性「RoguePlanet」は **「レースコンディション（Race Condition）」** という種類の攻撃です。

**レースコンディションをわかりやすく例えると…**

> 🏃 AさんとBさんが同じロッカーを同時に使おうとしている状況を想像してください。
> 
> - Aさん（正規の処理）：「ロッカーを確認してから、鍵をかける」
> - Bさん（攻撃者）：「Aさんが確認した直後、鍵をかける前の一瞬に侵入する！」
>
> コンピュータでも「確認した後・実行する前」の超短い瞬間を狙って割り込む攻撃があります。これがレースコンディションです。

Defenderの中の **`mpengine.dll`（エムピーエンジン）** というファイルが管理する部分にこの隙間があり、うまく悪用するとSYSTEM権限のシェル（コマンド操作画面）を起動できてしまいます。

### ShieldBreakの厄介なところ

| 項目 | 内容 |
|------|------|
| 対象OS | Windows 11 25H2、Windows Server 2025 |
| 成功率 | **100%**（研究者発表） |
| Windows 10 | 現時点では未対応だが、**脆弱性自体は存在する** |
| パッチ状態 | Microsoftのパッチを当てていても**突破可能** |

## なぜ重要なのか

### 🔴 深刻な理由①：守る側のソフトが攻撃の踏み台になる
Defenderはパソコンを「守るため」に高い権限で動いています。その守り手自身に穴があるということは、**最も信頼されているソフトが逆に最大の弱点になる**ということです。まるで「警備員さん自身が鍵を渡してしまう」状態です。

### 🔴 深刻な理由②：パッチを当てても安心できない
普通「パッチを当てれば安全」というのが常識です。しかし今回は **パッチを当てた状態でも攻撃が成功する** ことが示されました。「修正済みだから大丈夫」という安心感が崩れてしまいます。

### 🔴 深刻な理由③：他にも攻撃が増えている
今回のパッチ情報によると、Microsoftは今月だけで **421件ものセキュリティの穴** を修正しました。そのうち **236件はWindowsそのもの** の問題です。さらに以下の深刻な脆弱性も確認されています：

- **CVE-2026-68820**：すでに実際に攻撃で悪用されている！WinSockドライバの穴でSYSTEM権限を取得できる
- **CVE-2026-62832**：「LegacyHive」とも呼ばれ、他のユーザーのデータに勝手にアクセスできる

アメリカの政府機関（CISA）は「CVE-2026-68820は連邦機関は2026年8月25日までに必ず修正すること」と命令を出しています。

## 対策・今後の展望

### ✅ 今すぐできること

1. **Windows Updateを必ず実行する**
   - 今月のパッチで421件の問題が修正されています
   - ShieldBreakへの完全対応パッチはまだですが、他の多くの問題は修正されます

2. **CVE-2026-68820のパッチは特に優先して適用する**
   - すでに実際の攻撃に使われているため、非常に危険です

3. **怪しいファイルを開かない・実行しない**
   - 多くの攻撃は「ファイルを開かせる」ことで始まります

4. **アカウントは管理者権限で常用しない**
   - 普段使いは一般ユーザー権限で使うことで、被害を最小化できます

### 🔮 今後の展望

Microsoftはまだ「ShieldBreak」への公式回答を出していません（記事執筆時点）。新しいパッチが来るまでの間は「完全に安全な状態にできない」というのが現実です。研究者とMicrosoftの間でどんなやり取りが行われるか、続報に注目が必要です。

## 用語解説

| 用語 | 説明 |
|------|------|
| **ゼロデイ（Zero-Day）** | まだ修正パッチが存在しない新発見の脆弱性 |
| **PoC（Proof of Concept）** | 「この脆弱性は本当に使える」と証明するサンプルコード |
| **Microsoft Defender** | Windowsに最初から入っているウイルス対策ソフト |
| **SYSTEM権限** | Windowsで最も強力なアクセス権限。OS自体の操作も可能 |
| **CVE（シーブイイー）** | 脆弱性に付けられる世界共通の識別番号 |
| **CVSS スコア** | 脆弱性の深刻さを0〜10で表した点数。7.8は「高（High）」 |
| **レースコンディション** | 処理のタイミングの隙を突いて不正操作をする攻撃手法 |
| **mpengine.dll** | Defenderのスキャン処理を担う核心的なファイル |
| **パッチバイパス** | 修正プログラムを「回避」して攻撃を成功させること |
| **CISA** | アメリカのサイバーセキュリティ専門政府機関 |
| **KEVカタログ** | CISAが管理する「実際に攻撃で使われている脆弱性リスト」 |
| **シェル（Shell）** | コンピュータにコマンドで命令を出すための画面・インターフェース |
| **レジストリハイブ** | Windowsの設定情報をまとめたデータベースのかたまり |
