## 背景知識

### 🏫 まずここから！「企業のセキュリティ防御」って何？

企業のコンピューターシステムは、毎日ハッカーから狙われています。それを防ぐために、企業は様々な「防御の仕組み」を導入しています。

代表的なものを学校に例えると…

| セキュリティ用語 | 学校で例えると |
|---|---|
| **ファイアウォール** | 校門の守衛さん（不審者を入れない） |
| **EDR（端末監視ツール）** | 教室内の監視カメラ（異常な動きを検知） |
| **SIEM（ログ管理システム）** | 生活指導日誌（誰がいつ何をしたか記録） |
| **SOC（監視チーム）** | 防犯担当の先生たち（24時間監視） |

### 🎯「攻撃シミュレーション」って何をするの？

本物の攻撃が来る**前に**、自分たちで「練習の攻撃」を仕掛けて、防御の弱点を見つける活動です。

これには主に2種類あります：

#### ① ペネトレーションテスト（通称：ペンテスト）
> セキュリティの専門家が、本物のハッカーのように攻撃を試みるテスト。
> 「泥棒役の専門家を雇って、自宅の防犯の穴を見つけてもらう」イメージ。

#### ② BAS（ブリーチ・アンド・アタック・シミュレーション）
> **Breach and Attack Simulation** の略。
> ソフトウェアが自動で何千回も攻撃をシミュレーションして、どの防御が機能していないか継続的にチェックする仕組み。

今回の記事は、このBASや類似のシミュレーションを**3億3800万回**も実施したデータを分析したレポートです。

## 何が起きたのか

### 📊 3億3800万回のテストが明らかにしたこと

セキュリティ企業が世界中の企業を対象に、膨大な数の攻撃シミュレーションを実施しました。

そのスケール感を想像してみてください：
- 日本の人口が約1億2000万人
- その**約2.8倍**の回数、攻撃テストを実施
- 対象は「大企業（エンタープライズ）」のシステム

このレポートが注目される理由は、**「企業がお金をかけて導入したセキュリティツールが、実際にはきちんと機能していないケースが多い」** という衝撃的な事実を示しているからです。

### 🔍 よく発見される「防御の失敗パターン」

このタイプのレポートで典型的に明らかになる問題点は以下の通りです：

```
【よくある企業の誤解】
「高いセキュリティ製品を買ったから安全！」
         ↓
【現実】
設定が甘い・更新されていない・連携できていない
= 攻撃を防げていない
```

具体的には：
1. **メール経由のマルウェア**（悪意あるプログラム）を検知できない
2. **ランサムウェア**の動きを止められない
3. **横移動攻撃**（社内ネットワークを侵入者が自由に動き回る）を検知できない
4. **正規ツールの悪用**（PowerShellなど）を見逃す

## 技術的な詳細

### 🦠 攻撃者が使う典型的な手口

攻撃者がよく使う「侵入から被害発生までの流れ」を見てみましょう：

```
【攻撃の流れ（キルチェーン）】

① フィッシングメール送信
   └→ 社員がだまされてリンクをクリック

② マルウェア（悪意あるソフト）の侵入
   └→ セキュリティツールが見逃す？ ← ここが問題！

③ 権限の拡大（特権昇格）
   └→ 一般社員のPCから管理者権限を奪う
   └→ これも検知できていない？ ← 問題！

④ 横移動（ラテラルムーブメント）
   └→ 社内の他のPCやサーバーに広がる
   └→ 止められていない？ ← 問題！

⑤ データ窃取 or ランサムウェア発動
   └→ ここで初めて気づく企業が多い…
```

### 🔑 特によく見落とされる攻撃テクニック

#### LOLBaS（Living off the Land Binaries）
「土地の資源で生き延びる」という意味。

> **わかりやすく言うと：**
> ハッカーが怪しいツールを持ち込まず、**もともとWindowsに入っている正規のツール**（PowerShell、WMI、certutilなど）を悪用して攻撃すること。
> 
> 例：学校に外から凶器を持ち込まず、図工室にある道具を悪用するイメージ

セキュリティツールは「怪しいファイル」を探すのが得意ですが、「正規ツールの変な使い方」は見逃しやすいのです。

#### ランサムウェア（Ransomware）
> **身代金要求型ウイルス**のこと。
> 企業のファイルをすべて暗号化（鍵をかけて読めなく）して、「お金を払えば元に戻す」と脅す攻撃。
> 
> 病院や学校、自治体も狙われており、日本でも被害が続出している。

## なぜ重要なのか

### 💰 企業が直面している現実

#### 「防御ツールへの過信」問題

```
【よくある企業の実態】
セキュリティ予算：数千万〜数億円
導入ツール数：平均45〜70種類以上

でも実際の防御成功率：？？
```

このレポートが重要なのは、**「買ったから安心」ではなく「ちゃんと機能しているか確認しなければならない」** という現実を数字で示しているからです。

#### 日本企業への影響

日本でも近年、大企業のセキュリティ侵害が相次いでいます：
- 大手自動車メーカーのサプライチェーン攻撃
- 病院へのランサムウェア被害
- 官公庁・自治体へのサイバー攻撃

これらの多くが「防御ツールはあったのに機能しなかった」ケースです。

### 📈 2026年に向けた脅威の増大

- **AI（人工知能）を使った攻撃**の自動化・高度化
- **クラウドサービス**を狙った攻撃の増加
- **サプライチェーン攻撃**（取引先の弱点から侵入）の増加

## 対策・今後の展望

### ✅ 企業が取るべき対策

#### 1. 継続的な検証（Continuous Validation）
> セキュリティを「買って終わり」にせず、定期的にシミュレーションテストを実施する

```
悪い例：セキュリティツール導入 → 放置 → 3年後に侵害発覚
良い例：導入 → 月1回テスト → 弱点発見 → 修正 → また検証
```

#### 2. MITRE ATT&CKフレームワークの活用
> **MITRE ATT&CK**（マイター・アタック）とは、世界中で観測されたハッカーの攻撃手法をまとめたデータベース。
> 「ハッカーはこういう手口を使う」という辞書のようなもので、これを参考にテストを行う。

#### 3. ゼロトラスト（Zero Trust）の考え方
> 「社内ネットワークだからといって信頼しない」という考え方。
> 
> 例：会社の中にいても、「本当にこの人が本人か？」を毎回確認する仕組み

#### 4. 人への投資（セキュリティ教育）
技術的なツールだけでなく、**社員教育**が重要：
- フィッシングメールの見分け方
- 不審なリンクをクリックしない習慣
- インシデント（問題発生時）の報告手順

### 🔮 今後の展望

| 傾向 | 内容 |
|---|---|
| AI vs AI | 攻撃も防御もAIが活用される時代へ |
| 自動化テスト | BASツールの普及でより頻繁な検証が可能に |
| 規制強化 | 各国政府がサイバーセキュリティ基準を義務化 |
| 人材不足 | セキュリティ専門家の需要が急増 |

## 用語解説

| 用語 | 読み方 | 意味 |
|---|---|---|
| **エンタープライズ** | Enterprise | 大企業・企業向けシステムのこと |
| **BAS** | ブリーチ・アンド・アタック・シミュレーション | 自動で攻撃をシミュレーションして防御を検証するツール |
| **ペネトレーションテスト** | Penetration Test（ペンテスト） | 専門家が擬似攻撃を行い脆弱性を発見するテスト |
| **ランサムウェア** | Ransomware | ファイルを暗号化して身代金を要求するウイルス |
| **EDR** | Endpoint Detection and Response | PCなどの端末を監視して不正な動きを検知するツール |
| **SIEM** | Security Information and Event Management | ログ（記録）を集めて分析するセキュリティ管理システム |
| **SOC** | Security Operation Center | セキュリティを24時間監視する専門チーム・組織 |
| **ゼロトラスト** | Zero Trust | 「誰も最初から信頼しない」というセキュリティの考え方 |
| **LOLBaS** | Living off the Land Binaries | OSに元々入っているツールを悪用した攻撃手法 |
| **MITRE ATT&CK** | マイター・アタック | 攻撃者の戦術・手法をまとめた世界標準の知識データベース |
| **横移動（ラテラルムーブメント）** | Lateral Movement | 侵入後に社内の他システムへ移動・拡大する攻撃行動 |
| **キルチェーン** | Kill Chain | 攻撃が完成するまでの一連のステップ（段階） |
