# 3,000件以上の偽求人URL発見！「ブラウザの中の偽ブラウザ」でパスワードを盗む新手口

**元記事**: [CTM360 Uncovers Over 3,000 Recruitment Phishing URLs Using Browser-in-the-Browser (BitB) Credential Traps](https://inl03.netline.com/ltr6/?_m=3n.009a.4056.sp0ao46r89.342o)
**解説日**: 2025年7月

---

## 背景知識

まず、この記事を読むために必要な基礎知識を説明します。

### 🎣 フィッシング詐欺とは？
「フィッシング（Phishing）」とは、本物そっくりの偽サイトや偽メールを使って、パスワードやクレジットカード番号などの大切な情報を騙し取る攻撃です。釣り（fishing）から来た言葉で、ユーザーを「餌」で釣るイメージです。

### 📅 Calendly（カレンドリー）とは？
Calendlyは、「空き時間を選んでミーティングを予約できる」人気のスケジュール管理サービスです。就職活動の面接日程調整などでよく使われています。今回の攻撃では、このサービスを**丸ごと偽物に見せかけた**ページが使われました。

### 🔐 多要素認証（MFA）とは？
パスワードだけでなく、スマホに届くワンタイムパスワード（数字6桁など）も合わせて入力することで本人確認をする仕組みです。「2段階認証」とも呼ばれ、セキュリティを高めるために広く使われています。

### 🪟 Browser-in-the-Browser（BitB）とは？
今回の記事の核心となる技術です。

> **「ブラウザの中に、偽物のブラウザウィンドウを表示する」**攻撃技術

Googleで「Googleでログイン」ボタンを押すと、小さなポップアップウィンドウが出てきてログインを求めることがありますよね。あれを**完全に偽物で再現**する技術です。本物のURLバーや鍵マーク（🔒）まで画像で偽装するので、見た目だけでは本物との区別がほぼつきません。

## 何が起きたのか

セキュリティ企業「CTM360」が、**「RecruitTrap（リクルートトラップ）」**と名付けた大規模な詐欺キャンペーンを発見しました。

### 📊 規模の大きさ
- **2ヶ月間で3,000件以上**の偽URLを確認
- **50以上の実在する企業・組織**を名乗って偽装
- **14の業種**をターゲットに
- 被害者の多くは**マーケティング職の社員**

### 🎭 攻撃の流れ（概要）

```
① 偽の採用担当者からメール・招待が届く
         ↓
② 偽のCalendly（面接日程調整）ページに誘導
         ↓
③ 「Googleでログイン」ボタンを押すと…
         ↓
④ 偽のGoogleログイン画面（BitB）が表示される
         ↓
⑤ パスワードを入力 → 攻撃者にリアルタイムで届く
         ↓
⑥ 2段階認証のコードまで奪われる
         ↓
⑦ アカウントを完全に乗っ取られる
```

## 技術的な詳細

### 🎭 STEP 1：偽の求人メールが届く

攻撃は、**実在する企業の採用担当者を名乗ったメールや会議招待**から始まります。このとき、

- 実在する採用担当者の名前・顔写真・役職
- LinkedInなどSNSから集めた被害者の職歴情報

などを使って、**「本当に自分宛に送られてきた求人連絡だ」**と信じさせます。

### 🪤 STEP 2：偽サイトへの誘導

被害者は2種類の偽サイトのどちらかに誘導されます。

| 種類 | 内容 |
|------|------|
| **偽Calendlyページ** | 本物そっくりの日程調整ページ（全体の96%） |
| **企業独自の採用ポータル** | 特定企業のブランドを丸ごと偽装したサイト |

### 🪟 STEP 3：BitBで偽ログイン画面を表示

「Googleアカウントで続ける」ボタンを押すと、**ブラウザ上に小さなウィンドウが現れます**。このウィンドウは、

- ✅ 本物そっくりのURLバー（`accounts.google.com`など）
- ✅ 本物そっくりの鍵マーク（🔒）
- ✅ 本物そっくりのGoogleのデザイン

…をすべて**画像とHTMLで偽造**しています。実際にはウィンドウが開いているのではなく、**Webページ上に「ウィンドウっぽいもの」が描かれているだけ**です。スマホでは全画面で表示される場合もあります。

### ⚙️ STEP 4：リアルタイムで認証情報を中継する

ここが最も怖い部分です。

```
被害者がパスワードを入力
        ↓
偽サイトが即座に本物のGoogleにログイン試行
        ↓
Googleが2段階認証コードを被害者のスマホに送信
        ↓
偽サイトが「コードを入力してください」と要求
        ↓
被害者がコードを入力 → 攻撃者に届く
        ↓
攻撃者が本物のGoogleアカウントにログイン完了 🔓
```

これを「**リアルタイムMFA中継攻撃**」と呼びます。2段階認証をしていても破られてしまうため、特に危険です。

ログインが成功すると、被害者は**本物のCalendlyページに転送**されるため、「問題なかった」と思い込んでしまいます。

### 🤖 STEP 5：自動化・巧みな絞り込み

この偽サイトはただの静的なページではなく、**「状態機械（ステートマシン）」**として動作します。

- **個人のメールアドレスは弾く**（企業アカウントだけを狙う）
- CAPTCHAでボット・研究者を排除
- Socket.IOという技術でリアルタイム通信
- セッション管理でユーザーを段階的に誘導

つまり、価値の高い**企業アカウントだけを効率よく狙う**賢い仕組みになっています。

### 🏗️ 大規模な共有インフラ

- 約96%が**Calendlyテーマ**
- **Cloudflare**を使って攻撃者の本当のサーバーを隠蔽
- AWSのクラウドサーバーを悪用（50.9%）
- `.cfd`というドメインが最多（40%）
- テンプレートを使い回しているため、企業名を変えるだけで**すぐに別の企業になりすませる**

## なぜ重要なのか

### 💼 なぜマーケティング職が狙われるのか？

マーケティング担当者のアカウントには以下のものが紐づいていることが多いからです。

| アクセスできるもの | 攻撃者にとっての価値 |
|---|---|
| 広告プラットフォーム（Meta広告など） | 不正広告の出稿・課金 |
| 企業のSNSアカウント | なりすまし・偽情報拡散 |
| 顧客データ | 個人情報の売却・悪用 |
| メールシステム | さらなるフィッシング |

### 😨 2段階認証が突破される

「2段階認証を設定しているから安全」と思っている人も多いですが、この攻撃はそれを**リアルタイムで中継して突破**します。これは多くのユーザーにとって「最後の砦」が崩れることを意味します。

### 🌍 規模が大きすぎる

2ヶ月で3,000件以上のURLというのは、1日あたり約50件の偽サイトが作られていたことになります。転職活動中の人なら誰でも被害に遭う可能性があります。

## 対策・今後の展望

### ✅ 個人でできる対策

#### 1. URLを必ず確認する
BitBの偽ウィンドウは、ウィンドウをブラウザの外にドラッグしようとすると**できない**ことで見分けられます。本物のポップアップウィンドウは動かせますが、偽物はWebページの一部なので動きません。

#### 2. パスキー（Passkey）を使う
パスワードの代わりに生体認証（指紋・顔）でログインする「パスキー」は、フィッシングサイトでは原理的に使えないため、より安全です。

#### 3. 求人メールは公式サイトで確認
「面接の招待が来た！」と思ったら、メール内のリンクを直接クリックせず、**企業の公式サイトから採用ページを確認**しましょう。

#### 4. セキュリティキー（物理キー）を使う
YubiKeyなどの物理的なセキュリティキーは、正規サイト以外では動作しないため、リアルタイム中継攻撃に対して有効です。

### 🛡️ 企業でできる対策

- 従業員へのフィッシング教育（特に転職時期）
- メールフィルタリングの強化
- FIDO2準拠の認証方式の採用
- ゼロトラストセキュリティの導入

### 🔮 今後の展望

テンプレートを使い回すこの手口は、**AIを使ってさらに精巧なパーソナライズ**が可能になると予想されます。「あなたのLinkedInを見て連絡しました」という求人メールには、今後もより一層の注意が必要です。

## 過去記事との関連

今回は特定の過去記事との直接の関連はありませんが、フィッシング攻撃の進化という観点では重要なトレンドがあります。

従来のフィッシングは「本物に似たURLのサイトに誘導する」ものでした。しかし今回のBitB攻撃は「**正規のサイト上に偽のウィンドウを出す**」という一歩進んだ手口です。さらにリアルタイムMFA中継を組み合わせることで、**「2段階認証さえしていれば安心」という常識が崩れつつある**ことを示しています。

## 用語解説

| 用語 | 説明 |
|------|------|
| **フィッシング（Phishing）** | 偽サイト・偽メールでパスワードなどを騙し取る攻撃 |
| **BitB（Browser-in-the-Browser）** | ブラウザの中に偽のブラウザウィンドウを表示する攻撃技術 |
| **MFA（多要素認証）** | パスワード+ワンタイムコードなど複数の方法で本人確認をする仕組み |
| **OTP（ワンタイムパスワード）** | 一度しか使えない使い捨てのパスワード（6桁の数字など） |
| **Calendly** | オンラインでミーティングの日程調整ができるサービス |
| **Socket.IO** | サーバーとブラウザがリアルタイムで通信するための技術 |
| **Svelte/SvelteKit** | Webサイトを作るためのプログラミングフレームワーク |
| **状態機械（ステートマシン）** | 状況に応じて次の動作が変わるシステムの設計パターン |
| **Cloudflare** | Webサービスを高速・安全にする会社。今回は攻撃者がサーバーの場所を隠すために悪用 |
| **AWS EC2** | Amazonのクラウドサーバー。今回は攻撃インフラとして悪用 |
| **CTM360** | バーレーン発のサイバーセキュリティ企業。今回の調査を実施 |
| **パスキー（Passkey）** | パスワード不要で指紋や顔認証でログインできる新しい認証方式 |
| **FIDO2** | フィッシングに強い認証の国際規格 |
