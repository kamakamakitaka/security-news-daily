# Chrome DevToolsを悪用したブラウザ乗っ取り技術が発見される

**元記事**: [Chrome DevTools Technique Enables Authenticated Session Hijacking in Live Windows Browsers](https://inl03.netline.com/ltr6/?_m=3n.009a.4056.sp0ao46r89.342i)
**解説日**: 2025年7月11日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な概念を押さえておきましょう。

### 🍪 Cookieとは？
Webサイトにログインすると、ブラウザは「Cookie（クッキー）」という小さなデータを保存します。これは「あなたはログイン済みですよ」という証明書のようなものです。このCookieを盗まれると、**パスワードを知らなくても、あなたとして勝手にログイン**できてしまいます。

### 🔧 Chrome DevToolsとは？
Chrome DevTools（開発者ツール）は、Webサイトを作る人が使うChromeの内蔵ツールです。普段は「F12キー」を押すと出てくるあれです。開発者がWebページの中身を確認したり、動作をテストするためのものですが、**非常に強力な機能**を持っています。

### 📡 Chrome DevTools Protocol（CDP）とは？
CDPは、外部のプログラムがChrome DevToolsの機能を操作できる「通信規格」です。例えるなら、**テレビのリモコンのような仕組み**です。リモコン（外部プログラム）でテレビ（Chrome）を操作できるイメージです。

### 🔐 App-Bound Encryption（アプリ限定暗号化）とは？
Googleが2024年ごろに導入したセキュリティ機能です。Chromeが保存するCookieを「このアプリ（Chrome）だけが解読できる形」で暗号化する仕組みです。これにより、従来の「Cookieを保存ファイルから直接盗む」手口が使えなくなりました。

---

## 何が起きたのか

セキュリティ研究会社の**SpecterOps**が、WindowsのChromeやMicrosoft Edgeブラウザに対して使える**新しい攻撃手法**を詳しく公開しました。

この手法「**CDP-Enable-BOF**」を使うと、攻撃者はすでに起動中のブラウザの「内側から」デバッグ機能を有効化し、以下のことができてしまいます。

- ✅ ログイン中のサービスのCookieを盗む
- ✅ 保存されたパスワードを読み取る
- ✅ 閲覧履歴・ブックマーク・拡張機能の情報を取得
- ✅ ブラウザを遠隔操作して画面を覗き見る
- ✅ ブラウザを使って通信を傍受する（プロキシ化）

> 💡 ポイント：これは「Chromeに新しい脆弱性が見つかった」というニュースでは**ありません**。すでにパソコンに侵入できた攻撃者が、その後の活動でChromeを悪用する「第二段階の攻撃手法」です。

---

## 技術的な詳細

### 攻撃の前提条件

この攻撃が成立するには、**まず攻撃者がすでにそのWindowsパソコンでプログラムを実行できる状態になっている**必要があります。つまり「家に泥棒が入ることに成功した後」の話です。

### なぜApp-Bound Encryptionをすり抜けられるのか？

Googleが導入したApp-Bound Encryptionは「Cookieファイルを外から読み取る」攻撃に対して有効です。しかし今回の手法は、**ブラウザのプロセス（動いているプログラム）の内部に入り込んで**、Chromeが自分自身のCookieを読み取る機能を悪用します。

例えるなら…
> 🏦 銀行の金庫を外から無理やり開けようとする（従来の攻撃）→ セキュリティが防ぐ
> 🏦 銀行員に変装して金庫を内側から開けさせる（今回の攻撃）→ セキュリティをすり抜ける

### 攻撃の手順（簡略版）

```
1. 動いているChromeやEdgeのプロセスを見つける
2. Chromeの内部コード(chrome.dll)を探す
3. ブラウザの内部メモリに小さなプログラムを注入する
4. ブラウザ内部からデバッグサーバー機能を起動する
5. デバッグ機能経由でCookieやパスワードを吸い出す
```

### Chromeの対策をなぜ回避できるのか？

Googleは2025年5月のChrome 136で、外部から`--remote-debugging-port`というオプションを付けてChromeを起動し直す手法を封じました。

しかし今回の手法は、**すでに起動しているChromeの中に入り込んで**デバッグ機能を有効化するため、この対策が効きません。

## なぜ重要なのか

### 📊 影響の大きさ

| 項目 | 内容 |
|------|------|
| 対象OS | Windows（x64のみ） |
| 対象ブラウザ | Chrome・Microsoft Edge |
| 前提条件 | 攻撃者がすでにPCで操作できる状態 |
| 盗めるもの | Cookie・パスワード・閲覧履歴など |

### 🌐 現実的な脅威

「すでにパソコンが侵害されているなら、そもそも終わりでは？」と思うかもしれません。でも現実の攻撃では、**段階的に権限を奪っていく**のが一般的です。

- マルウェア感染 → 限定的な操作ができる
- 今回の手法 → ブラウザ内のすべての認証情報を奪える
- → 会社の内部システムにも侵入可能に

特に**企業のセキュリティ担当者**にとっては、侵入された後の被害を最小化するための「防衛策」を考える上で非常に重要です。

### 🔒 App-Bound Encryptionへの皮肉

Googleが新しいセキュリティ機能を導入したことで、攻撃者がより高度な手法へ移行したことをGoogleも認めており、「ABEの導入後、リモートデバッグを使ったCookie盗難が増加している」と2025年3月の投稿で述べています。**防御策が高度になれば、攻撃も高度になる**という「いたちごっこ」の典型例です。

## 対策・今後の展望

### 👤 一般ユーザーができること

1. **不審なファイルを開かない・実行しない**
   - この攻撃は「すでにパソコンが侵害されている」が前提なので、まずはマルウェア感染を防ぐことが最重要です

2. **OSとブラウザを常に最新の状態に保つ**
   - Chromeは自動更新を有効にしておきましょう

3. **パスワードマネージャーの使い方を見直す**
   - ブラウザ保存のパスワードは今回の手法で盗まれる可能性があります。専用のパスワードマネージャーアプリの利用も検討しましょう

4. **多要素認証（MFA）を設定する**
   - Cookieが盗まれてもMFAがあれば被害を防げるサービスもあります

### 🏢 企業・IT担当者ができること

1. **Sysmonの監視を設定する**
   - 記事によると、`chrome.exe`や`msedge.exe`へのプロセス注入を検知するには**Sysmon Event ID 8・10**を監視することが推奨されています

2. **EDR（端末保護ツール）の導入**
   - プロセス注入を検知・遮断するセキュリティツールを導入する

3. **最小権限の原則を徹底する**
   - 攻撃者が侵入しても動ける範囲を最小限にする

### 🔮 今後の展望

Googleはすでにこの種の攻撃を認識しており、Chrome 136での対策も行っています。ただし、今回のような「内部から起動する」手法への対策はまだ不十分です。今後、Chromeの新バージョンで追加の対策が講じられる可能性があります。

## 過去記事との関連

今回の記事は独立したニュースですが、一連の流れとして理解できます。

- **2018年頃〜**：CDPを使ったCookie盗難が議論され始める
- **2024年**：GoogleがApp-Bound Encryptionを導入（外部ファイルからのCookie盗難を防ぐ）
- **2025年3月**：Google自身が「ABE導入後にリモートデバッグ悪用が増加」と報告
- **2025年5月**：Chrome 136でリモートデバッグの外部起動を制限
- **2025年12月**：DeathFlamingoが動作中のEdgeへのCDP注入を文書化
- **今回**：SpecterOpsがより洗練された「CDP-Enable-BOF」技術を公開

このように、**Googleのセキュリティ強化 → 攻撃者の手法進化 → さらなる防御策**というサイクルが続いています。

## 用語解説

| 用語 | 解説 |
|------|------|
| **Cookie（クッキー）** | Webサイトへのログイン状態などを保存するブラウザのデータ。盗まれるとなりすましに使われる |
| **Chrome DevTools** | Chrome内蔵の開発者向けツール。Webページのデバッグ・分析に使う |
| **CDP（Chrome DevTools Protocol）** | 外部プログラムからDevToolsを操作するための通信規格 |
| **App-Bound Encryption** | ChromeのCookieをChrome自身しか読めない形で暗号化するGoogle製のセキュリティ機能 |
| **BOF（Beacon Object File）** | 侵入テストツール「Cobalt Strike」で使われる小さなプログラム。ターゲットのメモリ上で動く |
| **プロセス注入（Process Injection）** | 動いているプログラムの内部に別のコードを送り込む技術。攻撃にも防御テストにも使われる |
| **セッションハイジャック** | ログイン中のセッション（通信の流れ）を乗っ取る攻撃。Cookieを盗むことで実現できる |
| **Sysmon** | Windowsの詳細なログを記録するMicrosoft製の無料ツール。不審な動作の検知に使われる |
| **CFG / CET** | プログラムの実行経路を保護するWindowsのセキュリティ機能。プロセス注入を困難にする |
| **SpecterOps** | サイバーセキュリティの研究・ペネトレーションテストを専門とする米国のセキュリティ企業 |
| **ポスト・エクスプロイテーション** | 攻撃者がシステムへの侵入に成功した「後」に行う活動のこと |

---

> 💬 **まとめ**：今回の発見は「Chromeに穴が開いた」というより「すでに侵入された後の被害がより深刻になる」という話です。一番大切な防衛策は、**そもそもマルウェアに感染しないこと**。不審なメールのリンクをクリックしない、OSとソフトを最新に保つ、という基本が最大の防御です！
