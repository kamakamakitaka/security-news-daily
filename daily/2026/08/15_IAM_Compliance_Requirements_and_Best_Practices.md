# IAM（アイデンティティとアクセス管理）のコンプライアンス要件とベストプラクティス

**元記事**: [IAM Compliance Requirements and Best Practices](https://inl03.netline.com/ltr6/?_m=3n.009a.4057.sp0ao46r89.344k)
**解説日**: 2025年1月

---

## 背景知識

### 🏫 まず「IAM」って何？

**IAM（Identity and Access Management）** とは、日本語で「**アイデンティティとアクセスの管理**」といいます。

学校で例えると…

> 🏫 **学校の入退室管理システム**のようなものです。
> - 「この生徒は図書室に入れる」
> - 「先生だけが職員室に入れる」
> - 「部外者は校舎に入れない」
>
> これをデジタルの世界（会社のシステムやデータ）で行うのがIAMです。

### 📋 「コンプライアンス」って何？

**コンプライアンス（Compliance）** とは、「**ルールや法律をきちんと守っていること、またはそれを証明できること**」です。

> 🍔 ファストフード店で例えると…
> 「食品衛生法を守って調理しています」と**言うだけ**ではなく、
> **保健所の検査に合格する証拠（記録・書類）が必要**、というイメージです。

### 🔑 なぜIAMのコンプライアンスが必要なの？

会社は「誰がどのデータにアクセスできるか」を**ルールで決めている**だけでなく、
「**本当にそのルール通りに動いているか証明**」しないと、法律違反になることがあります。

## 何が起きたのか

### 📰 この記事の概要

これは特定の事件の記事ではなく、**IAMコンプライアンスの解説・ガイド記事**です。

記事が伝えているのは、こんな問題です：

> ❌ **多くの企業が「ルールを文書で決めている」だけで、**
> **「実際にそのルール通りに動いているか確認できていない」**

つまり…

```
【紙の上のルール】 ≠ 【実際のシステムの動き】
        ↑
   この「ズレ」が問題！
```

### 🕳️ 「アイデンティティのダークマター」問題

記事では **「Identity Dark Matter（アイデンティティのダークマター）」** という言葉が登場します。

> 🌌 宇宙の「ダークマター（暗黒物質）」= 存在するけど見えないもの
>
> ITの世界でも、**管理システムから見えていないアカウントやアクセス権**が存在します。
> - 昔から使われている古いシステムのアカウント
> - アプリ内だけで管理されているパスワード
> - 機械が自動で使う「サービスアカウント」

これらが**監視の外**にあるため、セキュリティの穴になっています。

## 技術的な詳細

### 🔍 「ポリシーの意図」と「実際の動作」のズレ

記事では3つの典型的な問題を挙げています：

| 問題の種類 | 具体的な例え |
|-----------|------------|
| **想定されたカバレッジ** | 「中央のルールを各アプリが守っているはず」と思っているが、実は守っていない |
| **観測されない実行** | ログイン記録はあるが、ログイン後に**何をしたか**が記録されていない |
| **設定と現実のズレ** | 「最小限の権限だけ与える」とルールに書いてあるが、実際には**管理者権限が残っている** |

> 🏠 家で例えると…
> 「玄関の鍵はかけるルール」を決めても、
> **裏口の鍵が開けっぱなし**なら意味がない。
> しかも「裏口の存在を誰も知らない」という状態がダークマターです。

### 📜 関係する主な法律・規制

記事では、IAMコンプライアンスに関係する主な規制を紹介しています：

#### 1. **SOX法（サーベンス・オクスリー法）**
- 🏦 **対象**: 主に上場企業（特に米国）
- 📌 **内容**: 財務データへのアクセス管理・変更管理の証拠を残すことが義務
- 🇯🇵 **日本でいうと**: 日本版SOX法（J-SOX）として日本でも同様の規制があります

#### 2. **PCI DSS（クレジットカード業界のセキュリティ基準）**
- 💳 **対象**: クレジットカード情報を扱う企業すべて
- 📌 **内容**: カード情報へのアクセス制限・認証の強化・ログの記録
- 🛒 **身近な例**: ネットショッピングサイトが守るべき基準

#### 3. **HIPAA（医療情報保護法）**
- 🏥 **対象**: 医療機関・健康保険など（主に米国）
- 📌 **内容**: 電子カルテなど医療情報へのアクセス制御と記録

#### 4. **ISO/IEC 27001**
- 🌍 **対象**: 世界中の企業（認証を取得したい場合）
- 📌 **内容**: 情報セキュリティ管理の国際規格
- 🇯🇵 **日本でも**: 多くの日本企業が取得している認証

#### 5. **GDPR（EU一般データ保護規則）**
- 🇪🇺 **対象**: EU（ヨーロッパ）の個人情報を扱う企業
- 📌 **内容**: 個人データへのアクセスを適切に制限・管理する義務
- 🇯🇵 **日本への影響**: 日本企業でもEUのユーザーがいれば対象になる

## なぜ重要なのか

### 💥 コンプライアンス違反の影響

```
コンプライアンス違反が発覚すると…
        ↓
😰 監査（検査）で指摘される
        ↓
💰 罰金・制裁（GDPRなら最大2,000万ユーロ！）
        ↓
📰 ニュースになって企業の信頼失墜
        ↓
👥 取引先・顧客が離れる
```

### 🎯 「紙の上だけのコンプライアンス」が危ない理由

> 📖 テストで例えると…
> 「この問題の答えは〇〇です」と**ノートに書いてあるだけ**では、
> テスト本番で正解できるか分かりません。
> **実際に解けることを証明**しないといけないのと同じです。

セキュリティ監査（検査）でも、「ルールが書いてあります」だけでは不十分で、
「**実際にそのルール通り動いていた証拠（ログ・記録）**」が求められます。

## 対策・今後の展望

### ✅ 記事が推奨するベストプラクティス

#### 1. 「定期的なチェック」から「継続的な監視」へ

```
❌ 古いやり方: 年に1回や四半期に1回だけアクセス権を確認
✅ 新しいやり方: 常時自動監視して、異常があれば即座に検出
```

> 🔥 火災報知器で例えると…
> ❌「月に1回、火事が起きていないか確認する」
> ✅「煙感知器が常時監視して、煙が出たら即アラート」

#### 2. 「設計の確認」より「実際の動作の確認」

| 確認すること | 具体例 |
|------------|--------|
| 本当に最小限の権限か | 「閲覧のみ」のはずが「削除もできる」状態になっていないか |
| 不要なアカウントの削除 | 退職した社員のアカウントが残っていないか |
| 特権アカウントの監視 | 管理者権限を使った操作をすべて記録しているか |

#### 3. コントロールの「一元化」

> 🗂️ 学校の例で言うと…
> 各教室ごとにバラバラな入室ルールを作るより、
> **学校全体で統一した入退室システム**を作る方が管理しやすい。
> 1回作ったコントロールを、複数の規制・法律に使い回せるようにする。

#### 4. 証拠の自動収集

監査（検査）のたびに手動で記録を集めるのではなく、
**システムが自動的にログ・証拠を収集・保存**できる仕組みを整える。

### 🔮 今後のトレンド

- **AI・自動化**によるアクセス権の異常検知
- **ゼロトラスト**（「誰も信用しない、常に確認する」という考え方）の普及
- 人間だけでなく**機械・AIのアカウント管理**（非人間アイデンティティ）への注目

## 過去記事との関連

今回の記事は特定の事件ではなくガイド記事ですが、
**IAM（アクセス管理）の不備が原因のセキュリティ事件**は非常に多く発生しています。

例えば：
- 退職した社員のアカウントが削除されずに不正利用された事件
- 過剰な権限を持つアカウントが攻撃者に乗っ取られた事件

これらはすべて、今回解説した**「ポリシーと実態のズレ」**が根本原因です。
アクセス管理の問題は、多くのサイバーセキュリティインシデントの入口になっています。

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **IAM** | アイエーエム | Identity and Access Management。誰がどのシステムにアクセスできるかを管理する仕組み |
| **コンプライアンス** | - | 法律・規則・社内ルールをきちんと守り、それを証明できる状態 |
| **監査（Audit）** | かんさ | ルールが守られているか第三者が検査すること |
| **ポリシー** | - | アクセスに関するルールや方針をまとめた文書 |
| **特権アカウント** | とっけんアカウント | 管理者など、強い権限を持つアカウント（悪用されると被害が大きい） |
| **最小権限の原則** | さいしょうけんげんのげんそく | 業務に必要な最小限のアクセス権だけを与えるというセキュリティの基本原則 |
| **ダークマター（Identity Dark Matter）** | - | 管理システムから見えていない、管理されていないアカウントや権限 |
| **SOX法** | ソックスほう | 企業の財務情報の正確性を守るための米国の法律 |
| **PCI DSS** | ピーシーアイ ディーエスエス | クレジットカード情報を守るための国際的なセキュリティ基準 |
| **HIPAA** | ヒパア | 米国の医療情報を守るための法律 |
| **GDPR** | ジーディーピーアール | EUの個人データ保護に関する法律。違反すると巨額の罰金 |
| **ISO/IEC 27001** | アイエスオー 27001 | 情報セキュリティ管理の国際規格 |
| **ゼロトラスト** | - | 「社内にいるから安全」とは考えず、常にアクセスを検証するセキュリティの考え方 |
| **ログ** | - | システムへのアクセスや操作の記録。証拠として使われる |
| **エンタイトルメント** | - | アカウントに与えられたアクセス権・権限の一覧 |

---

> 💡 **まとめ**
>
> IAMコンプライアンスとは、「**誰がどのデータにアクセスできるか**」というルールを
> 決めるだけでなく、**実際にそのルール通り動いていることを証明できる状態**にすることです。
>
> 「ルールを作った＝安全」ではなく、
> 「**ルール通りに動いていることを常に確認・記録できている**」ことが重要です。
> これはIT企業だけの話ではなく、個人情報を扱うすべての企業・組織に関わる問題です。
