# GitLabの深刻な脆弱性：ログインなしで他人のプロジェクトを消せる欠陥が発見された

**元記事**: [Critical GitLab GraphQL Flaw Could Let Unauthenticated Attackers Delete Public Projects](https://inl03.netline.com/ltr6/?_m=3n.009a.4059.sp0ao46r89.347o)
**解説日**: 2026年8月19日

---

## 背景知識

まず、このニュースを理解するための基本的な言葉を説明します。

### GitLabとは？
**GitLab（ギットラボ）**は、プログラマーたちが「ソースコード（プログラムの設計図）」を保管・管理・共有するためのプラットフォームです。GitHubと同じようなサービスだと思ってください。世界中の企業や開発者が自社のプロジェクトをGitLabで管理しています。

GitLabには大きく2つの使い方があります：
- **GitLab.com**：GitLab社が運営するクラウドサービス（会員登録してすぐ使える）
- **セルフマネージド（自己管理型）**：企業が自分たちのサーバーにGitLabをインストールして運用する形態

### GraphQLとは？
**GraphQL（グラフキューエル）**は、ウェブサービスにデータをやり取りするための「通信の仕組み（API）」の一種です。  
イメージとしては、レストランの注文票のようなもの。お客さん（ブラウザやアプリ）がどのデータが欲しいかを書いて厨房（サーバー）に渡すと、ピッタリな情報だけが返ってくる仕組みです。

### CVSSスコアとは？
**CVSS（シーブイエスエス）スコア**は、脆弱性（セキュリティの弱点）の深刻さを0〜10点で表す点数です。
- 0〜3.9：低（Low）
- 4.0〜6.9：中（Medium）
- 7.0〜8.9：高（High）
- 9.0〜10.0：緊急（Critical）

今回の脆弱性は**9.4点**という非常に高い点数で、「最大級の危険度」に分類されます。

---

## 何が起きたのか

2026年8月17日、GitLabは緊急のセキュリティアップデートを公開しました。

発見されたのは**CVE-2026-19478**と呼ばれる脆弱性（セキュリティの欠陥）です。この欠陥があると、なんと**ログインしていない第三者（部外者）でも、GitLab上の公開プロジェクトを勝手に書き換えたり削除したりできてしまう**可能性があります。

さらに、**ユーザーのデータ（個人情報なども含む）**まで改ざん・削除される危険性があります。

通常、GitLabのアップデートは「毎月第2・第4水曜日」という決まったスケジュールで行われます。しかし今回は**スケジュール外の緊急リリース**として公開されました。それほど深刻な問題だったということです。

---

## 技術的な詳細

### どんな攻撃が可能なのか？

この脆弱性を使うと、攻撃者は以下のことができてしまいます：

| 攻撃の特徴 | 内容 |
|---|---|
| 認証不要 | ログインやアカウントなしで攻撃可能 |
| リモート攻撃 | インターネット越しに遠隔から実行可能 |
| 被害者の操作不要 | 対象ユーザーが何かをクリックするなどの「きっかけ」すら不要 |

これは非常に危険な組み合わせです。  
「鍵もかけずに無防備な状態で、侵入者が遠くからドアを開けられる」ようなイメージです。

### なぜGraphQLが関係するの？

GitLabはデータのやり取りにGraphQLという仕組みを使っています。この仕組みの中に「**ディレクティブ（指示文）**」という特定の命令を送れる機能があります。

今回の欠陥は、**特定の条件下でその命令を悪用すると、認証（本人確認）をすり抜けてプロジェクトの変更や削除ができてしまう**というものです。

GitLab社は「どのディレクティブが問題か」「どんな条件が必要か」については、悪用防止のため詳細を公開していません。

### 同時に修正された別の脆弱性

今回のアップデートでは、もう1つ**CVE-2026-19650**という脆弱性も修正されました。

こちらは「**CSRF（クロスサイトリクエストフォージェリ）**」という種類の攻撃で、深刻度は7.1点（高）です。  
CSRFとは、悪意のあるウェブサイトを被害者に閲覧させることで、本人が意図しない操作を実行させる攻撃手法です（こちらは被害者の操作が必要）。

## なぜ重要なのか

### 影響を受けるバージョン

以下のバージョンを使っているセルフマネージド環境が対象です：

- GitLab **18.2〜18.10**（⚠️ 修正パッチが提供されていない！）
- GitLab **18.11 〜 18.11.10**（修正済みは18.11.11以降）
- GitLab **19.0 〜 19.0.7**（修正済みは19.0.8以降）
- GitLab **19.1 〜 19.1.5**（修正済みは19.1.6以降）
- GitLab **19.2 〜 19.2.3**（修正済みは19.2.4以降）

特に注意が必要なのは、**18.2〜18.10のバージョンは修正パッチが提供されていない**点です。このバージョンを使っている組織は、より新しいバージョンへのアップグレードが必要です。

### 誰が影響を受けるの？

✅ **影響なし（対応不要）**
- GitLab.comのユーザー（GitLab社がすでに修正済み）
- GitLab Dedicatedのユーザー（同上）

⚠️ **要対応**
- 自分たちのサーバーにGitLabをインストールして使っている企業・組織

GitLabは世界中の企業のソフトウェア開発の中枢を担っているため、**ここが攻撃されると、企業の重要なプログラムやデータが失われる**可能性があります。

## 対策・今後の展望

### 今すぐやるべきこと

セルフマネージドでGitLabを運用している場合は、以下のいずれかにアップデートしてください：

```
✅ GitLab 19.2.4（最新）
✅ GitLab 19.1.6
✅ GitLab 19.0.8
✅ GitLab 18.11.11
```

> ⚠️ **18.10以前を使っている場合は、これらのバージョンへの移行が必要です。**

### 朗報もあります
- 現時点（2026年8月18日時点）で、この脆弱性を実際に悪用した攻撃は確認されていません
- GitHub上などに攻撃コードも流出していません

ただし、セキュリティの世界では「今は大丈夫でも、すぐに攻撃が始まる」ことが多いため、**早急なアップデートが強く推奨されます**。

### 今後の情報公開
GitLabは脆弱性の技術的な詳細を「修正後90日」で公開する方針を持っています。今回は2026年11月中旬頃に詳細が公開される予定です。

## 用語解説

| 用語 | 意味 |
|---|---|
| **GitLab** | プログラムのソースコードを管理・共有するプラットフォーム |
| **GraphQL** | ウェブサービスでデータをやり取りするための通信規格 |
| **ディレクティブ** | GraphQLにおける特別な指示・命令のこと |
| **CVE** | 脆弱性を識別するための番号（Common Vulnerabilities and Exposures） |
| **CVSSスコア** | 脆弱性の深刻度を0〜10で示す点数 |
| **認証（Authentication）** | 「あなたは誰ですか？」を確認する仕組み（ログインなど） |
| **セルフマネージド** | 自分たちのサーバーにソフトをインストールして運用する形態 |
| **CSRF** | 悪意あるサイトを通じてユーザーに意図しない操作をさせる攻撃 |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアのセキュリティ上の弱点・欠陥 |
| **パッチ** | ソフトウェアの問題を修正するための小さなアップデート |
| **リモートコード実行** | インターネット越しに別のコンピュータで命令を実行させる攻撃 |

> GitLabという開発者向けサービスに、ログイン不要・遠隔から・誰かの操作も不要で、プロジェクトを消したりデータを改ざんできる深刻な欠陥が見つかりました。GitLab.comユーザーは心配不要ですが、自社サーバーで運用している企業は今すぐアップデートが必要です！
