# ハッカーが14,500台以上のダホア製カメラに不正侵入！パスワード攻撃・認証回避・P2P中継の三刀流

**元記事**: [Hackers Compromised 14,500+ Dahua Devices Using Credential Attacks, Auth Bypasses, and P2P](https://inl03.netline.com/ltr6/?_m=3n.009a.4060.sp0ao46r89.3482)
**解説日**: 2025年8月19日

---

## 背景知識

まず、このニュースを理解するために必要な基礎知識を説明します。

### 🎥 Dahua（ダホア）って何？

**Dahua Technology（浙江大華技術）** は中国の大手セキュリティカメラメーカーです。世界中の家庭・企業・施設に監視カメラや録画装置（NVR）を販売しており、日本でも多く使われています。「防犯のためのカメラ」が逆に攻撃対象になっている、という皮肉な状況です。

### 🏠 監視カメラのネットワーク構成（超シンプル解説）

```
インターネット
    ↓
ルーター（NAT）← 家や会社の玄関口
    ↓
監視カメラ（Dahua製）← 内側に隠れている
```

カメラは通常、ルーターの「内側」に隠れていて、外からは直接アクセスできません。でも今回の攻撃では、その「壁」を突き破る技術が使われました。

### 🔑 「認証」とは？

認証とは「あなたは正しいユーザーですか？」を確認する仕組みです。ドアに鍵をかけるようなもので、正しいID・パスワードを持っていないと中に入れません。今回の攻撃では、**この鍵を破る・あるいは鍵なしで入り込む** 手口が使われました。

### 📡 P2P（ピアツーピア）って何？

P2Pとは「仲介サーバーを通じて2台の機器を直接つなぐ」技術です。LINEのビデオ通話やリモートデスクトップと同じ仕組みで、カメラメーカーが「どこからでもスマホでカメラを見られる！」という便利機能として提供しています。

> 💡 **例え話**: P2Pは「引っ越しセンターの荷物追跡」みたいなもの。荷物（カメラ映像）の場所（シリアル番号）さえわかれば、荷物がどこにあっても取り出せてしまう仕組みです。

## 何が起きたのか

### 📋 事件の概要

2026年6月17日〜7月22日の約5週間で、セキュリティ研究者グループ **Hunt.io** が **「OperationCameraSwarm（作戦名：カメラ大群）」** と名付けた攻撃活動を発見・調査しました。

| 項目 | 内容 |
|------|------|
| 被害台数 | **14,530台以上** のDahua製機器 |
| 攻撃期間 | 2026年6月17日〜7月22日（約5週間） |
| 主な被害地域 | **ウクライナ・ロシア** に集中 |
| 発見のきっかけ | 攻撃者がうっかり **407MBのファイルを公開状態** にしていた |

### 🕵️ どうやって発見されたの？

攻撃者が使ったサーバーの **作業フォルダがうっかりインターネットに公開されていた** ため、研究者たちがそれを発見。234個のフォルダ・2,616個のファイルの中に、攻撃ツール・ログ・コマンド履歴・作戦記録がすべて含まれていました。

> 💡 **例え話**: 泥棒が犯行現場の写真や計画書をうっかりSNSに投稿してしまったようなものです。

## 技術的な詳細

攻撃は **3つの方法** を組み合わせて行われました。

### 🔐 攻撃手法①：クレデンシャル攻撃（12,324台）

**「クレデンシャル攻撃」** とは、パスワードを総当たりで試したり、他のサービスで流出したID・パスワードを使い回して不正ログインする攻撃です。

```
攻撃者 → 「admin/admin」「admin/123456」「admin/password」...
         ひたすら試す → 正しいパスワードに当たるまで繰り返す
```

> 💡 初期設定のパスワードを変えていないカメラが多く、簡単に侵入されてしまいました。

---

### 🚪 攻撃手法②：認証バイパス（1,923台）

これが最も危険な手口です。**CVE-2021-33044** と **CVE-2021-33045** という2つの脆弱性（セキュリティの欠陥）が悪用されました。

| 脆弱性番号 | 危険度スコア | 内容 |
|-----------|------------|------|
| CVE-2021-33044 | **9.8 / 10点** | 特殊なデータを送ると鍵なしで入れる |
| CVE-2021-33045 | **9.8 / 10点** | 「自分自身」のふりをして鍵をごまかす |

**CVE-2021-33044の仕組み（超簡単に）**
```
通常: ユーザー → ID・パスワード送信 → 確認 → ログイン許可
攻撃: 攻撃者 → 特殊な「NetKeyboard」形式のデータ送信 → 確認スキップ → ログイン許可！
```

**CVE-2021-33045の仕組み（超簡単に）**
```
通常: 外部ユーザー → ログイン要求 → 審査あり
攻撃: 攻撃者 → 「127.0.0.1（カメラ自身のアドレス）」のふりをしてログイン要求
     → 「あ、自分自身からのアクセスか、信頼していいか」 → 審査スキップ！
```

> ⚠️ この脆弱性は **2021年に発見・修正済み** のはずなのに、ファームウェア（カメラの内部プログラム）を更新していないユーザーがまだ大量にいたため、今も悪用されています。

また、侵入後に **「永続アカウント」** が作られていました。これはファクトリーリセット（工場出荷状態に戻す）をしても消えないバックドア（隠し扉）で、一度侵入されると追い出すのが非常に困難になります。

---

### 📡 攻撃手法③：P2Pリレー（283台）

これが最も巧妙な手口です。

```
通常の状態:
インターネット → ルーター（壁） → カメラ（守られている）

P2P攻撃:
インターネット → Dahuaのクラウドサーバー（Easy4IP）→ カメラに届く！
              ↑ シリアル番号さえわかればルーターの壁を迂回できる
```

**手順（わかりやすく）:**
1. 攻撃者がカメラの **シリアル番号** を入手（製品の箱や設定画面から）
2. そのシリアル番号をDahuaの **P2Pクラウドサービス** に送る
3. サービスが「そのカメラに接続してあげる」とトンネル（通り道）を作る
4. **認証（パスワード確認）の前に通り道が開通してしまう！**
5. ルーターの壁の向こうにあるカメラに、外からアクセス可能に

調査によると、回収された攻撃コードでは **生きているシリアル番号の89.4%** で認証なしにチャンネルが開いたと記録されていたとのこと（ただしこの数字は攻撃者の記録によるもので、第三者による独立検証はまだ行われていません）。

## なぜ重要なのか

### ⚡ 数字で見る深刻さ

- **14,530台超** の監視カメラが不正アクセスを受けた
- 脆弱性の危険度スコアが **9.8/10点**（満点に近い最高レベル）
- 脆弱性は **2021年から存在**（4〜5年放置されていた！）
- 米国のセキュリティ機関CISAの「既知の悪用済み脆弱性リスト」に **今も掲載中**

### 😱 カメラが乗っ取られると何が起きる？

監視カメラが攻撃者に支配されると…

1. **のぞき見・盗撮** → プライバシーの完全な侵害
2. **内部ネットワークへの侵入口** → カメラを踏み台に会社や家全体を攻撃
3. **DDoS攻撃の道具** → 大量のカメラをボットとして使い、他のサービスを攻撃
4. **ランサムウェア** → 映像を人質にして金銭を要求

### 🌏 被害地域について

被害はウクライナとロシアに集中していましたが、Dahua製品は世界中で使われているため、日本も無関係ではありません。

## 対策・今後の展望

### ✅ 今すぐできる対策

**Dahua製品を使っている方は:**

| 優先度 | 対策 |
|-------|------|
| 🔴 最優先 | **ファームウェアを最新版に更新する**（Dahua公式サイトから） |
| 🔴 最優先 | **デフォルトのパスワードを必ず変更する** |
| 🟠 高優先 | **P2P機能が不要なら無効化する** |
| 🟠 高優先 | **「永続アカウント」が作られていないか確認する** |
| 🟡 推奨 | カメラを外部ネットワークから切り離すか、VPN経由のみのアクセスにする |

### 📋 脆弱性への対応状況

- Dahuaは2021年時点で修正済みファームウェアを公開済み
- CISAは「対策を適用するか、対策できないなら使用をやめること」と勧告中
- 修正版ファームウェアはDahua公式ダウンロードサイトで確認可能

### 🔮 今後の展望

このような「古い脆弱性がずっと放置されたまま悪用される」ケースは後を絶ちません。IoT機器（カメラ・ルーター・スマート家電など）は、パソコンと違って「自動アップデート」の仕組みが弱く、ユーザーも更新を忘れがちです。メーカー・行政・ユーザーが連携して対応することが求められています。

## 過去記事との関連

今回の記事は独立した新規案件ですが、**IoT機器のセキュリティ問題** は繰り返し起きているテーマです。「Miraiボットネット」（2016年）では同様にIPカメラが大量に乗っ取られ、大規模なDDoS攻撃に使われました。今回の事件はその延長線上にあり、「監視カメラのセキュリティ管理」が依然として世界的な課題であることを改めて示しています。

## 用語解説

| 用語 | 意味 |
|------|------|
| **クレデンシャル攻撃** | IDとパスワードを大量に試してログインを突破する攻撃 |
| **認証バイパス** | 本来必要なパスワード確認を飛ばして侵入する手口 |
| **CVE（Common Vulnerabilities and Exposures）** | 世界共通の脆弱性管理番号。CVE-2021-〇〇〇〇は「2021年に登録された脆弱性」 |
| **CVSS スコア** | 脆弱性の危険度を0〜10点で表す国際基準。9.8は「最高レベルに危険」 |
| **P2P（ピアツーピア）** | 仲介サーバーを通じて2台の機器を直接つなぐ通信方式 |
| **NAT（Network Address Translation）** | ルーターが家庭内の機器を外部から隠す仕組み |
| **ファームウェア** | カメラなどのハードウェアに組み込まれたOSのようなプログラム |
| **バックドア（永続アカウント）** | 攻撃者が後から再侵入するために残す隠し扉 |
| **KEV（Known Exploited Vulnerabilities）** | CISAが管理する「実際に悪用が確認された脆弱性リスト」 |
| **Easy4IP** | Dahuaが提供するP2Pクラウドサービスの名称 |
| **シリアル番号** | 製品1台ごとに割り当てられた固有の識別番号 |
| **PoC（Proof of Concept）** | 脆弱性が実際に悪用可能だと証明するためのサンプルコード |
| **CISA** | 米国のサイバーセキュリティ専門機関（日本のIPA的な存在） |

---

> 🔒 **まとめ**: 「ちゃんと鍵（パスワード）をかける」「鍵の欠陥（脆弱性）が見つかったら早めに直す（アップデート）」「使わない機能（P2P）はオフにする」。この3つが守られるだけで、今回のような被害の大半は防げました。セキュリティの基本は地味ですが、それを続けることが最大の防御です。
