# CDNツナミ攻撃：HTTP/3の変換を悪用した最大350倍のDoS増幅攻撃

**元記事**: [CDN Tsunami Attack Abuses HTTP/3 Translation for Up to 350x DoS Amplification](https://inl03.netline.com/ltr6/?_m=3n.009a.4061.sp0ao46r89.349m)
**解説日**: 2025年7月11日

---

## 背景知識

まずこのニュースを理解するために、いくつかの基本的な仕組みを説明します。

### 🌐 Webサイトへのアクセスの仕組み

あなたがブラウザでWebサイトを開くとき、実は裏側ではこんな流れが起きています。

```
あなたのPC → CDN（中継サーバー）→ 本物のWebサーバー（オリジン）
```

**CDN（Content Delivery Network）** とは、世界中に置かれた「中継サーバーの集まり」です。  
Cloudflare（クラウドフレア）やAmazon CloudFrontなどが有名で、Webサイトを高速化・保護する役割を持っています。  
宅配便に例えると、「地域の集荷センター」のような存在です。荷物（データ）を本社（本物のサーバー）ではなく近くのセンターで受け取り、効率よく届けてくれます。

### 📡 HTTP/3 と HTTP/1.1 って何？

**HTTP（HyperText Transfer Protocol）** はブラウザとサーバーが「会話」するためのルール（通信規格）です。バージョンがあり、新しいほど速くて効率的です。

| バージョン | 特徴 |
|---|---|
| HTTP/1.1 | 古い規格。現在も広く使われている |
| HTTP/2 | 速度改善版 |
| **HTTP/3** | **最新版。特に速く、モバイルに強い** |

**ポイント**：CDNはブラウザとは最新の「HTTP/3」で話すけれど、裏の本物のサーバーとは古い「HTTP/1.1」で話している、という「ギャップ」があります。これが今回の攻撃の核心です。

### 💥 DoS攻撃とは？

**DoS攻撃（Denial of Service Attack＝サービス妨害攻撃）** とは、大量のリクエスト（アクセス要求）を送りつけて、サーバーをパンクさせてWebサイトを使えなくする攻撃です。  
お店に「冷やかし客」を大量に送り込んで、本当のお客さんが入れないようにする嫌がらせ、と思ってください。

### 📦 QPACK（圧縮技術）とは？

HTTP/3では**QPACK**という技術を使って、リクエストのヘッダー（手紙でいう「宛名や差出人情報」）を**ギュッと圧縮**して送ります。  
例えば「`User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)...`」という長い文字列を、「番号：5番」のような短いコードで送れます。

## 何が起きたのか

サイバーセキュリティの研究者たちが、**「CDNツナミ（CDN Tsunami）」** と名付けた新しい攻撃手法を発見・発表しました。

この攻撃の恐ろしいところは、**攻撃者が少ない通信量（弱い攻撃）を送るだけで、本物のサーバーには最大350倍もの負荷をかけられる**点です。

### 対象となったCDN企業（6社）

- **Alibaba（アリババ）**・**Baidu（バイドゥ）**・**Tencent（テンセント）**：中国系大手
- **Cloudflare（クラウドフレア）**：世界最大級のCDN
- **Amazon CloudFront**：AWSのCDNサービス
- **Fastly（ファストリー）**：動画配信でも使われるCDN

**6社すべてが攻撃の影響を受ける**ことが確認されました（影響の程度は異なります）。

---

## 技術的な詳細

### 🔑 なぜ増幅できるのか？（共通の原因）

攻撃の根本原因は「**CDNはブラウザとHTTP/3で話すが、裏のサーバーとはHTTP/1.1でしか話せない**」という構造的なギャップです。

```
攻撃者 ──[HTTP/3: 圧縮された小さいデータ]──→ CDN ──[HTTP/1.1: 展開された大きいデータ]──→ 本物のサーバー
        ←←←←←←←←←←←←←←← 増幅！ →→→→→→→→→→→→→→→
```

研究者たちは2種類の攻撃を発見しています。

---

### 攻撃① HBA（HTTP/3 帯域幅増幅攻撃）

**帯域幅（Bandwidth）** とは「データの道路の幅」のようなもの。広いほど多くのデータを流せます。

**仕組み（図解）：**

```
攻撃者が送るもの：
  「ヘッダー番号5番」（数バイトの小さなデータ）
        ↓
CDNが変換する：
  「User-Agent: Mozilla/5.0 (Windows NT ...)...」（数百バイトの大きなデータ）
        ↓
本物のサーバーに届く：
  何十倍・何百倍もの大きなデータ！
```

**具体的な数字：**
- 攻撃者が使う通信量：**500Kbps以下**（YouTubeの低画質動画程度）
- 本物のサーバーへの負荷：**100Mbps超え**（高画質ストリーミング並み）

Alibaba・Baidu・Tencent は「ダイナミックテーブル」という特殊な圧縮機能も使えるため、最大**350倍**もの増幅が可能でした。

| CDN | 最大増幅率 |
|---|---|
| Baidu | 約66倍 |
| Alibaba | 約65.8倍 |
| Tencent | 約54倍 |
| Amazon CloudFront | 約51倍 |
| Cloudflare | 約48倍 |
| Fastly | 約36倍 |

---

### 攻撃② HCA（HTTP/3 接続数増幅攻撃）

こちらは「**サーバーが同時に受け付けられる接続数（席数）を占領する**」攻撃です。

**お店の例えで説明：**

> レストランに「席に座るだけで注文しない冷やかし客」が大勢来て、本当のお客さんが座れなくなる状態をイメージしてください。

**HTTP/3の「多重化」という特性を悪用します：**

- HTTP/3では、1本の接続で**複数の「ストリーム（会話）」を同時進行**できます
- 各ストリームが来ると、CDNは裏のサーバーに**別々のHTTP/1.1接続**を張る
- 攻撃者がデータ送信をわざとゆっくりにすると、接続が長時間占領される

```
攻撃者の接続4本
  └─ 各96ストリーム
  └─ 計384本の接続をサーバーに強制
        ↓
サーバーの限界（例：256接続まで）を超えて
        ↓
一般ユーザーが接続できなくなる！
```

Cloudflareだけは「リクエストを全部受け取ってからサーバーに転送する」方式のため、この攻撃②には影響を受けませんでした。

## なぜ重要なのか

### 📌 影響の深刻さ

1. **少ない攻撃コストで大きなダメージ**：攻撃者は安いインターネット回線でも、大規模なDoS攻撃を起こせます
2. **世界中の有名CDNが対象**：CloudflareやAWS CloudFrontは世界中のWebサイトで使われているため、影響範囲が非常に広い
3. **Webサイト管理者は自分では対処できない**：対策はCDN側で行う必要があり、Webサイトの設定変更では防げません

### ⚠️ ただし、今のところ実害は報告なし

- **CVE番号（脆弱性の公式ID）はまだ割り当てられていません**
- **実際に悪用された事例も今のところ報告されていません**

BaiduとTencentはすでに対策を実施済みです。

---

## 対策・今後の展望

### CDN側の対策（研究者が提案）

- CDNがHTTP/3のリクエストを受け取ったとき、**本物のサーバーに転送する前にバッファリング（一時的にため込む）**する
- 1つのHTTP/3接続から発生するバックエンド接続数を制限する
- HTTP/3→HTTP/1.1変換時のヘッダー展開サイズに上限を設ける

### Webサイト管理者ができること

残念ながら、**Webサイト管理者側でできる対策はほぼありません**（記事でもそう述べられています）。  
ただし以下は検討できます：

- **HTTP/3を本当に必要でなければ無効化する**（ただし利便性は落ちる）
- **利用しているCDNの対策状況を確認**する
- **CDN側のセキュリティ設定を最新の推奨設定にする**

### 今後の動向

各CDN会社への報告はすでになされており、BaiduとTencentは修正済みです。残りの会社も対応中と見られます。CDN業界全体として「エンドツーエンドでHTTP/3をサポートする」方向に進めば、根本的な解決につながります。

## 過去記事との関連

今回の攻撃は、過去にも報告されてきた「**プロトコル変換の隙間を突く攻撃**」の系譜に位置します。  
特に2023年に話題になった**HTTP/2のRapid Reset攻撃**（HTTP/2の多重化機能を悪用した大規模DDoS）と構造的に似ており、「新しい高速プロトコルの普及に対して、セキュリティ対策が追いついていない」という共通の問題を浮き彫りにしています。技術が進歩するほど、新たな攻撃面（アタックサーフェス）も生まれることを示した事例と言えるでしょう。

## 用語解説

| 用語 | 説明 |
|---|---|
| **CDN** | 世界中に分散した中継サーバー群。Webサイトを高速化・保護する |
| **HTTP/3** | Webの通信規格の最新版。速度が速く圧縮効率が高い |
| **HTTP/1.1** | Webの古い通信規格。現在も広く使われている |
| **DoS攻撃** | サーバーに大量のリクエストを送り、使えなくする攻撃 |
| **オリジンサーバー** | CDNの裏にある、本物のWebサーバー |
| **QPACK** | HTTP/3で使われるヘッダー圧縮技術 |
| **増幅攻撃** | 小さな攻撃を大きな攻撃に「増幅」させる手法 |
| **多重化（マルチプレクシング）** | 1本の接続で複数の通信を同時に行う技術 |
| **ストリーム** | 多重化通信における、個々の「会話チャンネル」 |
| **バッファリング** | データを一時的にため込んでから処理すること |
| **CVE** | 脆弱性に付けられる公式の識別番号 |
| **帯域幅（Bandwidth）** | データ通信の「道路の幅」。広いほど多くのデータを流せる |
| **ダイナミックテーブル** | QUPACKで使う、よく使うヘッダーを登録しておく仕組み |

---

> 💡 **まとめ**：「CDNツナミ」は、最新通信技術HTTP/3と古い通信技術HTTP/1.1の「翻訳の隙間」を突いた賢い攻撃です。攻撃者は少ない通信量で最大350倍もの負荷をWebサーバーにかけられます。現時点では実害はなく、対策はCDN側が担うべき問題ですが、世界中の有名CDN全てが影響を受けるという点で、業界全体への重要な警告となっています。
