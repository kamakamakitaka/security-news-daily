# Cloudflare Workersへのスペクター攻撃：隣のプログラムから秘密の鍵が盗まれてしまう脆弱性

**元記事**: [Cloudflare Workers Spectre Attack Leaks JWT From Co-Located Worker at 12 Bits/Second](https://inl03.netline.com/ltr6/?_m=3n.009a.4061.sp0ao46r89.34am)
**解説日**: 2026年8月20日

---

## 背景知識

まず、このニュースを理解するために必要な用語と概念を押さえておきましょう。

### 🏢 Cloudflare Workersとは？
**Cloudflare（クラウドフレア）** は、世界中のウェブサイトを高速・安全に配信するサービスを提供している大手IT企業です。その中の **Workers（ワーカーズ）** というサービスは、世界中のCloudflareのサーバー上で、企業や開発者が書いたプログラム（コード）を動かすことができる仕組みです。

> 🏫 **例え話**：学校の調理室に例えるなら、Cloudflareのサーバーは「大きな調理室」で、WorkersはそこでA組・B組・C組がそれぞれ同時に料理をしているようなイメージです。部屋は同じでも、それぞれのグループは別々に作業しているはずですよね。

### 🔑 JWT（JSON Web Token）とは？
**JWT（ジェイダブリュティー）** は、ログイン情報や権限情報などを安全にやり取りするための「デジタルな身分証明書」のようなものです。ウェブサービスで「あなたはログイン済みですよ」と証明するために使われます。これが盗まれると、他人になりすましてサービスを利用される危険があります。

### 👻 Spectre（スペクター）攻撃とは？
**Spectre攻撃** は、2018年に発見されたCPU（コンピューターの頭脳）の設計上の弱点を悪用した攻撃です。

> 🏫 **例え話**：CPUは処理を速くするために「先読み」（次にやることを予測して前もって準備しておくこと）をします。これを「投機的実行」と言います。Spectre攻撃はこの「先読み」の仕組みを悪用して、本来見られてはいけない他のプログラムのメモリ（記憶領域）をのぞき見る攻撃です。まるで「隣の部屋のドアに耳を当てて会話を盗み聞きする」ようなイメージです。

### 🧱 V8 Isolate（アイソレート）とは？
**V8** はGoogleが開発したJavaScriptの実行エンジンで、**Isolate（分離環境）** はその中でプログラムをお互いに干渉しないように分けて動かす仕組みです。ただし、完全に別々のプロセス（処理単位）ではなく、同じOS上の同じプロセス内で「ソフトウェア的に」分離されています。

## 何が起きたのか

セキュリティ研究者たちが、Cloudflare Workersの本番環境（実際に動いている環境）に対して、**Spectre攻撃を使って別のWorkerが持つJWT（デジタル身分証）を盗み出すことに成功した**と発表しました。

### 📊 驚くべき速度の向上
- **2021年の先行攻撃**：1分間に2ビット（情報の最小単位）しか盗めなかった
- **今回の攻撃**：1秒間に最大12ビット、精度99.16%で盗み出せた
- これは**約360倍もの高速化**です！

> 🏫 **例え話**：以前は「壁に小さな穴を1分かけてやっと1つ開けられた」のが、今回は「1秒間に12個の穴を開けられるようになった」イメージです。

研究者たちは自分たちでコントロールする「攻撃者Worker」と「被害者Worker」を使い、JWTを被害者のメモリに意図的に置いた状態で実験を行いました。**実際の顧客データには一切アクセスしていない**ことも明記されています。

## 技術的な詳細

### 🔧 なぜ同じプロセス内に複数のWorkerがいるのか？
Cloudflare Workersは、起動の速さ（低レイテンシ）を実現するために、複数のテナント（利用者）のコードを**同じOSプロセス内で動かし**、V8 Isolateによってソフトウェア的に分離しています。完全に別プロセスにすると起動が遅くなるため、この設計を採用しています。

> これが今回の攻撃の根本的な原因です。「壁を薄くすることで速くなるが、隣の声が聞こえやすくなる」トレードオフです。

### 🕵️ 攻撃の手順（簡略版）

```
1. 攻撃者Workerと被害者Workerが同じサーバープロセス内に配置される
       ↓
2. 攻撃者がSpectre攻撃を利用して、隣のWorkerのメモリを少しずつ読み取る
       ↓
3. WebSocket（リアルタイム通信の仕組み）を使って「タイミング」を計る
       ↓
4. Durable Objects（長時間動き続けるオブジェクト）を使って
   5〜20時間以上、攻撃を継続する
       ↓
5. JWTを1秒12ビットのペースで盗み出す
```

### 🛡️ Cloudflareの防御機能「DyPrIs」の弱点
Cloudflareは **DyPrIs（ダイプリス：Dynamic Process Isolation）** という防御機能を持っていました。これは「怪しいスクリプトを別プロセスに隔離する」仕組みです。

しかし研究者は2つの弱点を発見しました：

| 弱点 | 説明 | 例え話 |
|------|------|--------|
| **Durable Objectsの問題** | 長時間動いている処理は、隔離が始まる前に攻撃を続けられる | 「退場命令が出ても、今の試合が終わるまでプレーできる」 |
| **WebSocket I/Oによる検知回避** | 大量の通信をすることで、DyPrIsの怪しさ検知センサーを誤魔化せる | 「警報機の音を大きな雑音でかき消す」 |

### 💻 実験環境
- OSはLinux
- AMD EPYC Zen 2 / Zen 3プロセッサ
- CPU使用率10〜25%の夜間に測定（最もよい条件で計測するため）
- CPU負荷が高いと速度は落ちるが、攻撃自体は可能

## なぜ重要なのか

### 🌍 影響範囲の大きさ
Cloudflare Workersは世界中の企業が利用している大規模なサービスです。もしこの攻撃が悪意ある第三者によって実際に行われていたとすれば、**他の利用者のJWT（ログイン認証情報）が盗まれ、なりすましログインなどの被害**が発生していた可能性があります。

### 🔬 研究として重要な点
- Spectre攻撃は「理論上は危険」とされてきましたが、実際のクラウド環境でここまで高速に機能することが**実証された**ことは大きな意味を持ちます
- 「ソフトウェアによる分離だけでは不十分な場合がある」という教訓を業界全体に示しています
- DyPrIsのような「検知型の防御」は、I/Oで誤魔化せるという**根本的な限界**があることを指摘しています

### ✅ 幸いなこと
- Cloudflareは**すでに対策済み**です
- 過去3年間、実際の悪用の痕跡は見つかっていません
- 研究者たちは責任ある開示（攻撃方法を公開する前にCloudflareに報告）を行いました

## 対策・今後の展望

### 🔒 Cloudflareが実施した対策（2025年9月発表）

| 対策名 | 内容 |
|--------|------|
| **DyPrIsの改善** | 既存の隔離メカニズムの検知能力を強化 |
| **V8 Sandbox** | 64ビットポインタへの一時的なアクセスを制限（メモリの読み取りをより困難に） |
| **MPK（Memory Protection Keys）ベースの分離** | ハードウェアレベルでWorkerのメモリ領域を保護する仕組みを導入 |

### 🔮 業界への示唆
研究者たちは「**検知は実行中にリアルタイムで行い、I/O活動で抑制できないシグナルを使うべき**」と提言しています。クラウドサービス全体のセキュリティ設計に影響を与える可能性のある重要な提言です。

## 過去記事との関連

以前、**CDN Tsunami Attack（CDNツナミ攻撃）** についてご紹介しました。あの記事では、CDN（コンテンツ配信ネットワーク）のHTTP/3の変換機能を悪用して最大350倍もの攻撃増幅を行うDoS攻撃を解説しました。

今回のCloudflare Workers Spectre攻撃も、同様に**クラウドサービスのインフラ（基盤）が持つ構造的な特性を巧みに悪用した攻撃**という点で共通しています。CDNやクラウド実行環境といった「便利さのための仕組み」が、攻撃者にとっての足がかりになり得るという、現代のクラウドセキュリティが直面する共通の課題を示しています。

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **Spectre攻撃** | スペクター | CPUの「先読み処理（投機的実行）」の脆弱性を悪用して、他のプログラムのメモリを盗み見る攻撃 |
| **JWT** | ジェイダブリュティー | JSON Web Token。ログイン状態や権限を証明するデジタルな身分証明書 |
| **Cloudflare Workers** | クラウドフレア ワーカーズ | 世界中のCloudflareサーバー上でコードを実行できるクラウドサービス |
| **V8 Isolate** | ブイエイト アイソレート | GoogleのJS実行エンジン「V8」が提供するプログラムの分離実行環境 |
| **DyPrIs** | ダイプリス | Dynamic Process Isolation。怪しいスクリプトを別プロセスに自動隔離するCloudflareの防御機能 |
| **Durable Objects** | デュラブル オブジェクト | Cloudflare Workersで長時間状態を保持して動き続けられる仕組み |
| **WebSocket** | ウェブソケット | サーバーとブラウザがリアルタイムで双方向通信するための技術 |
| **MPK** | エムピーケー | Memory Protection Keys。ハードウェアレベルでメモリ領域を保護する仕組み |
| **iTLB** | アイティーエルビー | 命令翻訳索引バッファ。CPUが命令を高速に処理するためのキャッシュ機構 |
| **投機的実行** | とうきてきじっこう | CPUが次の処理を予測して事前に実行しておく高速化技術。Spectreの根本原因 |
| **ビット** | - | 情報の最小単位。0か1かの1つのデータ |
| **テナント** | - | クラウドサービスを利用している企業・ユーザーのこと |

---

> 💡 **まとめ**：「同じサーバーで複数のお客さんのプログラムを動かす」という便利な仕組みの裏に、「隣のプログラムを盗み見られるかもしれない」という根本的なリスクが潜んでいた、というお話でした。Cloudflareはすでに対策済みで被害も確認されていませんが、クラウドセキュリティの設計の難しさを改めて示す重要な研究です。
