# アイデンティティ管理は「数時間で起きる侵害」に対応できていない

**元記事**: [Identity Governance Wasn't Built for Breaches That Happen in Hours](https://inl03.netline.com/ltr6/?_m=3n.009a.4062.sp0ao46r89.34bo)
**解説日**: 2025年7月11日

---

## 背景知識

まず、この記事を理解するためのキーワードを押さえましょう。

### 🔑「アイデンティティ（Identity）」って何？
セキュリティの世界での「アイデンティティ」とは、**「誰がシステムにアクセスするか」を示す情報**のことです。ユーザーアカウント（ID・パスワード）や、プログラムが自動で動くときに使う「サービスアカウント」などが含まれます。

**例え話**: 学校で例えると、「生徒証」のようなものです。生徒証を持っている人だけが図書室に入れる、というルールに近い概念です。

### 🏛️「IGA（Identity Governance and Administration）」って何？
日本語では「**アイデンティティ管理・統治**」と訳します。

- **誰が**、**どのシステムに**、**どんな権限で**アクセスできるかを管理・監視する仕組みのことです
- 例えば、「Aさんは経理システムにアクセスできるが、人事システムは見られない」といったルールを管理します

**例え話**: 学校の「鍵の管理簿」に近いです。「誰がどの部屋の鍵を持っているか」を定期的に確認して、不要になった鍵は回収する、あのイメージです。

### 🔐「エンタイトルメント（Entitlement）」って何？
「**アクセス権限**」のことです。「このファイルを読める」「このシステムを操作できる」といった、個々の権限のことを指します。

### 👤「CISO」って何？
**Chief Information Security Officer**の略で、**企業のセキュリティ責任者**のことです。会社全体のサイバーセキュリティ戦略を担う最高責任者です。

## 何が起きたのか

この記事は、特定のサイバー攻撃事件を報告するものではなく、**現在のアイデンティティ管理の仕組みに重大な欠陥がある**という問題提起をしています。

### 📋 現状の問題

多くの企業では、「誰がどのシステムにアクセスできるか」の確認を**3ヶ月に1回（四半期ごと）** や**年1回**しかやっていません。

```
現在の一般的な運用イメージ
├── 1月：アクセス権限の棚卸し実施
├── 2月〜3月：そのまま放置
├── 4月：アクセス権限の棚卸し実施 ← また3ヶ月後
└── ※この間に不正なアクセスが起きても気づかない！
```

### ⚡ でも、攻撃者は「数時間」で動く

記事によると、攻撃者がアカウントを乗っ取ってから実際に被害を起こすまで、**わずか数時間〜数分**しかかからないケースが増えています。

**例え話**: 3ヶ月に1回しか点検しない防犯カメラがあるとします。泥棒はカメラをすり抜けて、あっという間に盗みを働いてしまいます。それと同じ状況です。

## 技術的な詳細

### 🌐 問題が深刻化している3つの理由

#### ① アイデンティティの爆発的な増加（Identity Sprawl）

現代の企業では、クラウドやSaaSサービス（インターネット経由で使うソフトウェア）の普及により、管理すべきアカウントの数が爆発的に増えています。

特に注目されているのが「**非人間アイデンティティ（Non-Human Identity）**」です。

```
アイデンティティの種類
├── 人間のアイデンティティ（社員のアカウントなど）
│   例：田中さんのGoogleアカウント
└── 非人間のアイデンティティ（機械が使うアカウント）
    例：自動でデータをバックアップするプログラムのアカウント
        AIエージェントが使うアカウント
        → これが人間のアカウントより「はるかに多い」！
```

自動化やAIが進むにつれて、機械が使うアカウントが爆発的に増え、人間の手で管理するのが不可能になってきています。

#### ② 「ゴム印」化した権限確認

アカウントやアクセス権限の数が多すぎるため、担当者が内容をちゃんと確認せずに「とりあえずOK」と承認してしまう「**ゴム印（rubber stamp）**」状態になっています。

**例え話**: 先生が大量の提出物をチェックしなければならないとき、内容を読まずに全部に「確認済み」のはんこを押してしまうイメージです。形式上は確認しているのに、実際は何もチェックできていない。

#### ③ 規制当局や保険会社からの圧力

- 法規制（コンプライアンス）を監視する機関や、**サイバー保険**の会社が「**毎日ちゃんと管理できているか証明しろ**」と求めるようになりました
- 「3ヶ月前に確認しました」では不十分で、「**今日この瞬間も適切なアクセス管理をしています**」という証明が必要になっています

### 🤖 解決策：「自律型アイデンティティガバナンス」

記事では、AIを使った**自律型（Autonomous）の管理システム**が解決策として紹介されています。

```
従来の仕組み                    自律型の仕組み
┌─────────────────┐           ┌─────────────────┐
│ 3ヶ月に1回確認  │           │ 24時間365日監視 │
│ 人間が手動で確認│    →      │ AIが自動で判断  │
│ 大量のリストを  │           │ 異常をリアルタイム
│ ひたすら確認    │           │ で検知・対応    │
└─────────────────┘           └─────────────────┘
```

AIが以下のことを自動でやってくれます：

| 機能 | 説明 | 例え話 |
|------|------|--------|
| **通常の行動パターンの学習** | 普段どんなシステムにアクセスするかを覚える | いつもと違う時間に違う部屋に入ろうとしたら警告 |
| **異常の即時検知** | いつもと違う行動をしたらすぐ察知 | 「この人、突然管理者権限を使おうとしている！」 |
| **不要な権限の自動削除** | 使われていない権限を自動で取り除く | 卒業した先輩の下駄箱の鍵を自動で回収 |
| **危険な組み合わせの検出** | 同一人物が持つと危険な権限の組み合わせを発見 | 「お金を動かす権限」と「承認する権限」を同じ人が持つのはNG |

## なぜ重要なのか

### 💥 現実の脅威との「タイムギャップ」

```
攻撃者のスピード  ：数時間〜数分で被害発生
従来の管理のスピード：数週間〜数ヶ月に1回の確認
                    ↑ここに巨大な「すき間」がある！
```

この「すき間」こそが、サイバー攻撃者に悪用されます。

### 🏢 企業への影響

1. **情報漏洩リスクの増大**: 不要なアクセス権限が残っていると、乗っ取られたアカウントで広範囲の情報にアクセスされる危険があります
2. **コンプライアンス違反**: 法律や規制を守れていない証拠になりかねません
3. **セキュリティ担当者の過重労働**: 膨大な権限リストを手動で確認する作業が担当者を疲弊させています

### 👥 私たちへの影響

企業の情報管理が甘いと、私たちが登録したサービスの個人情報（名前・住所・クレジットカード情報など）が漏れるリスクが高まります。

## 対策・今後の展望

### ✅ 段階的な改善ステップ

記事では、いきなりすべてを変えるのではなく、**段階的に移行する「成熟モデル」**が紹介されています。

```
ステップ1: 基盤整備
  └─ 正確なアイデンティティと権限データの整理
  └─ どんなアクセスが「普通」かのデータ収集
  └─ リスクスコアリング（危険度の数値化）

ステップ2: 自動化の導入（ガードレール付き）
  └─ 高リスクな操作は人間が最終確認
  └─ すべての自動判断を記録・監査可能に

ステップ3: 信頼の構築
  └─ 実績を積みながらAIへの信頼度を上げていく
  └─ 徐々に自動化できる範囲を広げていく
```

### 🔮 今後の展望

- **AIを活用したリアルタイム管理**が業界標準になっていく
- 「3ヶ月に1回のチェック」から「**毎秒の自動監視**」へのシフトが加速
- ただし、**高リスクな判断は人間が最終確認する仕組み**を残すことが重要

### 💡 私たちができること

企業側の話が中心ですが、私たちも日常でできることがあります：

- 🔑 使わなくなったアプリやサービスのアカウントは削除する
- 🔒 パスワードの使い回しをしない（一つが漏れると全部危険）
- 📱 多要素認証（MFAパスワード以外にもSMSコードなどで確認）を設定する

## 過去記事との関連

今回は特定の過去記事との直接の関連はありませんが、**「アイデンティティ（ID・アカウント）の管理」はサイバーセキュリティの中心的なテーマ**です。

最近のサイバー攻撃の多くは、「システムの脆弱性を直接攻撃する」のではなく、「**正規のアカウントを乗っ取って正規ユーザーになりすます**」手法が主流になっています。だからこそ、「誰がどこにアクセスできるか」の管理が、現代セキュリティの最重要課題になっているのです。

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **IGA** | アイジーエー | Identity Governance and Administration。アイデンティティの管理・統治の仕組み |
| **CISO** | シーアイエスオー | Chief Information Security Officer。企業のセキュリティ最高責任者 |
| **アイデンティティ** | - | セキュリティ文脈では「誰がアクセスするかを示す情報（アカウント等）」 |
| **エンタイトルメント** | - | 個別のアクセス権限のこと |
| **サービスアカウント** | - | プログラムや自動化ツールが使う機械用アカウント |
| **非人間アイデンティティ** | - | 人ではなくプログラムやAIが使うアカウント |
| **コンプライアンス** | - | 法律・規則・ルールを守ること |
| **ラテラルムーブメント（横移動）** | - | 攻撃者が一つのアカウントを乗っ取った後、社内の別のシステムに次々と侵入していくこと |
| **多要素認証（MFA）** | エムエフエー | パスワードに加えて、スマホのSMSコードなど複数の方法で本人確認する仕組み |
| **SaaS** | サース | Software as a Service。インターネット経由で使えるソフトウェアサービス（GoogleドキュメントやSlackなど） |
| **自律型ガバナンス** | - | AIが自動でアクセス権限を監視・管理する仕組み |
| **職務分掌（SoD）** | - | Segregation of Duties。不正防止のために、重要な業務を複数の人に分担させること |

---

> 💬 **まとめ**: 企業がシステムへのアクセス権限を「3ヶ月に1回確認」という古い方法で管理しているうちに、攻撃者は「数時間」で侵害を完了させてしまいます。AIを使ったリアルタイムの自動監視に切り替えることで、この危険なタイムギャップを埋めようというのが、この記事の主張です。アカウント管理の問題は、企業だけでなく私たち一人ひとりのデータにも直結する、身近なセキュリティ課題です！
