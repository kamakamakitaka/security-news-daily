# ゾンビカード攻撃：期限切れのVisaカードが復活してしまう新たな脆弱性

**元記事**: [Zombie Card Attack Can Revive Expired Visa Cards for Contactless Payments](https://inl03.netline.com/ltr6/?_m=3n.009a.4062.sp0ao46r89.34c0)
**解説日**: 2026年8月21日

---

## 背景知識

このニュースを理解するために、まずクレジットカードの仕組みを整理しましょう。

### 💳 クレジットカードの「有効期限」とは？

クレジットカードには、表面に「MM/YY」形式で有効期限が書かれています。この期限が切れると、新しいカードが発行されます。でも、実は**カード番号（アカウント番号）は同じまま**で、期限だけが変わることがほとんどです。

### 📱 タッチ決済（コンタクトレス決済）の仕組み

最近のクレジットカードやスマホ決済でよく使う「タッチするだけで払える」機能は、**NFC（近距離無線通信）** という技術を使っています。スマホのSuicaやQUICPayも同じ仕組みです。

決済の流れはこんな感じです：

```
カード → 【NFC通信】→ レジ端末(POS) → 銀行サーバー
         ↑ここを改ざん！
```

### 🔐 EMVとは？

**EMV（Europay・Mastercard・Visa）** は、クレジットカード決済の国際標準規格です。「ICチップ付きカード」はすべてこの規格に基づいています。安全性を高めるために、暗号技術（サイン・署名）が使われています。

### 🕵️ 中間者攻撃（MitM）とは？

**Man-in-the-Middle攻撃** とは、AさんとBさんが通信しているとき、その間にこっそり割り込んで内容を盗み見たり改ざんしたりする攻撃です。今回の攻撃でも、カードとレジ端末の間に攻撃者が割り込みます。

---

## 何が起きたのか

アメリカ・マサチューセッツ大学アマースト校の研究者たちが、**「ゾンビカード攻撃（Zombie Card Attack）」** と名付けた新しい攻撃手法を発見・実証しました。

### 🧟 「ゾンビ」カードとは？

> 死んで（期限切れに）なったはずのカードが、まるでゾンビのように復活して使えてしまう

…という意味を込めた名前です。

### 具体的に何ができるのか？

- **期限切れのVisaカード**（例：「2024年12月まで有効」で失効済みのカード）を使って
- **実際のお店で商品を買える**ことを実証しました
- しかも、カードの**暗号（セキュリティの核心部分）を一切破らずに**！

2026年8月12〜14日にボルチモアで開催された「USENIX Security Symposium」という権威あるセキュリティ学会で発表されました。研究チームはすでに2025年5月にVisaと関係銀行に報告しています。

---

## 技術的な詳細

### 🔍 有効期限が「2か所」に存在する問題

実はVisaのタッチ決済では、有効期限の情報が**2か所**に分かれて入っています。

| 場所 | 技術的な名前 | 誰が使うか |
|------|-------------|-----------|
| ① Tag 5F24 | Application Expiration Date | **レジ端末**が確認する |
| ② Tag 57（Track 2） | Track 2 Equivalent Data | **銀行サーバー**が確認する |

これを図で表すと：

```
期限切れカード
　　　↓
② Track 2（銀行用）：「2024/12」← そのまま（改ざんしない）
① Tag 5F24（端末用）：「2024/12」→「2027/12」← ここだけ改ざん！
　　　↓
レジ端末：「あ、2027年まで有効だ、OK！」✅
　　　↓
銀行サーバー：「2024/12...口座は生きてるし、暗号も合ってる、OK！」✅
```

### 🛡️ なぜ暗号が守ってくれないの？

クレジットカードには「このカードは本物だよ」と証明するための**デジタル署名（fDDA）** が使われています。でも…

> Visaの「Kernel 3」という実装では、この署名の対象に **Tag 5F24（端末用の有効期限）が含まれていない**！

つまり、**有効期限を書き換えても署名の検証には影響しない**のです。鍵のかかっていない引き出しを改ざんするようなものです。

さらに問題があります：

- **端末が期限チェックをした結果**（Terminal Verification Results）は、銀行に送るとき**すべてゼロ（正常）にリセット**される仕様になっている
- つまり「端末が期限切れと判断した」という情報が、**銀行には届かない**！

### 🏦 銀行ごとの対応の違い

研究チームが5つの大手米銀行でテストしたところ、対応がバラバラでした：

| 銀行 | 改ざん検知 | 結果 |
|------|----------|------|
| 銀行A | ❌ 気づかない | 複数カードの同時使用も可能（最悪） |
| 銀行B | ✅ 検知できる | 1枚のみ使用可能（比較的安全） |
| 銀行D | ✅ 検知できる | でも複数カードの同時使用は止められず |

## なぜ重要なのか

### ⚠️ 影響の大きさ

1. **暗号を破らずに攻撃できる**
   　通常、クレジットカードの攻撃というと「暗号を解読する」難しい作業が必要ですが、この攻撃は**暗号に触れずに成立**します。これは非常に珍しく、危険です。

2. **物理カードがあれば誰でも試せてしまう**
   　期限切れのカードを持っているだけで（自分の古いカードでも）、理論上は実行できます。

3. **規格そのものの問題**
   　これは特定の会社のミスではなく、**EMVという世界標準規格の設計上の問題**であるため、影響範囲が非常に広いです。

4. **Visa・EMVCo・各銀行がまだ公式な対策を発表していない**
   　2026年8月20日時点で、Visaをはじめとする関係機関からの対策ガイダンスは一切公表されていません。

### 😮 でも、悪用は報告されていない

研究者が発見した**学術的な実証実験**であり、実際の犯罪への悪用は報告されていません。ただし、今後悪用される可能性は否定できません。

## 対策・今後の展望

### 🔒 今すぐできること（ユーザー向け）

| 対策 | 説明 |
|------|------|
| 💳 古いカードはすぐに廃棄 | ハサミで切るだけでなく、ICチップ部分も物理的に破壊する |
| 📱 明細を定期的に確認 | 見知らぬ引き落としがないかこまめにチェック |
| 🔔 利用通知を設定 | カード会社のアプリで「使われたらすぐ通知」をONに |
| 💰 上限設定を活用 | タッチ決済の1回あたりの上限金額を低く設定する |

### 🏦 本当の対策（業界・規格レベル）

根本的な解決には、規格改定が必要です：

- **Tag 5F24をデジタル署名の対象に含める**
- **端末の期限チェック結果（TVR）を銀行にも正確に送る**
- **銀行が独立して有効期限を再確認する**

ただし、EMVのような世界規格の変更は時間がかかるため、すぐには難しいのが現状です。

### 📰 現状

研究チームは2025年5月と2025年12月にVisaと関係銀行に報告済みですが、2026年8月現在、公式な対策は発表されていません。CVE番号（脆弱性の公式登録番号）も割り当てられていない状態です。

## 過去記事との関連

以前、**Rustのサプライチェーン攻撃**（2億4500万ダウンロードのライブラリへのマルウェア混入）について解説しましたが、今回の事件と共通する重要なポイントがあります。

> **「信頼されているシステムの中に潜む見落とし」** が悪用される

- Rustの事件では「信頼されているライブラリ」に悪意あるコードが混入
- 今回の事件では「信頼されている規格（EMV）」に設計上の抜け穴が存在

どちらも「安全だと思われていたもの」の内側に問題があったという点で、セキュリティの本質的な難しさを示しています。どんな巨大なシステムも、細部の見落としが致命的な弱点になりうるのです。

## 用語解説

| 用語 | 説明 |
|------|------|
| **NFC（近距離無線通信）** | 数センチの距離で機器同士が通信できる技術。SuicaやタッチペイはすべてNFC |
| **POS端末** | レジにあるカード読み取り機のこと（Point of Sale） |
| **EMV** | クレジットカードのICチップ決済の国際標準規格。Europay・Mastercard・Visaの頭文字 |
| **MitM（中間者攻撃）** | 通信の間に割り込んで、内容を盗み見たり改ざんしたりする攻撃 |
| **TLV（Tag-Length-Value）** | データを「タグ（種類）・長さ・値」の組み合わせで表現する形式。カードデータの保存に使われる |
| **fDDA（高速動的データ認証）** | カードが本物かどうかを確認するためのデジタル署名技術 |
| **PAN（主口座番号）** | クレジットカードの16桁の番号のこと |
| **Kernel 3** | Visaのタッチ決済処理を担当するソフトウェア実装 |
| **CVE** | 脆弱性に割り当てられる公式の識別番号（例：CVE-2024-XXXX） |
| **USENIX Security** | コンピュータセキュリティ分野で世界トップクラスの学術会議 |
| **CDCVM** | 消費者デバイス（スマホなど）を使った本人確認方法のフラグ |
