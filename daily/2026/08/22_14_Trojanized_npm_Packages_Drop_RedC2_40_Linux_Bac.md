# 14個のトロイの木馬化されたnpmパッケージが「RedC2 4.0」というAI搭載Linuxバックドアをばらまいていた

**元記事**: [14 Trojanized npm Packages Drop RedC2 4.0 Linux Backdoor With AI-Assisted C2](https://inl03.netline.com/ltr6/?_m=3n.009a.4063.sp0ao46r89.34c8)
**解説日**: 2025年7月10日

---

## 背景知識

まず、この記事を理解するために必要なキーワードをおさえましょう。

### 📦 npm（エヌピーエム）とは？
**npm（Node Package Manager）** とは、JavaScriptのプログラムを作るときに使う「部品の図書館」のようなものです。

たとえばプログラマーが「日付を計算する機能」を作りたいとき、ゼロから全部作るのは大変です。そこで、すでに誰かが作って公開している「パッケージ（部品）」をダウンロードして使います。npmはその部品を管理・配布する仕組みです。

> 🎮 **例え話**: ゲームのMOD（改造データ）配布サイトのようなもの。誰でも部品を公開でき、誰でも使えます。

### 🐴 トロイの木馬とは？
「トロイの木馬」とはギリシャ神話に登場する話から来た言葉で、**外見は普通の便利なソフトウェアに見えるが、中に悪意のあるコードが隠されているマルウェア（悪意あるプログラム）** のことです。

### 🖥️ C2（シーツー）サーバーとは？
**C2（Command and Control＝コマンド＆コントロール）サーバー** とは、攻撃者がウイルスに感染したパソコンを遠隔操作するための「司令塔」です。

> 🎮 **例え話**: RPGゲームの「魔王の城」のようなもの。感染したパソコン（手下）がこの城に命令を聞きに行き、攻撃者（魔王）の指示通りに動きます。

### 🐧 Linuxとは？
**Linux（リナックス）** とは、WindowsやmacOSと並ぶOSの一種です。サーバー（インターネットを支えるコンピュータ）の多くがLinuxで動いており、企業や研究機関にとって非常に重要なシステムです。

### 🤖 AIとは（このニュースの文脈で）？
この記事では、攻撃者が**AIを活用して攻撃の自動化・高度化**を行っていると示されています。具体的には、C2サーバーの管理やマルウェアの制作にAI技術が活用されています。

## 何が起きたのか

セキュリティ会社「Trend Micro（トレンドマイクロ）」の研究チームが、**14個の危険なnpmパッケージ**を発見しました。

これらのパッケージは、表向きには「カレンダー機能」や「連続記録（ストリーク）の計算ツール」として公開されていました。しかし、その中には**「RedC2 4.0」というLinux向けの強力なバックドア（裏口）プログラムが隠されていました**。

## 技術的な詳細

### 🎭 どうやって騙すのか？

この攻撃が非常に巧妙な点は、**パッケージが「本当に動く」こと**です。

- インストールすると、カレンダーや日付計算の機能は**ちゃんと動きます**
- しかし裏側では、悪意あるプログラムが**こっそり同時に起動**します

> 🎮 **例え話**: 本物のお菓子が入っているのに、箱の二重底にこっそり盗聴器が仕込まれているようなイメージです。

### ⚙️ 感染の仕組み（ステップバイステップ）

```
① プログラマーが便利そうなパッケージをnpmからインストール

② パッケージが読み込まれると、自動で悪意あるファイルが起動
   （インストール時の特別な操作すら不要！読み込むだけでOK）

③ 悪意あるファイル（math-core.bin / calc.bin など）が
   実行可能な状態に変えられ、バックグラウンドで密かに起動

④ 感染したパソコンが攻撃者のC2サーバーに「チェックイン（出欠確認）」

⑤ 攻撃者がパソコンを遠隔操作できる状態になる
```

### 🚨 特に怖いポイント：「間接的に読み込むだけで感染する」

通常、こういった攻撃はパッケージを**直接**インストールしたときに発動します。しかしこの攻撃は、

> **「そのパッケージを使っている別のパッケージ」を使うだけでも感染する**

という仕組みになっています。これを「**推移的な依存関係（transitive dependency）**」と呼びます。

> 🎮 **例え話**: 危ない食べ物を食べた人から調理された料理を食べるだけで、あなたも影響を受けてしまうイメージです。

### 🦠 RedC2 4.0の機能

攻撃者が使う「RedC2 4.0」は、**まるで本格的なツールキット**のように機能が揃っています：

| 機能 | 説明 |
|------|------|
| ターミナルアクセス | 感染したパソコンをコマンドで自由に操作 |
| ファイル転送 | ファイルを盗んだり送り込んだりする |
| 監視 | システムの情報を収集する |
| 認証情報の窃取 | パスワードやSSHキーを盗む |
| ブラウザの情報収集 | ブラウザに保存されたパスワードを盗む |
| ネットワーク経由の横移動 | 同じネットワーク内の別のパソコンにも侵入する |
| メモリ上での実行 | ファイルを残さずプログラムを動かす（検出回避） |

Linux版・Windows版・macOS版の3つがあり、OSをまたいで攻撃ができます。

### 👤 攻撃者について

「**MarlboroMan（マルボロマン）**」と名乗る脅威アクター（攻撃者）が、2026年6月初旬にハッカーフォーラムで「RedC2 4.0」を宣伝・販売していたことが確認されています。

- **2025年8月**: RedC2 2.0 リリース
- **2026年1月**: RedC2 3.0 販売
- **2026年6月**: RedC2 4.0 宣伝開始（Linux版バックドア「RedShell」を初搭載）

このことから、少なくとも約1年間にわたって活発に開発・販売されている「**サービスとして販売される攻撃ツール（MaaS: Malware as a Service）**」であることがわかります。

## なぜ重要なのか

### 🌍 影響を受ける可能性がある人・組織

- **企業の開発者**: JavaScriptを使ってシステムを作っている開発者全員が対象になりえます
- **サーバー管理者**: Linuxサーバーを使っている企業・組織
- **オープンソースプロジェクト**: 多くのプロジェクトが外部パッケージに依存しているため、1つの感染が連鎖する危険性があります

### ⚠️ なぜ特に危険なのか

1. **発見が難しい**: ちゃんと動く正規機能と悪意あるコードが同居しているため、動作テストだけでは発見できません
2. **自動起動**: インストール後の特別な操作なしで起動します
3. **間接感染**: 自分が直接使っていなくても感染の可能性があります
4. **AI活用の攻撃**: 攻撃がより高度化・自動化されています
5. **クロスプラットフォーム**: Windows・Linux・macOSすべてを標的にします

### 💰 攻撃者の目的

- 企業の機密データや認証情報（パスワード）の窃取
- 感染したサーバーを踏み台にした別の攻撃への悪用
- ランサムウェア（身代金要求ウイルス）の展開

## 対策・今後の展望

### ✅ 開発者ができる対策

#### 1. パッケージを使う前に確認する
```
- 公開日・更新日が不自然に新しくないか？
- ダウンロード数が極端に少なくないか？
- 作成者の情報は信頼できるか？
- パッケージの中身（ソースコード）を確認できるか？
```

#### 2. セキュリティツールを使う
- **npm audit**（npmに標準搭載の脆弱性チェックツール）を定期的に実行する
- **Dependabotなどの自動依存関係チェックツール**を導入する

#### 3. 不審なファイルに注意する
今回の場合、以下のような**不審な名前のバイナリファイル**が含まれていました：
- `math-core.bin`
- `calc.bin`
- `calc-math.dat`

npmパッケージに`.bin`や`.dat`のような実行ファイルが含まれている場合は注意が必要です。

#### 4. 「最小権限の原則」を守る
開発環境・本番環境ともに、不必要な権限を与えないようにしましょう。

### 🔮 今後の展望

- **AI活用型攻撃の増加**: 攻撃者もAIを使うことで、より巧妙・大規模な攻撃が増えると予想されます
- **サプライチェーン攻撃の継続**: npmのような広く使われるエコシステムを狙う攻撃は今後も続くでしょう
- **セキュリティツールの進化**: 各セキュリティ企業もAIを使った検出技術を高度化しています

## 過去記事との関連

今回の「npmパッケージを悪用したサプライチェーン攻撃」は、近年増加している**ソフトウェアサプライチェーン攻撃（Software Supply Chain Attack）** の典型的なパターンです。

過去にも、
- **「typosquatting（タイポスクワッティング）」攻撃**: 有名パッケージに似た名前の偽物パッケージを公開する手口
- **SolarWinds事件（2020年）**: 企業向けソフトウェアにバックドアが仕込まれ、多数の政府機関や企業が被害を受けた事件

など、「信頼された経路を悪用する攻撃」は繰り返されてきました。今回の事件は、その手口がさらに**AI活用**によって高度化していることを示す最新の事例です。

## 用語解説

| 用語 | 読み方 | 説明 |
|------|--------|------|
| **npm** | エヌピーエム | JavaScriptの部品（パッケージ）を管理・配布する仕組み |
| **トロイの木馬** | - | 正常に見せかけて悪意あるコードを隠したマルウェア |
| **バックドア** | - | 攻撃者がこっそり侵入するための「裏口」プログラム |
| **C2サーバー** | シーツーサーバー | 感染したパソコンを遠隔操作するための「司令塔」サーバー |
| **マルウェア** | - | 悪意あるソフトウェアの総称（ウイルス・スパイウェアなど） |
| **Linux** | リナックス | 多くのサーバーで使われているOS |
| **依存関係** | いぞんかんけい | あるプログラムが動くために必要な別のプログラムとの関係 |
| **推移的依存関係** | すいいてきいぞんかんけい | 「Aが使うBが使うC」のように間接的な依存関係 |
| **サプライチェーン攻撃** | - | ソフトウェアの開発・配布の流れの中に悪意あるコードを混入する攻撃 |
| **ビーコン** | - | 感染したパソコンが定期的に攻撃者のサーバーに「生存確認」を送ること |
| **横移動（ラテラルムーブメント）** | - | 感染したパソコンから同じネットワーク内の別のパソコンへ侵入を広げること |
| **MaaS** | マース | Malware as a Service。マルウェアをサービスとして販売するビジネスモデル |
| **SSHキー** | エスエスエイチキー | サーバーにログインするための電子的な鍵。盗まれると不正ログインされる |
| **BOF** | ビーオーエフ | Beacon Object File。メモリ上で直接実行できるプログラムの形式 |
| **SOCKS5プロキシ** | ソックスファイブプロキシ | 通信を中継する仕組み。攻撃者が身元を隠すために使う |
| **UAC bypass** | ユーエーシーバイパス | Windowsの「管理者権限の確認」を回避する手法 |
