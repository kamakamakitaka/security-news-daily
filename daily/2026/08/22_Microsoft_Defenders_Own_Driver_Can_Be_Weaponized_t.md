# Windowsの守護者が凶器に？マイクロソフトのセキュリティソフト自身のドライバーが悪用される手口

**元記事**: [Microsoft Defender's Own Driver Can Be Weaponized to Delete Security Software at Boot](https://inl03.netline.com/ltr6/?_m=3n.009a.4063.sp0ao46r89.34ce)
**解説日**: 2026年8月22日

---

## 背景知識

まず、このニュースを理解するためのいくつかの基礎知識を押さえましょう。

### 🖥️ Windowsの「階層構造」とは？

パソコンの中は、まるでビルの構造のように「階層」になっています。

```
【Ring 0】カーネル（OS の核心部分）← 最も権限が強い・最も深い場所
    ↓
【Ring 3】ユーザーモード（普段使うアプリなど）← 一般的な操作
```

**カーネル（kernel）**とは、OSの最も深い部分で、ハードウェア（CPU・メモリなど）を直接操作できる「司令塔」のようなものです。ここに侵入されると、パソコン上のほぼあらゆることが可能になります。

### 🛡️ Microsoft Defenderとは？

**Microsoft Defender**は、Windowsに最初から入っているウイルス対策ソフトです。みなさんのパソコンにも入っているはずです。これがウイルスを検知・削除するために、いくつかの「部品（ファイル）」を使っています。

### 🔧 ドライバー（Driver）とは？

**ドライバー**とは、OSがハードウェアやシステムの特殊な機能を使うために必要な「橋渡し役のプログラム」です。プリンタードライバーをイメージするとわかりやすいですね。ドライバーはカーネル（Ring 0）レベルで動くことが多く、非常に高い権限を持ちます。

### 🏠 「起動時（ブート時）」の特殊な状況

パソコンを起動するとき、Windowsはいくつかの「段階」を経て立ち上がります。特に注目すべきは：

```
電源ON
 → ハードウェアが起動
 → ファイルシステムが読み書き可能になる ← ここが重要！
 → セキュリティソフトが起動する
 → デスクトップが表示される
```

**「ファイルシステムが使えるようになった瞬間」から「セキュリティソフトが動き始めるまで」の間**に、わずかな「すきま時間」があります。今回の攻撃はまさにこの「すきま」を狙います。

## 何が起きたのか

セキュリティ研究会社「**Check Point Research**」の研究者、**Jiří Vinopal（イジー・ヴィノパル）氏**が、驚くべき技術を発見しました。

> 「Microsoft Defenderに内蔵されている正規のドライバーを使って、Defender自身を含むセキュリティソフトを完全に削除できる」

この発見は、2026年8月にラスベガスで開催されたセキュリティの世界最大イベント「**Black Hat USA 2026**」と「**DEF CON 34**」で発表されました。

ポイントは以下の3つです：

- ✅ **Windowsの弱点（バグ）を突いているわけではない**
- ✅ **外部から怪しいファイルを持ち込む必要がない**
- ✅ **Windows 7から最新のWindows 11まで全バージョンに影響**

---

## 技術的な詳細

### 🔍 問題の「ドライバー」とは何か？

今回の主役は **`BTR.sys`（Boot Time Removal Tool）** というファイルです。

このファイルは何をするものかというと、「ウイルス対策ソフトが、Windowsが起動している間に削除できなかったウイルスファイルを、**次の起動時に削除する**」ための専用ツールです。

たとえるなら：
> 「お店の営業中はお客さんが邪魔で掃除できないから、**閉店後（起動前）に掃除する専用の掃除機**」

このBTR.sysは、**Defenderの公式ファイルに内蔵されていて、Microsoftが正式に署名した正規のファイル**です。だから「危険なドライバー」のブロックリストには絶対に載せられない、という問題があります。

### 🔑 暗号鍵が「全バージョン共通」だった

研究者がBTR.sysを詳しく調べたところ、このドライバーへの命令を暗号化するための**鍵（RC4暗号の256バイトの鍵）**が、Windows 7以降の**全バージョンで同じ値**であることがわかりました。

> 💡 例え話：「銀行の金庫の鍵が、全国どの支店でも同じだった」ようなもの

この鍵さえわかれば、誰でも「正規の命令書」を偽造してBTR.sysに渡せてしまいます。

### ⚡ 「黄金の窓（Golden Window）」を狙う攻撃の流れ

攻撃の流れを順番に見てみましょう：

```
①  攻撃者が管理者権限でパソコンを操作
     ↓
②  Defenderの公式ファイルからBTR.sysを取り出す
     ↓
③  暗号化された「命令書」（削除リスト）を偽造して用意
     ↓
④  BTR.sysをWindowsのシステムに登録
    ※ 通常の記録（ログ）には残らない方法で！
     ↓
⑤  パソコンを再起動
     ↓
⑥【黄金の窓】ファイルシステムON ＋ セキュリティソフトがまだ起動していない
     ↓
⑦  BTR.sysが最高権限（Ring 0）でDefenderを丸ごと削除！
     ↓
⑧  Windowsが起動完了 → もうDefenderは動いていない
```

実際のデモでは、**完全にアップデート済みのWindows 11の最新版（25H2）で、「改ざん防止機能（Tamper Protection）」が有効な状態でも、Defenderを完全削除することに成功**しました。

### 🕵️ 痕跡が残りにくい

通常、Windowsにプログラムをサービスとして登録すると「**イベントID 7045（サービスがインストールされた）**」というログが残ります。しかしこの手法では、そのログすら残らない方法でインストールされるため、発見が難しいのです。

## なぜ重要なのか

### 📊 影響範囲の広さ

| 項目 | 内容 |
|------|------|
| 対象OS | Windows 7 〜 Windows 11 25H2（ほぼ全Windowsユーザー） |
| 必要条件 | 管理者権限（Administrator） |
| 特殊なツール | 不要（Windowsに最初から入っているファイルだけ） |
| バグの悪用 | なし（仕様通りの動作を利用） |

### 🤔 「脆弱性（バグ）ではない」という難しさ

Microsoftは「これは管理者権限がすでに必要なので、すぐに修正する脆弱性とは見なさない」と回答しています。

> 💡 例え話：「マスターキーを持っている人が鍵を開けられる」のは設計通りなので「バグではない」、でも「そのマスターキーを悪用されたら全部屋が危ない」という問題です。

ただし、現実の攻撃では「管理者権限を取得した後、さらにセキュリティソフトを消す」という流れは非常によくあります。今回の手法は、その「消す」部分を極めて効果的にしてしまいます。

### ✅ 現時点では実際の被害なし

Check Point Researchは「**現時点ではこの手法が実際の攻撃に使われた証拠はない**」としています。これは「先手を打って公表した」責任ある情報開示（Responsible Disclosure）です。

## 対策・今後の展望

### 🛡️ 一般ユーザーへの対策

**正直なところ、一般ユーザーが今すぐできる完全な対策はありません。** ただし、以下を意識することでリスクを下げられます：

| 対策 | 理由 |
|------|------|
| ✅ 管理者アカウントで普段使いしない | この攻撃には「管理者権限」が必須。普段は一般ユーザーアカウントを使いましょう |
| ✅ 怪しいソフトをインストールしない | 攻撃者がこの手法を使うには、まず管理者権限が必要。そのきっかけになりやすい |
| ✅ Windowsのアップデートを欠かさない | Microsoftが将来的に対策を講じた場合、アップデートで配布される可能性がある |
| ✅ 複数のセキュリティ対策を組み合わせる | 1つのセキュリティに頼りすぎない（多層防御） |

### 🔮 今後の展望

- **Microsoft**が何らかの緩和策（完全修正でなくても対策）を出す可能性がある
- **セキュリティ製品**が「BTR.sysの不審な使われ方」を検知する機能を追加する可能性がある
- **企業向け**には、管理者権限を必要以上に与えない「最小権限の原則」の徹底が特に重要

ということです。セキュリティソフトも「正規ファイルの悪用」を検知するのが非常に難しく、攻撃者にとって魅力的な手口になっています。

## 用語解説

| 用語 | 説明 |
|------|------|
| **カーネル（Kernel）** | OSの核心部分。ハードウェアを直接操作できる最高権限の領域 |
| **ドライバー（Driver）** | OSが特定のハードウェアや機能を使うための橋渡しプログラム |
| **BTR.sys** | Defenderが「次回起動時に削除する」操作を実行するための専用ドライバー |
| **Ring 0** | カーネルが動作する最高権限レベル（数字が小さいほど権限が強い） |
| **RC4暗号** | データを暗号化するための方式の一つ |
| **Tamper Protection** | Defenderが自分自身を改ざんされないように守る機能 |
| **WDAC** | Windows Defender Application Control。危険なドライバーをブロックする仕組み |
| **管理者権限（SeLoadDriverPrivilege）** | Windowsでドライバーを読み込むために必要な特別な権限 |
| **Black Hat / DEF CON** | 世界最大規模のセキュリティ研究者向け会議・イベント |
| **Responsible Disclosure（責任ある開示）** | 脆弱性を発見した際、公表前にメーカーに通知してから公開する倫理的な手順 |
| **BYOVD（Bring Your Own Vulnerable Driver）** | 既知の欠陥ドライバーを外部から持ち込んで悪用する攻撃手法 |
| **Golden Window（黄金の窓）** | 起動時にファイルシステムが使えるようになってからセキュリティソフトが起動するまでの短い時間 |
| **イベントID 7045** | Windowsがサービスのインストールを記録するログの識別番号 |

---

> 🔑 **まとめると**：「鍵を守るはずの警備員が持っているマスターキーを使って、その警備員自身を追い出せてしまう」という巧妙な手口です。完全な修正は難しいですが、「まず管理者権限を奪われないこと」が最大の予防策です。
