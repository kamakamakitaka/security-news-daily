# Keycloakの重大なパスワードリセット欠陥：未認証の攻撃者がどのアカウントでも乗っ取れる可能性

**元記事**: [Critical Keycloak Password Reset Flaw Could Let Unauthenticated Attackers Take Over Any Account](https://inl03.netline.com/ltr6/?_m=3n.009a.4064.sp0ao46r89.34ds)
**解説日**: 2025年7月14日

---

## 背景知識

このニュースを理解するために、まずいくつかの基本的な仕組みを押さえておきましょう。

### 🔑 「Keycloak（キークローク）」って何？

企業やサービスが複数のシステムを運営しているとき、「ユーザーのログイン管理」をまとめて行うためのソフトウェアです。Red Hat（レッドハット）という会社が開発したオープンソース（無料で公開されている）のツールで、「**1回ログインするだけで、複数のサービスを使えるようにする**」仕組み（シングルサインオン）などを提供しています。

> **例え話**: 学校のIDカードを使えば、図書室にも、体育館にも、コンピュータ室にも入れる仕組みをイメージしてください。Keycloakはその「IDカードを管理するシステム」です。

企業の内部システムから、大規模なWebサービスまで、世界中で広く使われています。Keycloakの「後ろ側」にあるすべてのサービスへのアクセスをKeycloakが守っているため、Keycloak自体に穴が空くと、**その後ろのすべてが危険になる**という性質があります。

### 🔐 「パスワードリセット機能」の仕組み

「パスワードを忘れた」ときの手順は、多くのサービスで共通です：

1. 「パスワードを忘れた」ボタンを押す
2. メールアドレスを入力する
3. そのメールに**特別なリンク（アクションリンク）**が届く
4. そのリンクを踏んで、新しいパスワードを設定する

この「特別なリンク」が存在するのは、**「メールを受け取れる本人だけが、パスワードを変更できる」**ことを確認するためです。これが今回の脆弱性の核心です。

### 📊 CVSSスコアって？

「脆弱性（セキュリティの穴）の深刻さ」を数字で表すものです。0〜10点で評価され、10点に近いほど危険です。

| スコア | 深刻度 |
|--------|--------|
| 9.0〜10.0 | **緊急（Critical）** |
| 7.0〜8.9 | 重要（High） |
| 4.0〜6.9 | 警告（Medium） |
| 0.1〜3.9 | 注意（Low） |

今回の脆弱性は **9.1点** なので、最も危険な「緊急」レベルです。

## 何が起きたのか

**一言でまとめると：**
> 「パスワードリセット機能」の欠陥により、攻撃者が**メールの確認なしに**、誰のパスワードでも書き換えて、アカウントを乗っ取れる脆弱性が発見されました。

2026年8月（記事の日付より未来の日付が記されていますが、記事の内容に沿って解説します）、Red HatとKeycloakプロジェクトは、**CVE-2026-18963**という識別番号がついた重大な脆弱性を公表し、修正版をリリースしました。

この欠陥の恐ろしいところは：
- ✅ **ログインしていない攻撃者でも**悪用できる
- ✅ **被害者が何かをする必要がない**（リンクをクリックしなくても被害に遭う）
- ✅ **管理者アカウントも含む、すべてのアカウント**が対象
- ✅ 悪用に特別な技術や権限は不要

## 技術的な詳細

### 🔍 何が問題だったのか？

通常のパスワードリセットの流れを「鍵と錠前」に例えて考えてみましょう。

**正常な手順：**
```
① 「鍵をなくした」と申告する
② 本人確認のため、登録メールに「合言葉」が送られる
③ その「合言葉」を使って初めて、鍵を作り直せる
```

**今回の欠陥（攻撃の流れ）：**
```
① 「鍵をなくした」と申告する
② 「合言葉のメール」が届く前に、巧妙な操作をする
③ ②の確認をすっ飛ばして、直接「鍵の作り直し」の段階に移行できてしまう！
```

### 🛠️ 技術的な説明（少し詳しく）

Keycloakのパスワードリセット処理には**「状態管理」**という仕組みがあります。処理の各ステップで「今どの段階か」を記録しており、正しい順序で進まないと先に進めないはずです。

しかし今回の欠陥では、この**「状態の検証（確認）が不十分」**でした。

攻撃者が特別に細工したリクエスト（命令）をKeycloakの「`reset-credentials`（パスワードリセット）エンドポイント」に送ると：

1. 本来は「メールで送られる特別なトークン（合言葉）」が必要なはずが…
2. **その確認が行われないまま**、「パスワード変更フェーズ」に直接ジャンプしてしまう

> **例え話**: マンションのオートロックを解除するとき、通常は「住人証明→暗証番号→ドア開錠」という順番ですが、この欠陥は「住人証明」の部分を巧みにスキップして、いきなり「ドア開錠」できてしまうようなものです。

## なぜ重要なのか

### 🌍 Keycloakの普及度

Keycloakは世界中の企業・組織・政府機関などで広く採用されており、その「後ろ側」には多数のシステムが連なっています。Escapeというセキュリティ企業の研究者・Enzo Mongin氏は別の事例を解説した際に、こう指摘しています：

> 「攻撃者がKeycloakの境界を突破したら、Keycloakだけでは済まない。**その後ろに連なるすべてのものに侵入できる**」

これは非常に重要な指摘です。Keycloakは「玄関の鍵」のような存在なので、玄関を破られると家中どこでも侵入できてしまうのです。

### ⚠️ 影響の深刻さ

| 項目 | 内容 |
|------|------|
| 攻撃に必要な条件 | **なし**（未ログインでも攻撃可能） |
| 被害者の操作 | **不要**（被害者は何もしなくても被害に遭う） |
| 乗っ取れるアカウント | **全ユーザー**（管理者含む） |
| CVSSスコア | **9.1（緊急）** |

管理者アカウントを乗っ取られた場合、攻撃者はシステム全体を掌握できます。

### ✅ 現時点での状況

記事執筆時点では、**実際に悪用された証拠はなく、公開されたエクスプロイト（攻撃コード）も確認されていない**とのことです。ただし、脆弱性の情報が公開された今、攻撃者が動き出す可能性があるため、迅速な対応が必要です。

## 対策・今後の展望

### 🛡️ 今すぐできる対策

**① 修正版へのアップデート（最優先）**

| 製品 | 対応バージョン |
|------|--------------|
| Keycloak（一般公開版） | **26.7.2**（2026年8月19日リリース） |
| Red Hat build of Keycloak 26.4 | **26.4.15** 以降 |
| Red Hat build of Keycloak 26.6 | **26.6.6** 以降 |

**② すぐにアップデートできない場合の暫定対策**

Red Hatは一時的な回避策も公開しています：

> **「パスワードを忘れた」機能を無効にする**

設定場所（管理コンソール）：
```
Realm settings（レルム設定）
  → Login（ログイン）
    → Forgot password（パスワードを忘れた）
      → 無効にする
```

⚠️ **注意**: この設定は、管理しているすべての「レルム（realm＝管理グループ）」に対して個別に行う必要があります。あくまで暫定措置なので、できるだけ早くアップデートしてください。

### 📅 今後の動向

今回修正されたバージョン26.7.2では、CVE-2026-18963のほかに、**合計8件の脆弱性**が修正されています。また、2週間前のバージョン26.7.1でも**12件の脆弱性**が修正されており、Keycloakに対するセキュリティ研究が活発化していることがわかります。Keycloakを利用している組織は、今後もアップデートへの注意が必要です。

## 過去記事との関連

今回の記事では、セキュリティ研究者のEnzo Mongin氏が**2026年7月に別のKeycloakの脆弱性**（アクセスコントロールの欠陥）を公表していたことに触れています。Keycloakに関するセキュリティ調査が活発に行われている中で、今回の「パスワードリセットの欠陥」が見つかった形です。

また、同じバージョン26.7.2で修正された**CVE-2026-15571**（予測可能なアカウントリンクのハッシュ値を使ったアカウント乗っ取り）も注目されます。このように、Keycloakは現在、複数の研究者から集中的に調査されており、**次々と新しい脆弱性が発見・修正されている状況**です。利用者はこれを「活発に改善が進んでいる」と前向きに捉えつつも、**アップデートへの追従を怠らない**ことが重要です。

## 用語解説

| 用語 | 解説 |
|------|------|
| **Keycloak（キークローク）** | 企業などがユーザーのログイン・認証をまとめて管理するためのオープンソースソフトウェア |
| **CVE（Common Vulnerabilities and Exposures）** | セキュリティの脆弱性に付けられる世界共通の識別番号（例：CVE-2026-18963） |
| **CVSS（Common Vulnerability Scoring System）** | 脆弱性の深刻度を0〜10で数値化したスコアリングシステム |
| **脆弱性（ぜいじゃくせい）** | ソフトウェアやシステムのセキュリティ上の欠陥・弱点 |
| **エンドポイント** | システムへのアクセス窓口となるURL・接続先のこと |
| **アクションリンク / アクショントークン** | パスワードリセット時などにメールで送られる「本人確認用の特別なリンク・合言葉」 |
| **シングルサインオン（SSO）** | 1回のログインで複数のサービスを利用できる仕組み |
| **レルム（Realm）** | Keycloakにおけるユーザー・設定の管理グループ（テナントのような概念） |
| **未認証（Unauthenticated）** | ログインしていない状態のこと。つまり誰でも攻撃できることを意味する |
| **エクスプロイト** | 脆弱性を実際に悪用するためのプログラムや手法 |
| **オープンソース** | ソースコード（設計図）が公開されており、誰でも無料で使用・改良できるソフトウェア |
| **Red Hat（レッドハット）** | オープンソースソフトウェアを企業向けに提供する大手IT企業（IBM傘下） |
| **CWE-640** | 「パスワード忘れ時の回復メカニズムが脆弱」という脆弱性の分類番号 |
| **状態管理（State Management）** | 処理の「どの段階にいるか」を記録・確認する仕組み |

> 💡 **まとめ**: Keycloakという「玄関の鍵」のようなシステムに、「本人確認なしに鍵を作り替えられる」重大な欠陥が見つかりました。管理者も含む全アカウントが標的になりうるため、利用している組織は速やかなアップデートが必須です。
