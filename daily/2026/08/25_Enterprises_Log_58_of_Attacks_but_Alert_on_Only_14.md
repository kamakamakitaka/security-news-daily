# 企業はサイバー攻撃の58%を記録しているが、アラートを出すのはわずか14%——新調査が明らかに

**元記事**: [Enterprises Log 58% of Attacks but Alert on Only 14%, New Research Finds](https://inl03.netline.com/ltr6/?_m=3n.009a.4065.sp0ao46r89.34fc)
**解説日**: 2026年8月25日

---

## 背景知識

このニュースを理解するために、まず「企業のセキュリティ監視」の仕組みを知っておきましょう。

### 企業のセキュリティ監視とは？

企業のネットワークは、毎日無数の「通信」が行き交っています。その中には、正常なものもあれば、**攻撃者による不審なアクセス**も混じっています。

これを管理するために、企業は主に2つの仕組みを使っています：

| 仕組み | 役割 | 例え |
|--------|------|------|
| **ログ(Log)** | 起きたことを記録する | 防犯カメラの録画 |
| **アラート(Alert)** | 危険なことが起きたときに担当者へ通知する | 防犯カメラの動体検知アラーム |

> 🏫 **例え話**：学校に例えると、「ログ」は生徒の出入りを記録する台帳、「アラート」は不審者が来たときに鳴るブザーのようなものです。

### よく使われるセキュリティツール

- **SIEM（シーム）**: Security Information and Event Management の略。ログを一か所に集めて分析するシステム。たくさんの防犯カメラの映像を一つの画面で管理するシステムのイメージ。
- **SOC（ソック）**: Security Operation Center の略。セキュリティを24時間監視する専門チームや施設のこと。

## 何が起きたのか

今回の調査（リサーチ）で、**非常に危険な実態**が明らかになりました。

> 📊 **調査結果のポイント**：
> - 企業はサイバー攻撃の **約58%をログ（記録）している**
> - しかし、担当者にアラート（警告）を出しているのは **わずか約14%** にすぎない

つまり、こういうことです👇

```
攻撃が100回あったとすると…

✅ 記録されているもの：58回（約半数以上はちゃんと記録されている）
🔔 担当者が気づくもの：14回（なんと86回は見逃されている！）
```

> 🏫 **例え話**：防犯カメラが不審者をちゃんと録画しているのに、警備員への通知が鳴らないので、誰も気づかないまま侵入されている——そんな恐ろしい状況です。

## 技術的な詳細

### なぜこんなギャップが生まれるのか？

「記録はしているのに、なぜアラートが出ないの？」と疑問に思う人もいるでしょう。主な原因はいくつかあります：

#### 1. 🔕 アラートの設定が不十分
ログ（記録）は残っていても、「これは危険！」と判断するための**ルール（しきい値）が設定されていない**ケースが多いです。
カメラはちゃんと映しているのに、「この動きが検知されたらアラームを鳴らす」という設定を誰もしていない状態です。

#### 2. 📦 データ量が多すぎる
現代の企業ネットワークでは、**1日に何百万件ものログ**が生成されます。全てを人間がチェックするのは不可能で、重要なアラートが埋もれてしまいます。

#### 3. 🛠️ ツールがバラバラで連携していない
セキュリティツールが複数あり、それぞれがバラバラに動いているため、**全体像が見えにくい**のです。

#### 4. 👩‍💻 人手不足
セキュリティの専門家は世界的に**深刻な人手不足**です。アラートが来ても、対処できる人がいない「アラート疲れ」という問題もあります。

### ギャップの図解

```
【理想】
攻撃発生 → ログ記録 → アラート発報 → 担当者が対応 → 被害ゼロ

【現実】
攻撃発生 → ログ記録(58%) → アラート発報(14%) → 担当者が対応 → 被害拡大💀
              ↑ここまではできてる    ↑ここで大きな穴！
```

## なぜ重要なのか

### 🚨 「記録しているだけ」では意味がない

この調査が示す最大の問題は、「**見ているようで見ていない**」という点です。

企業の担当者は「ちゃんとログを取っているから安心」と思っているかもしれません。しかし実際には、攻撃者はその「見えていない86%の隙間」を巧みに突いてくる可能性があります。

### 実際の被害シナリオ

```
攻撃者がネットワークに侵入
    ↓
侵入の痕跡はログに残っている（記録58%の中に含まれる）
    ↓
しかしアラートが鳴らないので担当者は気づかない
    ↓
攻撃者はゆっくりと時間をかけて内部を探索
    ↓
重要なデータを盗み出す、またはシステムを破壊する
    ↓
被害が発覚したときには手遅れ…
```

> 🏫 **例え話**：泥棒が家に侵入した記録はカメラに残っているのに、誰も映像を確認していなかったので、翌朝起きたら金庫が空になっていた——という状況です。

## 対策・今後の展望

### 企業が今すぐできること

#### ✅ 1. アラートルールの見直し
ログを取るだけでなく、「**どんな動きをアラートにするか**」のルールをきちんと設定・定期的に更新することが重要です。

#### ✅ 2. SIEM・AIの活用
膨大なログを人間だけで分析するのは限界があります。**AIを使った異常検知**を導入することで、人間が見落としやすいパターンを自動で発見できます。

#### ✅ 3. SOCの強化・外部委託
自社でSOC（監視チーム）を持てない中小企業は、**専門のセキュリティ会社にアウトソーシング（外部委託）**する方法も有効です。

#### ✅ 4. 定期的な訓練・演習
実際に攻撃を受けたときに素早く対応できるよう、**模擬攻撃演習（ペネトレーションテスト）**を定期的に行うことが推奨されます。

### 今後の展望

この調査結果を受けて、セキュリティ業界では以下のトレンドが加速すると考えられます：

- 🤖 **AI・機械学習を活用した自動アラート分析**の普及
- 📋 **アラートの質を重視する文化**への転換（量より質）
- 🔗 **セキュリティツールの統合・一元管理**の推進

## 用語解説

| 用語 | 読み方 | 意味 |
|------|--------|------|
| **ログ(Log)** | ログ | システムで起きた出来事の記録。防犯カメラの録画のようなもの |
| **アラート(Alert)** | アラート | 危険なことが起きたときに担当者へ送る警告通知 |
| **SIEM** | シーム | ログを一か所に集めて分析・監視するセキュリティシステム |
| **SOC** | ソック | セキュリティを24時間監視する専門チームや施設 |
| **しきい値** | しきいち | 「ここを超えたら危険」と判断するための基準値 |
| **アラート疲れ** | — | アラートが多すぎて担当者が慣れてしまい、重要な警告を見逃してしまう問題 |
| **ペネトレーションテスト** | — | 実際に擬似的な攻撃を行い、自社のセキュリティの弱点を探す演習 |
| **アウトソーシング** | — | 業務を外部の専門会社に委託すること |
| **異常検知** | いじょうけんち | 通常とは異なる不審な動きをAIなどが自動で発見する仕組み |

---

> 💡 **まとめ**：「記録している＝安全」ではありません。記録した情報を**ちゃんと活かして警告を出す仕組み**がなければ、宝の持ち腐れです。セキュリティは「取っているか」ではなく「**活かしているか**」が重要です！
