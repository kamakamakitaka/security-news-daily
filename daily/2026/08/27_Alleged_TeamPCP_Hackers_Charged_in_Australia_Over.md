## 背景知識

今回の記事を理解するために、まずいくつかの重要な概念を押さえておきましょう。

### 🏗️ オープンソースソフトウェアとは？
「オープンソース」とは、プログラムのコード（設計図）が誰でも見られる形で公開されているソフトウェアのことです。世界中の開発者が協力して作るため、品質が高く、企業でも広く使われています。

### 🔗 サプライチェーン攻撃とは？
サプライチェーンとは「部品の流通経路」のこと。お弁当を作るとき、食材を仕入れる農家→加工工場→スーパー→あなた、という流れがサプライチェーンです。

ソフトウェアの世界では、開発者が「すでに作られた便利なツール（部品）」を組み合わせてプログラムを作ります。サプライチェーン攻撃とは、**この「部品」に毒を仕込む攻撃**です。部品を信頼して使った開発者や企業が、知らないうちに感染してしまいます。

### 🔧 CI/CD（継続的インテグレーション/継続的デリバリー）とは？
ソフトウェアを自動的にビルド（組み立て）してリリース（公開）する仕組みです。工場の自動ベルトコンベアのようなものです。このベルトコンベアが汚染されると、出荷される全製品が危険にさらされます。

### 📦 PyPI・npm・Docker Hub・GitHub Actionsとは？
ソフトウェアの「部品」を配布するための公式配布サービスです。
- **PyPI**: Python言語の部品置き場
- **npm**: JavaScript言語の部品置き場
- **Docker Hub**: アプリのパッケージ置き場
- **GitHub Actions**: コードを自動処理するシステム

## 何が起きたのか

オーストラリア連邦警察（AFP）は2026年8月27日、**「TeamPCP」**と呼ばれるサイバー犯罪グループのメンバーとされる2人の男性を起訴しました。

- **ルーベン・イアン・トムソン容疑者（21歳）**：西オーストラリア州コットスロー在住
- **ルイ・マイケル・ゲブラー容疑者（23歳）**：西オーストラリア州マンデュラー在住

この2人は2026年3月に起きた大規模サイバー攻撃の主犯とされており、合計14件の罪状で起訴されています。警察は彼らの自宅を家宅捜索し、電子機器を押収しました。

### 被害の規模
| 項目 | 数字 |
|------|------|
| 被害組織数（確認済） | 世界1,000社以上 |
| 流出した認証情報 | 50万件以上 |
| 流出したデータ量 | 300GB以上 |
| 被疑者が関与した配布経路 | 5つのプラットフォーム |

## 技術的な詳細

### 🎯 攻撃の全体像：「連鎖する毒矢」

TeamPCPの攻撃は、まるで**ドミノ倒し**のように、一つの侵害が次の侵害を引き起こす巧妙な手口でした。

```
① TrivyのIDとパスワードを盗む
        ↓
② そのパスワードで Checkmarx KICSに侵入・改ざん
        ↓
③ LiteLLMがTrivyの汚染版を取り込む
        ↓
④ LiteLLMのパスワードが盗まれ、LiteLLM本体が改ざんされる
        ↓
⑤ LiteLLMを使う1,000社以上の企業が感染
```

### 🔍 各ツールの役割

**Trivy（トリビー）**：ソフトウェアの「脆弱性（弱点）」を自動でチェックするスキャナーです。安全を守るためのツールが、逆に攻撃の踏み台にされました。

**Checkmarx KICS**：コードの設定ミスを検出するセキュリティツールです。

**LiteLLM（ライトLLM）**：ChatGPTなどの複数のAIサービスをまとめて管理するゲートウェイです。企業のAIサービス用のAPIキー（合鍵）が集中しているため、攻撃者にとっては「宝の山」でした。

### 🔑 攻撃の核心：「信頼された鍵」を盗む

攻撃者がやったことを、わかりやすく例えると...

> 🏢 **例え話**
> あるビルの清掃員（Trivyのメンテナー）の入館カードを盗みます。その入館カードでビル内の別の部屋（Checkmarx KICS）に侵入。そこで見つけた管理者カードを使って、さらに重要な部屋（LiteLLM）に入り込み、システムに罠を仕掛ける——という感じです。

技術的には、**「パブリッシング認証情報（公開用パスワード）」**を盗み、正規の公式リリースチャンネルから「毒入りバージョン」を配布しました。ユーザーには「公式の正しいバージョン」に見えるため、非常に気づきにくいのです。

### ⚠️ バージョン固定をしていなかった問題

LiteLLMは、Trivyを「バージョン指定なし」で使っていました。これは「最新版のTrivyを自動で使う」という設定ですが、最新版が汚染されていた場合、自動で毒入りバージョンを取り込んでしまいます。

> 🍎 **例え話**
> 「りんごジュースを作るとき、スーパーの棚にある一番新しいりんごを使う」というルールにしていたら、そのりんごに農薬が混入していても気づかずに使ってしまう、というイメージです。

## なぜ重要なのか

### 1. 「安全を守るツール」が攻撃の入口になった
TrivyもCheckmarxも**セキュリティ用のツール**です。安全を守るために使うものが攻撃の足がかりにされたという皮肉な事実は、セキュリティ業界に大きな衝撃を与えました。

### 2. AI時代の新たなリスク
LiteLLMのような**AIゲートウェイ**が攻撃対象になったことは、AI活用が進む現代において特に重大です。企業のAI利用に関わる「合鍵（APIキー）」がまとめて盗まれる可能性があります。

### 3. 被害は長期間続く
FBIは「盗まれた認証情報は、初回侵害の遥か後まで悪用され続ける可能性がある」と警告しています。パスワードを変えていない企業は、今後も被害を受けるリスクがあります。

### 4. 規模の大きさ
研究機関CloudSEKの分析では、実際の影響が**2,500組織・約43万のCI/CDパイプライン**に及ぶ可能性が指摘されています。

## 対策・今後の展望

### 企業・開発者向けの対策

FBIとAFPは以下の対策を推奨しています：

| 対策 | 内容 |
|------|------|
| 🔑 認証情報のローテーション | CI/CD用パスワード・トークン・クラウド認証情報をすべて変更する |
| 📌 バージョン固定 | 外部ツールは「最新版自動使用」ではなく、特定バージョンに固定する |
| 🔍 ログの確認 | 侵害期間中にアクセスされた認証情報をすべて疑う |
| 🔒 最小権限の原則 | ツールに必要最小限の権限だけ与える |

### 今後の展望

- 両容疑者への判決次第では、サプライチェーン攻撃への法的抑止力が高まる可能性があります
- 最も重い罪（犯罪収益関与）の最高刑は**懲役20年**
- オープンソースのセキュリティ強化に向けた国際的な議論が加速するとみられます

|------|------|
| **TeamPCP** | 今回のサイバー犯罪グループの名称 |

| **オープンソース** | 設計図が公開されているソフトウェア |

| **認証情報のローテーション** | パスワードや鍵を定期的に変更すること |
| **バックドア** | 攻撃者が密かに仕込む「裏口」。気づかれずにシステムに侵入できる |

> 💡 **まとめ**
> 今回の事件は「信頼していたツールが罠だった」という、現代のソフトウェア開発が抱えるリスクを象徴しています。使う部品（ライブラリ）を常に検証し、パスワードは定期的に変え、バージョンは固定する——これらの「地道な習慣」が大規模被害を防ぐ鍵となります。
