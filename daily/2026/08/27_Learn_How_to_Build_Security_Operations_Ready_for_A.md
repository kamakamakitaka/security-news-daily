# AIを使った攻撃に備えるセキュリティ対策の作り方

**元記事**: [Learn How to Build Security Operations Ready for AI-Powered Attacks](https://inl03.netline.com/ltr6/?_m=3n.009a.4067.sp0ao46r89.34hp)
**解説日**: 2025年7月11日

---

## 背景知識

この記事を理解するために、いくつかの基本的な概念をおさえておきましょう。

### 🛡️ セキュリティチーム（SOC）とは？
企業の中で「サイバー攻撃から守る専門チーム」のことです。  
警備会社の監視員のようなイメージで、24時間システムを監視して、不審な動きを見つけたら対応します。

### 🤖 AIと攻撃の関係
最近では、**攻撃者（ハッカー）もAIを使い始めています**。  
AIを使うと「どこに弱点があるか探す」「攻撃用のプログラムを作る」といった作業が、以前よりずっと速くできるようになりました。

### 🏗️ クラウドインフラとは？
インターネット上にある、企業のデータやサービスを動かすための「場所・仕組み」のことです。  
Amazon（AWS）やGoogle（GCP）、Microsoft（Azure）などが提供しています。  
最近の企業システムのほとんどがここで動いています。

### 🔍 脆弱性（ぜいじゃくせい）とは？
システムやソフトウェアにある「弱点・穴」のことです。  
家の鍵のかかっていない窓のようなもので、攻撃者はここを狙って侵入します。

---

## 何が起きたのか

これは特定の「事件」ではなく、**今のセキュリティ業界が直面している大きな変化**についての記事です。

ひとことで言うと：

> **「AIのおかげで攻撃がものすごく速くなっている。守る側も速くならないと間に合わない」**

という問題提起です。

この記事は、セキュリティ会社「**Wiz（ウィズ）**」が開催するウェビナー（オンライン勉強会）の告知を兼ねており、AI時代に対応したセキュリティ体制の作り方を解説するとしています。

## 技術的な詳細

### ⚡ AIで攻撃はどう変わったか？

従来の攻撃と、AI支援の攻撃を比べてみましょう。

| 作業内容 | 従来の攻撃者 | AI支援の攻撃者 |
|---|---|---|
| 弱点を探す | 数日〜数週間 | 数時間〜数分 |
| 攻撃コードを作る | 高い技術が必要 | AIが自動生成 |
| システム内を移動する | 手動で試行錯誤 | パターンを学習して効率化 |

> 🎮 **ゲームで例えると…**  
> 昔の攻撃者は「マップを手書きしながらダンジョンを探索するプレイヤー」でした。  
> 今の攻撃者は「攻略サイト（AI）を見ながら最短ルートでボスまで到達するプレイヤー」です。

---

### 🧩 守る側の「情報バラバラ問題」

守る側には大きな課題があります。  
セキュリティチームは多くの情報を持っているのですが、それが**バラバラのツールに分散**しています。

```
脆弱性の情報 → ツールA
クラウドの警告 → ツールB
ログイン情報の異常 → ツールC
アプリの動作記録 → ツールD
      ↓
「どれが本当に危険？」を判断するのに時間がかかる！
```

例えば「この弱点、本当に攻撃者が使えるの？」「このサーバーに重要なデータある？」「誰が担当者？」という質問に答えるのに、複数のツールを行き来しなければなりません。

> 🏥 **病院で例えると…**  
> 患者の検査結果が「血液検査はA病院」「レントゲンはB病院」「問診票はC病院」に分かれていたら、正確な診断に時間がかかりますよね。それと同じ問題が起きています。

---

### 🗺️ 「攻撃パス」という考え方

記事の中で重要なのが「**アタックパス（攻撃経路）**」という概念です。

攻撃者は1か所の弱点を狙うのではなく、**弱い場所から徐々に重要なシステムへと移動していきます**。

```
例）
インターネットに公開されたサーバー
        ↓（脆弱性を利用）
社内ネットワークへ侵入
        ↓（権限を奪う）
重要なデータベースへアクセス
        ↓
個人情報・機密情報が盗まれる！
```

守る側は「どこが入口になり得るか？」「入られたら次にどこへ行けるか？」を**地図のように把握**する必要があります。

## なぜ重要なのか

### 🕐 時間との勝負

攻撃者がAIを使えば、攻撃の速度が上がります。  
守る側が「情報を集めて、分析して、担当者に連絡して…」とやっている間に、攻撃が完了してしまう可能性があります。

### 🏢 影響を受けるのは？

- **企業・組織**：顧客データの漏洩、システム停止、金銭的被害
- **私たち一般人**：個人情報の流出、サービスが使えなくなる
- **社会インフラ**：電力・病院・交通などの重要システムへのリスク

### 📊 セキュリティ担当者が抱える具体的な悩み

記事では、以下の質問に「素早く答えられるか？」が重要だと言っています：

1. この弱点は、攻撃者が実際に使える場所にある？
2. その場所に重要なデータがある？
3. そこから、もっと重要なシステムへ移動できる？
4. 誰が対応すべき担当者？
5. 何を最初に直すべき？

これらに**素早く答えられない**と、対応が遅れてしまいます。

## 対策・今後の展望

### ✅ 今すぐできる・目指すべき対策

記事では、AI時代のセキュリティに必要な3つの要素が語られています：

#### 1. 「広い視野」を持つ
クラウド、コード、ログイン情報、使用しているSaaSサービス（Google WorkspaceやSlackなど）、AIサービス…すべてを一か所から見渡せる仕組みを作る。

#### 2. 「情報をつなぐ」
バラバラのツールの情報を統合して、「この弱点は危険度〇〇、担当者は△△さん、今すぐ対応が必要」まで一気に判断できる状態を目指す。

#### 3. 「対応を速くする」
危険だとわかったら、担当者に通知して修正するまでの時間を短くする。AIはすべての判断を自動化するのではなく、**人間が判断するための準備を素早くやってくれる役割**として使う。

### 🔮 今後の展望

- セキュリティ分野でも「AIで守る vs AIで攻める」という構図が加速する
- セキュリティツールの統合・一元管理がますます重要になる
- AIに判断を任せすぎず、人間の確認を適切に組み合わせることがカギ

> 💡 **私たち個人でできること**  
> - パスワードを使い回さない（パスワードマネージャーを使う）
> - 不審なメールのリンクをクリックしない
> - ソフトウェアのアップデートをこまめに行う（脆弱性を塞ぐため）

## 用語解説

| 用語 | 読み方 | 意味 |
|---|---|---|
| **脆弱性** | ぜいじゃくせい | システムやソフトの「弱点・穴」。攻撃者に狙われる |
| **SOC** | ソック | Security Operations Center。企業のセキュリティ監視チーム |
| **エクスプロイトコード** | — | 脆弱性を実際に攻撃するためのプログラム |
| **クラウドインフラ** | — | インターネット上で動く企業のシステム基盤 |
| **SaaS** | サース | Software as a Service。SlackやGmailのようにネット経由で使うソフト |
| **アタックパス** | — | 攻撃者がシステム内を移動する「経路・ルート」 |
| **テレメトリ** | — | システムの動作を自動的に記録したデータ |
| **リメディエーション** | — | 問題を修正・改善すること |
| **ソフトウェアサプライチェーン** | — | ソフトを作るために使う外部ライブラリや部品の連鎖。ここへの攻撃も増加中 |
| **ウェビナー** | — | Web + Seminar。オンラインで開催するセミナー |

> 📝 **まとめると…**  
> AIのおかげで、ハッカーは以前よりずっと速く・効率的に攻撃できるようになっています。守る側も、バラバラな情報を素早く統合して「どこが本当に危険か」を速く判断できる仕組みが必要です。これは企業だけの問題ではなく、私たちの個人情報や日常生活を守るためにも非常に大切な課題です。
