# GPUThorとは？グラフィックカードのメモリを攻撃して管理者権限を奪う新手法

**元記事**: [New GPUThor Rowhammer Defeats ECC on NVIDIA RTX A6000 to Gain Host Root Access](https://inl03.netline.com/ltr6/?_m=3n.009a.4067.sp0ao46r89.34ij)
**解説日**: 2025年7月

---

## 背景知識

このニュースを理解するために、いくつかの基本的な概念を先に説明します。

### 🖥️ GPU（グラフィックス処理ユニット）って何？

GPUは、もともとゲームの映像を描画するために作られたチップです。でも最近は、AIの学習・科学計算・動画編集など、膨大な計算を並列（同時）に処理するために広く使われています。NVIDIAはGPU業界のトップメーカーで、今回の記事に出てくる「RTX A6000」などは、研究機関や企業が使うプロ向けの高性能GPUです。

### 💾 DRAM（メモリ）の仕組み

コンピュータのメモリ（RAM）は、電気的なスイッチ（セル）が格子状（グリッド）に並んだ構造をしています。ちょうど**マンションの部屋**のようなイメージです。横方向に並んだ部屋の列を「行（ロウ）」と呼びます。

### 🔨 Rowhammer攻撃とは？

**Rowhammer（ローハンマー）攻撃**は、メモリの特定の「行」に対して物理的に大量のアクセスを繰り返すことで、**隣の行のデータを壊してしまう攻撃手法**です。

マンションの例えで言うと：「3階の床を何万回もドンドン叩き続けたら、2階の天井にヒビが入って、2階の部屋の様子が変わってしまった」というようなイメージです。これを「ビットフリップ（bit flip）」と呼び、データの0と1が意図せず入れ替わってしまう現象です。

> 💡 **ビットフリップ**: コンピュータのデータは「0」と「1」の組み合わせで表現されています。ビットフリップとは、この「0」が「1」に、または「1」が「0」に勝手に変わってしまうことです。

### 🛡️ ECC（エラー訂正コード）とは？

**ECC（Error Correcting Code）**は、メモリのビットフリップを自動的に検出・修正する仕組みです。これを使うと、1ビットのエラーは自動修正、2ビットのエラーは検出できます。

銀行の「チェックディジット」（クレジットカード番号の最後の数字が入力ミスを検出するやつ）に似た仕組みで、データに「おまけの確認情報」を付け加えて保存し、読み出す時に「あれ、おかしいぞ」と気づく仕組みです。

### 🔐 ルート権限（root shell）とは？

コンピュータには使用できる機能に「権限レベル」があります。**ルート権限（root）**は、コンピュータの最高管理者権限のことで、システムのあらゆる操作ができます。普通のユーザーが「一般社員」なら、ルートは「会社の全権を持つ社長」のようなものです。

## 何が起きたのか

カナダのトロント大学の研究チームが、**「GPUThor（GPUソー）」**という新しい攻撃手法を開発・発表しました。

この攻撃のポイントは次の3つです：

1. **NVIDIAのプロ向けGPU**（RTX A6000など、GDDR6メモリ搭載）が対象
2. **ECCが有効でも攻撃が成立する**（従来はECCを有効にすれば防げると言われていた）
3. **最終的にコンピュータの最高管理者権限（root）を奪える**

攻撃の対象になることが確認されたGPUは以下の通りです：

| GPU名 | メモリ容量 |
|---|---|
| RTX A6000 | 48 GB |
| RTX A5000 | 24 GB |
| RTX A4500 | 20 GB |
| RTX A4000 | 16 GB |

研究チームは、これらのGPUを**24時間ずつ**叩き続ける実験を行い、攻撃の成立を確認しました。

## 技術的な詳細

### 📌 従来の攻撃との違い

以前の研究（GPUHammer）では、NVIDIAはECCを有効にすることで攻撃を防げると発表していました。しかし今回のGPUThorは、ECCを突破します。なぜでしょうか？

#### ① 非均一ハンマリング（Non-uniform hammering）

従来の攻撃は、「攻撃したい行（被害者行）」の両隣の行を**同じ回数だけ**叩いていました。

GPUThorは、**隣の行（攻撃者行）をものすごく多く**叩き、目くらまし用の行（おとり行）はほんの少しだけ叩きます。

> 🎯 **例え話**: セキュリティカメラをごまかすのに、正面からじっと見るのではなく、横をチラ見しながら正面に集中するようなイメージです。メモリの防御機能（TRR）をうまく欺くことができます。

#### ② TRR（Target Row Refresh）の弱点を発見

**TRR（ターゲット行リフレッシュ）**は、よく叩かれている行の隣を自動的にリフレッシュ（データをリセット）する防御機能です。

研究チームは、このGPUのTRRが**72回のリフレッシュサイクルに1回しか**働いていないことを発見しました（本来は毎回働くべきものです）。これを利用して、防御の「スキ」をついた攻撃パターンを作り上げました。

#### ③ ワープ（Warp）の仕組みを利用

GPUは**ワープ**という単位（32スレッドのグループ）でまとめて処理します。同じワープ内の複数アクセスはメモリコントローラに「まとめて1回」として処理されますが、**異なるワープからのアクセスは別々に処理**されます。研究チームはこの違いをうまく利用して、攻撃の効率を高めました。

### 📊 攻撃の効果

ECCが無効の場合、1GBあたりのビットフリップ数：

```
GPUHammer（従来）:    16 フリップ/GB
GDDRHammer（従来最強): 758 フリップ/GB
GPUThor（RTX A5000):  377,552 フリップ/GB ← 約500倍以上！
```

#### ECC有効時でも…

研究チームはECCが有効な状態のRTX A6000でも攻撃を実施。

- 1日（24時間）で **11回の検出不能エラー（DUE）** と **1回のサイレントデータ破損（SDC）** が発生
- DUEが起きるたびに**GPU上の全プログラムが強制停止**し、リセットが必要に（サービス妨害攻撃＝DoS）
- SDC（サイレントデータ破損）では、エラーを検出できずに**データが静かに壊れる**という危険な状態に

> ⚠️ **SDC（サイレントデータ破損）が特に怖い理由**: 普通のエラーなら「壊れました！」と教えてくれます。でもSDCは「壊れているのに正常に見える」状態です。薬の瓶のラベルが「アスピリン」と書いてあるのに中身が別の薬に入れ替わっているようなもので、気づかずに使い続けてしまう危険があります。

### 🔓 権限昇格（Root取得）の手順

1. **ページテーブル**（メモリの地図のようなもの）を攻撃しやすい場所に配置する
2. 隣の行をハンマリングして、ページテーブルの「ページフレーム番号」（メモリのアドレス情報）をビットフリップで書き換える
3. 書き換えられたアドレスを使って、**本来アクセスできないはずのメモリ領域**に侵入
4. これを応用して、ホストコンピュータ（GPUを動かしているパソコン本体）の**最高管理者権限（root）を奪取**

## なぜ重要なのか

### 🌐 クラウドやAI分野への影響が大きい

今日、AIの学習や科学シミュレーションには、**複数のユーザーが同じGPUを共有して使う「マルチテナント環境」**が一般的です（クラウドサービスなど）。

この環境では、悪意のあるユーザーが「普通のプログラムを実行しているふり」をしながら、同じGPUを使っている別のユーザーのデータや、サーバー本体を攻撃できてしまいます。

### ⚠️ ECC「だけ」では守れないことが証明された

NVIDIAが公式にRowhammerへの対策として推奨していた**ECCが突破された**ことは、業界に大きな衝撃を与えています。セキュリティ対策が「完璧」ではないことが再確認されました。

### 📉 DoS攻撃として使える

権限奪取まで至らなくても、ECC有効時でも**2時間ごとにGPUをクラッシュさせる**ことができます。これはAI推論サービスやビジネスクリティカルな計算を妨害するサービス妨害攻撃（DoS）として悪用できます。

## 対策・今後の展望

研究チームとNVIDIAは以下の対策を推奨しています：

### ✅ 今すぐできる対策

| 対策 | 説明 |
|---|---|
| **クロステナントGPU共有を避ける** | 複数ユーザーが同じGPUを共有する使い方をやめる |
| **ECCエラーカウンターを監視する** | 異常なエラー増加を早期に検知する |
| **信頼できないCUDAプログラムの実行を制限する** | 出所不明のGPUプログラムを動かさない |
| **System-Level ECC を有効にする** | NVIDIAはまずこれを推奨（完全ではないが有効） |

> 💡 **CUDA（クーダ）**: NVIDIAが開発した、GPUでプログラムを動かすための仕組みです。

### 🔮 今後の展望

- NVIDIAは2025年7月にセキュリティ通知を発表しましたが、完全なハードウェア的修正は容易ではありません
- 研究チームは悪用コードを公開していませんが、**研究論文として公開**されているため、将来的に悪用される可能性があります
- 次世代のGPUやメモリ規格（GDDR7など）での改善が期待されます

## 過去記事との関連

今回のGPUThorは、同じトロント大学のチームによる研究の**第3弾**にあたります：

```
GPUHammer（第1弾）
  └ NVIDIAハードウェアへの初のGPU Rowhammer攻撃
  └ 1GBあたり16ビットフリップ → ECCで防御可能

GPUBreach（第2弾）
  └ GPUのページテーブルを悪用した権限昇格研究
  └ 今回の権限奪取コードとして流用された

GPUThor（第3弾・今回）
  └ ECCを突破し、ECC有効でもDoS・権限奪取が可能に
  └ ビットフリップ数が23,597倍に向上
```

まさに「イタチごっこ」の状況で、防御技術が進化すると攻撃技術も進化するという、セキュリティの世界の典型的な流れです。

## 用語解説

| 用語 | 意味 |
|---|---|
| **Rowhammer（ローハンマー）** | メモリの特定行を大量アクセスして、隣の行のデータを壊す攻撃手法 |
| **ビットフリップ（Bit flip）** | メモリ上のデータの0と1が意図せず入れ替わる現象 |
| **ECC（Error Correcting Code）** | メモリのエラーを自動検出・修正する仕組み |
| **GDDR6** | GPU向けの高速メモリ規格（DDR6のGPU版） |
| **TRR（Target Row Refresh）** | よく叩かれた行の隣を自動リフレッシュするメモリの防御機能 |
| **CUDA（クーダ）** | NVIDIAが開発したGPUプログラミングの仕組み |
| **ワープ（Warp）** | GPUが処理する32スレッドのひとかたまり |
| **ルート権限（root）** | コンピュータの最高管理者権限 |
| **DoS（サービス妨害攻撃）** | システムを正常に使えなくする攻撃 |
| **ページテーブル** | プログラムがどのメモリを使っているかを管理する「地図」 |
| **SDC（サイレントデータ破損）** | エラーを検出できず、データが静かに壊れる状態 |
| **DUE（検出不能エラー）** | ECC が修正できないエラーで、システムがクラッシュする |
| **マルチテナント環境** | 複数のユーザーが同じハードウェアを共有して使う環境 |
| **非均一ハンマリング** | おとり行とは異なる頻度で攻撃行を叩く、防御回避テクニック |

---

> 🔒 **まとめ**: GPUThorは「ECC（エラー訂正）があれば安全」というこれまでの常識を覆した重大な研究です。特にAIやクラウドサービスでGPUを共有利用している環境では、今すぐ対策を検討する必要があります。セキュリティは「一度設定したら終わり」ではなく、攻撃手法の進化に合わせて継続的にアップデートすることが大切です。
